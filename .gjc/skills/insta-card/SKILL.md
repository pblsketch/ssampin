# insta-card — 녹화 영상 → 인스타 카드뉴스 + 캡션

화면 녹화 mp4 하나를 받아 **1080×1350(4:5) 캐러셀 5~6장 + 필요하면 영상 슬라이드 + 캡션**을 만든다.
스타일은 `references/style.md`에 잠겨 있다. **임의로 바꾸지 않는다.**

## 준비물

- 소스 영상 (화면 녹화 mp4)
- `ffmpeg` / `ffprobe` — 없으면 `FFMPEG` 환경변수로 경로 지정
- Chrome — 없으면 `CHROME` 환경변수로 경로 지정
- Node 18+

## 절차

### 0. 무엇을 소개할지 먼저 확정한다

사용자에게 이미 들었으면 그대로 쓴다. 안 들었으면 **딱 이 세 가지만** 묻는다.

1. 소개할 기능과 **빼야 할 기능** (예: "수행평가·성적은 빼줘")
2. 카드 장수 (기본 6장 = 표지 1 + 기능 4 + 마무리 1)
3. 마무리 카드의 행동 유도 (댓글 유도인지, 링크 노출인지)

> **링크 노출 여부는 반드시 확인한다.** 댓글 유도형이면 카드·캡션 어디에도 URL을 넣지 않는다.

### 1. 영상을 읽는다

```bash
node .gjc/skills/insta-card/scripts/scan.mjs "<영상경로>" .insta-work
```

컨택트시트가 `.insta-work/sheet_*.jpg`로 나온다. **전부 Read로 직접 본다.**
그다음 관심 구간을 원본 해상도로 뽑아 다시 본다.

```bash
node .gjc/skills/insta-card/scripts/scan.mjs "<영상경로>" .insta-work --at 10,40,90,151
```

보면서 다음을 적어 둔다.

- 기능별 시각 구간 (몇 초에 무슨 화면인가)
- **크롭 좌표** — 창 전체가 아니라 그 기능 영역만. 사이드바·창 테두리·작업 표시줄은 뺀다
- **개인정보 위험** — 실명, 학교명, 교사 이름, 사진에 박힌 글자
- 빼기로 한 기능이 화면에 걸리는 구간

### 2. 사실 확인 — 코드로 대조한다

카드에 쓸 기능 설명은 **영상에서 본 것 + 코드에서 확인한 것**만 쓴다.
"한글이나 PDF로 내보내기 되죠?" 같은 말을 그대로 옮기지 말고 실제 형식을 찾는다.

```bash
grep -rn "hwpx\|xlsx\|pdf" src/adapters/components/<해당기능> | head
```

또 **지금 출시된 빌드에 그 기능이 실제로 있는지** 확인한다.
기능 스위치(`featureFlags.ts` 등)로 막혀 있는데 녹화는 로컬 빌드로 찍은 경우가 실제로 있었다.
막혀 있으면 **만들되, 사용자에게 알리고 게시 시점을 다음 릴리즈 뒤로 제안한다.**

### 3. config.json을 쓴다

`assets/example-config.json`을 본뜬다. 스키마는 `references/style.md` 아래쪽에 있다.

- 카드당 **제목 2줄 + 기능 설명 4줄까지**. 그 이상은 안 들어간다
- 이미지 높이는 **적지 않는다** — `w`만 주면 실제 크롭 비율로 자동 계산된다
- 카피는 `references/style.md`의 문장 규칙을 따른다

### 4. 만든다

```bash
node .gjc/skills/insta-card/scripts/crop.mjs config.json    # 크롭 추출
node .gjc/skills/insta-card/scripts/build.mjs config.json   # 카드 + 영상 슬라이드
```

### 5. 눈으로 확인한다 — 건너뛰지 않는다

```bash
node .gjc/skills/insta-card/scripts/build.mjs config.json --review
```

`<out>/src/_review.jpg` 한 장에 전 카드가 깔린다. Read로 보고 다음을 확인한다.

- 글자 겹침 (특히 설명 목록 ↔ 하단 서명)
- 크롭이 중간에서 잘려 실수처럼 보이는 곳
- 마우스 커서가 글자 위에 얹힌 곳 → **다른 초의 프레임으로 다시 크롭한다**
- 빼기로 한 기능이 화면에 남아 있는지
- 읽히면 안 되는 이름·학교명

영상 슬라이드는 프레임을 뽑아 확인한다.

```bash
node .gjc/skills/insta-card/scripts/build.mjs config.json --review-clips
```

### 6. 캡션을 쓴다

`<out>/caption.md`에 다음을 담는다.

1. **게시 순서 표** — 슬라이드 번호 / 파일 / 정지·영상 여부
2. **캡션 본문** — 기능별로 항목을 나눠 구체적으로. 카드에 못 넣은 것까지 여기서 푼다
3. **해시태그** 15~20개
4. **첫 댓글 문장** (선택)
5. **문구 주의** — 확인한 사실과 다르게 쓰기 쉬운 지점을 메모로 남긴다

캡션 어투는 `references/style.md`의 문장 규칙과 같다. 과장하지 않고, 되는 것만 적는다.

### 7. 정리하고 보고한다

- `.insta-work/`와 `<out>/src/_*.jpg` 같은 임시물은 지운다
- 사용자에게: 만든 것 → 왜 그렇게 했는지 → **확인 결과와 걸린 점**

## 절대 규칙

- **전체 화면을 쓰지 않는다.** 기능 영역만 크롭한다.
- **되는 것만 쓴다.** 사용자가 말한 기능이라도 코드에서 확인 안 되면 그대로 쓰지 말고 알린다.
- **개인정보는 게시 전에 막는다.** 실명·학교명이 읽히는 컷은 안 쓰고, 사진에 박힌 글자는 흐리게 덮는다.
- **댓글 유도형이면 URL을 넣지 않는다.**
- 빼달라고 한 기능은 크롭 밖으로 밀어낸다.
