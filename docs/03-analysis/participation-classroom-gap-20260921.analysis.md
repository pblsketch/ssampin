# 참여교실 — 다른 퀴즈·설문 도구와 견준 부족한 점과 개선 계획 (2026-09-21)

오너가 파세오 세션 `0bd65e67-ccda-43af-b34d-28517218401d` 의 결과물을 실기기에서 써 보고 남긴
지적에서 출발했다. 지적 다섯 가지는 이 날 구현으로 반영했고(아래 1절), 이 문서는 그 과정에서
조사한 레퍼런스와, **아직 남은 격차·순서**를 정리한다. 여기의 2·3절은 아직 구현하지 않은 계획이다.

## 0. 조사한 도구와 근거

| 도구            | 확인한 것                                                                                                                    |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------- |

**요약 —** "교사만 학생별 응답을 본다"는 쌤핀의 지금 구조는 Kahoot·Pear Deck과 같은 계열이고,
업계에서 벗어난 설계가 아니다. 다만 **교실 화면에 학생 글이 그대로 나가는 유형**(아이디어·질문
모으기, 워드클라우드, 서술형)에는 대부분의 도구가 **지우거나 미리 거르는 장치**를 두고 있는데,
참여교실에는 그 장치가 없다. 이것이 지금 가장 큰 격차다.

## 1. 이 날 반영한 것 (구현 완료 · 미출시)

1. 문항 목록을 **끌어서 순서 바꾸기**. 키보드 사용자를 위해 [위로]·[아래로]도 같이 둔다.
2. 척도·2축 평가·여러 항목 척도를 **가치수직선 하나**로 합쳤다. 항목 개수와 기준(축) 개수로
   세 가지를 모두 만든다. 학생 입력은 숫자 칸에서 **슬라이더**로 바뀌었다.
3. 질문 받기를 **아이디어·질문 모으기**에 합쳤다. 문항을 만들 때 **투표(공감) 여부를 고른다.**
4. 교실 화면(별도 창)을 쓸모 있게 고쳤다 — 참여 인원·응답 현황 막대, 모든 유형의 결과 그림,
   공감 많은 순 정렬. 단추 이름을 `교실 화면 띄우기`로 바꾸고 닫기와 설명을 붙였다.
5. 학생별 응답은 **카훗 방식 유지**. `교사 전용 · 교실 화면과 학생 화면에는 나가지 않아요` 표시를
   붙여 선생님이 안심하고 펼치게 했다.

곁가지로, 결과 그림의 막대 바탕이 **아예 투명하던 것**을 고쳤다(`bg-sp-accent/10` 류는 규칙이
생성되지 않는다 — 저장소의 알려진 함정). 이미지 위치 문항의 정답 영역 표시도 같은 이유로
테두리만 보이던 것을 고쳤다.

## 2. 남은 격차 — 코드로 확인한 것

우선순위는 **교실에서 사고가 나는 정도 → 수업 준비 시간을 줄이는 정도** 순이다.

### P0. 부적절한 응답을 교실 화면에서 지울 방법이 없다

- `liveSession.hiddenWordsByQuestion` 과 `hideWord()` 는 **이미 있는데**, 참여교실 콘솔에 그 단추가
  없고 `QuestionResponseSummary`·`ParticipationShare` 가 그 목록을 보지 않는다. 즉 **워드클라우드조차
  참여교실에서는 못 지운다**(옛 멀티설문 v2 경로에만 있다).
- 아이디어·질문 모으기와 서술형은 학생이 쓴 **문장이 그대로** 교실 화면에 뜬다. 지우는 수단이 없다.
- Mentimeter·Slido가 공통으로 갖춘 최소 장치다. 없으면 한 명의 장난이 교실 전체 화면을 차지한다.

### P1. 문항 제한 시간이 실제로 돌지 않는다

- 문항마다 `timerSeconds` 를 저장하고 검증까지 하지만, 참여교실의 교사 콘솔·교실 화면·학생 화면
  어디에도 카운트다운이 없다. 선생님이 눈대중으로 "그만" 해야 한다.
- 진행 방식(교사가 한 문항씩 넘김) 자체는 유지하되, **남은 시간 표시와 자동 마감을 고를 수 있게**
  하는 것이 Kahoot·Quizizz와의 가장 눈에 띄는 차이다.

### P1. 문항 본문에 이미지를 넣을 수 없다

- `QuestionBase.mediaUrl` 필드는 있으나 참여교실 편집기가 노출하지 않고
  `mapQuestionsForLiveHTML` 도 학생에게 보내지 않는다. **보기 이미지와 이미지 위치 표시에만** 이미지가 된다.
- 지도·그래프·작품 사진을 띄우고 묻는 수업이 막힌다. 다른 도구는 전부 기본 기능이다.

### P2. 결과를 앱 밖으로 못 가져간다

- 지난 활동 결과는 앱 안에서만 본다. CSV·인쇄·한글 문서 어느 쪽도 없다.
- 생기부 근거나 상담 자료로 옮기려면 손으로 옮겨 적어야 한다. 쌤핀의 다른 기능(생기부 근거)과
  이어 붙이면 경쟁 도구에 없는 강점이 되는 자리다.

### P2. 문항별 정답률·오답 분석이 얕다

- 지금은 **순위·점수·학생별 응답**만 있다. "몇 번 문항을 반이 어려워했는가"를 한눈에 보는 표가 없다.
- 형성평가로 쓰려면 이것이 본체다(Kahoot의 문항 보기, Quizizz의 보고서).

### P2. 학생 별명이 자유 입력이라 누가 누군지 흐릿하다

- 참여 학생은 아무 별명이나 적는다. 중복도 막지 않는다. 교사 화면에 이름이 보여도 **명렬과 맞추는
  일은 선생님 몫**이다.
- 쌤핀에는 이미 학급 명렬이 있다. **명단에서 고르게 하는 선택지**는 다른 도구가 못 하는 것이고,
  출결·상담·생기부와 바로 이어진다. (익명이 필요한 주제를 위해 끌 수 있어야 한다.)

### P3. 자기 속도(과제형) 진행이 없다

- 활동은 선생님이 한 문항씩 넘겨야만 진행된다. Quizizz·Wooclap의 과제형(집에서 각자 풀기)이 없다.
- 학생 접속 서버가 선생님 컴퓨터에서 도는 구조라 **그대로 옮길 수 없다.** 별도 설계가 필요하다.

### P3. 문항을 다시 쓰기 어렵다

- 활동 복제는 되지만 **문항 단위 보관·검색·가져오기**가 없다. 매번 처음부터 적는다.

## 3. 제안하는 순서

| 단계 | 내용                                                                                                                                                                    | 크기 |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| 1    | **모더레이션** — 교사 콘솔의 각 응답·단어 옆에 [교실에서 가리기], 교실 화면이 가린 항목을 빼고 그린다. 기존 `hideWord` 를 문항 유형 전체로 넓히고 스냅샷에 실어 보낸다. | 중   |
| 2    | **문항 제한 시간** — 문항별 남은 시간 표시(교사·교실·학생), 자동 마감은 문항 설정으로 켜고 끈다.                                                                        | 중   |
| 3    | **문항 이미지** — 편집기에 본문 이미지 입력(기존 `QuestionImageInput` 재사용), 학생 payload·교실 화면에 함께 내려보낸다.                                                | 소   |
| 4    | **문항별 정답률 표 + 결과 내보내기** — 활동 결과 화면에 문항×정답률 표를 더하고 CSV로 저장한다.                                                                         | 중   |
| 5    | **학급 명렬에서 고르기(선택)** — 활동 설정에 "학급 명단에서 고르게 하기"를 두고, 켜면 학생 화면이 명단 선택으로 바뀐다. 끄면 지금처럼 별명.                             | 대   |
| 6    | 문항 보관함·가져오기                                                                                                                                                    | 대   |
| 7    | 자기 속도(과제형) — 서버 구조 결정이 먼저다.                                                                                                                            | 대   |

1~4는 지금 구조 위에서 더하는 일이라 위험이 낮다. 5는 개인정보 판단이 필요하고,
7은 접속 서버를 어디에 둘지부터 정해야 한다 — 둘 다 오너 결정이 먼저다.
