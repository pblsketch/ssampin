# Phase 0 실측 재측정 — 유료 키 발급 후 (2026-08-18)

$20 충전 후 발급한 키로 다시 쟀다. 앞선 `measure-2-rate-limit.md`(익명 측정)의 결론 중
**한 가지가 뒤집히고, 한 가지는 그대로 남았다.**

## 1. 뒤집힌 것 — REST가 열린다

익명일 때 429로 막혔던 `POST /zen/v1/chat/completions` 가 키를 붙이자 **200으로 응답**한다.
무료 모델 `deepseek-v4-flash-free` 단발 호출 2.6초 성공.

즉 **"서버에서 Zen을 부를 수 없다"는 결론은 틀렸다.** 키가 있으면 부를 수 있다.

## 2. 그대로 남은 것 — 무료 모델은 잔액으로 풀리지 않는다

무료 모델로 20건을 연속 호출하자 **첫 건만 200이고 나머지 19건이 전부 429**였다.
오류 유형은 익명일 때와 **똑같은 `FreeUsageLimitError`**:

```
{"type":"error","error":{"type":"FreeUsageLimitError",
 "message":"Error from provider (Console): Rate limit exceeded. Please try again later."}}
```

**충전한 잔액이 무료 모델의 한도를 풀어주지 않는다.** 무료 몫은 잔액과 별개의 주머니다.
따라서 무료 모델은 제품에 쓸 수 없다 — 실사용은 유료 모델로 가야 한다.

부수 확인: 잔액·사용량 조회 API는 없다(`/zen/v1/balance`·`usage`·`credits`·`account`·`me` 전부 404).
잔액은 대시보드에서만 볼 수 있다.

## 3. 유료 모델 실측 — 제품이 쓸 경로에서 도구 호출이 된다

`gpt-5-nano` 로 계획서 §7 실측 ①을 REST에서 그대로 재현:

| 항목             | 기준 | 결과                             | 판정 |
| ---------------- | ---- | -------------------------------- | ---- |
| 도구 선택 정확도 | ≥80% | **83%** (15/18)                  | PASS |
| 스키마 준수      | ≥90% | **100%** (17/17)                 | PASS |
| 멀티턴 3턴 유지  | 유지 | **3/3 도구 선택, 맥락 승계 2/2** | PASS |
| 없는 도구 지어냄 | 0건  | **0건**                          | PASS |
| 스트리밍(SSE)    | —    | **지원, tool_calls 델타 확인**   | —    |

`minimax-m3` 는 첫 시도에서 `503 Upstream request failed` 로 건너뛰었으나, 재시도에서는 정상
동작했다. **일시적 상류 장애**였다(스크립트가 이를 "tools 미수용"으로 표시한 것은 오분류다).

## 4. 질문 1건당 실제 비용

챗봇 한 번의 왕복(질문 → 도구 호출 → 도구 결과 → 최종 답변, **모델 호출 2회**)을 5건 측정한 평균.

| 모델         | 입력/출력 토큰 | 질문 1건     | $20으로     | 응답 시간 |
| ------------ | -------------- | ------------ | ----------- | --------- |
| `gpt-5-nano` | 697 / 939      | **$0.00041** | 약 48,700건 | **17초**  |
| `minimax-m3` | 1,741 / 254    | **$0.00083** | 약 24,200건 | **5초**   |

월 비용 추정 (교사 1명이 하루 5건, 월 20일 사용 가정):

| 교사 수 | `gpt-5-nano` | `minimax-m3` |
| ------- | ------------ | ------------ |
| 100명   | 월 $4.10     | 월 $8.27     |
| 500명   | 월 $20.52    | 월 $41.36    |
| 1,000명 | 월 $41.03    | 월 $82.72    |

## 5. 판정 — 모델 선택

**`minimax-m3` 를 권한다.** 비용이 2배지만 절대액이 작고(1,000명 기준 월 $83),
**응답이 5초 대 17초로 3배 이상 빠르다.**

`gpt-5-nano` 가 느린 이유는 생각 과정(reasoning)에 출력 토큰을 많이 쓰기 때문이다
(출력 939 토큰 중 상당수가 사용자에게 보이지 않는 추론 토큰). 챗봇에서 17초는 쓰기 어렵다.

## 5-1. 아직 안 잰 것 — 계획서의 실측 ③(한국어 품질)

계획서 §7 의 실측 ③은 **한국어 품질**(생기부 문체 9/10, 환각 0건)이다. 아직 미실시다.
`measure-3-cost.mjs` 의 파일명 3은 실행 순서일 뿐 계획서의 실측 ③이 아니다.

## 5-2. 무료 모델을 끝까지 파본 결과 — 폐기 확정

"활성화가 안 된 것 아니냐"를 확인했다. **아니다.**

- 키를 넣은 직후 무료 모델은 **200으로 정상 응답**했다(2.6초). 꺼져 있었다면 한 번도 답하지 않는다.
- 그 뒤 연속 호출이 429가 되고, **1시간 뒤 10초 간격 6회 재시도에서도 6/6 전부 429**였다.
  짧은 순간 제한이 아니라 몫이 바닥난 상태가 유지된다.
- 콘솔 번들에 이 상황 전용 안내창이 들어 있다:
  `dialog.usageExceeded.freeTier.title` = **"Free limit reached"**.
  즉 무료 티어는 스위치가 아니라 **소진되는 몫**이다.
- **워크스페이스 화면에 잔여 무료 사용량 표시가 없다**(오너 확인). 얼마 남았는지도, 언제 차는지도
  알 수 없다. 볼 수 없는 한도 위에는 제품을 세울 수 없다.
- 소진 속도: **오늘 측정 한 사람이 하루치를 다 썼다.** 교사 여러 명이 동시에 쓰는 구조에서는
  의미 있는 양이 아니다.

### 새로 발견된 선택지 — OpenCode Go (채택하지 않음)

무료 한도 안내창이 사용자에게 권하는 해법이 이것이다:

> "Subscribe to OpenCode Go for reliable access to the best open-source models, starting at $5/month."

앞서 정체를 몰랐던 별도 엔드포인트 `/zen/go/v1` 이 이 구독이다. **26종**을 포함하며
그중에 우리가 권하는 `minimax-m3` 도 있다(일반 Zen 은 62종).

**그럼에도 채택하지 않는다:**

- 같은 콘솔에 `dialog.usageExceeded.accountRateLimit.title` = **"Go limit reached"** 안내창이
  따로 있다. Go 에도 사용 한도가 있다.
- 이것은 **개발자 1인 구독**이지, 서버 한 곳이 교사 수천 명의 요청을 대신 보내는 용도가 아니다.
  사전 부검(§11)이 최대 위험으로 꼽은 **"재판매로 간주되어 키 정지"** 에 정면으로 걸린다.

### 결론

**종량제(pay-as-you-go)로 간다.** 위험이 없고, 이미 실측된 대로 교사 1,000명이 하루 5건씩
써도 월 $83 이다. 충전한 $20 만으로도 `minimax-m3` 기준 약 24,000건이다.

## 6. 남은 위험

- **무료 모델 계획은 폐기 확정**(§5-2). 소진되는 몫인데 잔량 표시조차 없다.
  계획서 §8.4(유료 전환 대비)가 아니라 **처음부터 유료가 전제**다.
- **자동 재충전.** 잔액이 $5 아래로 가면 $20이 자동 결제된다. 반드시 끄거나 월 상한을 걸 것.
  중계 구조는 전 사용자 요청이 키 하나로 몰리므로, 상한이 유일한 제동 장치다.
- **재판매 간주 위험(사전 부검 §11).** 키 하나로 다수 최종 사용자를 중계하는 것에 대한 조항이
  약관에 없다. 규모가 커지기 전에 문의해 두는 편이 안전하다.
- **개인정보.** 유료 모델은 "무료 기간 데이터가 학습에 쓰인다"는 문구의 적용을 받지 않지만,
  재위탁 대상·국외 이전 표는 실제 상류 제공자 기준으로 다시 확인해야 한다
  (법인 소재지가 아니라 재위탁 대상으로 판단 — 과거 오판 사례 있음).
