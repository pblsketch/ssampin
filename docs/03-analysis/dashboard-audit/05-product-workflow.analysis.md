## A. 교사 일과 시뮬레이션

> 페르소나: 김선생 (중학교 국어 담임, 경력 10년, 2학년 3반 담임 + 5개 반 수업)

---

### [P0] 출근 직후(08:00) — 시간표가 첫 화면에 있으나 "지금 몇 교시"가 불명확

- **사용자 시나리오**: 교실 PC를 켜자마자 오늘 시간표, 날씨, 긴박한 일정을 30초 안에 파악하고 싶다.
- **현재 상태**: 메인 대시보드에 Clock(날짜+시각) + WeatherBar + MessageBanner가 상단에 있고, 아래 위젯 그리드에 시간표 카드(DashboardTimetable)가 배치된다. 08:00 시점은 수업 전이므로 `getCurrentPeriod()`가 null을 반환 — 현재 교시 하이라이트가 없다. 시간표 위젯은 오늘 요일의 교사 시간표를 목록으로 보여주고, 첫 수업까지 남은 시간이나 "수업 시작까지 N분" 정보는 어디에도 없다.
- **문제/기회**: 교사가 가장 먼저 알고 싶은 정보는 "첫 교시 언제 시작이지?"인데 이 계산을 교사 머릿속에서 직접 해야 한다. 시간표 위젯에는 교시별 시작/종료 시각이 표시되지만 잔여 시간 표시가 없어 인지 부하가 발생한다.
- **개선안**: 수업 시작 전 구간(`currentPeriod === null && 다음 교시까지 N분 이내`)에 시간표 위젯 헤더에 "1교시까지 N분" 카운트다운 칩을 소형으로 표시. 첫 교시 셀에 보조 하이라이트(선 색상 변경 수준)를 추가하면 클릭 없이 바로 인지 가능.
- **메트릭 제안**: 출근 시간대(07:30~08:30) 사용자 세션 평균 체류 시간. 현재보다 20% 단축되면 성공.

---

### [P0] 수업 직전(08:50, 09:50...) — 현재 교시 하이라이트는 동작하나 "다음 교시" 정보가 없다

- **사용자 시나리오**: 쉬는 시간 10분 동안 현재 어느 반에 있는지, 다음에 어느 교실로 이동해야 하는지 빠르게 확인하고 싶다.
- **현재 상태**: `currentPeriod`가 계산되어 해당 행에 `border-l-4 border-sp-highlight` + `ring-2 ring-sp-highlight/30` + 펄스 애니메이션이 적용된다(DashboardTimetable.tsx:250-254). 교사 시간표 모드에서는 학급명도 표시된다. 그러나 목록이 위에서 아래로 흐르기 때문에 현재 교시가 시야 밖에 있으면 스크롤 없이 보이지 않는다. "다음 교시" 강조는 없다.
- **문제/기회**: 교사는 "지금 이 교시" 뿐 아니라 "다음 수업 어디로 가야 하나"가 중요하다. 교사 시간표에 'next' 교시 표기가 없으면 매번 한 줄씩 내려 읽어야 한다. 7교시짜리 시간표라면 현재 교시가 5교시일 때 스크롤이 필요할 수 있다.
- **개선안**: (1) 현재 교시를 위젯 상단에 자동 스크롤(auto-scroll-into-view). (2) 다음 교시에 보조 테두리 강조(예: `border-l-2 border-sp-accent/50`)를 추가. (3) 시간표 위젯 헤더 영역에 "현재: 3교시 수학 / 다음: 4교시 영어 (B동 2-5)" 요약 한 줄 고정 표시.
- **메트릭 제안**: 시간표 위젯 내 스크롤 발생 비율 측정. 수업 전 10분 구간에 스크롤이 사라지면 성공.

---

### [P1] 수업 중(위젯 모드) — "흘낏 봄" 목적은 달성되지만 학급별 맥락 전환이 없다

- **사용자 시나리오**: 수업 중 자리배치, 출석부, 간단한 메모를 위젯 창에서 눈으로만 참조하고 싶다. 다른 창으로 전환 없이 10초 이내에 원하는 학생 이름이나 자리를 확인.
- **현재 상태**: 위젯 모드(Widget.tsx)는 투명 배경(opacity 기본 설정)에 드래그 이동, 리사이즈, always-on-top으로 동작한다. 자리배치(Seating), 담임 메모장(StudentRecords) 위젯이 존재한다. 그러나 수업 중 "현재 수업 중인 학급"을 기준으로 위젯 데이터가 전환되는 컨텍스트 스위치 기능이 없다. 교과 교사가 2-1, 2-3, 3-2 를 순서대로 가르친다면 각 수업마다 자리배치 위젯이 자동으로 해당 학급으로 바뀌지 않는다.
- **문제/기회**: 위젯 모드의 핵심 약속은 "흘낏 봄"인데 학급 전환이 수동이라면 실제 수업 중 가치가 반감된다. 자리배치 위젯을 열어도 이전 학급 배치를 보여주면 혼란이 발생한다.
- **개선안**: 현재 교시에 맞는 학급을 교사 시간표에서 자동으로 읽어 `Seating`·`StudentRecords` 위젯의 기본 학급을 자동 선택. 교과 교사(담임 아님)에게도 적용. 이미 `getEffectiveTeacherSchedule()`이 교시별 classroom을 반환하므로 연결이 가능하다.
- **메트릭 제안**: 수업 중 구간에 위젯 내 학급 수동 전환 버튼 클릭 수. 자동화 후 해당 클릭이 80% 감소하면 성공.

### [P1] 쉬는 시간(10분) — 할일 체크와 학생 상담 메모는 잘 되어 있으나 접근 경로가 분산

- **사용자 시나리오**: 쉬는 시간 학생 상담 내용을 빠르게 메모하고 오늘 할 일 체크.
- **현재 상태**: 대시보드에 DashboardTodo(할 일)와 DashboardStudentRecords(담임 메모) 위젯이 있다. 담임 메모 위젯은 오늘 기록을 탭(전체/출결/상담/생활) 분리로 보여준다. 그러나 "빠른 메모 추가" 경로가 위젯 내에서 직접 제공되지 않고 `/homeroom` 페이지로 이동해야 한다.
- **문제/기회**: 쉬는 시간 10분 중 교사가 앱을 열고 페이지를 이동하고 학생을 선택하고 카테고리를 고르는 흐름은 3~4클릭이다. 위젯 모드에서는 IPC를 통해 메인 창 페이지로 이동할 수 있지만 위젯에서 직접 기록 입력 UI가 없어 반드시 전환이 필요하다.
- **개선안**: (1) 담임 메모장 위젯에 "학생 선택 + 카테고리 + 메모" 인라인 빠른 입력 폼 추가 (위젯 내 축약 UI). (2) 또는 Ctrl+K Quick Add(이미 v2.0.0에 존재)에서 학생 기록 빠른 추가 지원.
- **메트릭 제안**: 수업 시간 후 10~20분 구간의 학생 기록 신규 생성 수. 증가하면 접근성 개선 성공.

---

### [P2] 점심 시간 — 급식 메뉴 위젯은 있으나 "오늘 메뉴"가 최우선 노출되지 않는다

- **사용자 시나리오**: 점심 직전 급식 메뉴를 보고 싶다. 식당까지 걸어가기 전 30초 안에 확인.
- **현재 상태**: DashboardMeal 위젯이 존재하며 NEIS API와 수동 입력을 지원한다. DateNavigator로 다른 날짜도 조회 가능하다. 그러나 메인 대시보드 기본 프리셋에서 급식 위젯의 우선순위 위치가 고정되어 있지 않고 위젯 그리드 내 사용자가 임의 배치한 위치에 있다.
- **문제/기회**: 급식 정보는 점심 직전 1~2분 참조 용도다. 이미 위젯이 존재하므로 접근 자체는 문제없다. 다만 NEIS 미연동 사용자 또는 수동 등록 않은 사용자에게 급식 위젯이 "급식 정보가 없습니다" 빈 상태만 표시하면 위젯이 공간 낭비가 된다.
- **개선안**: 급식 정보가 없을 때 빈 상태 메시지를 "NEIS 학교 코드 등록 → 자동 연동" 단계 안내 포함 CTA로 교체. 점심 시간(11:30~13:30)에는 급식 위젯 헤더를 강조하거나 알림 도트를 표시.
- **메트릭 제안**: 급식 위젯 "NEIS 연동 유도" CTA 클릭률.

---

### [P1] 방과 후 — 내일 준비와 학부모 연락 흐름이 메인 대시보드에서 지원 안 됨

- **사용자 시나리오**: 방과 후 담임 메모 정리, 내일 시간표 확인, 학부모 연락 항목 체크.
- **현재 상태**: DashboardTimetable에 DateNavigator가 있어 내일 날짜로 이동해 시간표를 미리 볼 수 있다. 담임 메모는 오늘 날짜 기준으로만 표시된다(`today = todayString()`). 할 일 위젯은 overdue/today/future 구분이 있으나 대시보드 위젯에서 "내일 할 일"만 필터링하는 뷰는 없다.
- **문제/기회**: "내일 준비" 컨텍스트를 대시보드에서 전환하는 방법이 없다. 교사는 방과 후 내일 수업 준비를 하면서 "내일 시간표 → 내일 할 일 → 내일 일정" 세 가지를 함께 봐야 하는데 각 위젯이 독립적으로 날짜 상태를 가진다.
- **개선안**: 대시보드 헤더에 "오늘/내일" 전역 날짜 컨텍스트 토글을 추가. 토글 시 시간표·이벤트·할 일 위젯이 동시에 내일 날짜로 전환. 현재 DateNavigator가 각 위젯에 독립적으로 구현되어 있으므로, 전역 `viewDate` zustand 슬라이스 도입이 필요.
- **메트릭 제안**: 방과 후 구간(15:00~18:00) 위젯별 날짜 탐색 클릭 수. 전역 토글 도입 후 개별 위젯 탐색 클릭이 감소하면 성공.

## B. 정보 우선순위 (Information Hierarchy)

### [P1] 메시지 배너가 시계와 나란히 놓여 시각 위계 최상단을 과점한다

- **사용자 시나리오**: 대시보드를 열었을 때 가장 중요한 정보(현재 교시)를 즉각 인지하고 싶다.
- **현재 상태**: design examples/ssampin_main_dashboard/screen.png를 확인하면 헤더 좌측에 날짜/시각(대형 텍스트), 우측에 MessageBanner(전체 너비의 약 50%)가 배치된다. 시각적 면적 기준으로 메시지 배너가 현재 교시 위젯과 동등하거나 더 큰 공간을 차지한다. 그 아래 위젯 그리드에 시간표·좌석배치·이번 주 일정이 세 열로 배치된다.
- **문제/기회**: PRD의 정보 우선순위는 ① 현재 교시 ② 오늘 일정 ③ 메모/할일 ④ 날씨/메시지 순이어야 한다. 그런데 메시지 배너가 헤더 전면에 나와 있어 실제 정보 위계와 시각 위계가 역전된다. MessageBanner는 교사가 매일 수동 입력하는 정보고 수업 진행 현황보다 낮은 우선순위여야 한다.
- **개선안**: MessageBanner를 헤더에서 분리해 위젯 그리드 상단 전폭 슬롯으로 이동(선택 위젯으로 구성). 헤더는 Clock + WeatherBar만 남겨 인지 밀도를 낮춘다. 또는 MessageBanner 기본값을 `collapsed=true`로 설정해 한 줄 요약만 보이게 한다.
- **메트릭 제안**: 헤더 영역 시선 체류 시간(eye-tracking 대용: hover 이벤트 분포). 시간표 위젯 카드로 시선이 먼저 이동하는 비율 개선.

---

### [P2] 위젯 카드 기본 크기가 정보 우선순위를 반영하지 않는다

- **사용자 시나리오**: 처음 앱을 설치하고 대시보드를 열면 가장 중요한 정보가 가장 크게 보여야 한다.
- **현재 상태**: registry.ts에서 `weekly-timetable`은 `defaultSize: { w: 2, h: 5 }`, `today-class`는 `{ w: 1, h: 4 }`, `meal`은 `{ w: 1, h: 3 }`, `todo`는 `{ w: 1, h: 3 }`으로 정의된다. 프리셋 배열(presets.ts) 순서가 위젯 배치 순서를 결정한다. 중학교 담임 프리셋은 `['weekly-timetable', 'today-class', 'seating', 'favorite-tools', 'today-progress', 'meal', 'events', 'dday-counter', 'memo', 'student-records', 'survey', 'consultation', 'todo']`로 13개다. 4열 그리드에 13개 위젯이 올라가면 초기 화면에서 모든 위젯을 볼 수 없어 스크롤이 필요하다.
- **문제/기회**: 중학교 담임 기준 13개 위젯은 화면 밀도가 높다. 가장 중요한 `weekly-timetable`이 2열 5행을 차지하더라도 나머지 위젯들이 압박해 정보 우선순위가 시각적으로 흐려진다.
- **개선안**: 기본 프리셋을 "핵심 3~5개" 슬림 버전으로 줄이고, 이후 사용자가 직접 추가하도록 유도. 또는 위젯 그리드 상단 고정 슬롯(Pinned row)에 시간표/현재교시만 고정 표시하고 나머지는 스크롤 영역으로 분리.
- **메트릭 제안**: 첫 실행 후 위젯 제거 비율(사용자가 불필요한 위젯을 제거한 수). 높으면 기본 프리셋 과다.

---

### [P3] WidgetSettingsPanel에서 위젯 순서 변경은 가능하나 중요도 프리셋이 없다

- **사용자 시나리오**: 설정을 열어서 자신에게 맞게 위젯을 재배치하고 싶다.
- **현재 상태**: WidgetSettingsPanel 탭 "위젯 구성"에서 드래그 앤 드롭으로 순서 변경, 위젯 추가/제거가 가능하다. "스타일" 탭에서 테마 색상과 폰트 설정도 가능하다.
- **문제/기회**: 사용자가 원하는 배치를 처음부터 탐색하려면 위젯 이름(텍스트)만 보고 판단해야 한다. 각 위젯의 실제 모양 미리보기가 없으며 "담임에게 추천", "교과 교사에게 추천" 같은 설명이 없어 선택 기준이 불분명하다.
- **개선안**: WidgetSettingsPanel "위젯 구성" 탭에 위젯별 카드 미리보기(썸네일) 또는 역할별 추천 배지를 추가. 온보딩에서 선택한 역할(homeroom/subject)을 기준으로 "선생님께 추천" 아이콘을 달아 발견성을 높인다.
- **메트릭 제안**: 위젯 추가 패널 열람 후 실제 위젯 추가 전환율.

### [P1] 빈 위젯의 empty state 메시지가 통일되어 있지 않다

- **메트릭 제안**: 건너뛰기 선택 사용자 중 7일 내 NEIS 연동 완료율.

## D. 위젯 모드 가치 명확성

### [P0] 위젯 모드 전환 어포던스가 숨겨져 있다

- **사용자 시나리오**: 처음 쌤핀을 설치한 교사가 "위젯 모드"가 무엇인지, 어디서 켜는지 알고 싶다.
- **현재 상태**: 위젯 모드 전환은 다음 경로들로만 가능하다: (a) Widget.tsx 헤더 우측 "전체 화면으로 전환" 버튼(open_in_full 아이콘), (b) WidgetContextMenu 우클릭 > "전체 화면으로 전환", (c) 더블클릭. 메인 대시보드에서 위젯 모드로 진입하는 버튼이 사이드바나 헤더에 눈에 띄게 존재하지 않는다(PRD FR-WIDGET-01: "타이틀바 또는 트레이 메뉴"라고 되어 있으나 구현 확인 필요).
- **문제/기회**: PRD의 핵심 차별화 기능인 위젯 모드를 대다수 신규 사용자가 발견하지 못할 가능성이 높다. 위젯 모드를 한 번도 사용하지 않으면 "항상 띄워두는 교사 대시보드"라는 제품 포지셔닝 자체가 실현되지 않는다.
- **개선안**: (1) 사이드바 하단 또는 헤더 우상단에 "위젯 모드 켜기" 버튼을 1클릭으로 상시 노출. (2) 온보딩 완료 후 첫 대시보드 진입 시 "위젯 모드 소개" 1회성 툴팁/코치마크. (3) 위젯 모드의 가치 — "수업 중에도 모니터 한쪽에서 자리배치·메모 흘낏 확인" — 를 온보딩에서 명시적으로 설명.
- **메트릭 제안**: 위젯 모드 최초 활성화율(설치 후 7일 내). 현재 `track('widget_open')`이 있으므로 측정 가능.

### [P1] 배경 투명도 기본값 80%는 실용적이나 사용자가 인지하지 못한다

- **사용자 시나리오**: 위젯 모드를 켜고 투명도를 조절하려 한다.
- **현재 상태**: Widget.tsx에서 `settings.widget.opacity`를 CSS rgba에 적용한다. 기본값은 Settings에서 설정하며 PRD 기준 80%. WidgetContextMenu(design examples/ssampin_widget_context_menu/screen.png)에 "투명도 조절" 슬라이더(0~100%)가 확인된다. 위젯 편집 버튼(edit 아이콘)이 위젯 헤더 우측에 있지만 작은 아이콘이라 초보 사용자에게 발견성이 낮다.
- **문제/기회**: 위젯 투명도는 교실 프로젝터 화면에 올려두는 데 중요한 설정이다. "배경 뒤로 보내서 반투명하게"가 핵심 UX인데 우클릭(ContextMenu)을 모르면 평생 불투명 상태로 쓸 수 있다.
- **개선안**: 위젯 최초 실행 시 1회성 안내: "우클릭해서 투명도를 조절하세요". 또는 위젯 헤더에 투명도 슬라이더를 직접 노출하거나, 헤더의 설정 버튼 클릭 시 투명도 슬라이더가 포함된 드롭다운 표시.
- **메트릭 제안**: 위젯 투명도 조절 사용률(기본값 80%에서 변경한 사용자 비율).

### [P1] 32개 위젯의 발견성 — 탭 필터는 있지만 역할별 추천이 없다

- **사용자 시나리오**: 위젯 편집 패널을 열어 "내게 맞는 위젯"을 찾으려 한다.
- **현재 상태**: WidgetSettingsPanel "위젯 구성" 탭에서 카테고리별(시간표/학급/정보/관리) 목록으로 위젯을 표시한다. 각 위젯에는 `availableFor.role` 필터가 정의되어 있으나(registry.ts), 현재 사용자의 역할(담임/교과/행정)로 필터링해서 "선생님께 추천" 뱃지를 보여주는 기능이 없다.
- **문제/기회**: 위젯이 19종(registry.ts 확인, image-sticker 4종 제외 시 15종 기능 위젯)이라 목록이 길다. 담임 교사에게 SeatingChart가 중요하지만 교과 교사에게는 불필요하다. 탭 필터만으로는 이 구분이 안 된다.
- **개선안**: 위젯 목록 상단에 "선생님 역할에 맞는 위젯" 섹션을 추가. 온보딩에서 입력한 역할(homeroom/subject)을 기준으로 상위 3~5개 위젯을 추천. `availableFor.role` 데이터가 이미 있으므로 렌더링 로직만 추가하면 된다.
- **메트릭 제안**: 위젯 발견(추가) 다양성 — 1인당 평균 활성 위젯 종류 수.

### [P2] 4종 레이아웃(full/split-h/split-v/quad)의 차별화가 직관적으로 인지되지 않는다

- **사용자 시나리오**: LayoutSelector를 열어 레이아웃을 선택하려 한다.
- **현재 상태**: LayoutSelector에 전체화면/좌우분할/상하분할/4분할 4개 옵션이 있고 각 옵션에 미니 SVG 아이콘 + 이름 + 단축키(Ctrl+1~4)가 표시된다. 아이콘은 직사각형 윤곽선으로 레이아웃 형태를 암시한다.
- **문제/기회**: 레이아웃의 실제 의미(각 분할에 위젯이 어떻게 배치되는지)를 SVG 아이콘만으로 파악하기 어렵다. "좌우 분할"이 무엇을 의미하는지(두 위젯이 나란히? 두 그룹이 나란히?) 선택 전에 알 수 없다.
- **개선안**: LayoutSelector에 각 레이아웃의 실제 위젯 배치 미리보기 썸네일 추가. 또는 선택 시 실시간 미리보기. 4분할 모드에서 현재 0.7배 scale 축소가 적용되는데(Widget.tsx:314), 글자가 너무 작아질 수 있으므로 최소 가독성 보장 가이드라인 필요.
- **메트릭 제안**: 레이아웃 선택 후 5분 내 재변경 비율. 높으면 선택 단계에서 이해 부족.

### [P2] 메인 대시보드 ↔ 위젯 데이터 동기화가 실시간으로 작동하나 사용자가 인지 못 한다

- **사용자 시나리오**: 메인 앱에서 메모를 수정하고 위젯 모드를 보면 즉시 반영되기를 기대한다.
- **현재 상태**: DashboardTimetable.tsx에 `window.electronAPI?.onDataChanged` IPC 이벤트 구독이 구현되어 있다. 파일 변경 감지 시 store를 reload한다. 기술적으로 실시간 동기화가 된다.
- **문제/기회**: 동기화가 되더라도 사용자가 이를 인지하지 못하면 신뢰감을 주지 못한다. 특히 처음 위젯 모드를 사용할 때 "이 데이터가 최신인가?" 불안이 있을 수 있다.
- **개선안**: 위젯 헤더에 "마지막 업데이트 N초 전" 미세한 타임스탬프 표시. 또는 데이터가 갱신될 때 위젯 카드에 1초짜리 flash 효과. 이미 있는 "새로고침 버튼"(refresh 아이콘)의 위치를 더 눈에 띄게 조정.
- **메트릭 제안**: 위젯 내 수동 새로고침 버튼 클릭 빈도. 낮을수록 자동 동기화 신뢰도 높음.

## E. 한국 교사 컨텍스트 적합성

### [P1] 9개 교과 컬러만 정의되어 정보/진로/한국사 등 미매핑 교과가 회색으로 처리된다

- **사용자 시나리오**: 정보, 한국사, 진로, 경제, 윤리 등을 가르치는 교사가 시간표 컬러 구분을 사용하려 한다.
- **현재 상태**: CLAUDE.md에 정의된 9개 교과(국어=yellow, 영어=green, 수학=blue, 과학=purple, 사회=orange, 체육=red, 음악=pink, 미술=indigo, 창체=teal)만 색상이 매핑된다. registry.ts에 `subjectColors?: SubjectColorMap`로 커스텀 가능하다고 되어 있으나 기본 매핑 외 교과는 `text-sp-text` 기본색이 적용된다.
- **문제/기회**: 2022 개정 교육과정 기준 중학교 과목 수는 20종 이상, 고등학교는 더 많다. 9개 기본 교과 외 교과를 가르치는 교사에게 시간표 컬러 구분이 작동하지 않아 핵심 UI 기능이 반쪽짜리가 된다.
- **개선안**: (1) 설정 > 시간표에서 교과명과 색상 커스텀 매핑 UI 제공(이미 `SubjectColorMap` 타입이 있음). (2) 자주 쓰는 추가 교과(정보, 한국사, 진로, 도덕, 가정, 기술, 경제, 법과정치, 사회문화 등) 확장 기본 매핑 추가. (3) 미매핑 교과는 교과명의 해시값으로 색상 자동 배정(색상 충돌 완전 제거는 불가능하나 완전 단색보다 유용).
- **메트릭 제안**: 설정에서 교과 색상 커스텀 설정한 사용자 비율.

---

### [P1] 담임 vs 교과 교사 역할 차이가 onboarding에서는 구분되나 위젯 실시간 필터링에서는 약하다

- **사용자 시나리오**: 교과 교사(담임 아님)가 앱을 설치하고 담임 전용 위젯(자리배치, 담임메모장, 설문, 상담)이 안 보이길 원한다.
- **현재 상태**: registry.ts의 `availableFor.role: ['homeroom']` 필터가 있다. presets.ts에서 역할별로 다른 위젯 집합이 프리셋으로 제공된다(high-subject에는 seating, student-records, survey, consultation이 없다). 그러나 이미 프리셋이 적용된 사용자가 역할을 바꾸면 프리셋이 재적용되지 않는다.
- **문제/기회**: 연도 중에 담임에서 교과 전용으로 바뀌거나, 반대의 경우, 위젯 설정이 자동 업데이트되지 않아 불필요한 위젯이 남게 된다. `availableFor.role` 데이터가 있음에도 런타임 필터링이 적극적으로 활용되지 않는다.
- **개선안**: 설정 > 기본 정보에서 역할 변경 시 "위젯 프리셋을 역할에 맞게 재구성하시겠습니까?" 확인 모달 제공. 기존 커스텀 배치는 보존 옵션 제공.
- **메트릭 제안**: 역할 변경 후 위젯 구성 변경 비율.

### [P0] 학생 이름·학번이 위젯 모드에서 항상 노출 — 개인정보 보호 우려

- **사용자 시나리오**: 교실에서 위젯 모드를 항상 띄워두고 있을 때 학생들이 다른 학생의 상담 기록이나 출결 기록을 보는 상황.
- **현재 상태**: DashboardStudentRecords는 학생 이름 + 기록 내용(출결 사유, 상담 메모)을 위젯에 바로 표시한다. 자리뽑기 학생 노출 금지 정책(메모리: feedback_seat_picker_private_no_student_exposure.md)이 이미 적용되어 있으나, 위젯의 담임 메모장 내용에 대한 유사 보호 정책이 없다.
- **문제/기회**: 교실 PC 화면에 상담 기록("결석 사유: 병원 방문", "상담: 가정 불화")이 프로젝터로 나오면 학생 인권 및 개인정보보호법 위반 가능성이 있다. 실제 수업 상황에서 교사가 위젯 모드를 켜 두면 학생들이 이 화면을 볼 수 있다.
- **개선안**: (1) 담임 메모장 위젯에 "개인정보 가리기" 토글 버튼 추가 — 학생 이름 이니셜 처리(예: "김○○"), 기록 내용 블러 처리. (2) 프로젝터 모드 개념 도입: 사이드바 또는 위젯 메뉴에 "프로젝터 모드" 토글을 두고, 활성화 시 개인 식별 정보가 모두 숨겨짐. (3) 위젯 모드 최초 실행 시 "개인 정보가 포함된 위젯이 있습니다. 프로젝터/공개 화면에서 사용 시 주의하세요" 경고 1회 표시.
- **메트릭 제안**: 담임 메모장 위젯 활성화 사용자 중 개인정보 가리기 기능 사용률.

### [P2] D-Day 알림 정책(D-3, D-1, D-0)이 한국 학사력의 장기 준비 일정에 부족하다

### [P3] 학교급(초/중/고) 구분이 위젯 기본 설정에는 반영되나 교시 시간 자동 설정이 부족하다

- **문제/기회**: 초등학교 교시 시간(40분 수업, 10분 쉬는시간)과 중·고등학교(45분~50분 수업)는 다르다. 또한 초등은 블록 수업, 오전·오후 구분이 다르다. 학교급 선택 후 교시 설정 step에서 이 차이가 명확히 안내되지 않을 수 있다.

- **메트릭 제안**: 온보딩 후 교시 시간 수정 비율(높으면 기본값 부적합 신호).

## F. 새로 추가할 만한 기능 / 빠진 워크플로우

### [P1] 출석 빠른 입력 위젯이 없다

- **사용자 시나리오**: 수업 시작 직후 출석을 확인하고 결석/지각 학생을 빠르게 기록하고 싶다.
- **현재 상태**: 담임 메모장(`/homeroom`)에 출결 기록 기능이 있다. 그러나 위젯 모드에서 직접 출결 입력이 불가능하다. StudentRecords 위젯은 오늘 기록을 조회만 할 수 있고 신규 입력 UI가 없다.
- **문제/기회**: 수업 시작 후 1분 내에 출석을 확인하는 루틴이 있다. 이 순간 위젯 모드에서 바로 "홍길동 결석" 한 줄 입력이 가능하면 메인 앱 전환 없이 처리할 수 있다.
- **개선안**: 위젯 모드 StudentRecords 위젯에 "빠른 출결 입력" 미니 폼 추가. 학생 선택(드롭다운) + 출결 유형(지각/결석/조퇴 버튼) → 저장. 현재 교시 학급을 자동 선택.
- **메트릭 제안**: 위젯 모드에서 출결 기록 입력 수 증가율.

### [P2] 실시간 담벼락(v2.0.0 신규)이 대시보드에서 발견되지 않는다

- **현재 상태**: registry.ts에 실시간 담벼락 위젯이 없다. 사이드바에 담벼락 메뉴가 있겠지만 대시보드 위젯으로는 노출되지 않는다. v2.0.0의 주요 신규 기능임에도 대시보드에서 "담벼락에 새 글이 있습니다" 같은 알림 위젯이 없다.
- **문제/기회**: 실시간 담벼락은 학생 참여 기능이다. 교사가 수업 중 위젯 모드를 켜 두면서 학생들이 담벼락에 올린 내용을 흘낏 확인할 수 있으면 수업 인터랙션 가치가 높다. 그러나 진입점이 없으면 사용 빈도가 낮아진다.
- **개선안**: 실시간 담벼락 알림 위젯 추가(최신 N개 포스트 미리보기, 새 글 알림 배지). 또는 DashboardEvents 위젯에 담벼락 활동 요약 표시.
- **메트릭 제안**: 담벼락 기능 주간 활성 사용자 수.

- **개선안**: 대시보드 헤더 또는 사이드바 하단에 "Ctrl+K 빠른 추가" 힌트 텍스트를 한 줄로 표시. 또는 온보딩 완료 후 1회성 토스트 "Ctrl+K를 누르면 빠르게 항목을 추가할 수 있습니다".

## G. 메인 vs 위젯 가치 차별화 평가

### [P1] 위젯 모드가 "축소판"에 머물 위험이 있다

- **사용자 시나리오**: 위젯 모드를 켰을 때 메인 앱을 작게 줄인 것 이상의 차별화된 가치를 느끼고 싶다.
- **현재 상태**: 위젯 모드는 메인 대시보드와 동일한 위젯 컴포넌트(registry.ts)를 공유한다. 레이아웃 4종과 0.7~0.85배 scale 축소가 차별화 요소다. 컨텍스트 메뉴(우클릭)로 투명도·always-on-top·크기 조절이 가능하다. 그러나 위젯 모드 전용 기능(현재 수업 학급 자동 컨텍스트, 프로젝터 모드, 출석 빠른 입력 등)이 없어 메인 앱의 "소형 버전" 수준에 그친다.
- **문제/기회**: 위젯 모드의 PRD 포지셔닝은 "바탕화면에 항상 띄워두는 상시 모니터링용"이다. 이것이 진정한 차별점이 되려면 위젯 모드에서만 가능한 UX가 있어야 한다. 현재는 메인 앱을 작게 만든 것과 기능적으로 동일하다.
- **개선안**: 위젯 모드 전용 기능 3가지를 우선 추가: (1) 현재 교시 학급 자동 컨텍스트(앞서 기술), (2) 프로젝터 모드(개인정보 블러), (3) "수업 타이머" 미니 위젯(남은 교시 시간 카운트다운). 이 세 가지가 위젯 모드의 독자적 가치를 만든다.
- **메트릭 제안**: 위젯 모드 일일 평균 사용 시간(메인 앱 사용 시간 대비). 위젯이 "항상 켜져 있는" 상태가 되면 성공.

---

### [P2] 메인 대시보드의 가치 — "깊은 작업" 경로가 위젯 카드 클릭 외에 없다

- **사용자 시나리오**: 메인 대시보드에서 일정 관리나 학생 기록 작업을 시작하려 한다.
- **현재 상태**: WidgetCard에는 `navigateTo` 속성이 있어 카드 헤더 또는 특정 버튼 클릭 시 해당 페이지로 이동한다. 그러나 위젯 카드에서 직접 데이터를 편집하는 "인라인 편집" 기능이 대부분 없다(MessageBanner 인라인 편집이 유일한 예외).
- **문제/기회**: 메인 대시보드의 가치는 "한 화면에서 모든 것을 보면서 필요하면 깊이 들어가는" 것이다. 현재는 위젯이 순수한 읽기 전용 미리보기여서 할 일 체크, 메모 추가, 일정 추가 등 모두 페이지 이동 필요. 이는 "대시보드의 가치 = 깊은 작업 진입 허브"로 제한한다.
- **개선안**: 핵심 위젯에 인라인 액션 추가: Todo 위젯에 체크박스 직접 클릭 완료 처리, Events 위젯에 "일정 추가" 빠른 폼(날짜+제목만), Memo 위젯에 "메모 추가" 버튼. 이미 Ctrl+K Quick Add가 있으므로 위젯 헤더에 "+" 버튼으로 동일 Quick Add 트리거.
- **메트릭 제안**: 대시보드에서 직접 완료 처리된 할 일 비율 vs. 할 일 페이지에서 완료 처리 비율.
