- 조사일: 2026-09-09 KST
- 범위: 자료 조사와 제품 방향 제안. 구현·배포·결정 변경 없음.
- 결론: 기존형을 포함한 8종을 후보로 두고, 기록 영역과 보유 근거에 따라 선택하도록 제안한다. 아래 이름·순서는 공식 지정 양식이 아니라 자료를 바탕으로 재구성한 쌤핀 제안이다.

## 3. 템플릿 후보 8종

아래는 제품 제안이다. 문장 틀을 채우기 위해 사실을 만들지 않는다. ‘선택’ 요소는 근거가 있을 때만 넣는다.

| 후보                       | 권장 구성                                                                 | 어울리는 기록                           | 선택에 필요한 근거                                                                     |
| -------------------------- | ------------------------------------------------------------------------- | --------------------------------------- | -------------------------------------------------------------------------------------- |
| 1. 교사 평가 먼저 — 기존형 | 교사의 핵심 판단 → 동기·질문 → 과정 → 결과                                | 탐구 흐름이 충분한 세특·동아리          | 첫 판단을 뒷받침할 실제 활동과 수행. 동기는 확인된 경우만                              |
| 2. 성취 중심형             | 할 수 있게 된 것 → 이를 보여 준 수행 → 교과적 특성·역량                   | 일반 수업·수행평가 세특, 초등 교과 기록 | 성취기준과 연결되는 학생의 구체적인 응답·산출물·수행                                   |
| 3. 질문·탐구형             | 질문·문제 인식 → 탐색·분석 → 발견·해석 → 교사 평가                        | 실험·조사·탐구 수업                     | 실제 제기한 질문, 탐구 방법, 도달한 결과. 후속 질문은 선택                             |
| 4. 피드백·성장형           | 처음 수행 → 받은 피드백 → 수정·재시도 → 확인된 변화                       | 글쓰기·발표·문제 해결·실기              | 시점이 구별되는 전후 수행과 피드백. 처음 상태를 결핍으로 꾸미지 않음                   |
| 5. 과제·문제 해결형        | 과제·문제 → 판단·전략 → 실행·조정 → 결과·평가                             | 프로젝트·제작·실천 활동                 | 학생 개인의 선택과 실행. 팀 전체 성과를 개인 성과로 바꾸지 않음                        |
| 6. 협업·기여형             | 공동 과제 → 개인의 역할·행동 → 상호작용 → 공동 결과에 대한 기여           | 모둠 수업·자율·자치·동아리              | 실제 역할 수행, 의견 조정·도움·기여 장면. 갈등 해결은 실제 있을 때만                   |
| 7. 진로 탐색형             | 관심 분야 → 탐색 활동 → 자기 이해·판단 → 다음 탐색 방향(선택)             | 진로활동                                | 학교 교육활동·상담 등에서 확인된 탐색 과정. 희망 직업 확정과 진로 변경을 강요하지 않음 |
| 8. 생활·관계 종합형        | 지속적으로 나타난 특성 → 대표 생활 장면들 → 관계·책임·자기관리 → 종합의견 | 행동특성 및 종합의견                    | 일정 기간의 반복 관찰. 단일 사건으로 성격을 단정하거나 성장 서사를 만들지 않음         |

근거 연결: 2번은 공식 예시집의 구성 요소에 가장 가깝다. 3~5번은 수행 과정·결과 및 성장 기록을 수업 유형에 맞게 나눈 제안이다. 6~8번은 훈령의 창체·진로·행특 기록 목적을 반영한 제안이며, 공식적으로 이름 붙은 템플릿은 아니다.

독서·토론·실험·예체능은 별도의 대등한 서술 구조를 계속 추가하기보다 위 템플릿의 활동별 설정으로 제공하는 편이 낫다. 예를 들어 토론은 탐구형 또는 협업형, 글쓰기는 성취형 또는 성장형에 연결할 수 있다. 독서활동상황 자체와 독서 연계 수업의 세특은 구분해야 한다.

우선 제공 제안: 기존형 + 성취 중심형 + 피드백·성장형 + 협업·기여형 + 생활·관계 종합형. 이후 탐구형·문제 해결형·진로 탐색형 추가. 현재 기본형을 유지하되 새 유형의 선택은 교사가 한다.

## 4. 사용자 제작 기능 제안

권장 흐름: 기본 템플릿 복제 → 적용 영역 선택 → 구성 블록 추가·삭제·순서 변경 → 강조점·문체 설정 → 현재 근거로 미리보기 → 내 템플릿 저장.

저장할 항목:

- 이름·설명, 학교급·적용 영역, 필요하면 과목 범위.
- 구성 블록의 순서와 의미: 성취, 활동 맥락, 질문, 과정, 결과, 피드백, 변화, 협업, 교사 평가 등.
- 각 블록에 필요한 근거, 근거 부족 시 생략 또는 추가 관찰 요청 여부.
- 평가 위치, 첫 문장 방식, 문장 길이, 강조점, 피하고 싶은 표현, 개인 목표 분량.
- 참고 출처와 확인일, 템플릿 버전. 실제 생성 초안에도 사용한 버전을 남기는 방안.

예: ‘국어 고쳐쓰기 중심’ = 첫 수행 → 피드백 → 수정 전략 → 수정 후 수행 → 교사 평가. 전후 글이 없으면 변화 블록을 채우지 않고 필요한 자료를 안내한다. 이는 문장 예문이 아닌 기록 구조다.

교사가 긴 프롬프트를 처음부터 쓰게 하기보다 블록 편집을 기본으로 제공하고, 추가 지시는 보조로 둔다. 교사가 가진 예문에서 문체·구조를 추출하는 기능은 별도 후보이며, 학생의 사실을 다른 학생에게 복제하는 기능으로 만들지 않는다.

템플릿 공유를 후속 기능으로 검토한다면 학생 본문·관찰 자료를 제외한 구조와 설정만 공유하는 방식이 적합하다. 공개 자료 문장을 앱에 수록할 때는 개별 자료의 이용 조건을 먼저 확인한다.

## 5. 모든 템플릿에 공통으로 남길 조건

2026 중학교 기재요령은 AI 생성 문장을 그대로 입력하는 행위를 유의사항에 포함한다. 교사 검토가 전제된 초안으로 제공해야 한다. 학생 자료는 학교교육계획·교사 지도라는 조건에서 활용 가능한 자료를 구별해야 한다. 자기평가의 주장을 교사의 관찰 사실로 자동 변환해서는 안 된다.

제품 동작 제안:

- 없는 동기·결과·피드백·성장을 작성하지 않는다. 근거가 짧으면 글도 짧을 수 있다.
- 금지 내용 확인, 학교급·학년·영역별 조건, 실제 바이트 계산은 사용자 설정으로 해제할 수 없게 한다.
- 같은 근거로 다른 템플릿을 미리 본 뒤 교사가 비교·적용한다. 기존 편집 내용을 자동으로 덮지 않는다.
- 구조 변경과 사실 추가를 구별한다. 템플릿 선택만으로 근거를 다른 학생·영역에 옮기지 않는다.
- ‘더 좋은 생기부’ 식의 등급 대신 ‘어떤 근거에 어울리는지’를 설명한다.

## 6. 후속 설계에서 검증할 것

1. 기존형의 평가 선두 방침은 기본값으로 보존하고, 다른 순서 선택을 허용하는 범위는 별도로 결정한다.
2. 고정된 ‘하나의 탐구 흐름’ 지시와 네 역할 표식·범례가 각 템플릿과 충돌하지 않도록 설계한다.
3. 2026 초·고 기재요령과 5월 길라잡이·현장점검 자료의 관련 본문을 추가 대조한다.
4. 동일한 교사 작성 가상 근거로 8종을 비교한다. 사실 추가 여부, 근거 연결, 영역 적합성, 구성 차이, 실제 분량, 수정 보존을 평가한다.
5. 근거 한 건, 전후 자료 부재, 학생 자기평가만 있음, 팀 결과만 있음, 영역 부적합 등의 실패 상황도 확인한다.

검증 상태: 공식 웹 원문·중학교 PDF 관련 텍스트 및 현재 저장소의 구조 지시를 확인했다. 예시집 전체·초고 기재요령 전체·교원 자료실 첨부는 미검증이다. 코드 변경이 없어 tsc/lint/test/regression-check는 실행하지 않았다. 구현 승인이나 실제 생성 품질 검증을 의미하지 않는다.
