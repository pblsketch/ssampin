# 쌤도구 팝업 구현 가능성 검토

- 날짜: 2026-09-08
- 범위: 현재 코드 조사와 제품 범위 제안. 기능 구현·실행 검증은 하지 않음.
- 판단: 구현 가능. 별도 창 기반은 이미 있고, 핵심 추가 작업은 실행 상태 보존과 작은 창 레이아웃이다.

## 1. 확인한 기반

| 근거 | 확인 내용 | 의미 |
| --- | --- | --- |
| `electron/main.ts`의 `createQuickAddWindow`, `getAllAppWindows`, `broadcastToAllWindows` | 별도 BrowserWindow 생성 및 여러 창에 데이터 변경 전달 | 도구 창도 앱 창 관리에 등록하는 방식으로 확장 가능 |
| `electron/sidePinBrowserWindow.ts` | 별도 창 생성, 준비 완료 후 표시, 닫기 및 포커스 처리 | 창 생명주기 처리의 참고 구현이 존재. 투명창·클릭 통과 설정을 그대로 복제할 필요는 없음 |
| `src/App.tsx` | `mode`로 위젯·빠른 추가·사이드핀·설문 공유 화면 분기 | 도구 전용 진입점을 추가할 수 있음 |
| `Tools/toolRegistry.ts`, `Tools/ToolLayout.tsx` | 17종 도구를 공통 입력으로 렌더링하며 병렬 보기·전체화면·단축키 제공 | 도구 내용 재사용 가능. 팝업 허용 목록은 병렬 보기 목록과 따로 정의해야 함 |
| `Tools/Timer/TimerMode.tsx`, `StopwatchMode.tsx`, `PresentationMode.tsx` | 시간·진행 상태가 화면 내부 상태이며 Date.now 기반 경과 시간 보정이 있음 | 창 이동 시 상태 전달 필요. 타이머는 화면 제거 시 interval 정리도 수행 |
| `Tools/ToolRandom.tsx`, `ToolRoulette.tsx`, `ToolScoreboard.tsx` | 제외 목록·추첨 결과·팀 정보 등이 화면 내부 상태 | 새 창에서 같은 화면을 띄우기만 하면 기존 진행 상황을 이어받지 못함 |

경로에서 `Tools/`는 `src/adapters/components/Tools/`를 뜻한다. 현재 사용자 노출 목록은 `ToolsGrid.tsx`로 확인했다. 도구별 모든 실행 경로를 실기기로 검증한 것은 아니다.

Electron은 독립 창, 크기 변경, 항상 위 표시를 지원한다. 창이 가려졌을 때 타이머 처리에 영향을 주는 backgroundThrottling 설정도 제공한다. 설정만으로 절전 중 알람까지 보장되지는 않는다.

## 2. 지원 도구 제안

| 단계 | 도구 | 판단 이유 및 조건 |
| --- | --- | --- |
| 1차 | 타이머(스톱워치·발표 타이머 포함) | 다른 페이지를 보며 시간을 확인하는 용도에 가장 적합. 남은 시간·랩·발표 순서·알람 중복 방지가 필수 |
| 1차 | 랜덤 뽑기, 룰렛 | 명렬표·수업 기록을 보면서 발표자 선정 가능. 선택 학급·제외 대상·이력 유지 필수 |
| 1차 | 신호등, 활동 기호 | 활동 상태를 계속 표시하는 작은 창에 적합 |
| 1차 | 주사위, 동전 | 짧게 조작하고 결과를 보여주는 용도. 작은 화면에 적합 |
| 1차 | 점수판 | 다른 수업 화면과 점수를 함께 표시. 팀명·점수 유지 및 팀 수별 최소 크기 필요 |
| 1차 | QR코드 | 다른 페이지를 사용하면서 참여 링크를 계속 제시. 스캔 가능한 최소 표시 크기 필요 |
| 2차 | 모둠 편성기, 자리 뽑기 | 큰 화면이 유리하고 명단·조건·결과 적용 처리가 있음. 특히 자리 뽑기는 좌석 데이터 수정 및 전체화면 직접 제어 검토 필요 |
| 2차 | 칠판 | 별도 판서 창은 유용하나 캔버스 크기 변경·필기 보존 검증 필요 |
| 2차 | 객관식·주관식·복합 유형 설문, 워드클라우드, 교실 약속 정하기 | 학생 응답 연결·세션 상태·교사 제어와 결과 표시 분리 검토 필요. 기존 설문 공유 창과 역할 중복 확인 |
| 2차 | 가치수직선 토론, 신호등 토론, 협업 보드, 실시간 담벼락 | 넓은 참여·표시 화면과 실시간 연결 유지가 중요. 작은 팝업보다 결과 전용 큰 창이 적합 |
| 초기 제외 | 과제수합, 서명받기, 서식, 마크다운 변환기, 학교 알리미, 배점 계산기 | 현 단계에서는 입력·관리 중심. 수업 중 계속 띄워두는 1차 도구보다 우선순위 낮음 |
| 초기 제외 | 내 이모티콘 | 기존 별도 선택창 활용 흐름이 있어 추가 팝업의 역할부터 정리 필요 |
| 별도 대상 아님 | 숲소리, PBL스케치, DoRms, 도름스 오락실, 스마트 행정 자동화시스템, PDF LAB, 원클릭업무포털 | 외부 사이트 또는 외부 프로그램 실행 도구. 내부 도구 팝업화와 다른 범위 |

인터랙티브 슬라이드는 현재 도구 목록에서 노출 보류되어 있으므로 이번 지원 목록에 포함하지 않는다. 사용자가 추가하는 미니앱도 초기 범위에서는 제외한다.

1차는 **9개 도구 카드**이며 타이머 안에 3개 모드가 있다. 첫 구현 검증은 타이머·랜덤 뽑기 2개로 하고 통과 후 나머지 7개로 확장하는 순서를 권한다.

## 3. 권장 사용 흐름 (제안, 확정 아님)

1. 도구 카드의 기존 클릭은 본문 열기를 유지하고, 보조 버튼 `새 창으로 열기`를 제공한다.
2. 도구 내부에는 `팝업으로 옮기기`를 둔다. 실행 중인 시간·입력·결과를 그대로 넘긴다.
3. 팝업이 열리면 본문은 다른 페이지로 자유롭게 이동할 수 있다. 같은 도구 페이지에는 `팝업으로 사용 중`과 `창 보기`·`본문으로 가져오기`를 표시한다.
4. 서로 다른 도구 창은 동시에 허용하되, 같은 도구를 다시 열면 기존 창을 앞으로 가져온다. 초기에는 같은 도구를 두 창에서 동시에 조작하지 않는다.
5. 창에는 크기 조절, `항상 위` 토글, `본문으로 가져오기`를 제공한다. 항상 위는 기본 꺼짐을 제안한다.
6. X는 창을 닫고 해당 실행을 종료한다. 진행 중인 타이머나 잃게 되는 결과가 있으면 종료 확인을 제공한다. 창만 옮기려는 경우는 `본문으로 가져오기`를 사용한다.
7. 메인 창 최소화·페이지 이동 중에는 팝업이 유지된다. 앱을 완전히 종료하면 팝업도 종료한다. 앱 재실행 후 진행 상태 복구는 초기 범위에 포함하지 않는다.

기존 병렬 보기는 한 창에서 도구 두 개를 배치하는 기능이다. 이번 기능은 시간표·생기부 등 다른 쌤핀 페이지와 도구를 동시에 사용하는 목적이므로 함께 유지할 가치가 있다. 초기에는 병렬 보기 슬롯에서 직접 팝업으로 옮기기는 후속 범위로 둔다.

## 4. 구현 방식과 난이도

- **창 열기: 낮음~중간.** 전용 도구 창 관리자와 `mode=toolPopup` 같은 진입점을 추가한다. 모달이 아닌 독립 창으로 만들고, 앱 전체 대시보드 초기화·알림 작업이 창마다 중복 실행되지 않게 한다.
- **상태 보존: 중간~높음.** 도구 실행 상태를 화면 밖의 세션으로 분리한다. 초기에는 한 세션의 조작 주체를 본문 또는 팝업 하나로 제한한다. 창마다 별개인 Zustand 상태를 자동 공유된다고 가정하면 안 된다.
- **이동 실패 복구:** 상태 전달 → 새 화면 준비 확인 → 조작권 전환 순서를 사용한다. 팝업 로드 실패 시 원래 화면과 실행을 유지한다. 이동 중 종료·중복 클릭·재시도도 처리한다.
- **타이머:** 현재의 경과 시간 보정은 활용하되 이동 가능한 종료 예정 시각·일시정지 시간으로 상태를 표현한다. 알람 발생 책임은 한 곳에 둔다. 최소화·가려짐·절전 복귀를 따로 검증한다.
- **명단·설정:** 도구 창을 기존 데이터 변경 전달 대상에 등록하고 필요한 저장소 초기화·재읽기를 연결한다. 실행 도중 다른 창에서 학급이나 명단을 바꿔도 추첨 대상이 조용히 바뀌지 않도록 실행 시 선택 맥락을 유지한다.
- **작은 창 화면: 중간.** 공통 ToolLayout을 팝업에 맞게 줄이고 도구별 최소 크기를 정의한다. 단순히 전체 화면 배율만 줄이는 방식은 글씨와 버튼을 지나치게 작게 만든다.
- **창 관리:** 다중 모니터·배율·모니터 분리 시 화면 안 복구를 검증한다. ADR-051의 기존 창 가시성 원칙을 따른다. 단축키는 활성 창에서만 동작하고 Esc는 전체화면 해제·닫기 동작을 구별해야 한다.
- **보안:** 허용된 도구 ID만 수신하고 창 간 요청의 발신자를 확인한다. 도구 팝업은 내부 화면만 로드하며 외부 URL을 권한 있는 창에 넣지 않는다.
- **브라우저 호환:** 데스크톱 앱을 제품 지원 기준으로 검증하되 개발 브라우저에서는 사용자 클릭 기반 새 창 열기 및 차단 안내를 제공한다. 브라우저의 항상 위·창 위치 제어는 데스크톱 앱과 동일하게 보장하지 않는다.

따라서 전체 범위는 버튼 하나 추가가 아닌 **중간 규모 기능**으로 보는 것이 적절하다. 정확한 일정은 타이머·랜덤 뽑기 두 도구의 상태 이전 검증 후 산정한다.

## 5. 구현 착수 시 통과 조건

1. 5분 타이머 실행 → 팝업 이동 → 본문에서 시간표·생기부 이동 → 시간이 이어지고 알람은 한 번만 발생.
2. 메인 창 최소화와 팝업 가려짐·최소화를 구별해 타이머·알람 확인. 절전 복귀 시 지난 시간이 반영되고 중복 알람 없음.
3. 뽑기 후 제외 목록·선택 학급·결과 이력을 팝업과 본문 사이에서 유지. 다른 창의 명단 변경에도 대상이 임의로 교체되지 않음.
4. 팝업 생성 실패·이동 중 닫기·연속 클릭에도 원래 실행 유실이나 복제 없음.
5. 타이머+뽑기+점수판을 함께 열어 별도 조작 가능. 메인 창 페이지 이동에 영향 없음. 메모리·CPU 사용도 함께 관찰.
6. 작은 창, 팀 수가 많은 점수판, QR 스캔, 100%/150%/200% 배율, 보조 모니터 분리에서 화면과 버튼 접근 가능.
7. X 종료, 본문 복귀, 앱 종료, 전체화면 및 Esc 동작 확인. 개발 브라우저와 설치된 Windows 앱을 각각 검증.
8. `npx tsc --noEmit`, `npm run lint`, `npm run test`, `npm run regression-check` 통과. 사용자 가이드 변경 후 `cd landing && npm run docs:check && npm run build` 확인.

이번 검토에서는 위 실행 시험과 전체 검증 게이트를 실행하지 않았다. 결론은 현재 소스와 공식 API에 근거한 구현 가능성 판단이며, 팝업 기능이 이미 작동한다는 의미는 아니다.
