# 누적 관찰 → 과제물 결합 → AI 생기부 초안 흐름 — 현재 상태 분석과 고도화 방안

- 일자: 2026-09-04
- 목적: "학급반·수업반 특기사항을 누적 관찰하고, 학생 과제물과 결합해 AI 브릿지로 생기부 초안을
  쓰는" 흐름의 **현재 상태를 코드·문서 근거로 객관화**하고, 2022 개정 교육과정 성취기준

- 성격: 분석·제안. 구현 결정은 없다. 프롬프트 원문은 싣지 않는다(ADR-072 결정 1, 저장소 공개).
- ⚠️ **2차 분석이 이 문서의 결론 일부를 바꿨다** — [2차: 탐구 흐름·키워드·STT](record-draft-flow-v2-inquiry-thread.analysis.md).
  특히 §4 방안 2-5 "성취기준 원문을 AI에 함께 싣는다"는 **철회**(복사형 세특을 만든다). 우선순위는 2차 §9 가 정본.
- 관련: [ADR-072](../../DECISIONS.md) · [ADR-074](../../DECISIONS.md) ·

## 1. 한 줄 결론

**파이프라인의 뼈대(관찰 → 근거 창고 → 초안)는 이미 서 있고, 병목은 모델이 아니라 근거의
구조와 위생이다**(실측 확인). 그런데 지금 근거에는 "**무엇을 배우는 장면인가**"를 가리키는 축,
즉 **성취기준이 없다.** 앱 어디에도 성취기준 코드를 담는 칸이 없고, 진도는 자유 문자열
`unit`·`lesson` 뿐이다. 성취기준 MCP 자료(초·중·고·특성화고 4종, MIT, 실제 조회 확인)는
이 빈 축을 **공식 원문으로** 채울 수 있는 재료다. 다만 (1) 2026학년도 중3·고3은 아직 2015
개정이라 자료가 없고, (2) 주제(topic) 단위 서술은 기계 생성 후보라 그대로 문장에 쓰면
안 되며, (3) 관찰·근거·초안 화면에 **사용량 계측이 0건**이라 "얼마나 쌓이고 있는가"를 아무도
모른다는 점을 먼저 인정해야 한다.

## 2. 현재 상태 — 근거로 본 것

### 2-1. 파이프라인 3단과 그 사이의 이음새

| 단계        | 저장 단위                                                                                    | 확인한 사실                                                                                                                                                                                 |
| ----------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ① 누적 관찰 | 교과 `ObservationRecord`(`observations.json`) / 담임 `StudentRecord`(`student-records.json`) | 둘 다 `slots?`(선택) 보유 — 교과 6종(질문·시도·시행착오·산출물·피드백·융합), 담임 6종(학습 태도·인성·관계·학급 역할·변화·아쉬운 점·진로). 학기 스탬프 `term?` 있음. 알림은 슬롯 인지형 문구 |
| ② 근거 창고 | `RecordEvidence`(`record-evidence.json`)                                                     | 출처 6종(manual·observation·studentRecord·assignment·attachment·evaluation), `slots?`·`excludedFromAi?` 보유. **동기화 34종에 포함됨**(`syncRegistry.ts` 28-b, ADR-072 "남은 한계"는 해소)  |
| ③ 초안      | `RecordDraft`(`record-drafts.json`)                                                          | 영역 7종 × 학교급 한도, `requiresTeacherReview: true` 고정, 확정 잠금(`upsert` 단일 관문). **학년도·학기 칸은 여전히 없다** — 학년이 바뀌면 덮어쓴다                                        |

이음새의 상태:

- **①→② 끌어오기**(`evidenceImport.ts`)는 관찰·누가기록의 슬롯을 그대로 싣는다(D4 수정 완료).
- **과제물→②**: `Submission.textContent`(텍스트 제출)와 **파일명·지각 여부만** 들어간다. 파일
  본문은 드라이브에만 있다. 단, `ObservationAttachment.extractedText`(첨부 추출 원문) 경로는
  따로 있어 첨부로 올린 파일은 본문이 들어온다 — **"과제수합으로 낸 파일"과 "첨부로 올린 파일"의
  대우가 다르다.**
- **평가→②**: 루브릭은 수준 이름·성취 설명·요소 메모·총평(배점 제외), 성적은 성취도·영역명·
  응시 여부·증빙 메모(점수 제외). `PerformanceAssessmentResult` 에 `rubricGradingId`·
  `assignmentId`·`submissionId` 가 있어 **"과제물 ↔ 교사 평가"는 데이터로 이미 이어져 있다.**
- **②→③ AI 경로는 브릿지(MCP)뿐이다.** 도구: `get_record_evidence`·`get_record_drafts`·
  `write_record_draft`·`check_record_draft`·`get_record_guidelines`. 초안 입력창의 안내문이
  "AI에게 초안을 요청하면 자동 입력됩니다"인데, 그 AI는 외부 AI(교사 구독)다.
- **인앱 쌤핀 AI 경로(Phase 4)는 미착수**다. `RecordDraft/` 컴포넌트에 assist 참조 0건.
  ADR-074 결정 2가 "생기부는 계속 닫는다"를 현행으로 못 박고 있다.
- **자기평가서(Phase 3)는 설계만** 있고 엔티티 0건이다.

### 2-2. 성취기준은 어디에도 없다

| 찾은 곳                                   | 상태                                                                                                               |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `ProgressEntry`(진도)                     | `unit`·`lesson` 자유 문자열. 코드 칸 없음                                                                          |
| `Rubric`·`RubricCriterion`                | 요소 이름·수준·배점. 성취기준 연결 없음                                                                            |
| `AssessmentPlanItem`(평가 계획)           | `areaName`·`method`. 성취기준 없음                                                                                 |
| `Assignment`(과제)                        | 제목·설명·마감·대상. 성취기준 없음                                                                                 |
| `ObservationRecord`·`StudentRecord`       | 태그·분류·슬롯. 성취기준 없음                                                                                      |
| `scoringRubricParser.ts`(평가계획서 파싱) | **성취기준 코드를 읽기는 한다** — 그런데 접두사로 과목명만 추정하고 코드는 버린다(`[12언매01-01]` → '언어와 매체') |

즉 성취기준 코드가 앱에 **들어오는 지점은 하나 있는데(평가계획서 파싱), 보존되지 않는다.**

### 2-3. 실측이 말한 것 (2026-08-24, Solar Pro 3, 가상 자료 5사례 × 2회)

- 근거가 두꺼우면 문장력은 쓸 만하다(A 2/2). **얇은 근거 창작은 지시 위치로 고쳐진다**(B 0/2 → 2/2).
- **기재 금지 항목은 프롬프트로 못 막는다**(C 0/2 → 보강 후 0/2) → 입력 차단으로 구현 완료.
- **교사 지시가 안전 규칙을 이긴다**(E 0/2, 한도 4배 창작) → 저장 시점 차단 설계(Phase 4 미구현).
- 하네스에는 **"성취기준을 잘못 인용하는가"를 보는 사례가 없다.** 성취기준을 넣기 시작하면
  새 실패 유형(없는 코드 창작·엉뚱한 성취기준 인용)이 생길 수 있고, 지금은 잴 수 없다.

### 2-4. 계측 공백 — "누적"이 실제로 되고 있는지 모른다

`useAnalytics` 호출이 있는 화면은 상담·자리배치 등이고, **관찰 입력·근거 창고·초안 화면에는
0건**이다. ADR-081(2026-09-01)로 넣은 계측 6종에도 생기부 축은 없다. 그래서 다음 질문에 답할
수 없다: 슬롯을 실제로 붙이는가, 근거 창고를 여는 교사가 몇 명인가, 초안이 브릿지에서
써지는가 교사가 직접 쓰는가. **고도화 순서를 정하려면 이 숫자가 먼저 필요하다.**

### 2-5. 제품 경계 (이 분석이 지켜야 하는 것)

- **선생님 비용 0**, BYOK 금지, **대필 금지 — 보조까지만**(`feedback_no_ai_features` 현행 방침).
- 누적형 개인 보상·게이미피케이션 금지. 진행 표시는 "미기록 N명" 수준까지.
- 오프라인 완전 동작·로컬 JSON. 외부 MCP를 앱 런타임이 매번 부르는 구조는 이 원칙과 충돌한다.
- 학사 규정 의존 기능은 **기재요령 원문을 확인**하고 만든다(`feedback_verify_regulation_before_impl`).
- UI 변경은 프론트엔드 디자인과 함께 정한다.

기록), 원문은 저작권법상 공공저작물 취급. 주제·선수관계는 DECK6 데이터셋(MIT) 파생.

### 3-2. 실제 조회 결과 (이 세션에서 확인)

이 환경에는 `korean-teacher-skills` 플러그인으로 **초등·중등 MCP가 이미 연결돼 있다**(도구명이
저장소 README와 일치). 조회 결과:

- `list_curricula`: 중 13교과군 · 고 16교과군 집계 정상. 초등 11교과 정상.
- `search_standards("일차함수", middle)`: `[9수02-15]`~`[9수02-18]` 4건, 영역 "변화와 관계".
- `get_standard("9수02-15")`: `officialText` "일차함수의 개념을 이해하고, 그 그래프를 그릴 수
  있다." + 출처 로케이터(고시 별책 8, PDF 41쪽, SHA-256) + 연결 주제 3건(관점 facet 별).
- `get_topic(...)`: `evidence`(관찰 증거) 1문장 + `assessmentPrompts`(평가 문항) 1문장.
  **단, 문장이 틀에 박힌 기계 생성문이다** — "…와 관련된 과제에 적절한 절차와 전략을 선택해
  수행하고 그 과정을 설명한다". `summaryKind: "mechanical-derivative"` 로 스스로 밝히고 있다.

**판정**: 성취기준 **코드·원문·영역·학년군·출처**는 신뢰할 만한 정본이다. **주제 단위
관찰 증거·평가 문항은 "교사가 다듬을 초안"까지만** 쓸 수 있고, 생기부 문장의 재료로 직접
흘려보내면 천편일률에 AI 티가 난다.

### 3-3. 쓰기 전에 알아야 할 제약

1. **적용 학년 시차.** 2022 개정은 2025학년도 중1·고1, 2026학년도 중2·고2, 2027학년도 전
   학년 적용이다. **2026학년도 지금 중3·고3은 2015 개정**이고, 세 자료 어디에도 2015 개정은
   없다. 2026학년도에 이 기능을 켜면 교사 셋 중 하나는 "내 과목이 없다"를 본다.
2. **오프라인.** 쌤핀은 오프라인 완전 동작이 원칙이다. 앱이 런타임에 `npx` MCP를 띄우거나
   서버를 부르는 구조는 맞지 않는다. 데이터를 **앱에 번들**(MIT 허용)하거나 **서버에 적재해
   한 번 내려받아 캐시**하는 구조여야 한다. 반면 **브릿지 경로(교사의 Claude/Codex)는 교사가
   MCP를 하나 더 등록하면 끝**이다.
3. **검색 품질.** 부분 문자열 매칭이라 "함수"는 잘 찾고 "그래프 그리기"는 못 찾는다. 앱 안에서
   쓴다면 "과목 → 영역 → 목록에서 고르기"가 검색보다 낫다.
4. **학교급 분기.** `RecordDraft.SchoolLevel` 은 초·중·고 셋뿐이다. 특성화고 전문교과는
   `high` 안에서 "일반/전문" 구분이 하나 더 필요하다.

## 4. 고도화 방안 — 여러 갈래

각 방안에 **효과 / 비용 / 위험 / 전제**를 적는다. 서로 배타적이지 않다. 우선순위는 §5.

### 방안 0 — 먼저 재고, 학년도 칸을 만든다 (위생)

- **내용**: 관찰 입력(슬롯 선택 포함)·근거 창고 열기·끌어오기·초안 저장(출처 teacher/bridge)에
  ADR-081 방식(**이름만**, 값 없음) 계측을 붙인다. `RecordDraft` 에 `term?` 을 더한다(관찰·
  누가기록의 `withDerivedTerm` 선례 재사용).
- **효과**: "누적이 되고 있는가"에 숫자로 답한다. 이후 모든 방안의 우선순위 근거가 된다.
  학년 전환 시 초안 덮어쓰기 사고를 막는다.
- **비용**: 작음. **위험**: 없음. **전제**: 없음.

### 방안 1 — 브릿지 경로에 성취기준 MCP를 "함께 등록" (코드 거의 없음, 즉시)

- **내용**: 교사가 이미 브릿지를 쓰는 Claude Desktop/Codex에 학습맵 MCP를 하나 더 등록하도록
  안내한다. 브릿지 `register` 에 `--with-curriculum <elementary|secondary|vocational>` 옵션을
  두거나, `/docs` 가이드에 등록 명령 한 줄을 싣는다. `get_record_guidelines` 응답에 "성취기준은
  교육과정 MCP의 `officialText` 만 인용하고 코드를 창작하지 말 것"을 더한다.
- **효과**: 오늘 당장 "이 학생 근거를 `[9수02-15]` 성취수준에 비추어 세특 초안" 이 가능하다.
  외부 AI(Claude·GPT)는 실측상 규정 준수가 Solar보다 낫다.
- **비용**: 문서 + 등록 옵션. **위험**: 교사가 성취기준 문장을 그대로 세특에 옮겨 적는 것 —
  `check_record_draft` 가 "성취기준 원문 그대로 복사" 를 경고 flag 로 잡게 하면 완화된다.
- **전제**: 없음. 브릿지 경로는 이미 정식(B안)이다.

### 방안 2 — 성취기준을 앱의 "축"으로 들인다 (핵심, 최소판부터)

- **내용**:
  1. 성취기준 정본(코드·원문·과목·영역·학년군·출처)을 **앱에 번들**한다. 주제·선수관계는 넣지
     않는다(용량·품질 이유). 초등 320KB급이니 중등을 합쳐도 수 MB 안이다. 갱신은 릴리즈로.
  2. `TeachingClass.subject`(이미 있음) + 학년으로 후보를 좁혀, **진도 입력에 "성취기준 고르기"**
     를 붙인다. `ProgressEntry.standardCodes?`(선택). 단원명을 자유 문자열로 쓰던 교사는 그대로
     쓰면 된다 — 슬롯과 같은 "선택" 원칙.
  3. **관찰 입력에서 "오늘 진도의 성취기준" 칩을 자동 제안**한다. 그날·그 반의 진도에 코드가
     있으면 칩이 뜨고, 한 번 탭이면 `ObservationRecord.standardCodes?` 에 붙는다. 담임
     누가기록에는 붙이지 않는다(행특은 성취기준 축이 아니다).
  4. 근거 창고 끌어오기가 코드를 싣고(`RecordEvidence.standardCodes?`), 브릿지
     `get_record_evidence` 화이트리스트(`normalizeRecord`)에 추가한다 — **여기 안 넣으면 조용히
     사라진다**(D4 재발 방지).
  5. AI에 보낼 때는 **코드가 아니라 원문을 근거 옆에 함께 싣는다.** 모델이 코드를 외워서 원문을
     창작하게 두지 않는다.
- **효과**: 세특의 골격(성취기준 → 그 기준에서 드러난 학생의 특성)이 근거 단계에서 잡힌다.
  "병목은 근거의 구조" 라는 실측 결론에 정확히 대응한다.
- **비용**: 중. 엔티티 3곳 선택 필드 + 번들 데이터 + 진도·관찰 입력 UI(디자인 협업 필수) +
  브릿지 미러·계약 테스트(`entitySampleContract` 메타테스트가 새 필드를 잡는다).
- **위험**: (a) **2015 개정 학년은 자료가 없다** → `standardCodes` 와 별개로 `standardText?`
  자유 입력을 허용해 교사가 직접 적을 수 있게 한다. 2027학년도부터 자연 해소. (b) 칩이 늘어
  입력이 무거워진다 → 진도에 코드가 있는 날만 칩이 뜬다. (c) 학기 초 진도에 코드를 다는 일이
  "큰 배치 작업" 이 된다 → 단원 하나에 한 번이면 그 단원 전체 차시에 상속되게 한다.
- **전제**: 기재요령에서 세특의 성취기준 서술 요건을 원문으로 확인한 뒤 문구를 정한다.

### 방안 3 — 성취기준 커버리지 뷰와 슬롯 인지형 알림의 확장

- **내용**: 수업반 화면에 **학생 × 성취기준(이번 학기 진도에 달린 것)** 표를 두고, 근거가
  있는 칸/없는 칸만 보여준다. 관찰 알림은 지금 "질문 5건인데 시행착오 0건" 을 말하는데, 여기에
  "이번 단원 성취기준에 근거 0건인 학생 N명" 을 더한다.
- **효과**: 학기말에 "이 학생은 쓸 게 없다"가 미리 보인다. 누적을 실제로 끌고 가는 장치.
- **비용**: 중(뷰 1개 + 알림 규칙 확장). **위험**: 점수판처럼 보이면 게이미피케이션 금지에
  걸린다 → 순위·누적 점수 없이 "빈 칸" 만. 알림 대상 선정 규칙은 바꾸지 않는다(ADR-072 결정 6).
- **전제**: 방안 2.

### 방안 4 — 과제물 본문을 들이고, 과제에 성취기준을 단다

- **내용**: (a) 과제(`Assignment`)에 `standardCodes?` 를 달면 그 제출물이 자동으로 해당
  성취기준의 근거가 된다. (b) 과제수합 파일 제출물도 `ObservationAttachment.extractedText`
  경로처럼 본문을 뽑아 근거로 싣는다(텍스트·HWP·PDF는 이미 파싱 수단이 있다). (c)
  `PerformanceAssessmentResult` 의 `assignmentId`·`rubricGradingId` 연결을 이용해 **"과제물 +
  교사 평가" 를 근거 하나로 묶어** 끌어온다.
- **효과**: 오너 요구 "과제물과 교사 평가의 유기적 결합" 이 데이터 조인으로 실제가 된다.
  드라이브에만 있던 본문이 근거가 된다.
- **비용**: 중~상(파일 본문 추출은 용량·형식 편차가 크다). **위험**: 학생 글이 세특에 그대로
  흘러드는 문제 — Phase 3 설계와 같은 원칙("교사가 골라야 창고로")을 적용한다. 본문에 기재
  금지 항목이 섞이면 `excludedFromAi` 자동 표시가 이미 받쳐 준다.
- **전제**: 방안 2(코드 칸).

### 방안 5 — 자기평가서 문항을 성취기준·슬롯에서 끌어낸다 (Phase 3 보강)

- **내용**: Phase 3 설계의 "슬롯 달린 추천 문항" 을 성취기준 주제의 `assessmentPrompts` 로
  **씨앗만** 만든다. facet 이 "문제 해결과 수학적 설명" 이면 슬롯 [시도]·[시행착오], "표현·
  모델링과 연결" 이면 [융합] 식으로 매핑한다. 학생 답은 대기 목록 → 교사 선택 → 창고
  (`selfAssessment`) 원칙 그대로.
- **효과**: 근거 3종이 **같은 언어(슬롯)** 와 **같은 축(성취기준)** 으로 정렬된다.
- **비용**: Phase 3 자체가 중상. 문항 씨앗은 작음. **위험**: 기계 생성 문항이 그대로 학생에게
  가면 어색하다 → 교사가 반드시 고쳐 쓰는 흐름(빈 칸이 기본, 추천은 꺼내 쓰기). 미성년자
  데이터 수집이라 방침·에듀집 확인이 착수 조건이다(설계서 §3-6).
- **전제**: Phase 3 착수 결정.

### 방안 6 — 인앱 쌤핀 AI 개방(Phase 4)에 성취기준을 태워 보내되, 하네스를 먼저 넓힌다

- **내용**: Phase 4 를 착수한다면, 근거와 함께 **성취기준 원문을 사용자 턴에 실어** 보낸다.
  하네스에 **F 사례(성취기준 오인용·코드 창작)** 를 더해 C·E 와 함께 게이트로 삼는다.
- **효과**: 진입장벽 0 경로에서도 골격 있는 초안. **비용**: Phase 4 전체(높음). **위험**:
  ADR-074 결정 2 를 뒤집는 결정이며, 무료 티어 학습 활용·재위탁 확인·계약 테스트 갱신이
  따른다. **재론 조건은 설계서 §4-6 의 3종 확인**이다. 이 문서는 이를 앞당기자고 제안하지 않는다.

### 방안 7 — 학교급 분기와 2015 개정 공백의 정직한 처리

- **내용**: 설정에 "특성화고(전문교과)" 를 두고 vocational 자료를 선택 번들(용량이 크므로
  기본 제외·필요 시 내려받기). 2015 개정 학년에는 "이 학년은 2022 개정 자료가 없습니다 —
  직접 입력" 안내를 화면에 그대로 적는다.
- **효과**: "내 과목이 없다" 를 오류가 아니라 사실로 보여준다. **비용**: 작음~중.
- **위험**: 없음. **전제**: 방안 2.

## 6. 이 분석이 확인하지 못한 것

- **실사용량**: 계측이 없어 관찰 누적·근거 창고·초안 사용률을 숫자로 말할 수 없다(§2-4).
- **기재요령 원문**: 세특의 성취기준 서술 요건·표현 제한은 이번에 원문을 열어 보지 않았다.
  방안 2의 문구를 정하기 전에 확인한다.
- **번들 용량**: 중등 패키지의 실제 데이터 크기를 재지 않았다(초등 README 기준 320KB).
- **2015 개정 자료원**: 세 저장소에 없다는 것만 확인했고, 대체 자료원은 찾지 않았다.
- **브릿지 실기기**: 학습맵 MCP와 쌤핀 브릿지를 한 클라이언트에 같이 등록했을 때 도구 이름
  충돌(`list_curricula` 류는 브릿지에 없어 충돌 가능성은 낮다)은 실측하지 않았다.
