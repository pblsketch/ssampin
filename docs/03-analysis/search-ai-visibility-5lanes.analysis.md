### 이미 잘 되어 있던 것

- 자바스크립트 없이 받은 HTML에 본문 전부 존재 (142KB, `<h1>` 1개) — SPA 사고 없음
- `noindex` 사고 없음 (meta·`X-Robots-Tag` 모두 깨끗)
- 없는 페이지가 실제 404 반환 (soft 404 아님)
- 페이지별 고유 title·description (도움말 45편 포함)
- 구글 서치콘솔·네이버 서치어드바이저 소유확인 완료, `Yeti` 허용 명시
- 공유 링크(`/s/`, `/submit/`, `/booking/`, `/check/`, `/memo/`)에 `noindex` 적용됨

## 4. 변경 내역

### 4.1 정본 주소 일원화

- `config.ts`에 `SITE_URL = 'https://www.ssampin.com'` 신설. 메타·사이트맵·구조화 데이터가 전부 이 상수를 참조한다.
- `layout.tsx`에서 **canonical을 제거**했다. 루트 레이아웃의 canonical은 자기 주소를 지정하지 않은 모든 하위 페이지에 상속되므로, 여기 두면 안 된다. 정본 주소는 페이지마다 각자 선언한다.
- `page.tsx`(홈)·`/about`·`/ai-bridge`·`/credits`·`/privacy`·`/terms`·`/school-adoption`·`/docs/*`에 자기 canonical 추가.

### 4.2 AI 크롤러 정책 (`robots.ts`)

용도별로 나눠 전부 허용:

- 학습용 — `GPTBot`, `ClaudeBot`, `Google-Extended`, `CCBot`, `Applebot-Extended`
- 검색 색인용 — `OAI-SearchBot`, `Claude-SearchBot`, `PerplexityBot`
- 실시간 열람용 — `ChatGPT-User`, `Claude-User`, `Perplexity-User`

동시에 **개인정보가 오가는 경로를 크롤러에서 제외**했다(`/admin/`, `/s/`, `/check/`, `/submit/`, `/booking/`, `/memo/`, `/staffroom/join`). 각 페이지에 `noindex`가 있지만 크롤러가 아예 오지 않는 편이 안전하고 색인 예산도 아낀다.

### 4.3 구조화 데이터 재편 (`content/structuredData.ts` 신설)

원칙 두 가지를 코드로 고정했다.

1. **`@id` 고정** — 같은 실체는 어느 페이지에서든 같은 `@id`로 부른다. 페이지마다 Organization을 새로 선언하면 검색엔진·AI 안에서 "쌤핀"이 여러 실체로 쪼개진다.
2. **화면에 보이는 것만 선언** — 제품 정보·FAQ·이동경로는 그 내용이 실제로 보이는 페이지에서만 붙인다.

| 스키마                | 이전                 | 이후                         |
| --------------------- | -------------------- | ---------------------------- |
| Organization + sameAs | 없음                 | 전역 (GitHub·에듀집 연결)    |
| WebSite               | 전 페이지            | 전역 (`@id` 부여)            |
| SoftwareApplication   | 전 페이지            | 홈만                         |
| FAQPage               | 전 페이지            | 홈만                         |
| BreadcrumbList        | 전 페이지 "홈" 1단계 | 페이지별 실제 계층           |
| TechArticle           | 없음                 | 도움말 45편 (`dateModified`) |

`datePublished`는 일부러 넣지 않았다. 우리가 가진 날짜는 마지막 수정일뿐이라, 그 값을 최초 발행일인 척 적으면 화면이 사실 아닌 것을 말하게 된다.

### 4.4 FAQ 원천 통합 (`content/faq.tsx` 신설)

화면과 구조화 데이터가 배열 하나를 같이 읽게 했다. 각 문답은 `answer`(순수 텍스트, LD로 감)와 선택적 `answerNode`(링크 포함 화면용)를 갖는다. 이제 답변을 고치면 LD가 자동으로 따라간다.

### 4.5 `llms.txt` · `llms-full.txt` 신설

정적 파일이 아니라 라우트로 만들어, 도움말이 늘거나 버전이 오르면 안내서도 같이 최신이 된다. 담은 것은 "쌤핀에 관해 이 사이트만 확정할 수 있는 사실"이다 — 이름·요금·지원 OS·오프라인 동작 범위·자료 보관 위치·에듀집 등록 여부.

### 4.6 사이트맵

전 URL을 www로 바꾸고 `/about`을 추가했다. `/privacy`·`/terms`는 의도적으로 `noindex`라 **넣지 않았다** — noindex 페이지를 사이트맵에 올리면 크롤러에게 모순된 신호를 준다.

### 4.7 모바일 앱 껍데기 (`mobile.html`)

`m.ssampin.com`은 로그인해서 쓰는 앱 화면이라 크롤러가 받아 가는 것은 본문 없는 껍데기뿐이다. `noindex, follow`를 달아 브랜드 검색에 빈 페이지가 걸리지 않게 했다.

### 6.2 콘텐츠·디자인 협업이 필요한 것

- **첫 문단 직답 문장 (AEO)** — 홈 히어로는 지금 슬로건("중요한 걸 핀으로 꽂아두는")이라, "쌤핀이 무엇인가"에 대한 40자 직답이 없다. 답변엔진은 답이 되는 문장을 찾아 추출하므로 직답이 최상단에 있어야 한다. 다만 히어로 문구 변경은 디자인 영역이라 단독으로 손대지 않았다.
- **의도 랜딩 (질문 하나 = 페이지 하나)** — 도움말은 기능 설명 중심이다. "교사용 시간표 프로그램 무료", "학급 자리배치 프로그램" 같이 실제로 검색창에 치는 질문 전용 페이지가 없다. 서치콘솔·서치어드바이저의 검색어 목록을 본 뒤 만드는 게 순서다.
- **네이버 블로그 투트랙** — 네이버는 자기 생태계 안(inside) 콘텐츠를 우대한다. 블로그로 신뢰를 쌓고 데이터는 자기 도메인(outside)에 두는 구조가 정답인데, 이건 운영 결정이다.

### 6.3 판단 보류

- **`/privacy`·`/terms`의 `noindex`** — 명시적으로 그렇게 코딩되어 있어 기존 결정으로 보고 유지했다. 다만 학운위 심의·에듀집 맥락에서는 개인정보처리방침이 검색되는 게 오히려 신뢰 신호로 작동한다. 되돌릴 의향이 있으면 알려달라.
- **IndexNow 연동** — 새 페이지를 발행 즉시 빙·네이버 계열에 알리는 기능이다. 키 발급과 배포 파이프라인 연동이 필요해 이번 범위에서 뺐다.

## 8. 재발 방지 메모

- **루트 레이아웃에 절대 canonical을 두지 않는다.** 하위 페이지 전부가 그 주소를 자기 정본이라고 신고하게 된다. 이번 사고의 원인이었다.
- **구조화 데이터는 화면과 같은 원천에서 만든다.** 따로 들고 있으면 반드시 어긋나고, 어긋난 쪽이 사용자에게 거짓을 말한다.
- **`noindex` 페이지는 사이트맵에 넣지 않는다.** 모순된 신호다.
- 편집 후 `git diff --numstat`으로 줄바꿈 뒤집힘을 확인한다. 이번에도 3개 파일이 LF→CRLF로 뒤집혀 전체 diff가 났고, LF로 되돌린 뒤에야 실제 변경만 남았다.
