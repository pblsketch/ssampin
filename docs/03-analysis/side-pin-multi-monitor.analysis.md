# 옆핀 모니터 선택 — 현황 분석

- 작성일: 2026-08-27
- 출처: 챗봇 미해결 피드백 "옆핀을 듀얼모니터 중에서 다른 모니터 화면으로 보내고 싶어요"
- 범위: 코드 실측 기반 현황·위험 분석. 구현 계획은 `docs/01-plan/features/side-pin-multi-monitor.plan.md`

---

## 1. 한 줄 결론

**기능의 70%는 이미 만들어져 있고, 빠진 것은 "사용자가 고르는 길"뿐이다.**
옆핀을 어느 모니터에 그릴지 결정하는 계산·저장·재배치는 전부 구현되어 테스트까지 있다.
다만 그 값을 **사람이 정할 수단이 하나도 없어서** 항상 주 모니터에만 뜬다.

---

## 2. 지금 실제로 일어나는 일

옆핀을 켜면 다음 순서로 위치가 정해진다.

| 단계 | 파일                                                       | 하는 일                                              |
| ---- | ---------------------------------------------------------- | ---------------------------------------------------- |
| 1    | `electron/sidePinElectron.ts:73`                           | 연결된 모니터 목록을 Electron `screen`에서 읽는다    |
| 2    | `electron/sidePinService.ts:88`                            | 저장된 `displayId`를 `preferredDisplayId`로 넘긴다   |
| 3    | `electron/sidePinGeometry.ts:89` (`pickDisplay`)           | 고른 모니터가 있으면 그것, 없으면 주 모니터          |
| 4    | `electron/sidePinGeometry.ts:234` (`resolveSidePinLayout`) | 그 모니터 작업 영역의 오른쪽 끝에 손잡이·패널을 배치 |

`displayId`는 `electron/sidePinDeviceState.ts`가 `side-pin-device-state.json`에 저장한다.
동기화하지 않는 **기기 전용 파일**이다(학교 PC와 집 노트북은 모니터 구성이 다르므로).

### 빠져 있는 것

`displayId` 값을 **쓰는 경로가 딱 하나뿐이다** — 고른 모니터가 사라졌을 때 시스템이 스스로 고치는 경우
(`sidePinService.ts:94-97`). 사용자가 고르는 IPC도, 트레이 메뉴도, 설정 화면도 없다.

```
$ grep -rn "displayId" electron/ src/ | grep -v test | grep -v desktopWidget
# → 정의·읽기 6곳, 사용자 입력 0곳
```

같은 처지의 값이 하나 더 있다. `panelWidth`(패널 너비 360~460)도 저장 모델과 정규화 함수까지
다 있는데 조절 수단이 없어 항상 기본값 400으로 고정되어 있다.

### 원래 계획에는 있었다

`docs/01-plan/features/side-pin-v0.plan.md:67`의 "옆핀에 포함하는 것" 목록에
**"모니터 선택과 패널 너비 설정"**이 명시되어 있고, 같은 문서 469행 1차 구현 범위 6번에도
"고정, 단축키, 모니터 선택"이 들어 있다. 즉 **누락이지 기각이 아니다.**

## 3. 위험 — 구현 전에 결정해야 하는 것들

### 🔴 T1. 모니터를 한 번 뽑으면 사용자의 선택이 영구히 지워진다 (치명)

```ts
// electron/sidePinService.ts:94-97
if (layout.usedFallbackDisplay && device.displayId !== layout.displayId) {
  device = { ...device, displayId: layout.displayId }; // ← 저장값을 덮어쓴다
  deps.saveDeviceState(device);
}
```

지금은 이 코드가 옳다. `displayId`를 채우는 주체가 이 코드 자신뿐이라, 없어진 모니터 번호를
계속 들고 있어 봐야 의미가 없기 때문이다.

**그런데 사용자가 직접 고를 수 있게 되는 순간 이 코드는 결함이 된다.**
노트북에 외장 모니터를 꽂아 쓰는 교사가 "외장 모니터"를 골라 두고 퇴근하며 케이블을 뽑으면,
그 순간 저장값이 노트북 화면으로 덮어써진다. 다음 날 다시 꽂아도 옆핀은 노트북 화면에 남는다.
**매일 다시 골라야 한다.**

→ **"사용자가 고른 값"과 "지금 실제로 쓰는 값"을 분리해 저장해야 한다.**
고른 값은 절대 시스템이 덮어쓰지 않는다.

### ⚪ T2. 왼쪽 모니터에서는 손잡이 잡기가 조금 불편하다 (감수 — 결정 완료)

**요구는 단순하다: 고른 모니터가 어느 것이든 그 모니터의 오른쪽 끝에 붙인다.**
지금은 항상 주 모니터의 오른쪽에만 붙는다 — 그것만 고치면 된다.
(오너 확인 2026-08-27)

따라오는 특성이 하나 있다. 왼쪽 모니터의 오른쪽 끝은 두 모니터가 맞닿은 경계이고,
경계에서는 커서가 멈추지 않고 옆 화면으로 넘어간다. 그래서 "끝까지 밀면 조준 없이 잡힌다"가
그쪽에서만 성립하지 않는다(`sidePinGeometry.ts`의 `hasDisplayToTheRight` 주석이 이미 적어 둔 사실).

**이것을 고치려 하지 않는다.** 왼쪽 가장자리 붙이기를 따로 만드는 것은 손잡이 모서리 둥글기·
펼침 방향·마우스 판정을 전부 좌우 대칭으로 다시 만드는 일이고, 얻는 것은 조준 한 번뿐이다.
목록에 배치(왼쪽/오른쪽)를 적는 것은 **경고가 아니라 어느 모니터인지 알아보게 하려는 것**이다(§5).

### 🟡 T3. 배율이 다른 모니터로 옮기면 패널 창이 새로 만들어진다 → 쓰던 메모가 날아갈 수 있다

손잡이 너비는 그 모니터의 배율로 계산된다(`resolveSidePinRailWidth`). 배율이 다르면 창 크기가
달라지고, `sidePinWindow.ts`의 `hasSameSize` 검사가 어긋나 **창을 파괴하고 다시 만든다**
(`replaceRail` / `replacePanel`). 렌더러가 리로드되므로 **패널에서 작성 중이던 메모 초안은 사라진다.**

이 위험은 이미 알려져 있다 — `src/global.d.ts:755`의 `reportEditorActivity` 주석이
"이 신호가 없으면 타이핑 도중 접혀 쓰던 글이 날아간다"고 적고 있다. 모니터 이동은 그 상황을
**사용자가 직접 만드는 새 경로**다.

반대로 좋은 소식도 있다. 바탕화면 위젯이 2026-08-18에 겪은 "다른 배율 모니터로 옮기면 그림이
옛 배율에 멈춰 절반만 보인다" 문제(`electron/desktopWidgetDpiRestore.ts`)는 **창을 새로 만드는
덕분에 원천적으로 일어나지 않는다.**

→ 편집 중(`memoEditorActivity`)에는 이동을 미루거나, 저장 후 이동한다.

### 🟡 T4. Windows에서 모니터 번호는 세션 간에 바뀔 수 있다

`display.id`는 저장 키로 쓰기에 완전히 안정적이지 않다(특히 재부팅·케이블 재연결 후).
번호만으로 찾으면 T1의 덮어쓰기가 더 자주 터진다.

→ 저장할 때 `id`와 함께 **`label`·해상도·좌표를 같이 남기고**, `id`로 못 찾으면
그 정보로 한 번 더 찾는다.

### ⚪ T5. `anchorRightEdge()`는 테스트만 있고 호출자가 없다 (참고)

`sidePinGeometry.ts:185`에 정의되어 테스트 4건이 붙어 있으나 프로덕션 호출자가 0이다.
현재는 `sidePinBrowserWindow.ts:88`의 `applyFixedBounds()`가 요청 좌표를 강제 복원하는 방식으로
같은 문제를 막고 있다. 이번 작업 범위는 아니지만, 모니터 이동으로 배율이 섞이면 다시 볼 가치가 있다.

## 4. 사용자가 고르는 길 — 진입점 비교

| 진입점                     | 장점                                                                                                | 단점                                                                                                                                 | 판정                |
| -------------------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | ------------------- |
| **트레이 우클릭 메뉴**     | 옆핀이 접혀 있어도, 심지어 아직 안 켰어도 닿는다. 이미 "옆핀 손잡이 위치 초기화"가 같은 자리에 있다 | 발견성이 낮다                                                                                                                        | ✅ **1순위**        |
| **설정 → 위젯/창 탭**      | 발견성이 높고 "창 닫기 동작"·"시작 모습" 옆이라 맥락이 맞다                                         | 설정 창을 열어야 한다. 동기화되는 설정 저장소가 아니라 기기 전용 파일을 봐야 해서 배선이 하나 더 필요하다                            | ✅ **2순위 (함께)** |
| 옆핀 패널 안 "모양" 팝오버 | 보면서 바로 바꾼다                                                                                  | **고르는 순간 패널이 다른 모니터에서 새로 만들어지고, 커서는 옛 모니터에 남아 즉시 접힌다.** 사용자에게는 "옆핀이 사라졌다"로 읽힌다 | ❌ 제외             |
| 손잡이를 옆 모니터로 끌기  | 가장 직관적                                                                                         | 손잡이는 오른쪽 끝 고정이라 가로 끌기 개념이 없다. 끌기 판정·경계 넘김·되돌리기를 새로 만들어야 한다                                 | ⏸ 후순위            |
| 단축키 "다음 모니터로"     | 빠르다. 단축키 등록기가 이미 있다(`sidePin:toggle` 등 3개)                                          | 모니터가 3대 이상이면 몇 번 눌러야 할지 모른다                                                                                       | ⏸ 선택 사항         |

**권장: 트레이 + 설정 두 곳.** 배선(IPC)은 한 벌이면 둘 다 덮는다 — preload는 옆핀 창과
메인 창이 공유한다(`electron/sidePinBrowserWindow.ts`가 같은 `preload.js`를 쓴다).

## 5. 모니터를 어떻게 불러 줄 것인가

교사에게 `2528732444` 같은 번호를 보여줄 수는 없다. Electron의 `display.label`은 Windows에서
비어 있거나 `\.\DISPLAY1` 같은 값이 오기도 한다.

→ **좌표로 배치를 계산해 사람 말로 만든다.**

```
모니터 1 · 주 모니터 (1920×1080)
모니터 2 · 오른쪽 (2560×1440, 배율 150%)
```

주 모니터 기준 x좌표 비교로 왼쪽/오른쪽/위/아래를 정하는 **순수 함수**로 만들면
Electron 없이 테스트할 수 있다 — `sidePinGeometry.ts`가 이미 쓰는 방식 그대로다.
모니터가 여러 대일 때 번호만으로는 어느 것이 어느 것인지 알 수 없으므로, 배치 표시가 사실상 이름 역할을 한다.

## 6. 경계 — 건드리지 않아야 하는 것

- **동기화 설정에 넣지 않는다.** `useSettingsStore`는 기기 간에 동기화된다. 모니터 선택이 거기
  들어가면 학교 PC와 집 노트북이 서로의 값을 계속 덮어쓴다. `side-pin-device-state.json` 유지.
- **좌표를 저장하지 않는다.** 지금처럼 매번 작업 영역에서 다시 계산한다. 저장하는 것은
  "어느 모니터인가"뿐이다.
- **도메인 정본과 electron 사본을 함께 고친다.** `src/domain/entities/SidePinDeviceState.ts`가 정본이고
  `electron/sidePinDeviceState.ts`가 사본이다. `sidePinDeviceState.mirror.test.ts`가 동치를 강제한다.
