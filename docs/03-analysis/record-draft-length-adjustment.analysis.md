## 2. 권장 화면 흐름

기존 오른쪽 AI 패널에서 접어 펼치는 **[분량 조절]**을 제공한다. 별도 전체 화면이나 설정 페이지는 만들지 않는다.

- AI 결과 아래: `1,782 / 1,500바이트 · 282바이트 초과 [분량 조절]`
- 직접 쓰는 칸의 바이트 표시 옆에도 같은 버튼. 누르면 현재 입력을 대상으로 오른쪽 패널이 열린다.
- 출발점에 따라 대상은 `고른 AI 초안` 또는 `현재 작성 글`로 자동 선택하고 표시한다.
- 글이 비어 있으면 조절 불가. 기존 초안 생성으로 안내한다.

예시(수치와 결과는 화면 설계용 가상값):

```text
분량 조절                         대상: AI 초안 v2
현재 1,782바이트                   영역 한도 1,500바이트

목표 분량 [ 1,500 ] 바이트
[줄이기] [근거로 보충하기]

핵심 활동과 교사 평가를 유지하며 줄입니다.
                                  [조절안 만들기]

조절안 v3       1,782 → 1,463바이트 · 319바이트 줄임
[원문과 비교]                       [이 글로 바꾸기]
```

목표는 영역 한도를 기본값으로 두고 직접 입력 가능하게 한다. 목표보다 긴 글은 줄이기, 짧은 글은 근거로 보충하기를 기본 선택한다. 사용자가 더 짧게 쓰고 싶다면 목표를 낮춘다. 슬라이더는 작은 바이트 값을 정밀하게 고르기 어려워 첫 버전에서 제외한다.

`목표 분량`과 `영역 한도`를 구분한다. 목표 1,500은 정확히 1,500을 보장하는 약속이 아니라 상한 안에서 가까이 쓰라는 요청이다. 제안하는 내부 목표 범위는 목표의 95~100%(1,500이면 1,425~1,500B)이며 규정상 최소 분량으로 표시하지 않는다. 짧다는 이유만으로 경고색이나 품질 점수를 주지 않는다.

## 3. 줄이기와 보충하기의 차이

**줄이기**는 현재 글의 사실·활동·교사 평가를 보존하고 중복 표현과 장황한 설명부터 압축한다. 새 활동·성과를 추가하지 않는다.

**근거로 보충하기**는 현재 글과 같은 학생·영역·주제에 속한 전송 가능한 근거를 함께 읽는다. 초안에서 빠진 구체적인 과정·결과를 보충하며, 근거가 없으면 목표에 못 미쳐도 멈춘다. 문구는 `근거가 부족해 목표보다 짧게 작성했어요.`로 한다. 모델의 설명은 참고이며 사실 보존이 자동으로 검증됐다고 표시하지 않는다.

조절을 시작한 AI 판의 threadId를 기준으로 근거 범위를 고정한다. 현재 화면에서 선택한 다른 주제를 실수로 섞지 않는다. 직접 작성한 글은 현재 영역의 근거를 기본으로 쓰고 주제 범위를 명시한다. AI 제외·기재 금지 근거 필터, 이름 가림을 그대로 적용한다. 현재 글도 외부로 보내므로 동일한 마스킹·기재 금지 처리 정책을 적용해야 한다.

## 4. 실제 분량을 맞추는 처리

1. 학생·영역·과목, 조절할 원문, 원문 판, 목표, 근거 범위, 공급자·모델을 실행 시점에 고정한다.
2. 규정 지시문과 분량 조절 요청을 구성해 기존 구독 AI 경로로 실행한다.
3. 결과의 이름을 복원하고 문단 표식을 분리한 뒤, 실제 저장·복사할 본문으로 바이트를 계산한다. 모델이 적은 바이트 수는 믿지 않는다.
4. 목표 범위를 벗어나면 실제 측정값과 차이를 알려 최대 1회 자동 재조정한다. 근거 부족 응답은 늘리기 재시도에서 제외한다. 재전송도 같은 마스킹 경로를 사용한다.
5. 재시도 후에도 맞지 않으면 실제 수치와 미달·초과 이유를 표시한다. 무한 호출하거나 문자열 끝을 강제로 자르지 않는다.
6. 조절안은 새 AI 판으로 남기고 원문과 비교한다. 교사가 반영하기 전 현재 글은 바뀌지 않는다. 기존 판 상한 20개 정책을 따른다.
7. 실제 영역 한도를 넘으면 해당 결과의 반영을 비활성화한다. 개인 목표만 넘고 실제 한도 이내라면 `목표보다 N바이트 많음`을 표시하고 교사가 선택할 수 있게 한다. 뒤에 붙일 때는 기존 글+빈 줄+새 글의 합산 길이로 검사한다.

복원 전 별칭, 문단 역할 표식, 줄바꿈 정규화 때문에 프롬프트의 길이와 최종 본문의 길이가 다를 수 있다. 원문을 그대로 돌려준 응답도 감지해 `분량이 바뀌지 않았어요.`로 안내한다.

## 5. 구현 시 반드시 함께 해결할 연결부

- **미저장 글 전달:** 행의 `text`와 저장된 `draft.content`는 다르다. 초과 입력은 저장에 실패하므로 저장소에서 원문을 다시 읽으면 조절해야 할 글을 잃는다. 버튼은 행의 현재 입력을 직접 전달해야 한다. 현재 blur 시 저장된 글로 다시 동기화하는 흐름도 함께 점검한다.
- **편집 도중 결과 도착:** 실행 후 교사가 글을 더 고쳤다면 바로 덮어쓰지 않는다. 시작 원문과 최신 입력을 비교하고 최신 글과 재비교하게 한다.
- **원문 비교:** 기존 비교는 저장된 내 글과 AI 판을 비교한다. v2를 줄인 v3은 v2와 비교해야 하므로 조절 원문 비교가 추가로 필요하다.
- **반영 실패:** 현재 applyVersion은 onApply 실패를 화면 안내로 처리하는 catch가 없다. 초과·저장 실패 시 미리보기와 원문을 유지하고 오류를 표시해야 한다.
- **실행 상태:** 생성·분량 조절·형광펜 다시 표시의 중복 실행을 막는다. 학생·영역 이동이나 패널 닫기 후 도착한 결과가 다른 학생에게 반영되지 않게 한다. 일괄 생성은 현 학생 조절이 끝날 때까지 유지한다.
- **영역 한도:** 부모에서 계산한 한도와 검증 여부를 패널에도 전달한다. 초등의 미확인 한도를 새 기능이 강제 한도로 승격시키면 안 된다.
- **기록 상태:** AI 조절안을 반영하면 다시 교사 검토 대상이 되도록 상태와 되돌리기 처리를 확인한다.
- **데이터:** 기존 RecordAiDraft에 선택 필드로 조절 종류·목표·원문 판 ID를 추가하는 정도로 시작한다. 내 글의 영구 이력 보존은 ADR-085와 별도 결정이 필요하며 이번 제안에 포함하지 않는다.

첫 생성에도 같은 목표 분량을 선택적으로 전달하면 과다·과소 생성을 줄일 수 있다. 처음부터 학급 전체 분량 일괄 조절까지 확대하지 않고 한 학생의 조절·비교·반영을 먼저 완성하는 것을 권장한다.

## 6. 규정과 계산의 검증 범위

2026학년도 고등학교 공통과목은 일부 학년에 1·2 합산 제한이 있다. 따라서 모든 과목 칸을 무조건 1,500으로 채우는 설계는 피하고, 교사가 이번 글의 목표를 더 낮출 수 있어야 한다. 학기 간 자동 잔여량 계산은 과목 매핑이 필요한 별도 범위로 둔다.

- 교육부 종합지원포털, 2026-07-04 답변: https://star.moe.go.kr/web/contents/m30103.do?id=121823&schM=view
- 이번에 실제 나이스 입력창과 줄바꿈·특수문자 바이트가 일치하는지는 검증하지 않았다. 현재 계산식과 브릿지는 같은 계약을 사용하므로 계산식 수정은 양쪽 계약 확인과 함께 다룬다.

현재 코드 확인용으로 실행:

```text
npx vitest run src/domain/entities/__tests__/RecordDraft.test.ts src/domain/services/__tests__/recordDraftPack.test.ts src/adapters/stores/__tests__/useRecordDraftsStore.test.ts src/adapters/components/RecordDraft/__tests__/RecordDraftAiPanel.test.tsx --maxWorkers=2
Test Files 4 passed (4)
Tests 99 passed (99)
Duration 2.00s
```

이는 기존 바이트 계산·한도·근거 요청·AI 패널 동작 테스트다. 신규 분량 조절 기능의 검증이나 실제 AI 품질 검증은 아니다. 앱 코드를 변경하지 않아 전체 구현 게이트(tsc/lint/전체 test/regression-check)는 실행하지 않았다.

구현 후 확인할 시나리오:

- 1,782B 글을 1,500 목표로 줄여 한도 이내 반영. 원문과 핵심 사실 비교.
- 620B 글을 근거로 보충. 근거 부족·0건이면 허구 추가 없이 미달 안내.
- 초과로 저장되지 않은 현재 입력도 정확한 원문으로 전달되고 취소 시 유지.
- 첫 응답 초과 → 재조정 1회 → 여전히 초과 시 수치 표시·반영 차단.
- 한글·영문·공백·LF/CRLF·특수문자·별칭 복원·문단 표식 제거 뒤 길이 검사.
- 뒤에 붙이기 합산 초과, 저장 실패, 연결 해제, 같은 글 반환 처리.
- 생성 도중 학생/영역 전환·추가 편집·다중 클릭에도 잘못된 덮어쓰기 없음.
- 학급 운영과 수업 관리 모두 같은 흐름. 초등 한도 미확인·진로 영역·개인 목표 축소 유지.
- 실제 연결 AI로 합성 근거의 줄이기·보충하기 품질 확인, 원문과 결과를 교사 관점으로 대조.

구현 완료 시 프로젝트 전체 검증 게이트와 /docs 가이드 갱신 및 docs:check·landing build도 수행한다.
