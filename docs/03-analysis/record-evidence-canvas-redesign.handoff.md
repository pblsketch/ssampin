# 근거 지도 재설계 — 새 구현 세션 핸드오프

작성: 2026-09-11 · 작업 위치: `E:/github/ssampin` · 현재 브랜치: `main`

## 1. 요청과 권한

사용자는 Manyfast처럼 근거들을 플로우 그래프로 표현하고 직접 정리하는 경험을 원한다. 레퍼런스 조사와 개선 계획을 긍정적으로 평가했으며, 교사에게 기능·버튼·용어가 복잡하지 않고 기존 페이지와 연동되어야 한다는 보완을 요청했다. 그 보완까지 계획에 반영한 뒤 **새 세션에서 구현할 수 있도록 핸드오프**를 요청했다.

이전 조사 세션의 '구현하지 않음'은 당시 작업 범위다. 새 세션에서 이 문구를 구현 금지로 해석하지 않는다. 첨부 프롬프트는 계획에 따른 로컬 구현·테스트·문서 갱신을 요청한다. 이미 정한 방향의 재승인을 반복 요청하지 않고 일반적인 구현 선택은 근거를 남겨 진행한다. 실제 미해결 제품 선택이 기존 계약을 크게 바꿀 때만 좁혀 질문한다.

공유 상태 변경은 별도다. 이번 위임에 커밋·push·PR·릴리즈·배포·운영 DB 변경은 포함하지 않는다. 실제 학생 자료를 합성 테스트 자료로 덮어쓰지 않는다.

3. `docs/architecture-rules.md`, `docs/design-system.md`, `docs/coding-conventions.md`, `.impeccable.md`, 관련 `design examples/` 이미지.
4. ADR-083/085/086/093/103/104/105와 기존 `record-narrative-graph.plan.md`, `record-flow-graph-overlay.design.md` 중 관련 계약.
5. `docs/03-analysis/record-evidence-canvas-handoff-baseline.json`: 인계 직전 branch·HEAD·전체 `git status --short` 스냅샷. 파일 내용 백업이나 복구 수단이 아니며 최신 상태보다 우선하지 않는다.

현재 계획은 옛 ADR-103/104의 자유 캔버스 기각·읽기 전용 조망을 바꾸는 후속 방향이다. 옛 문서를 근거로 다시 레인/칩 보강으로 축소하지 않는다. 반면 원본 보존·학생 경계·AI 명시적 적용·글 저장 보호·한도 초과 저장 허용 등 무관한 계약은 유지한다. 변경 결정은 다음 빈 ADR 번호를 실제 확인해 후속 ADR로 기록한다. 번호를 미리 고정하거나 기존 결정의 역사를 삭제하지 않는다.

개발 스킬을 적용할 때 현재 런타임에서 해당 SKILL.md를 읽는다. `.agents/skills/ssampin-develop/SKILL.md`에 있는 병렬 UI/인프라 예시보다 사용자의 **main 단일 작업 위치·병렬 구현 금지**가 우선이다. 레이어 분해·검증은 활용하되 구현은 순차로 진행한다. 특정 도구/모델이 없다는 이유로 멈추거나 대체 모델명을 임의로 강제하지 않는다. tmux 전용 실행 환경을 전제로 하지 않는다.

## 3. 반드시 보존할 사용자 경험

- 새 사이드바 메뉴 없이 기존 **근거 정리 ↔ 초안** 유지. 지도는 근거 정리 본문이다.
- 상단 작업 버튼 최대 3개: **근거 추가 / AI로 정리 제안 / 이 근거로 초안 쓰기**. 강조는 마지막 하나. 학생 선택·보기·지도 조작과 구별해 실제 화면에서 센다.
- '작성 구성에 담기'라는 중간 단계를 만들지 않는다. 초안 준비에서 **글 순서 조정**을 필요할 때만 펼친다.
- 연결·분류·설명을 한 번도 편집하지 않아도 현재 범위의 근거로 초안 생성 가능. 평소 관찰 입력도 본문 우선·주제 선택.
- 같은 행동은 모든 진입점에서 같은 이름. 화면 위치 정돈은 **카드 위치 정돈**, AI 정리와 구분.
- AI 정리 제안은 기존 묶기·연결·배치 기능을 한 입구에서 제공. 상세 요청은 선택 사항. 적용 전 자료 쓰기 0회.
- 오른쪽 보조 공간은 하나. 근거 상세와 정리 제안, 초안 준비/결과가 해당 화면에서 교대로 사용.
- 다중 학생·날짜 입력, 일괄 초안 생성, 분량 조절, 기존 글 비교·반영·붙이기, 복사·내보내기를 보존.

전체는 여러 작은 작업 단위로 순차 실행한다. 단계별 결과를 저장하고 다음 단계로 진행한다. S0/P0 또는 시제품만 끝냈을 때 전체 구현 완료라고 하지 않는다. 세션이 끝나면 마지막 통과 단계·미완료 계약·다음 첫 명령을 남긴다.

React Flow/ELK는 후보이며 설치되어 있거나 호환성을 검증했다고 가정하지 않는다. 도입 전 React 18·현재 번들·라이선스·레이아웃 제약을 공식 문서로 확인하고 작은 합성 그래프로 선택 근거를 남긴다. 패키지 추가는 로컬 구현 범위지만 잠금파일 삭제로 해결하지 않는다. domain/usecases에 그래프 라이브러리 타입을 유출하지 않는다.

## 6. 핵심 실패 시나리오

- 같은 이름/같은 번호의 다른 학생·수업반, 다른 학기/과목 근거가 섞임.
- A→B, A→C, B→D, C→D가 직렬 B→C로 보이거나 선택한 D가 AI 입력에서 누락됨.
- 카드 이동/관계 삭제가 근거 소유·원본·글 순서를 바꿈.
- 원본 수정/삭제·재제출 뒤 이전 AI 응답이 최신 글이나 근거를 덮어씀.
- 수합에서 이미 추가한 제출물을 또 추가하거나, 과목·학생을 다시 선택해야 함.
- 탭 이동/학생 변경 시 미저장 글이 사라짐. 저장 실패를 성공으로 표시.
- 근거 0건 또는 제외 근거만 선택했는데 생성됨. 4개 이상 연결을 말없이 3개로 축소.
- AI 정리 제안을 누르는 즉시 저장. AI 연결 설명을 교사의 관찰 사실로 저장.
- 버튼을 숨겨 비교/제외/원본/실패 상태를 찾지 못함. 연결을 만들지 않으면 생성 불가.
- 큰 글꼴·좁은 창에서 카드 전문/초안 버튼이 잘림. 키보드만으로 연결 불가.

UI 위치는 기기별 보관을 기본으로 하되 의미 관계는 기존 보관/동기화 계약에 포함한다. 새로운 관계 저장 파일의 실패·백업·복구 경로를 빼먹지 않는다. 구버전 복귀가 신규 관계를 소실시키지 않는 정책을 P0에 명시한다.

## 7. 검증 명령과 증거

인수용 기존 테스트(두 명령은 별도 실행):

```bash
npx vitest run src/domain/rules/__tests__/narrativeScenes.test.ts src/adapters/components/RecordDraft/__tests__/narrativeFlowView.test.tsx --maxWorkers=2
npx vitest run src/adapters/components/RecordDraft/__tests__/recordFlowIntent.test.ts src/adapters/components/RecordDraft/__tests__/recordEvidenceFlow.test.tsx src/adapters/components/RecordDraft/__tests__/draftFlushRegistry.test.ts --maxWorkers=2
```

조사 세션 결과는 각각 **2파일/47개**, **3파일/44개 통과**. 새 세션 baseline이나 새 캔버스의 구현 증거가 아니므로 현재 상태로 재실행한다.

단계별 관련 회귀 검사와 필수 게이트:

```bash
npx tsc --noEmit
npm run lint
npm run test
npm run regression-check
npm run build
```

가이드는 `landing/src/content/docs.ts`, 이미지는 `landing/public/docs/screenshots/` 갱신. `landing` 디렉터리에서 각각 실행:

```bash
npm run docs:check
npm run build
```

기존 실패가 있다면 최초 출력으로 기록하고 이번 변경과 구별한다. 검사를 제거하거나 `--no-verify`로 우회하지 않는다. 현재 단계 영향 밖의 실패를 임의 대규모 수정하지 않는다. 전체 게이트 미통과 상태는 미통과로 보고한다.

브라우저 QA는 런타임에서 사용 가능한 관련 스킬을 먼저 읽고 로컬 HTTP 서버로 실행한다(`file://` 금지). 합성 데이터 전용 브라우저 프로필/저장공간을 쓴다. 기존 `seed:record-flow` 스크립트는 대상 저장 위치·원복 방법을 읽기 전 실행하지 않는다. 실제 사용자 Electron 데이터를 지우거나 초기화하지 않는다.

실제 AI/실기기 접근이 없으면 모의 테스트·브라우저 검사와 명확히 구분한다. 교사 3~5명의 명칭 이해·독립 과업 수행은 사람이 참여해야 하는 별도 검증이며 자동 테스트로 대체했다고 하지 않는다. 가능한 구현·자동 검증은 계속 진행하고 미확인 범위를 정확히 남긴다.

## 8. 종료 기록

실행 체크리스트/AC 대응 증거는 `docs/03-analysis/record-evidence-canvas-redesign.execution.md`에 새로 작성한다. 아직 이 파일은 없으며 새 세션이 실제 수행한 결과만 기록한다. 계획서를 읽은 것만으로 AC를 통과 처리하지 않는다.

월별 진행 기록 최신 위에 단계·명령·출력 요약·실제 화면 증거·잔여를 남기고, PROGRESS는 3~5줄 및 링크/300줄 상한을 지킨다. 사용자 보고는 무엇이 가능해졌는지·어떤 검증을 통과했는지·어떤 부분이 미검증인지 짧게 쓴다.
