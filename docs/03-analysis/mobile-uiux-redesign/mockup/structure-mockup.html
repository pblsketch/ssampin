출결은 탭일까, 반 안에 있는 걸까

준일님이 지적하신 부분입니다. 출결은 학급과 수업에서 하는 일이니, "출결"이라는 독립된 장소가 따로 있는 게 아니라는 것.

이게 왜 중요하냐면, 애플 가이드라인이 "탭은 이동만 담당하고, 탭 버튼으로 동작을 실행하면 안 된다"고 못박기 때문입니다. 제가 앞서 드린 A안(출결 탭 승격)은 이 원칙에 걸립니다.

두 안의 차이는 한 줄입니다. A안은 "자주 하니까 앞에 두자", B안은 "반 안에서 하는 일이니 반 안에 두자".

B안으로 확정하되, 담임과 수업을 각각 탭으로 분리했습니다(2026-08-12 결정). 원래 시안은 "학급" 한 탭 안에 담임과 수업을 세그먼트로 다시 나눴는데, 그럴 이유가 없다는 판단입니다. 코드를 확인해 보니 근거가 더 있었습니다.

  • check_circle담임 기록과 수업반 기록은 저장되는 곳이 아예 다릅니다 — 담임은 StudentRecord, 수업반은 ObservationRecord로 저장소가 따로 있습니다.
  • check_circle화면 폴더도 이미 갈라져 있습니다 — pages/students/(담임 계열)와 components/Class/(수업반 계열).
  • check_circle즉 속은 이미 나뉘어 있는데 겉의 탭만 하나로 묶고 세그먼트로 다시 갈라놓은 상태였습니다. 탭을 나누는 게 속과 겉을 맞추는 쪽입니다.
  • check_circle담임반 3-2에 국어 수업도 들어가는 경우, 같은 반이 두 군데 보이지만 하는 일이 다릅니다 — 학급의 3-2는 조회·생활기록, 수업의 3-2는 교시 출결·진도.

06 — 뒤로가기

이건 시안이 없습니다. 눈에 안 보이는 문제라서요

지금 안드로이드에서 룰렛을 열고 뒤로가기를 누르면, 이전 화면이 아니라 앱이 닫힙니다. 팝업을 열고 눌러도 마찬가지입니다.

색이나 팝업을 아무리 다듬어도 이건 안 고쳐집니다. 화면마다 주소를 붙여야만 고쳐집니다. 지금은 주소가 없어서 폰이 "돌아갈 데가 없다"고 판단하고 앱을 닫는 겁니다.

이게 "마감 공사가 아니라 구조 재설계"라는 결정의 실질적인 내용입니다. 그리고 부수 효과가 큽니다 — 지금 앱 중심 파일에 도구 18개가 이름으로 하나하나 나열돼 있는데, 주소를 붙이면 이게 한 줄로 접힙니다. 도구를 늘리거나 자리를 바꿀 때 그 파일을 안 건드려도 됩니다.
덤으로 따라오는 것

되돌리기

주소가 생기면 팝업도 뒤로가기로 닫힙니다. 그리고 삭제할 때 되돌리기를 붙일 자리도 같이 생깁니다.

07 — 정리

순서는 이렇게 하는 게 맞습니다

눈에 보이는 것부터 하고 싶은 게 자연스럽지만, 그러면 손해입니다. 지금 팝업이 17개 파일에 각자 따로 만들어져 있어서, 재설계하면서 "이건 팝업으로 빼자"고 할 때마다 18번째, 19번째가 늘어납니다.

토큰 대신 직접 박은 색도 지난 계획 때 149건이었는데 지금 280건입니다. 그냥 두면 줄지 않고 늡니다.

확정된 결정 · 2026-08-12

이만큼 정해졌습니다

  • 탭 — 홈 · 학급 · 수업 · 일정 · 더보기. 출결은 탭이 아니라 반 안의 세그먼트.
  • 학급 탭 — 기본은 표시, 설정에서 숨길 수 있음. 담임이 없으면 안내 문구.
  • 도구 — 더보기 안에 유지. "쌤도구" 중간 문만 없애 3번 → 2번.
  • 반 선택 — 눌러서 고르는 방식. 헤더 3층 → 1층.
  • 출결 — 다른 학생만 누르는 방식. 3,180px → 1,350px.
  • 출결 저장 — 직전에 반·날짜 확인 한 번.
  • 일정 / 할 일 — 세그먼트 유지. 보관함은 유지하되 목록 맨 아래로 자리 이동.
  • 일정 달력 — 주 단위 기본, 월은 펼쳐서 봄.
  • 홈 — "오늘 남은 일"에 출결과 할 일 합류.
pending아직 안 정한 것

홈 카드 숨김·순서 변경(05번 홈에서 다룬 항목)은 아직 결정되지 않았습니다. 넣는다면 홈에 편집 손잡이를 두지 말고 설정에서만 바꾸도록 하는 게 안전합니다 — 데스크톱에서 위젯 손잡이가 위젯 버튼을 삼켰던 것과 같은 구조의 위험이라서요.

그리고 Fantastical의 주/월 접기 방식은 [관측] 등급입니다. 이번에 스크린샷으로 확인하지 못했습니다. 주 단위 기본은 NN/g의 고정 영역 원칙만으로도 근거가 서지만, 세부 동작은 실물 확인이 남아 있습니다.

작업 순서 제안

공용 부품과 주소를 먼저, 화면은 그 위에

  • 1단계 — 팝업·헤더·되돌리기를 공용 부품 하나씩으로. 그리고 화면마다 주소 붙이기(뒤로가기 해결).
  • 2단계 — 출결을 "다른 애만 누르는" 방식으로. 매일 여러 번 쓰는 화면이고, 데이터는 이미 준비돼 있습니다.
  • 3단계 — 학급 화면 헤더를 한 층으로.
  • 4단계 — 탭을 홈 · 학급 · 수업 · 일정 · 더보기로. 담임 아닌 선생님의 빈 학급 탭 처리 포함.
  • 5단계 — 더보기 첫 화면에 도구 그리드와 검색.
  • 6단계 — 할 일에서 보관함을 전환에서 빼고, 일정 달력을 주 기본으로.
  • 7단계 — 홈 "오늘 남은 일"에 출결과 할 일 합류. 앞 단계가 끝나야 붙일 게 정해지므로 마지막입니다.
warning착수 전에 확인할 것

주소 붙이는 작업은 앱 중심 파일 하나를 크게 건드립니다. 이 파일은 이 프로젝트에서 가장 많이 수정된 파일이라 다른 세션과 부딪힐 위험이 가장 큽니다. 시작하기 전에 다른 작업이 이 파일을 만지고 있지 않은지 확인해야 합니다.

그리고 데이터가 흐르는 배관(저장·동기화·규칙)은 하나도 건드리지 않습니다. 바꾸는 건 화면을 조립하는 층까지입니다.

이 파일은 결정을 위한 시안이고 앱 코드가 아닙니다. 여기서 정한 것만 실제 화면으로 옮깁니다.
