## 2. 재설계가 실제로 건드려야 하는 지점

### P1. 학생 탭 — 헤더가 3층

`StudentsPage.tsx:340-479`. 콘텐츠 위에 헤더만 3줄이 쌓인다.

1. 제목 + 기록보기 아이콘 + 좌석/명단 토글
2. 반 선택 가로 스크롤 탭 (담임반 + 수업반 N개)
3. 날짜 이동바 (← 8월 12일 (화) → · "오늘로 가기")

여기에 App 전역 헤더와 세그먼트까지 더하면 **첫 학생이 보이기 전까지 5개 층**을 지난다.

### P2. 출결 체크 — 세로 스크롤 폭증

`AttendanceCheckPage.tsx:657-806`. 학생 1명당:

- 이름 줄
- 상태 버튼 5개 (grid-cols-5, 각 52px)
- 출석이 아니면 → 사유 칩 4종 + 메모 입력칸이 **펼쳐짐**

30명이면 최소 30 × (24 + 52) ≈ 2,300px. 결석자가 생기면 더 늘어난다.

> **[2026-08-12 정정]** 위 추정은 행 위아래 여백(`px-4 py-3` = 24px)을 빼먹었다. 목업 실측 기준 **행 하나가 106px**이라 30명이면 **약 3,180px**. 실제 상태는 여기 적힌 것보다 더 길다. 근거: `mockup/structure-mockup.html`
> 상단엔 6칸 카운터(`:658`)가 고정으로 자리를 먹는다.

### P3. 더보기 — 18개가 평평한 리스트 뒤에 숨음

`MorePage.tsx:64-103`은 메뉴 5줄뿐이고, 쌤도구 14종은 그 안쪽 한 단계 더 들어가야 한다. 검색 없음, 즐겨찾기 없음, 최근 사용 없음.

### P4. 라우터 부재 — 안드로이드 뒤로가기 미지원

`App.tsx:139-165`. 탭·하위페이지·전체화면 전환이 전부 `useState`.
주소가 없어서 **하드웨어 뒤로가기가 앱을 종료시킨다.** 바텀시트를 열고 뒤로가기를 눌러도 마찬가지.
→ 구조 재설계의 핵심 항목. 선행 계획에서는 "범위 제외"였다.

### P5. 표준 부재로 화면마다 다른 모양

| 항목                   | 실측                          | 위치                                                                                    |

## 3. 건드리지 않을 것 (무손상 경계선)

재설계는 **화면 조립 층만** 바꾸고 아래는 그대로 둔다.

- `src/mobile/stores/` 28개 스토어 — 데이터 로드·저장·동기화
- `src/domain/` — 출결 판정, 학기 판정, 팬아웃 배정 등 규칙
- `src/mobile/di/container.ts` — 저장소 연결
- 동기화 프로토콜 일체 (Drive 업/다운로드, 충돌 처리, 매니페스트)

특히 다음은 과거 데이터 사고 이력이 있어 절대 우회 금지:

- 출결은 **학번(number)으로 식별** — 번호 없는 학생 기록 차단 로직(`StudentsPage.tsx:236`, `AttendanceCheckPage`)
- 그룹 학급 공유 레코드 조회는 반드시 `findAttendanceRecordForClass` 경유(`StudentsPage.tsx:91-99`)
- 빈 명단 저장 차단(`AttendanceCheckPage.tsx:580`) — 그날 출결이 지워짐

## 4. 회귀 방지 방법

단계마다 CLAUDE.md 검증 게이트 4종 통과 후 다음 단계로.

```bash
npx tsc --noEmit
npm run lint
npm run test
npm run regression-check
npm run build:mobile
```

추가로 이 저장소엔 **소스를 직접 검사하는 계약 테스트**가 있다(바텀시트 커버리지, 위젯 손잡이 마커, 담임 매핑 등). 화면을 갈아엎으면 이 테스트가 먼저 빨간불을 낸다.
원칙: **테스트를 고쳐서 통과시키지 않는다.** 테스트가 지키려던 기능을 새 구조에서도 유지하는 방식으로 해결한다.

실화면 검증은 `npm run dev:mobile -- --host 127.0.0.1` → 390px 뷰포트, 라이트/다크 양쪽.
(vite 개발 서버 2개 동시 실행 금지 — 무한 로딩)

## 5. Mobbin 레퍼런스 조사 브리프

MCP 등록·인증 완료 (`https://api.mobbin.com/mcp`). 조사 축 7개:

| #   | 찾을 것                                          | 대응 문제 |
| --- | ------------------------------------------------ | --------- |
| R1  | 기능 많은 업무앱의 하단 탭 구성 원칙             | 전체 IA   |
| R2  | 반 선택 + 날짜 이동 + 뷰 전환을 겹치지 않게 배치 | P1        |
| R3  | 다수 하위 메뉴를 검색·즐겨찾기·그룹으로 푸는 법  | P3        |
| R4  | 30명 상태를 빠르게 찍는 밀도 높은 체크 입력      | P2        |
| R5  | 카드 숨김·재배치가 있는 홈 대시보드              | 홈        |
| R6  | 캘린더 + 리스트 결합                             | 일정      |
| R7  | 스와이프 빠른 액션 + 되돌리기 / 바텀시트 표준    | P5        |

레퍼런스 앱군: 소비자 SNS 아님. **현장 업무앱**(근무 관리, 진료 차트, 출석 관리, 검수).
