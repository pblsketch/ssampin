# 성적 일람표 입력 구조 조사 (2026-09-13)

## 범위와 확인 수준

파일 호환성 조사만 수행했다. 제품 코드와 분석 기능은 변경하지 않았다.
아래는 지원 후보 구조와 독립적으로 작성한 가상 자료다. 제보자의 실제 파일이나 NEIS 공식 표준 전체를 검증한 결과가 아니다.

## 우선 지원할 구조

과목이 가로 열에 배치되고 한 학생의 점수·성취도·석차등급이 여러 행을 차지한다.
학생 번호와 이름은 첫 행에만 있거나 여러 행에 걸쳐 병합될 수 있다.

| 번호 | 성명     | 교과목   | 국어(4)  | 수학(4)  |
| ---- | -------- | -------- | -------- | -------- |
| 1    | 가상학생 | 합계     | 91.2(91) | 83.5(84) |
|      |          | 성취도   | A        | B        |
|      |          | 석차등급 | 1        | 2        |
|      |          | 과목평균 | 73.1     | 68.4     |

표의 과목명·학점·점수·학생명은 가상 값이다. `합계` 표기는 재현용 가정이며 실제 점수 행 명칭은 추가 확인 대상이다.

- 제목 영역: 학년도·학기·학년·반이 성적 본문과 분리될 수 있다.
- 과목명: 괄호에 학점 또는 단위수가 붙을 수 있다. 과목 이름 자체의 괄호와 구분해야 한다.
- 점수: 소수 점수와 괄호 속 정수 점수가 한 셀에 있을 수 있다. 두 값의 의미를 공식 자료 또는 실제 양식으로 확인한 뒤 원점수 매핑을 확정한다.
- 공통 행: 과목평균·성취도별 분포비율은 학생 개인 성적과 구분한다.
- 반복 표: 한 시트에 머리글과 과목 블록이 반복될 수 있다. 반복 구간에서 학생·과목 연결이 잘못 이어지지 않아야 한다.
- 정오표·문항정보표·수행평가 점수표는 별도의 입력 유형이다. 전과목 일람표의 구조 근거로 혼용하지 않는다.

## 현재 코드와의 불일치

`detectTranscriptLayout`은 한 행에서 번호/성명 중 하나와 성적 필드 2개 이상을 요구한다.
위 구조에서는 머리글에 과목명만 있고 학생별 행에 성적 필드가 하나씩 나타나므로 레이아웃을 찾지 못한다.
`parseTranscriptRows` 역시 학생 한 명을 한 행으로 처리한다.
따라서 파일을 읽는 데 성공해도 학생 0명으로 반환되어 일반적인 양식 확인 안내가 표시된다.

관련 위치:

- `src/domain/rules/neisTranscriptImportRules.ts`
- `src/infrastructure/parse/NeisTranscriptExcelParser.ts`
- `src/infrastructure/parse/sheetGrid.ts`
- `src/adapters/components/Homeroom/GradeOverview/HomeroomGradeOverviewTab.tsx`

## 검증

가상 자료를 ExcelJS로 생성해 실제 `parseTranscriptExcel`에 전달했다.

| 입력                                     | 결과                  |
| ---------------------------------------- | --------------------- |
| xlsx, 학생별 3행, 번호·성명 첫 행만 기재 | layout=null, 학생 0명 |
| xlsx, 학생별 3행, 번호·성명 세로 병합    | layout=null, 학생 0명 |
| HTML형 xls, 학생별 3행, rowspan 병합     | layout=null, 학생 0명 |

실행: `npx vitest run src/infrastructure/parse/transcript-ledger-format-probe.test.ts src/domain/rules/neisTranscriptImportRules.test.ts src/infrastructure/parse/sheetGrid.test.ts --maxWorkers=2`

결과: 3파일 19검사 통과. 신규 검사는 실패 현상이 발생함을 확인한 진단 검사 2개다. 수정 성공을 의미하지 않는다. 임시 검사 파일은 제거했다.
전체 검증 게이트·실제 사용자 파일·앱 화면 검증은 수행하지 않았다.

## 독립 구현 시 수용 기준

1. 기존 학생 1행 양식과 학생 여러 행 양식을 별도로 감지한다.
2. 고정된 3행 간격에만 의존하지 않고 행의 항목명을 읽어 학생별로 묶는다.
3. 병합/빈칸, 반복 머리글, 공통 통계 행, 학생 경계에서 연결을 검증한다.
4. 원점수·성취도·석차등급을 각각 보존한다. 빈 등급을 성취도에서 임의 환산하지 않는다.
5. 과목명과 학점, 소수 점수와 괄호 점수의 의미를 구분한다. 불명확한 값은 추정해 확정하지 않는다.
6. 이름만으로 다른 반 학생을 합치지 않는다. 저장 전 현재 학급과 파일의 학급 범위를 확인한다.
7. 파일 읽기 실패, 양식 감지 실패, 감지 후 학생 없음의 안내를 구분한다.
8. 시트 탐색은 별도 보완 대상으로 다룬다. 여러 시트가 있으면 첫 시트만 읽고 실패하지 않도록 하되 여러 학급을 무조건 합치지 않는다.

다음 단계는 이 형식 명세와 가상 자료를 기준으로 기존 구조 안에서 구현·검증하는 것이다. 제보 원인 확정과 실제 NEIS 양식 지원 완료는 원본 또는 공식 예시 검증 전까지 보류한다.
