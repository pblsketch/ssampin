E:/github/ssampin에서 생기부 AI 작성 방식 라이브러리 작업을 이어서 진행해 줘.

이 작업의 이유는 현재 초안이 고정된 시스템 프롬프트와 순서를 따라 수업·학생의 특성을 충분히 드러내지 못하기 때문이야. 여러 템플릿 선택, 구성 요소 조합, 사용자 커스텀 지시를 결합하려고 해. 대학 가이드북·실제 지원자 사례·교사 연수자료를 조사했고, 특히 동국대 자료까지 반영했어.

먼저 AGENTS.md를 따르고 git status --short와 현재 브랜치를 확인해. main의 다른 세션 변경을 보존해. PROGRESS.md와 DECISIONS.md를 읽은 다음 아래 문서를 순서대로 읽어 줘.

2. docs/03-analysis/record-draft-template-library-v2-research-20260909.md

목표는 기본 초점 8종과 행특 기본 구성, 독립적인 시작·묶기 설정, 모듈 조합, 사용자 지시, 내 작성 방식 저장·재사용을 구현하는 거야. 구체적인 필요 근거와 생략 조건은 v2 문서를 따라 줘. 기존형과 기존 초안은 보존하고, 자료에 없는 성장·동기·갈등·진로 연결을 만들지 마. 수업 맥락과 학생 개인의 수행을 구별하고 관찰 본문 입력을 계속 우선해.

지금까지는 조사·제안 단계이고 기능 구현과 실제 AI 생성 검증은 아직 안 했어. 새 세션에서는 핸드오프의 S0~S5를 따라 기준선 확인 → 상세 설계·테스트 명세 → 순차 구현 → 실제 생성 비교·화면 QA → 전체 게이트·사용자 가이드 갱신까지 진행해 줘. 계획 작성만 하고 끝내지 말고 로컬에서 검토 가능한 결과까지 완수해. 세부 구현 선택은 근거를 기록하며 진행하고, 중대한 미확정 사항만 구체적으로 질문해.

가장 중요한 점은 서버 L1과 앱의 고정 서사 지시가 동시에 존재한다는 거야. 선택 UI만 만들면 문제가 해결되지 않아. ADR-094를 읽고 기존 결정에서 바뀌는 부분을 새 ADR에 명시해. 공통 규정과 작성 구성을 분리하고, 구버전·캐시·규정 판본 호환성 및 되돌리기를 설계해. 비공개 서버 프롬프트 본문을 저장소·로그에 노출하지 마.

핸드오프 AC-01~15를 검증 증거와 연결해. 특히 동일 가상 근거를 여러 초점으로 실제 생성해 사실 보존과 구성 차이를 확인하고, 학생 전환·본문 수정·중단·늦은 응답·저장 실패·마스킹·분량 조절·구데이터도 검사해. 모의 테스트와 실제 모델/실제 Electron/설치본/운영 검증을 구별해서 보고해.

tsc, lint, test, regression-check, build와 변경된 공개 가이드의 docs:check/build를 실행하고 결과를 기록해. 다른 세션의 테스트 결과를 이번 작업의 증거로 사용하지 마. 필요한 계획·설계·QA·보고서와 PROGRESS/월별 기록을 갱신해.

운영 시크릿 변경·DB 변경·push·배포는 자동으로 하지 마. 필요한 로컬 구현·검증과 구체적인 적용/되돌리기 안을 먼저 끝내고 운영 승인을 마지막에 요청해. 실제 모델 접근이나 운영 의존성 때문에 확인하지 못한 항목은 미검증으로 남겨 명확히 설명해.
