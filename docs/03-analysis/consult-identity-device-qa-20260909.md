# 상담·설문 교사 신원 전환 — 실기기 확인 (2026-09-09)

대상: ADR-095 / 마이그레이션 071·072 / 엣지 함수 `consultation-teacher`·`survey-teacher` / 앱 교체분.
계획서 §9.4 실기기 목록 13종을 Claude 세션이 CDP 로 앱을 조종해 대행했다.

## 어떻게 했나

- 준일님이 이미 `npm run electron:dev` 를 띄워 둔 상태여서 **vite 를 하나 더 띄우지 않았다**
  (같은 `node_modules/.vite/deps` 를 두 서버가 다투면 양쪽이 다 죽는다 — 기록된 사고).
  이미 도는 vite(5173)에 **확인 전용 Electron 창만** 붙였다:
  `VITE_DEV_SERVER_URL=http://localhost:5173 electron . --user-data-dir=.dev-data --remote-debugging-port=9333`.
- 조종은 `scripts/qa-cdp-driver.mjs`, 시나리오는 `E:/test/ssampin-consult-security/qa-*.mjs`(커밋 안 함).
- 암호문은 **랜딩의 진짜 `encrypt` 를 파일에서 꺼내** 만들었다. 내가 다시 구현하면 "내 구현끼리"
  맞춰 보는 셈이라 판 판정 시험의 의미가 없어진다.
- 시험 일정·설문은 `【QA】` 제목으로 만들고 확인 후 전부 지웠다(잔여 0).
  확인용 창의 구글 연결도 끊었다.

★ **엣지 함수 첫 호출은 콜드 스타트로 느리다.** 3.5초 뒤에 화면을 읽었더니 배너가 아직 없어서
"결함"으로 잘못 판단할 뻔했다. 8초로 늘리니 정상이었다. 화면 판정은 넉넉히 기다릴 것.

## 실기기에서만 잡힌 결함 1건 (수정 완료)

**설문 화면인데 "이 일정을 만든 계정"이라고 떴다.** 거부 사유 문구를 상담과 설문이 함께 쓰는데
명사가 상담 쪽에 고정돼 있었다. 게이트 4종·단위 테스트는 전부 초록이었다 — 두 화면이 같은
문구를 쓴다는 사실은 문자열만 봐서는 드러나지 않는다.

고친 방식: 문구에서 "일정"이라는 말을 뺐다. 무엇을 못 열었는지는 배너 제목이 이미 말한다
("명단을 불러오지 못했습니다" / "응답을 불러오지 못했습니다").

- `different_account`: "만든 사람의 구글 계정으로만 열 수 있습니다. 설정 > 구글 연결에서 그 계정으로 바꿔 주세요."
- `legacy_closed`: "예전 방식으로 열 수 있는 기간이 끝났습니다. 이 기기에 받아 둔 사본이 있으면 아래에 표시됩니다."
- `owner_bound`: "만든 선생님의 구글 계정으로만 열립니다. …"

앱에서 바뀐 문구를 다시 확인했고, 옛 문구를 고정하던 테스트도 함께 고쳤다.
