# 사진 명렬표 얼굴-이름 학습 — 실기기 확인 시나리오

- 대상 커밋: `76d984f0` ~ `26bc497b` (계획 `d9dc459c` 포함 10개)
- 작성일: 2026-08-19
- **릴리즈 보류 중** — 수업반 지원은 끝났고, 이제 **실기기 확인만 남았다** (§0)

## 0. 먼저 알아야 할 것 — 무엇이 끝났고 무엇이 남았나

오너 결정(2026-08-19)은 **수업반 기능이 구현될 때까지 출시 보류**였습니다.
그 조건은 2026-08-20 에 **충족됐습니다** — 수업반 사진 명렬표를 넣으면 기존 명단에
얼굴만 얹는 경로가 구현되어, 담임·수업반 두 경로가 모두 돕니다.

수업반이 어려웠던 이유는 파일이 아니라 **앱 안에서 수업반 학생을 구분하는 방식**이었습니다.
담임 학생은 절대 바뀌지 않는 고유번호를 갖지만, 수업반 학생은 `학년-반-번호` 조합뿐이라
번호가 바뀌면 사진이 옆 학생에게 옮겨 붙습니다. 그래서 **번호가 같아도 이름까지 같아야**
붙이도록 했고, 사진 이름표를 `수업반id--학년-반-번호` 로 갈라 한 반을 지워도 다른 반이
멀쩡하게 두었습니다.

**남은 것은 실기기 확인 하나**입니다. 기능은 `FEATURE_FLAGS.studentPhotos` 로 아직 잠겨
있고, 이 확인이 끝나야 켜서 내보냅니다. 확인용으로 켜려면 저장소 뿌리에 `.env.local` 을
만들고 `VITE_FEATURE_STUDENT_PHOTOS=true` 를 넣은 뒤 개발 서버를 다시 띄웁니다.

**그러므로 이번 확인의 목적**은 **"담임·수업반 두 경로가 실제 파일로 제대로 도는가"**입니다.

## 1. 준비물

- 나이스에서 받은 **사진 명렬표** — 한글(`.hwp`) 또는 엑셀(`.xlsx`), 최신 형식
- 가능하면 **사진 없는 그냥 명렬표**도 하나 (안내 확인용)
- 가능하면 **예전 형식 파일**도 하나 (안내 확인용)
- 담임 반 명단이 들어 있는 상태
- **기능 스위치를 켠 상태** — 저장소 뿌리에 `.env.local` 을 만들고
  `VITE_FEATURE_STUDENT_PHOTOS=true` 를 넣은 뒤 개발 서버를 다시 띄웁니다.
  (켜지 않으면 `[사진 명렬표]` 버튼과 `이름 쓰기` 모드가 아예 보이지 않습니다 — 버그가 아닙니다.)

> 💡 **실제 학생 사진이 없어도 확인할 수 있습니다.**
> `_workspace/test-rosters/` 에 진짜 나이스 파일과 같은 구조로 만든 **가짜 얼굴 44장짜리**
> 담임·수업반 명렬표가 들어 있습니다(자세한 순서는 그 폴더의 `README.md`).
> 얼굴마다 생김새가 다르고 사진 아래에 이름이 찍혀 있어 **얼굴과 이름이 맞게 붙었는지**
> 눈으로 바로 확인됩니다.

> ⚠️ 확인이 끝나면 **설정 → 백업/복원 → 학생 사진 → 모두 지우기**로 정리해 주세요.
> 실제 학생 얼굴 사진이 테스트용 PC에 남지 않도록 합니다.

## 2. 가져오기 (가장 중요)

### 2-1. 정상 가져오기

1. 학급 운영 → 명렬 관리 → **[사진 명렬표]** 버튼
2. 나이스 사진 명렬표 파일을 끌어다 놓기(또는 선택)
3. 확인 화면에 **얼굴이 격자로** 보이는지

| 봐야 할 것        | 정상                                          |
| ----------------- | --------------------------------------------- |
| 학생 수           | 실제 인원과 같음                              |
| 얼굴 사진         | 각 칸에 보임 (회색 사람 모양이 아님)          |
| 이름              | `1번 홍길동` 형태로 사진 아래                 |
| **1번 학생 얼굴** | **명렬표 원본과 같은 사람인가** ← 이것만은 꼭 |

4. 확인 질문 **두 개를 체크하기 전에는 [명단에 반영] 버튼이 눌리지 않는지**
5. 반영 후 토스트에 `… · 사진 22장` 이 뜨는지

### 2-2. 사진이 없는 명렬표

- 파랑 안내 **"사진이 들어 있지 않아요. 이름만 가져올게요"**
- 격자는 **회색 사람 모양**, 이름은 정상
- 반영하면 이름만 들어감

### 2-3. 예전 형식 파일

- **빨강 안내**가 뜨고 **확인 단계로 넘어가지 않는지**
- 문구가 "나이스에서 최신 형식으로 다시 받아 주세요" 취지인지
- ❌ "열 수 없는 파일입니다" 같은 막다른 안내면 **버그**

### 2-4. 이름이 다른 학생이 있을 때 (충돌)

명단에 이미 있는 학생과 이름이 다른 경우를 일부러 만들어 보세요
(예: 명단에서 한 명 이름을 살짝 바꾼 뒤 가져오기).

- 충돌 해결 창이 뜨는지
- ⚠️ **이때 "명단에 반영했어요" 완료 화면이 같이 뜨면 버그** (고쳤지만 재확인)
- 창이 **두 개 겹쳐 보이면 버그**
- ⚠️★ **충돌을 해결해 반영한 뒤 사진이 실제로 저장됐는지** — 2026-08-20 에 실제로 터진 결함입니다.
  "취소하면 사진을 버린다"와 "충돌 창이 뜨면 이 창을 닫는다"가 서로 부딪혀,
  **이름은 들어가는데 사진만 0장**이 되었습니다. 확인 방법:
  자리배치 → `[이름 학습]` 에서 `이름 쓰기` 가 **눌리는지**(잠겨 있으면 사진이 0장),
  또는 설정 → 백업/복원 → 학생 사진 장수

### 2-5. 취소했을 때 사진이 안 남는지 ★

1. 사진 명렬표 가져오기 → 충돌 창 → **취소**
2. 이어서 **[엑셀 가져오기]** 나 **[일괄 입력]** 으로 다른 명단 반영
3. 토스트에 **`· 사진 N장` 이 뜨면 버그** (취소한 사진이 저장된 것)

### 2-6. 수업반(교과) 사진 ★★

⚠️ **담임과 다릅니다 — 수업반은 사진만 얹습니다. 명단이 먼저 있어야 합니다.**
수업반 학생에게는 고유번호가 없어 `학년-반-번호 + 이름`으로 맞추기 때문입니다.

1. 수업 관리 → 수업반 하나 선택 → 명렬 탭 → 명단을 먼저 넣기
2. 같은 화면의 **[사진 명렬표]** → 수업반 사진 명렬표 선택
3. **`사진 N장을 넣었어요`** 가 뜨는지

| 봐야 할 것                      | 정상                                                               |
| ------------------------------- | ------------------------------------------------------------------ |
| 명단이 비어 있을 때             | "명단을 먼저 넣어 주세요" 안내 — **조용히 아무 일도 안 나면 버그** |
| 번호는 같은데 이름이 다른 학생  | 그 학생만 못 넣었다고 알려 줌 — **엉뚱한 학생에게 붙으면 심각**    |
| 여러 반이 섞인 수업반           | 1반 3번과 2반 3번이 **서로 다른 얼굴**인지                         |
| 같은 학생이 담임 반에도 있을 때 | 한쪽 사진을 지워도 **다른 쪽은 남아 있는지**                       |

## 3. 얼굴 학습 화면

### 3-1. 진입

- 학급 운영 → 자리배치 → 툴바에 **[이름 학습]** 이 바로 보이는지 (`⋯` 안이 아님)
- 모드가 **자유 · 순서 · 맞혀보기 · 이름 쓰기** 네 개인지

### 3-2. 얼굴 카드

- 카드에 **얼굴**이 뜨는지
- **학번이 안 보이는지** ← 보이면 얼굴 안 보고 순서로 맞힐 수 있어 의미가 없음
- 정답을 확인한 뒤에야 학번 + 이름이 보이는지

### 3-3. 진행이 초기화되지 않는지 ★

1. **[이름 학습]** 을 누르자마자 **곧바로 [맞혀보기]** 선택
2. 1~2문제 풀기
3. 사진이 다 뜨는 순간 **모드가 '자유'로 돌아가거나 진행이 사라지면 버그**

> 고친 항목입니다. 사진이 많을수록 잘 드러나므로 반드시 "열자마자 바로" 조작하세요.

### 3-4. 이름 쓰기 — 한글 입력 ★★

**자동 시험으로 검증이 불가능한 항목입니다. 반드시 손으로 확인해 주세요.**

1. **[이름 쓰기]** 모드
2. 이름을 치다가 **글자가 아직 완성되지 않은 상태에서 Enter**
   (예: `홍길ㄷ` 상태에서 Enter)
3. **여기서 채점되면 버그** — 미완성 이름이 제출된 것
4. 글자를 완성한 뒤 Enter → 정상 채점되는지

키보드 종류별로 되면 더 좋습니다: Windows 한/영, 두벌식/세벌식.

### 3-5. 채점 규칙

| 입력                                       | 기대                              |
| ------------------------------------------ | --------------------------------- |
| 정확한 이름                                | 정답                              |
| 띄어쓰기만 다름 (`남궁 민수` ↔ `남궁민수`) | 정답                              |
| **한 글자 다름** (`김민수` → `김민서`)     | **오답 + 정답 공개, 재시도 없음** |
| 빈칸 Enter                                 | 오답                              |

- **[초성 보기]** → `ㄱㄴㅇ` 형태로 나오고 **정답 이름은 안 보이는지**
- **[모르겠어요]** → 오답 처리 후 정답 공개
- 한 바퀴 끝나면 **[틀린 학생만 다시]** 가 뜨는지

### 3-6. 사진이 없는 반

- **[이름 쓰기]** 버튼이 **잠겨 있고** 이유가 안내되는지

## 4. 용량과 사진 품질

1. 설정 → 백업/복원 → **학생 사진** 섹션
2. `22장 저장돼 있어요 (약 0.8MB)` 형태로 보이는지

| 항목              | 기대                                         |
| ----------------- | -------------------------------------------- |
| 22명 기준 총 용량 | **1MB 안팎** (10MB가 넘으면 축소가 안 된 것) |
| 얼굴 알아보기     | 카드에서 누구인지 구분 가능                  |
| 빠진 학생         | 없어야 함. 있으면 몇 명인지 기록             |

> ⚠️ 사진 축소는 브라우저 기능이라 자동 시험이 불가능합니다.
> **용량이 예상보다 훨씬 크면 축소가 동작하지 않는 것**이니 꼭 알려 주세요.

## 5. 삭제와 개인정보

### 5-1. 전체 삭제

1. 설정 → 백업/복원 → 학생 사진 → **[사진 모두 지우기]**
2. 확인 문구가 "되돌릴 수 없어요"를 포함하는지
3. 지운 뒤 **0장**이 되는지
4. 이름 학습을 열면 얼굴이 사라지고 예전처럼 학번 카드로 나오는지

### 5-2. 학생 한 명 삭제

1. 명렬 관리에서 학생 한 명 삭제
2. 설정에서 사진 수가 **1장 줄어드는지**

### 5-3. 인터넷이 없을 때 (선택)

1. 인터넷을 끊고 **[사진 모두 지우기]**
2. **"이 컴퓨터에서는 지웠지만 클라우드에 N장이 남아 있어요"** 취지로 안내되는지
3. ❌ 그냥 "삭제 완료"만 뜨면 버그 (사실이 아닌 안내)
