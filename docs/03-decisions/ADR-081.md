# ADR-081: 계측은 "이름만" 담고, 모바일은 롤업에서 갈라 둔다

**날짜**: 2026-09-01
**상태**: 채택

### 배경

"쌤핀 AI 를 얼마나 쓰나"에 답하려고 운영 DB 를 뒤졌더니, 답이 통계에 없었다. 서버의
남용 방지 표를 대신 세어야 했다 — 그 표는 통계용이 아니라 언제 지워도 되는 자료다.
같이 나온 것들: 위젯·아이콘 창 기록이 전부 익명, 옆핀·교무실·모바일은 기록 자체가 없음,
도구 33종 중 12종이 집계에서 빠짐, 오류의 97%가 무해한 잡음.

### 결정

1. **기기 번호는 창이 아니라 진입 파일에서 붙인다.**
   `initAnalyticsIdentity()` 를 `main.tsx`·`sidepin-main.tsx` 의 **module 최상단**에서 부른다.
   effect 안에서 부르면 늦다 — React 는 자식 effect 를 먼저 돌리므로 자식이 먼저 보낸
   기록에는 번호가 안 붙는다. 이것이 위젯·아이콘 기록이 통째로 익명이던 원인이다.

2. **계측에는 값이 아니라 이름만 담는다.**
   설정 변경은 바뀐 **항목 이름**만(`diffSettingsKeys`), 모바일 화면 이름은 주소가 아니라
   `route.kind` 에서 조립(`screenNameOf`), 동기화 실패 사유는 원문이 아니라 **분류된 이름**,
   쌤핀 AI 는 질문 내용을 담지 않는다. 값을 담기 시작하면 그 순간 통계 표가 개인정보
   저장소가 된다. 이 세 함수에는 "값이 안 새는가"를 못박는 시험을 붙였다.

3. **모바일 기록은 `mobile_` 로 시작하고, 롤업에서 뺀다.**
   이름만 나눠서는 부족하다 — 활성 사용자를 세는 롤업은 이벤트 이름을 가리지 않는다.
   `065_analytics_mobile_split.sql` 이 데스크톱 뼈대 롤업 둘에서 `mobile_%` 를 뺀다.
   그래야 지금까지 쌓은 추세선이 그대로 이어지고, "사용자가 늘었다"가 실제 성장인지
   계측 변경인지 헷갈리지 않는다. **앱보다 마이그레이션을 먼저 적용해야 한다.**

4. **잡음은 목록에 적힌 것만 거른다.**
   `isNoiseError` 는 ResizeObserver 두 줄만 안다. "오류가 많으니 대충 줄이자"로 넓히면
   진짜 결함을 조용히 숨기게 된다 — 같은 기간의 `prompt() is not supported` 168건은
   버튼이 아무 동작도 안 하던 **진짜 결함**이었고, 통계에 남아 있었기에 찾아냈다.

5. **앱 안 도구는 자기 화면에서, 바깥으로 나가는 도구는 누르는 자리에서 센다.**
   외부 도구 7종은 화면 이동이 없어 방문 기록조차 안 남는다 — `ToolsGrid` 의 클릭에서
   세지 않으면 영영 0 이다. 반대로 앱 안 도구를 거기서 또 세면 두 번 세어진다.

### 남긴 것

모바일에서 데스크톱 도구 컴포넌트를 띄울 때 나가는 `tool_use` 는 여전히 기기 번호가 없다.
번호를 붙이면 모바일 사용자가 데스크톱 도구 순위에 섞인다. 플랫폼 구분을 스키마 전체에
넣는 결정이 필요해 오너 판단으로 남긴다(`os_info` 로는 지금도 구분 가능).
