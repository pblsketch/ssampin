# ADR-082: "내 AI로 실행" — 선생님 본인 구독 CLI(Claude Code·Codex)를 쌤핀이 대신 띄운다. 구글은 약관상 뺀다

- **상태**: active(계획 단계, 착수는 S0 실측 후) · **일자**: 2026-09-04 · **계획서**: `docs/01-plan/features/assist-own-subscription-cli.plan.md`
- **발단**: 오너가 OpenMotion(openmotion.design, "Claude Code 또는 Codex 구독으로 동작, API 키 불필요") 방식을 쌤핀에 적용하자고 결정했다. 반론 3건(①구독은 BYOK 보다 부담 ②설치·로그인 장벽 ③Solar 로 충분)을 **오너가 전부 기각**했다 — "이미 구독하는 선생님이 많다 / UX 로 풀면 된다 / `solar-pro3` 품질이 부족하고 브릿지 작업을 앱 화면으로 가져와 생기부 초안까지 쓰게 하고 싶다."
- **레퍼런스 실측**: OpenMotion 1.1.0 의 `app.asar` 를 직접 읽었다. 바이너리를 동봉하지 않고 **사용자가 설치한 `claude`/`codex` 를 PATH 에서 찾아** `claude auth login`/`codex login` 을 자식 프로세스로 띄워 로그인시키고, Agent SDK(`pathToClaudeCodeExecutable`)·Codex SDK(`codexPathOverride`)로 실행한다. 자체 MCP 서버를 `mcpServers` 로 물리고 `allowedTools` 를 그것만으로 제한한다. API 키 병행 지원. 제미나이는 지원하지 않는다.

### 결정 1 — 비용 조건은 "쌤핀이 비용을 _새로_ 요구하지 않는다"로 읽는다 (feedback_no_ai_features 완화)

선생님이 **이미 가진** 구독을 **본인 PC 에서** 쓰는 것(BYOS)은 허용. BYOK(API 키 입력)는 여전히 기각 — 쌤핀 화면에 키 입력란을 만들지 않는다. 기본값은 쌤핀 AI(Solar, 무료)이고 "내 AI"는 **선택**이다.

### 결정 2 — 공급자는 Claude Code·Codex 2종. 구글은 인앱 실행에서 뺀다

2026-09-04 공식 문서 기준:

구글은 **선생님이 Antigravity IDE 를 직접 열어 쌤핀 브릿지(MCP)를 쓰는 기존 경로만** 유지한다. 재검토 조건: Google 이 제3자 임베딩을 허용하는 문서를 내거나 교육청 Workspace 에 Gemini Code Assist 가 포함될 때. **그 전에는 다시 제안하지 않는다.**

### 결정 3 — 쌤핀은 토큰을 만지지 않는다

설치는 공식 한 줄 명령(`irm https://claude.ai/install.ps1 | iex`, `winget install OpenAI.Codex` 등)을 쌤핀이 새 터미널에서 대신 실행해 주고, 로그인은 `claude auth login`/`codex login` 을 자식 프로세스로 띄워 **각 회사 브라우저 화면**에서 끝내게 한 뒤 `auth status`/`login status` 로 결과만 본다. 쌤핀 화면에 로그인 폼·키 입력란은 없다. 이것이 Anthropic 약관의 상한이고, OpenMotion 도 정확히 여기까지만 한다.

### 결정 4 — 도구는 동봉 브릿지 MCP 를 그대로 물린다. 범위는 브릿지 전체(오너 결정)

`aiBridgeCore.buildEntry()` 의 엔트리를 `claude --mcp-config` / `codex exec -c mcp_servers.ssampin.*` 로 넘긴다. PII 토큰화·동의 게이트·`SSAMPIN_BRIDGE_ALLOW_WRITE`·ADR-072 의 입력 단계 기재금지 차단은 **공급자와 무관하게** 그대로다. 쓰기는 CLI 권한 프롬프트를 쌤핀이 받아 **미리보기 → [실행]** 로 바꾼다(S3). CLI 에 학생 원문을 직접 넣는 코드 경로는 만들지 않는다(계약 테스트로 고정).

### 결정 5 — Claude 는 `--bare` 를 쓰지 않고, 깨지면 Solar 로 폴백한다

`--bare` 는 구독 로그인을 읽지 않으며 _"will become the default for `-p` in a future release"_ 다. 실행 전 버전 하한·상한을 검사하고, 인증 오류·한도 오류는 분류해 쌤핀 AI 로 폴백 + 한 줄 안내. 빈 작업 폴더 + `--strict-mcp-config` + `--disallowedTools` 로 사용자 전역 설정이 끼어드는 것을 막는다.

### 결정 6 — 학습 활용 고지는 유지한다

세 회사 소비자 플랜은 대화가 학습에 쓰일 수 있다. 처음 켤 때 쉬운 한국어로 고지하고 끄는 방법을 링크한다(ADR-061/072 와 같은 원칙).

### 남는 것

- ADR-052 의 "재판매 간주 위험"은 이 구조에 해당하지 않는다(각 교사가 자기 PC 에서 자기 구독을 쓴다).

### D6 보정 (2026-09-04 구현 중 실측·코드 대조로 확정) — 게이트 메커니즘이 바뀌었다

D6 은 "쓰기는 `--permission-prompt-tool`(Claude)·app-server 승인(Codex)을 쌤핀 게이트 MCP 로
받아 미리보기 → [실행] 카드로 잇는다"고 적었다. **결과(미리보기 → [실행])는 그대로지만
메커니즘은 성립하지 않아 바꿨다.** 코드를 읽어 확인한 것:

- 브릿지 쓰기는 파일 드롭이 아니라 **앱으로 오는 차단형 loopback HTTP** 다. 브릿지 쪽 12초
  (`postLoopback`), 앱 쪽 10초(`APPLY_TIMEOUT_MS`)가 **번들에 박힌 상수**라 120초짜리 승인을
  버틸 수 없다. 늦게 누른 [실행]은 결과가 버려져 "모델은 실패했다는데 파일은 바뀐" 분열이 된다.
- 앱 서버가 없으면(`control.json` 부재) 브릿지는 `decideWritePath()` 로 **파일을 직접 쓴다.**

→ **C3′ "제안 후 즉시 반환"**: `aiBridgeLiveSyncHost.applyWrite` 에서 도메인 403 검사 **뒤**,
렌더러 위임 **앞**에 분기를 두고, 활성 중이면 저장하지 않고 제안만 렌더러로 보낸 뒤
**즉시 409** 로 답한다. 선생님이 [실행]을 누르면 그때 기존 `applyLiveSyncWrite` 로 적용한다.

함께 확정한 것(모두 코드·실측 근거):

1. **쓰기 허용은 env 가 아니라 기존 설정 토글(capability 파일)이 정한다.** 브릿지 쓰기 도구는
   `assertWriteAllowed` 가 호출마다 capability 를 읽고, env `SSAMPIN_BRIDGE_ALLOW_WRITE` 는
   관찰 도구 2곳만 본다. 그래서 구독 실행은 **env 를 주입하지 않는다**(`buildEntry(ctx,{})`).
2. **`activeUntil` 은 대입만 한다.** `Math.max` 로 갱신하면 `max(Infinity, …)` 가 계속
   `Infinity` 라 실행이 끝나도 영원히 409 가 되어, 다른 AI 앱의 저장까지 앱 재시작 전까지 막힌다.
3. **끝난 뒤 15초는 아직 활성이다.** 브릿지는 stdin 이 닫힌 뒤 진행 중이던 요청(상한 12초)만
   끝내고 죽는다. 그 사이 늦은 쓰기도 [실행] 없이 저장되면 안 된다.
4. **패널 실행은 capability 와 무관하게 활성으로 친다.** 토글이 꺼진 채 시작한 실행 도중에
   선생님이 켜면 브릿지는 호출마다 capability 를 다시 읽어 쓰기가 열린다.
5. **서버 생존 조건에 `allowGradeWrite` 를 넣었다.** 채점 쓰기(`setRubricGrading`)는 loopback 을
   거치지 않고 `rubrics` 가 `WRITE_DOMAINS` 밖이라 호스트 409 분기에 도달하지 않는다 —
   앱이 없으면 파일에 직접 쓴다. 서버가 떠 있어야 브릿지가 거부한다.
   **행동 변경**: 앱을 켠 채 하던 외부 클라이언트의 채점 직접쓰기도 이제 거부된다(릴리즈 노트에 명기).
6. **`ensureServer()` 가 시작까지 책임진다.** 기존 `startServer` 는 `starting` 플래그로 조기
   반환해, 부팅 자동 시작과 겹친 호출이 "안 떴다"고 오판했다. 또 부팅 때 listen 이 실패하면
   토글을 껐다 켜기 전에는 영영 안 떴다. `control.json` 은 판정에 쓰지 않는다 — 크래시 잔존
   파일에 속는다.
7. **종료는 동기 kill 이다.** `before-quit` 는 await 를 기다리지 않는데 `liveSyncHost.stop()`
   (control.json 삭제)은 `will-quit` 에 있다. 비동기로 죽이면 남은 브릿지가 "앱이 없다"고 보고
   파일을 직접 쓴다. `storageLocation` 의 `app.exit(0)` 은 quit 이벤트를 아예 건너뛰므로 거기서도 부른다.
8. **argv 도 실측으로 바뀌었다**(claude 2.1.258 / codex 0.144.4):
   `--disallowedTools` 는 블랙리스트라 내장 도구 12개 이상이 샜다 → **`--tools ''` + `--restricted`**.
   A/B: 34.3초·3턴·훅 7건·도구 72개 → **15.6초·2턴·훅 0건·도구 54개**.
   **stdin 을 닫지 않으면** claude 는 3초를 버리고 **codex 는 무한 대기**한다(184초 타임아웃 실측).
   `--bare` 금지 근거는 CLI `--help` 원문에 있다 — "OAuth and keychain are never read".
   `--permission-prompts` 는 2.1.259+, `--append-system-prompt-file`·`--max-turns` 는 없다.
9. **별칭 문제의 전제가 틀렸다.** 브릿지는 번호 별칭이 아니라 불투명 토큰(`stu_…`)을 쓰므로
   "남의 실명 복원"은 구조적으로 없다. 진짜 문제는 `rosterFrom` 이 **이름과 학번을 둘 다** 가려
   모델이 별칭을 브릿지의 학번과 이어 붙일 수 없다는 것 → "별칭 = 소속 번호" 힌트 줄을 붙인다.
   번호는 `list_students` 가 이미 내보내는 정보라 새로 새는 게 없고 실명은 안 나간다.

**남는 잔여 위험**(릴리즈 노트에 적는다): 앱 **하드크래시** 고아가 direct create 를 쓸 수 있다
(update/delete 는 브릿지가 거부). 토글을 켠 직후 첫 `beat()` 까지의 ms 창도 같다.
둘 다 브릿지 커밋 `SSAMPIN_BRIDGE_NO_DIRECT=1` 로 봉쇄 예정.
