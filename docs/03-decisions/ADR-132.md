# ADR-132 — 학생 입장은 인터넷 주소를 정식 경로로 하고, 같은 Wi-Fi 주소는 경고와 함께 보조로만 쓴다

- 날짜: 2026-09-22
- 상태: 채택, 로컬 구현 · 미배포 · 오너 실기기 확인 대기
- 대상: 쌤도구 **퀴즈·설문·토론**([ADR-128](ADR-128.md))의 라이브 콘솔(`LiveConsoleContainer`)
- 관계: [ADR-124](ADR-124.md) 4절(짧은 코드 되살림)을 **바꾸지 않고 순서만 뒤집는다**
- 설계: [participation-classroom-ux.design.md](../02-design/features/participation-classroom-ux.design.md)
- 검증: [participation-classroom-ux.md](../04-report/features/participation-classroom-ux.md)

## 발단

오너가 교실 화면 캡처를 보고 물었다 — "참여 주소가 URL이 아니고 숫자(`http://125.177.195.51:63108`)로 되어 있다."

코드를 따라가 보니 그림이 이랬다.

1. 학생 서버가 뜨면 **같은 Wi-Fi 주소를 곧바로** 화면에 띄운다.
2. 그 뒤 터널(인터넷 참여 주소)을 켠다. 붙는 데 최대 30초, 첫 사용이면 `cloudflared`
   내려받기(62.8MB)까지 걸린다.
3. 터널이 붙으면 주소를 **조용히 갈아치운다.**

그 사이 선생님이 화면에 뜬 숫자 주소를 불러 줄 수 있다. 그런데 그 주소는 **교사 컴퓨터와 같은
Wi-Fi에 붙은 기기에서만** 열린다. 휴대전화 데이터를 쓰는 학생은 못 들어온다.
오너의 판단은 "한 반 30명이 모두 학교 Wi-Fi에 붙어 있는 일은 실제 수업에서 거의 없다"였다.

## 조사

같은 Wi-Fi 경로를 없애자는 안(B)도 검토했고, 저장소에 남은 기록을 먼저 확인했다.

- `liveAccessUrl.ts` 는 2026-08-27 커밋 `9d6e9d75` 에서 **실제 신고를 받아** 만들어졌다 —
  "학교망이 터널을 막아 초대 단추가 통째로 사라진다."
- `docs/user-guide.md` 와 랜딩 `/docs` 는 이미 "터널이 실패하면 같은 Wi-Fi 주소가 뜬다"고 안내한다.
- 터널 성공·실패를 남기는 **계측이 없다.** "실패는 드물다"도 "자주 실패한다"도 근거가 없다.

없애 버리면 학교망이 막힌 교실에서 수업이 통째로 안 열린다. 근거 없이 그 길을 지울 수는 없다.

## 결정

### 1. 순서를 뒤집는다

| 단계        | 화면                                          | 학생 안내   |
| ----------- | --------------------------------------------- | ----------- |
| `preparing` | "인터넷 참여 주소를 준비하고 있어요" + 기다림 | **못 한다** |
| `internet`  | 짧은 주소 + 코드 (또는 터널 주소)             | 한다        |
| `local`     | 같은 Wi-Fi 주소 + **경고**                    | 한다        |

- 준비 중에는 **주소 칸도 QR도 그리지 않는다.** 빈 칸이 뜨면 그걸 불러 주거나 찍는다.
- 준비 중에는 `활동 시작` 을 막는다. 아무도 못 들어온 채 첫 문항이 나가는 일을 없앤다.
- 기다리기 싫은 선생님을 위해 **[기다리지 않고 같은 Wi-Fi 주소로 시작하기]** 를 둔다.
- 한 번 같은 Wi-Fi 로 내려가면 **뒤늦게 터널이 붙어도 주소를 바꾸지 않는다.**
  이미 불러 준 주소가 화면에서 갈아치워지면 학생이 헷갈린다.

### 2. 짧은 주소 발급 실패로 같은 Wi-Fi 주소까지 내려가지 않는다

터널은 붙었는데 짧은 주소·코드 발급만 실패하면, **터널 주소를 그대로 안내한다.**
ADR-124 4절이 폴백 조건을 "터널·숏코드가 **모두** 실패할 때"로 못박은 것과 같다.
(옛 코드는 둘을 한 `try` 에 묶어 두어, 순서를 뒤집을 때 같은 Wi-Fi 로 내려갈 뻔했다.)

### 3. 주소의 종류를 교실 화면에도 보낸다

`ShareSnapshot.entryKind` 를 더한다. 교실 화면(별도 창)은 스냅샷만 받으므로,
이 값이 없으면 준비 중에 빈 주소 칸을 띄우거나 같은 Wi-Fi 주소를 인터넷 주소인 양 보여 준다.
교실 화면에는 뒷자리에서 읽히는 **짧은 한 줄**을 쓴다("선생님과 같은 Wi-Fi에 연결해야 들어올 수 있어요").

### 4. 같은 Wi-Fi 경로는 지우지 않는다

ADR-124 4절의 폴백은 유지한다. 지우는 결정은 **계측을 붙여 실패율을 본 뒤**에 한다.

## 버린 안

- **B. 같은 Wi-Fi 경로 삭제** — 학교망이 막힌 교실에서 수업이 안 열린다. 근거(계측)가 없다.
- **C. 두 주소를 나란히** — 선생님이 둘 중 무엇을 불러야 하는지 모른다. 지금 화면이 그랬다.

## 남는 것

- 터널 성공·실패와 실패 단계를 남기는 **계측**(오너 판단 대기). B안을 다시 보려면 이것이 먼저다.
- (2026-09-22 정정) 나머지 실시간 쌤도구는 **이미 인터넷 주소 우선**이었다 —
  `tunnelLoading` 이면 "인터넷 연결 준비 중…"을 보여 주고, **`tunnelError` 일 때만** 같은 Wi-Fi
  주소를 적는다(`ToolPoll`·`ToolSurvey`·`ToolWordCloud`·`DiscussionLive`·`ToolRealtimeWall`·
  `ToolClassroomAgreement`·옛 `ToolMultiSurvey` 확인). 같은 Wi-Fi 주소를 먼저 띄우는 순서는
  **이 참여 콘솔(`LiveConsoleContainer`)에만** 있던 것이다. 처음 이 문서에 "나머지 7종도 옛
  순서"라고 적은 것은 **코드를 보지 않고 쓴 잘못이다.**
- 다만 **한 군데가 남았다** — `TeacherControlPanel` 의 초대 모달은 `qrUrl = displayUrl || localUrl`
  이라, 터널을 기다리는 동안 **같은 Wi-Fi 주소와 그 QR을 먼저** 보여 준다(`{!displayUrl && localUrl}`).
  객관식 설문·주관식 설문·옛 멀티설문의 **교사 주도 다문항 모드**가 이 모달을 쓴다.
  고칠지는 오너 결정 사항이다.

## 후속 (2026-09-22) — 초대 모달에도 같은 규칙을 적용했다

`TeacherControlPanel` 의 [학생 참여 링크] 모달(객관식 설문·주관식 설문·옛 멀티설문의
**교사 주도 다문항 모드**)이 `qrUrl = displayUrl || localUrl` 이라, **터널을 기다리는 동안
같은 Wi-Fi 주소와 그 QR을 먼저** 보여 주고 있었다. 이 결정의 마지막 남은 자리였다.

- 준비 중에는 주소도 QR도 내놓지 않는다. [기다리지 않고 같은 Wi-Fi 주소로 시작하기]를 둔다.
- 같은 Wi-Fi 주소에는 경고를 붙인다. 짧은 주소·전체 주소 칸은 인터넷 주소일 때만 그린다.
- 경고의 첫 문장을 **까닭에 따라 나눴다**(`entryAccessWarning(kind, reason)`).
  기다리지 않기로 한 선생님에게 "인터넷 참여 주소를 만들지 못했어요"라고 하면
  **되지도 않을 일을 포기한 것처럼** 들린다 — 사실 그때는 아직 만드는 중이다.
  이 갈래는 참여 콘솔(`ParticipationConsole`)에도 함께 적용했다.

## 근거

브라우저 확인(실제 크롬 + CDP, `output/participation-ux/entry.mjs`):

- 준비 중 — 주소 칸 없음, `활동 시작` 막힘, 교실 화면도 "준비 중".
- 터널 연결 — 주소가 나오고 QR을 **다시 읽어** 같은 주소가 나왔다. 학생 창이 그 주소로 실제 입장.
- 터널 실패 — 같은 Wi-Fi 주소 + 경고가 교사·교실 양쪽에 떴다.
- 기다리지 않고 내려간 뒤 — 6초 뒤 터널이 붙어도 주소가 **그대로**였다.
