# ADR-122: 오늘 기록 위젯을 담임+수업반 학생 기록 허브로 넓히고, 저장 위치는 항상 선생님이 고른다

- 결정일: 2026-09-15
- 범위: 대시보드 `student-records` 위젯, 빠른 학생 기록 모달, 전역 단축키·명령 팔레트, 담임·수업 출결 진입
- 상태: **v2.5.3 출시(2026-09-18)**. 오너 승인 2026-09-18 KST.

## 배경

선생님이 수업 중이나 학급 생활 중에 학생의 모습을 남기려면 담임 업무 또는 수업 관리의 깊은 화면까지 들어가야 했다. 기존 `student-records` 위젯은 담임 전용 조회 카드여서 교과 선생님에게는 아예 제공되지 않았다.

## 결정

1. **위젯을 하나로 유지하고 역할만 넓힌다.** 새 위젯 id 를 만들지 않는다. 카드 두 개가 같은 일을 하면 어느 쪽을 봐야 하는지 알 수 없다. 제공 대상은 담임뿐 아니라 교과·부장으로 넓히고, 담임 명렬이 없으면 담임 전용 줄(담임 출결 진입·출결/상담/생활 요약·미완료 후속조치)만 빠진다.

2. **저장 위치는 절대 추측하지 않는다.** 학생을 먼저 찾되, 그 기록이 담임 누가기록으로 갈지 어느 수업반의 관찰기록으로 갈지는 화면에서 직접 고른 뒤에만 저장된다. 현재 수업이나 진입 화면을 근거로 기본값을 정하지 않는다.
   - 담임 맥락 → 기존 `useStudentRecordsStore.addRecordWithTags`
   - 교과 맥락 → 기존 `useObservationStore.addRecord`
   - 새 저장소·제3의 기록 모델을 만들지 않는다.

3. **학생 동일성은 `반 별칭 + 번호 + 이름`이 모두 같을 때만 합친다**(`domain/rules/quickStudentRecord.ts`). 담임 명렬과 수업반 명단은 서로 다른 식별자를 쓰기 때문에(`Student.id` 대 `studentKey`) 이름만 견주면 동명이인이 한 사람으로 합쳐지고, 그러면 **남의 기록칸에 저장**된다. 반을 알 수 없는 수업반(예: 이름이 "공국2")은 담임 명렬과 합치지 않고 두 줄로 남긴다. 줄이 둘인 것은 불편할 뿐이지만 잘못 합친 것은 사고다.

4. **학생 칩에는 오늘 기록의 종류만 표시한다.** 출결(`✔`)과 누가기록/특기사항(`●`)을 구별하되 건수·누적량·미기록 경고·순위는 넣지 않는다. 기록량으로 학생을 줄 세우지 않기로 한 기존 결정을 그대로 따른다.

5. **출결은 이 카드가 저장하지 않는다.** 담임 출결은 담임 업무 기록 탭의 출결 화면, 수업 출결은 해당 수업반의 수업 기록 입력 화면으로 데려다 놓기만 한다. 수업반 출결을 담임 기록 사본으로 추정하지 않는다.

6. **여러 명 기록은 명시적 모드다.** 고른 학생 전원에게 공통으로 있는 맥락만 고를 수 있고, 공통 맥락이 없으면 이유를 말하고 저장 화면으로 넘어가지 않는다. 저장 직전에 "어느 맥락의 몇 명"인지 보여준다. 일부만 실패하면 성공으로 덮지 않고 실패한 학생만 남겨 바로 다시 저장하게 한다.

7. **저장에 실패하면 화면을 비우지 않는다.** 성공했을 때만 시작한 학생 목록으로 돌아가고, `저장하고 닫기`는 한 명만 기록하려는 경우의 별도 종료 경로다.

8. **전역 단축키 기본값은 `Ctrl/Cmd+Alt+R`**이다. 기존 명령과 겹치지 않으며 설정에서 바꾸거나 끌 수 있다. 명령 팔레트(`Ctrl/Cmd+K`)에도 같은 모달을 노출한다. 단축키로 열면 검색창에 바로 커서가 간다.

9. **창을 건너가는 진입은 이동 문자열 하나에 의도까지 싣는다.** 같은 카드가 메인 창과 바탕화면 위젯 창 양쪽에 놓이는데, 위젯 창에는 페이지 전환도 빠른 추가 모달도 없다. 그래서 위젯 창에서는 `navigateToPage` IPC 로 메인 창을 띄우고, 하위 탭 요청(`requestHomeroomTab`·`selectClass`)은 창을 못 건너오므로 `homeroom#attendance`·`class-management#attendance:<반 id>`·`dashboard#quick-student-record[:<반 id>]` 처럼 fragment 에 담아 보낸다. 해석 규칙은 기존 `parseNavigationTarget` 한 곳에만 둔다.
   - 옆핀에는 이 카드가 올라가지 않는다(`sidePin.eligible: false`). 옆핀에서는 전역 단축키만 쓴다.

## 대안과 영향

- **새 위젯을 하나 더 추가**: 담임 카드와 새 카드가 같은 정보를 두 곳에 나눠 갖게 되고, 옆핀 제외 정책도 두 번 관리해야 한다. 적용하지 않는다.
- **현재 수업을 저장 위치로 자동 확정**: 교시가 밀리거나 보강일 때 다른 반에 저장된다. 적용하지 않는다.
- **담임·교과 기록을 한 모델로 통합**: 두 기록은 생기부에서 쓰이는 자리와 뜻이 다르다. 기존 저장 경계를 유지한다.
- **이름+번호만으로 학생 합치기**: 짧은 코드로 화면은 깔끔해지지만 오합침의 대가가 개인정보 사고다. 적용하지 않는다.

모바일 기록 UX 는 이번 범위가 아니다. 모바일 전역 FAB 에 학생 기록을 붙이는 것은 후속 후보로 남긴다.
