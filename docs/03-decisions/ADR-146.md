# ADR-146 — 자료 파일 저장 안전장치와 손상 파일 격리: 디스크에 내려쓴 뒤 교체하고, 다시 만들 수 있는 상태 파일 2종만 격리 후 초기화한다

- 날짜: 2026-11-11
- 상태: 채택 · 구현 완료(미커밋) · v2.5.10 출시 예정
- 요구사항 정본: `.dryforge/007/spec.md` WP1(개발 도구 폴더 — 저장소에는 올라가지 않는다. 이 ADR이 결정을 옮겨 적었다)
- 결정자: 오너 (2026-11-10 대화 — "나머지도 해결해보자"), 2026-11-11 출시 승인
- 관련: `electron/dataFileWrite.ts` · `electron/dataFileRead.ts`(새 파일) · `electron/dataFileRules.ts` ·
  `src/adapters/stores/useTasksSyncStore.ts` · `docs/google-tasks-sync.md` · ADR-144(드라이브 동기화 교착)

## 발단

오너 PC 에서 `tasks-sync-state.json` 과 `tasks-sync-state.backup.json` 이 **둘 다** 0x00 으로 채워진 210바이트였다
(2026-11-06 13:37:48). 그날 PC 가 비정상 종료됐다(Kernel-Power 41). 깨진 파일은 이 둘뿐이었다.

코드에서 확인한 것:

- 저장이 임시 파일에 쓰고 **fsync 없이** 이름을 바꿨다. 이름만 바뀌고 내용은 디스크에 없는 채로 전원이 끊기면
  길이만 맞는 빈 파일이 남는다.
- 저장할 때마다 백업을 **제자리에 덮어썼고**, 기존 원본이 길이 10 초과이기만 하면 JSON 검사 없이 백업으로 복사했다.
  깨진 원본이 마지막 정상 백업을 덮는다.
- 이름 바꾸기가 EPERM/EBUSY/EACCES(백신·색인이 파일을 잠깐 잡은 경우)로 실패해도 다시 시도하지 않았다.
- `data:read` 는 원본·백업이 모두 깨지면 예외를 던진다. **null 로 위장하지 않는 것은 의도된 설계**다(빈 파일로 오인해
  기존 자료를 덮어쓰는 사고 방지). 그런데 구글 할 일 연동은 이 예외를 콘솔에만 남겨, 연동이 **알림 없이 꺼진 채** 굳었다.
- 구글 할 일 동기화는 "구글 목록 응답에 없음 = 쌤핀에서 삭제"를 **목록 ID 를 보지 않고** 적용했다. 상태가 초기화된 뒤
  선생님이 다른 목록을 고르면(또는 평소에 목록을 바꾸면) 옛 목록에 연결된 쌤핀 할 일이 통째로 지워진다.

## 결정

### 1. 쓰기 — 디스크에 내려쓴 뒤 교체한다

1. 임시 파일에 쓰고 **fsync 한 뒤**, 다시 읽어 **내용 전체**가 같은지 확인하고 이름을 바꾼다.
   `data:write` · `data:writeIfUnchanged` · `data:read` 의 백업 복구 쓰기 · 백업 만들기 · 시작 시 백업이 모두 이 한 길을 쓴다.
2. 백업은 **기존 원본이 JSON 으로 읽힐 때만** 만들고, 백업도 임시 파일을 거쳐 교체한다.
   깨진 원본이 백업을 덮지 않고, 백업 쓰기가 실패해도 기존 백업은 그대로다.
3. 이름 바꾸기가 EPERM/EBUSY/EACCES 면 짧게(20·40·80ms) **최대 3회** 다시 시도한다. 끝까지 실패하면 원본은 그대로이고
   임시 파일은 남기지 않는다. 로그에는 오류 코드만 남긴다(파일 내용·학생 정보 금지).
4. **fsync 실패를 삼키는 것은 "이 저장소는 fsync 를 지원하지 않는다"는 코드뿐이다**
   (EINVAL·ENOTSUP·EOPNOTSUPP·ENOSYS·EISDIR). 그런 저장소(일부 네트워크 폴더 등)에서 실패로 돌리면 그 PC 는
   아무것도 저장하지 못한다. 그 밖의 코드(EIO·ENOSPC 등)는 내용이 디스크에 내려가지 못했다는 뜻이므로 저장 실패로 돌린다.

### 2. 읽기 — 격리는 허용 목록 2종만

1. 원본·백업이 모두 깨졌을 때 **허용 목록의 "다시 만들 수 있는 상태 파일"만** 깨진 파일을 지우지 않고
   `<파일 이름>.corrupt-<시각>` 으로 옮긴 뒤 "없음"을 돌려준다.
   허용 목록: `tasks-sync-state`, `drive-sync-device-state`. 판정 함수는 `electron/dataFileRules.ts` 한 곳에 둔다.
2. **사용자 자료 파일은 예외를 그대로 던진다.** 절대 조용히 비우지 않는다. 잃으면 판정이 달라지는 동기화 장부
   (`calendar-sync` · `calendar-sync-queue` · `drive-sync-manifest`)도 허용 목록에 넣지 않는다.
   목록에 더하려면 "이 파일이 없어져도 다시 만들 수 있는가"를 먼저 확인한다.
3. **읽기 자체가 막힌 원본은 백업으로 대체하지 않는다.** 잠금·권한(EBUSY·EPERM 등)으로 못 읽은 것은 깨졌는지 알 수 없다.
   짧게 다시 읽어 보고 끝까지 안 되면 오류를 던진다 — 백업을 읽지도, 원본을 덮지도, 격리하지도 않는다.
   한 세대 옛 백업이 지금 내용인 것처럼 돌아가거나 온전한 원본을 덮는 일을 막는다.
4. 깨진 원본을 옮기지 못했으면 "없음"으로 넘기지 않고 예전처럼 오류를 던진다.
5. 격리 파일 이름은 `.json` 으로 끝나지 않게 한다(백업·동기화가 깨진 파일을 자료로 주워 가지 않도록).

### 3. 알림 — 격리됐다는 사실을 화면이 안다

메인 프로세스가 이번 실행에서 격리한 파일 이름을 기억하고 화면이 물어볼 수 있게 한다.
구글 할 일 연동은 상태 파일이 격리·초기화됐으면 **꺼진 상태로 시작하고 한 번** 알린다:
「구글 할 일 연동 설정을 읽지 못해 연동이 꺼졌어요. 할 일은 그대로예요. 설정에서 다시 켜 주세요.」
처음 쓰는 PC(파일이 원래 없음)와 다른 파일이 격리된 경우에는 알리지 않는다.

### 4. 구글 할 일 — "구글에 없음 = 삭제"는 같은 목록일 때만

구글 목록 응답에 아예 없는 할 일을 삭제로 보는 것은 **그 할 일의 `googleTaskListId` 가 지금 동기화하는 목록과 같을 때만**이다.
다른 목록에 묶였거나 목록 ID 가 없는 할 일은 지우지 않는다. 상태가 초기화된 뒤 다른 목록을 고르는 경우와,
평소에 목록을 바꾸는 경우를 함께 막는다. 옛 목록의 할 일을 쌤핀에서 고치면 수정 올리기의 404 → 새 생성으로
지금 목록에 옮겨지는 기존 정책(`docs/google-tasks-sync.md`)은 그대로다.

## 버린 안

- **모든 파일을 깨지면 격리하고 비우기.** 사용자 자료를 "없음"으로 돌려주면 저장 경로가 빈 파일로 오인해 편집분만으로
  덮어쓴다. 예외를 던져 기능이 멈추는 쪽이 자료를 잃는 것보다 낫다.
- **시작 스냅샷(`backups/startup/`)으로 사용자 자료를 자동 복원하기.** 이번 범위가 아니다. 어느 시점의 자료로 되돌릴지는
  제품 판단이라 **오너 판단을 기다린다.**
- **fsync 오류를 전부 무시하기.** 디스크 가득·입출력 오류까지 삼키면 길이만 맞는 빈 파일로 원본을 덮을 수 있다.

## 한계

- fsync 는 파일 핸들에만 건다(Windows 는 폴더 핸들에 걸 수 없다). 이름 바꾸기 자체가 디스크에 내려가기 전에 전원이
  끊기는 경우까지 막지는 못한다. "깨질 가능성을 줄였다"이지 "깨지지 않는다"가 아니다.
- 옛 목록에 묶인 할 일은 쌤핀에 남지만 새 목록으로 **자동으로 옮겨 올라가지는 않는다.**
- 이미 지워진 할 일(이전 버전에서 목록을 바꿔 지워진 것)은 되돌리지 않는다.
- macOS 실기기는 확인하지 못했다.
