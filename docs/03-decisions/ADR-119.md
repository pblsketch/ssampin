# ADR-119: 여러 학생의 근거 지도 제안은 대상·확인 간격·뼈대를 나누고 검토 후 적용한다

- 날짜: 2026-09-13
- 상태: 로컬 구현, 미배포

## 결정

여러 학생의 근거 지도 제안은 하나의 실행 방식으로 고정하지 않고 세 설정을 독립적으로 둔다.

- 대상 학생: 현재 학생, 직접 선택, 반 전체
- 확인 간격: 1명씩, N명씩, 전체 계속 만들기
- 뼈대: 기존 구성 유지, 직접 선택, AI에게 주제별로 맡기기

따라서 특정 학생을 골라 N명씩 확인하거나 반 전체의 제안을 계속 만드는 조합이 가능하다. N명씩은 동시에 N명을 호출한다는 뜻이 아니라 N명의 제안을 만든 뒤 다음 생성 전에 멈추는 검토 간격이다. 반 전체 화면은 전체 선택 수, 제안 가능한 학생 수, 근거가 없어 건너뛸 학생 수를 따로 보여 준다.

AI 요청과 결과는 학생별로 나눈다. 전체 계속 만들기도 학생별 제안을 차례대로 만들며, 제안 생성만으로 실제 근거·주제·장면을 바꾸지 않는다. 교사가 학생별 결과를 확인하고 `검토 완료`로 표시해야 적용할 수 있다. 여러 명 적용은 검토를 마친 학생만 대상으로 한다. 보류, 미완성, 원본 변경 학생은 일괄 적용에서 제외한다.

뼈대 정책은 작업 시작 시 복사본으로 고정한다. 기존 구성 유지는 현재 장면과 교사 메모를 기준으로 삼고, 직접 선택은 고른 뼈대의 역할·이름·차례를 강제한다. AI 선택은 허용된 뼈대 후보 안에서 학생의 주제별로 고르게 하며 후보 밖의 값은 거부한다. 적합한 후보가 없으면 교사의 직접 선택이 필요한 상태로 남긴다.

## 저장과 복구

제안에는 생성 당시 원본을 판별할 값을 저장한다. 적용 직전에 현재 근거·주제·장면과 다시 비교하는 compare-and-set 방식으로 원본 변경을 감지하며, 달라진 학생은 적용하지 않고 다른 학생의 결과는 유지한다.

지도 적용은 근거 파일과 주제 파일을 함께 바꾸므로 적용 기록을 먼저 남기고 단계별 저장 상태를 기록한다. 중간 저장이 실패하면 이미 쓴 파일을 이전 값으로 되돌리고, 그 복구도 끝나지 않으면 `recovery-required`로 남겨 다음 시작 때 복구한다. 성공한 적용은 `committed`로, 되돌린 적용은 `rolled-back`으로 기록한다.

되돌리기는 학생 단위로 수행한다. 해당 적용 뒤에 교사가 다시 고친 내용이 있으면 옛 전체 자료로 덮지 않고 충돌로 막는다. 되돌린 제안의 검토 상태는 미검토로 바꾸므로 다시 적용하려면 다시 확인해야 한다.

## 실행 중단과 재진입

중단은 실행 중인 학생의 AI 요청과 아직 시작하지 않은 요청을 함께 취소한다. 늦게 도착한 응답은 실행·시도 식별자로 거부한다. 완성된 학생 결과는 보존한다.

패널을 닫거나 앱을 재시작해도 같은 반·영역의 최신 작업을 불러온다. 재시작 뒤 AI를 자동 호출하지 않고 사용자가 `이어 하기`를 눌렀을 때만 남은 학생을 다시 시작한다.

## 결과

교사는 제안을 몇 명씩 확인할지와 누구에게 적용할지를 따로 통제한다. 긴 반 전체 작업을 중단하고 이어 갈 수 있으며, 제안 생성·검토·적용·되돌리기의 경계가 저장 기록으로 남는다.

학생별 요청이 늘어 전체 처리 시간이 길어질 수 있다. 실제 제공자의 속도와 사용량 제한은 학생별 실패·중단 상태로 드러내며 자동 무한 재시도하지 않는다.
