# ADR-088: 생기부 초안 분량 조절 — 앱이 세고, 한 번만 되묻고, 못 맞추면 그렇게 말한다

- 일자: 2026-09-07
- 상태: 채택 (오너 승인 2026-09-07 → 계획서 `docs/01-plan/features/record-draft-length-adjustment.plan.md`)
- 관련: ADR-072(생기부 초안) · ADR-085(판 보존·형광펜) · ADR-084(공급자 고르기)
- 근거 분석: `docs/03-analysis/record-draft-length-adjustment.analysis.md` · 리뷰 이력 `docs/03-analysis/record-draft-length-adjustment.review-log.md`

### 발단 — 분량이 안 맞으면 지금은 손으로 고치는 수밖에 없다

생기부 영역에는 바이트 한도가 있다(중·고 진로 2,100B, 나머지 지원 영역 1,500B). AI가 쓴 초안은
자주 이 한도를 넘거나 반대로 너무 짧게 나온다. 지금 화면은:

- 편집 칸에는 바이트 표시가 있지만 **AI 결과 미리보기에는 없다.** 넘긴 줄 모르고 [반영]을 누른다.
- 한도를 넘긴 글은 저장이 거부된다. 그런데 **거부되면 아무 일도 안 일어나고 아무 안내도 없었다**
  (아래 "함께 고친 기존 결함" 1번).
- 결국 선생님이 눈으로 세어 가며 손으로 줄인다.

### 왜 그렇게 정했나

**3번(앱이 센다)** — 이 저장소에는 "프롬프트로는 규정을 못 막는다"는 실측이 있다. 금지 항목을
전부 열거하고 재강조해도 모델이 그대로 옮겨 적었다(2/2 실패). 바이트도 같다. 모델에게 세라고
시키면 틀린 숫자를 근거로 [반영]이 켜지고, 저장은 거부된다.

**6번(1회만)** — 왕복 한 번이 1~2분이다. 맞을 때까지 돌면 선생님은 몇 분을 기다리다 결국 손으로
고친다. 정직하게 "여기까지가 최선입니다"라고 말하고 실제 숫자를 보여 주는 편이 낫다.

**7번(중간 결과를 디스크에 안 남김)** — ADR-085는 "AI가 만든 것마다 전부 남긴다"이지만, 재조정
중간 결과까지 판으로 남기면 학생·영역당 상한 20개를 **두 배로 갉아먹는다.** 대신 두 결과를
화면에 나란히 놓아 "만든 것을 보여 준다"는 취지는 지킨다. 고른 하나만 디스크로 간다.
★후보를 **패널이 아니라 부모 화면**에 둔다. 패널은 학생을 바꾸면 통째로 새로 만들어져서, 패널에
두면 고르기 전에 다른 학생을 한 번 눌렀다 돌아오는 것만으로 왕복 2회 결과가 사라진다.

**8번(안 지운다)** — 자동으로 지우면 §"조용한 삭제" 사고를 재현한다. 이 저장소에서 끌 수 없는
필터가 근거 8건을 없앤 적이 있고, 게이트 4종은 전부 초록이었다. 반대로 그냥 보내면 근거였다면
절대 안 나갔을 학교폭력 조치사항·질병명·부모 직업이 외부 CLI로 나간다. 확인 한 번이 두 나쁜
선택을 피하는 유일한 길이다.

**11번(잠금을 부모로)** — 잠금을 패널에 두면 학생을 바꿨을 때 새 인스턴스의 잠금은 초기값이라
CLI 왕복 2건이 동시에 돌고, 옛 인스턴스의 실행 번호는 옛 클로저에 살아 있어 "늦게 온 결과 버리기"
비교가 언제나 통과한다. 부모는 다시 만들어지지 않는다. 대신 **반드시 풀리게** 해야 한다 — 이
저장소에는 stdin 을 안 닫아 codex 가 무한 대기한 전례가 있고, 부모 잠금이 안 풀리면 그 화면의
AI 가 통째로 잠긴다.

**12번(회수 가능하게)** — 한도를 넘긴 결과를 손댈 수 없게 두면, 모델의 명중률이 곧 기능의
성공률이 된다. 왕복 1~2분이 그대로 버려진다. 편집 칸은 **이미 한도를 넘긴 글자를 담을 수 있다**
(거부하는 것은 저장이지 입력이 아니다). 그래서 이 버튼이 성립한다.

### 함께 고친 기존 결함 3건 (C0)

새 기능을 그 위에 얹을 수 없어 **먼저** 고쳤다. 셋 다 검증 게이트 4종이 전부 초록인 채 있었다.

1. **반영 실패가 조용히 삼켜졌다.** `applyVersion` 에 `try/catch` 가 없어 한도 초과로 던지면
   `markApplied` 도 큐 진행도 실행되지 않았다. 눌렀는데 아무 반응이 없다.
2. **초점을 잃으면 저장이 거부된 글이 화면에서 되돌아갔다.** 되돌리기 효과가 `focused` 를 의존
   목록에 두고 있어 초점이 빠지는 것만으로 다시 돈다. 저장이 거부되면 `draft.content` 는 옛 글이라
   방금 쓴 글이 사라지고 붉은 오류만 남는다. **이 기능의 전제("조절할 글은 화면에 있다")를
   무너뜨리는 결함이었다.**
3. **[다시 표시]의 중복 실행 잠금이 `useState` 라 뚫렸다.** 상태 갱신이 비동기라 두 호출이 같은
   옛 값을 본다.

### 결과 (Consequences)

- **좋아지는 것**: 분량 때문에 손으로 세며 고치던 일이 줄어든다. 한도 초과 결과도 버려지지 않는다.
  기존 결함 3건이 함께 해소된다.
- **★한도 강제의 우회가 생긴다**: 한도를 넘어 `record-drafts.json` 에는 저장이 거부된 본문이
  조절안 판의 원문 스냅숏(`adjust.sourceText`)으로 `record-ai-drafts.json` 에는 남고 동기화된다.
  의도된 절충이다 — 그래야 원문 판이 상한에 밀려 지워져도 [원문과 비교]가 산다. 개인정보 수위는
  `RecordDraft` 와 같다(같은 폴더·백업·보관함·동기화, ADR-085).
- **저장 용량**: 1,500B 본문 x 2벌 x 20판 ≈ 칸당 약 60KB. 넘치면 판 상한을 20 → 12로 낮춘다.
- **새로 나가는 것**: 지금까지 외부 CLI 로 나간 것은 근거뿐이었다. 이제 **초안 본문 자체**가
  나간다. 그래서 마스킹을 조립 함수 안에 두고, 이음매 게이트(`ownAiEgress.test.ts`)가 1차와
  재조정 2차 **양쪽** 명령줄에 실명 0건을 확인한다.
- **품질은 자동 판정하지 않는다.** "사실이 보존됐다"는 표시를 만들지 않는다. 모든 초안은 여전히
  교사 최종 검토 대상이다.

### 후속 (Follow-ups)

1. 학기 간 잔여 바이트 자동 계산(2026학년도 고교 공통과목 1·2학기 합산 제한). 과목 매핑이 선행돼야 한다.
2. [뒤에 붙이기]의 앞글 기준을 "화면의 현재 입력"으로 통일. 지금은 저장된 글이라 어긋난다 —
   이번에는 미저장 입력이 있으면 **막고 이유를 표시**하는 것으로 대신했다.
3. 학급 전체 일괄 분량 조절. 실패 처리·중단·되돌리기가 통째로 다른 문제다.
4. `neisByteLength` 계산식이 실제 나이스 입력창과 일치하는지 확인. 브릿지 core 와 같은 계약이라
   양쪽을 함께 봐야 한다. **이번 변경은 계산식을 건드리지 않았다.**
5. [편집칸에 넣기] 와 화면 이동 가드의 충돌 — 한도 초과 글을 편집 칸에 두면 `flushAllDrafts()` 가
   실패해 왕복 이동이 막히고, 안내는 원인을 말해 주지 않는다. 실기기에서 재현해 보고 정한다.
