# ADR-145 — 컴시간 2차 대응: 겹친 난독화를 끝까지 풀고, 세션 쿠키는 통신 계층(메인)이 메모리에만 들고 요청 토큰과 함께 싣는다

- 날짜: 2026-11-10
- 상태: 채택 · 구현 완료(미커밋) · 미출시
- 결정자: 오너 (2026-11-10 대화 — "사용자들이 보고한 버그가 더 없는지 확인하고 있으면 고쳐서 릴리즈하자")
- 관련: v2.5.8 컴시간 1차 대응(`9d97bb7d`, `docs/progress/2026-11.md` 11-06 절) · ADR-091·ADR-123(컴시간 보강·교체)

## 발단

v2.5.8(11-06)로 컴시간 암호화에 대응한 지 사흘 만에 컴시간이 다시 바꿨다. 11-09 챗봇 제보 3건
("우리 학교가 검색이 안 돼", "컴시간에 연동할 수 없다는데", "컴시간 변경 미반영")이 같은 원인이었고,
11-10 실서버 확인에서 v2.5.8 코드는 `mainRoute 코드를 찾지 못했어요`로 전부 실패했다.

바뀐 것(실측 2026-11-10):

1. 요청 함수와 복호화 열쇠가 **한 겹 더** 감춰졌다(풀어낸 스크립트 안에 같은 방식의 블록이 또 있다).
2. 검색 주소가 `btoa(라우트 + 'l' + encodeURIComponent(학교명) + '_enc5')` 를 한 번 더 URL 인코딩한 꼴이 됐다
   (검색어가 EUC-KR 이 아니라 UTF-8).
3. 응답 표식이 `enc5` 가 됐다(base64).
4. 열쇠가 네 조각으로 나뉘어 순서가 섞였다(`a[2]+a[1]+a[3]+a[0]`).
5. `/st` 가 세션 쿠키를 내려 주고, 페이지에 심은 `__HourRequestToken` 을 `X-Hour-Token` 머리말로 받는다.

화면에서는 실패가 "검색 결과가 없어요"·"컴시간에 연결하지 못했어요"로만 보여, 선생님이 원인을 알 수 없었다.

## 결정

1. **난독화는 더 풀 것이 없을 때까지 푼다**(상한 8겹). 가장 안쪽 층을 앞에 두고 찾는다.
2. **값을 못 박지 않는다.** 표식은 `enc숫자` 전체를 받고 `enc1` 만 16진수·나머지는 base64 로 본다.
   주소·열쇠 정규식은 새 형식 먼저, 옛 형식 나중 순서로 여러 개를 둔다. 옛 두 형식도 계속 읽는다.
3. **세션 쿠키는 메인 프로세스가 메모리에만 든다.** `/st` 응답의 Set-Cookie 에서 `이름=값`만 받아
   뒤이은 요청에 붙이고, 새 `/st` 를 받으면 갈아 끼운다. 디스크에 쓰지 않고 대상 호스트는 comci.net 고정이다.
   요청 토큰은 renderer 가 페이지에서 읽어 넘기고, 메인은 형식(영숫자 16~128자)만 확인해 싣는다.
   쿠키 쌍도 글자를 좁혀 받는다 — renderer·서버가 준 글자가 머리말에 그대로 들어가기 때문이다.
4. **검색 실패는 "결과 없음"과 구분해 보여 준다**(세 검색 창 모두 공용 안내 상자).

## 버린 안

- **렌더러가 쿠키 값을 만들어 넘기기.** 지금은 쿠키 값이 토큰과 같지만 이름(`HourSession4082S`)과 그 관계는
  컴시간 사정이라 언제든 바뀐다. 응답에서 받은 것을 그대로 돌려주는 쪽이 덜 깨진다.
- **컴시간 페이지 스크립트를 실행해서 값 얻기.** 남의 스크립트를 앱 안에서 실행하지 않는다(기존 원칙).

## 한계

- 컴시간이 의도적으로 바꾸고 있어 **다시 깨질 수 있다.** 그때는 "컴시간 서비스 구조가 바뀐 것 같아요"가
  뜨고 엑셀 불러오기·직접 입력으로 안내한다. 자동 감지·알림은 아직 없다.
- 실서버 확인은 앱 코드를 node 로 돌려 학교 검색 1회·시간표 1회로 했다. 설치본(메인 프로세스 경로)은 실기기 확인의 몫이다.
- macOS 실기기는 확인하지 못한다.
