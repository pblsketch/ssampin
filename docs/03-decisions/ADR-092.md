# ADR-092 · 실기기 대행 QA 결함 10건의 처리 방향 (2026-09-08)

## 배경

2026-09-08 실기기 확인을 Claude 세션이 CDP 로 앱을 조종해 대행했다(`docs/03-analysis/pre-release-device-qa-20260908.md` §6).
게이트 4종이 전부 초록인 채로 결함 10건(R-1~R-10)이 나왔고, 오너가 "다 고쳐라"고 결정했다. 고치면서 정한 것을 남긴다.

## 결정

1. **답할 AI 의 기본 선택은 "답할 수 있는 통로"여야 한다(R-1).** 쌤핀 AI(Solar)를 꺼 둔 채 "내 AI"만 켰으면 패널은 연결된 첫 구독으로
   선택을 옮기고, 꺼진 쌤핀 AI 는 고르기 목록에서 뺀다. 그래도 보낼 수 없는 선택이면 [보내기]는 **조용히 무시하지 않고 한 줄로 말한다.**
   스토어의 차단선(`ask` 의 조용한 return)은 마지막 방어선으로 그대로 둔다.
2. **분량 조절의 대상은 라벨이 가리키는 그 글이다(R-2).** 미리보기 중(반영 전)인 AI 판이 있으면 그 판의 글을 조절하고, 아니면 편집 칸의
   글을 조절한다. 원문은 패널이 정해서 실행 함수에 넘긴다 — 실행 함수가 따로 읽지 않는다. 조절 결과 판에는 어느 판을 조절했는지(`sourceVersionId`)
   와 그 판의 주제를 물려준다.
3. **초안이 아닌 답(거절·되묻기·목록)은 저장 후보가 아니다(R-3).** 도메인 규칙 `judgeNonDraftReply` 가 보수적으로 판정한다
   (사람에게 말을 거는 표현, 또는 목록 줄 2줄 이상). 분량 조절에서는 그런 후보를 빼고, 전부 그러면 실패로 말하며 그 글은 "AI가 보낸 설명 보기"로
   읽을 수만 있다. 초안 생성에서는 판을 만들지 않고 사유와 앞부분을 보여 주며 멈춘다. 설명문에는 재조정을 걸지 않는다 — 같은 원문이면 같은 거절이 온다.
4. **조절 대상이 이미 한도를 넘었으면 [분량 조절]을 저절로 펼친다(R-4).** 결과가 한도를 넘었을 때만 펼치던 것을 넓혔다.
5. **[편집칸에 넣기] 뒤 화면 이동은 막지 않되 말한다(R-5, ADR-088 후속 5 의 결론).** 실측: 이동은 막히지 않았고 글은 메모리에만 남아 앱을 끄면
   사라진다. 막으면 선생님이 보드를 못 보고 갇힌다. 그래서 넣는 순간과 이동하는 순간에 "한도를 넘어 저장되지 않았다"를 알린다. 저장은 여전히 한도
   안에서만 된다.
6. **[중단]을 둔다(R-6).** 패널(구독 CLI 가 답하는 턴만), 초안 생성, 분량 조절. 멈춤은 main 러너가 프로세스를 죽여 `cancelled` 를 흘리는 기존
   통로를 쓴다 — 포트는 `CancelableAssistPort.cancel()`, 실행 도우미는 `AbortSignal`. 쌤핀 AI(중계 서버) 턴에는 [중단]이 없다: 멈출 틈이 없고
   비용은 이미 나갔다.
7. **좁은 폭에서는 짓누르지 않고 가로 스크롤로 넘긴다(R-7).** 초안 화면 왼쪽 칸에 최소 폭(320px)을 두고 안내문은 줄바꿈하지 않는다.
8. **모델은 내부 이름이 아니라 선택 상자와 같은 이름으로(R-8).** `shortModelLabel` 을 미리보기 머리에도 쓴다.
9. **끌어놓기 화면낭독 문구는 한국어(R-9).** 모든 `DndContext` 에 `DND_KO_ACCESSIBILITY` 를 넘긴다. 새 DndContext 도 같은 값을 넘겨야 한다.
10. **`sp-danger` 는 없는 토큰이다(R-10).** 교무실 6파일을 `sp-error` 로 바꿨다. 정의되지 않은 `sp-*` 는 CSS 규칙이 아예 안 만들어져 조용히 안 보인다.

## 하지 않은 것

- 스토어 `ask` 의 조용한 return 을 오류 턴으로 바꾸지 않았다 — 화면이 먼저 막으므로 거기까지 오면 코드 결함이다.
- 한도 초과 글을 재시작 뒤에도 살리는 임시 저장은 만들지 않았다(ADR-088 결정: 디스크엔 한도 안 글만).
