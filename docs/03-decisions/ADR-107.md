# ADR-107 · 장면 체계는 근거 지도 안으로 — 장면 열 · 주제 사이 이음말 화살표 · 오른쪽 상세 다섯 모드, 흐름 보기는 없앤다

- 날짜: 2026-09-11
- 상태: 채택 (구현·검사 완료 · 미커밋 · v2.5.2 로 ADR-103~106 과 함께 출시, 오너 실기기 테스트 뒤)
- 대체: ADR-103 결정 1(흐름 보기)·ADR-104(흐름 보기 위의 그래프 조망·개요 지도·[모두 접기])의 **화면**을 없앤다. ADR-103 결정 2~9
  (장면 배열 = 작성 구성, 4자리, 뼈대, 장면 메모, AI 장면 배치, 주제 이음말, 요청서 규칙)와 ADR-106(근거 사이 연결·요청서·상단 단추 3개·보조 공간 하나)은 그대로다.
- 관련: ADR-106 실행 기록 `docs/03-analysis/record-evidence-canvas-redesign.execution.md`(§장면 통합), 오너 결정(2026-09-11):
  "장면 체계는 핵심 기능 — 빼는 게 아니라 지도에 자연스럽게 통합" + "주제와 주제 사이의 이음말도 중요 — 지도니까 화살표에 메모", 디자이너 검토(2026-09-11, scene-map-designer).

## 무엇을 정했나

1. **주제 묶음은 둘 중 하나로 그린다.** 장면이 있으면 **장면 열**(`[평가 | 동기 | 과정 | 결과 … | 자리 미정]`, x = 장면 차례, 카드는 열 안에 적힌 차례로 세로),
   장면이 없으면 예전대로 **연결 층**(왼쪽→오른쪽, 같은 층은 날짜순). 열이 있는 묶음에서는 손으로 민 위치(`offsets`)를 쓰지 않는다 — 열이 자리를 정한다.
   장면 열에 놓는 것은 흐름 보기의 놓는 곳 이름표(`drop:scene:…`·`drop:unplaced:…`)를 그대로 써 부모의 `onDragEnd` 가 갈라지지 않는다.
2. ~~**글 순서(열)와 관계(화살표)를 한 화면에 둔다.**~~ (ADR-108 로 대체 — 화살표는 장면 사이로) 원문: 열은 초안 차례, 화살표는 근거 사이 연결(ADR-106). 열을 가로지르는 화살표는 그대로 그리고,
   뒤 카드가 왼쪽에 있는 역방향 연결은 카드 위를 가로지르지 않게 **두 카드 아래로 돌아서** 간다(`edgeGeometry`).
3. **주제 사이 이음말은 화살표 라벨이다.** 앞 주제에서 이어진 묶음은 앞 묶음 바로 아래에 오고(줄기 모델 `lanes` 의 차례 그대로), 두 묶음 사이 왼쪽에 화살표와
   `↳ 이음말` 라벨이 그려진다. 라벨을 누르면 오른쪽에 「주제 이음」이 열려 이음말을 적거나 [연결 끊기]를 한다. 저장은 흐름 보기와 같은 관문(`setLink`).
4. **오른쪽 보조 공간은 여전히 하나, 모드는 다섯.** 근거 상세 · 연결(ADR-106) + **장면**(카테고리 바꾸기·←→·장면 메모·놓인 근거 [빼기]·자리 미정 [여기에 놓기]·
   [+ 주제 미정 근거에서 고르기]·[+ 이 뒤에 장면 끼우기]·[장면 지우기]) · **주제**(이름·앞 주제와 잇기·[뼈대 깔기/고르기]·[AI 장면 배치 제안]+추가 요청·
   [이 주제로 초안 쓰기]·[이어진 흐름 전체로]·[주제 설정 더 보기]) · **주제 이음**(이음말·연결 끊기). 열 머리 = 장면, 묶음 제목 = 주제, 사이 라벨 = 주제 이음.
   같은 것을 다시 누르면 닫힌다. 카드·연결을 누르면 장면·주제 선택은 닫힌다(교대).
5. **뼈대·AI 장면 배치의 입구.** 장면이 없는 묶음 머리 [뼈대 깔기]와 주제 상세 [뼈대 고르기]가 도구줄 아래 인라인 뼈대 칸을 **그 주제로** 연다(팝오버 금지 규칙 유지).
   [AI로 정리 제안 ▾] 메뉴는 「주제 미정 근거 N건을 주제로 묶기」 + **열린 주제마다** 「‘주제’의 장면 배치 제안」(근거 0건이면 잠금). 추가 요청은 주제 상세에 있다.
   제안 점선(`NarrativeSuggestGhost`)은 그 묶음 머리 아래에 뜨고, 적용 전 저장 0회·적용 실패 시 제안 유지는 그대로다.
6. **가상 평가 자리**는 열로도 보인다(점선 아님 — 접근 이름에 「아직 저장되지 않은 자리」). 거기에 메모를 적거나 카드를 놓으면 `materializeScene` 이 먼저 진짜 자리를 세운다.
7. **흐름 보기를 없앤다.** `NarrativeFlowView`·`NarrativeLane`·`SceneCell`·`LinkArrow` 와 그 검사 파일을 지우고, 보기 전환은 [지도 | 보드] 둘이다.
   설정에 남은 `recordEvidenceViewMode: 'flow'` 는 **읽는 쪽이 지도로 본다**(설정 파일을 고치지 않는다). 타입에 `'flow'` 는 옛 값으로만 남긴다.
   흐름 보기 검사(`recordEvidenceFlow.test.tsx`)는 지도 UI 로 옮겨 `recordEvidenceMapScenes.test.tsx` 가 됐다 — 놓기 관문·가상 평가 자리·AI 배치 생명주기·쓰다 만 메모 확인이 그대로 지켜진다.
8. **상단 단추는 여전히 셋.** 흐름 보기의 [+ 주제]·[뼈대 고르기]·[AI로 장면 배치]는 지도 안(맨 아래 [+ 주제] 칸·묶음 머리·주제 상세·정리 제안 메뉴)으로 들어갔다.
9. **화면 낱말**: 장면 · 자리 미정 · 뼈대 깔기/고르기 · 이음말 · 주제 이음 · AI 장면 배치 제안. "서사·줄기·노드·엣지·캔버스"는 코드에만.

## 왜

오너는 흐름 보기를 없애되 **장면 체계는 핵심**이라고 했다 — "선생님이 학생의 배움 과정에 의미를 부여하고 체계적으로 서술하는 데 뼈대와 장면이 중요". 두 보기가 같은 자료를
따로 그리면 선생님은 "관계는 지도, 차례는 흐름"으로 오가야 하고, 이전 세션이 그 이유로 제거를 보류했다. 장면을 **열**로 지도에 얹으면 글 순서와 관계가 한 화면에 놓이고,
주제 사이 이음말은 "지도니까 화살표에 메모"라는 오너 직관 그대로 라벨이 된다. 새 화면·새 저장 경로는 없다 — 모든 저장은 흐름 보기가 쓰던 관문(`placeInScene`·`detachToUnplaced`·
`layScaffold`·`setLink`·`setSceneNote`·`addScene`·`moveScene`·`removeScene`·`runNarrativeSuggest`)을 그대로 부른다.

디자이너 검토에서 받아들인 것: 열 머리는 한 줄(메모는 아이콘 + title) · 자리 미정 열은 점선 윤곽 · 역방향 화살표는 아래로 우회 · ↑↓ 는 hover 에서 · 장면 상세에 자리 미정 목록 +
[여기에 놓기] · 낱말 유지(자리 미정·장면·뼈대 고르기). 받아들이지 않은 것: 열 4개 이상의 가로 스크롤을 열 폭 축소로 막기 — 카드 폭(224px)을 줄이면 본문 3줄이 깨져
[화면에 맞추기]로 두었다(오너 실기기에서 다시 볼 것).
