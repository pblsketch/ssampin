# ADR-141 — Google Tasks 동기화: 충돌은 쌤핀이 이기고 덮이는 구글 내용을 기록·알린다, 암호화 저장소가 없으면 로그인 정보는 메모리에만 둔다

- 날짜: 2026-10-14
- 상태: 채택 · 구현·커밋 `9d429a50` `c525aeb8` `8f28b3ca` `6eb65042` `f780f358`(설정 카드·문서는 이어서) ·
  **실제 구글 계정 확인 미완**(체크리스트 [google-tasks-sync.md](../google-tasks-sync.md) §8) · 미출시
- 요구사항 정본: `.dryforge/spec.md`(개발 도구 폴더 — 저장소에는 올라가지 않는다. 이 ADR 이 결정을 옮겨 적었다)
- 결정자: 오너 (2026-10-14 대화 — "추천대로", 이어서 독립 검토가 올린 질문 4개 모두 추천안)
- 관련: [ADR-039](ADR-039.md)·[ADR-040](ADR-040.md)(기기별 값은 동기화 대상에 두지 않는다) ·
  [ADR-066](ADR-066.md)(출처별 분리·토스트도 개인정보 표면) · [ADR-136](ADR-136.md)(구글에서 받은 자료)

## 발단

구글 OAuth 심사가 2026-10-14 에 승인되어 Tasks 동기화를 보강하게 됐다. 이미 구현되어 있었으므로(2026-05 정밀화,
5단계 파이프라인) "새로 만들기"가 아니라 요구사항 대비 부족한 곳을 메우는 작업이 됐다.

- **충돌이 알림 없이 덮였다.** 올리기(PUSH)가 가져오기(PULL)보다 먼저 돌아, `pendingRemoteOp: 'update'` 인 항목은 구글 상태를
  보지 않고 쌤핀 내용으로 덮었다. 구글에서 고친 내용이 흔적 없이 사라졌다. (초기 보고에서 "최신 쪽이 이긴다"고 설명했으나
  실제로는 쌤핀이 항상 이겼다 — 오너에게 정정하고 다시 확인받았다.)
- **지운 마감일·메모가 반대쪽에 가지 않았다.** 올리기는 값이 없는 칸을 아예 보내지 않았고(PATCH), 가져오기는 구글 메모가
  없으면 쌤핀 메모를 남겼다. 두 쪽이 영구히 어긋났다.
- **로그에 이메일·인증 코드가 남았다.** 코드 교환 로그가 이메일을, 콜백 요청 로그가 `code` 가 든 주소 전체를 찍었다.
- **암호화를 못 쓰면 평문 파일로 썼다.** 구글 토큰과 마크다운 변환의 실명 복원표가 같은 규칙을 탔다.

## 결정

1. **승자는 바꾸지 않는다 — 쌤핀이 이긴다.** 오너가 "쌤핀이 항상 이김"을 골랐다(구글 앱에서 방금 고친 것이 아직 못 올린
   쌤핀 수정을 덮는 쪽보다 안전하다). 시각 비교로 승자를 정하지 않는다(쌤핀 PC·구글 서버·휴대폰 시계가 다르다).
2. **덮이거나 사라지는 구글 내용을 기록하고 알린다.** 종류는 `edit-edit`·`remote-deleted`·`local-deleted` 세 개.
   - 판정은 올리기 **전에** 구글 목록을 한 번 읽어서 한다. 올리거나 지울 보류 변경이 있을 때만 읽는다(일일 쿼터 5만 건 보호).
   - `lastSyncedAt`(이 PC 시계)과 구글 `updated`(서버 시계)의 차이는 **5분 허용 오차**를 두고, 내용이 같으면 충돌이 아니다.
   - 구글에서 이미 지운 항목에는 수정을 보내지 않고 새로 만든다. 읽기에 실패한 회차에는 수정 응답의 `deleted: true` 로 가른다
     (실제 확인: 삭제된 항목에 수정을 보내면 구글이 오류 없이 200 으로 받아 주고 삭제 상태 그대로다 — 옛 코드는 이 응답을 성공으로 보고
     이어지는 가져오기에서 쌤핀 할 일을 지울 수 있었다).
   - 기록은 기기 전용 키 `tasks-sync-conflicts`(드라이브 동기화 제외, 메타 테스트가 강제), 최대 20개, 같은 충돌은 한 번만.
   - 알림은 앱 안 토스트 한 번(개수만, 제목 없음). 설정 > Google Tasks 카드의 "최근 충돌 기록"에서 구글에 있던 내용을 본다.
     선택·되돌리기 화면은 만들지 않는다.
3. **한쪽에서 지운 것을 다른 쪽에서 고친 경우**: 구글에서 지웠는데 쌤핀에서 고쳤다면 쌤핀 변경을 살려 구글에 다시 만들고,
   쌤핀에서 보관했는데 구글에서 고쳤다면 삭제가 이긴다(영구 삭제는 로컬 기록이 이미 없어 기록하지 못한다). 둘 다 기록한다. 삭제는 의도적 행위이고, 고친 내용은 잃지 않는 쪽이다.
4. **마감일·메모를 지우면 반대쪽에서도 지운다.** 수정(PATCH)에서 `null` 로 보내고, 가져오기에서 구글 메모가 없으면 쌤핀도 지운다.
   생성(POST)은 빈 칸을 보내지 않는다.
5. **민감 정보는 로그에 남기지 않는다.** 이메일(기본 캘린더 ID·이름 포함), 인증 `code` 가 든 주소, `client_id`, `redirect_uri`.
   소스 검사 테스트가 `console` 인자의 식별자를 직접 본다.
6. **암호화 저장소를 못 쓰면 평문을 쓰지 않고 메모리에만 둔다**(모든 키). 옛 평문 파일은 쓰기에서 지우고, 암호화가 가능한데
   옛 평문이 남았으면 읽는 순간 암호화해 다시 쓴다.

## 근거

- 오너가 이 요구를 직접 명시했다: "조용히 덮어쓰기 금지", "평문 저장 금지", "민감 정보 로깅 금지".
- 충돌 기록을 `tasks-sync-state` 나 할 일 파일에 두지 않은 이유는 ADR-039/040/066 과 같다 — 기기마다 본 일이 다르고,
  동기화 대상에 두면 다른 기기가 같은 충돌을 또 기록하거나 지운 기록이 되살아난다.
- 스냅샷을 가져오기 단계의 `listTasks` 로 대신하지 않는 이유: 가져오기는 올린 뒤 다시 읽어야 한다(올린 결과를 반영).

## 하지 않은 것

- 시각으로 승자를 정하기, 항목별 합치기, 충돌 선택 화면.
- `updatedMin`·`syncToken` 증분 동기화, 시간·우선순위·반복·하위 할 일 동기화, 다중 목록, 새 OAuth 스코프.
- 쓰이지 않는 `SyncTodos.ts` 삭제(문서에 "사용 안 함"으로만 표시).
- Tasks 카드의 "확인되지 않은 앱 경고는 정상" 안내 문구 변경 — 심사 승인 후에도 경고가 남는지 확인한 뒤 오너가 바꾼다.

## 한계 / 남은 것

- **구글 API 동작은 직접 확인했다(2026-10-14, API 탐색기·임시 목록)**: `null` 로 지우기, 삭제 표시의 모양, 삭제된 항목에 대한 수정 응답
  ([google-tasks-sync.md](../google-tasks-sync.md) §9). **쌤핀 앱 화면에서는 확인하지 못했다**: 충돌 3종의 실제 동작, 심사 승인 뒤 동의 화면.
- 마지막 동기화 직후 5분 안에 구글에서 고친 변경은 판정하지 못하고, 시계가 심하게 어긋난 PC 에서는 불필요한 알림이 날 수 있다.
- 컴퓨터를 두 대 이상 같은 목록에 연결하는 경우의 조정은 하지 않는다("한 대에서만 켜기" 안내).
- 암호화를 못 쓰는 PC 에서는 앱을 다시 켤 때마다 다시 로그인해야 하고 마크다운 변환의 실명 복원표도 비어 있다.
  일반적인 Windows·macOS 에서는 암호화가 가능하므로 드문 경로다.
- 구글에서 반복 할 일을 완료해도 쌤핀은 다음 회차를 만들지 않는다(기존 한계).

## 되돌리기

각 변경이 독립 커밋이다. 충돌 알림만 끄려면 `useTasksSyncStore.ts` 의 `judgeConflict` 호출만 되돌리면 된다(승자·올리기
순서는 그대로다). 암호화 규칙은 `secureStorage.ts` 커밋 하나를 되돌린다 — 되돌리면 옛 평문 폴백이 돌아온다.
