# ADR-085: 생기부 초안 3차 — 근거는 보드 한 장, AI 초안은 오른쪽 패널, 문단에는 형광펜 (ADR-083 두 곳 수정)

- 일자: 2026-09-06
- 상태: 채택 (오너 인터뷰 2026-09-06 → 설계서 `docs/02-design/features/record-draft-uiux-v3.design.md`)
- 관련: ADR-072(생기부 초안) · **ADR-083(이 문서로 두 곳 수정)** · ADR-084(공급자 고르기)

### 발단 — 화면이 쓰는 순서를 안 따라간다

오너와 초안 화면을 같이 놓고 본 인터뷰에서 문제 8개가 확인됐다(설계서 §1). 핵심은 셋이다.

1. **초안 화면과 근거 자료 화면이 학생 선택을 공유하지 않는다.** 근거 화면은 늘 첫 학생으로 열린다.
2. **근거 자료 화면에 층이 최대 12개 동시에 보인다**, 근거 카드 하나에 조작이 10개 안팎이고, 주제로 묶는
   길이 세 가지(끌어놓기·체크 후 묶기·"이것도 이 주제?")라 어느 것이 정석인지 알 수 없다.
3. **AI 미리보기 글자가 9.6~10.4px** 다(`text-[0.6rem]` 14곳). 편집 칸은 14px 인데 AI 답만 작다.
   초안 문단이 무엇(동기·과정·결과·평가)인지 알 길도 없다.

### 오너 결정 (2026-09-06)

| 항목                  | 결정                                                                                       |
| --------------------- | ------------------------------------------------------------------------------------------ |
| 기본 경로             | **근거 정리 → AI 초안 → 검토.** AI 활용이 기본                                             |
| 근거 정리 화면        | **보드형이 목록 화면을 대체**한다(전환 유지 안 함). 열 = 미분류 + 학생의 주제              |
| 묶기 방법             | **체크 후 묶기가 정석**, 문자열 제안은 보조, **끌어놓기 제거**(dnd-kit 코드 삭제)          |
| AI 분류 제안          | **허용** — "이렇게 묶으면 어떨까요"까지. 저장은 [적용]을 눌러야 한다                       |
| 카드 상시 표시        | 본문·날짜·주제·출처·유형 토글·수정·삭제. AI 전송/제외는 접는다                             |
| 엑셀·끌어오기         | 「가져오기 ▾」 하나로 접는다                                                               |

| 외부 AI용 select·복사 | 제거, AI 패널 안 주제 선택으로 합침                                                        |

| 내 글 이전 버전       | 저장하지 **않는다**. [바꾸기] 직후 30초 [되돌리기](메모리만)                               |
| 글자 크기             | 작은 글자(0.55·0.6·0.65rem)를 없애 설정 > 화면 글꼴 크기를 따르게 **먼저** 고친다          |
| 형광펜 기준           | 영역 무관 **공통 골격 4종**: 동기·질문 → 과정 → 결과 → 교사 평가                           |
| 형광펜 표식 주체      | AI 가 문단 앞에 `[동기]` 류 표식을 붙여 보내고 앱이 색으로 바꾼다. 저장 본문에는 표식 없음 |
| 형광펜 범위           | 미리보기 **와** 저장 후 편집 칸 모두. 화면 스위치 1개. 범례는 켰을 때만                    |
| 편집 후 표식          | 고친 문단은 색이 흐려짐 + [다시 표시]로 AI 재요청(본문 불변, 표식만 갱신)                  |

### ★ADR-083 수정 두 곳

1. **"담임 행특에는 적용하지 않는다" → 폐기.** 오너: 학급 운영에서 남긴 기록에도 행특·자율·진로에 들어갈
   줄기가 있다. 주제 묶기·형광펜은 담임/교과 구분 없이 적용한다.
2. **"AI 는 흐름을 만들지 않는다. 제안은 전부 문자열 검사" → 완화.** AI 는 분류 **제안**을 할 수 있다.
   지키는 선:
   - 제안은 화면에 점선(고스트)으로만 뜨고, [적용] 전에는 **아무것도 저장되지 않는다**(`setThread` 0회).
   - 근거 본문이 밖으로 나가므로 **생기부 초안과 같은 규칙**: 구독 AI(Claude Code·Codex)만, 쌤핀 AI(Solar)
     폴백 없음, 실명·학번 가림(`redactOutbound` 세션), `excludedFromAi`·기재 금지 근거 제외.
   - 기존 문자열 검사 제안(`threadSuggest.ts`)은 AI 없이도 도는 **보조**로 남긴다.
3. 유지: 주제는 선택이다 · 점수판 없음 · 고아 threadId 관용 · 주제 이름 1순위는 수행평가 이름.

### 데이터

- `RecordDraft.roleMarks?` — [반영] 시점의 문단별 역할. additive optional, 병합에서 부재를 빈 값으로 덮지 않는다.
- `RecordAiDraft`(신규, `record-ai-drafts.json`) — 실명 복원이 끝난 문단 목록·제외 요약·공급자·반영 시각.
  별칭 매핑은 저장하지 않는다. 동기화(snapshot)·보관함·학년도 전환 대상. 개인정보 수위는 `RecordDraft` 와 같다.
- `Settings.recordHighlightOn?` — 형광펜 스위치.

### 하지 않는 것

마인드맵 시각화 · 내 글 이전 버전 디스크 저장 · 형광펜 색 직접 편집기 · 쌤핀 AI(Solar)로 분류 제안·초안 폴백 ·
영역별 형광펜 어휘 분기.

#### ADR-085 보강 (2026-09-06, 구현 중 결정): 보드의 저장 관문과 AI 제안 경계

- 근거 정리 보드가 근거를 옮기는 길은 `useRecordEvidenceStore.moveToThread / moveToNewThread / unclassify` 셋뿐이다. 셋 다 `studentRef` 를 필수로 받아
  다른 학생·없는 근거는 저장 전에 걸러 `skippedIds` 로 돌려주고, 화면은 그 건수를 반드시 말한다("N건은 이 학생 근거가 아니라 묶지 않았습니다").
  `moveToNewThread` 는 주제 생성 + 이동이 한 동작이며, 옮길 근거가 0건이면 빈 주제를 만들지 않고 이동 저장이 실패하면 방금 만든 주제를 지운다.
- AI 분류 제안(`buildThreadSuggestPack` → `parseThreadSuggestions`)의 결과는 **스토어·파일에 두지 않는다.** 보드 컴포넌트 메모리에만 있고
  점선 고스트 카드로만 보이며, [이 열 적용]/[전체 적용]이 곧 위 관문 호출이다. 학생을 바꾸면 제안은 사라진다. 파서는 실패 이유 4종
  (`empty-answer`·`none`·`no-format`·`no-valid-numbers`)을 구분해 "AI 가 묶을 것이 없다고 답함"과 "형식을 못 읽음"을 다르게 안내한다.
- 서랍(주제 줄기·가져오기)은 `createPortal` 로 body 에 붙이고 `role="dialog"` + `bg-sp-card` + `data-sp-floating` 을 함께 단다 — 보드가 유리 패널 안에 있어
  안쪽에 띄우면 배경이 지워지기 때문. RecordDraft/\*_ 에서는 `sp-_/NN` 투명도 수식을 쓰지 않는다(이 프로젝트의 토큰 정의로는 규칙이 생성되지 않아 배경이 사라진다).

#### ADR-085 보강 2 (2026-09-06, 오너 결정): 거울 카드·1건 주제 제안·끌어놓기 부활·모델 이름

- 배경: 오너가 실기기에서 근거 정리 보드를 쓰고 7건을 지적했다(설계서 `docs/02-design/features/record-evidence-board-v2.design.md` §1).
  핵심은 "이미 기록해 둔 것이 왜 저절로 안 보이나"와 "왜 끌어다 놓을 수 없나"다. 위 결정표의 두 줄(「가져오기 ▾」로 출처마다 끌어온다 · 끌어놓기 제거)을 오너가 뒤집었다.

| 항목                             | 확정                                                                                                                                         |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| R1 기존 기록을 어떻게 넣나       | **거울 카드**: 저장하지 않고 미분류 열에 비춰 보이기만 하다가, 처음 손댈 때(끌기·주제 보내기·AI 제외·수정) 그때 근거로 저장                  |
| R2 AI 가 1건짜리 주제도 제안하나 | **허용**: 기록이 하나여도 뚜렷한 활동이면 "주제 씨앗"으로 제안한다. 서로 관련 없는 기록을 억지로 묶는 것은 여전히 금지. 적용은 교사가 누른다 |
| R3 끌어놓기 부활                 | **위 결정표의 "끌어놓기 제거"를 뒤집는다.** 하단 바 = 정석·키보드 경로, 끌기 = 마우스 지름길. **저장 관문은 하나**(아래)                     |
| R4 모델 이름                     | 모델 라벨에서 부연 설명("가장 강력함"·"꼼꼼함" 등)을 **통째로** 뺀다. `기본 (권장)` 은 모델명이 아니라 "고르지 않음"이라 그대로 둔다         |

- R1 거울 카드의 근거: 기록은 관찰 탭 등 **원본이 따로 있다.** 보드가 열릴 때마다 조용히 복제해 저장하면
  (1) 동기화 파일이 학생 수 × 기록 수만큼 부풀고, (2) 교사가 지운 복제본이 다음에 열면 되살아나며, (3) 원본을 나중에 고쳐도 복제본은 옛 글로 남는다.
  거울 카드는 손대기 전까지 원본을 그대로 **비추기만** 하고, 손댄 순간부터가 "근거"다. AI 분류 제안이 "적용 전 저장 0회"인 것과 같은 원칙이다.
  거울에는 [삭제]가 없다(지울 것은 원본이고 그 자리는 관찰 탭이다). 이미 저장된 `sourceId` 는 거울을 만들지 않는다.
- R2 의 근거: 지시가 "같은 탐구 흐름으로 이어지는 것만 묶어라"로 엄격해 서로 다른 활동 3~5건이면 규칙대로 `없음`이 정답이 됐고, 화면은 이유를 몰라 막다른 길이 됐다.
  1건 주제를 허용하고 `없음 | 이유` 형식으로 이유를 받아 화면에 보인다. 저장은 여전히 [적용]을 눌러야 한다(위 보강의 "적용 전 저장 0회" 유지).
- R3 의 근거와 지키는 선: 3차에서 끌어놓기를 뺀 이유는 "묶는 길이 셋이라 헷갈린다"였다. 이번에는 길을 늘리는 것이 아니라 **같은 관문으로 가는 입구를 둘** 두는 것이다.
  - 저장은 위 보강의 `moveToThread / moveToNewThread / unclassify` 그대로. 거울은 `add(threadId)`. **새 저장 경로를 만들지 않는다.**
  - 클릭(선택)과 끌기(이동)는 6px 이동 거리로 가른다. 키보드 끌기 센서는 붙이지 않는다(키보드 경로는 하단 바).
  - 닫힌 주제 열은 받지 않는다. 움직임은 사용자 동작에 답할 때만(대상 열 테두리 강조·끌기 미리보기), 그 외 애니메이션 없음.
- R4 의 근거: 오너가 "부연 설명은 필요 없다, 모델명만"으로 정했다. 목록은 두 군데다: 앱 안 `ownAiCliRules.ts`(서버 실패 시 대비용)와
  서버 `supabase/functions/ssampin-ai-models`(평소에 화면에 뜨는 목록). **서버 함수는 배포해야 화면에 반영된다**(배포는 오너 승인 후 별도).
- 같이 정한 것: 화면 문구와 모델에게 가는 문자열의 em 대시(`—`)는 쌍점(`:`)으로 바꾼다. 주석·JSDoc 은 대상이 아니다.
  메타 테스트 `recordDraftNoEmDash.meta.test.ts` 로 다시 들어오지 않게 잠근다.
