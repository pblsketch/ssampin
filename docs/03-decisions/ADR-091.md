# ADR-091: 컴시간 일일자료(보강·교체)도 받아 "이번 주 변경"으로 따로 안내한다

- **상태**: active · **일자**: 2026-09-08 · **관련**: ADR-020 계열 컴시간 변경 감지(2026-07-03, `42e1a5ef`)
- **발단**: 사용자 제보 — "컴시간 알리미의 시간표가 변경되었는데 새로고침을 누르면 변동 없음이라고 뜬다."

## 실측 (2026-09-08)

- 컴시간 `/st` 페이지는 격자를 두 벌 준다. `원자료=…자료481`(학기 기본 편성표)과 `일일자료=…자료147`(보강·교체가 반영된 이번 주 표, 바뀐 칸은 `>` 접두).
- 앱은 원자료만 읽고 비교했다(`ComciganApiClient.getSchoolData` → `baseGrid`). 오너 설정 학교로 두 격자를 직접 견주니 **25칸이 달랐고 전부 `>` 표시**였는데, 앱은 이 칸을 영원히 보지 못했다. 선생님이 컴시간 알리미 앱에서 보는 "변경"은 대부분 이쪽이다.
- 쿼리 `_0_1` 은 (버전 0, 이번 주 r=1). 주 선택은 그대로 둔다.

## 결정

1. **일일자료를 같이 받는다.** `dailyGrid?` 로 넘기되 **선택 자료**다 — 페이지에서 코드를 못 찾거나 응답에 없으면 기본 편성표만으로 예전처럼 돌아간다(에러 아님).
2. **두 판정을 섞지 않는다.** 기본 편성표 diff(저장본 ↔ 서버 원자료)는 그대로 "검토 후 적용". 이번 주 변경은 **서버 원자료 ↔ 서버 일일자료**를 같은 교사로 견준 차이다. 저장본과 견주면 기본 편성표 변경과 섞여 무엇이 이번 주만의 일인지 알 수 없다.
3. **이번 주 변경은 알리기만 한다.** 시간표에 반영하지 않는다(이번 주만의 일을 기본 편성표에 덮으면 다음 주가 틀어진다). 스토어 `weeklyComciganChanges`(비영속) → 시간표 화면 교사 탭 배너에 요일·교시·전후 과목을 펼친다. 확인 함수는 `weeklyChangeCount` 를 함께 돌려주고, 위젯 배너는 unchanged + weekly>0 을 "최신 상태"로 뭉개지 않고 `weekly` 로 올린다.
4. **문구**: 기본 편성표가 그대로면 "기본 시간표는 그대로예요. 이번 주 보강·교체가 N칸 있어요." — 자동 확인(앱 시작, 하루 1회)에서도 알린다. 기본 편성표까지 바뀌면 검토 안내 뒤에 한 문장으로 덧붙인다.

## 하지 않은 것 · 다음

- 이번 주 변경을 **변동 시간표(overrides)** 로 자동 등록하는 것. 날짜 매핑(요일→이번 주 날짜)·유형 추정(swap/substitute/cancel)이 필요하고, 틀리면 실제 수업이 어긋난다. 오너가 원하면 별도 설계.
- 다음 주(r=2) 조회. 컴시간 폴링 금지 원칙(하루 1회 + 수동)은 그대로.
