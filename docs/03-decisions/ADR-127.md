# ADR-127 — 참여교실 세 화면의 시각 언어

- 날짜: 2026-09-21
- 상태: 채택, 로컬 구현 · 미배포 · 오너 실기기 확인 대기
- 관련: [ADR-126](ADR-126.md)(유형 통합)의 화면을 다듬는다. 조사·제안은
  프론트엔드 디자인 전문 에이전트와 함께 했다(협업 규칙).

## 발단

오너가 "선생님이 문항을 만드는 창, 학생이 응답하는 창, 교실에 공유되는 창의 디자인이
너무 무난하고 밋밋하다. 퀴즈·설문·토의토론에 맞게 더 매력적으로" 라고 요청했다.

실제로 찍어 보니 세 화면이 모두 **한 가지 파란색과 한 가지 글자 크기**로만 그려져 있었고,
교실 화면은 교사 콘솔과 같은 크기로 결과를 그려 뒷자리에서 읽히지 않았다.

## 결정

### 1. 문항 유형은 무리별 색과 아이콘으로 구분한다

> ⚠️ **이 절의 5무리 구분은 [ADR-129](ADR-129.md)가 퀴즈·토론·설문 3무리로 대체했다.**
> 아래 표는 기록으로 남긴다. 색을 무리에 준다는 원칙과 `questionTypeStyle.ts` 한 곳에서
> 정한다는 원칙은 그대로다.

`src/adapters/multiSurvey/questionTypeStyle.ts` 하나에서 정한다. 15가지 색을 쓰면
아무것도 구분되지 않으므로 **답하는 방식**으로 묶는다.

| 무리      | 유형                       | 색 토큰        |
| --------- | -------------------------- | -------------- |
| 고르기    | 객관식·복수 선택·OX·신호등 | `sp-accent`    |
| 적기      | 단답형·빈칸·서술형·숫자    | `sp-info`      |
| 자리 잡기 | 가치수직선·이미지 위치     | `sp-success`   |
| 순서·배분 | 순서 배열·순위·점수 배분   | `sp-warning`   |
| 모으기    | 아이디어·질문·워드클라우드 | `sp-highlight` |

- `sp-error`(파괴적 액션)와 `sp-muted`(비활성)는 뜻이 정해져 있어 쓰지 않는다.
- 아이콘은 Material Symbols. **React 화면에만** 쓴다.
- 편집 화면 문항 목록의 유형 색은 **왼쪽 띠(별도 요소)** 로 그린다. 같은 상자에
  유형 테두리색과 선택 테두리색을 겹치면 어느 쪽이 이길지 정해지지 않는다.

### 2. 결과 그림은 보는 거리에 따라 두 벌로 그린다

`QuestionResponseSummary` 에 `size: 'compact' | 'display'` 를 둔다.
`compact` 는 교사 콘솔·유형 미리보기(책상 30cm), `display` 는 교실 화면(교실 뒷자리)이다.
글자·막대·점·단어 크기만 갈리고 **모양은 같다** — 한쪽을 키우면 다른 쪽이 망가진다.

### 3. 보기 글자는 학생 휴대폰과 교실 화면이 같다

교실 화면은 보기를 `1 2 3 4` 로, 학생 폰은 `A B C D` 로 부르고 있었다. **둘 다 A·B·C·D** 로
맞춘다. 선생님이 "B 고른 사람?" 하고 부를 수 있어야 한다.
OX는 `O`·`X`, 신호등은 `찬`·`보`·`반` 처럼 첫 글자를 쓴다.

### 4. 채운 배경 위 글자색이 보장된 토큰은 `sp-accent` 뿐이다

`sp-accent` 에는 짝이 되는 `sp-accent-fg` 가 자동 계산된다. `sp-highlight`·`sp-success` 등에는
그런 짝이 없어 테마 13종에서 대비가 무너진다. 그래서 **강조색 칩은 채우지 않고
테두리+글자색**으로 그린다(`border-2 border-sp-highlight text-sp-highlight`).

### 5. 학생 화면의 색은 활동 목적이 아니라 **문항 성격**으로 가른다

디자인 제안은 활동 목적(퀴즈/토의토론/활동) 3색이었으나 **뒤집었다.**
ADR-125로 목적 선택을 없앴기 때문에 새 활동은 전부 `activity` 다 — 3색을 넣어도
모든 활동이 같은 한 색으로 나온다.

대신 문항마다 `scored`(정답이 있는가)로 가른다. 한 활동 안에서도 문항에 따라 색이 바뀌고,
학생은 "지금은 맞히는 문항인지, 생각을 내는 문항인지"를 색과 라벨(`◆ 정답이 있는 문항` /
`◇ 생각을 모으는 문항`)로 안다. 정답 문항은 파랑, 의견 문항은 청록이다.

### 6. 움직임은 이미 있는 것만 쓴다

`animate-scale-in`(응답 수가 바뀔 때 숫자가 살짝 커졌다 돌아온다 — `key` 를 값으로 둬서
새 keyframe 없이 얻는다), `.sp-floating-card`(교실 화면에서 글 응답이 떠오른다),
막대의 `transition-[width]`. 전부 `motion-reduce:` 짝을 단다.

### 7. 교실 화면은 한 화면에 들어오게 한다

응답 현황(숫자·막대)은 위에 고정하고 결과는 남은 높이 **가운데**에 둔다(`my-auto`).
정답이 있는 문항은 정답과 분포를 **나란히** 놓는다 — "정답은 이거고 우리 반은 이렇게
갈렸다"가 한 번에 읽혀야 한다.

## 하지 않은 것

- **보기별 무지개색**(A=빨강 B=파랑…): 색만으로 뜻을 전하게 되고 차분함을 잃는다.
  정답만 채우고 나머지는 회색으로 둔다. 색맹 사용자를 위해 `· 정답` 글자를 함께 적는다.
- **순위판에 트로피·연속 기록 같은 장식**: 누적형 보상 게이미피케이션 금지 규칙.
- **학생 페이지에 외부 아이콘·폰트 CDN 추가**: 약한 네트워크에서도 즉시 열려야 한다.
  유니코드 기호(`◆`·`◇`·`✓`)만 쓴다.
- **새 폰트·새 keyframe 도입**: 테마 13종과 학생 페이지가 이미 맞춰져 있다.

## 곁가지로 고친 결함

- 결과 막대 바탕(`bg-sp-accent/10`)과 이미지 위치 정답 영역(`bg-sp-accent/20`)이
  **원래부터 투명**이었다. sp 토큰 + 투명도 수식은 이 저장소에서 클래스가 생성되지 않는다.
- 대기 화면의 학생 아바타가 **빈 파란 동그라미**였다(참여교실은 아바타 글자를 받지 않는다).
  별명 첫 글자를 쓴다.
- 학생 결과 화면이 이유를 받지 않은 문항에도 "별도로 작성하지 않았어요"를 띄웠다.
- 항목 추가·삭제 단추에 꾸밈이 없어 글자처럼 보였다. `삭제` 가 두 줄로 꺾이기도 했다.
- `ShareEntryCodeBar` 의 `rounded-sp-pill` → `rounded-full`(이 저장소에서 쓰지 않기로 한 클래스).

## 지킴이

- `questionTypeStyle.test.ts` — 목록의 모든 유형과 저장된 모든 옛 유형에 색·아이콘이 있다.
  무리는 다섯이고 서로 다른 색이며, `sp-error`·`sp-muted` 를 침범하지 않는다.
  **클래스 문자열에 투명도 수식(`/숫자`)이 없다.**
- `QuestionResponseSummary.test.tsx` — 가치수직선 평균·좌표, 응답 0건에도 안 깨진다.
- 실제 크롬: 학생 페이지 22건(입력·제출 자료·투표 유무·실행 오류 0건), 교실 화면과
  편집 화면 스크린샷.

## 알려진 한계

- **다크 테마와 나머지 11개 프리셋은 눈으로 확인하지 못했다.** 미리보기 하네스가 설정
  저장소를 띄우지 않아 테마를 바꾸지 못했다. 모든 색을 `sp-*` 토큰으로만 썼고 채운 배경은
  `sp-accent` 로 제한했지만, **오너 실기기에서 다크로 한 번 볼 것.**
- 교실 화면(별도 창)은 Electron IPC가 있어야 뜬다. 임시 하네스로 그림만 확인했다.
