# ADR-089 — 생기부 작성 규정을 나눠 주는 서버 문에 잠금장치를 달고, 못 막는 것은 사실대로 적는다 (2026-09-07)

### 배경

생기부 초안은 "선생님 본인 구독 AI"로만 만든다(ADR-082). 그러려면 작성 규정(1층 프롬프트)이
선생님 PC 의 CLI 까지 평문으로 가야 한다. 규정 본문을 설치파일에 넣으면 압축만 풀어도 읽히므로,
서버 환경변수에 두고 **실행 시점에 받아 메모리에만** 두기로 했다(D7).

그 배급 창구(`ssampin-record-prompt`)를 이번에 점검하다 세 가지를 확인했다. 전부 실측이다.

**① 문이 열쇠조차 없이 열려 있다.** Authorization 헤더를 하나도 붙이지 않고 POST 해도
게이트웨이가 막지 않고 함수 본문까지 도달한다(2026-09-07 실호출, `verify_jwt = false` 확정).
검사는 `installId` 길이 8~64 뿐이고, 저장소의 다른 **14개** 함수가 쓰는 공용 횟수 제한을
이 함수만 쓰지 않고 있었다. 앱 기능은 미출시지만 **엔드포인트는 이미 살아 있다.**

**② 명령줄에는 규정만 실리는 게 아니다.** 코덱스에는 `--append-system-prompt` 가 없어 규정을
사용자 프롬프트 앞에 붙여 **위치 인자**로 보낸다(`ownAiCliRules.ts`). 그 프롬프트 안에는
**선생님이 넣은 학생 근거 본문**이 들어 있고, 이름 가림은 그 반 명단 안에서만 작동한다
(`recordDraftPack.ts`). 즉 **다른 반 학생 이름이 가려지지 않은 채 명령줄에 실릴 수 있다.**

**③ 차단된 요청은 어디에도 기록되지 않는다.** 공용 헬퍼(`_shared/rateLimit.ts`)는 한도를
넘으면 즉시 빠져나가고 insert 를 하지 않는다. 그래서 표에는 통과한 요청만 쌓인다 —
하루 100만 번 때리는 사람도 행이 상한에서 멈춰 **상한에 닿은 큰 학교와 숫자가 같다.**

### 결정

**D1. 한도를 건다.** 설치본 분당 10회·하루 200회, IP 분당 60회. 분당과 하루를 **따로 검사해**
안내 문구를 나눈다("1분 뒤"와 "오늘 다 씀"은 다른 상황이다).

**D2. 한도의 1순위 목적은 수확 방어가 아니다.** 규정은 한 번만 새면 전부 새는 성질이라
작정한 사람은 1회 호출로 끝내고 어떤 한도에도 안 걸린다. 진짜 목적은 **우리 쪽 캐시·루프
사고의 상한과 알람**이다 — 지금 이 창구를 지키는 것은 클라이언트 1시간 캐시 하나뿐이고,
그게 깨지면 학생 30명당 fetch 30회가 나가는데 아무도 모른다. 이 저장소에는 `useState` 이중
클릭 가드가 뚫린 전례가 있다.

**D3. 하루 단위 IP 한도(`dayip:`)는 두지 않는다.** 학교 하나가 회선을 공유하므로(NAT)
24시간 창 상한은 **학교 전체를 종일 막는데**, 공격자는 회선만 바꾸면 그만이다.
`ssampin-assist` 도 같은 이유로 일간 IP 규칙이 없다 — 검증된 형태로 맞춘 것이다.

**D4. 전역 상한도 두지 않는다.** 이 호출은 비용이 0 이라 상한은 예산 보호가 아니라
**공격자가 태워서 전국 선생님의 초안을 끄는 스위치**가 된다.

**D5. 고장 나면 막지 않고 통과시킨다(fail-open).** 횟수를 세는 DB 가 죽었을 때 요청을 막으면
그 순간 **모든 선생님의 초안이 멈춘다.** 지키는 것이 학생 개인정보가 아니라 쌤핀의 노하우
문서이므로, 정상 선생님을 막느니 공격자를 통과시키는 쪽을 고른다. → **오너 승인(2026-09-07).**

**D6. 스위치를 3단으로 만든다.** `off`(한도 블록을 통째로 건너뛴다 — 429 만이 아니라
**DB 왕복까지** 멈추는 진짜 킬 스위치) / `observe`(세기만) / `enforce`(막음). 코드 기본값은
`observe` 이고, **알 수 없는 값이 들어오면 소리를 내고 `observe` 로 간다** — `?? 'observe'`
만으로는 부재만 처리되고 `offf` 같은 오타는 킬 스위치를 무력화한다.

**D7. 운영값은 `enforce` 로 시작한다.** ★계획 초안은 `observe` 로 두고 앱 출시 뒤 전환하자고
했는데, 따져 보니 **두 모드의 관측 데이터가 완전히 같다**(통과도 차단도 양쪽 다 기록된다).
차이는 429 를 돌려주느냐뿐이다. 그런데 이 기능을 담은 앱이 **현장에 0대**이고(v2.4.9 는
2026-09-04 출시, 기능 구현은 그 뒤), 다음 출시본에는 429 를 제대로 안내하는 코드가 함께
들어간다. 즉 `observe` 로 두면 **사는 것 없이 문만 계속 열어 두는** 셈이다. → 오너 결정으로
`enforce` 채택. "작업은 끝났는데 실제로는 아무것도 안 막는" 상태를 만들지 않는다.

**D8. 차단 사건을 따로 기록한다.** 공용 헬퍼가 차단 시 아무것도 안 남기므로(배경 ③),
`endpoint: 'record-prompt-blocked'` 로 한 행을 남긴다. 헬퍼를 `max: 1` 로 재사용해
**IP 당 분당 1행**으로 스스로 묶이게 했다 — 공격자가 로그를 부풀려 표를 터뜨리는 증폭 경로가
생기지 않는다. **새 마이그레이션 0건**(`supabase db push` 는 060 미적용이라 금지).

**D9. 앱은 규정을 못 받아도 멈추지 않는다.** 이전에 받아 둔 값을 **만료 후 24시간까지** 쓴다.
그 뒤에는 멈춘다 — 규정은 학사 기재요령에 매인 문서라 무한정 낡은 것을 쓰면 **폐지된 규정으로
초안을 쓰는 셈**이 된다. ★서버 쪽 fail-open 만으로는 부족하다: 429·500 은 "성공적으로 반환된
응답"이라 서버 try/catch 를 안 타고 클라이언트에서 반 전체 큐를 멈춘다.

**D10. 어느 규정 판본으로 만든 초안인지 남긴다.** 서버는 전부터 판본을 내려보내고 있었는데
앱이 버리고 있었다. `RecordAiDraft.promptVersion` 을 선택 필드로 더한다 — 규정을 고친 뒤
**옛 규정으로 만든 초안을 골라낼 수 있어야** 한다.

**D11. 재시도 폭주를 문구가 아니라 장치로 막는다.** [이어 하기] 버튼은 큐를 **즉시** 다시
부르므로 "1분 뒤에 다시" 라고 써 놓아도 곧바로 눌리면 또 429 가 된다. 한도로 멈춘 경우에만
60초 잠그고 남은 초를 보여 준다.

**D12. 코덱스 세션 파일 잔존은 선생님께 알리지 않는다.**
Codex 로 초안을 만들면 작성 규정과 근거 본문이 `~/.codex/sessions` 에 파일로 남지만
(Codex 가 스스로 남기는 것이라 우리가 못 끈다), **이 사실을 사용자 가이드·앱 고지문에 넣지
않는다.**
→ **오너 결정(2026-09-07):** _"서버에 있는 시스템 프롬프트가 유출되는 건 사용자 문제가 아니라
개발자인 내 문제다."_
→ ★**이 결정은 ADR-084 의 "코덱스 잔존은 사실대로 안내한다"를 뒤집는다. 누락이 아니라
결정이므로 되돌리지 말 것.** 내부 QA 체크리스트에는 그대로 남긴다.
→ 남는 위험은 아래 "여전히 막지 못하는 것"에 그대로 적는다.

**D13. 반면 우리가 새로 시작하는 수집은 반드시 적는다.** 초안을 만들 때마다 쌤핀 서버에
**설치 식별자·접속 IP·시각**이 남는다. 남의 프로그램이 남기는 것과 달리 이건 우리가 만드는
것이고, 접속 IP 는 국내법상 개인정보라 처리방침 항목이다. → `/docs` 와
`landing/src/app/privacy/page.tsx` 양쪽(한국어·영어)에 적었다.

**D14. 명령줄 노출(배경 ②)은 별도 작업 단위로 뺀다.** 되돌리기가 서버는 몇 분인데 앱은
릴리즈 주기라, 한 묶음에 넣으면 그 결함 하나가 빠른 되돌리기를 인질로 잡는다.
**미룬 것이 아니라 나눈 것이다** — 세 갈래 중 **유일하게 학생 개인정보가 걸린 것**이므로
격하하지 않는다. 새 작업의 목표는 "명령줄 노출 줄이기"가 아니라
**"규정 + 학생 근거 본문을 명령줄에서 뺀다"** 이다.

**D15. 어떤 문서에도 "완전 차단"류 표현을 쓰지 않는다.**

### 결과

**좋아지는 것**

- 열쇠 없이 무제한으로 받아 가던 경로가 **닫힌다**(`enforce` 로 배포).
- 캐시가 깨지는 사고에 상한과 알람이 생긴다. 차단·통과·배급량을 SQL 로 볼 수 있다.
- 서버가 이상해도 선생님 화면은 안 멈춘다(만료 캐시 24시간).
- 한도 안내가 원인을 "인터넷"으로 단정하지 않는다. [이어 하기] 가 폭주하지 않는다.
- 500 로그에 함수 이름이 찍힌다(옛 `internalErrorResponse(e)` 인자 1개 버그 수정 — 그동안
  오류가 `undefined` 로 찍혀 배포 후 진단이 불가능했다. `tsconfig.json` 의 `include` 가
  `["src"]` 라 타입 검사가 이 파일을 아예 안 봐서 오래 살아남았다).
- 어느 규정 판본으로 만든 초안인지 남는다.
- 선생님이 **쌤핀 서버에 무엇이 남는지** 알게 된다.

**여전히 막지 못하는 것 (릴리즈 노트 작성 시 반드시 참조)**

- **1회 수확은 여전히 가능하다.** 규정은 한 번만 새면 전부 새는 성질이라 횟수 제한은 작정한
  사람을 막지 못한다.
- **설치 식별자 기준 한도는 사실상 무효다** — 그 값은 앱이 보내는 것이라 공격자가 바꾼다.
  실효 있는 선은 IP 분당 한도 하나뿐이다.
- **하루 몫을 다 쓴 선생님이 재시도하면 학교 공용 분당 몫을 태운다.** 분당을 먼저 검사하기
  때문인데, 순서를 뒤집으면 분당 차단이 24시간 회복인 일간 몫을 태워 더 나쁘다
  (`ssampin-assist` 도 같은 순서다).
- **[이어 하기] 쿨다운은 [AI로 초안 쓰기] 새 시작은 막지 않는다.**
- **코덱스는 계속 `~/.codex/sessions` 에 규정과 선생님이 넣은 학생 기록 본문을 남긴다.**
  우리가 못 끄고, **선생님께 알리지도 않기로 했다**(D12). 그 파일은 백업·PC 교체·수리·공용
  PC 로 따라가며, 다른 반 학생 이름은 가려지지 않은 채 들어 있다. **이 위험은 남는다.**
- claude 명령줄에는 규정이, 코덱스 명령줄에는 **가려지지 않은 타반 학생 이름이 실릴 수
  있다**(D14 로 분리).
- 규정은 설계상 앤트로픽·오픈AI 로 나간다. 그건 기능의 전제다.
- DB 장애 중에는 한도가 없다(fail-open). **그리고 그 상태와 "아무도 안 막힌다"가 기록상 같은
  모양이라**, 함수 로그의 `rate-limit unavailable` 을 함께 봐야 구분된다.

**비용**

통과 1건마다 조회 3 + **INSERT 2문**(분당·일간을 따로 부르므로 한 문이 아니다), 차단 시 기록
1문. 캐시가 1시간이라 정상 호출량 자체는 작다. **다만 최악값을 적어 둔다** — 일간 IP 한도를
없앴으므로 한 IP 의 하루 최대 통과가 86,400 이고, 통과당 3행이라 **하루 최대 삽입이 IP 하나
기준 259,200행**이다. `ssampin_rate_limits` 에는 보존 기간이 없다(후속 3).

### 후속

1. **규정 회전 운영 규칙** — 시크릿 값만 바꾸면 앱 수정 없이 유출된 사본이 낡는다. 다만
   **즉시 발효되지 않는다**: 클라이언트가 서버의 `version` 을 무효화 신호로 쓰지 않으므로
   전파 상한이 **앱 세션 길이 + 24시간(만료 캐시 상한)** 이다. 보안 장치가 아니라
   **감가상각 장치**로만 판다.
2. `scripts/regression-grep-check.mjs` 가 다른 세션에서 풀리면 REGRESSION 규칙 추가
   ("배급은 반드시 `checkRateLimit` 를 지난다"). 지금은 vitest 메타 테스트가 고정한다.
3. **`ssampin_rate_limits` 보존 기간 정리 — 우선순위 상향.** 14개 함수 공용이고, 위 최악값과
   함수 로그의 IP 까지 더해 보존 기간 없는 표면이 늘었다.
4. `ssampin-ai-models` 도 같은 무검증 구조다(길이 검사만). 모델 목록은 비밀이 아니라 범위 밖.
5. 관측에서 **같은 IP 아래 서로 다른 installId 가 하루 50개 이상**이 2일 연속 보이고
   **사람이 시간 분포까지 확인하면** 구글 신원 결합(옵션 B)을 상정한다. ★숫자만으로 자동
   발동시키지 않는다 — NAT 학교 50명과 로테이션 공격자 50개는 같은 서명을 낸다.
6. ~~**(다) 규정 + 학생 근거 본문을 명령줄에서 뺀다**~~ → **완료(2026-09-07, 같은 날).**
   계획서 `.omc/plans/record-draft-codex-argv-20260907.md`, 결과는 아래
   **"후속 6 처리 결과"** 절. 계획이 필수로 잡았던 ⒜~⒠ 다섯 항목을 모두 처리했다.

| codex-cli 0.153.4 | `codex exec … -` + stdin 에 프롬프트                                   | **exit 0 · 6초 · `turn.completed` · 응답 도착** |

★**"stdin 을 닫지 않으면 멈춘다"는 여전히 사실이지만, 이번 경우가 아니다.** 그 실측은 stdin 을
**열어 둔 채 아무것도 안 준** 경우다. 써 넣고 곧바로 `end()` 하면 두 CLI 다 정상 동작한다.
저장소 세 곳의 머리말이 이 구분 없이 "인자로 넘긴다"를 근거로 적혀 있어 함께 고쳤다.

★codex 1차 시도는 사용량 한도로 실패했는데, 그때도 `thread.started` → `turn.started` 는 찍혔다 —
**stdin 은 읽혔다는 뜻**이고 무한 대기도 없었다(3초 종료). 한도가 풀린 뒤 재측정해 완주를 봤다.

### 적용

- **claude — 항상 stdin.** 첨부가 있을 때만 열던 경로(ADR-090)를 **항상**으로 바꿨다.
  명령줄 노출을 없애는 것이 목적이라 첨부 유무와 상관이 없다.
- **codex — 버전 조건부 stdin.** `CODEX_STDIN_MIN = '0.153.4'`(**실측한 버전만 적는다**).
  그 아래는 옛 경로(위치 인자)를 그대로 쓴다 — 구버전에서 `-` 가 프롬프트 **글자로** 읽히면
  조용한 오작동이 되는데, 그건 명령줄 노출보다 나쁘다.
  ★**`OWN_AI_VERSION_FLOOR` 는 올리지 않았다.** 올리면 구버전 선생님이 노출이 남는 게 아니라
  **코덱스를 아예 못 쓰게** 된다.
- **codex 는 규정까지 함께 빠진다.** codex 에는 시스템 자리가 없어 규정을 프롬프트 앞에 붙여
  보내는데, 그 덩어리 전체가 stdin 으로 가기 때문이다. claude 는 규정이
  `--append-system-prompt` 옵션이라 **여전히 명령줄에 남는다**(아래 "남은 것").
- **러너 실행 시간 상한 신설** — `RUN_TIMEOUT_MS = 10분`. 그전에는 상한이 **아예 없어서**
  CLI 가 멈추면 선생님이 [중단]을 누를 때까지 무기한 매달렸다.
- **EPIPE 처리**는 ADR-090 이 이미 넣어 둔 것을 그대로 쓴다.

### 가드 — 빈 곳을 재고 통과하지 않게

`ownAiEgress.test.ts` 는 `commandLineText(buildClaudeArgv(...))` 로 실명을 찾고 있었다.
프롬프트가 stdin 으로 옮겨 가면 **argv 에 본문이 없어서 이유가 틀린 채 항상 통과**한다 —
저장소의 실명 유출 가드가 조용히 무력화되는 모양이다. 그래서:

- `claudeOutbound()` 를 두어 **argv + stdin 메시지 합본**을 재게 했다.
- 새 단언마다 **짝**을 붙였다: "argv 에 없다" 옆에 반드시 **"그래도 stdin 에는 있다"**.
  이게 없으면 "어디에도 없어서" 참인 경우와 구분되지 않는다.
- codex 도 같은 짝으로 고정하고, **두 경로가 같은 글을 보낸다**(조립을 `buildCodexStdinText`
  한 자리에서 한다)를 단언한다.

### 남은 것 (위 "여전히 막지 못하는 것"에 더한다)

- **claude 의 규정(`--append-system-prompt`)은 여전히 명령줄에 있다.** 파일로 넘기는 길
  (`--append-system-prompt-file`)은 **규정을 디스크에 쓰는 것**이라 D7 에 더 나쁘다.
- **codex 0.153.4 미만은 옛 경로 그대로다.** 그 버전에서는 규정·근거 본문이 명령줄에 남는다.
- **코덱스 세션 파일 잔존은 그대로다.** stdin 으로 보내든 argv 로 보내든 코덱스는 대화를
  `~/.codex/sessions` 에 남긴다. D12 대로 사용자에게 알리지 않는다.
