# ADR-101 · 상담 주제는 선생님이 미리 차려 둔다 — 고른 결과는 새 칸이 아니라 잠긴 메모 안으로

- 날짜: 2026-09-09
- 상태: 채택 (구현 완료 · 마이그레이션 073·엣지 함수 운영 적용 완료 2026-09-09, 앱 미출시)
- 관련: 오너 제안(예약자가 상담 주제를 맨손으로 적어야 한다), ADR-060·ADR-095(상담 예약 보안)

## 무엇을 정했나

상담 일정에 **교사가 만든 상담 주제 선택지**(`topicOptions`, 최대 10개)를 둔다. 학부모·학생
예약 화면은 그 목록을 체크 목록으로 보여 주고 **여러 개 고를 수 있다**. 지금까지 있던
직접 적는 칸은 그대로 남는다. 선택지를 하나도 만들지 않으면 예약 화면은 예전과 똑같다.

## 왜 이렇게 했나

### 1. 고른 결과를 담을 **새 DB 칸을 만들지 않는다**

가장 곧은 설계는 `consultation_bookings` 에 `topics` 칸을 더하는 것이다. 하지 않았다.

- 예약자가 무엇을 고르는지는 그 자체로 민감하다. "학교폭력", "가정 형편" 같은 선택지가
  평문으로 서버에 쌓이면, 상담 내용을 종단간 암호화해 온 이유(ADR-060·044)가 절반 무너진다.
- 따로 암호화하려면 `book_consultation_slot` RPC 인자, 엣지 함수 select 목록, 학부모 셀프
  조회 RPC, 로컬 사본 저장까지 **다섯 자리**가 함께 바뀐다. 손댈 곳이 많을수록 한 곳이
  빠진 채로 게이트가 초록일 확률이 올라간다.

그래서 고른 주제는 지금까지처럼 `memo_encrypted` **한 칸 안에** 직접 적은 글과 함께 잠겨서
들어간다. 예약 경로·내보내기·캘린더 추가·이 기기 사본은 **한 줄도 바뀌지 않았다.**

담는 모양은 접두사 한 줄이다.

```
[주제] 학교생활 · 교우관계
요즘 친구 문제로 힘들어하는 것 같습니다.
```

접두사가 없으면 통째로 직접 적은 글이다 — 이 기능 이전 예약이 그렇다. **옛 예약이 그대로
열리는 것이 이 모양을 고른 이유다.**

### 2. 담는 쪽과 푸는 쪽이 다른 프로젝트라 규칙이 두 벌이다

학부모 예약 화면은 별도 Next.js 프로젝트(`landing/`)라 앱의 domain 을 import 할 수 없다.
접두사·구분자가 한쪽만 바뀌면 **선생님 화면에서 고른 주제가 칩이 아니라 `[주제] ...` 글자
그대로 보인다.** 타입도 테스트도 이걸 못 잡는다(두 프로젝트가 서로 모른다). 그래서 두
파일의 리터럴을 회귀 검사 #85-1·#85-2 로 못 박았다.

### 3. 새 컬럼은 anon 이 **자동으로 못 읽는다**

044 가 `consultation_schedules` 의 테이블 SELECT 를 회수하고 **그 시점의 컬럼 목록만** 다시
GRANT 했다(민감 칸 제외 방식). 044 파일 주석은 "앞으로 안전한 컬럼이 추가되어도 자동으로
포함된다"고 적혀 있지만 사실이 아니다 — 컬럼 목록은 마이그레이션이 돌던 순간에 확정된다.

학부모 예약 화면은 로그인 없이(anon) 이 칸을 읽어야 하므로 073 이 **컬럼 단위 GRANT 를
명시**한다(071 이 `crypto_version`·`crypto_salt` 에 한 것과 같다). 빠뜨리면 예약 화면의 일정
조회가 통째로 400 이 되어 "일정을 찾을 수 없습니다"가 뜬다 — 화면 코드는 멀쩡한 채로.

### 4. 배포 순서가 어긋나도 예약은 받는다

PostgREST 는 없는 컬럼을 select 하면 **행이 아니라 400** 을 준다. 마이그레이션보다 랜딩이
먼저 올라가면 예약 화면 전체가 죽는다. 그래서 `getSchedulePublic` 은 실패하면 새 칸을 빼고
한 번 더 부른다. 정상 배포에서는 재시도가 일어나지 않고, 순서가 어긋난 동안에는 선택지만
안 보인 채 예약은 그대로 받는다(회귀 검사 #85-4).

### 5. 교사 화면은 "만들기"와 "수정" 두 곳 모두에서 고칠 수 있다

같은 편집기(`TopicOptionsEditor`)를 두 모달이 함께 쓴다. 화면 하나만 만들면 이미 나눠 준
링크의 주제를 못 바꾼다. 선택지를 비우는 것(`[]`)과 손대지 않는 것(`undefined`)을 구분해,
비우면 서버에서도 지워진다.

## 대안과 기각 이유

- **`consultation_bookings.topics` 평문 칸** — 고른 주제가 서버에 읽히는 채로 쌓인다.
  종단간 암호화 원칙과 정면으로 어긋난다.
- **`topics_encrypted` 별도 암호 칸** — 원칙은 지키지만 예약 RPC·엣지 함수·셀프 조회·
  로컬 사본까지 다섯 자리가 함께 바뀐다. 얻는 것에 비해 깨질 자리가 많다.
- **메모를 JSON 으로 바꾸기** — 옛 예약(평문)과 새 예약(JSON)을 구분하는 판정이 필요하고,
  선생님이 예전 데이터를 직접 열어 볼 때 글자가 아니라 중괄호가 보인다.
- **선택지를 한 개만 고르게(라디오)** — 상담은 보통 여러 이야기를 한 번에 한다. 오너 요청도
  복수 선택이었다.
- **주제를 필수로** — 고를 것이 없으면 아무거나 눌러야 한다. 지금도 주제는 선택 항목이다.
