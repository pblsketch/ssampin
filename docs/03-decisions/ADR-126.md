# ADR-126 — 참여교실 문항 유형을 합치고, 학생별 응답은 교사 화면에만 둔다

- 날짜: 2026-09-21
- 상태: 채택, 로컬 구현 · 미배포 · 오너 실기기 확인 대기
- 관련: [ADR-125](ADR-125.md)(문항 유형으로 만들기)의 유형 목록을 줄인다. 조사 근거는
  [참여교실 격차 분석](../03-analysis/participation-classroom-gap-20260921.analysis.md).

## 발단

오너가 실기기에서 써 보고 다섯 가지를 지적했다. 문항 순서를 바꾸기 번거롭다, 가치수직선·2축
평가·척도가 겹친다, 아이디어 투표와 질문 받기가 겹친다, 교실 화면이 무엇인지 모르겠다,
교사 콘솔이 누가 무엇을 골랐는지까지 보여도 되는가.

## 결정

### 1. 척도·2축 평가·여러 항목 척도를 가치수직선 하나로 합친다

> ⚠️ **이 절의 "2축 평가"(축 2개)는 [ADR-130](ADR-130.md)이 되돌렸다.**
> 가치수직선은 이제 한 줄만 만들고, 두 기준은 새 유형 `2×2 매트릭스`(`quadrant`)가 맡는다.
> 아래 표의 셋째 줄과 `axes`·`:y` 이야기는 기록으로만 남긴다. 척도·여러 항목 척도를
> 가치수직선으로 모은다는 결정은 그대로다.

새 확장 유형 `valueline` 을 두고 **항목 개수 × 기준(축) 개수**로 세 가지를 모두 만든다.

| 만들고 싶은 것    | 설정                      |
| ----------------- | ------------------------- |
| 가치수직선 · 척도 | 항목 1개, 축 1개 (기본값) |
| 여러 항목 척도    | 항목 여러 개, 축 1개      |
| 2축 평가          | 항목 여러 개, 축 2개      |

- 항목이 하나뿐이면 **이름을 비워 둘 수 있다** — 질문 자체를 재는 경우다. 둘 이상이면 이름을 요구한다.
- 양 끝 이름(`xMinLabel`·`xMaxLabel`, 축이 둘이면 `yMinLabel`·`yMaxLabel`)은 **필수**다.
  이름 없는 1~10 눈금은 교실에서 뜻이 통하지 않는다.
- 응답은 항목마다 `<항목id>:x`(축이 둘이면 `:y`도) 칸에 담는다. 축이 하나인데 `:y` 가 오면 거부한다.
- 학생 입력은 숫자 칸이 아니라 **슬라이더**다. 옛 2축 평가·여러 항목 척도가 숫자 칸이라 어려웠다.

### 2. 질문 받기를 아이디어·질문 모으기에 합치고, 투표는 고른다

`brainstorm` 에 `allowVoting` 설정을 둔다. 켜면 지금처럼 공개 후 서로 공감을 누르고,
끄면 모으기만 한다(옛 질문 받기의 쓰임). **설정이 없는 옛 자료는 투표를 받는 것으로 본다** —
옛 아이디어 투표·질문 받기 문항의 동작이 그대로 유지된다.

### 3. 합쳐진 유형은 목록에서 빼되, 저장된 자료는 계속 읽는다

`scale`·`matrix`·`rating`·`qna` 는 **유형 목록(`questionCatalog`)에서 뺀다.** 새로 만들 수는 없다.
도메인 유형·검증·집계·역변환은 그대로 두어 **이미 만들어 둔 활동과 지난 결과는 열리고 진행된다.**
문항 유형 19종 → 15종.

### 4. 학생별 응답은 카훗 방식을 유지한다

교사 콘솔에서만 펼쳐 보고, 교실 화면·학생 화면에는 내보내지 않는다. Kahoot·Pear Deck과 같은 구조다.
대신 `교사 전용 · 교실 화면과 학생 화면에는 나가지 않아요` 를 화면에 적는다 —
선생님이 "이게 애들한테도 보이나?"를 걱정하지 않게 하는 것이 목적이다.

### 5. 교실 화면(별도 창)의 쓸모를 분명히 한다

TV·빔프로젝터용 화면이다. 조작 단추를 두지 않는다. 다음을 지킨다.

- 응답을 받는 중에는 **참여 인원·응답 수·진행 막대**를 크게 보여 준다.
- **정답이 있는 문항의 결과는 받는 중에 그리지 않는다**(정답 유출). 정답이 없는 의견 문항은
  모이는 대로 보여 준다 — Mentimeter처럼 쌓이는 모습이 교실 화면의 쓸모다.
- 공개 뒤에는 **모든 문항 유형의 결과 그림**을 그린다. 공감은 많은 순으로 정렬한다.
- 단추 이름은 `교실 화면 띄우기`, 옆에 `교실 화면 닫기`. 창을 연 직후 지금 상태를 한 번 더 보낸다 —
  대기 화면에서 열면 다음 변화까지 아무 일도 없어 빈 화면처럼 보였다.

### 6. 문항 순서는 끌어서 바꾼다

왼쪽 목록을 끌어놓아 옮기고, 옮긴 문항을 계속 편집한다(보던 자리가 튀지 않는다).
끌기는 마우스만 되므로 **[위로]·[아래로] 단추를 함께 남긴다** — 키보드 사용자의 유일한 길이다.

## 대안과 하지 않은 것

- **`matrix` 에 축 개수를 더해 재사용**: 옛 자료에는 축 설정이 없어 기본값을 2로 봐야 하는데,
  새 문항의 기본값은 1이다. 같은 필드가 자료에 따라 다른 기본값을 갖는 구조는 조용히 틀린다.
  새 유형을 만들고 옛 유형을 얼린 이유다.
- **합쳐진 유형을 자료까지 변환**: 손실 변환이고 되돌릴 수 없다. ADR-125의 "자동으로 덮어쓰거나
  손실 변환하지 않는다"를 따른다.
- **학생별 응답 제거**: 오답을 낸 학생을 찾아 돕는 형성평가 용도가 사라진다. 오너가 카훗 방식을 택했다.
- **활동별 익명 옵션 추가**: 이번에는 넣지 않기로 했다(설정이 하나 늘어난다). 필요해지면 다시 꺼낸다.

## 지킴이

- `advancedQuestionRules.test.ts` — 축 1개는 `:x` 하나만, 2개는 `:x`·`:y` 둘 다 요구. 목록에서
  `scale`·`matrix`·`rating`·`qna` 가 빠졌고 `valueline` 이 있다. 투표를 끄면 학생 payload의
  `allowVoting` 이 false, 설정 없는 옛 자료는 true.
- `ParticipationFlow.test.tsx` — 끌어놓기로 옮기면 목록 순서와 저장 결과가 함께 바뀌고,
  보던 문항이 따라간다. 끝에서는 [위로]·[아래로]가 막힌다.
- `QuestionResponseSummary.test.tsx` — 가치수직선 평균·응답 수·좌표, 응답 0건에도 안 깨진다.
- `participationExpanded.test.ts` — 실제 HTTP/WebSocket으로 확장 입력 9종 연속 제출.
- `QuestionTypeChip.test.tsx` — 아는 유형 전부에 라벨이 있다(개수를 숫자로 박지 않는다).

## 알려진 한계

- 학교망 터널·실제 휴대폰 여러 대 동시 참여·설치본 Electron은 확인하지 않았다.
- 교실 화면(별도 창)은 Electron IPC가 있어야 뜨므로 **실제 창으로는 확인하지 못했다.**
  스냅샷을 만드는 쪽과 그리는 쪽은 자동 검사로만 확인했다.
- 부적절한 응답을 교실 화면에서 지우는 장치는 여전히 없다. 분석 문서의 P0이다.
