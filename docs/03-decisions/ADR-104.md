# ADR-104 · 흐름 보기에 **그래프 조망**을 덧입힌다 — 편집은 레인, 보기는 그래프. 화면 낱말은 주제/흐름

- 날짜: 2026-09-10
- 상태: 채택 (구현·게이트 4종 완료 · 미커밋 · v2.5.2 로 ADR-103 과 함께 출시)
- 관련: ADR-103(흐름 보기 기본·레인 구조·자유 캔버스 기각), 설계 `docs/02-design/features/record-flow-graph-overlay.design.md`,
  오너 요청 "Manyfast 유저 플로우처럼 노드·엣지·섹션 그래프" + 결정 "권고대로 · 서사라는 말은 빼라"(2026-09-10)

## 무엇을 정했나

1. **편집 구조는 ADR-103 그대로**(주제 세로 × 장면 가로 레인, 끌어놓기). 자유 캔버스는 다시 열지 않는다 —
   생기부 초안은 한 줄로 이어지는 글이라 분기 노드·자유 배치는 보기에는 좋아도 쓰기에는 이득이 없고,
   좌표 저장·자동 배치·동기화 충돌이 새로 생긴다.
2. 그 위에 **읽기 전용 그래프 조망**을 덧입힌다: **개요 지도**(주제 노드 · 이음말 라벨 화살표 · 누르면 이동) ·
   **이어진 흐름 섹션**(사슬 묶음, 머리글 + 왼쪽 띠) · **범례**(자리 4색 · 화살표 · 점선). 전부 CSS·단추로 그린다(SVG·캔버스 없음).
3. 편집 보조 셋: **장면 사이 [+]**(저장 배열 인덱스로 끼움) · **[되돌리기]**(장면 이동 · 근거 놓기 · 뼈대 깔기, 토스트 5초) ·
   **AI 흐름 제안 요청 칸**(추가 요청 + 칩 4종 → [제안 받기], 점선 미리보기에 변경 요약).
4. **화면 낱말** — "서사"는 쓰지 않는다(이면의 설계 철학이라 오너가 뺐다). 화면은 **흐름**. 주제/장면/뼈대/이음말/자리 미정/주제 미정 근거.
   "줄기"는 코드·주석과 보드 보기의 「시간순 줄기」에만 남는다. "문단 차례"는 쓰지 않는다 — 생기부는 문단을 나누지 않는다
   (저장 시 `stripNarrativeMarks` 가 공백으로 잇는다, 오너 결정 2026-09-06).
5. 섹션은 **영역이 아니라 사슬**로 묶는다. 주제에는 영역이 저장돼 있지 않아 근거로 추정하면 "왜 이 주제가 여기에"가 된다.

## 왜

오너가 원한 것은 "한눈에 보이는 구조"였고, 그것은 보기의 문제다. 보기만 그래프로 더하면 ADR-103 의 저장 계약(근거 먼저 ·
장면 나중 · 주제 파일 1회 쓰기)과 검사 100여 건을 그대로 지킨다.

## 코드 사실

- `restoreScenes(threadId, scenes)` 를 주제 스토어에 더했다 — 뼈대 깔기 되돌리기는 메모 출처·id 를 보존해야 하므로
  `applyNarrativeDraft`(AI 메모 표식이 붙는다)를 쓰지 않는다.
- 근거 놓기 되돌리기는 놓기 직전 자리(`EvidenceOrigin`)를 표로 적어 두고 같은 자리끼리 묶어 되돌린다.
- [초안 순서] 칩의 이동은 인덱스가 아니라 `data-scene-id` 로 찾는다(사이 삽입 손잡이가 자식으로 끼어들었다).

## 하지 않은 것

자유 캔버스 · 영역별 섹션 · 흐름 판(버전) · Undo 스택 · 여러 장 한 번에 보내기.
