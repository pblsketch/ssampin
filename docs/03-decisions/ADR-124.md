# ADR-124: 멀티설문 v2 라이브에 입장 코드를 다시 보여 준다 (QR 전용 결정을 뒤집음)

- 결정일: 2026-09-18
- 범위: 멀티설문 v2 라이브 콘솔(대기 화면·교실 화면), 공유 창 스냅샷, 입장 코드 발급·변경
- 상태: **구현 완료 · 미출시**. 자동 검사는 전부 통과. 폰 2대 이상이 필요한 실기 확인은 아직 하지 않았다.
- 관련: 2026-06-12 v2 개편 때의 "입장 코드 폐기, QR+URL 전용" 결정을 대체한다.

## 발단

v2 라이브는 학생 입장 경로를 QR과 긴 주소 두 가지로만 안내했다. 코드는 서버에서 발급되는데도
화면에 보여 주지 않고 버렸다(`LiveConsoleContainer` 가 `shortUrl` 만 쓰고 `code` 를 흘려보냈다).

교실에서는 그것으로 충분하지 않다.

- 카메라를 못 쓰는 학생(기기 제한·앱 권한·구형 기기)은 QR 앞에서 멈춘다.
- 긴 주소를 칠판에 적어 주면 학생이 오타를 낸다. 자리에서 화면이 안 보이는 학생도 있다.
- 교사가 "코드 몇 번이에요?"라는 질문에 답할 수단이 아예 없었다.

## 결정

1. **코드를 버리지 않고 상태로 보관한다.** 숏코드 발급 결과의 `code` 를 콘솔이 들고 있으면서
   대기 화면과 교실 화면 상단 배너에 크게 보여 준다. 주소와 코드를 나란히 두지 않고 **분리**해
   표시한다 — 멀리서도 코드만 읽히게 하는 것이 목적이다.

2. **QR을 대체하지 않는다. 두 번째 길이다.** QR·주소 표시는 그대로 두고 코드를 더한다.
   대기 화면의 QR 담당은 `ShareLobbyScreen`, 코드 담당은 `ShareEntryCodeBar` 로 나눈다.

3. **교사가 코드를 기억하기 쉬운 값으로 바꿀 수 있다.** 대기 화면의 입력으로 변경하며
   검증은 기존 `validateCustomCode` 규칙을 **그대로 재사용한다**. 코드 규칙을 새로 만들지 않는다.

4. **코드 발급·변경 실패가 라이브를 막지 않는다.** 인터넷 참여 주소(터널)가 없으면 코드 변경을
   거부하고 이유를 한국어로 알린다. 발급 자체가 실패하면 코드 칸을 숨기고 주소만 안내하며,
   터널·숏코드가 모두 실패하면 기존의 같은 Wi-Fi 주소 폴백이 유지된다. 이 경우에도 라이브는
   시작되고 진행된다.

5. **공유 창(별도 창)에도 코드를 실어 보낸다.** `ShareSnapshot` 에 `entryCode: string | null` 을
   더한다. 별도 창은 스토어를 못 보므로 스냅샷이 유일한 통로이고, 값이 없으면 `null` 로 코드 칸을
   숨긴다. JSON으로 오갈 수 있는 값만 담는다는 스냅샷 규칙은 그대로다.

6. **옛 결정을 가리키는 주석을 남겨 두지 않는다.** `shareSnapshot.ts`·`ClassroomShareView.tsx`·
   `ShareLobbyScreen.tsx` 에 있던 "코드 폐기 — QR+URL 전용" 주석을 현재 동작으로 고쳤다.
   결정이 뒤집혔는데 코드 주석이 옛 결정을 말하고 있으면 다음 사람이 되돌린다.

## 하지 않은 것 · 알려진 한계

- 코드로 들어오는 **전용 입력 화면**은 만들지 않았다. 학생은 여전히 숏코드 주소로 들어온다 —
  코드는 그 주소의 마지막 조각을 말로 전할 수 있게 하는 값이다.
- 코드 중복·선점 처리는 서버(숏링크) 규칙에 맡긴다. 앱에서 재시도 루프를 돌리지 않는다.
- 실기 확인(폰 2대 이상으로 코드 입장, 발급 실패 시 폴백)은 아직 하지 않았다. 출시 전 조건이다.
