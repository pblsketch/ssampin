# ADR-098 · 쌤도구를 별도 창으로 띄운다 — 상태는 "멈추고 담아 넘기고", 소유자는 언제나 한 창

- 날짜: 2026-09-09
- 상태: 채택 (구현 완료, 미출시)
- 관련: [계획](../01-plan/features/tool-popup.plan.md) · [설계](../02-design/features/tool-popup.design.md) · [검증](../03-analysis/tool-popup.qa.md) · [검토](../03-analysis/tool-popup-feasibility-20260908.analysis.md)

## 무엇을 정했나

쌤도구 9종(타이머·랜덤 뽑기·신호등·점수판·룰렛·주사위·동전·QR코드·활동 기호)을
쌤핀 본문 밖 **별도 Electron 창**으로 띄울 수 있게 한다. 창을 옮길 때 진행 중인 시간·입력·
제외 목록·결과가 그대로 따라간다.

## 왜 이렇게 했나

### 1. 창마다 화면을 새로 만드는 것은 "상태 이전"이 아니다

도구의 실행 상태는 화면 안 `useState` 에 있고, Zustand 저장소도 창마다 따로 산다.
새 창에서 같은 부품을 다시 그리면 **처음부터 시작**한다. 그래서 상태를 화면 밖으로 꺼내
넘길 수 있는 **스냅샷 계약**을 만들었다.

### 2. "먼저 멈추고 담는다" — 정지 책임을 계약 함수 안에 둔다

`capture()` 는 순수 함수가 아니다. **돌고 있는 타이머·애니메이션·예약 알람을 먼저 끄고**
상태를 돌려준다. 이렇게 하면 소유자가 없는 짧은 구간만 생길 뿐, 두 창이 동시에 소유자인
구간이 **아예 없다**. 그 결과 같은 타이머가 두 번 끝나거나 알람이 두 번 울리는 일이 구조적으로 막힌다.

호출하는 쪽에 "옮기기 전에 멈추세요"라고 주석으로 부탁하는 방식은 쓰지 않았다.
근거 본문 가리기를 주석 계약으로 뒀다가 실제로 유출된 사고가 있었기 때문이다.

### 3. 시간은 "남은 초"가 아니라 "찍은 시각과 함께" 넘긴다

창을 만들고 화면이 준비되기까지 실제로 2~3초가 걸린다(실측). 남은 초만 넘기면 그만큼
시간이 뒤로 간다. 그래서 스냅샷에 `capturedAt` 을 넣고, 받는 쪽이 흐른 시간을 더해 복원한다.
옮기는 사이에 0에 닿았으면 받는 쪽이 **한 번만** 알람을 울린다.

### 4. 새 창이 "준비 끝"이라고 말하기 전에는 원본을 놓지 않는다

`toolPopup:open` 은 팝업 렌더러가 `markReady` 를 보낸 뒤에야 성공으로 돌아온다.
10초 안에 신호가 없거나 로드가 실패하면 main 이 창을 정리하고 실패를 돌려주며,
본문은 스냅샷으로 원래 실행을 되살린다(흐른 시간 반영). **실패해도 실행이 사라지지 않는다.**

### 5. 도구 하나당 창 하나. 재열기는 기존 창 포커스

같은 도구를 두 창에서 동시에 조작하면 결과가 갈라진다. main 이 `Map<도구, 창>` 으로 강제하고,
이미 팝업으로 열린 도구는 **본문에서 아예 그리지 않는다**(안내 + [창 보기] 만 보여 준다).

### 6. 보안 — 도구 id 는 허용목록으로, 발신 창은 역조회로

내부 화면만 로드하고 `installNavigationGuard` 를 건다. IPC 는 (가) 도구 id 가 domain 허용목록에
있고 (나) 발신 `webContents` 가 앱이 아는 창일 때만 받는다. 본문 복귀 요청의 도구 id 는
**인자를 믿지 않고** 발신 창에서 역조회한다 — 팝업이 남의 도구를 되돌릴 수 없다.

## 하지 않기로 한 것

- 같은 도구를 두 창에서 동시에 조작 / 같은 도구 팝업 여러 개
- 앱 재시작 후 실행 복구 (창 위치·크기 기억도 안 함)
- 병렬 보기 슬롯에서 팝업으로 직접 옮기기 — 후속 범위
- 자리 뽑기·모둠 편성기·칠판·설문/토론/협업 계열 — 큰 화면·학생 연결이 얽혀 별도 설계 필요

## 대가

- 도구마다 `capture`/`resume` 한 쌍을 유지해야 한다. 새 상태를 추가하고 스냅샷에 안 넣으면
  옮길 때 그 값만 조용히 사라진다. 9종 왕복 테스트가 이 실수를 잡는다.
- 마운트 시 상태를 초기화하는 기존 효과 두 곳(`ToolRandom` 의 모드·자료원 초기화, 명단 제외
  초기화)이 **복원한 값을 지워 버려서** 첫 실행을 건너뛰도록 고쳤다. 같은 함정이 다른 도구에
  생기면 왕복 테스트에서 값이 빈 채로 돌아온다.

## 검토에서 되돌아온 것 (설계 보정)

첫 구현은 **팝업 → 본문 복귀 상태를 첫 렌더에만 읽었다.** 본문이 이미 그 도구 화면에 있으면
페이지 값이 바뀌지 않아 화면이 다시 만들어지지 않고, 넘어온 스냅샷이 조용히 버려졌다
(타이머가 05:00 으로 초기화). 게다가 쓰이지 않은 봉투가 보관함에 남아, 나중에 그 도구로
들어가면 이미 끝난 타이머의 **유령 알람**이 울렸다. 검증 시나리오가 하필 본문을 시간표로
옮겼다 돌아오는 경로여서 통과했다.

**보정**: 복귀 봉투를 "마운트 때 한 번"이 아니라 **도착하는 대로** 집는다. 집을 때마다 세대
번호를 올려 도구 화면에 `key` 로 걸어 새로 만든다. 여는 쪽과 같은 "명시적 봉투" 방식으로
양쪽이 통일됐고, 봉투가 즉시 소비되므로 유령 알람도 구조적으로 사라진다.
REGRESSION #75 가 이 왕복을 고정한다.

## 곁가지로 고친 것

**타이머 "시간 종료!" 덮개가 아무것도 가리지 못했다.** `bg-sp-bg/90` 은 `sp-*` 토큰이라
Tailwind 가 규칙을 만들지 않아 완전히 투명했다(실측 `rgba(0,0,0,0)`). 뒤의 7xl 숫자가 글씨와
겹쳐 보였다. 인라인 `var(--sp-bg)` 로 불투명하게 덮고, 밝은 테마에서 대비 미달이던
`text-red-400`(2.13~2.77)을 테마별로 갈리는 `text-sp-error`(3.72 이상)로 바꿨다.
가릴 대상이 같은 자리·같은 크기의 숫자라 **반투명이 곧 겹침**이어서 90%를 살리지 않고 불투명을 골랐다.
REGRESSION **#82** 로 못 박았고 변이 시험으로 검사가 진짜 잡는지 확인했다.
저장소 전체에 퍼진 같은 함정 수천 곳은 자리마다 디자인 판단이 필요해 손대지 않았다.

`PresentationMode` 의 발표자 id 가 `c-${Date.now()}` 라 같은 밀리초에 둘을 더하면 겹쳤다.
발표 순서표가 그 id 로 관리되므로 한 명이 순서에서 사라지고 React key 도 중복됐다.
순번을 붙여 서로 다르게 만들었다(팝업 이관이 순서표를 그대로 옮기려면 반드시 달라야 한다).
