# ADR-131 — 진행을 세 축으로 나눈다: 응답 마감 · 결과 공개 · 정답 공개

- 날짜: 2026-09-21
- 상태: 채택, 로컬 구현 · 미배포 · 오너 실기기 확인 대기
- 대상: 쌤도구 **퀴즈·설문·토론**([ADR-128](ADR-128.md))
- 설계: [participation-classroom-ux.design.md](../02-design/features/participation-classroom-ux.design.md)
- 검증: [participation-classroom-ux.md](../04-report/features/participation-classroom-ux.md)

## 발단

진행 중 교사가 누를 수 있는 단추가 `응답 마감 · 결과 공개` **하나**였다.
그래서 "이제 그만 내세요"만 하고 싶어도 분포가 학생 화면에 곧바로 떴다.
정답이 있는 문항은 정답까지 함께 나갔다.

실화면으로 확인한 결함은 두 가지였다.

1. 마감과 공개를 나눌 수 없다. 생각을 다 모은 뒤 **잠깐 이야기하고** 공개하는 수업이 막힌다.
2. 교실 화면(별도 창)으로 보내는 자료에 **응답을 받는 중에도 정답이 그대로 실려 있었다.**
   화면이 그리지 않을 뿐이었다(`shareSnapshot` 의 `currentQuestion.correctChoiceIds`).

## 조사

같은 일을 하는 도구는 모두 이 셋을 **따로** 둔다 (2026-09-21 공식 문서 확인).

| 제품       | 응답 잠금            | 결과 표시                 | 정답 표시      |
| ---------- | -------------------- | ------------------------- | -------------- |
| Slido      | 자물쇠 아이콘        | 눈 아이콘                 | 체크(객관식만) |
| Wooclap    | 자물쇠               | 그림 단추                 | 체크 단추      |
| Mentimeter | Enable participation | Hide/Show responses (`H`) | —              |

Slido 문서는 "잠긴 설문은 새 투표를 받지 않지만 **결과는 계속 보여 줄 수 있다**"고 못박는다.
잠금과 표시가 서로 독립임을 제품 설명으로 선언한 셈이다.

## 결정

### 1. 진행을 세 축으로 나눈다

| 축        | 저장 위치                      | 뜻                                 |
| --------- | ------------------------------ | ---------------------------------- |
| 응답 잠금 | `LiveSession.phase`            | `open` 받는 중 / `revealed` 마감됨 |
| 결과 공개 | `LiveSession.resultsPublished` | 응답 분포를 학생·교실에 보여 준다  |
| 정답 공개 | `LiveSession.answerPublished`  | 정답·해설을 보여 준다              |

이 셋을 조합한 **파생 단계**를 `domain/rules/participationStage.ts` 한 곳에서 계산한다.
`lobby · collecting · closed · results · answer · finished` 여섯이다.

교사 화면·교실 화면·교실 화면 스냅샷이 각자 조합하면 곧 어긋난다. 실제로 옛 구조에서
"마감"이 곧 "공개"였고 그 틈으로 정답이 샜다.

### 2. `phase: 'revealed'` 의 **뜻만** 바꾸고 이름은 둔다

`revealed` 는 이제 **"응답을 마감했다"** 를 뜻한다(공개 여부와 무관).

이름을 바꾸지 않은 이유는 이 값을 읽는 화면·마이그레이션·테스트가 12개 파일에 걸쳐 있고,
옛 자료(`participationResults` 에 저장된 지난 활동)도 같은 문자열을 갖고 있기 때문이다.
대신 **사람에게 보이는 말**은 `stageLabel()` 한 곳에서 `응답 마감됨` 으로 통일한다.

### 3. 서버에 `closed` 단계를 새로 둔다

`electron/ipc/liveMultiSurvey.ts` 의 `Phase` 를 `lobby | open | closed | revealed | ended` 로 넓힌다.

- `close` → `open`에서 `closed` 로. 이미 마감·공개 상태면 그대로 둔다(두 번 눌러도 안전).
- `publish` → `closed`에서 `revealed` 로 올리고 개인 결과를 갈아 끼운다.
- `advance` · `reopen` 은 `closed`·`revealed` 양쪽에서 받는다.

`closed` 에서 학생 기기로 내려보내는 것은 **문항과 내가 낸 답뿐**이다.
집계·공감 목록·개인 결과는 보내지 않는다.

### 4. 정답을 공개하기 전에는 **자료 자체를** 보내지 않는다

`buildShareSnapshot()` 이 교실 화면 창으로 보내는 문항에서 정답을 도려낸다.

- `correctAnswer` · `solution` · `explanation` 은 **지운다.**
- `correctChoiceIds` · `acceptedAnswers` 는 **빈 배열로 둔다.**
  자리까지 없애면 그 값을 읽는 화면이 터진다 — 실제로 결과 그림이 통째로 하얘졌다.
  (`QuestionResponseSummary` 가 `correctChoiceIds.includes(...)` 로 정답 표시를 고른다.)
- 정답이 있는 문항의 **응답 원문**도 결과 공개 전에는 빈 배열로 보낸다.

정답을 도려내면 `questionHasAnswer()` 로는 더 이상 판단할 수 없으므로
스냅샷에 `currentQuestionScored` 를 따로 실어 보낸다.

### 5. 직선형 절차로 가두지 않는다

- `closed` 에서 곧바로 [다음 문항]으로 갈 수 있다.
- [정답·해설 공개] 전에 [토론 후 다시 답하기]를 할 수 있다.
- [결과 공개]를 건너뛰고 [정답·해설 공개]를 바로 눌러도 된다(정답을 공개하면 결과도 함께 본다).

### 6. 정답을 공개하지 않은 채로 결과만 공개할 때는 **누적 정답 수도 감춘다**

`buildPersonalResults(live, survey, { revealAnswer: false })` 는 이번 문항을 누적에서 뺀다.
1번 문항에서 `1문항 중 1문항 정답` 은 그 자체로 정답을 알려 주기 때문이다.

정답 없이 분포만 공개할 때 학생 화면에는 어느 보기가 정답인지 **표시하지 않은** 분포가 간다.
Slido 의 "잠금 → 결과 표시 → 정답 표시" 순서와 같다.

## 범위 밖 (이 결정에 들어 있지 않은 것)

- 문항 유형 구성·이름([ADR-128](ADR-128.md)·[ADR-129](ADR-129.md)·[ADR-130](ADR-130.md)) — 그대로다.
- 옛 멀티설문 v2 경로(`purpose` 가 없는 설문)는 **건드리지 않는다.** `phase` 하나로 그대로 돈다.
- 문항 제한 시간·부적절 응답 가리기·결과 내보내기는
  [격차 분석](../03-analysis/participation-classroom-gap-20260921.analysis.md)에 그대로 남는다.

## 따라오는 것

- 교사 화면의 진행 단추는 **아래 고정 띠**로 간다. 질문이 길거나 응답이 많아도 밀리지 않는다.
- 교실 화면에 `응답 마감` 이라는 상태가 새로 생긴다.
- 학생 화면에 `응답을 마감했어요. 더 낼 수 없어요.` 단계가 새로 생긴다.
- 공개 가이드(`landing/src/content/docs.ts`)의 `[응답 마감 · 결과 공개]` 안내를 세 단계로 고쳐야 한다.
