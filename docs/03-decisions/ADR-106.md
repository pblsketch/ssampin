# ADR-106 · 근거 정리의 기본 보기는 **근거 지도**다 — 근거끼리 직접 잇고, 연결·화면 위치·글 순서를 따로 둔다

- 날짜: 2026-09-11
- 상태: 채택 → **일부 대체됨(ADR-108, 2026-09-11 실기기 제보)**: 결정 2·8·9(근거끼리 직접 잇기·연결 편집 공간·[연결하기])의 **화면 입구를 없앴다.** 화살표는 장면 단위다.
  자료 계층(`RecordEvidence.links`·저장 관문·요청서 「근거 사이 연결」 분기)은 남아 있으나 화면에서 만들 길이 없다 — 걷어낼지 되살릴지는 오너 판단(ADR-108 §하지 않은 것).
  1차 구현·검사 완료 · 미커밋 · v2.5.2 로 ADR-103~105·107·108 과 함께 출시, 오너 실기기 테스트 뒤
- 대체: ADR-103 결정 1(기본 보기 = 흐름)과 ADR-104 결정 1·2(자유 캔버스를 다시 열지 않는다, 그래프는 읽기 전용 조망)를
  **부분 대체**한다. 장면 배열 = 작성 구성(ADR-103 결정 2~9)과 ADR-104 의 편집 보조(사이 삽입·되돌리기·AI 요청 칸)는 그대로다.
- 관련: 계획 `docs/01-plan/features/record-evidence-canvas-redesign.plan.md`(§1·§4~6·§11), 실행 기록
  `docs/03-analysis/record-evidence-canvas-redesign.execution.md`, 오너 방향 "Manyfast 유저 플로우처럼 근거를 플로우 그래프로 —
  지금은 절반만 구현된 느낌"(2026-09-11) + 교사 난이도 보완(기능 분리·버튼 수·이름), 디자이너 검토(2026-09-11).

## 무엇을 정했나

1. **기본 보기 = 근거 지도**(`recordEvidenceViewMode` 미설정 = `map`). 흐름(주제×장면)·보드(열)는 보기 메뉴에 남고 이미 고른
   보기는 그대로다. 세 보기는 같은 자료를 다르게 본 것이다.
2. **근거끼리 직접 잇는다.** 연결은 앞 근거의 `RecordEvidence.links[]`(뒤 근거 id · 이음말 · 출처)에 산다. 새 파일을 만들지
   않으므로 동기화·백업·보관·학년도 전환이 근거와 같은 축으로 간다. 분기(하나→여럿)·합류(여럿→하나)를 모두 허용하고, 자기 연결·
   같은 쌍 중복·남의 학생·**반대 방향이 이미 있는 쌍**은 저장 관문(`linkEvidence`)이 사유와 함께 거절한다(저장 0회).
3. **세 가지를 분리한다.**
   - 관계(연결): 근거 파일. 주제 소유(`threadId`)와 독립이다 — 다른 주제의 근거와도 잇고, 연결이 소유·본문·장면을 바꾸지 않는다.
   - 화면 위치: **기기별** `localStorage`(자동 배치에 더하는 차이값). 요청서·근거 파일·동기화 어디에도 들어가지 않는다.
     [카드 위치 정돈]은 이 값을 비우는 것뿐이다.
   - 글 순서: 장면 배열(ADR-103) 그대로. 지도에서 [고른 근거 N건으로 초안 쓰기]를 누르면 장면을 얹지 않고 **연결을 따라**
     차례를 정한다(`orderForDraft` — 연결이 없으면 날짜순과 같고, 고리는 날짜순으로 돌리며 그 사실을 화면이 말한다).
4. **읽는 자리에서 가린다.** 상대 근거가 지워졌거나 아직 안 온 연결은 `resolveEvidenceEdges` 가 없는 것처럼 다루고 건수로만
   알린다(지우지 않는다). 지운 근거를 [되돌리기]로 살리면 연결도 돌아온다. 근거 지도·초안 패널·요청서가 전부 이 함수만 본다.
5. **요청서에 연결이 실린다.** 양 끝이 다 실린 연결만 「근거 사이 연결」 줄(`- 1 → 3: 이음말`)이 되고, 설명 없는 연결을 성장·인과로
   단정하지 말라는 지시가 붙는다. AI 가 적은 이음말은 `(AI 가 제안한 설명)` 으로 밝힌다. **연결이 하나도 없으면 요청서는 글자 하나까지
   예전과 같다**(기준선 픽스처 불변). 장면이 있으면 장면 차례가 우선이고 연결 줄은 그 번호를 쓴다.
6. **화면과 요청서가 같은 집합을 본다.** 초안 패널의 「초안에 쓸 근거 N건 · 빠진 M건」·「연결 K건을 따라 차례를 정합니다」는
   요청서 조립과 같은 함수로 센다. 4개 이상이어도 조용히 자르지 않는다.
7. **상단 작업 단추는 셋**: [+ 근거 ▾] · [AI로 정리 제안 ▾](주제 묶기·장면 배치를 한 입구에서) · [고른 근거 N건으로 초안 쓰기 /
   근거 N건으로 초안 쓰기](강조는 이것 하나). 학생 선택·영역 필터·보기 전환·지도 조작(하단 오른쪽: 맞추기·±·정돈·넓게 보기)은 따로 센다.
   연결·주제·장면을 한 번도 손대지 않아도 초안을 만들 수 있다.
8. **오른쪽 보조 공간은 하나.** 고른 근거의 상세(기존 근거 카드 전체 + 이 근거의 연결)와 고른 연결의 이음말 편집이 교대로 든다.
   연결 먼저, 설명은 필요할 때 — 잇고 나면 그 연결이 열려 이음말을 **원하면** 적는다. 칩(변화·뒷받침·다른 모습)은 입력 지름길이다.
9. **키보드 경로**: 카드 둘을 Enter/Space 로 고르고 하단 바 [연결하기]. 손잡이 끌기와 같은 저장 관문이다. 손잡이는 Tab 순서에 없다.
10. **화면 낱말**: 근거 · 주제 · 연결 · 이음말 · 지도. "서사·줄기·노드·엣지·캔버스"는 코드에만 남는다(ADR-104 결정 4 유지).

## 왜

오너가 원한 것은 "근거들을 하나의 플로우 그래프로 시각화"하는 경험이고, ADR-104 의 읽기 전용 조망은 **주제 사이**만 그려 근거 사이의
관계를 만질 수 없었다(계획서 §2 진단). 그렇다고 장면 배열을 버리면 초안 차례를 정하는 유일한 손잡이가 사라지므로, **관계는 지도가,
차례는 장면이** 맡도록 셋을 갈랐다. 연결을 근거 파일에 두면 새 파일이 끌고 오는 잠금 순서·동기화 키·백업·학년도 전환 계약을 새로
짜지 않아도 되고, 위치를 기기에만 두면 동기화 충돌 표면이 늘지 않는다. 화살표는 SVG 하나, 카드는 절대 위치 div 라 새 라이브러리도
없다 — React Flow/ELK 는 검토만 하고 도입하지 않았다(합성 그래프에서 필요한 것은 층 배치와 곡선뿐이었다).

## 코드 사실

- 도메인 `evidenceGraph.ts`: `resolveEvidenceEdges`(가리기·중복 제거·건수) · `linkRejection`(5가지 사유) · `orderForDraft`(Kahn +
  날짜순 동률) · `layerEvidences`(가장 긴 길 층, 고리는 뒤→앞 연결 무시) · `edgesWithin`·`edgesAround`.
- 저장소 `useRecordEvidenceStore`: `linkEvidence` · `unlinkEvidence` · `setEvidenceLinkNote` · `reverseEvidenceLink`. 전부 근거 파일
  1회 쓰기, 못 이으면 저장 0회. 마지막 연결을 끊으면 `links` 칸이 없어진다(옛 자료와 같은 모양).
- 요청서 `recordDraftPack.ts`: `DraftPackEvidence.links` 를 그대로 받아 스스로 푼다. 새 분기(연결 있음·장면 없음)에서만 번호를 매기고
  넘어온 차례를 지킨다(`keepOrder`). 결과에 `linkCount`·`cyclicLinks`.
- 화면: `EvidenceMapView`(묶음 세로 쌓기·층 배치·SVG 화살표·라벨 단추·손잡이 끌기·확대) · `EvidenceMapNode` · `EvidenceMapSidePanel` ·
  `evidenceMapLayout.ts`(순수) · `useEvidenceMapPositions`(localStorage). 놓는 곳 이름표는 보드와 같아 다른 묶음에 놓으면 예전 옮기기,
  같은 묶음이면 자리 밀기(저장 0회).
- 초안 패널: `requestedSelection` 쪽지 → 「고른 근거 N건」 칩, 장면을 얹지 않음, 요청서와 같은 함수로 연결 수·고리 여부를 센다.
- 브릿지 미러: `links` 는 아직 `notMirrored`. 브릿지가 연결을 읽으려면 파서와 계약 표를 함께 고친다.
- 이동 요청 `flow` 모드는 지도에 있을 때 지도에 머문다(보기가 멋대로 바뀌지 않게).
