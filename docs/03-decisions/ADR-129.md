# ADR-129 — 문항 유형을 퀴즈·토론·설문으로 나눠 보여 주되, 모드로 가두지 않는다

- 날짜: 2026-09-21
- 상태: 채택, 로컬 구현 · 미배포
- [ADR-127](ADR-127.md) 1절의 "상호작용 방식 기준 5무리"를 대체한다.
- [ADR-125](ADR-125.md)의 "목적을 먼저 고르지 않는다"는 **유지**한다.

## 발단

오너가 "원래는 퀴즈 모드와 설문·토론 모드로 나눠서 선택해 진행하려 했는데 구현이 안 된 것 같다"고
물었다. 확인해 보니 **구현이 빠진 것이 아니라 ADR-125에서 없앤 것**이었다. `purpose` 필드는
타입에 남았지만 새 활동은 항상 `'activity'` 로만 만들어지고, 목적에 따라 갈리던 코드 세 곳은
실행되지 않는 상태였다.

## 조사한 것

| 도구       | 모드를 먼저 고르나                                                      | 한 활동에 섞을 수 있나                                       |
| ---------- | ----------------------------------------------------------------------- | ------------------------------------------------------------ |
| 띵커벨     | **그렇다.** 퀴즈 8종 / 토의·토론 7종을 먼저 고른다                      | **아니다.** 퀴즈와 토의·토론을 같이 낼 수 없다 — 알려진 한계 |
| Kahoot     | 아니다. 유형을 **지식 확인용 / 의견 수집용 두 묶음**으로 보여 준다      | 그렇다. 공식 가이드가 섞는 흐름을 권한다                     |
| Mentimeter | 아니다. **Quiz Competition 슬라이드**와 일반 Question 슬라이드로 갈린다 | 그렇다. 순위표는 **퀴즈 슬라이드 점수만** 계산한다           |

쌤핀의 현재 규칙(정답이 있는 문항만 채점·점수·순위에 들어가고 의견 문항은 정답률 분모에서
빠진다)은 Mentimeter와 같다. 모드로 가두는 쪽은 띵커벨뿐이고, 그게 한계로 꼽힌다.

## 결정

### 1. 모드 선택 화면은 만들지 않는다 (ADR-125 유지)

활동을 만들 때 퀴즈/토론을 먼저 고르지 않는다. **한 활동 안에서 퀴즈로 확인하고 바로 그 주제로
토론하는 흐름**이 이 도구의 쓸모이고, 쌤도구 카드 설명도 그렇게 적혀 있다.

### 2. 대신 문항 유형 목록을 **퀴즈·토론·설문** 세 묶음으로 나눠 보여 준다

선생님이 실제로 하는 고민이 "지금 퀴즈를 내려는 건가, 의견을 모으려는 건가, 입장을 나누려는
건가"이기 때문이다. 가르는 기준은 **돌려받고 싶은 것**이다.

| 무리                                 | 돌려받는 것                   | 유형                                                                                    | 색           |
| ------------------------------------ | ----------------------------- | --------------------------------------------------------------------------------------- | ------------ |
| **퀴즈** 정답을 맞혀요               | 맞았는지와 점수               | 객관식 퀴즈 · OX · 단답형 · 빈칸 채우기 · 순서 배열 · 이미지 위치 표시 · 숫자 입력·추정 | `sp-accent`  |
| **토론** 입장을 정하고 생각을 나눠요 | 서로 읽고 견줄 글·입장        | 가치수직선 · 2×2 매트릭스 · 신호등 · 아이디어·질문 모으기 · 서술형 · 워드클라우드       | `sp-success` |
| **설문** 의견을 모아 봐요            | 몇 명이 무엇을 골랐는지(분포) | 객관식 투표 · 복수 선택 · 순위 매기기 · 점수 배분                                       | `sp-info`    |

무리 이름 옆에 한 줄 설명을 함께 적는다. 이 색은 편집 화면 문항 목록의 왼쪽 띠에도 흐른다 —
목록만 봐도 퀴즈 문항과 토론 문항이 섞인 모양이 보인다.

### 3. 객관식은 정답을 쓰는 것과 쓰지 않는 것을 **따로 둔다**

`객관식 퀴즈`(`multiple`, 정답 지정) / `객관식 투표`(`single-choice`, 정답 없음).
저장되는 유형 자체가 다르고, 고를 때 하는 고민도 다르다. Kahoot의 Quiz / Poll 과 같다.
**이미 코드에 있던 구분을 화면으로 꺼낸 것**이지 새 유형을 만든 것이 아니다.
추가한 뒤에도 편집 화면의 [정답 사용]으로 서로 오갈 수 있다.

목록은 15개 → **16개**가 된다([ADR-130](ADR-130.md)의 2×2 매트릭스까지 더해 지금은 17개).

### 4. 신호등·옛 가치수직선은 저장 유형이 아니라 본래 무리를 따른다

신호등은 `single-choice` 로, 옛 가치수직선은 `scale` 로 눕지만 `presentation` 을 보고
**토론**으로 분류한다. 저장 형태 때문에 설문 묶음에 끼면 선생님이 못 찾는다.

## 대안

- **띵커벨식 모드 선택(가두기)**: 한 활동에서 퀴즈 → 토론으로 넘어가는 수업을 못 하게 된다.
- **모드를 고르되 기본값만 바꾸기**: 선택이 한 번 더 생기는데 얻는 것이 "기본값"뿐이다.
  같은 효과를 유형 묶음으로 얻을 수 있어 고르지 않았다.
- **ADR-127의 5무리(고르기·적기·자리 잡기·순서 배분·모으기) 유지**: 기준이 *답하는 방식*이라
  선생님의 고민과 맞지 않는다. 두 분류를 함께 두면 색이 두 뜻을 갖게 되어 대체했다.

## 지킴이

- `questionTypeStyle.test.ts` — 무리는 퀴즈·토론·설문 셋이고 색이 서로 다르다. 유형별 소속을
  하나씩 고정한다. 객관식은 정답을 쓰면 퀴즈, 아니면 설문. 신호등은 저장 유형과 무관하게 토론.
  목록의 모든 유형과 저장된 모든 옛 유형에 색·아이콘이 있다.

## 함께 고친 것

- 유형 선택 창이 열릴 때 고른 유형이 목록 맨 위 항목과 어긋나 있었다(기본값이 `single-choice`
  였는데 목록 첫 줄은 객관식 퀴즈). 목록 첫 항목으로 시작하게 했다.
