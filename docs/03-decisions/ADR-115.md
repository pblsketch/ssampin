# ADR-115: 전과목 성적은 학생별 여러 행을 묶고, 확인한 한 파일로 교체한다

- 날짜: 2026-09-13
- 상태: 채택, 로컬 구현, 미배포

## 배경

과목이 가로 열에 있고 한 학생의 점수·성취도·석차등급이 여러 행에 나뉜 일람표를 기존 학생 1행 인식으로 읽지 못했다. 반복 구간을 별도 학생으로 저장하면 앞 과목이 사라지고, 기존 번호 기준 병합은 이전 학급·학기의 학생을 남길 수 있다.

## 결정

1. 여러 행 양식은 별도 도메인 규칙으로 읽고 기존 학생/과목 구조로 정규화한다. 원래의 한 행 양식과 단일 과목 가져오기 경로는 유지한다.
2. 학생 번호·이름과 과목별 값을 확인하며 반복 구간을 합친다. 충돌하거나 성적 행의 학생을 확인할 수 없으면 전체 가져오기를 중단한다.
3. 전과목 가져오기만 성적 시트를 탐색한다. 여러 성적 시트·명시된 여러 학급·학기가 있으면 사용자에게 한 학급·한 학기 파일을 요청한다.
4. 저장 전 파일·시트·학급·학기·학생을 확인한다. 명시적으로 반영하면 현재 성적 전체를 교체한다. 기존 `upsertMany` API는 유지하고 파일 가져오기에는 별도 `replaceAll`을 사용한다.
5. 의미를 확정할 수 없는 점수는 선택 필드 `scoreText`에 원문 보존하고 계산하지 않는다. `합계(원점수)`·`총점(원점수)`로 명시된 복합 셀만 괄호 속 원점수를 읽는다. 성취도에서 등급을 임의 환산하지 않는다.
6. 석차·수강자수·석차등급이 없으면 등급 경계를 계산할 수 없다고 표시한다. 학생 명렬표·수업 관리 점수·외부 동기화는 변경하지 않는다.

## 영향과 제한

- 기존 JSON은 선택 필드가 없어도 그대로 읽는다. 원문 점수도 동일한 로컬 저장 경로를 사용한다.
- 파일 반영은 이전 성적 전체 교체임을 화면과 사용자 가이드에 명시한다. 반영 전 취소는 기존 데이터를 유지한다.
- 실제 사용자 제보 파일과 전체 NEIS 양식 검증은 별개다. 구현 검증은 독립적인 가상 자료와 로컬 실행으로 수행한다.
- 공식 형식으로 확인되지 않은 복합 점수는 원점수 의미를 추정하지 않는다.
