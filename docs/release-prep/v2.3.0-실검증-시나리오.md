## 1. 준비 (10분) — 안전장치와 "마법사 열기"

### 1-1. 백업부터 (모든 시나리오 공통)

앱 실행 → **설정 > 연동·백업 > 백업/복원 > 내보내기** → 파일 저장(바탕화면 등).
이 파일 하나면 무슨 일이 있어도 되돌릴 수 있습니다.

### 1-2. 복사본 환경 만들기 (B·C용)

학년도 마무리는 **실제로 명렬·출결·기록을 비웁니다.** 실사용 데이터로 하지 마시고, 복사본에서 하세요.

PowerShell(또는 터미널)에서:

```powershell
# 1) 실데이터를 격리 폴더로 복사 (원본은 그대로 둡니다)
New-Item -ItemType Directory -Force "E:\github\ssampin\.dev-data"
Copy-Item -Recurse -Force "$env:APPDATA\ssampin\data" "E:\github\ssampin\.dev-data\data"
```

### 1-3. (삭제됨) 마법사 잠금 열기 — **이제 필요 없습니다**

예전에는 학년도 마무리가 2학기에만 되도록 막혀 있어서 설정을 손봐야 했지만, **지금은 언제든 실행할 수 있습니다.**
대신 학년도 중간(1학기)에 실행하면 **한 번 더 확인 팝업**이 뜹니다 — 그 팝업이 제대로 뜨는지가 이번 검증 항목입니다(B-2 참조).

### 1-4. 복사본으로 앱 실행

```powershell
cd E:\github\ssampin
npm run electron:dev:fresh
```

- 처음 실행은 화면이 뜨기까지 **5~6분** 걸립니다(정상).
- 이 창은 `.dev-data` 폴더만 봅니다 — **실사용 데이터는 전혀 건드리지 않습니다.**
- 검증이 끝나면 창을 닫고 `.dev-data` 폴더를 지우면 흔적이 남지 않습니다.

## 2. 시나리오 A — 수업반 보관 (15분, 실사용 데이터 가능)

> 새 학기에 실제로 하시게 될 동작입니다. 이것만은 실사용 데이터로 해 보셔도 좋습니다(되돌리기 쉬움).

### A-1. 한 개 보관

1. **수업 관리** 화면 → 아무 수업반의 **⋮ 메뉴 → 보관**
2. 확인 창이 뜹니다.

**정상**: 확인 창에 ①"출결·진도·기록은 그대로 남고 언제든 다시 볼 수 있어요" ②같은 반의 다른 과목이 있으면 "다른 과목 N개는 계속 활성 상태로 남아요" ③"다른 기기를 먼저 동기화하는 것을 권장" ④"시간표는 따로 갱신해 주세요"가 보임. 버튼은 "보관하기".
→ 보관하면 목록에서 사라지고 **아래쪽 "보관된 수업반 (N개)"** 칸에 학기·교실별로 정리되어 나타남.

**이러면 알려주세요**: 확인 창이 "정말요?" 같은 애매한 문구 / 같은 반의 다른 과목이 같이 사라짐 / 보관 섹션이 안 보임.

### A-2. 보관된 반 열어 보기 (핵심)

보관된 수업반을 클릭.

**정상**: 상단에 **"보관됨 · 2026학년도 1학기"** 배지 + 조회 전용 안내. **출결·진도·기록 탭을 열면 데이터가 그대로 보입니다.** 학생을 눌러 출결을 바꾸려 해도 반응하지 않음(저장 안 됨).

**이러면 알려주세요**: 데이터가 안 보이거나 빈 화면 / 입력이 되어버림 / "알 수 없는 반"으로 표시.

### A-3. 여러 개 한 번에

목록에서 **선택 모드(체크박스)** → 2개 이상 체크 → **"선택한 N개 보관"**.

**정상**: 한 번의 확인으로 전부 보관. 선택 모드에서는 드래그 순서 변경이 잠김.

### A-4. 해제

보관 섹션에서 **보관 해제**.

**정상**: 확인 없이 즉시 활성 목록 **맨 아래**로 복귀 + 토스트("보관함 보기" 액션).

### A-5. 다른 화면에서 숨는지

①자리뽑기·룰렛·모둠 등 **도구의 명렬 선택** ②설정의 **담임 명렬 → 수업반 복사** 대상 목록.

**정상**: 보관된 반이 선택지에 없음. 단, 이전에 그 반을 골라 저장해 둔 도구는 **여전히 그 명단을 보여줌**(선택이 깨지지 않음).

### A-6. 순서 바꿔도 안 사라지는지 (중요)

활성 반들을 드래그로 순서 변경 → 앱을 껐다 켜기.

**정상**: 보관된 반이 그대로 있음. (예전 구조에서는 여기서 사라질 수 있었고, 그걸 막은 수정입니다.)

## 3. 시나리오 B — 학년도 마무리 마법사 (20분, 복사본에서만)

> **준비 1-2~1-4를 마친 복사본 창에서** 진행하세요.

### B-1. 진입

**설정 > 연동·백업 > 학년도 마무리** 탭.

**정상**: "현재 학기: 2026학년도 1학기" + **"학년도 마무리 시작하기"** 버튼이 **바로 눌립니다**(잠금 없음). 학년도 중간이라는 안내 한 줄이 함께 보임.

### B-2. 4단계 살펴보기 (아직 실행 전)

①안내 → ②보관 범위 → ③새 학년도 정보 → ④요약.

**정상**:

- ①에 **무엇이 보관되고(명렬·출결·기록·진도·좌석…) 무엇이 유지되는지(설정·서식·노트·즐겨찾기)**가 구분되어 보임. 상담 기록은 대상이 아니라는 안내.
- ③에서 학교·담임 여부·반·교시를 새로 확인. "지난 학기 수업반 틀 가져오기"는 **기본 꺼짐**.
- ④ 버튼 문구: 지금(1학기)이면 **"2026학년도 1학기를 보관하고 2학기 시작하기"**, 2학기라면 "2026학년도를 보관하고 2027학년도 시작하기".
- Drive 동기화를 쓰는 경우 ④에 **"다른 기기들을 모두 업데이트·동기화했어요" 체크**를 해야 실행 버튼이 열림.

**중간에 창을 닫고 다시 들어가 보세요** → 3단계였다면 3단계로 복귀. 그리고 **여기까지는 데이터가 하나도 바뀌지 않아야 합니다.**

### B-2a. 중간 마감 확인 팝업 (이번에 새로 넣은 것 — 꼭 봐 주세요)

④에서 실행을 누르면, **지금은 학년도 중간이므로 한 번 더 묻는 팝업**이 떠야 합니다.

**정상**: 팝업에 ①"지금은 2026학년도 1학기예요. 보통 2월에 하지만 지금도 가능해요" ②**"출결과 학생 기록은 학년도 단위로 집계돼요 — 지금 보관하면 이번 학년도 통계가 1학기와 2학기로 나뉘어 보입니다(보관함에서는 그대로 볼 수 있어요)"** ③"수업반만 정리하려면 '수업반 보관'이 더 알맞아요" ④"되돌릴 수 있어요"가 모두 보임.
버튼은 **"수업반 보관으로 가기"가 주 버튼**, "그래도 마무리하기"는 눈에 덜 띄는 형태.

- **"수업반 보관으로 가기"를 눌러 보세요** → 팝업·마법사가 닫히고 **수업 관리 화면으로 실제 이동**해야 합니다.
- 다시 들어와 이번엔 "그래도 마무리하기"로 진행.

**이러면 알려주세요**: 팝업 없이 바로 실행됨 / "가기"를 눌렀는데 아무 데도 안 감 / 통계가 나뉜다는 안내가 없음.

> 참고: 2학기(학년도 말)에 실행할 때는 이 팝업이 뜨지 않는 것이 정상입니다.

### B-3. 실행

④에서 실행(중간 마감이면 위 팝업에서 "그래도 마무리하기").

**정상**: 진행이 **1/5 안전 백업 → 2/5 보관 → 3/5 확인 → 4/5 정리 → 5/5 완료**로 표시. 완료 후 담임 명렬·수업반 목록이 비고, 각 빈 화면에 **"2026학년도 기록은 보관함에 안전하게 있어요 [열기]"**가 보임.

**이러면 즉시 알려주세요**: 진행이 중간에 멈추고 아무 안내가 없음 / 완료됐는데 빈 화면에 "데이터가 없습니다"만 뜸 / 보관함에 항목이 안 생김.

### B-4. 되돌리기 (가장 중요)

학년도 마무리 탭 → 보관함 항목의 **"전환 취소(이 시점으로 복원)"**.

**정상**: 확인 후 전환 **전 상태로 완전 복귀**(명렬·출결·기록 모두). 보관 사본은 그대로 남음.

**이러면 즉시 알려주세요**: 일부만 복원됨 / 복원이 실패했는데 원래 데이터도 없음.

**함께 확인**: 복원 확인 창에 ①"복원 후 다시 마무리하면 새 회차로 보관돼요" ②전환 후 새로 입력한 내용이 있다면 **"지금 입력한 내용은 이 복원으로 덮어써져요"** 경고가 보이는지.

### B-5. 되돌린 뒤 다시 마무리하기 (이번에 새로 넣은 것 — 순환 확인)

B-4로 복원한 상태에서 **다시 학년도 마무리를 실행**해 보세요.

**정상**: "이미 같은 학기 보관함이 있다"며 막히지 **않고**, 보관함에 **"2026학년도 1학기 (2번째 보관)"**으로 새 항목이 생김. 1번째 보관본도 **그대로 남아 있고** 각각 따로 열람·복원·삭제됨.

**이러면 알려주세요**: 재마무리가 거부됨 / 1번째 보관본이 덮어써지거나 사라짐 / 회차 표시가 안 보임.

## 4. 시나리오 C — 보관함 열람·삭제 (10분, 복사본에서)

### C-1. 열람

보관함 항목의 **열람** 버튼.

**정상**: 명렬·누가기록·관찰 기록·출결 통계·진도 5개 탭. **관찰 기록의 사진 첨부도 "첨부 보기"로 열림.** 학생 이름 검색 동작. 하단에 "좌석·설문·과제·루브릭·성적 분석도 함께 보관되어 있어요(열람은 준비 중)".

**이러면 알려주세요**: 기록이 비어 보임 / 사진이 안 열림 / 어딘가에 수정·저장 버튼이 보임(있으면 안 됩니다).

### C-2. 삭제 게이트

보관함 항목의 **휴지통 아이콘**.

**정상**: "**2026학년도 2학기 삭제**"를 정확히 타이핑해야 삭제 버튼이 열림. 문구에 **"이 PC의 보관함에서 삭제 / 다른 기기 사본이 다음 동기화 때 다시 내려올 수 있어요"**가 있고 버튼은 "이 PC에서 삭제". 백업 내보내기 링크 제공.

**이러면 알려주세요**: 타이핑 없이 삭제됨 / "영구 삭제·되돌릴 수 없음"처럼 지키지 못할 약속이 있음.

## 5. 시나리오 D — 2기기 Drive 동기화 (40분, **가장 중요**)

> 자동 검증이 닿지 못한 영역입니다. 두 대(또는 PC+폰)가 필요합니다.

### D-0. 안전장치

1. 두 기기 모두 **최신 코드로 실행** 중인지 확인(구버전 혼재는 별도 항목 D-4에서 따로 봅니다).
2. **PC에서 백업 내보내기** 1회(1-1).
3. Drive는 30일간 이전 버전 복구가 가능합니다(Drive 웹 → 파일 우클릭 → 버전 관리).

### D-1. 보관이 다른 기기로 전해지는가

1. **A기기**에서 수업반 하나 보관 → 잠시 대기(또는 수동 동기화)
2. **B기기**에서 동기화 → 수업 관리 확인

**정상**: B에서도 그 반이 보관 섹션으로 내려가 있음.

### D-2. 전환이 다른 기기로 전해지는가 (핵심)

1. **A기기**에서 학년도 마무리 실행(복사본 환경 권장 — 실데이터라면 백업 필수)
2. A에서 동기화 완료 확인
3. **B기기**를 켜고 동기화

**정상**: B의 명렬·수업반도 새 학년도 상태(비어 있음)가 되고, **B에도 "지난 학년도 기록은 보관함에 있어요" 안내**가 보임. 모바일이라면 **"다른 기기에서 학년도 마무리가 실행됐어요 — 지난 기록은 PC의 보관함에서 볼 수 있어요"** 배너가 1회.

**이러면 즉시 알려주세요**: B에 아무 안내 없이 데이터만 사라짐 / B에서 동기화했더니 **A의 작년 명렬이 다시 살아남**(← 가장 중요한 확인 포인트).

### D-3. 작년 데이터가 되살아나지 않는가 (최중요)

1. A에서 전환 완료
2. **B기기를 일부러 전환 전 상태로 두고** 출결이나 기록을 하나 입력 → 동기화
3. **A로 돌아와 동기화**

**정상**: A에 **작년 기록이 유입되지 않음**. A의 새 학년도 데이터가 그대로.

**이러면 즉시 알려주세요**: A의 화면에 작년 학생·출결이 다시 나타남. (이것이 4라운드 QA에서 가장 집요하게 막은 지점입니다 — 실제로 뚫리면 바로 알려 주세요.)

### D-4. 보관함이 새 PC로 따라오는가
