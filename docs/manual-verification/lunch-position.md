# 점심 위치 이동 — 수동 검증 시나리오

본 문서는 "점심 위치 1급 도메인 승격 + 표 내 인라인 위·아래 버튼" PR (DECISIONS.md 참조)
의 회귀 시 사용자가 따라할 수 있는 수동 검증 절차를 기록한다.

## 사전 준비

```bash
cd E:/github/ssampin
npm run dev
```

브라우저가 자동으로 열리지 않으면 `http://localhost:5173` 직접 접속.

## 검증 절차 (13단계)

### 1. 빠른 설정 적용

- [ ] 설정 → 교시 시간 설정 진입
- [ ] [빠른 설정] 토글 → 중학교 선택 → [자동 생성] 클릭
- [ ] 기대: 1~7교시 자동 생성, 4교시 후 점심 12:50~13:40 표시

### 2. 사용자 커스텀 교시 시간

- [ ] 1교시 시작을 08:40으로 변경 (종료는 자동 09:25로 갱신)
- [ ] 2교시 시작을 09:40으로 변경
- [ ] 3교시 시작을 10:40으로 변경
- [ ] 기대: 변경된 시간이 그대로 표 안에 반영

### 3. 점심 위치 한 칸 위로 이동

- [ ] 표 안의 🍱 점심 행에서 [↑] 버튼 클릭
- [ ] 기대:
  - 1·2·3교시 시간이 **한 글자도 안 바뀜**
  - 점심 행 위치가 3교시 직후로 이동
  - 4·5·6·7교시 시작 시간이 정확히 -50분 평행 이동 (기존 점심 길이 50분이라고 가정)
  - 점심시간 카드의 "현재 위치"가 "3교시 후"로 표시

### 4. 점심 위치 한 칸 아래로 이동

- [ ] 점심 행 [↓] 버튼 클릭
- [ ] 기대: 4교시 후로 돌아감, 시간 원복

### 5. 여러 칸 점프

- [ ] [↑] 두 번 연속 클릭 → 2교시 후
- [ ] [↑] 한 번 더 → 1교시 후
- [ ] 기대: 1교시 시간 보존, 2·3·4·5·6·7교시 평행 이동

### 6. 경계 가드 — 위쪽

- [ ] 1교시 후 상태에서 [↑] 시도
- [ ] 기대: [↑] 버튼이 **disabled** 상태 (회색·반투명), 클릭 무반응, hover 시 툴팁 "점심은 1교시 전에 둘 수 없습니다"

### 7. 경계 가드 — 아래쪽

- [ ] 마지막 교시 직전 위치로 이동 (예: 7교시제면 [↓] 연달아 → 6교시 후)
- [ ] [↓] 한 번 더 시도
- [ ] 기대: [↓] 버튼이 disabled, 클릭 무반응

### 8. 점심 길이 0분 가드

- [ ] 점심시간 카드의 lunchStart/lunchEnd를 같은 시각으로 설정 (예: 12:00 ~ 12:00)
- [ ] [↑] 또는 [↓] 버튼 시도
- [ ] 기대: 토스트 메시지 "점심 위치를 옮길 수 없습니다", 위치 불변

### 9. 키보드 접근성

- [ ] Tab 키로 점심 행 포커스 (시각적 ring 표시 확인)
- [ ] ↑/↓ 화살표 키 입력
- [ ] 기대: 마우스 클릭과 동등하게 위치 이동

### 10. 영속성

- [ ] 위치를 3교시 후로 변경
- [ ] 앱 완전 종료(전체창 닫기) → 재시작
- [ ] 설정 → 교시 시간 설정 재진입
- [ ] 기대: 점심 위치 3교시 후 그대로 유지, **마이그레이션 console 로그 0건** (개발자 도구 확인)

### 11. 학급 시간표 ↔ 교사 시간표 — 시간표 페이지

- [ ] 시간표 페이지 진입 → "학급 시간표" 탭
- [ ] 점심 행 위치 확인
- [ ] "교사 시간표" 탭으로 전환
- [ ] 기대: 점심 행이 **양쪽 탭에서 같은 위치**에 표시됨

### 12. 학급 시간표 ↔ 교사 시간표 — 편집기

- [ ] 시간표 편집기 진입 → 학급 모드 점심 위치 확인
- [ ] 교사 모드로 전환
- [ ] 기대: 점심 행이 양쪽 모드에서 같은 위치

### 13. 설정 변경의 위젯 반영

- [ ] 설정에서 [↑]로 점심 위치 변경
- [ ] 시간표 페이지로 이동
- [ ] 기대: 학급/교사 양쪽 탭 모두 변경된 점심 위치 즉시 반영

## 회귀 발생 시

- 어느 단계에서 실패했는지 위 체크리스트에 표시
- 콘솔 에러/경고 캡처
- DECISIONS.md의 ADR 섹션 + `src/domain/rules/periodRules.ts` 함수 시그니처 확인
- `npm run test -- periodRules.test` + `PeriodTab.test` 결과 첨부
