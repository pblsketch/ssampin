## 2. 나이스 실제 모델 분석 (매뉴얼 p28~35)

나이스 일일출결관리(담임용)의 구조는 우리가 만든 것보다 **단순**하다:

- **교시 칸에는 결시 '/' 하나만** 찍는다. 출석은 빈칸. 칸마다 상태를 고르지 않는다.
- **종류(결석/지각/조퇴/결과)와 구분(질병/미인정/기타/출석인정), 사유 텍스트는 학생당 하루 1건** — 행 끝 '마감'란 클릭 → '출결마감구분' 창에서 한 번에 입력.
- '사유'란은 자유 텍스트(감기·늦잠·학교장허가 교외체험학습 등) = **생기부 특기사항의 증빙 보조부**.
- 출석인정 사유는 '/'를 찍지 않고 사유란에만 기록.
- '깨끗이' 모드로 지우기. '사유일괄입력'·'비고 일괄'로 단체 입력.

**결론**: "칸='/'·상태와 사유는 행(하루) 1건" 모델을 차용하되, 나이스의 마감 절차·다단계 창 없이 **팔레트 방식**으로 더 단순화한다(§3). 이 모델은 기재요령 별표 8 §3 바("같은 날 지각·조퇴·결과는 한 가지로만")와도 기존 구현보다 더 정합적이다.

## 3. 확정 설계 — 출결 탭 화면과 인터랙션 (사용자 설계 채택)

### 3.1 화면 구조

```
담임업무 → 기록 탭 서브탭: [출결] [누가기록] [통계] [조회]   ← 기본 = 출결
─ 출결 탭 (전용 전체 화면) ─────────────────────────────
  날짜 내비게이션 (◀ 어제 · 날짜(달력) · 내일 ▶ · 오늘)   ← 기존 DateNavigator 재사용
    └ 오늘이 아니면 날짜 주황 강조 + "(과거)" 배지
  팔레트 바 (상시 표시)
    종류: [결석] [지각] [조퇴] [결과] [지우개]
    사유: [질병] [미인정] [기타] [인정]      비고: [________] (선택)
    현재 선택을 크게 강조 표시 (예: "지각 · 질병")
  도구: [텍스트로 입력] [↶ 되돌리기] [↷ 다시 실행] [오늘 기록 비우기]   저장 상태(자동 저장됨 ✓)
  출결 표 (세로 스크롤, 헤더·번호·이름 고정)
    번호 | 이름 | 조회 | 1교시 … N교시 | 종례 | 구분 | 사유
    ─ 교시 칸: 결시 '/' 표시(색=종류), 출석은 빈칸
    ─ 구분 칸: "지각(질병)" 형식 행 요약
    ─ 사유 칸: 자유 텍스트, 클릭 즉시 인라인 입력
  하단: 교시 합계 행 + 상단 요약 칩(결석 2 · 지각 1 …, 클릭 시 해당 행 하이라이트)
```

### 3.2 입력 규칙 — "팔레트 먼저, 클릭은 기준 교시에"

1. 팔레트에서 **종류+사유(+비고)를 사전 설정**한다. 예: [결석+미인정], [지각+질병].
2. 학생 행의 **교시 칸을 클릭하면 그 교시를 기준으로 즉시 적용**된다 (`computeAutoPeriods` 앵커):
   - [결석] + 아무 칸 클릭 → 그 학생 **전 교시** 결석 (기준 교시 무관)
   - [지각] + 2교시 클릭 → **조회~2교시** 지각 / 1교시 클릭 → 조회~1교시 지각
   - [조퇴] + 5교시 클릭 → **5교시~종례** 조퇴
   - [결과] + 3교시 클릭 → **3교시만** 결과
3. **즉시 적용·자동 저장**: 선택 모드·체크박스·"N명에게 적용" 버튼 없음. 클릭 즉시 행 반영 + 자동 저장(디바운스 ~800ms, 날짜 이동·화면 이탈 시 즉시 플러시, "저장됨 ✓" 상태 표시). 단체 사례(체험학습 20명) = 팔레트 1회 설정 + 학생당 1클릭.
4. **지우개**: 팔레트 다섯 번째 도구. 칸 클릭 = 그 칸만 지움(출석 처리), 이름 클릭 = 그 학생 하루 전체 지움. (나이스 '깨끗이'와 동일 개념)
5. **미세 수정**: 적용 후에도 칸 클릭(같은 팔레트로 기준 교시 재지정)·지우개로 칸 단위 자유 편집.
6. **행당 구분 1건**: 상태·사유·비고는 학생-하루 단위 1건. 저장 시 찍힌 교시들에 행의 status+reason+memo를 기존 per-period 형식으로 fan-out → **저장 구조·동기화·미러·통계 코드 불변**.

### 3.3 텍스트 빠른 입력 (사용자 제안)

출결 탭 도구줄의 [텍스트로 입력] → 패널: 여러 줄 입력 + 규칙·예시 상시 안내 + **줄별 해석 미리보기** + 적용.

- **규칙**: 한 줄 = 학생 한 명. `학생 [교시] [사유] 종류 [비고…]`
  - 학생 = 이름 또는 번호 (동명이인이면 번호 사용 안내). 맨 앞 고정, 나머지 토큰 순서 자유.
  - 교시 = 조회/종례/N교시/N — **결석은 생략**(전 교시 자동), 지각·조퇴·결과는 필수(없으면 그 줄 오류).
  - 사유 = 질병/미인정/기타/인정 — 생략 시 '기타'.
  - 종류 = 결석/지각/조퇴/결과 — 필수.
  - 나머지 단어 전부 = 비고.
- **예시**: `김정민 2교시 질병 지각 감기` / `이서연 조회 미인정 지각` / `4 3교시 미인정 결과`
- 미리보기: `✓ 김정민 — 지각(질병) 조회~2교시 · 감기` / `✗ 3행: 교시가 없어요`. 적용 후 undo 가능.
- 파서 = **도메인 순수 함수 `parseAttendanceQuickText`** + 단위 테스트(정상 3형·순서 뒤섞기·오류 케이스).

### 3.4 되돌리기 / 다시 실행

- 행 단위 변경 이력 스택(세션 내, 최대 50건). [↶]/[↷] 버튼 + Ctrl+Z / Ctrl+Shift+Z.
- 자동 저장 체제이므로 undo/redo도 저장을 다시 트리거한다.
- "변경 초기화"의 의미 재정의: 자동 저장에서는 '저장 전으로'가 무의미 → **"오늘 기록 비우기"(확인 후 전체 지우기)**로 교체.

### 3.5 실수 방지 장치

- 현재 팔레트를 색+라벨로 크게 강조(무엇이 적용될지 항상 보임).
- 적용된 칸에 종류 색·라벨 표기, 방금 적용한 행 1초 하이라이트.
- 잘못 클릭 → Ctrl+Z 한 번으로 복구.

### 3.6 여러 날 출결 — 출결 탭으로 완전 이관

여러 날 출결(입원·체험학습)을 누가기록에 남기지 않고 **출결 탭으로 이관**한다. 이로써 **출결 탭 = 유일한 출결 입력구**가 되어 단일 기록자 원칙이 더 단순해진다(카드 경로 출결 완전 소멸 → 이중 기록자 방어 로직 자체가 불필요해짐).

- 출결 탭 도구줄 [여러 날 입력] → 패널: **팔레트(종류+사유+비고) 그대로 재사용** + 기간(시작~종료, 주말 자동 제외 유지) 또는 여러 날 달력 선택(기존 MultiDatePicker 재사용) + 학생 다중 선택(명단 체크) → 미리보기(N명×M일) → 적용.
- 저장은 기존 fan-out 로직 재사용(스키마·동기화 불변). 명령 팔레트 "여러 날 출결" intent는 출결 탭으로 라우팅 변경.

### 3.7 누가기록 페이지(구 '입력' 탭) 리디자인

출결이 완전히 빠진 뒤의 누가기록은 **관찰·상담·생활 기록 전용**으로 정리한다. 3컬럼 구조(학생 선택 | 분류+메모 | 오늘 기록)는 이 용도에 적합하므로 유지하되, 출결 잔재를 걷어내 가볍게 만든다:

- **중앙 컬럼에서 제거**: 출결 카테고리(유형 칩·교시 칩·사유 칩), 나이스 반영·서류 제출 체크박스(출결 전용이었음), 출결 번호 충돌 Notice, 출결 안내 문구, 출결 단축키(A/L/E/X).
- **유지**: 분류(관찰/상담/생활)+태그, 메모+템플릿, 후속조치, 첨부(관찰), 학생 다중 선택(같은 관찰을 여러 학생에게), 날짜 모드(하루/기간/여러 날 — 비출결 기록에도 유용하므로 존치).
- **우측 '오늘 기록' 리스트**: 출결 미러 기록(att-\*)의 **표시는 유지**(하루 전체 파악용)하되, 출결 항목의 인라인 편집은 제거하고 "출결 탭에서 수정" 이동 링크로 교체 — 출결 편집 경로를 출결 탭 하나로 통일. 관찰·상담·생활은 기존 인라인 편집 유지.
- 탭 라벨 '입력' → '누가기록'.

### 3.8 좌석 배치 뷰 (B안 — 사용자 채택)

출결 탭에 **[명렬 | 좌석] 보기 토글**을 추가한다. 교실 화면(전자칠판·TV)에 띄워 조회 시간에 자리를 훑으며 체크하는 시나리오 대응.

- 좌석 데이터는 자리 배치 도구의 `useSeatingStore`(데스크톱 원본) 재사용 — 단 **렌더 컴포넌트는 신규 제작**(기존 SeatCard·Group/FreestyleSeatingView는 편집 강결합이라 재사용 불가, §3.10-4). 1차는 **grid 레이아웃 우선**(모둠/자유는 후속 확장). 좌석 데이터가 없으면 토글 숨김 + 명렬만.
- **좌석 뷰 입력 = 같은 팔레트**: 좌석 카드 클릭 → 팔레트(종류+사유+비고) 즉시 적용. 단, 좌석에는 교시 축이 없으므로 **지각·조퇴·결과 선택 시 팔레트에 '기준 교시' 선택기가 나타남**(결석·지우개는 불필요). 그리드 뷰에서는 클릭한 칸이 기준 교시(선택기 숨김).
- 좌석 카드에 현재 상태 표시: 구분 라벨("지각(질병)") + 종류 색. 지우개·undo/redo·자동 저장·텍스트 입력은 뷰와 무관하게 동일 동작.
- 보기 선택은 기기별 localStorage 영속(모바일 P2와 동일 패턴).
- 결번·번호 없는 학생 좌석은 비활성 표시. 렌더 게이트(번호 충돌)는 두 뷰 공통.

### 3.9 기존 기능과의 관계

- P5의 선택 모드·일괄 적용 바는 **팔레트로 대체·제거**(같은 목적, 더 적은 품).
- 단일 기록자 메타 가드: "카드=여러 날 전용" 가드에서 → **"InputMode(누가기록)에 출결 입력 경로 부재 + 출결 탭이 유일한 기록자"** 가드로 승계·강화(ADR-018 원칙, 가드 완화 아님).
- 인정 사유 통계 제외(P6)·`computeAutoPeriods`·`summarizeNeisAttendance` 재사용 — 도메인 무변경.
- 기존 데이터(교시별 상이 상태) 로드: `pickRepresentativeAttendance`로 행 구분 요약 표시 + 개별 표기 유지(정보 무손실).

### 3.10 실행 안전·계약 명세 (Planner 코드 검증 반영 — 실행자 필독)

**(1) 자동 저장 ↔ 재시드 안전 프로토콜 (P7.2b 핵심 — 데이터 소실 방지, Architect Synthesis 반영)**

- 현 구조의 함정: `loadDayRecords`가 스토어 스냅샷(`attendanceRecordsAll`)에 의존해 **저장이 끝날 때마다 재시드 effect가 재실행**된다(`HomeroomAttendanceGrid.tsx:124`, `InputMode.tsx:121-127` — "스토어가 이긴다" 주석의 의도된 v1 설계). 자동 저장을 얹으면 그리드 자신이 800ms마다 "외부"가 되어 **플러시 직후의 in-flight 편집이 구버전 스냅샷으로 덮여 사라진다.**
- 해법 (2중 구조 — **dirty-gate가 주, 서명은 보조**):
  1. **dirty-gate (데이터 안전의 주 메커니즘, 결정적)**: 그리드가 **편집 중(dirty)이면 외부 스냅샷 변경으로 재시드하지 않는다**. 자동 저장 하에서 "현재 날짜의 권위는 포커스된 그리드"로 시맨틱 재정의(v1 'store wins'는 수동 저장 전제였음). 날짜 이동·비-dirty 상태의 외부 변경은 기존대로 재시드.
  2. **자기 저장 서명 (보조 — 비-dirty 시 불필요한 matrix 재구성/팝오버 리셋 방지)**: (a) **canonical 투영을 저장측·재시드측 양쪽에 동일 적용** — 비어있지 않은 교시만·교시 정렬·학생 번호 정렬·reason/memo 정규화 (`saveDayAttendance`가 빈 교시를 삭제하므로 보낸 byPeriod와 읽은 records의 형태가 다름에 유의). (b) 단일 슬롯이 아닌 **보류 서명 set**(빠른 연속 저장 경합 대비). (c) 서명 = canonical 투영의 **내용 다이제스트**(카운트류 요약 금지).
  3. **상태 소유**: 자동 저장 타이머·서명 set·undo 스택은 **그리드 컴포넌트 내부**(주입된 `loadDayRecords` 반환값만 사용 — 스토어 직접 import 금지 유지, 메타 가드 5 보존).
- 디바운스 ~800ms + **플러시 3종 필수**: 날짜 이동 · 컴포넌트 unmount · window blur/beforeunload.
- **자동 저장 성공 토스트 금지** — 조용한 "저장됨 ✓" 상태칩으로 대체. 오류만 토스트. 미러는 디바운스로 접혀 "마지막 상태 1회만" write.
- 순서: **P7.2b에서 dirty-gate+서명 구현(과도기에 카드 경로 공존하므로 필수) → P7.3에서 카드 소멸 후 `attendanceRecordsAll` 의존 드롭으로 단순화**.
- 대안 기록: 스토어 write-버전 카운터는 결정적이지만 저장 계층 불변 규율(동기화·미러·모바일이 같은 액션 공유)을 건드려 채택하지 않음 — 서명이 실기기에서 실패하면 재검토할 대안으로 보존.

**(2) undo/redo 스택 규격 (P7.2b)**

- 단위 = **행 스냅샷**(studentKey → 이전 row 전체), 세션 내 최대 50. undo/redo = matrix에 스냅샷 적용 + 자동 저장 트리거(dirty-gate·서명으로 재시드 회피).
- undo/redo 후 dirty·저장 상태·요약 칩 즉시 갱신. "오늘 기록 비우기" = 확인 모달 → 전 행 clear + 저장(빈 교시는 `saveDayAttendance`가 자동 삭제) → undo 스택 1엔트리.
- **런타임 회귀 테스트 필수(메타 테스트로 대체 불가)**: fake timer 컴포넌트 테스트로 ① 저장 플러시 직후 연속 편집 무손실(dirty-gate) ② 플러시 3종 발화 ③ undo→자동 저장→재시드 억제의 일관성 ④ 외부(비-dirty) 변경은 정상 재시드 — 를 실증. P7.2b 완료 기준에 포함.

**(3) 텍스트 파서 계약 (P7.2)**

- 시그니처: `parseAttendanceQuickText(text, roster: {number, name}[], periodCount)` — 순수 함수, **명렬을 인자로**(동명이인 판정).
- 토큰화 우선순위: 첫 토큰=학생(순수 숫자=번호, 아니면 이름; 동명이인 → 줄 오류 "번호로 입력"). 나머지에서 ① 종류(결석/지각/조퇴/결과) 첫 매칭 1개(필수) ② 교시(조회/종례/N교시/순수 N) ③ 사유(질병/미인정/기타/인정, 생략=기타) ④ **남은 토큰 전부 비고**(종류·사유 예약어의 2번째 출현은 비고로 — `김철수 2교시 지각 지각계 제출` 케이스).
- 결석=교시 생략 허용(전 교시), 지각·조퇴·결과=교시 필수(없으면 줄 오류).
- 테스트 표: 정상 3형 + 순서 뒤섞기 + 교시 누락 + 동명이인 + 비고 예약어 포함 + 이름이 '조회'인 학생.

**(4) 좌석 뷰 매핑·범위 계약 (P7.4 — Architect 코드 확인 반영)**

- **id↔번호 매핑 계층 필수**: 좌석은 `student.id`로 저장(`useSeatingStore` — seats/groups/freestyleDesks 전부 id), 출결은 `studentNumber` 식별. `useStudentStore` 명렬로 `Map<studentId, {number, name}>` 구성 → 좌석 클릭(id)→번호→출결 행 적용, 상태 오버레이는 역방향 동일 맵.
- **렌더는 신규 제작(기존 컴포넌트 재사용 불가 — 코드 확인)**: `SeatCard`는 `Seating.tsx` 내부 미export+드래그/편집 강결합+초록 '출석' 점 하드코딩, `GroupSeatingView`/`FreestyleSeatingView`는 스토어 **편집 액션을 직접 호출**(`moveFreestyleDesk` 등). 따라서 **데이터(useSeatingStore)만 재사용**하고 출결 전용 읽기 전용 좌석 카드/레이아웃 컴포넌트를 신규 작성한다. 좌석 편집 함수 미참조(import 부재)로 "편집 호출 0"을 구조적으로 보장.
- **레이아웃 범위 — grid 우선**: 1차 배포는 **grid 레이아웃**(토글은 해당 반 레이아웃이 grid일 때 노출, 모둠/자유 반은 "좌석 보기는 준비 중" 안내). 모둠/자유(특히 freestyle의 정규 좌표→픽셀 기하 복제)는 후속 확장 — 3종 전부는 규모가 L로 확대되므로 분리.
- 비활성 판정: `studentNumber == null || isVacant || 번호 충돌` → 좌석 카드 회색·클릭 무시. 렌더 게이트(번호 충돌)는 두 뷰 공통.
- 좌석 데이터 `loaded` 게이트, 데이터 없으면 토글 숨김. 좌석 뷰 활성화로 명렬 변경 자동 동기화 구독(`useSeatingStore:1071-1075`)이 좌석 write를 유발할 수 있음 — 실렌더에서 "출결 화면 진입만으로 좌석 파일이 바뀌지 않는지" 확인.

**(5) 행 1건 모델 vs 레거시 데이터 경계 (P7.2)**

- **팔레트 클릭·행 사유 편집 = 그 학생 하루 전체 재작성**(찍힌 교시 외 clear, 전 교시 동일 사유·비고). 레거시 교시별 이질 상태는 로드·표시 단계까지 보존(대표 요약+개별 칸 색), **첫 편집 순간 평탄화됨을 수용**(규정상 행당 구분 1건이 원칙이라 정합). 행 사유 편집의 fan-out 대상 = 찍힌 교시 전체.

**(6) 메타 가드 재작성 명세 (2회 수정 — ADR-018 승계·강화)**

- P7.1: 렌더 게이트·미러 순서·교시 단일 출처 가드의 `read('InputMode.tsx')` → `read('AttendanceMode.tsx')` 리타깃. 셸 store 미import 가드 유지.
- P7.3: "카드 출결=dateRangeMode 게이트" 가드 → **"InputMode에 출결 입력 경로 부재(ATTENDANCE_TYPES·attendanceType 쓰기·출결 저장 분기 없음)"** 검증으로 교체, 단축키 가드 삭제, 신규 "출결 입력 컴포넌트는 AttendanceMode 유일" 가드 추가. 각 테스트 주석에 근거(기록자 제거=강화, 완화 아님) 명시.

**(7) 기타 실행 지점**

- DateNavigator: 과거/미래 구분·주황 강조·"(과거)" 배지 확장(다른 사용처 영향 없게 prop 기본값 보존, 또는 AttendanceMode 로컬 래퍼).
- viewMode 마이그레이션 지점: `useStudentRecordsStore`(타입+초기값 'attendance'), **`RecordsTab` 로컬 `type ViewMode`(:14)**·MODE_TABS(:16-20)·prefill 시 setViewMode('input') 유지(:49)·라벨 '입력'→'누가기록'. 초기값 변경으로 **기록 탭 첫 진입 화면이 출결로 바뀜** — 릴리즈 노트 고지.
- 명령 팔레트 "여러 날 출결" intent: 현재 `setIntent+onNavigate('homeroom')`만 수행(`commandRegistry.ts:151-153`) → **`requestHomeroomTab('records')` 패턴(:178-179) 추가** + records viewMode='attendance' 전환 + 여러 날 패널 자동 오픈, intent 소비처 InputMode→AttendanceMode 이동.

**(8) 공유 뷰(AttendanceGridView) 변경 격리 원칙**

- 담임 전용 추가(빈칸화·구분/사유 열·선택 훅)는 전부 **opt-in prop(기본 off)** — 수업관리(`AttendanceMatrixCore.tsx:322-329`)는 prop 미전달로 격리.
- 단, **table-fixed/colgroup은 공유 뷰의 표 골격 변경이라 수업관리 렌더에도 적용된다**(열 폭 균등화 — 개선이나 '무변화'는 아님). P7.1 완료 기준을 "수업관리 화면 무변화"에서 **"수업관리 실렌더로 회귀 아님 확인"**으로 재정의하고, P7.6 실렌더 대상에 수업관리(AttendanceMatrixCore) 화면을 포함한다.
- 행 '구분'·'사유' 열은 뷰가 `<table>` 전체를 소유하므로 셸 주입 불가 → opt-in prop(`reasonColumn`/`onReasonEdit` 등, 기본 off)로 뷰에 추가(기존 '요약' 열 패턴).

## 4. Phase 분할 (커밋 단위, 순차 — 각 단계 게이트+실렌더 후 커밋)

### P7.1 — 페이지 분리 + 표 레이아웃 교정 · 규모 M

- 기록 탭 서브탭 `입력/통계/조회` → **`출결/누가기록/통계/조회`** (기본=출결). 스토어 ViewMode에 'attendance' 추가, 탭 라벨 '입력'→'누가기록'.

- **과도기 명시**: P7.3 전까지 여러 날 출결 카드는 누가기록에 임시 존치(기존 가드 그대로) — 어느 시점에도 여러 날 입력 수단이 사라지지 않게. 릴리즈는 P7.3까지 묶어서.

- 메타 가드(attendanceSingleWriter)를 새 호스트 파일 기준으로 승계 갱신(불변식 동일).
- viewMode 마이그레이션은 §3.10-(7) 지점 목록(스토어 타입·초기값 + RecordsTab 로컬 타입·MODE_TABS·prefill) 전부.
- 완료 기준: 교시 열 균등 정렬·종례 정상 표시, 누가기록 입력부 짤림 없음, 날짜 이동·과거 배지 동작, **수업관리 실렌더로 회귀 아님 확인**(table-fixed가 공유 뷰라 수업관리 열 폭도 균등화됨 — §3.10-8).

### P7.2 — 팔레트 모델 + 텍스트 입력 + undo/자동 저장 · 규모 **L+ (2커밋 분할)**

- **P7.2a — 팔레트+행 모델**: 팔레트 바(종류 5도구×사유 4칩+비고), 칸 클릭=기준 교시 즉시 적용(§3.10-5 전-행 재작성), 지우개, 행 '구분'·'사유' 칸, 5-상태 순환·우클릭 팝오버·이름 클릭 팝오버·선택 모드·일괄 바 제거. (이 커밋까지는 수동 저장 유지)
- **P7.2b — 자동 저장+undo**: §3.10-(1) 자기 저장 억제 서명 + 디바운스/플러시 3종 + 조용한 저장 상태, §3.10-(2) undo/redo 스택, "오늘 기록 비우기". **최대 위험 커밋 — 회귀 테스트(억제 서명·플러시·undo 저장 일관성) 필수.**
- 텍스트 빠른 입력: §3.10-(3) 계약대로 `parseAttendanceQuickText` 도메인 순수 함수+테스트 표, 입력 패널+미리보기.
- 완료 기준: 지각(2교시 등교, 질병) = 팔레트 설정 후 **칸 1클릭**(자동 저장까지), 체험학습 20명 = 팔레트 1회+20클릭, 텍스트 3줄 입력→미리보기→적용 정상, 잘못 클릭 복구 = Ctrl+Z 1회, **fake timer 런타임 회귀 테스트 4종 GREEN(§3.10-2 — 저장 직후 연속 편집 무손실·플러시 3종·undo 일관성·외부 변경 정상 재시드)**, 메타 가드 GREEN.

### P7.3 — 여러 날 출결 이관 + 누가기록 정화 · 규모 M (§3.6·3.7)

- 출결 탭 [여러 날 입력] 패널: 팔레트 재사용 + 기간/여러 날 선택(주말 자동 제외·MultiDatePicker 재사용) + 학생 다중 선택 + N명×M일 미리보기 → 적용. 명령 팔레트 "여러 날 출결" intent 라우팅 변경.
- InputMode(누가기록)에서 출결 완전 제거: 출결 카테고리·유형/교시/사유 칩·나이스/서류 체크·번호 충돌 Notice·출결 단축키·출결 저장 분기. 우측 '오늘 기록'의 출결 항목은 표시 유지 + 인라인 편집 → "출결 탭에서 수정" 링크로 교체.
- 메타 가드 강화: "누가기록에 출결 입력 경로 부재 + 출결 탭이 유일 기록자".
- 완료 기준: 입원 5일(주말 제외)·체험학습 단체가 출결 탭에서 입력됨, 누가기록에 출결 UI 잔재 0, 기존 여러 날 fan-out 저장·미러 동작 동일.

### P7.4 — 좌석 배치 뷰 (B안, §3.8·§3.10-4) · 규모 **M (grid 우선)**

- 출결 탭 [명렬|좌석] 토글(localStorage 영속, grid 레이아웃일 때 노출 — 모둠/자유 반은 "좌석 보기 준비 중" 안내, 좌석 데이터 없으면 숨김).
- 좌석 뷰: **출결 전용 읽기 전용 좌석 카드 신규 제작**(데이터만 `useSeatingStore` 재사용, 편집 액션 import 부재로 구조적 격리) + **id↔번호 매핑 계층**(§3.10-4) + 좌석 카드 클릭 = 팔레트 적용 + 상태 라벨 오버레이.
- 팔레트에 '기준 교시' 선택기 추가 — 좌석 뷰에서 지각/조퇴/결과 선택 시 노출(그리드 뷰는 클릭 칸이 기준이므로 숨김).
- 모둠/자유 레이아웃 렌더(특히 freestyle 좌표 기하)는 **후속 확장**으로 분리(범위 확대 시 L).
- 완료 기준: 좌석 뷰에서 [지각+질병+기준 2교시] 설정 후 좌석 1클릭 = 조회~2교시 질병 지각(자동 저장), 그리드와 상호 전환 시 상태 일치, 번호 없는 재학생 좌석 비활성, 좌석 편집 액션 import 0(가드), 출결 화면 진입만으로 좌석 파일 무변경 확인, 좌석 없으면 명렬만.

### P7.5 — 요약·표시 강화 · 규모 S

- 구분 칸 "지각(질병)" 형식(행 기준) + 사유 텍스트 말줄임·툴팁 — 문제 4·7 마무리.
- 상단 요약 칩(결석 2·지각 1…) 클릭 → 해당 학생 행(좌석 뷰에선 좌석 카드) 하이라이트.

### P7.6 — 실렌더 검증 게이트 · 규모 S

- **커밋 전 실렌더 필수**(이번 문제들은 타입·테스트 게이트로 안 잡혔음): dev 서버 + Playwright로 명단 등록 후 스크린샷 — 열 정렬·팔레트 적용·텍스트 입력·여러 날 패널·좌석 뷰·누가기록 정화·**수업관리 출결 화면(공유 뷰 table-fixed 무회귀 — §3.10-8)**·다크/라이트 확인. 이후 기존 4종 게이트.

### 순서·릴리즈 원자성

`P7.1 → P7.2 → P7.3`은 **한 릴리즈로 묶는다**(과도기 상태를 사용자에게 배포하지 않음). P7.4(좌석 뷰)·P7.5(표시)·P7.6(실렌더)는 뒤따름. 각 단계는 게이트 통과 후 개별 커밋.
