## 1. Overview

### 1.1 Purpose

모바일 앱(`src/mobile/`)에서 (1) 잘못된 하드코딩 데이터를 실제 데이터와 연동하고, (2) 좁은 화면을 효율적으로 쓰며, (3) 6개로 과밀한 하단 탭을 정리하고, (4) 빠른 기록 제스처를 도입하고, (5) PC 없이도 기본 설정을 할 수 있게 한다.

**비평 요약**

- 보고서의 코드 사실관계는 **#4를 제외하면 정확**하다. #4("월간 캘린더 없음")는 사실과 정반대이므로 채택하지 않는다.
- 보고서가 #2를 "치명적 문제"로 규정한 부분은 과장 — 1교시 하드코딩은 R6 회귀를 막기 위한 **문서화된 의도적 결정**이다. 다만 사용자 불편은 실재하므로 "사일런트 자동 매칭"이 아니라 **현재 교시로 기본값을 채우는 교시 선택 드롭다운**으로 푼다(아래 F-2).
- 제안 3.2의 "스와이프 = 즉시 결석 처리" + "점진적 공개로 버튼 숨기기"는 **위험**하다. 좌측 스와이프 한 번에 학생이 결석 처리되는 건 오작동 비용이 너무 크고, 숙련도 추정으로 버튼 affordance를 숨기는 건 발견 가능성을 떨어뜨린다. → **iOS식 "스와이프하면 액션 버튼이 드러나는" 방식**(즉시 실행 X)으로 채택하고, 버튼은 항상 노출 유지.
- 햅틱(`navigator.vibrate`)은 **iOS Safari 미지원** — Android 보조 피드백으로만 취급하고 단독 의존 금지.
- 제안 3.1의 "할 일을 탭에서 빼서 FAB 액션으로"는 재고 필요 — 할 일은 "추가"보다 "조회" 빈도가 높은 표면이라 FAB 뒤로 숨기면 열람이 불편해진다. → **4탭 + FAB**(홈 / 학생 / 일정·할일 / 더보기)로 절충.

## 2. Goals

### 2.1 Primary Goals

1. **데이터 정합** — 모바일에 표시되는 출결 통계·교시가 실제 학급 데이터를 반영한다 (P0).
2. **화면 효율** — 홈 탭에서 자주 안 보는 카드(날씨·급식)를 접거나 숨길 수 있다 (P1).
3. **네비게이션 단순화** — 하단 탭을 6 → 4개 + FAB로 재편해 터치 영역을 넓힌다 (P2).
4. **빠른 기록** — 학생 명단에서 스와이프로 칭찬 메모/지각·결석 액션을 1~2탭에 도달한다 (P2).
5. **모바일 독립성** — 교시 시간 등 기본 설정을 모바일에서도 변경하고 동기화한다 (P2).

### 2.2 Non-Goals

- 데스크톱 앱 UI 변경 (모바일 한정).
- 일정 탭 월간 캘린더 신규 구현 (이미 존재 — 필요 시 개선만 별도 검토).
- NEIS 연동 자동화.
- 위젯/데스크톱 아이콘 모드와 무관.
- 모바일 전용 신규 도메인 기능 추가 (기존 표면의 UX 개선만).

### 2.3 Success Metrics

- `grep -rn "= 30" src/mobile/components/Today/TodayHub.tsx` → 0건 (하드코딩 제거 확인).
- 출결 체크 화면 진입 시 교시 드롭다운 기본값 = 현재 교시(수업 시간대) — E2E 검증.
- 일정 추가 모달에서 시간 입력 후 저장 → 목록·캘린더에 시간 표시 — E2E 검증.
- 하단 탭 4개, 모든 탭/FAB 터치 타깃 ≥ 44×44px (WCAG 2.5.5).
- 학생 명단 좌/우 스와이프 → 액션 버튼 노출, 오작동(즉시 실행) 0건.
- `npx tsc --noEmit` 에러 0개, `npm run lint` 에러 0개 유지.
- iOS PWA(`m.ssampin.com`)에서 safe-area-inset 침범(FAB·탭바가 홈 인디케이터와 겹침) 0건.

## 3. User Stories

- **US-1 (담임)**: 아침에 홈 탭을 열면 출결 요약이 **우리 반 실제 인원수** 기준으로 보였으면 한다. (현행: 항상 30 기준)
- **US-2 (교과)**: 3교시 수업에 들어가 출결 체크를 누르면 **3교시가 기본 선택**돼 있길 바란다. 1교시로 고정돼 매번 바꾸는 게 번거롭다. (현행: period=1 고정)
- **US-3 (담임)**: 종례 후 학교 일정을 추가할 때 "15:00 학부모 상담"처럼 **시간을 같이 입력**하고 싶다. (현행: 모달에 시간 필드 없음)
- **US-4**: 홈 화면에서 우리 학교는 급식이 없어서 **급식 카드를 숨기고 싶다**. 날씨도 평소엔 접어두고 필요할 때만 펴고 싶다.
- **US-5**: 한 손으로 폰을 쥐고 복도에서 **하단 탭을 누를 때 옆 탭이 눌리지 않았으면** 한다. 6개는 너무 빽빽하다.
- **US-6 (담임)**: 명단에서 학생을 **오른쪽으로 슥 밀면 칭찬 메모**, 왼쪽으로 밀면 지각/결석 처리 버튼이 떠서 빠르게 기록하고 싶다. 단, 실수로 결석 처리되면 안 된다.
- **US-7**: PC가 없는 상황에서도 모바일에서 **교시 시간/학급 정보를 한 번은 설정**할 수 있어야 모바일 단독으로 쓸 수 있다.

## 5. Non-Functional Requirements

### 5.1 Performance

- 카드 접기/탭 전환 60fps 유지. 스와이프 제스처는 `transform`만 사용(레이아웃 thrash 금지).
- 모바일 번들 크기 증가 < 15KB gzip (스와이프 라이브러리 도입 시 — 가능하면 무라이브러리 포인터 이벤트 구현).

### 5.2 Accessibility

- 모든 탭/버튼/FAB 터치 타깃 ≥ 44×44px (WCAG 2.5.5, 데스크톱 `IconButton` 정책과 동일선).
- 스와이프 액션은 **대체 경로 필수** — 스와이프 못 하는 사용자는 학생 탭→바텀시트로 동일 작업 가능(이미 존재).
- 드롭다운/토글 `aria-label` 한국어 지정. Undo 토스트 `role="alert"`.

### 5.3 Platform (모바일 PWA 제약)

- `navigator.vibrate` — iOS Safari 미지원. 보조 피드백으로만, 단독 의존 금지.
- `env(safe-area-inset-*)` — notch/홈 인디케이터 대응 필수(FAB·탭바·바텀시트).
- 인앱 브라우저(카카오톡 등) — 기존 [`InAppBrowserBanner`](../../../src/mobile/components/InAppBrowserBanner.tsx) 흐름 깨지지 않게.

### 5.4 Internationalization

- 모든 UI 텍스트 한국어 고정.

## 6. Constraints & Assumptions

### 6.1 Constraints

- Clean Architecture 4레이어 의존성 준수. 모바일은 `@mobile/*` 네임스페이스 + 모바일 전용 store, 도메인 규칙은 `@domain/*` 재사용.
- **`src/mobile/` 외 파일(특히 NEIS Schedule 관련)은 건드리지 않는다** — 다중 세션 병렬 작업 중. 변경 시 명시 path만.
- 디자인 작업은 frontend-design 에이전트와 협업(단독 진행 금지). `rounded-sp-*` 금지, 직각 금지.
- 데스크톱→모바일 단방향이던 설정을 양방향으로 여는 건 Phase 5에서만, 충돌 안전망 동반.

### 6.2 Assumptions

- 1~7교시 범위로 충분(8교시 이상 미지원, 기존 가정 유지).
- 모바일은 단일 사용자, 동기화 충돌은 드물게 발생(first-sync-confirmation 수준 처리로 충분).
- 일정 탭 월간 캘린더는 현행 유지 — 보고서의 "월간 뷰 없음"은 오인이므로 신규 작업 없음.

### 6.3 Out of Scope

- 데스크톱 앱 변경, 위젯/아이콘 모드.
- 일정 주간 스크롤 뷰 신규 추가(월간으로 충분 — 필요 시 별도 PDCA).
- 모바일 도구(설문/체크리스트/과제) 페이지의 UX 개편.
