## 1. 무엇을 만드는가

선생님이 **초안을 어떤 관점으로 쓸지 고르게** 한다. 지금은 고른다는 개념 자체가 없다 —
모든 학생·모든 수업·모든 영역이 같은 골격(교사 평가 → 동기 → 과정 → 결과, 하나의 탐구 흐름)으로 나온다.

세 가지를 따로 고른다.

| 설정          | 뜻                                                                     | 기본값      |
| ------------- | ---------------------------------------------------------------------- | ----------- |
| **작성 초점** | 이 기록에서 무엇을 중심에 둘지 (기존형 + 8종 + 행특용 1종)             | 기존형      |
| **시작 방식** | 글을 무엇으로 여는지 (교사 판단 / 수행·장면 / 질문·문제)               | 교사 판단   |
| **묶는 방식** | 근거 여러 건을 어떻게 잇는지 (대표 장면 하나 / 이어진 과정 / 성취별로) | 이어진 과정 |

여기에 **요소 조정**(초점이 기본으로 주는 항목을 빼거나 더하기), **추가 지시**(자유 문장),
**내 작성 방식 저장**(이름 붙여 저장·불러오기·복제·수정·삭제)을 얹는다.

## 2. 왜 화면만 만들면 안 되는가 — 이 작업의 핵심

같은 순서를 **세 곳이 동시에 요구**하고 있다.

1. **서버 1층 규정**(`RECORD_PROMPT_L1`, 판본 2) — §6 골격·§8 영역별·§9 예시·§11 출력 형식이
   "교사 평가가 맨 앞", "이 순서를 바꾸지 마십시오", "질문 없이 이어 붙이면 실패한 기록"까지 못 박는다.
2. **앱이 매 요청에 붙이는 문장**(`NARRATIVE_MARK_INSTRUCTION`) — `[평가] → [동기] → [과정] → [결과]`
   순서와 첫 문장 어미를 요청 끝에서 다시 말한다.
3. **꾸러미 마지막 줄**(`recordDraftPack`) — "활동을 나열하지 말고 하나의 탐구 흐름으로 이어 주세요."

화면에 고르는 단추만 붙이면 선택은 2·3번과, 나아가 1번과 **정면으로 충돌한다.** 모델은 규정 쪽을 따르므로
결과가 안 바뀌거나(선택이 무의미) 규정을 어긴 글이 나온다(더 나쁘다).

그래서 이 작업은 **공통 규정과 작성 구성을 갈라 놓는 일**이 본체다.

- **공통 규정(서버 1층, 못 끔)**: 사실 창작 금지 · 시점 · 문체 · 관찰 가능한 표현 · 기재 금지 · 하지 말 것 · 마지막 점검.
- **작성 구성(요청서 2층, 선생님이 고름)**: 무엇을 어떤 순서로 쓸지 · 시작 방식 · 묶는 방식 · 요소 · 추가 지시.

1층은 판본 **3**으로 올려 "구성과 순서는 요청서가 정한다"고 넘겨준다. 본문은 저장소에 넣지 않는다.

## 3. 범위

### 이번에 만드는 것

- 초점 카탈로그 10종(기존형 + T1~T8 + 생활·관계 종합)과 요소(모듈) 정의.
- 시작 방식 3종 · 묶는 방식 3종 — 초점과 **독립**.
- 요소 빼기/더하기, 추가 지시.
- 내 작성 방식 저장·불러오기·복제·수정·삭제(설정에 보관, 학생 원문 저장 안 함).
- 실제 적용될 설정 요약 + 근거 부족·조합 충돌 안내.
- 규정 판본 문지기(1층이 판본 3 미만이면 기존형으로 되돌리고 이유를 말함).
- 1층 규정 판본 3 본문 초안(비공개 작업본) + 적용·되돌리기 절차.

### 이번에 안 만드는 것

- 작성 방식 공유·마켓 · 대학별 합격 최적화 · 실제 학생부 예문 수록.
- 교사가 가진 예문에서 문체를 뽑아내는 기능.
- 기존 초안 일괄 재작성(선생님이 손댄 글을 덮지 않는다).
- 쌤핀 AI(Solar)로 초안 쓰기 — 지금처럼 구독 AI 전용을 유지한다.

## 4. 보존해야 할 계약

| 계약                                                                   | 어디서 지키는가                        |
| ---------------------------------------------------------------------- | -------------------------------------- |
| 기재 금지 근거는 **조립 단계에서 빼기**(프롬프트로 막지 않기, ADR-072) | `recordDraftPack` 그대로               |
| 실명·학번 **마스킹은 꾸러미 한 곳**                                    | 추가 지시도 같은 `mask()` 를 통과      |
| 성취기준은 **키워드만**                                                | 그대로                                 |
| 기존 초안·편집 글 자동 덮어쓰기 금지                                   | [반영]은 지금 경로 그대로              |
| 분량은 **앱이 바이트로 판정**                                          | `recordLengthGoal` 그대로              |
| 요청 시작 시 대상 고정(학생·근거·본문)                                 | 실행 시작 시 **작성 방식도 함께 고정** |
| 형광펜 4색·저장 표식·옛 초안 호환                                      | 역할 어휘 4종 유지, **순서만** 가변    |

## 6. 운영 경계 (자동으로 하지 않는다)

- `RECORD_PROMPT_L1` 시크릿 교체 · `ssampin-record-prompt` 재배포 · push · 릴리즈는 **오너 승인 뒤**.
- 코드의 `PROMPT_VERSION` 상수는 3으로 올리되 **배포하지 않는다** — 운영은 계속 2를 돌려주고,
  앱은 판본 3 미만이면 새 구성을 아예 쓰지 않는다. 즉 **승인 전까지 실사용 동작은 오늘과 같다.**
- 되돌리기: 시크릿을 판본 2 본문으로 되돌리고 함수를 판본 2로 재배포하면 모든 앱이 자동으로 기존형만 쓴다.
