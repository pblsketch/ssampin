## 2. 기준 기획서를 뒤집는 지점 — 숨기지 않는다

v0 기획서 §6.1:

> "두 영역은 탭으로 교체하지 않는다. 위젯 영역을 열었다고 메모 영역이 사라지지 않고, 메모 영역을 열었다고 위젯 카드가 메모 목록으로 섞이지 않는다."

이 작업은 **앞 문장의 강도를 낮춘다.** 다만 **탭으로 바꾸는 것은 아니다** — 접힌 칸은 띠로 남아 있고 그 띠가 곧 반대쪽으로 가는 길이다. 뒷 문장(내용이 섞이지 않는다)은 그대로 지킨다.

**왜 뒤집는가**: 손잡이에 버튼이 둘인데 결과가 "넓이 3:2 대 2:3"이면, 사용자가 버튼을 나눠 놓은 이유가 화면에서 되돌아오지 않는다. 오너 판단이다(2026-08-19).

## 4. 화면 설계

### 4.1 접힌 띠

이미 있는 칸 머리말이 그대로 띠가 된다. 새 화면을 만들지 않는다.

```
┌─────────────────┐
│ ▦ 위젯          │
│  오늘 수업      │
│  할일           │   ← 들어온 칸이 화면을 거의 다 쓴다
│  일정           │
├─────────────────┤
│ ▤ 메모       ⌃  │   ← 48px 띠. 누르면 이 칸으로 넘어간다
└─────────────────┘
```

- 띠 자체가 **버튼**이다(한국어 `aria-label`, 키보드 포커스 가능).
- **접힌 동안에는 머리말의 `action` 슬롯을 렌더하지 않는다.** 메모 머리말에는 "새 메모" 버튼이 들어 있어(`SidePinMemoList.tsx:78-84`), 그대로 두면 48px 안에 목표가 둘이 되어 오조작이 난다.
- 접힌 칸의 컨테이너는 `overflow-hidden`이어야 한다(§3-9). **기존 편집 중 접기 경로에도 함께 적용한다.**

### 4.2 규칙 우선순위 — 편집이 먼저다

1. **편집 중**(`memoEditing`/`widgetEditing`) → 지금과 동일하게 **쓰는 칸**이 넓어진다.
2. 편집 중이 아니면 → **들어온 칸**(`activeZone`)이 넓어진다.
3. `activeZone`이 `'both'` **또는 `null`** 이면 → 둘 다 보인다(현행 3:2).

**이 순서가 뒤바뀌면** 메모가 띠로 접힌 상태에서 메모를 쓸 방법이 사라진다. 코드 주석이 이미 "둘 다 접혀 아무것도 안 보이는" 최악을 경고하고 있다(`SidePinPanel.tsx:128-133`).

> **알려진 동작(문서화 대상)**: 마우스가 벗어나 접히면 칸 선택은 초기화된다(`:541`·`:735`·`:755`에서 `activeZone: null`). 다시 열 때는 **그 순간 가리킨 손잡이 절반**이 칸을 정하므로, 메모 버튼 위에서 다시 열면 메모가 다시 커진다. 3:2로 돌아가는 경우는 **끌기 자리에서 열 때와 `Ctrl+Alt+P`로 열 때** 둘뿐이다. 직전 칸을 기억하는 장치(`lastEntryZone`)는 **도입하지 않는다** — 그 값이 발동하는 구간이 정확히 "앱이 대신 고르지 않기로 한" 구간이고, 접힘 사고가 4회 난 코드를 건드리는 비용이 이득보다 크다.

### 4.3 고정(📌) — 신규 기능이 아니라 기존 결함 수리

**지금도 이미 깨져 있다.** 손잡이 메모 버튼을 클릭하면 `pinnedZone='memo'`가 되는데(§3-12), 패널 헤더 라벨은 `pinnedZone !== 'none'`만 보고 "고정 해제"라고 쓴다(`SidePinPanel.tsx:123,164`). 그런데 그 버튼은 `'both'`를 보내고, 해제 조건은 `state.pinnedZone === zone`이라(`:780`) 첫 누름은 **해제가 아니라 `'both'`로 재고정**된다. 정확히는 **한 번에 못 풀고, 한 번은 반대로 간다**(두 번째 누름은 `'both' === 'both'`가 되어 풀린다).

**★그리고 이 결함은 Step A가 증폭한다.** 같은 분기가 `activeZone: zone`도 함께 실행하므로(`:790-806`), 헤더 버튼이 `'both'`를 보내는 한 **누르는 순간 칸 선택이 통째로 풀려 3:2로 튄다.** Step A 이후에는 "한 칸을 크게 보다가 고정 해제를 눌렀더니 화면이 반으로 갈라진다"가 된다. 그래서 §4.3은 선택 항목이 아니라 **Step A의 일부**다.

**라벨만 고쳐서는 안 된다** — `SidePinPanel.tsx:166`의 `onTogglePin('both')` 하드코딩을 **지금 칸을 넘기도록** 함께 바꿔야 아래 표가 성립한다.

규칙을 못박는다.

| 지금 상태                | 버튼 라벨                                                   | 누르면                                                           |
| ------------------------ | ----------------------------------------------------------- | ---------------------------------------------------------------- |
| `pinnedZone === 'none'`  | `고정` (칸이 지정돼 있으면 `위젯 고정`/`메모 고정`)         | 지금 칸을 고정                                                   |
| `pinnedZone === 지금 칸` | `고정 해제`                                                 | 해제                                                             |
| `pinnedZone !== 지금 칸` | `위젯 고정` / `메모 고정` (**"고정 해제"라고 쓰지 않는다**) | 고정을 지금 칸으로 옮긴다 (`:790-806`이 이미 그렇게 구현돼 있다) |

## 8. 하지 않는 것

- **포인터 구역 분할(`panel-memo` 신설)** — `entryZoneOf`는 **패널이 없을 때만** 호출되므로 `'panel-*'` 값에는 이 기능의 소비자가 없다(`sidePinPointerRegion.ts:45-47`). 나머지 소비처는 "안이냐 밖이냐"만 본다(`SidePinRuntimeState.ts:181-183`). 게다가 렌더러가 보내는 구역 값은 메인이 **버리고 실제 커서를 다시 읽는다**(`main.ts:3105`, 50ms 폴링 `sidePinElectron.ts:127`). 구역을 쪼개면 패널 안에서 칸을 지날 때마다 `pointer-region-changed`가 새로 발생해 **옆핀의 접힘/펼침 타이밍 전체**에 영향을 준다 — 이 패널의 사고 4회가 모두 그 계열이다. **다음 세션이 같은 함정을 다시 파지 않도록 여기 남긴다.**
- **다른 칸을 완전히 숨기기** — 전환 버튼을 헤더로 올리는 순간 탭이 되어 §2의 뒷 문장까지 무너진다.
- **창 높이를 칸 하나 크기로 줄이기** — 창 기하·모니터·배율 계산이 얽힌다. v2.4.1~2.4.2에서 반복 사고.
- **직전 칸 기억(`lastEntryZone`)** — §4.2 인용 참조.
- **접힌 칸 지연 렌더** — 이득이 불확실한데 접힘/펼침이 튈 위험이 크다.
- **`Ctrl+Alt+P`의 의미 바꾸기** — 지정이 없을 때 양쪽을 여는 것은 의도된 규칙이다.

- **접힌 칸의 본문을 들어내지 않고 감춘다**(`hidden`). 들어내면 그 칸이 다시 만들어져 **스크롤 위치·메모 검색어·열어 둔 위젯이 초기화**된다. 메모를 쓰는 동안 위젯 칸이 접히는 기존 동작에도 같은 문제가 있어 함께 막았다.

**검증** — `tsc` 0 · `lint` 0 error(경고 135, 기존) · 옆핀 테스트 **11파일 171건 통과**(신규 `sidePinZoneLayout.test.ts` 10건 포함) · `regression-check` 43/43 · `npx tsc -p tsconfig.electron.json --noEmit` 오류 **264건으로 변경 전과 동일**(이 설정은 원래 기준선 오류가 많아 개수 비교로 본다).
