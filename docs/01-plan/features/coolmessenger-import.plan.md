## 0. 배경 한 문단

교사는 쿨메신저 쪽지로 "7월 21일(화) 14:00 학폭위 심의" 같은 업무 연락을 하루에도 여러 건
받는다. 그걸 일정에 옮기는 건 순전히 손일이다. `coolm-helper`는 쪽지함 파일을 직접 읽어
날짜·시간을 규칙으로 뽑아내 일정으로 등록해주는 윈도우 프로그램이고, 쌤핀 사용자와 대상이
정확히 겹친다. **쌤핀에는 이미 일정(`SchoolEvent`)·할일(`Todo`)·개인정보 마스킹
(`domain/privacy/maskEngine.ts`)이 다 있어서, 붙일 자리가 이미 마련되어 있다.**

이 기능은 **AI를 전혀 쓰지 않는다.** 전부 글자 패턴 규칙(정규식)이라 API 비용이 0원이고
인터넷 없이 동작한다 — "선생님이 AI 비용을 내지 않을 것"이라는 원칙과 정면으로 맞는다.

## 2. 확정된 범위 (2026-08-21 오너 결정)

| 항목      | 결정                                               | 이유                                                                                                                   |
| --------- | -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 1차 범위  | **핵심만** — 쪽지 목록에서 골라 등록               | ⚡간편 등록(pywinauto)은 쌤핀에 없는 도구라 재작성 비용 2배 + 쿨메신저 창 구조 의존으로 잘 깨짐                        |
| 진입 위치 | **일정·할일 화면 안 "쿨메신저에서 가져오기" 버튼** | 일정을 등록하려는 맥락에서 바로 손이 닿음                                                                              |
| 기본값    | **꺼짐. 설정에서 켬**                              | **쿨메신저를 안 쓰는 시도교육청이 많다.** 안 쓰는 선생님께 버튼이 보이면 안 됨                                         |
| 등록 대상 | **일정·할일 둘 다**                                | 원본 파서가 이미 `is_deadline`을 구분한다. "제출/마감/기한"은 할일로, 나머지는 일정으로 추천하고 사용자가 바꿀 수 있게 |

### 기각된 안

- ⚡**간편 등록** (현재 열린 쿨메신저 창 읽기) — 1차 제외. 쌤핀엔 `koffi`가 있어 불가능하진
  않으나, 핵심 기능이 실사용 검증된 뒤에 재검토한다.
- **안내문구 보정** (`proofread.py`, Gemini 사용) — **영구 제외.** 원본에서 AI 비용이 드는
  유일한 부분이며, 쌤핀 원칙과 충돌한다.
- **구글 캘린더 연동** (`calendar_sync/`) — 불필요. 쌤핀은 이미 갖고 있다(OAuth 심사 통과).

## 3. 기술 검증 — 이미 끝난 것

가장 큰 위험은 "SQLite 파일을 읽으려면 무거운 부품을 새로 설치해야 하나"였다. **아니었다.**

쌤핀의 Electron 43은 Node 24를 품고 있고, **Node 24에는 SQLite 읽기가 기본 내장**되어 있다.
실제 쌤핀 Electron으로 실행해 확인했다:

```
$ npx electron /tmp/eltest.js
NODE: 24.18.1 ELECTRON: 43.4.1
node:sqlite OK -> DatabaseSync,StatementSync,Session,constants,backup

$ npx electron /tmp/eltest2.js     # 쿨메신저 스키마 흉내 + 쿨메신저 실행중 상황 재현
READONLY OK -> [{"Title":"학폭위","MessageText":"7월 21일(화) 14:00 회의"}]
```

**의미**: 새 의존성 0개. 설치 파일이 무거워지지 않고, 네이티브 모듈 재빌드
(`electron-rebuild`)도 필요 없다. `better-sqlite3` 도입은 **불필요하다.**

### 알아낸 사실 (원본에서 확보 — 이게 진짜 값어치)

| 항목           | 값                                                                                                                            |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 쪽지함 위치    | `%LOCALAPPDATA%\CoolMessenger\Memo\*.udb` (가장 최근 수정된 것 선택)                                                          |
| 받은 쪽지 표   | `tbl_recv` — `MessageKey, Sender, ReceiveDate, Title, MessageText, IsUnRead, DeletedDate`                                     |
| 교직원 명단 표 | `tbl_member` — `MemberName` (개인정보 탐지 사전으로 재활용)                                                                   |
| 날짜 형식      | `2026/07/16 17:04:52 (목)`                                                                                                    |
| 안전 규칙      | **원본을 쓰기 모드로 절대 열지 않는다.** `.udb` + `-wal` + `-shm` 세 파일을 임시 폴더에 복사한 뒤 복사본을 읽기 전용으로 연다 |

## 4. 파서 이식 시 반드시 살릴 함정 (원본이 실사용으로 알아낸 것)

기계적으로 옮기면 놓치는, **실제로 쪽지를 많이 받아본 사람만 아는** 규칙들이다:

1. **기준일은 오늘이 아니라 쪽지 받은 날**이다. 지난주 쪽지의 "내일"은 지난주 기준이어야 한다.
2. `2. 3` 같은 **목록 번호**, `1-2교시` 같은 표현을 날짜로 오인하지 않는다
   → `.`/`-` 구분자에 연도가 없으면 요일 `(화)`나 `일` 표기가 있어야만 날짜로 인정.
3. **연도 생략 시** 기준일에서 30일 이상 과거면 이듬해로 해석한다.
4. `1:` 같은 조각을 시간으로 오인하지 않는다 → `:` 형식은 분까지 있어야 인정.
5. 개인정보 이름 탐지의 **오탐 방지 사전** — `위기학생`·`전입학생`의 앞부분을 이름으로 잡지
   않도록 `NAME_STOPWORDS` 30여 개를 유지한다.
6. **개인정보는 자동으로 지우지 않고 빨간 글씨로 표시만 한다.** 지울지는 사용자가 결정.
   원본 README: _"사람 눈이 마지막 방어선입니다."_ — 이 판단을 그대로 따른다.

## 5. 레이어 배치 (아키텍처 규칙 준수)

> ⚠️ **이름 주의** — `domain/rules/koreanDateParser.ts` 는 **이미 있는 다른 기능이다**
> (할일 빠른입력 `parseQuickInput`, `Todo.tsx`가 쓴다). 이름이 비슷해 헷갈리기 쉬우니
> 이 기능의 파서는 **`coolMessageDateParser.ts`** 로 따로 둔다. 둘은 합치지 않는다 —
> 저쪽은 "사용자가 친 한 줄 → 할일 하나", 이쪽은 "남이 보낸 쪽지 전체 → 일정 여럿"이다.

```
domain/            외부 의존 0 — 여기가 이식의 본체
  rules/coolMessageDateParser.ts   ← date_parser.py 이식 (순수 정규식) ✅ M1 완료
  privacy/maskRules.ts             ← pii_detector.py 규칙 추가 (기존 파일 확장)
  entities/CoolMessage.ts          ← 쪽지 · 일정후보 타입
  rules/coolMessageToCandidate.ts  ← pipeline.py 의 후보 생성 로직

electron/          Node 전용 — 파일·DB 접근은 전부 여기
  coolMessengerReader.ts           ← db_reader.py 이식 (node:sqlite)
  main.ts                          ← IPC 핸들러 3개 추가
  preload.ts                       ← window.electronAPI 노출

adapters/
  repositories/CoolMessengerRepository.ts
  components/CoolMessenger/ImportModal.tsx   ← 미리보기·인라인 편집 화면 (신규)
  components/Settings/tabs/CalendarTab.tsx   ← 켜기 스위치 (기존 파일 수정)
```

**핵심**: 날짜 파싱·개인정보 탐지는 전부 `domain/`의 순수 함수로 간다. 파일도 DB도 모르는
코드라 테스트가 쉽고, 아키텍처 규칙 위반이 없다.

## 9. ⚠️ 실기기 검증 계획 (오너 PC에 쿨메신저 없음 — 2026-08-21 확인)

개발 PC에 쿨메신저가 없어서, **실제 쪽지함으로는 한 번도 돌려보지 못한 상태다.**
대신 아래까지는 자동 테스트로 막아 뒀다.

- 실물과 같은 스키마(`tbl_recv` 칸 이름, `2026/07/16 17:04:52 (목)` 형식, WAL 모드)의
  **가짜 쪽지함을 만들어 읽는 테스트** 20개
- 쿨메신저가 **켜져 있는 상황**(연결이 열린 WAL)에서도 읽히는지
- **원본이 한 바이트도 안 바뀌는지** (sha256 스냅샷 비교) ← 가장 중요한 안전 속성
- 표·칸이 바뀌었을 때 조용히 실패하지 않고 오류를 내는지

**그래서 실기기에 남은 위험은 하나로 좁혀졌다** — _"쿨메신저의 진짜 스키마가 우리가 아는 것과
같은가."_ 다르면 `CoolSchemaMismatchError`가 명확한 문구로 뜬다.

### 협조 요청할 선생님께 부탁할 것

1. 설정에서 기능을 켤 때 쪽지함을 **찾았는지** (못 찾으면 안 켜진다)
2. 쪽지 목록이 뜨는지, **최신순·안읽음 우선**이 맞는지
3. 날짜를 **잘못 잡은 쪽지**가 있으면 그 쪽지 문구 그대로 (개인정보는 지우고) 알려주기
4. 개인정보 빨간 표시가 **과한지/모자란지**
5. 쿨메신저에서 그 쪽지가 **안읽음→읽음으로 바뀌지 않았는지** (우리는 읽기만 한다)
