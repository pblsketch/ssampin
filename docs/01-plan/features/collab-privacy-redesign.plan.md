## 2. 결함 목록

| ID     | 결함                                         | 심각도 | 원인                                                                                  |
| ------ | -------------------------------------------- | ------ | ------------------------------------------------------------------------------------- |
| **D1** | 상담·설문 테이블 전 행 익명 읽기             | 치명   | `FOR SELECT USING (TRUE)` — 행 전체 공개                                              |
| **D2** | `admin_key` 가 D1을 타고 함께 노출           | 치명   | RLS는 **행 단위라 열을 못 가린다**. 클라이언트가 `select=` 에서 빼는 건 방어가 아니다 |
| **D3** | 서명 이미지 버킷 익명 목록·다운로드          | 치명   | `sigv2_signatures_public_read` 가 `USING (bucket_id = ...)` 뿐, 경로 제한 없음        |
| **D4** | 암호문과 열쇠가 같은 DB에 나란히             | 높음   | `consultation_schedules.admin_key` 평문 저장 → 종단간 암호화가 무력                   |
| **D5** | 과제 수합에 **명단 전체** 업로드 + 이름 평문 | 높음   | `assignments.student_list JSONB NOT NULL`, `submissions.student_name`                 |
| **D6** | 서명 명단·서명자 이름 평문                   | 높음   | `sigv2_sessions.roster_snapshot`, `sigv2_entries.signer_name`                         |

**D1+D2+D4가 겹치면**: 아무나 → 상담 일정 186건의 `admin_key` 획득 → 예약 256건의 암호문 복호화
→ 보호자 이름·연락처·상담 내용 열람. 게다가 `admin_key` 는 교사용 관리 키다.

## 3. 설계 원칙

> **클라우드는 "그게 누구인지" 몰라도 되게 한다.**

1. **열쇠를 서버에 두지 않는다.** `admin_key` 원본은 교사 PC와 공유 링크(URL 조각 `#`)에만.
   서버엔 대조용 해시만 둔다. URL 조각은 브라우저가 서버로 보내지 않는다 —
   상담 예약이 이미 쓰는 방식(`BookingPageContent.tsx:66`)이고, 설계는 옳았는데 열쇠를 같이 둬서 무력했다.
2. **이름은 링크 키로 암호화**해서 저장한다. 화면에 이름을 보여줘야 하는 곳(서명 명단 고르기)은
   링크를 가진 사람만 풀 수 있으면 충분하다.
3. **식별은 결정적 해시로.** 암호문은 매번 달라져 중복검사·`UNIQUE` 에 못 쓴다.
   `member_ref = HMAC(링크키, 정규화된 이름+학번)` 형태로 만들면 서버는 원본을 모른 채 같은 사람인지 판단한다.
   _(sigv2 엔 이미 `member_ref` 컬럼이 있다 — 현재 값이 무엇인지 확인 후 재사용 검토.)_
4. **공개 읽기 정책 금지.** `USING (TRUE)` 와 버킷 전체 공개는 쓰지 않는다.
   공개가 필요한 조회는 **RPC(SECURITY DEFINER)로 반환 열을 고정**한다.

### 감수하는 대가 (사용자 확인 완료)

- 교사가 링크를 잃으면 그 자료는 **아무도 못 연다.** 완화책: 쌤핀 앱이 링크 키를 로컬에 보관하고
  학년도 마무리 시 함께 보관·경고한다.
- 서버가 이름을 모르므로 정렬·검색 일부를 클라이언트로 옮겨야 한다.
- 기존 데이터(186·256·129행 등) 이관 작업이 따로 필요하다.

## 4. 단계

### P0 — 노출 차단 (즉시, 코드 변경 최소)

목표: **D1·D2·D3 를 먼저 닫는다.** 설계를 기다리지 않는다.

- [ ] `consultation_schedules` `surveys` 의 `USING (TRUE)` SELECT 정책 제거
      → 공개 조회용 RPC 신설(반환 열에서 `admin_key` 제외)
- [ ] `consultation_bookings` `survey_responses` 도 동일 처리
      (지금은 남의 예약·응답을 전부 읽을 수 있다)
- [ ] `sigv2-signatures` 버킷 공개 읽기 정책 제거 → **서명 URL을 만료 있는 서명된 URL로 전환**
- [ ] 회귀 확인: 학부모 예약 화면, 설문 응답 화면, 서명 화면, 교사 현황 화면이 그대로 동작하는지 실제로 열어볼 것

**위험**: 정책을 조이면 학부모·학생 화면이 조용히 깨질 수 있다. 반드시 실화면 확인 후 배포.

### P1 — 열쇠 분리 (D4)

- [ ] `admin_key` 를 **해시로만 저장**(`admin_key_hash`), 원본은 교사 PC + 링크에
- [ ] 교사 인증 경로를 "키 대조"에서 "해시 대조"로 변경
- [ ] 기존 186건은 이관 스크립트로 해시 생성 후 원본 열 삭제
- [ ] 이 단계가 끝나야 상담 예약 암호화가 **실제 효력**을 갖는다

### P2 — 이름 암호화 (D5·D6)

- [ ] 과제 수합: `student_name` → `name_enc` + `member_ref`.
      `student_list` 는 **대조용 해시 목록**으로 축소(원본 명단 업로드 중단)
- [ ] 서명(sigv2): `roster_snapshot`·`signer_name` 동일 적용.
      학생 화면은 링크 키로 복호화해 이름 목록을 표시
- [ ] `UNIQUE` 제약을 `member_ref` 기준으로 재설계
- [ ] 서명 이미지 파일명에 이름이 들어가지 않는지 확인

### P3 — 기존 데이터 이관

- [ ] 이관 스크립트 + 되돌리기 경로
- [ ] 이관 전 백업, 실패 시 롤백 절차

### P4 — 문서 갱신

- [ ] 개인정보처리방침 제11·12·14조 (평문 저장 서술 삭제)
- [ ] `docs/edzip/학운위-심의자료.md` 표의 "평문" 표기
