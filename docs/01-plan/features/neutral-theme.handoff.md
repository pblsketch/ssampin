## 배경

(Goos Kim 제작) 스크린샷 — 칸반 보드 1장 + 모니터 4패널 1장.

이미지에서 직접 뽑은 색:

컨셉 = **유채색을 안 쓰고 검정 채움으로 강조하는 무채색 미니멀.** 그림자 없음,

기존 11개 프리셋 중 겹치는 것 없음 — `모노`는 무채색이지만 다크,

최종값 (아래 "결정 결과"·"추가로 잡은 것" 반영 후):

```ts
neutral-light  bg #f5f5f7  surface #fafafa  card #ffffff  border #e6e6ea
               accent #1c1c1e  highlight #b45309  text #17171a  muted #6e6e73
neutral-dark   bg #0b0b0d  surface #141416  card #161618  border #2a2a2e
               accent #fafafa  highlight #fbbf24  text #ededf0  muted #8e8e93
```

둘 다 `styleHint: { borderRadius: 10, cardGap: 14, showBorder: true, shadow: 'none', fontFamily: 'pretendard' }`.

> **정정** — 초안에는 "`neutral-dark` 의 흰색 accent 는 `index.css` 의
> `.bg-sp-accent.text-white` 자동 대비 가드가 이미 있어 안전하다"고 적었으나 **사실이
> 아니었다.** 그 가드는 정확 매치라 `text-white/70` 같은 알파 변형을 잡지 못하고,
> 실제로 모바일 안내 배너의 닫기 버튼이 흰 배경 위 흰 아이콘(1.03:1)으로 사라졌다.
> 앞경계 고정 쌍을 추가해 막았다. **"가드가 있으니 안전하다"는 실화면으로 확인하기
> 전까지는 가설일 뿐이다.**

## 결정 결과 (2026-08-14, 후속 세션에서 처리 완료)

### 1. `highlight` 를 빨강으로 둘지 → **앰버로 교체 (완료)**

**결정 근거** — 기존 11개 프리셋의 highlight 를 전수 확인하니 9개가 앰버·금색
계열이었고 빨강을 쓰는 테마는 하나도 없었다. 즉 쌤핀에서 빨강은 일관되게
"문제"를 뜻해왔다. 아래 (a) 안을 채택.

- `neutral-light` `#b91c1c` → `#b45309` (카드 대비 5.02:1, 배경 4.61:1)
- `neutral-dark` `#f87171` → `#fbbf24` (카드 대비 10.83:1, 네이비·포레스트·선셋과 동일 값)

무채색 컨셉 테스트는 bg·card·accent 만 검사하므로 그대로 통과한다.
실화면에서 `--sp-highlight` 가 글자·배경·테두리 세 경로 모두 `rgb(180,83,9)` 로
적용되는 것을 확인했다.

### 2. 어두운 테마의 오늘 색 파생을 유지할지 → **유지 (완료)**

되돌리는 비용(테마에 오늘 색을 직접 적는 선택 필드 신설 + `applyThemeColors`
시그니처 변경)에 비해 얻는 게 적다고 판단해 그대로 뒀다. 기존 슬레이트 남색도
포레스트·선셋에서는 겉돌던 색이라, 파생 쪽이 테마 일관성 면에서 낫다.

**단, 기존 다크 사용자에게 보이는 변화다** — 포레스트는 초록빛, 선셋은 갈색빛으로
오늘 카드 색이 바뀐다. 릴리즈 노트에 반드시 적을 것.

<details><summary>당시 검토 내용 (원문)</summary>

#### 2. 어두운 테마의 오늘 색 파생을 유지할지

준일님이 승인한 범위는 **"밝은 테마 전부"** 였는데, 구현은 어두운 테마에도 같은 규칙을
적용했다. 이유는 그렇게 하지 않으면 `neutral-dark` 만 혼자 슬레이트 남색이 되어 컨셉이
깨지기 때문. 부작용으로 forest/sunset/kraft-dark 의 오늘 색도 각자 색조로 바뀐다.

되돌릴 경우 — `computeTodayBg` 를 밝은 배경일 때만 파생하고 어두우면 기존 상수를
반환하도록 바꾸되, `neutral-dark` 에는 예외가 필요하다. 그러려면 테마에 오늘 색을
직접 적는 선택 필드(`todayBg?`)를 두고 `applyThemeColors` 가 `colors` 만이 아니라
테마 객체를 받도록 시그니처를 바꿔야 한다.

</details>

## 후속 세션에서 추가로 잡은 것 — 배경에 묻혀 안 보이던 글자 4건

준일님이 실화면에서 "배경 색에 묻혀서 텍스트가 안 보이는 부분들이 있다"고 신고.
브라우저에서 모든 텍스트의 유효 배경 대비를 훑어 특정했다.

앞의 둘은 **거울상 문제**다. accent 가 검정(라이트)·흰색(다크) 양 끝으로 가면서,
그동안 파랑·주황 accent 뒤에 가려져 있던 구멍이 드러났다.

**재발 방지 그물 `MT-D3`**(`accent-bg-white-text.metatest.test.ts`)로 두 구멍을
"지금 0건" 상태로 고정했다. 버그를 되살려 실제로 빨간불이 나는 것을 확인한 뒤 원복했다.

### 남긴 것 — 이 테마 탓이 아닌 저대비 2건

활동기호 노랑(`#ca8a04` 2.94:1)과 날씨 하늘색(`#0ea5e9` 2.55:1). **기존 라이트

또한 `text-gray-400` 류 옅은 중성색 51곳은 **일괄 보정하지 말 것.** 상당수가
학생 화면처럼 어두운 배경 위에 쓰여 강제로 어둡게 하면 그쪽이 깨진다

## 커밋 기록

다중 세션에서 인덱스가 공유되므로 `git commit -m "..." -- <path>` 로 **명시 경로**를
썼다 (`git add .` 금지). 옆핀 세션이 동시에 작업 중이던 `src/widgets/types.ts`·
`SidePin*` 은 제외했다.

- `22c25612` — `DashboardTheme.ts` · `useThemeApplier.ts` · `__tests__/DashboardTheme.test.ts` ·

- `2006f993` — `DashboardTheme.ts` · `accent-bg-white-text.metatest.test.ts`

**함정 2개 (재발 주의)**

1. **husky 훅이 `node` 를 못 찾아 커밋이 실패한다.** 신규 파일을 `git add` 한 채
   실패하면 그 틈에 다른 세션이 가져갈 수 있다(전례 있음). 커밋 앞에 PATH 를 얹고
   `add` 와 `commit` 을 한 호출로 붙일 것 —
   `$env:PATH = "C:\Program Files\nodejs;" + $env:PATH`.
2. **줄바꿈이 CRLF 로 뒤집혀 있었다.** `core.autocrlf=false` 에 `.gitattributes` 도
   없어 그대로 기록된다. 62줄짜리 변경이 379줄 재작성으로 남을 뻔했다. LF 로 되돌린 뒤 커밋했다.
