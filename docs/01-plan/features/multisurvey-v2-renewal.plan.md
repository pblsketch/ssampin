## 0. 비개발자 한 단락 요약

쌤도구 안에 있는 **복합 유형 설문**(OX·객관식·주관식·빈칸형·서술형이 한 세션에 섞이는 도구)을 Reference Board 수준의 매끄러운 UI/UX로 새 단장합니다. 게임화(점수·랭킹 강요)가 목적이 아니라 **학생이 활기차게 참여하는 흐름**이 목적이에요. 11종 옵션 토글로 게임 메카닉은 켜고 끌 수 있어요. 사용자(준일님·다른 선생님)에게는 **v2.1.0 한 번만 노출**되고, 기존에 만든 설문 자료는 **자동으로 새 형식으로 변환**됩니다 (백업 30일 보존). 다른 PC와 GDrive로 동기화 중이면 안전을 위해 **양쪽 PC가 다 v2.1.0이 되기 전까지는 sync 일시 정지** 안내가 뜹니다. 작업은 4 phase로 나누고, 가장 먼저 **Phase 0(UI 스파이크 1~2일)** 으로 화면을 먼저 그려본 다음 도메인을 짭니다.

## 1. 사용자 요청 요약

### 요청 ① — RB 수준의 매끄러운 UI/UX

> "쌤도구 - 복합 유형 설문을 고도화. 전면 리팩토링도 가능. 목표 수준은 외부 참고 사이트에서 제공하는 Reference Board(외부 도메인 (생략))의 게임 도구."

(deep-interview 진행 중 "게임화가 아니라 UI/UX 매끄러움이 목적"으로 정정)

### 요청 ② — 학생 활기 신호 (deep-interview Round 9)

- **신호 A**: 학생이 라운드 끝나도 "한 번 더!" "다음 거 뭐예요?" 자발적으로 요청
- **신호 B**: 평소 딴짓하던 학생도 교실 모니터에 시선이 쏠리고 학급 전체가 같은 화면을 봄

### 요청 ③ — 페인 (deep-interview Round 2·3)

- 교사: 설문 만드는 전 단계가 번거로움 (특정 단계가 아니라 전반)
- 학생: 제출 이후 (정답 공개·다음 문제 대기·최종 결과) 흐름이 단조로움

## 2. 근본 원인 분석 (brownfield)

### 2.1 현재 라이브 핸들러는 phase machine 일부만 구현

[electron/ipc/liveMultiSurvey.ts:1](../../../electron/ipc/liveMultiSurvey.ts#L1)

`stepMode=true`일 때 lobby → open → revealed 3 phase 머신은 이미 있음. 그러나 RB 패턴의 7단계(메이커·로비·문항·정답공개·라운드 결과·포디움·종료)와 매핑되지 않아 학생 활기 신호가 누락 (포디움·중간 랭킹·자동 진행).

### 2.2 학생 페이지 정적 HTML 생성 방식

[electron/ipc/liveMultiSurveyHTML.ts](../../../electron/ipc/liveMultiSurveyHTML.ts)

학생 페이지가 Electron의 정적 HTML 생성기로 만들어져서 sp-\* 토큰을 받기 어려움. CSS 변수 inline 주입 helper 부재.

### 2.3 11종 옵션 토글 UI 위치 미정

RB 분석 결과 11종 옵션(누적점수표시·해설노출·재입장 가능·배경음악 + 교사 집중·정답 제출 버튼·문항별 점수·빠른 풀이·연속 가산·랜덤 보너스·자동 넘김)이 발견됐는데, 쌤핀 현재 UI에는 옵션 자체가 없거나 분산됨.

### 2.4 결과/포디움 화면 부재

라운드 끝난 후 학생 화면은 단순 "응답 완료" 토스트. 정답 공개·등수·포디움 메타포 전무 → Round 9 신호 둘 다 안 만들어짐.

### 2.5 마이그레이션 인프라 부재

복합 설문 도메인 v1이 휘발성 + IPC 레이어 섞인 구조. 신규 도메인(`formatVersion: 2`)으로 전환하려면 어댑터·백업·라운드트립·sync 충돌 처리가 모두 신규 작성 필요.

## 10. ADR (Decision Record)

**Decision**: Option D — Phase 0 UI 스파이크 선행 + `formatVersion: 2` + 멀티 PC sync 일시 정지 + feature flag opt-in 출시

**Drivers**: ① 미감 우선 (RB 수준) ② 비개발자 사용자 안전 (sync 충돌 0) ③ 롤백 가능성 (flag + 백업)

**Alternatives considered**:

- A (빅뱅) — 회귀 폭 큼, 롤백 단위 큼 → 기각
- B (점진 4회) — KB/노션/release-notes 4회 = 사용자 피로 4배, 멀티 PC 시차 위험 → 기각
- C (A+B 병합) — 노출 2회는 같으나 사용자 **인지 적응 2회** 강요 → 기각

**Why D chosen**: flag OFF가 가장 빠른 롤백, 사용자 인지 1회, 점진 통합으로 회귀 분산. **노출 횟수가 아니라 인지 부하 횟수가 본질**.

**Consequences**:

- (+) 롤백 단위 최소 (flag OFF) / 사용자 인지 1회 / 다운그레이드 안전 / 멀티 PC 안전
- (−) flag 분기 코드 부채 (3개) / 제거 작업 v2.1.1 필요 / Phase 0 추가 비용 1~2주 / Percy 미도입으로 정성 평가 의존도 높음

**Follow-ups**:

- v2.1.1 flag 제거 후 facade hook 제거
- Percy/Chromatic 도입은 별도 PDCA
- D.2 폴백 합격선 확정 [TBD]
- 형제 도구(단순 설문·투표·워드클라우드) 통일은 v2.1.x/v2.2.0
