## 1. 왜 세션을 바꾸는가

Mobbin MCP를 등록·인증까지 마쳤지만, **인증한 세션에서는 도구를 쓸 수 없다.** Claude Code는 세션이 시작될 때 도구 목록을 확정하므로, 세션 시작 이후에 붙인 MCP 서버의 도구는 그 세션에 나타나지 않는다. 새 세션을 열면 바로 잡힌다.

**확인된 상태**

```
mobbin: https://api.mobbin.com/mcp (HTTP) - ✔ Connected
```

- 안내 페이지 `https://mobbin.com/mcp`는 MCP 서버가 아니다(POST 405). 실제 주소는 `api.mobbin.com`.
- OAuth 인증 완료. 새 세션에서 재로그인 불필요.
- 새 세션 시작 후 `ToolSearch`에 `select:` 또는 `mobbin` 키워드로 도구 스키마를 불러와 사용.

## 3. 사용자가 확정한 방향

1. **마감 공사가 아니라 화면 구조 재설계.** (색·팝업 통일 수준이 아니라 IA를 다시 짠다)
2. **단, 기존 기능에 문제가 생기면 안 된다.**

이 둘을 동시에 지키는 원칙 = **배관과 외관을 분리한다.**
화면 조립 층만 바꾸고, 데이터가 흐르는 배관(`src/mobile/stores/` 28개 · `src/domain/` · `di/container.ts` · 동기화 프로토콜)은 손대지 않는다.

## 4. 조사 브리프 (R1~R7)

레퍼런스 앱군은 소비자 SNS가 **아니라** 현장 업무앱 — 근무 관리, 진료 차트, 출석 관리, 창고 검수.

| #   | Mobbin에서 찾을 것                               | 대응 문제                | 근거 파일                            |
| --- | ------------------------------------------------ | ------------------------ | ------------------------------------ |
| R1  | 기능 많은 업무앱의 하단 탭 구성 원칙             | 전체 IA (탭 4 + 하위 18) | `App.tsx:114-165`                    |
| R2  | 반 선택 + 날짜 이동 + 뷰 전환을 겹치지 않게 배치 | 헤더 3층                 | `StudentsPage.tsx:340-479`           |
| R3  | 다수 하위 메뉴를 검색·즐겨찾기·그룹으로 푸는 법  | 더보기 18종              | `MorePage.tsx:64-103`                |
| R4  | 30명 상태를 빠르게 찍는 밀도 높은 체크 입력      | 출결 946줄               | `AttendanceCheckPage.tsx:657-806`    |
| R5  | 카드 숨김·재배치가 있는 홈 대시보드              | 홈 벤토                  | `TodayHub.tsx:221-289`               |

| R7  | 스와이프 빠른 액션 + 되돌리기 / 바텀시트 표준    | 명단 / 팝업 17개         | `SwipeRow/` · `fixed inset-0` 17파일 |

추가 조사 축: **모바일 라우팅과 뒤로가기 처리** — 현재 라우터가 없어 안드로이드 뒤로가기가 앱을 종료시킨다.

## 5. 절대 우회 금지 (과거 데이터 사고 이력)

- 출결은 **학번(number)으로 식별** — 번호 없는 학생 기록 차단 로직 유지 (`StudentsPage.tsx:236`)
- 그룹 학급 공유 레코드는 반드시 `findAttendanceRecordForClass` 경유 (`StudentsPage.tsx:91-99`)
- **빈 명단 저장 차단** (`AttendanceCheckPage.tsx:580`) — 뚫리면 그날 출결이 지워짐

이 저장소엔 소스를 직접 검사하는 계약 테스트가 있어 화면을 갈아엎으면 먼저 빨간불이 난다.
**테스트를 고쳐서 통과시키지 말 것.** 테스트가 지키려던 기능을 새 구조에서도 유지하는 방식으로 해결한다.

---

## 6. 프로젝트 규칙 (놓치기 쉬운 것)

- 디자인·UI/UX 단독 작업 금지 — `frontend-design` 스킬 협업 의무
- `sp-*` 토큰에 Tailwind 투명도 수식(`bg-sp-accent/40`) **무효 — 조용히 투명 렌더됨**. `black/white` 알파나 opacity 유틸로 대체
- 라운드는 Tailwind 기본 키만, 직각 금지, `rounded-sp-*` 금지
- 모든 UI 텍스트 한국어 / AI 기능·게이미피케이션 금지
- 작업은 `main` 단일 워킹트리. 새 브랜치·worktree·PR은 사용자가 명시 요청할 때만
- vite 개발 서버 2개 동시 실행 금지 (무한 로딩)

검증 게이트:

```bash
npx tsc --noEmit && npm run lint && npm run test && npm run regression-check && npm run build:mobile
```
