# Plan — 화살표·F키 단축키가 동작하지 않는 결함 수리

- **작성일**: 2026-08-20
- **상태**: **완료** — 구현·자동 검증·실기기 확인 전부 통과 (2026-08-20)
- **성격**: 기존 결함 수리. 옆핀과 코드가 겹치지 않으며 **단독으로 값이 있고 단독으로 되돌릴 수 있다**
- **발견 경위**: [side-pin-zone-open.plan.md](./side-pin-zone-open.plan.md)의 칸별 단축키를 `Ctrl+Alt+↑/↓`로 정하면서 드러남
- **영향 버전**: 미정 (v2.4.2 출시 이후)

---

## 1. 증상 — 지정은 되는데 눌러도 아무 일이 없다

설정 > 단축키에서 **화살표 키나 F1~F12를 포함한 조합은 지정할 수 있지만 절대 동작하지 않는다.** 실행해 확인했다.

```
설정에서 잡히는 값 : mod+alt+ArrowUp
저장·비교용 값     : arrowup                        ← 대소문자가 어긋남
일치 검사          : 실패
Electron 등록값    : CommandOrControl+Alt+arrowup   ← 잘못된 형식(Up 이어야 함)
```

## 2. 원인 — 키 이름을 만드는 쪽과 읽는 쪽이 어긋난다

| 위치                                                                | 하는 일                           | 결과                        |
| ------------------------------------------------------------------- | --------------------------------- | --------------------------- |
| `src/adapters/hooks/shortcut/keyNormalize.ts:20-23`                 | `ArrowUp`·`F5`는 **원형을 유지**  | `ArrowUp`                   |
| 같은 파일 `:47` `parseCombo`                                        | 조합 문자열을 **통째로 소문자화** | `arrowup`                   |
| 같은 파일 `:96` `matchesCombo`                                      | 위 둘을 비교                      | **영원히 불일치**           |
| 같은 파일 `comboToAccelerator` / `electron/main.ts:585-607`(복제본) | 한 글자면 대문자화, 아니면 그대로 | `arrowup` → Electron이 거부 |

## 3. ★"조용히" 실패하는가 — 절반만 그렇다

등록 실패는 수집되어(`electron/main.ts:1150-1182`) 토스트로 뜬다(`src/adapters/hooks/useGlobalShortcuts.ts:123-132`).

> "N개 단축키를 시스템에 등록하지 못했습니다. 다른 조합을 선택해주세요."

**그런데 이 토스트는 메인 창 렌더러에서만 뜬다.** 옆핀·위젯 모드로 메인 창을 접어 둔 사용자에게는 실제로 아무 신호가 없다. 게다가 문구가 **"다른 조합을 고르라"**고 안내해, 우리 쪽 결함을 OS 충돌로 오인하게 만든다. 사용자는 조합만 계속 바꾸다 포기한다.

→ **수리 성공의 기준은 "동작한다"가 아니라 "이 토스트가 뜨지 않는다"이다.**

## 4. 무엇을 하는가

### 4.1 선행 — 변환 함수를 별도 파일로 뺀다 (그물을 치기 위해)

`comboToAccelerator`가 `electron/main.ts`의 **모듈 사설 함수**인데, `main.ts`는 첫 줄부터 `electron`을 import한다. **이 저장소에서 `main.ts`를 import하는 테스트는 0건**(확인함)이므로, 지금 구조로는 복제본이 맞게 고쳐졌는지 검사할 방법이 없다.

- `electron/main.ts:585-607` → **`electron/shortcutAccelerator.ts`로 추출**
- 미러 동치 테스트를 신설한다. 선례가 이미 5개 있다: `electron/sidePinDeviceState.mirror.test.ts`, `closeAction.mirror.test.ts`, `archiveRules.mirror.test.ts`, `desktopWidgetBounds.mirror.test.ts`, `memoEditorActivity.mirror.test.ts`

> **구현 시 판단 1건** — 기존 미러 5건은 **정본이 모두 `src/domain/**`** 인데(테스트 주석: electron 은 rootDir 제약으로 `@domain`을 import 할 수 없다), 이번 정본은 어댑터 계층(`keyNormalize.ts`)이다. 특수 키 이름 표만 도메인 값객체로 올리면 선례·아키텍처 규칙과 정확히 일치한다. **표만 올리고 나머지는 그대로 두는 쪽을 권고**하되, import 제약을 실제로 확인한 뒤 정한다.

**이 추출이 없으면 "두 곳을 함께 고친다"를 지킬 그물이 없다** — 이 계획이 진단한 사고(복제본이 어긋남)가 그대로 재발할 조건이다.

### 4.2 수리

특수 키 이름을 세 형태로 오가는 표를 한 곳에 둔다.

| 쓰임             | 값                             |
| ---------------- | ------------------------------ |
| 저장·비교용 정본 | `arrowup` · `f5` (소문자 통일) |
| 화면 표시        | `↑` · `F5`                     |
| Electron 등록    | `Up` · `F5`                    |

대상: 화살표 4종(`Up`/`Down`/`Left`/`Right`) + `F1~F12`.

## 5. 수용 기준 (전부 자동 테스트로 검증 가능)

| #    | 층위   | 기준                                                                                                                                                                          |
| ---- | ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| AC-1 | vitest | `eventToCombo(Ctrl+Alt+ArrowUp)` → `canonicalizeCombo` → 저장 → `parseCombo` 비교가 **일치**한다                                                                              |
| AC-2 | vitest | `comboToAccelerator('mod+alt+arrowup')` === `'CommandOrControl+Alt+Up'`                                                                                                       |
| AC-3 | vitest | `F5`도 AC-1·AC-2와 같은 왕복이 성립한다                                                                                                                                       |
| AC-4 | vitest | 화면 표시가 `Ctrl+Alt+↑`이다 (`arrowup` 같은 날것이 노출되지 않는다)                                                                                                          |
| AC-5 | mirror | `electron/shortcutAccelerator.ts`와 `keyNormalize.ts`의 변환 결과가 **모든 특수 키에 대해 동일**하다                                                                          |
| AC-6 | 회귀   | 기존 조합(`mod+alt+t` 등)의 결과가 **하나도 바뀌지 않는다**                                                                                                                   |
| AC-7 | 회귀   | **이미 저장된 `mod+alt+ArrowUp`(대소문자가 섞인 옛 값)도 수리 후 그대로 동작한다** — `parseCombo`가 소문자화하므로 자동으로 치유된다. 사용자가 설정을 다시 지정할 필요가 없다 |

## 6. 검증 절차

1. `npx tsc --noEmit` / `npm run lint` / `npm run test` / `npm run regression-check`
2. **`npx tsc -p tsconfig.electron.json --noEmit`** — 검증 게이트 4종 중 `electron/`을 보는 것은 `npm run test` 하나뿐이라 따로 돌린다
3. **그물 실증**: 변환 표를 **한쪽(렌더러 또는 electron)만** 되돌렸을 때 AC-5가 빨간불이 나는지 확인한다. 이것이 "두 곳을 함께 고친다"를 지키는 유일한 장치다

## 7. 실기기 확인

| #   | 무엇을                                                                           | 통과 판정                                           |
| --- | -------------------------------------------------------------------------------- | --------------------------------------------------- |
| 1   | 설정 > 단축키에서 아무 명령에 `Ctrl+Alt+↑`를 지정하고 앱을 다른 창에 두고 누른다 | 그 명령이 실행되면 통과                             |
| 2   | 지정 직후 화면                                                                   | **"등록하지 못했습니다" 토스트가 뜨지 않으면 통과** |

| 4   | 기존 단축키(`Ctrl+Alt+T` 등)                                                     | 그대로 동작하면 통과                                |

> ⚠️ 일부 그래픽 드라이버가 `Ctrl+Alt+↑`를 화면 회전에 쓴다. 그 기기에서는 **OS가 먼저 가져가므로 우리 수리와 무관하게 실패**할 수 있고, 그때는 토스트가 뜨는 것이 정상이다. 1번이 실패하면 다른 조합(`Ctrl+Alt+F9` 등)으로 한 번 더 시험해 구분한다.

## 8. 하지 않는 것

- **다른 특수 키 확장**(`Home`/`End`/`PageUp` 등) — 지금 필요가 없다. 표에 줄을 추가하면 되는 구조로 만들어 둔다.
- **토스트 문구 전면 개편** — "다른 조합을 선택해주세요"가 오해를 부르지만, 실제 OS 충돌 때는 맞는 안내다. 이번엔 건드리지 않는다.

## 9. 구현 결과 (2026-08-20)

**고친 것** — `normalizeKey`가 이제 **모든 키 이름을 소문자로 통일**한다(`keyNormalize.ts`). 어긋남의 뿌리가 여기였다. 화면 표기(`↑`)와 Electron 등록 이름(`Up`)은 각각 표에서 되돌린다.

**추출** — `electron/main.ts`의 `comboToAccelerator`·`isSafeGlobalShortcutCombo`를 **`electron/shortcutAccelerator.ts`로 뺐다.** `main.ts`는 테스트에서 열 수 없어(저장소에 import 하는 테스트 0건) 복제본이 어긋나도 아무도 몰랐다.

**★미러 테스트는 import 가 아니라 소스 대조로 만들었다** — 처음엔 두 구현을 직접 불러 비교했는데, `electron/`이 `src/`를 import 하면 **`tsconfig.electron.json` 타입 검사가 13건 깨진다**(rootDir 제약). 그물을 놓으려다 다른 그물을 부수는 셈이라, 기존 미러 5건과 같은 방식(소스에서 표를 뽑아 비교)으로 바꿨다.

**검증** — `tsc` 0 · `lint` 0 error · `test` **464파일 5,628건 통과** · `regression-check` 43/43 · electron 타입 오류 **264건으로 기준선과 동일**.

**그물 실증** — electron 표에서 한 줄(`arrowdown`)만 지우니 미러 테스트 4건이 빨간불, 되돌리니 초록불.

**함께 갱신한 그물** — 기본 단축키 개수를 고정한 기존 테스트가 7개였는데 9개로 갱신했다(옆핀 칸별 열기 2개 추가).
