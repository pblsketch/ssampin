오너 요청 4건에서 출발해 전수조사한 결과다. 조사 중 **원래 요청에 없던 렌더링 결함 3건**이

| 항목                   | 값                                      | 출처                     |
| ---------------------- | --------------------------------------- | ------------------------ |
| 메인 창 최소 폭        | **1024px**                              | `electron/main.ts:2160`  |
| 왼쪽 메뉴 폭           | 256px (`w-64`), 접으면 64px             | `Layout/Sidebar.tsx:254` |
| 좁은 창의 실제 본문 폭 | **약 700px**                            | 1024 − 256 − 여백        |

| 브랜드 안티 참고       | **게이머 대시보드(과도한 네온/글로우)** | `.impeccable.md`         |
| 제1 디자인 원칙        | **정보 우선 — 장식보다 데이터**         | `.impeccable.md`         |

### 전제 A — `sp-*` 토큰에 투명도 표기는 작동하지 않는다

`bg-sp-accent/20` 같은 표기는 **에러 없이 조용히 무효**가 된다. 토큰이
`var(--sp-accent)` 형태로만 정의되어 있고 투명도 자리표시자가 없기 때문이다
(`tailwind.config.js:34~48`, Tailwind 3.4.17).

- 코드베이스 전체 **2,888곳 / 450개 파일**이 이 표기를 쓰고 있다 → 별건, 이번 범위 밖
- 그러나 **이번에 손대는 자리에는 이 표기가 몰려 있다** → 고치는 김에 함께 정리
- 대체 수단: `color-mix(in srgb, var(--sp-accent) 20%, transparent)` 인라인 스타일

### 전제 B — 의미 색상 토큰이 이미 있다

`--sp-info / --sp-success / --sp-warning / --sp-error` 가 테마별로 정의되어 있다
(`src/index.css:32-35, 231-234, 252-255`). 라이트는 600 톤, 다크는 400 톤으로 **이미
테마 대응이 끝나 있다.** 새 색을 만들 필요가 없다.

## 1. 좁은 창에서 대시보드 헤더가 무너진다

### 진단

세 가지가 겹쳤다.

**① 접히는 기준이 죽어 있다.** 헤더는 `flex-col md:flex-row` — "768px보다 좁으면 위아래로
쌓기"다. 그런데 창 최소 폭이 1024px이라 **768px 아래로 내려갈 수가 없다.** 쌓기 코드가
한 번도 작동한 적이 없고, 항상 가로 한 줄로만 그려진다.

**② 좁은 건 화면이 아니라 남는 자리다.** 본문 폭 700px에 아래를 다 넣으려 한다.

| 요소                                  | 필요 폭(대략)  |
| ------------------------------------- | -------------- |
| 시계 `text-4xl` "8월 18일 (화) 21:28" | 340px          |
| 날씨 4종 (기온·습도·미세먼지·상태)    | 420px          |
| 메시지 배너 `max-w-2xl`               | 최대 672px     |
| 버튼 3개 (새로고침·위젯 관리·스타일)  | 250px          |
| **합계**                              | **약 1,680px** |

700px 자리에 1,680px를 넣으니 전부 찌그러진다.

**③ 한글은 아무 데서나 끊긴다.** 자리가 모자라면 브라우저가 글자를 쪼개는데, 한국어는
`break-keep`(낱말 단위 묶기)이 없으면 **글자와 글자 사이 어디서든** 끊는다. 그래서
"맑음"이 "맑"/"음" 세로 2줄이 된다. 이 설정이 코드 전체에 **5곳뿐**이다.

구분점(`Dot`)은 `w-1 h-1` 고정이라 줄어들지 않고, 2줄이 된 텍스트 옆에 어정쩡하게 남는다.

### 방향 — **우선순위 축약 3단계**

숨길 것과 남길 것을 폭에 따라 정한다. 교사가 3초 안에 찾아야 하는 건 **날씨 상태와 기온**이고,
습도·미세먼지는 그 다음이다.

| 폭             | 시계              | 날씨                   | 배너        | 버튼         |
| -------------- | ----------------- | ---------------------- | ----------- | ------------ |
| 1280px+ (`xl`) | `text-4xl`        | 4종 전부               | `max-w-2xl` | 아이콘+라벨  |
| 1024~1280px    | `text-3xl`        | 기온·미세먼지·상태 3종 | `max-w-md`  | **아이콘만** |
| (창 최소폭)    | 위아래 2줄로 분리 | —                      | —           | —            |

### 시각 명세

**`DashboardHeader.tsx`**

```
- flex flex-col md:flex-row md:items-end justify-between gap-6
+ flex flex-col xl:flex-row xl:items-end justify-between gap-4 xl:gap-6
```

`md:` → `xl:` 한 글자 차이가 핵심이다. 1280px 아래에서 비로소 2줄로 쌓인다.

버튼 라벨: `위젯 관리` / `스타일` 텍스트를 `<span className="hidden xl:inline">` 로 감싼다.
(아이콘은 남기고 `title` 속성이 이미 있어 접근성 손실 없음)

**`Clock.tsx`**

```
- text-4xl font-bold text-sp-text font-display mb-2
+ text-3xl xl:text-4xl font-bold text-sp-text font-display mb-2 tabular-nums whitespace-nowrap
```

`tabular-nums` — 숫자 폭을 고정해 초가 바뀔 때 줄이 흔들리는 것을 막는다.

**`WeatherBar.tsx`**

```
컨테이너:
- flex items-center gap-4
+ flex flex-wrap items-center gap-x-3 gap-y-1 min-w-0

각 항목 <span>:
+ whitespace-nowrap break-keep   ← 항목 안에서는 절대 안 끊김

습도 항목:
+ hidden xl:flex                 ← 좁을 때 숨김 (예보 팝업에서 확인 가능)

구분점 Dot:
+ hidden xl:inline-block         ← 줄바꿈되면 오히려 방해
```

**`MessageBanner.tsx`**

```
컨테이너: max-w-2xl w-full → max-w-md xl:max-w-2xl w-full
제목 h3:  text-lg → text-base xl:text-lg + break-keep
```

### 리스크

- 습도를 숨기는 판단은 **오너 확인 필요**. 습도가 더 중요하면 미세먼지와 순서를 바꾼다.
- `xl:` 전환 시 1280px 부근에서 레이아웃이 한 번 크게 바뀐다 → 실제 창 크기 조절로 확인 필요.
- 위젯 창(`WidgetWeatherBar`)은 **별도 컴포넌트**라 이 변경의 영향을 받지 않는다.

## 2. 페이지 상단 제목줄이 배경과 안 어울린다

### 진단 (원인 확정)

반투명 배경 레이어(`AppBackdrop`)가 도입되면서, 뒤가 비쳐야 하는 요소들은 각각
**"나는 유리다"라고 등록**을 했다.

| 요소                | 등록 방법                              | 결과               |
| ------------------- | -------------------------------------- | ------------------ |
| html·body·앱 껍데기 | `sp-backdrop-on` 규칙이 배경 제거      | 비침 ✅            |
| 왼쪽 메뉴           | `data-sp-glass-surface` 속성           | 비침 ✅            |
| 카드들              | `bg-sp-card` 클래스 규칙               | 비침 ✅            |
| **페이지 제목줄**   | **`bg-sp-bg` — 어느 규칙에도 안 걸림** | **혼자 불투명 ❌** |

`src/index.css:329-333`이 비우는 대상은 `html`, `body`, `#root > div` **셋뿐**이다.
제목줄의 `<header>`는 여기 해당하지 않고, 유리 규칙(`bg-sp-card`, `data-sp-glass-surface`)에도
걸리지 않아 **모든 규칙을 빠져나간다.** 그래서 그라데이션 배경 위에 흰 판이 얹힌 것처럼 보인다.
아래쪽 실선(`border-b border-sp-border`)이 그 판을 배경에서 잘라내듯 끊어 이질감을 키운다.

**추가 발견 — sticky 옵션도 깨져 있다.** `bg-sp-bg/95`(`PageHeader.tsx:44`)는 전제 A의
무효 표기다. 스크롤 시 고정되는 헤더가 **의도한 반투명이 아니라 완전 투명**으로 렌더되어,
콘텐츠가 헤더 글자 위로 그대로 지나간다.

### 방향 — **사이드바와 같은 재질에 합류시킨다**

새 재질을 발명하지 않는다. 사이드바가 이미 쓰고 있는 유리 표면 규칙에 제목줄을 등록하면
반투명·흐림·얇은 빛줄기 테두리가 **자동으로 따라온다.** 한 파일 고치면 **14개 페이지가
전부** 해결된다.

### 시각 명세

**`PageHeader.tsx`** — `<header>`에 속성 하나 추가:

```
+ data-sp-glass-surface
```

이것만으로 유리가 켜졌을 때 `src/index.css:383-390` 규칙이 적용된다
(반투명 배경 + `backdrop-filter: blur()` + 테두리를 `color-mix(var(--sp-text) 10%)` 로 완화).
유리가 꺼져 있으면 규칙 자체가 발동하지 않아 **지금과 100% 동일** — 회귀 위험 없음.

sticky 배경 수정:

```
- sticky ? 'sticky top-0 bg-sp-bg/95 backdrop-blur-sm z-10' : 'bg-sp-bg'
+ sticky ? 'sticky top-0 backdrop-blur-sm z-10' : ''
  (+ style={{ backgroundColor: sticky
       ? 'color-mix(in srgb, var(--sp-bg) 95%, transparent)'
       : 'var(--sp-bg)' }})
```

경계선 완화(유리 꺼진 상태 포함):

```
- border-b border-sp-border
+ border-b   (+ style borderBottomColor:
              'color-mix(in srgb, var(--sp-text) 8%, transparent)')
```

### 리스크

- 제목줄 뒤로 콘텐츠가 지나갈 때 읽혀야 한다 → **sticky를 쓰는 페이지에서 스크롤 실측 필수.**
- 느린 기기 보호 규칙(`sp-glass-slow`)이 `[data-sp-glass-surface]`의 흐림을 자동으로 끈다
  → 성능 리스크는 이미 처리되어 있다.
- 14개 페이지 전부 육안 확인 대상.

## 3. 구글 계정 이메일이 크게 노출된다

### 진단 (근본 원인)

구글 캘린더를 연동하면 그 캘린더가 **자동으로 "카테고리"로 등록**되는데, 이름을 구글이 준
값 그대로 쓴다.

```
useCalendarSyncStore.ts:597   googleCalendarName: primary.summary
SyncFromGoogle.ts:102         const calendarName = mapping?.googleCalendarName ?? '구글 캘린더'
SyncFromGoogle.ts:105-108     categories.push({ id, name: calendarName, color: 'blue' })
```

**구글 기본(primary) 캘린더의 이름(`summary`)은 곧 계정 이메일이다.** 그래서 이메일이
카테고리 이름이 되어 필터 줄의 알약과 일정 카드의 칩에 계속 노출된다. 개인정보가 화면에
상시 떠 있는 문제이기도 하다.

**좋은 소식 — 통로가 한 곳이다.** 이름을 화면에 꺼내는 함수는 `getCategoryInfo`
(`categoryPresenter.ts:49`) 하나이고, 소비처는 5개 파일이다. 심지어 그 안에 구글 캘린더
ID를 알아보는 판별 함수 `isGoogleCalendarId`가 **이미 있다.** 다만 지금은 "저장된
카테고리를 못 찾았을 때만" 짧은 이름으로 바꾸는데, 실제로는 찾아지므로 그 처리가 건너뛰어진다.

### 방향 — **저장값은 그대로 두고 표시 이름만 파생한다**

저장된 이름을 바꾸면 마이그레이션이 필요하고, 설정 화면에서는 어느 계정인지 전체 주소를
봐야 한다. 그래서 **표시 계층에서만** 짧은 이름을 만든다. 마이그레이션 불필요.

표시 규칙:

| 상황                                       | 표시                                                                      |
| ------------------------------------------ | ------------------------------------------------------------------------- |
| 계정 본인 캘린더(primary) 1개뿐            | `내 구글 캘린더`                                                          |
| 계정 여러 개                               | `@` 앞부분만 (`eyoung1206@gmail.com` → `eyoung1206`), 12자 초과 시 말줄임 |
| 구글이 준 공유 캘린더 이름이 이메일이 아님 | 그 이름 그대로                                                            |
| 사용자가 별명을 지정함                     | **별명 우선** (카테고리 관리에서 편집 가능)                               |

배치:

- **필터 줄** — 구글 계정이 2개 이상이면 개별 알약을 늘어놓지 않고 `[G] 구글 ▾` **하나로
  묶어** 드롭다운에서 계정을 고른다. 1개면 지금처럼 단일 알약.
- **일정 카드 칩** — 이메일 텍스트를 빼고 **`GoogleBadge`(G 아이콘)만** 남긴다. 어느
  계정인지는 카테고리 색점으로 구분된다. (계정별 색 지정은 이미 가능)

### 시각 명세

`categoryPresenter.ts`에 파생 필드 추가 (원본 `name`은 유지):

```ts
/** 화면 표시용 짧은 이름. 저장값(name)은 건드리지 않는다. */
export function getCategoryDisplayName(
  info: CategoryItem,
  opts?: { readonly googleAccountCount?: number },
): string;
```

`getCategoryInfo`는 그대로 두고, 화면 5곳이 이 함수를 거치게 한다.

칩 스타일(필터 줄):

```
px-3 py-1.5 rounded-full text-xs font-medium max-w-[10rem] truncate
```

### 리스크

- **별명 편집이 이미 가능한지 확인 필요.** 가능하면 그것이 최선의 답이고, 자동 축약은 기본값
  역할만 한다.
- `isGoogleCalendarId`는 `@`가 있고 30자 초과인 ID도 구글로 판정한다 → 사용자가 직접 만든
  긴 이름 카테고리를 오판할 수 있다. 판별 조건 점검 필요.
- 설정 → 캘린더 화면에서는 **전체 이메일이 계속 보여야 한다**(어느 계정인지 확인해야 하므로).
  축약은 일정 화면에만 적용.

## 4. 왼쪽 강조 띠가 "AI 디자인스럽다" ← 핵심

### 전수조사

**총 37곳 / 29개 파일** (`border-l-4` 22곳 + `border-l-2` 15곳).

### 왜 AI스러워 보이는가 (진단)

1. **하나의 장치가 네 가지 뜻을 진다.** 경고 박스, 일정 분류색, "지금 이 교시", 인용문이
   전부 같은 4px 색 띠다. 한 장치가 모든 것을 뜻하면 아무것도 뜻하지 않게 되고, 그 순간
   "템플릿"으로 읽힌다.
2. **띠가 형태에 붙지 않고 얹혀 있다.** 중립 카드 옆구리에 채도 높은 4px 색 판이 맞대어
   있는 모양이다. 디자인된 게 아니라 **덧붙인 것**으로 보인다.
3. **튜토리얼의 표준 스니펫이다.** `border-l-4 border-amber-400 bg-amber-50`은 모든 CSS
   튜토리얼에 나오는 경고 박스 정답이다. 폰트로 치면 Inter에 해당한다.
4. **중요도와 강도가 반대다.** 가장 안 중요한 안내문이 화면에서 가장 채도 높은 요소가 된다.
   브랜드 원칙 "정보 우선 — 장식보다 데이터"와 정면으로 어긋난다.
5. 참고 레퍼런스인 **Notion·Linear 어느 쪽도 이 방식을 쓰지 않는다.** Notion은 옅은 색조
   배경 + 아이콘(콜아웃), Linear는 타이포 굵기 + 작은 색점을 쓴다.

### 없애면 안 되는 이유 (반드시 지킬 것)

이 띠는 취향이 아니라 **가독성 사고를 막으려고 만든 규칙**이다. 예전 다크 모드에서 "옅은
amber 배경 + 옅은 amber 글자"라 안내문이 거의 안 보였고(WCAG AA 미달), 그 해결책이
**"배경은 중립으로, 색은 띠·아이콘·라벨에만"** 이었다. 자동 검사
`Notice.metatest.test.ts`가 이 규칙을 강제하며, 대안으로 `bg-sp-card border-l-amber-400
text-sp-text`를 **명시적으로 권장**하고 있다.

→ 새 방식은 **"색으로 의미는 전하되 본문 가독성은 유지"** 라는 원래 목적을 반드시
대체해야 하고, **메타테스트 문구도 같은 작업에서 갱신**해야 한다.

### 용도별 대안

#### ① 안내·경고 박스 (`Notice.tsx` + amber 띠 대부분, 약 12곳)

**방향: 얕은 색조 면 + 아이콘 칩** (Notion 콜아웃 방식)

색을 옆구리 슬래브가 아니라 **면 전체에 아주 옅게 녹이고**, 색 예산은 원형 아이콘 칩에
몰아준다. 본문은 `sp-text` 그대로 — 가독성 규칙 유지.

```
컨테이너  rounded-lg border px-3.5 py-2.5 flex items-start gap-2.5
배경      color-mix(in srgb, var(--sp-warning) 7%, var(--sp-card))
테두리    color-mix(in srgb, var(--sp-warning) 22%, transparent)
아이콘 칩 w-5 h-5 rounded-full shrink-0 flex items-center justify-center
          배경 color-mix(in srgb, var(--sp-warning) 18%, transparent)
          글자 var(--sp-warning)
제목      font-bold text-sp-text   ← 의미색 아님(색은 아이콘이 전담)
본문      text-sp-text             ← 변경 없음
```

**왜 덜 AI스러운가** — 색이 형태에 스며들어 *면의 성질*이 되고, 덧붙인 부품이 아니게 된다.
경고/오류 구분은 색보다 **아이콘 모양**이 먼저 전달하는데, 이는 색맹 사용자에게도 통하는
더 나은 신호다.

**왜 더 안전한가** — `color-mix`의 기준을 `var(--sp-card)`로 잡으면 다크 테마에선 어두운
카드에 따뜻함이 7% 섞이고, 라이트 테마에선 밝은 카드에 섞인다. **테마별 분기 없이 자동
대응**된다. `bg-amber-50` 같은 고정 색이 라이트에서만 통했던 것과 대비된다.

#### ② 일정 카드의 분류색 (`EventList.tsx` 2곳)

**방향: 띠 제거 + 날짜 앞 색점**

지금 카드에는 **같은 정보가 두 번** 있다 — 왼쪽 4px 띠와 오른쪽 카테고리 칩. 띠를 지워도
정보 손실이 없다. 다만 목록을 세로로 훑는 스캔성은 지켜야 하므로, 색을 **눈이 이미 가는
자리**인 날짜 앞으로 옮긴다.

```
카드   - rounded-xl px-4 pt-4 pb-5 border-l-4 ${colors.border}
       + rounded-xl px-4 pt-4 pb-5 border border-sp-border
날짜 줄 앞에 추가:
       <span className={`w-1.5 h-1.5 rounded-full shrink-0 ${colors.dot}`} />
```

읽는 순서가 `[●] 8월 18일 (화)` → 제목이 되어, 색이 장식이 아니라 **문장의 일부**가 된다.

지난 일정(`border-l-4 border-red-500/60`)은 띠 대신 `opacity-60` + 날짜 취소선으로 낮춘다.

#### ③ "지금 이 항목" 상태 강조 (`DashboardTimetable` 2곳 외)

**⚠️ 여기에 실제 렌더링 결함이 있다.**

```
현재:  border-l-4 border-sp-highlight bg-sp-highlight/15
       ring-2 ring-sp-highlight/30 shadow-md shadow-sp-highlight/15
```

`/15`, `/30`이 전부 전제 A의 무효 표기다. → **배경도 링도 그림자도 그려지지 않고, 4px 띠
하나만 남는다.** "지금 이 교시"라는 가장 중요한 신호가 의도의 4분의 1만 렌더되고 있다.

**방향: 채워진 면 + 굵기 대비** — 띠·링·그림자를 전부 걷고, 면 하나로 말한다.
"지금"은 화면에서 가장 밝은 면 하나면 충분하다. 네 겹으로 쌓는 것이 바로 "게이머 대시보드"
안티 레퍼런스다.

```
배경    color-mix(in srgb, var(--sp-highlight) 14%, transparent)
테두리  1px, color-mix(in srgb, var(--sp-highlight) 35%, transparent)
글자    text-sp-text font-bold
제거    border-l-4 / ring-2 / shadow-md 전부
```

#### ④ 인용문 (`RealtimeWallCardMarkdown` 1곳)

**방향: 유지.** 인용문 왼쪽 선은 500년 된 타이포그래피 관습이지 AI 티가 아니다.
다만 4px → **2px**, 색을 `border-sp-border`로 낮춰 톤만 정돈한다.

### 한 번에 다 바꾸지 않는다

37곳을 일괄 치환하면 회귀 범위가 통제 불능이 된다. **공용 컴포넌트부터** 손대면 개별
파일 다수가 자동으로 따라온다.

### 리스크

- 메타테스트 2종(`Notice.metatest`, `light-theme-chip-legibility.metatest`)이 권장 문구를
  들고 있어 **함께 갱신 필요.** 검사를 무력화하지 말고 새 기준으로 다시 쓸 것.
- `color-mix` 대비 실측 필요 — 7% 색조 위 `sp-text`가 라이트/다크/뉴트럴 3테마에서
  4.5:1을 넘는지 확인.
- ③번은 **동작이 눈에 띄게 바뀐다**(지금 안 보이던 배경이 생김) → 오너 확인 후 진행.

## 착수 순서 (효과 ÷ 비용)

| 순위 | 작업                          | 파일           | 효과          | 비용                  |
| ---- | ----------------------------- | -------------- | ------------- | --------------------- |
| 1    | **제목줄 유리 합류** (2번)    | 1개 → 14페이지 | 큼            | 아주 작음             |
| 2    | **현재 교시 강조 복구** (4-③) | 2~4개          | 큼(결함 수정) | 작음                  |
| 3    | **좁은 창 헤더 정렬** (1번)   | 4개            | 큼            | 중간                  |
| 4    | **Notice 재설계** (4-①)       | 1개 → 12곳     | 중간          | 중간(메타테스트 동반) |
| 5    | **구글 이메일 축약** (3번)    | 1개 → 5화면    | 중간          | 중간                  |

6순위 이하: 일정 카드 띠 제거(4-②), 인용문 톤 정돈(4-④), 남은 개별 띠 정리.

## 결정이 필요한 것

1. **좁은 창에서 습도를 숨겨도 되는가?** (미세먼지와 우선순위 교체 가능)
2. **"지금 이 교시" 배경이 실제로 칠해지는 변화를 받아들이는가?** (지금은 띠만 보임)
3. **구글 계정 별명 지정 기능이 이미 있는가?** 있으면 그것을 안내하는 쪽이 자동 축약보다 낫다.
4. **37곳 전부 vs 상위 5개만** — 어디까지 이번 작업 단위로 볼 것인가.

## 검증 계획

착수 시 각 단계마다:

```
npx tsc --noEmit && npm run lint && npm run test && npm run regression-check
```

추가로 **실제 창 크기 조절 육안 확인**(1024 / 1280 / 최대화)과
**3테마(라이트·다크·뉴트럴) 전환 확인**이 필수다. 게이트 통과만으로 완료 선언하지 않는다.
