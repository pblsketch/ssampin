### 이번에 내린 설계 판단 3가지

1. **`assertNoPii` 는 기존 `domain/privacy/` 를 재사용한다.** 정규식을 새로 쓰지 않았다 —
   이미 검증된 `detectPatterns`·`detectKeywords` 가 있고, **두 벌이 되면 한쪽만 고쳐진다.**
2. **`assertNoPii` 는 중첩 구조를 재귀한다.** 얕게만 보면 `{ items: [{ title: '김지훈 상담' }] }` 를 놓치는데,
   **실제 위험이 정확히 그 모양**(`get_my_todos.items[].title`)이다.
3. **`checkOutboundText` 결과에 걸린 원문 값을 담지 않는다.** 로그로 새면 관문의 의미가 없다.
   테스트가 `JSON.stringify(result)` 에 전화번호 조각이 없음을 고정한다.

| `학부모 010.1234.5678 통화함`          | O            | O       |
| `031-123-4567`                         | O            | O       |
| `a4755b0f-...-9129-3171a4a53e17`(UUID) | **O (오탐)** | **X**   |

**오탐만 사라지고 정탐은 그대로다.** 두 방향을 다 테스트로 고정했다 —
오탐을 줄이려다 정탐까지 놓치면 관문의 의미가 없다.

## UltraQA (2026-08-21) — 결함 5건 발견, 5건 수정

목표는 "통과했다"가 아니라 **실제 결함을 찾는 것**이었다. 이음매(seam)만 집중해서 봤고,
같은 유형이 이번 작업에서만 **다섯 번** 나왔다: **층은 만들었는데 배선을 잊었다.**

### 결함 1 [치명] 그물 ③(`assertNoPii`)이 배선되지 않았다

`checkOutboundValue` / `checkOutboundText` 를 실제 경로에서 부르는 곳이 **0건**이었다.
이름을 지우는 코드는 **아예 없었다.** 그런데 개인정보처리방침 §11 과 패널 문구는 둘 다
"학생 이름은 전송 전에 지워집니다"라고 **약속하고 있었다** — 코드가 방침을 못 지키는 상태.

재현: 할 일 제목 `"김지훈 학부모 면담"` → 화이트리스트 통과(title 은 허용 필드)
→ 서버는 명단이 없어 한글 이름을 못 잡음 → **그대로 전송.**

**수정**: `src/domain/rules/redactOutbound.ts` 신설 → `useAssistStore.ask()` 안에 배선.

- **관문을 컨테이너가 아니라 `ask()` 안에 뒀다.** 호출자가 빠뜨릴 수 없게 하려고.
- `ask(port, question, cards, roster)` — `roster` 를 **필수 인자**로 만들었다.
- **카드를 통째로 버리지 않고 걸린 자유 입력 칸만 비운다**(계획서 §4.2.2). 버리면 숫자가
  사라져 P5 가 깨진다. 화면에는 **원본**이 남고 포트로는 **지운 사본**이 간다.
- 화면에 "보내기 전에 이름·연락처 N곳을 지웠어요. 위 카드는 그대로예요." 를 띄운다.
  (원래 「나갈 문장」 줄에 `removedNameCount={0}` 이 **하드코딩**돼 있었다 — 그 자리는
  보내기 **전**이라 숫자를 알 수 없다. 카드 아래로 옮겨야 참말이 된다.)

**그물이 진짜 잡는지 실증**: `outbound` → `cards` 로 되돌리니 테스트 2건 빨간불, 복구하니 초록불.

### 결함 2 [높음] `installId` 폴백이 서버 정규식을 통과 못 한다

`crypto.randomUUID` 가 없으면 `t_1787..._x9k2` 형태였는데 서버는 UUID 만 받는다 → **400.**
**수정**: `uuidFallback()` 이 규격대로 v4 모양을 만든다. 200회 생성해 서버와 **같은 정규식**으로 검사.

### 결함 3 [중간] 입력 길이 상한이 앱에 없었다

서버는 한 턴 2,000자에서 자르는데 입력창은 무제한 → 길게 쓴 선생님이 **보내고 나서야** 거절당한다.
**수정**: `ASSIST_MAX_QUESTION_CHARS` 를 도메인에 두고 `maxLength` 로 걸었다.
두 숫자가 어긋나면 테스트가 깨진다(`ASSIST_MAX_QUESTION_CHARS === LIMITS.maxTurnChars`).

### 결함 4 [높음] 제안 칩 4개 중 2개가 카드를 못 만들었다

- `'오늘 우리 반 출결'` → 어느 정규식에도 안 걸림 → **카드 0개**
- `'이번 달 기록 몇 건'` → `몇 명` 과 안 맞음(`몇 건`) → **카드 0개**

칩은 계획서가 **"1층 방어"**라 부르는 주 경로다. 눌러도 숫자가 안 나오면 AI 가 **근거 없이** 답하고
남는 카드도 없어 P5 까지 깨진다. `get_attendance_summary` · `get_records_stats` 두 도구는
**등록·테스트만 되고 아무도 부르지 않는 상태**였다.

**근본 원인**: `summarizeAttendance` 는 "하루·한 학급·학생별 상태" 모양을 받게 설계됐는데
**이 앱은 출결을 그렇게 저장하지 않는다.** 결석·지각한 학생만 기록으로 남는다.
Phase 1 에서 존재하지 않는 데이터 모양을 가정한 것 — 코드베이스 조사 문서에 이미
"전용 스토어 못 찾음"이라 적혀 있었는데도 그대로 갔다.

**수정**:

- `src/usecases/assist/summaries/toAttendanceRoll.ts` 신설 — 기록 있는 학생은 그 상태로,
  없는 학생은 **출석으로 채운다.** 판정은 `extractAttendanceType` **하나만** 쓴다
  (이 함수를 `studentRecordRules.ts` 에서 `export` 로 열었다. 파싱을 복사하면 소분류 형식이
  바뀔 때 한쪽만 고쳐져 **화면 숫자와 AI 숫자가 갈린다**).
- 흩어진 `if` 문을 `INTENT_RULES` **표**로 뽑고 `buildCards()` 를 순수 함수로 분리했다.
  if 문이 흩어져 있으면 칩만 늘리고 규칙을 빠뜨린다 — 실제로 그렇게 됐다.

### 결함 5 [높음] `count_students` 가 다른 반 숫자를 다른 반 이름으로 보여줬다

`countStudents(students, classes[0]?.name ?? '')` —
`students` 는 **담임 명렬표**(`students.json`), `classes[0]` 는 **교과 학급**이다.

## 그물 ③ 재설계 — 지우지 말고 **가리자** (2026-08-21, 오너 결정)

### 왜 바꿨나

UltraQA 직후 남은 열린 항목이 **학번**이었다. 방침은 "이름·학번은 전송 전에 지워진다"고
약속하는데, 할 일 제목에 `"15번 상담"` 처럼 **이름 없이 번호만** 쓰면 그대로 나갔다.

처음 낸 선택지는 둘 다 나빴다 —
① `N번` 을 전부 지우면 `"3번 항목 확인"` 같은 멀쩡한 제목이 통째로 날아가고,
② 방침 문구를 낮추면 보호가 줄어든다.

**두 선택지가 다 나빴던 이유는 둘 다 "지운다"를 전제로 깔았기 때문이다.**
걸리면 칸이 통째로 사라지니 **오탐의 대가가 너무 커서** 애매한 항목은 검사에 넣지도 못했다.

### 무엇으로 바꿨나

쿨메신저용으로 이미 만들어 둔 마스킹 엔진(`src/domain/privacy/maskEngine.ts`)을 그대로 쓴다.
**새로 만든 것이 아니라 있던 것을 연결했다.**

|                        | 예전 (지우기)   | 지금 (가리기)                                     |
| ---------------------- | --------------- | ------------------------------------------------- |
| `"김지훈 학부모 면담"` | `null`          | `"［이름1］ 학부모 면담"`                         |
| AI 가 할 수 있는 말    | 없음            | "학부모 면담이 하나 있어요"                       |
| `"15번 상담"`          | **그대로 유출** | `"［학번1］ 상담"`                                |
| `"3번 항목 확인"`      | —               | `"［이름2］ 항목 확인"` (오탐이지만 한 단어 손해) |

**★절충 — 연락처·주민번호·이메일은 여전히 칸을 통째로 비운다.**
한 칸에 여러 개가 있을 때(`"김지훈 (010-…) 면담"`) 못 잡은 값이 같이 남을 수 있는데,
이 셋은 하나만 새도 피해가 크다. 이름·학번·생년월일·주소는 가리는 쪽으로 간다.

### ★복원 — "이름은 화면에 남고, 숫자만 밖으로 나간다"가 말 그대로 성립한다

`restore()` 를 **화면에 띄우기 직전** 스토어가 돌린다.
모델은 `"［이름1］ 면담이 급해요"` 를 만들고, 선생님은 `"김지훈 면담이 급해요"` 를 본다.
이름은 이 컴퓨터 밖으로 **한 번도 안 나가는데** 답변은 자연스럽게 읽힌다.

별칭 매핑은 개인정보라 **`ask()` 함수 안에서만 살고 상태에 저장하지 않는다.**
모델이 별칭을 망가뜨리면(`"이름1 학생"`) 그 부분만 되돌리기가 실패할 뿐,
**다른 학생 이름이 끼어들거나 원문이 새지는 않는다**(테스트로 고정).

### 문서 정정 — 이제 "지워진다"가 아니다

같은 주장을 하는 곳 3군데를 전부 고쳤다(한 곳만 고치면 안 된다는 이 세션의 교훈).

| 위치                                   | 바뀐 문구                                                                                                                               |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `landing/src/app/privacy/page.tsx` §11 | "［이름1］ 같은 임시 표시로 바뀌어 나가므로 실제 이름은 전송되지 않으며, 연락처·주민등록번호가 포함된 항목은 그 항목 자체가 제외됩니다" |
| `landing/src/content/docs.ts` 쌤핀 AI  | "학생 이름·학번(［이름1］ 같은 임시 표시로 바뀝니다)"                                                                                   |
| `AssistDock.tsx` 입력부                | "이름은 보내기 전에 **가려집니다**"                                                                                                     |
