### 이번에 내린 설계 판단 3가지

1. **`assertNoPii` 는 기존 `domain/privacy/` 를 재사용한다.** 정규식을 새로 쓰지 않았다 —
   이미 검증된 `detectPatterns`·`detectKeywords` 가 있고, **두 벌이 되면 한쪽만 고쳐진다.**
2. **`assertNoPii` 는 중첩 구조를 재귀한다.** 얕게만 보면 `{ items: [{ title: '김지훈 상담' }] }` 를 놓치는데,
   **실제 위험이 정확히 그 모양**(`get_my_todos.items[].title`)이다.
3. **`checkOutboundText` 결과에 걸린 원문 값을 담지 않는다.** 로그로 새면 관문의 의미가 없다.
   테스트가 `JSON.stringify(result)` 에 전화번호 조각이 없음을 고정한다.

앱에서 고쳤던 **UUID 가 전화번호로 오인되는 오탐을 서버 코드에 그대로 다시 넣었다.**
`list_classes` 의 학급 id 가 막혀 정상 요청이 400 이 됐다.

검토에서 지적받은 _"한 곳을 고치면 같은 주장을 하는 다른 곳을 전부 찾아야 한다"_ 가
**바로 다음 파일에서 재현됐다.** 다행히 이번엔 테스트를 먼저 써 둬서 즉시 잡혔다.

수정: 전화 정규식 경계를 `(?<![\d-])` → `(?<![0-9A-Za-z-])` 로 좁혔다. 원본과 대조 확인:

| 입력                                   | 기존 경계    | 수정 후 |
| -------------------------------------- | ------------ | ------- |
| `010-9999-8888`                        | O            | O       |
| `연락처는 010 9999 8888 입니다`        | O            | O       |
| `학부모 010.1234.5678 통화함`          | O            | O       |
| `031-123-4567`                         | O            | O       |
| `a4755b0f-...-9129-3171a4a53e17`(UUID) | **O (오탐)** | **X**   |

**오탐만 사라지고 정탐은 그대로다.** 두 방향을 다 테스트로 고정했다 —
오탐을 줄이려다 정탐까지 놓치면 관문의 의미가 없다.

### ⚠️ 알려진 구멍 (후속 과제)

**`(02)123-4567` 처럼 괄호 지역번호는 못 잡는다.** 여는 괄호 뒤 구분자가 `)` 라
`[-.\s]?` 에 안 걸린다. **내 경계 수정 때문이 아니라 원본 정규식도 못 잡는다**(대조 확인).
