- **작성일**: 2026-08-19

## 1. 결론 — 가능하고, 만들 것이 적다

**고치는 화면을 새로 만들 필요가 없다.** 위젯 모드 모달의 내용물은 별도 화면이 아니라, 카드에 들어가는 **그 컴포넌트를 옵션 하나만 바꿔 그린 것**이다.

```
WidgetCard.tsx:141      <ModalContent isCompactMode={false} />   ← 모달(=고치는 화면)
DashboardTodo.tsx:29    isCompactMode = true                     ← 기본값(카드용 요약)
```

옆핀은 지금까지 `<Body />`를 옵션 없이 그려서 **자동으로 요약본**이 나오고 있었다. `isCompactMode={false}`로 그리면 위젯 모드 모달과 같은 화면이 나온다.

## 2. 대상은 5개다

옆핀에 올릴 수 있는 위젯 9개가 **전부 이미 `modalMode`를 갖고 있다.** 다만 성격이 갈린다.

| `modalMode` | 위젯                                                | 이 작업의 대상인가 |
| ----------- | --------------------------------------------------- | ------------------ |
| `view+edit` | **일정 · 할일 · 디데이 · 즐겨찾는 도구 · 즐겨찾기** | ✅ 대상 (5개)      |
| `expanded`  | 오늘 수업 · 진도 · 급식 · 달력                      | ❌ 크게 보기 전용  |

`expanded` 위젯에까지 여는 단추를 달면 **열어 놓고 "왜 아무것도 안 고쳐지지"**가 된다. 그래서 등록부가 밝힌 것만 연다. 판정은 화면이 아니라 조회 규칙(`SelectSidePinWidgets`)이 `editable`로 내린다 — 새 `modalMode` 값이 생기면 **조용히 "못 고침"** 쪽으로 떨어진다. 늘 위에 떠 있는 창에서 뜻하지 않게 고쳐지는 것보다, 못 고치는 편이 되돌리기 쉽다.

## 3. 모달이 아니라 화면 바꾸기

위젯 모드는 `WidgetModal`을 띄운다. **옆핀에서는 띄우지 않고 칸을 통째로 바꾼다.**

| 왜                                           | 근거                                                                                                                 |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 모달인 이점이 없다                           | 패널 폭이 360~460이라 모달을 띄워도 **어차피 화면을 다 덮는다**                                                      |
| 늘 위에 떠 있는 창에 창을 더 얹으면 헷갈린다 | 이 패널이 삭제 확인·모양 조절·메모 편집기에서 이미 내린 결론                                                         |
| 이 패널의 기존 언어와 맞는다                 | 메모 편집기가 정확히 같은 방식(`목록 ↔ 편집` 전환 + 왼쪽 위 돌아가기 + Esc)                                          |
| 새 변수를 안 만든다                          | `WidgetModal`은 포털·포커스 가둠·바깥 클릭 닫기를 갖고 있어, 늘 떠 있는 별도 창에서 어떻게 도는지 다시 검증해야 한다 |

**폭은 걸림돌이 아니었다.** `modalSize: 'lg'`는 `max-w-4xl`, 즉 **최댓값**이라(`WidgetModal.tsx:75-79`) 400px 창에서는 그냥 폭을 채운다. 다만 `lg`를 전제로 짠 **안쪽 배치**가 좁은 폭에서 눌릴 수 있어, 가로 넘침은 잘라 버리지 않고 스크롤로 닿게 뒀다.

## 4. 진짜 작업 — 접힘, 이 패널에서 네 번째

옆핀은 마우스가 벗어나면 접힌다. 할일을 적거나 일정을 고치는 동안 마우스는 대개 딴 데 있으므로, **그냥 붙이면 쓰는 도중에 접혀 입력이 날아간다.**

착수 전 상태를 보면 이게 왜 선행 작업인지 분명하다.

```
SidePinApp.tsx:280  <SidePinMemoZone ... onEditorActivityChange={reportEditorActivity} />
SidePinApp.tsx:271  <SidePinWidgetZone ... />   ← 창에 아무 말도 안 함
```

메모 칸이 쓰던 장치(`MemoEditorActivity` → `isEditorBusy`가 접힘 차단)를 위젯 칸에도 연결했다.

> 이 패널에서 "접힘"이 문제가 된 자리: ①메모 본문 타이핑 ②파일 대화상자 ③메모 검색 칸 ④위젯 열기. **새 상호작용을 붙일 때마다 다시 물어야 하는 질문**이다.

### 4.1 하마터면 낸 사고 — 신호를 합치면 안 된다

`reportEditorActivity`는 이름만 메모일 뿐 패널 전체의 바쁨 신호처럼 보여서, 위젯 칸도 **그대로 재사용하면 될 것 같았다.** 그런데 그 값은 IPC만 보내는 게 아니었다.

```
SidePinPanel.tsx:162   memoEditing ? 'h-12 flex-none' : `${growth.widget} basis-0`
```

`memoEditing`은 **위젯 칸을 48px 띠로 접는 배치 신호**다. 합쳤다면 **위젯을 여는 순간 위젯 칸이 접혀 방금 연 것이 사라졌을 것이다.**

→ 보낸 칸을 구분해 기억하고(`memoEditing` / `widgetEditing`), 배치는 **거울처럼** 뒀다. 메모를 쓰면 위젯이 접히고, 위젯을 고치면 메모가 접힌다.

**둘 다 참인 경우도 막았다.** 실제로는 한 칸이 48px 띠면 그 안에서 편집을 시작할 방법이 없어 동시에 참일 수 없지만, 만약 그렇게 되면 **둘 다 접혀 아무것도 안 보이고 되돌릴 방법이 없다.** `focusedZone` 한 값으로 좁혀 한쪽만 고르게 했다.

## 7-1. 아직 안 본 것 (다음 실사용에서)

아래는 이번 확인에서 다루지 않았다. 급하지 않아 실사용 중에 본다.

1. **거울 배치** — 위젯을 열면 메모 칸이 48px로 접히는가. 그 전환이 튀지 않는가.
2. **보호 상태** — 위젯을 열어 둔 채 화면이 잠겼다 풀리면 무엇이 보이는가(상세인가 목록인가). 잠긴 동안 패널이 떠 있지 않은 것은 코드로 확인했다(§8).
3. **5개 각각** — 확인한 것은 일정·할일 둘이다. 디데이·즐겨찾는 도구·즐겨찾기는 아직 안 봤다.
4. **가로 스크롤** — 일정·할일은 잘 읽혔다. 나머지 세 개 중 400px에서 표가 밀리는 것이 있는지.

## 8. 하지 않은 것

- **`expanded` 위젯 4개 열기**: 크게 보기 전용이라 조작 요청과 무관하다. 필요하면 별도 결정.
- **`WidgetModal` 재사용**: §3의 이유로 화면 바꾸기를 택했다.
- **위젯 칸에서 목록 순서 바꾸기**: `SelectSidePinWidgets`가 "대시보드에서 고른 순서를 그대로 받는다"를 원칙으로 못박았다.
- **잠금 시 상세 화면 강제 복귀**: 메모 칸은 하고 있으나 위젯 칸은 넣지 않았다. **확인해 보니 필요하지 않다** — `force-protect`가 `editorActivity`를 `'idle'`로 되돌리고 `hide-all`을 함께 보내므로(`resolveSidePinTransition.ts:874-895`, 주석: "잠금·절전에서는 편집 중이라도 화면 내용을 비운다"), **위젯을 열어 둔 채로는 패널이 떠 있을 수 없다.** 게다가 옆핀에 올릴 수 있는 위젯에는 학생 개인정보가 담긴 것이 애초에 없다(자리배치·학생기록·성적은 전부 `eligible: false`). 그래도 잠금 해제 뒤 무엇이 보이는지는 §7-5에서 눈으로 확인한다.
