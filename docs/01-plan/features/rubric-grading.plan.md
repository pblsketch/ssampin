# 수행평가 채점 (rubric-grading) 계획서

- **상태**: Plan v1.1 (오픈 퀘스천 4건 해소 — 사용자 확정)
- **작성일**: 2026-06-12
- **대상 버전**: v2.2.0 (예정)
- **위치**: 수업 관리 페이지 > '수행평가' 탭 신설 (과제 수합 탭 옆)

---

## 1. 배경

### 1.1 시장 근거 (2026-06-11 조사)

- 교사들은 수행평가 점수를 엑셀 수식(합계→급간 변환→나이스 일괄 입력)으로 수작업 관리 중이며, 이를 위한 서식을 직접 만들어 공유할 만큼 수요가 검증되어 있다.
- 8개 반 이상 수업하는 중등 교사일수록 "같은 평가를 여러 반에 반복"하는 부담이 크다.
- 고교학점제 도입으로 평가·기록 업무가 늘어 평가 도구 수요가 커진 시점이다.

### 1.2 쌤핀이 잘할 수 있는 이유

- 수업 관리에 **학생 명단이 이미 있다** — 경쟁 도구처럼 명단을 다시 입력할 필요가 없다.
- **XlsxExporter / PdfExporter / HwpxExporter** 내보내기 인프라 3종이 이미 구현되어 있다.
- 오프라인 완전 동작 + 로컬 JSON 저장 — 학생 평가 정보가 외부로 나가지 않는다.

### 1.3 제품 원칙 준수

- **AI 기능 없음** — 자동 채점·문장 생성 일절 없음. 순수 기록·계산·출력 도구.
- **보상 게이미피케이션 없음** — 점수는 평가·피드백 용도로만.

## 3. 목표 / 비목표

### 목표

1. 교사가 루브릭(평가 기준표)을 만들고, 수업반 학생들을 빠르게 채점하고, 결과를 엑셀로 내보낼 수 있다.
2. 같은 루브릭을 다른 수업반에 복사해 재사용할 수 있다.
3. 채점 결과를 **학생 피드백용 문서(PDF/HWPX)** 로 출력할 수 있다 — 점수 표시 여부 선택 가능.

### 비목표 (이번 범위에서 제외)

- AI 채점·문장 생성 (제품 원칙)
- 만점 환산, 등급(급간) 자동 변환 (D1)
- 학생이 직접 보는 온라인 화면 (QR 접속 등) — 출력물로만 전달
- 표(스프레드시트) 채점 화면 — 1차에서는 카드+목록만 (D3)
- 동료평가·자기평가 수집

## 4. 사용자 시나리오

### 시나리오 A — 채점 (grading)

> 국어 교사 김쌤은 '설득하는 글쓰기' 수행평가 루브릭을 만든다. 평가 요소 3개(주장의 명확성·근거의 타당성·표현), 수준 4개(탁월함 10점 / 잘함 8점 / 보통 6점 / 노력 필요 4점 — 요소마다 점수 다르게 설정). 2반에서 만든 루브릭을 3반·5반에도 복사한다. 발표를 들으며 학생 카드에서 수준을 클릭하고, "근거 출처가 부정확함" 같은 특이사항을 요소 옆에 메모한다. 채점이 끝나면 합계가 자동 계산된 엑셀을 내보내 나이스에 일괄 입력한다.

### 시나리오 B — 피드백 (feedback)

> 김쌤은 점수 산출이 목적이 아닌 형성평가에도 같은 루브릭을 쓴다. 채점 후 학생별로 "체크된 수준 + 요소별 메모 + 총평"이 담긴 피드백지를 **점수 없이** PDF로 출력해 나눠준다. 상담이 필요한 학생 3명만 골라 출력하기도 한다.

## 5. 기능 요구사항

### FR-1 탭 신설

- `ClassManagementPage`의 탭 배열에 `rubric`(가칭) 탭 추가 — **과제 수합(assignment) 옆**.
- 탭 이름: **수행평가** (UI 텍스트 전부 한국어).
- 수업반 미선택/명단 없음 상태는 기존 `RosterEmptyState` 패턴 재사용.

### FR-2 루브릭 빌더

- 수업반당 루브릭 **최대 10개** (한도 초과 시 안내).
- 루브릭 구성:
  - 제목, (선택) 설명
  - **평가 요소**: 개수 가변 (1~10개 권장 한도), 요소별 이름 직접 입력
  - **수준 (요소별 독립, D7)**: 각 평가 요소가 **자기만의 수준 목록**을 가짐 — 요소마다 수준 개수(2~6개 권장 한도)·이름·배점이 모두 다를 수 있음. 수준 이름 직접 입력 (기본값 4개: 탁월함/잘함/보통/노력 필요 — 수정 가능)
  - **성취 설명 (D5)**: 수준마다 성취 설명 입력란(선택 입력, 예: "근거 3개 이상을 정확한 출처와 함께 제시") — 비워두면 출력물에서 생략
- 편의 기능: 새 평가 요소 추가 시 **직전 요소의 수준 구성(이름·배점)을 기본값으로 복제** — 실제로는 요소 간 수준을 공통으로 쓰는 경우가 많으므로 입력 반복을 줄임
- 루브릭 수정·삭제 가능. 단, **채점 기록이 있는 루브릭의 구조 변경(요소/수준 추가·삭제)은 경고 후 진행** — 기존 채점 기록과의 정합성 규칙은 domain 레이어에서 강제.

### FR-3 채점

- 화면: 왼쪽 학생 목록(번호·이름·채점 완료 뱃지·합계 미리보기) + 오른쪽 선택 학생의 루브릭 카드 (D3).
- 카드에서 요소별로 수준 버튼 클릭 → 즉시 저장(자동 저장), 합계 자동 갱신.
- **요소별 특이사항 메모** 입력란 (요소마다 1개, 자유 텍스트).
- **학생별 총평** 입력란 1개 (피드백 출력물의 마무리 문단용, D6).
- 다음/이전 학생 빠른 이동 (키보드 ↑↓ 지원 권장).
- 미채점 요소가 있는 학생은 '부분 채점' 상태로 구분 표시.
- **결시 표시 (D8)**: 학생을 '결시'로 표시 가능 — 명단에 결시 뱃지, 채점 입력 비활성, 합계 산출 제외.

### FR-4 루브릭 공유 (복사)

- 루브릭 메뉴에서 "다른 수업반에 복사" → 수업 관리에 등록된 다른 수업반 선택(다중 선택 가능) → **독립 복사본 생성** (D2).
- 복사본은 채점 기록 없이 구조(요소·수준·점수·설명)만 복제.
- 대상 반이 이미 10개 한도면 해당 반은 건너뛰고 안내.

### FR-5 엑셀 내보내기

- 기존 `XlsxExporter` 확장. 시트 구성: 번호 / 이름 / 요소별 점수 / **합계**.
- 옵션: 요소별 메모 포함 여부 (기본 미포함 — 나이스 입력용은 점수만 필요).
- 부분 채점·미채점·결시 학생은 빈칸 처리 (0점 강제 금지, D8). 결시 학생은 비고 열에 '결시' 표기.

### FR-6 피드백 문서 출력 (PDF / HWPX)

- 대상 선택: **학생 1명 / 다중 선택 / 전체** (체크박스 명단).
- 형식 선택: PDF 또는 HWPX (기존 `PdfExporter`·`HwpxExporter` 확장).
- **점수 포함 토글**: 끄면 점수·합계를 숨기고 수준 이름·체크 표시·메모·총평만 출력 (피드백 용도).
- 출력물 구성(학생 1명당 1페이지 기본): 루브릭 제목 / 학생 정보 / **요소별 블록**(요소 이름 → 해당 요소의 수준 목록 중 체크 표시 + 성취 설명 + 특이사항 메모) / 총평.
  - 요소마다 수준 개수가 다를 수 있으므로(D7) 하나의 큰 표가 아니라 **요소 단위 블록 레이아웃**으로 출력 — HWPX 표 렌더링 부담도 줄어듦.
- 다중 출력 시 한 파일에 학생별 페이지 연속 생성.

## 6. 도메인 모델 스케치

```
Rubric (루브릭)
├─ id, classId(수업반), title, description?
├─ criteria: RubricCriterion[]      // 평가 요소
│   ├─ id, name, order
│   └─ levels: RubricLevel[]        // 요소별 독립 수준 (D7)
│       └─ id, name, score, description?  // 수준 이름 · 배점 · 성취 설명(선택, D5)
└─ createdAt, updatedAt

RubricGrading (채점 기록)
├─ id, rubricId, classId, studentId
├─ status: 'graded' | 'partial' | 'absent'  // 완료 / 부분 채점 / 결시 (D8)
├─ marks: { criterionId → levelId }         // 체크한 수준
├─ criterionNotes: { criterionId → string } // 요소별 특이사항 메모
├─ overallFeedback?: string                 // 총평 (D6)
└─ gradedAt

도메인 규칙 (domain/rules)
- 수업반당 루브릭 ≤ 10
- 요소 1~10개, 요소별 수준 2~6개 (한도는 설계 단계에서 확정)
- 합계 = Σ (체크된 수준의 score) — 미채점 요소는 합계에서 제외하고 '부분 채점' 표시
- 결시(absent) 학생은 합계 산출·통계에서 제외
- 채점 기록 존재 시 구조 변경 가드
```

- **수준이 평가 요소에 종속**(D7)이므로 루브릭 전체를 하나의 표로 그릴 수 없음 — 빌더·채점 카드·출력물 모두 **요소 단위 블록**으로 설계한다.

## 7. 아키텍처 배치 (Clean Architecture 4레이어)

| 레이어         | 추가물                                                                  | 비고                                       |
| -------------- | ----------------------------------------------------------------------- | ------------------------------------------ |
| domain         | `Rubric`, `RubricGrading` 엔티티 + `rubricRules.ts`                     | 외부 import 금지, 합계 계산·한도·가드 규칙 |
| application    | 루브릭 CRUD / 채점 저장 / 복사 / 내보내기 유스케이스                    |                                            |
| adapters       | `useRubricStore` (Zustand persist) + `ClassManagement/Rubric*` 컴포넌트 | UI 텍스트 한국어, sp-\* 토큰, rounded-xl   |
| infrastructure | `XlsxExporter`·`PdfExporter`·`HwpxExporter` 확장                        | 로컬 JSON 저장                             |

**주의사항 (기존 교훈 반영)**:

- 새 저장 도메인 추가 시 **`syncRegistry.ts`에 반드시 등록** (Google Drive 동기화 매핑 단일 소스 — 누락 시 메타테스트가 잡아줌).
- 모달 UI는 `Modal.tsx` 공용 컴포넌트 + `flex-1 min-h-0` 높이 상속 패턴 준수 (modal-scroll-overflow-fix 교훈).
- UI/UX 작업은 frontend-design 에이전트와 협업 (단독 디자인 금지 정책).

## 8. 단계별 구현 계획

| Phase | 범위                                              | 완료 기준                                     |
| ----- | ------------------------------------------------- | --------------------------------------------- |
| **1** | 도메인 모델 + 루브릭 빌더 + 탭 신설               | 루브릭 생성·수정·삭제, 한도 가드, 단위 테스트 |
| **2** | 채점 화면 (카드+목록) + 요소별 메모 + 총평 + 합계 | 자동 저장, 부분 채점 표시, 키보드 이동        |
| **3** | 루브릭 복사(공유) + 엑셀 내보내기                 | 다중 반 복사, 나이스 입력용 시트              |
| **4** | 피드백 출력 (PDF → HWPX) + 점수 토글 + 대상 선택  | 1명/선택/전체 출력, 점수 숨김 검증            |

- Phase 4에서 **PDF를 먼저, HWPX를 나중에** — HwpxExporter의 표 렌더링 가능 범위 확인이 선행 리스크 (§9 R-1).
- 각 Phase 종료 시 검증 게이트 4종 (tsc 0 / lint 0 / vitest / regression) 통과 필수.
