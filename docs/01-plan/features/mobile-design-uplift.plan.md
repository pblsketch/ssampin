## 1. 한 줄 결론

모바일 앱은 **뼈대(토큰·다크모드·세이프에어리어·터치 피드백)는 이미 준수한 수준**인데, **마감(색상 규칙 이탈 149건 · 이모지 아이콘 · 화면마다 다른 헤더/카드 스타일 · 9px 글씨 · 밋밋한 빈 화면)이 범용 템플릿 수준**이라 "전문 디자이너가 만진 앱" 느낌이 나지 않습니다. 새로 갈아엎을 필요 없이, **5단계 마감 공사**로 끌어올릴 수 있습니다.

### 2-2. 코드 감사 핵심 (파일:라인 근거는 `code-audit.md`)

**심각도 상**

1. **raw 색상 149건 / 55파일** — "sp-\* 토큰만 사용" 규칙(design-system.md) 위반. 다크모드에서 색이 어긋날 수 있는 시한폭탄. 대표: `SchedulePage.tsx:22-44`(일정 색 9종이 전부 raw), `students/shared.ts`, `ToolSurveyPage.tsx`
2. **초소형 텍스트 상시화** — 하단 탭 라벨 9px(`App.tsx:498`), 8px `micro` 토큰까지 존재(`tailwind.config.js:71-74`). 모바일 최소 가독 기준(11~12px) 미달
3. **44px 미만 터치 타깃** — 헤더 계정 버튼(크기 미지정), 카드 접기 토글 28px(`CollapsibleCard.tsx:67`), 메모 삭제 32px(`MemoPage.tsx:307`)
4. **한 앱에 표준이 여러 개** — 헤더 2종(유리 효과 vs 평면), 카드 모서리 3종(20px vs 12px vs 문서 규범 12px), 모달 2종(유리 vs 불투명), 버튼 모서리 3종

**심각도 중** 5. 이모지 아이콘 ↔ Material Symbols 혼용 (V1·V2와 동일 근원) 6. 공용 컴포넌트(EmptyState/Spinner) 만들어 놓고 안 씀 — TodoPage·SchedulePage는 인라인 자체 구현 7. 삭제(위험) 색상이 화면마다 다름 — `text-red-400`(raw) vs `bg-sp-error`(토큰) 8. 애니메이션 줄이기 설정(prefers-reduced-motion) 부분 대응 9. `text-gray-400` 저대비 텍스트 2곳

**심각도 하** 10. 햅틱(진동 피드백) 유틸이 있는데 3곳만 사용 11. 스켈레톤 로딩(뼈대 미리보기) 사실상 부재 — WeatherCard 1곳뿐 12. 인라인 style 53건 13. 문서-구현 불일치(문서엔 Noto Sans KR, 실제는 Pretendard) 14. 라우터 부재 → 하드웨어 뒤로가기 미지원 (이번 범위 제외 — 구조 공사라 별도 PDCA)

### 2-3. 이미 잘 되어 있는 것 (건드리지 않음)

## 3. 디자인 방향 — "정돈된 교탁 위의 온기"

ui-ux-pro-max 엔진에 쌤핀 특성(교사용 생산성 도구, 전문적·따뜻함)을 넣어 얻은 추천과 브랜드 문서(`.impeccable.md`)를 결합한 방향입니다.

| 축            | 결정                                                                                                            | 근거                                                                              |
| ------------- | --------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| **스타일**    | 현 글래스모피즘 유지 + **Micro-interactions 스타일** 강화 (엔진 추천: 생산성 도구 1순위, 성능·접근성 모두 우수) | 갈아엎기가 아니라 마감 강화. 엔진이 제안한 클레이모피즘(어린이용)은 기각          |
| **색**        | **sp-\* 토큰 단일화** (새 팔레트 도입 없음). 파랑 #3b82f6은 공식 브랜드 강조색이므로 유지                       | 브랜드 문서·데스크톱과 일치. 문제는 색 자체가 아니라 규칙 이탈                    |
| **온기 주입** | 이모지 대신 **쌤핀이 마스코트**를 빈 화면·온보딩·에러 화면의 공식 일러스트로 승격                               | "따뜻함" 브랜드 가치를 앱 안에서 표현하는 유일한 자산. 앱 아이콘과 내부 무드 통일 |
| **타이포**    | **Pretendard Variable을 공식 기본 폰트로 확정**(문서 정정 포함), 최소 크기 11px로 상향                          | 이미 로드 중인데 문서만 구식. 9px 탭 라벨은 가독 미달                             |
| **아이콘**    | **Material Symbols Outlined 단일 체계** + 도구별 시맨틱 컬러 칩 배경                                            | 데스크톱과 동일 체계. 이모지 전량 교체                                            |
| **모션**      | 마이크로 인터랙션 150-300ms 표준화 + 스켈레톤 로딩 + reduced-motion 전면 대응                                   | 엔진 UX 가이드라인 §7                                                             |

> **안티 레퍼런스 준수**: 과도한 네온/글로우 금지, 게이미피케이션 금지([[feedback_no_reward_gamification]]), 라운드는 Tailwind 기본 키만([[feedback_rounding_policy]]).

## 4. 실행 계획 — 5단계

각 단계는 독립 커밋 가능하고, 단계마다 검증 게이트(§5)를 통과해야 다음으로 넘어갑니다.
순서 원칙: **기반(토큰) → 표준(컴포넌트) → 표면(화면) → 감성(모션) → 마감(접근성)**.

### M1. 토큰 기강 잡기 (기반 공사) — 규모: 중

동작 변화 없는 순수 색·수치 치환. 이후 모든 단계의 전제.

- [ ] raw 색상 149건 → sp-_ 토큰 치환. 부족한 의미 토큰은 신설: `--sp-schedule-_`(일정 9색), `--sp-priority-\*`(할일 우선순위), 삭제 색은 `sp-error`로 통일
- [ ] 카드 모서리 표준 확정: `.glass-card` 20px → **`rounded-xl`(12px)로 통일** (문서 규범과 일치, 덮어쓰기 코드 제거)
- [ ] `micro`(8px) 폰트 토큰 삭제, `tiny`(9px)는 신규 사용 금지 처리. 하단 탭 라벨 9→11px
- [ ] 문서 정정: design-system.md 기본 폰트 Pretendard Variable로
- [ ] 이탈 방지 장치: 모바일 raw 팔레트 사용을 잡는 ESLint 래칫(현재 건수를 상한으로 고정, 신규 추가 차단)

### M2. 컴포넌트 표준화 (한 앱 = 한 표준) — 규모: 중

- [ ] **헤더 통일**: `MobileHeader` 공용 컴포넌트 1종(유리 효과 표준, 뒤로가기 44px, 타이틀 규격). 기존 `docs/계획_페이지헤더-통일.md` 초안 반영
- [ ] **모달/바텀시트 셸 통일**: 1종 표준(배경·모서리·손잡이·세이프에어리어), MemoPage 내부 중복 모달 2개와 SchedulePage 인라인 모달을 표준 셸로 이관
- [ ] **EmptyState/Spinner 전면 채택**: TodoPage·SchedulePage 등 인라인 구현 제거
- [ ] **버튼 모서리·높이 표준**: 주 버튼 `rounded-xl`·min-h 48px 단일화
- [ ] PWA 설치 배너 위치 수정 — FAB과 겹치지 않게 (V3)

### M3. 화면 표면 공사 (보이는 인상) — 규모: 대

- [ ] **이모지 아이콘 전량 교체**: 쌤도구 11종 → Material Symbols + 도구별 컬러 칩, 섹션 헤더·우선순위·안내 문구 이모지 제거
- [ ] **쌤핀이 빈 화면 시스템**: 빈 상태 4대 화면(좌석/일정/할일/급식)에 쌤핀이 일러스트 + 행동 유도 버튼("PC에서 시간표 등록하기" 안내 등). 소스: `public/floating-pin.png` 계열 자산
- [ ] **온보딩 리디자인**: 이모지 히어로 → 쌤핀이 일러스트, 6단계 유지하되 진행감 강화(현 점 인디케이터 개선)
- [ ] **홈 정보 위계 재조정**: 날짜를 헤더로 승격하고 "쌤핀" 워드마크는 축소 — 큰 제목 1개 원칙 (V5)
- [ ] 캘린더·좌석·시간표 등 조회 화면의 타이포 위계 점검(숫자는 tabular-nums)

### M4. 모션·체감 품질 — 규모: 중

- [ ] 모션 토큰 통일(150-300ms, ease-out 진입/ease-in 퇴장) + 페이지·탭 전환 시 콘텐츠 페이드/슬라이드 1종
- [ ] **스켈레톤 로딩** 도입: 홈 카드·학생 목록·일정 리스트 (현 "불러오는 중..." 텍스트 대체)
- [ ] 리스트 진입 스태거(항목당 30-50ms 지연) — 홈 카드·쌤도구 그리드
- [ ] **prefers-reduced-motion 전면 대응** (모든 keyframes·scale 효과)
- [ ] 햅틱 확대: 출결 체크·할일 완료·탭 전환 등 확인성 액션에 적용 (iOS 무효는 수용, Android에서만 동작)

### M5. 접근성 마감 — 규모: 소

- [ ] 터치 타깃 44px 미달 전수 수정(헤더 버튼·카드 토글·삭제 버튼·색상 도트 — hit area 확장 방식)
- [ ] 아이콘 전용 버튼 aria-label 보완(계정변경·로그아웃·뒤로가기)
- [ ] 저대비 텍스트 교정(`text-gray-400` 2곳, 반투명 red 텍스트)
- [ ] 라이트/다크 양쪽에서 본문 4.5:1 대비 검증

### 범위 제외 (별도 PDCA 후보)

- 라우터 도입(하드웨어 뒤로가기·딥링크) — 구조 공사, 회귀 리스크 큼
- 모바일 기능 추가 — `mobile-field-tools.plan.md` 등 기존 트랙과 분리 유지

## 5. 검증 게이트 (매 단계 공통)

```bash
npx tsc --noEmit          # 타입 에러 0
npm run lint              # ESLint 통과 (M1부터 raw 팔레트 래칫 포함)
npx vitest run --pool=forks   # 테스트 통과
npm run regression-check  # 회귀 체크
npm run build:mobile      # 모바일 빌드 성공
```

- **실화면 검증**: `npm run dev:mobile -- --host 127.0.0.1` → 390px 뷰포트에서 변경 화면 캡처, 이번 분석 스크린샷(before)과 비교. 라이트/다크 모두. 단계 완료 시 스크린샷을 `docs/03-analysis/mobile-design-uplift/after/`에 보관.

**알려진 함정 (필수 숙지)**

- sp-\* 토큰에 Tailwind 투명도 수식(`bg-sp-accent/40`) 무효 — 조용히 투명 렌더됨. opacity 유틸로 대체
- vite 개발 서버 2개 동시 실행 금지(무한 로딩) — 검증 전 기존 서버 확인
- 파일 이동/치환 시 ESLint 래칫 화이트리스트 승계 필수(ADR-018)
- 브라우저 모드는 명단 데이터가 비어 있음 — 좌석/출결 실데이터 확인은 Electron 동기화 계정 필요

## 6. 진행 방식 제안

- 한 세션 = 한 단계(M1~M5). main 단일 워킹트리, 단계 완료 시 커밋
- M3(쌤핀이 일러스트·화면 공사)는 frontend-design 협업 의무 대상 — designer 에이전트와 시안 합의 후 구현
- 쌤핀이 빈 화면용 일러스트 자산이 부족하면: 기존 `floating-pin.png` 변형으로 시작, 추가 포즈는 이미지 생성으로 별도 제작(사용자 확인 후)

## 7. 사용자 결정 필요 사항

1. **이 계획 승인 여부** (M1부터 순차 착수)
2. **쌤핀이 일러스트 추가 포즈 제작 방식** — 기존 자산 재활용만 vs 신규 생성(생성 시 시안 확인 절차 필요)
3. 하단 탭 라벨 크기 상향(9→11px)으로 탭바가 약간 높아질 수 있음 — 허용 여부
