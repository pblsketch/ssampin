## §S. step-2 확정 결정 (코디네이터 — 사용자 실행 위임 하)

§9의 실행 차단 분기 5건은 다음으로 확정한다:

1. **Option D 채택 — 진짜 D로 확정(Architect 2차 변경 2)**: **담임 소유 얇은 셸 + 공유 headless 프레젠테이션 코어 + 공유 도메인**. "완결형 셸 중립 승격+확장점 props" 경로는 사실상 확장점 붙은 A(blast radius 공유)이므로 **채택하지 않는다**. 공유 대상은 (a) `attendanceRules.ts` 순수 함수, (b) 날짜/저장/dirty 없는 headless 그리드 코어(§4 P4에 표면 정의)에 한정한다.
2. **Phase 순서 = 전략 1(탈위험 우선)** — `P1a → P2 → P3 → P4(⊃P1b) → P5 → P6`.
3. **글씨 확대 = 기본 상향** (설정 옵션 아님, 격자 리플로우 포함).
4. **PC 통계 위치 = ProgressMode(담임 통계 서브탭) 확장** (별도 진입점 아님).
5. **기록자 모델 = 단일 기록자(그리드)** — 카드 경로 출결 유형 제거 + 릴리즈 노트 고지.

**§6 선확인 완료**: ADR-019 병합 테스트 **존재 확인** — `src/usecases/sync/__tests__/mergeAttendance.test.ts`(확장 대상). 번호 충돌 가드 테스트 `src/adapters/stores/__tests__/attendanceNumberCollision.repro.test.ts`, 도메인 규칙 테스트 `src/domain/rules/attendanceRules.test.ts`도 존재(P1a는 이 파일 확장). `pickRepresentativeAttendance`는 `attendanceRules.ts:167` 실존 확인, `computeAutoPeriods` 부재 확인(신설 대상).

## §R. 규정 확인 결과 (2026 기재요령 원문 검증 — 사용자 지시 반영, v2 이후 수정)

사용자 지시("규정 관련한 건 2026 학생생활기록부 기재요령을 찾아서 제대로 확인한 뒤에 구현")에 따라 **교육부훈령 제555호(2026.3.1 시행) 별표 8 + 2026학년도 기재요령(중학교, 17개 시도교육청 공동, p55~66) 원문**을 확인했다. 상세 근거·인용은 `regulation-evidence.md` 참조. 계획에 미치는 변경:

1. **[P1a 변경] "지각 시 등교 전 교시 자동 결시(결과) 처리" 토글 폐기.** 별표 8 §3 바 — "같은 날짜에 지각, 조퇴, 결과가 발생한 경우에는 **학교장이 판단하여 어느 한 가지 경우로만 처리**한다." 지각한 날 등교 전 교시를 '결과'로 추가 집계하는 것은 이중 집계로 기재요령과 정면 충돌한다(학교 재량 영역이 아님). `attendanceLatePriorAbsent` Settings 필드·설정 UI 항목을 계획에서 **삭제**한다 → P1a는 Settings 무변경, 도메인 순수 함수+테스트만으로 더 단순해진다.
2. **[P1a 변경] 지각 자동 채움 = 건의 원문 그대로 '지각' 상태 채움.** `computeAutoPeriods('late', ref, n)` = **{조회..ref}** (해당 교시들을 status='late'로 기록 — 쌤핀 내부 세분화이며 규정과 충돌 없음. 건의: "지각 3교시를 클릭하면, 조회, 1,2,3교시가 모두 자동으로 체크").
3. **[P6 변경] 나이스식 통계는 일 단위 대표 접기 의무.** 규칙 바(하루 한 가지) + 사("같은 날짜에 결과가 1회 이상이라도 1회로 처리") → 교시별 저장은 유지하되 집계는 `pickRepresentativeAttendance`(absent>earlyLeave>late>classAbsence — '학교장 판단'에 대한 쌤핀 기본 우선순위)로 하루 1건으로 접는다. 표에 "동일 날짜 중복은 규정상 한 가지로만 집계(학교장 판단), 쌤핀은 심각도 우선" 각주 표기.
4. **[P6 변경] '인정' 사유 지각·조퇴·결과는 횟수 미포함.** 규칙 라 — 출석인정 사유로 인한 지각·조퇴·결과는 각각의 횟수에 포함하지 않는다. 생기부식 매트릭스에서 '인정'은 카운트 제외(별도 참고 표시는 허용). 사유 축은 규칙 마에 따라 질병·미인정·기타 3분류가 공식 집계 축.
5. **[안내 문구] 같은 날 복수 기록(지각+조퇴 등)은 쌤핀(개인 보조 기록장)에선 허용**하되, 통계·나이스 전기 관점의 안내 문구를 표기 — v2의 방침과 동일하나 이제 훈령 원문이 근거.

## §1. Principles (원칙 — 재사용 원칙 정제)

1. **예외 기반 입력(Exception-based).** 정상 출석은 무입력, 예외 학생만 손댄다. 나이스의 "전원 필수 입력" 마찰을 답습하지 않는다.
2. **재사용은 "도메인·프레젠테이션 코어"에서 하고, "완결형 셸"은 기능이 소유한다. (v2 정제 — Critic FAIL #1 대응)** `attendanceRules.ts`의 순수 함수(`cycleStatus`/`buildAttendanceMatrix`/`summarize*`/`pickRepresentativeAttendance`)와 작은 공용 프레젠테이션 코어는 공유하되, 자체 저장/날짜/dirty/일괄을 가진 완결형 셸(`AttendanceMatrixCore`)을 통째로 다른 기능에 끌어쓰지 않는다. "재사용"이 결합 증가로 전도되지 않게 한다.
3. **AttendanceRecord 불변 = 동기화 무회귀.** 저장 경로를 바꾸더라도 담임 미러(`bridgeHomeroomDayAttendance`, `number→studentId` 재매핑 포함)와 번호 충돌 가드를 반드시 승계한다.
4. **자동화는 초기값일 뿐, 항상 override 가능.** 자동 채움은 controlled 초기 Set. **규정에 반하는 자동화는 만들지 않는다**(§R — 지각 자동 결시 토글 폐기, 별표 8 §3 바). **비-present 상태는 절대 빈 Set을 산출하지 않는다**(빈 Set=전 교시 오해석 방지).
5. **진정 독립 Phase만 "독립"이라 부른다.** 순수 함수(P1a)만 화면 무관 독립 출시. UI 배선(P1b)은 최종 소비 화면(그리드=P4)에 소속되며 독립 Phase가 아니다.

## §2. Decision Drivers (상위 3)

1. **매일 반복 체감(사용자 1순위).** 일일 출결 체크 단축(건의 1·4)이 체감 이득 최대.
2. **회귀 격리 / 동기화 무회귀.** ADR-019 병합·툼스톤·담임 미러가 얽혀 저장 경로 변경(건의 1·5)이 최고 위험. 재사용 방식이 회귀 blast radius를 결정한다. **→ 이 드라이버가 §3 Option A vs D를 가른다.**
3. **기존 동선 공존.** InputMode는 관찰/상담/생활 기록과 화면 공유. 출결 보강이 기존 멘탈모델을 깨지 않아야 한다.

## §3. Viable Options (선택지 — Option D 추가)

### Option A — 셸 통째 재사용

`AttendanceMatrixCore`를 `ClassManagement/shared`에서 그대로 담임 화면(InputMode)이 import.

- **Pros**: 앱 전체 동일 그리드(학습비용 최저), 초기 diff 작음.
- **Cons**: 그리드는 자체 저장/날짜/dirty/일괄을 가진 완결형이라(`AttendanceMatrixCore.tsx:85-104,227-288,526-544`) 담임 4대 요구(미러 재매핑·렌더 게이트 가드·자동채움 어포던스·P5 다중선택)를 조건분기로 흡수 → **수업관리 출결과 회귀 blast radius 공유**. Homeroom→ClassManagement/shared 역참조(구조 냄새). 저장 버튼 2개·날짜 2개 UX 섬.

### Option B — 출결 전용 신규 모듈 신설

입력+일괄+통계+인쇄 통합 신규 화면.

- **Pros**: 전용 UX, 크라우드된 InputMode 미접촉.
- **Cons**: 신규 표면 과다, 로직 중복, 동기화 접점 다중화, 순차 소단위 원칙 충돌, 첫 가치 지연. → **기각**(강점은 D+P6 신규 통계로 흡수).

### Option C — InputMode 학생 리스트 원탭만

그리드 없이 좌측 리스트에 클릭=상태 순환만.

- **Pros**: 최소 변경.
- **Cons**: 나이스식 교시×학생 매트릭스 이점 없음, 앱 내 출결 UI 이원화, 건의 4·5 시너지 약함. → **기각**(D의 P4 fallback으로만 보존).

### Option D — 도메인 재사용 + 얇은 담임 셸 (v2 신규 · **Planner 추천**)

`attendanceRules.ts` 순수 함수 + 작은 공용 프레젠테이션 코어만 공유. 완결형 셸을 재사용할 경우 **`ClassManagement/shared`에서 중립 위치(`adapters/components/attendance/shared`)로 승격 + 확장점(외부 저장·날짜 위임·가드 게이트·자동채움 훅·다중선택)을 props로 명시**. 담임 전용 요구(미러·가드·자동채움·다중선택)는 담임 셸이 소유.

- **Pros**: 도메인만 공유해 회귀 격리(드라이버 #2 지배), 담임 요구가 셸에 자연 소속(조건분기 미축적), 폴더 소유권 정상화, P5 다중선택·P1b 자동채움이 담임 셸에 깔끔히 착지.
- **Cons**: 얇은 셸 신설 or 중립 승격의 초기 diff·설계 비용(중). 담임/수업 셸이 미세하게 상이할 수 있음(학습비용 중).

### 드라이버별 A vs D 대조 (지시 1)

| 드라이버               | Option A (셸 통째)                            | Option D (도메인+얇은 셸)         |
| ---------------------- | --------------------------------------------- | --------------------------------- |
| #1 매일 반복 체감      | 동일(같은 그리드 UX)                          | 동일(공용 코어로 UX 재현)         |
| **#2 회귀 격리(핵심)** | **낮음** — 한 셸이 두 기능, blast radius 공유 | **높음** — 도메인만 공유, 셸 독립 |
| #3 기존 동선 공존      | 조건분기 누적으로 InputMode 복잡화            | 담임 셸이 요구를 자연 흡수        |
| 폴더 소유권            | Homeroom→ClassManagement 역참조(냄새)         | 중립 승격 or 각자 소유(정상)      |
| 초기 속도              | 빠름(단 분기 누적)                            | 중(셸 신설/승격)                  |

**Planner 추천: Option D.** 근거 — 명명된 상위 드라이버 #2(회귀 격리)에서 D가 A를 지배한다. 담임 전용 4대 요구(미러 재매핑·렌더 게이트·자동채움·다중선택)는 정확히 "공유 셸을 오염시킬 조건분기"이며, D에서는 담임 소유 코드에 소속되어 수업관리 출결의 회귀 표면과 분리된다. UX 일관성(나이스 멘탈모델)은 공용 프레젠테이션 코어로 대부분 보존된다. 초기 비용(셸 승격)은 P5·P1b가 어차피 이 셸에 착지하므로 상환된다.
**A vs D 채택은 §S-1에서 진짜 D(담임 소유 얇은 셸 + 공유 headless 코어)로 확정됐다**(Architect 2차 변경 2 — "셸 승격+props 공유"는 확장점 붙은 A와 같아 드라이버 #2를 훼손하므로 배제). 이하 §4는 확정안 기준으로 기술한다.

## §4. 상세 Phase 계획 (D 기준)

### 순서 원칙 및 의존 그래프 (지시 3·12)

**정정 의존 그래프**: `P1a(독립) → [P4 ⊃ P1b] → P5`, 그리고 `P2 · P3 · P6 독립`.

- P1a는 화면 무관 순수 함수 → 어떤 화면보다 먼저 출시 가능(진정 독립).
- P1b(자동채움 어포던스)는 P4 그리드에 흡수 — 독립 Phase 아님.
- P5(다중선택)는 P4 그리드 위에 얹힘 → P4 선행.
- P2·P3·P6은 상호·타 Phase와 결합 없음.

**Phase 순서 — Stakeholder 노트 반영(지시 12).** Critic은 "대표 가치(건의 1 입력 단축)가 최고위험 P4에 인질 잡혔고, P4의 단축 효과가 그리드 내 자동채움(P1b)에 의존한다"고 지적했다. 이를 순서 근거에 반영해 **두 전략**을 제시하고, Phase 순서를 실행 차단 step-2 결정(§9)으로 올린다.

- **전략 1 (탈위험 우선 — Planner 기본 추천): `P1a → P2 → P3 → P4(⊃P1b) → P5 → P6`.** 저위험·즉시 체감(P2 영속·P3 스와이프)을 먼저 출시해 안전 가치를 조기 확보하고, 그리드 패턴이 익은 뒤 최고위험 P4에 착수. **대표 가치 P4는 최종이 아니며 P5·P6이 뒤따른다**(인질 우려 부분 완화). 단, 건의 1이 세 Phase 뒤로 밀리는 트레이드오프 잔존.
- **전략 2 (플래그십 우선): `P1a → P4(⊃P1b) → P5 → P2 → P3 → P6`.** 건의 1을 의존성이 허락하는 최단(2번째)에 배치해 대표 가치를 조기 인도. 대신 최고위험 작업을 전면 배치(P4 지연 시 첫 체감 가치가 늦음). P1a가 순수 함수 리스크를 선제거하고, P4 fallback(얇은 셸 축소)이 안전판.

두 전략 모두 의존 제약(P1a→P4→P5)을 만족한다. 가치 대 리스크 선호는 사용자 결정 → §9 step-2.

    - (ii) fallback — 그리드가 **저장 직전 신선 레코드 재시드** 후 병합 저장(두 경로 공존 유지, 병합 복잡도·인코드 경고 재현 위험).
  - **저장/날짜 섬 UX 해소**: `hideDateInput`으로 그리드 자체 날짜 숨기고 호스트(InputMode)의 날짜·단일 저장에 위임 → 한 화면 저장 버튼 1개·날짜 1개.

- **periodCount 단일 출처(Architect 2차 변경 5)**: 담임 그리드의 `periods` prop과 `computeAutoPeriods`의 `periodCount`는 **동일 출처(settings의 maxPeriods)**에서 도출한다. 그리드 `DEFAULT_PERIODS`(1..8)와 카드 `maxPeriods ?? 7`(`InputMode.tsx:101`)의 불일치로 자동채움과 교시축이 어긋나는 것을 방지.
- **글씨 확대 = 레이아웃 리플로우(지시 7/m2)**: 그리드 셀은 고정 `w-9 h-9` + `text-base` 아이콘, 헤더 `text-xs`(`AttendanceMatrixCore.tsx:461,401`). 폰트 상향은 **40×40 격자 리플로우 작업**이지 `seatingNameSize` 식 토큰 스위치가 아니다. 규모에 이 리플로우 포함 → **M→L 재산정.**
- **fallback(위험 시)**: Option C(InputMode 리스트 원탭 순환만)로 축소.
- **완료 기준**: §5 P4 + §6 회귀 케이스.

### P5 — 일괄 입력 확장 (건의 5) · 규모 L · P4 선행

- **어댑터**: (a) 다중 학생 선택 → "선택 학생 일괄 적용" 바(상태+사유+교시+메모). (b) `MultiDatePicker`에 시작~종료 범위 + 비수업일 자동 스킵.

### P6 — 학급 통계 한 화면 + 인쇄 (건의 6) · 규모 M(모바일)/L(PC 신규) · 독립 · §R 반영

- **집계 의미 정의(지시 9 + §R-3·4 — 기재요령 별표 8 §3 근거)**: 나이스식 주/월/연 매트릭스는 **일 단위 기준**(전일 결석 = **1일**, N교시 아님). 현 모바일 `AttendanceStatsTable`의 연인원(person-period) 합산과 구분한다.
  - **일 단위 대표 접기는 기존 `pickRepresentativeAttendance`(`attendanceRules.ts:167`, absent>earlyLeave>late>classAbsence) 재사용** — 규칙 바("같은 날 지각·조퇴·결과는 한 가지로만 처리")와 사("같은 날 결과 1회 이상이라도 1회")를 동시에 충족한다. 우선순위는 '학교장 판단' 사항에 대한 쌤핀 기본값임을 표 각주로 명시.
  - **'인정' 제외 × 대표 접기 합성 순서 고정(Architect 2차 변경 6)**: `pickRepresentativeAttendance`는 **사유(reason)를 보지 않으므로**(status 전용 우선순위, `attendanceRules.ts:153-192`), 규칙 라는 **reason-aware 사전 필터 → 대표 접기** 순서로 구현한다 — 즉 reason='인정' 엔트리를 먼저 제거한 교시맵을 접는다. 신규 주/월/연 버킷팅 순수 함수는 reason 인지 함수로 설계(단위 테스트에 합성 순서 케이스 포함). 공식 사유 축은 질병·미인정·기타 3분류(규칙 마).
  - 연인원 요약은 보조 뷰로 병존 가능(생기부식 표와 명확히 구분 라벨). **고지(변경 7)**: §R-2의 "지각=조회~등교 교시를 late로 기록" 결정으로 연인원(person-period) 뷰에서는 지각 1회 등교가 late N교시로 팽창해 보인다 — 보조 뷰 라벨에 "교시 연인원 기준" 명시.
- **모바일(확장)**: `AttendanceStatsTable`에 열 헤더 탭→사유 드릴다운, 학생 행 클릭→날짜별 세부(사유·메모·교시) 마스터-디테일. 기간필터 재사용.
- **PC(신규 — B 흡수)**: 나이스식 표(행=학생, 열=상태 일수 합계, 헤더 탭 시 사유 드릴다운) + 기간(주/월/학기/연/커스텀). **위치는 ProgressMode(담임 통계 서브탭) 확장으로 확정**(§S-4).
- **인쇄(신규 배선)**: 기존 `PrintCurrentView.ts`/`ElectronPrinterAdapter.ts` 또는 브라우저 인쇄 CSS(A4 가로). "화면용 요약 / 학기말 전체 매트릭스" 2종.
- **도메인**: `pickRepresentativeAttendance` + 주/월/연 버킷팅 순수 함수 신설(단위 테스트 대상).
- **완료 기준**: §5 P6.

## §5. Phase별 수용 기준 (테스트 가능)

## §10. ADR 초안 (리뷰 후 확정 — DECISIONS.md 등재용)

- **Decision**: 출결 개선은 **진짜 Option D(담임 소유 얇은 셸 + 공유 headless 코어 + 공유 도메인)** 기준, **AttendanceRecord 불변**·독립 Phase 분할(P4는 P4.1~P4.4 커밋 단위 분해). 자동채움은 순수 함수(P1a) 독립 출시 + 어포던스는 그리드(P4.3) 신설. 출결은 **단일 기록자=그리드**. 통계는 기재요령 별표 8 §3 정렬(reason-aware 사전 필터 → 일 단위 대표 접기). 모든 step-2 분기는 §S에서 확정 완료.
- **Drivers**: 매일 반복 체감 / 회귀 격리 / 기존 동선 공존.
- **Alternatives considered**: A(셸 통째 재사용) — 회귀 표면 공유로 열위. B(신규 모듈) — 순차 원칙 충돌 기각. C(원탭) — UI 이원화 기각(P4 fallback 보존).
- **Why chosen**: 드라이버 #2(회귀 격리)에서 D가 A 지배. 담임 4대 요구가 셸에 자연 소속, UX 일관성은 공용 코어로 보존.
- **Consequences**: 셸 중립 승격 or 얇은 셸 신설(초기 비용), 카드 출결 제거 시 UX 변경(릴리즈 노트), Settings 무변경(§R로 토글 폐기), 통계는 기재요령 별표 8 §3(바·사·라·마) 정렬 — 일 단위 대표 접기·'인정' 제외.
- **Follow-ups**: PC 통계 위치·인쇄 방식, 데스크톱 뷰 영속, 기재요령 연차 개정 시 별표 8 재확인.
