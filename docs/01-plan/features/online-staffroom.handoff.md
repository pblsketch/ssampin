## M1 범위 (이번에 만들 것)

부서를 만들고 사람을 모으는 데까지. 게시판·자료실·토론방·갤러리는 **M2 이후이므로 만들지 않는다.**

- 사이드바에 `온라인 교무실` 탭 추가 + 부서 목록 화면(빈 상태 포함)
- 부서 만들기 (이름·한 줄 소개. 배너 꾸미기는 M4)
- 초대: **링크 + 코드 발급**, 만료일 설정, QR 표시
- 참여: 초대 코드 입력 → **구글 로그인으로 신원(지메일) 확인** → 멤버 등록
- 멤버 관리: 목록, 내보내기, 관리자/일반 2단계 권한
- 관리자 구글 토큰 보관 (기존 `save-teacher-token` 패턴 재사용)

## 반드시 지킬 설계 결정 (틀리면 처음부터 다시 해야 하는 것들)

1. **초대 코드는 숫자 6자리가 아니다.** 기존 `src/domain/valueObjects/BoardSessionCode.ts`의
   31자 알파벳 6자리(혼동 문자 제외)를 재사용한다. 숫자면 100만 조합이라 뚫린다.
2. **코드 입력에 `supabase/functions/_shared/rateLimit.ts`를 반드시 물린다.** 경우의 수로만 막지 않는다.
3. **링크·코드는 초대장이지 열쇠가 아니다.** 입장은 구글 로그인 이메일 확인으로만 이뤄진다.
4. **부서 간 격리(RLS)를 코드보다 먼저 설계한다.** 쌤핀 최초의 다중 테넌트 기능이다.
   남의 부서 글·멤버·초대 코드가 보이지 않아야 한다. 마이그레이션은 `049_staffroom_*.sql`부터.
   (현재 최신은 `048_consultation_slot_blocked_by.sql`)
5. **관리자 토큰 보관 위치를 명시적으로 정한다** — 기존 `teacher_tokens`를 같이 쓸지 별도로 둘지.
   같이 쓰면 암호화 키 유출 시 과제 기능까지 피해가 번진다. 정한 이유를 PROGRESS.md에 남긴다.
6. **새 구글 권한(scope)을 추가하지 않는다.** `drive.file` 그대로다. 추가하면 OAuth 재심사 대상이 된다.
7. **UI 텍스트는 전부 한국어**, 하드코딩 HEX 금지(`sp-*` 토큰), 직각 금지(`rounded-*` Tailwind 기본 키만,
   `rounded-sp-*` 금지), `any` 금지.

## 하지 말 것

- 게시판/자료실/토론방/갤러리/회의록 구현 (M2 이후)
- 배너 꾸미기, 알림, 실시간 구독 (M4·M5)
- 새 브랜치·worktree·PR 생성 (사용자가 요청할 때만)
- `Sidebar.tsx`·`electron/main.ts` 등 다른 세션 작업 파일의 무관한 부분 수정
- 계획서에 없는 기능 추가. 특히 **활동 포인트·랭킹·출석도장은 프로젝트 금지 규칙이다.**

## 다중 세션 주의 (실제 사고가 있었던 부분)

- git 인덱스는 세션 간 공유된다. **커밋은 반드시 경로를 지정한다: `git commit -m "..." -- <path> ...`**
  `git add -A`나 경로 없는 커밋은 남의 파일 8개를 딸려 보낸 전력이 있다.
- `Sidebar.tsx`에 탭을 추가할 때는 다른 세션 변경과 충돌하지 않는 최소 범위만 건드린다.
- electron 메인/IPC/preload를 고치면 `npm run electron:dev`를 **재시작**해야 반영된다(watch 안 됨).

## PRD 스토리로 쪼갤 때의 기준

각 스토리는 "화면에서 눈으로 확인 가능한 단위"로 만든다. 예시:
- US-001 부서 도메인 규칙(권한 판정) + 단위 테스트
- US-002 Supabase 스키마 + RLS 마이그레이션 + 격리 테스트
- US-003 부서 만들기 화면·저장
- US-004 초대 발급(링크·코드·만료·QR)
- US-005 코드 입력 → 구글 로그인 → 멤버 등록 (rate limit 포함)
- US-006 멤버 목록·내보내기·권한 변경
- US-007 사이드바 탭 + 빈 상태 화면
- US-008 관리자 토큰 보관 경로 확정 및 연결

## 완료 기준 (검증 게이트 — 하나라도 빠지면 완료 아님)

```bash
npx tsc --noEmit          # 에러 0
npm run lint              # 통과
npm run test              # 통과 (electron 코드를 보는 유일한 게이트다)
npm run regression-check  # 통과
```

- 위 4종 결과를 **실행한 명령과 핵심 출력까지** 함께 보고한다. "통과했습니다"만 쓰지 않는다.
- **코드만 보고 "됐다"고 하지 않는다.** 최소한 `npm run electron:dev`로 띄워
  탭 진입 → 부서 만들기 → 초대 발급 → 코드로 참여까지 실제로 눌러 본 결과를 보고한다.
- 끝나면 `PROGRESS.md` 갱신, 새 결정이 있으면 `DECISIONS.md`에 ADR 추가.

## 프롬프트에 넣지 않았지만 알아두면 좋은 것

- 계획 세션의 상세 기록: `.omc/staffroom-progress.txt` (실측값·함정·9차까지의 개정 경위)
- 이 기능의 핵심 통찰 세 가지
  1. `drive.file` 권한 탓에 **읽기도 서버가 관리자 토큰으로 대행**해야 한다(§3.2.1)

  3. 부피 있는 것은 전부 드라이브, 서버는 문지기와 신호등만(§3.5-라)
- M2 이후로 넘어갈 때도 같은 형식으로 프롬프트를 만들면 된다. 범위와 "하지 말 것"만 바꾼다.
