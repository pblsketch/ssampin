# 생기부 근거 지도와 작성 흐름 재설계 제안

작성: 2026-09-11 · 상태: 조사에 근거한 **설계 제안**, 구현·ADR 변경·출시 승인 아님.

## 1. 권고

근거 관리의 중심을 **직접 편집하는 근거 지도**로 바꾼다. 교사가 근거 카드를 연결하고, 연결의 의미를 적고, 필요한 묶음만 초안 재료로 고를 수 있게 한다. 기존 장면 배열은 같은 작업 공간의 **작성 구성**으로 활용한다.

핵심은 세 가지를 구분하는 것이다.

**2026-09-11 사용 난이도 재검토:** 아래 세 구분은 내부 설계 원칙이다. 교사에게 세 가지 모드나 필수 단계를 학습시키지 않는다. 기존 `근거 정리 ↔ 초안` 안에서 작업하고, 정리하지 않은 근거로도 초안을 만들 수 있게 한다. §11의 노출·명명·연동 기준을 구현 수용 조건으로 추가한다.

1. **관계**: 어떤 관찰·과제·평가가 서로 연결되는가. 분기·합류가 가능하다.
2. **배치**: 화면에서 카드를 어디에 놓는가. 위치를 바꿔도 관계나 AI 입력은 변하지 않는다.
3. **작성 구성**: 이번 초안에 어떤 근거를 어떤 순서로 사용할 것인가. 그래프의 모든 연결을 자동으로 문단 순서로 바꾸지 않는다.

이는 ADR-103의 자유 캔버스 기각과 ADR-104의 읽기 전용 개요 지도 결정을 재검토하는 제안이다. 기존 결정을 이미 변경한 것으로 취급하지 않는다. 외형만 그래프처럼 만드는 보강은 이번 목표를 충족하지 못한다.

## 4. 교사가 사용하는 흐름

### 4.1 평소 기록과 수합

관찰은 지금처럼 내용을 먼저 입력한다. 주제·장면·연결은 선택이다. 수합 자료는 기존의 학생 식별·원본 비교 경로를 거쳐 근거로 가져온다. 기록할 때마다 그래프를 완성하도록 요구하지 않는다.

### 4.2 지도에서 관계 파악

학급 운영 또는 수합 관리에서 학생을 여는 기존 동작은 유지한다. 생기부 작업을 명시적으로 선택했을 때 기존 `근거 정리`로 이동하고 해당 학생·근거를 강조한다. 새 사이드바 메뉴를 만들지 않는다. 수업반·영역·과목·학기 범위를 이어받고, 담임과 수업반의 신원 키를 이름이나 출석번호만으로 합치지 않는다.

- 초기 배치: 기존 주제를 묶음으로, 근거를 날짜순으로 자동 정리한다. **날짜가 가깝다는 이유로 의미 있는 연결선을 만들지는 않는다.**
- 카드를 선택하면 원문·출처·날짜·교사 메모·원본 변경 여부를 오른쪽에 연다.
- 두 카드를 선택해 `[연결하기]`를 누르거나 연결점을 끌어 연결한다. 키보드 조작으로도 같은 일을 할 수 있다.
- 연결 설명은 선택이다. 먼저 연결하고, 선을 선택했을 때 `어떻게 이어지나요?`에 자유롭게 적는다. `변화`, `뒷받침`, `다른 모습`은 이때만 입력 도움으로 제시한다. 관계 유형 분류를 매번 요구하지 않는다. 설명 없는 연결을 AI가 성장·인과관계로 단정하지 않게 한다.
- 여러 근거가 하나의 장면을 뒷받침하거나, 한 근거에서 여러 후속 활동으로 갈라지는 모습을 표현한다.
- 근거가 다른 주제와 관련돼도 주제 소유는 자동으로 옮기지 않는다. '다른 주제와 연결'과 '주제 옮기기'는 서로 다른 동작이다.

### 4.3 필요한 부분에 AI 도움 받기

선택한 근거에 `[AI로 정리 제안]`을 제공한다. 설명은 `고른 근거의 주제와 연결을 제안해요. 적용하기 전에는 바뀌지 않아요.`로 둔다. 묶기·연결·장면 배치마다 별도 상시 AI 버튼을 두지 않는다. 기존 고급 요청은 제안 창의 선택 입력으로 유지하고 범용 쌤핀 AI와 섞지 않는다.

AI는 기존 근거 ID를 이용해 연결·묶음·설명을 제안한다. 점선 제안과 변경 목록을 함께 보여주고 일부만 선택해 적용할 수 있게 한다. 제안만으로 저장하지 않는다. '연결 이유'는 AI 해석이며 관찰 사실로 승격하지 않는다.

학생 자기평가나 제출물의 진술, 교사 관찰, 교사의 평가적 해석은 출처를 구별한다. 서로 모순되는 근거가 있으면 하나를 지우거나 AI가 임의로 결론 내리지 않고 교사가 비교하도록 표시한다.

### 4.4 초안 작성

고른 묶음 또는 근거에서 `[이 근거로 초안 쓰기]`를 누르면 기존 초안 화면의 AI 준비 영역이 열린다. 따로 '담기'를 하고 다시 찾아가는 단계는 없앤다. 포함 근거·기존 분량 목표를 바로 보여주고 `[AI로 초안 만들기]`로 실행한다. 기존 장면 순서 편집은 이곳의 접힌 `[글 순서 조정]`으로 제공하고, 펼치지 않아도 생성할 수 있다. 교사의 종합 판단을 한 번, 기본 맨 앞에 두는 정책은 유지한다.

생성 직전에는 `초안에 쓸 근거 9건 · 빠진 근거 3건 [확인]`처럼 짧게 표시한다. 펼치면 선택 12건 중 제외 2건·확인 필요 1건의 이유와 해당 카드가 나온다. 해결해야 하는 신원·범위 오류는 접힌 상세에 숨기지 않는다. 예시는 설계용 가상 수치다.

분기·합류가 있으면 기존 장면 순서 또는 날짜 기반 기본 순서를 제안하되, 교사가 필요할 때 조정한다. 순서가 인과관계를 뜻하지 않음을 AI 입력에서도 지킨다. '이어진 전체'를 누른 뒤 내부에서 조용히 3개로 자르지 않는다. 입력 예산이 부족하면 제외될 근거와 이유를 생성 전에 보여주고 선택을 좁히거나 요청을 나눈다.

생성 결과는 원래 글과 비교하고 기존 `[이 글로 바꾸기]`로 명시적으로 반영한다. 초안에서 `[사용한 근거 보기]`를 누르면 해당 근거와 장면을 강조한다. 이 단계의 표시는 **보낸 재료**이며 '모든 문장이 이 근거로 검증됨'을 뜻하지 않는다.

### 4.5 수정하고 되돌아오기

학생을 바꾸었다가 돌아와도 지도 위치·선택·미저장 편집·AI 결과가 올바른 학생 범위로 복원된다. 뒤늦게 온 AI 응답은 요청한 학생과 입력 판본에 귀속한다. 원본이 갱신됐으면 비교 후 적용하고, 이전 판본으로 만든 초안에는 재검토 상태를 표시한다.

## 5. 화면 구성

```text
학생 선택 | 수업반·영역·과목·학기              [근거 정리 / 초안]
 [근거 추가] [AI로 정리 제안] [이 근거로 초안 쓰기]      [보기 ▾]
──────────────────────────────────────────────────────────────────
            주제 묶음 A                    선택한 카드 상세
     [관찰] ──이어짐──> [후속 활동]        출처·날짜·원문
        ╲                 ╱                교사 메모
          ──뒷받침──> [장면]               원본과 비교
                                          ───────────────
            주제 묶음 B                    필요할 때 같은 자리에
     [제출물] ──다른 모습── [관찰]          AI 제안 (필요할 때)

 [미정리 근거 6건]   [화면에 맞추기] [확대/축소] [되돌리기]
```

이 도식은 배치 원칙을 설명하는 와이어프레임이며 실행되는 화면은 아니다.

- 가운데 캔버스가 주 작업 영역이다. 오른쪽 공간은 선택한 근거 상세 또는 AI 정리 제안을 보여준다. 초안으로 이동하면 같은 보조 공간을 기존 AI 준비·결과 화면으로 쓴다(ADR-093 취지 유지). 작성 구성은 준비 화면의 선택 조정 기능이다. 별도 채팅·버전·근거 패널을 동시에 열지 않는다.
- 지도 전체를 볼 때는 주제 이름과 근거 수, 주제를 펼치면 근거 카드와 연결이 보인다. 선택한 카드의 이웃을 강조해 관련 없는 선의 복잡도를 낮춘다.
- 단순한 축소 때문에 글씨를 못 읽는 상태가 기본이 되지 않도록, 상세는 확대율과 무관한 크기로 읽는다. 첫 진입은 주제 요약을 화면에 맞추고 마지막 사용자 배치를 기억한다.
- 카드 표면은 내용 요약·출처·날짜·상태를 우선한다. 장면 역할 색과 AI 제안 상태는 글자/아이콘으로도 구분한다. 전문은 선택으로 접근하며 hover에만 숨기지 않는다.
- 조작: 빈 공간 이동, 노드 선택, 드래그 영역과 텍스트 선택 분리, 연결 생성/삭제, 줌, 전체/선택에 맞추기, 정렬, 실행 취소/재실행.
- 좁은 창에서는 학생 목록을 선택기로 접고, 오른쪽 상세는 겹쳐 여는 보기로 바꾼다. 가로 스크롤이 있는 장면 칸을 캔버스 안에 다시 넣지 않는다.
- 기본 문구는 기존의 `근거 정리`, `초안`, `근거`, `주제`를 유지한다. 장면 이름은 선택적인 `글 순서 조정` 안에서 제공한다. `작성 구성`, `노드`, `엣지`, `DAG`, `서사`를 새 상위 메뉴로 만들지 않는다.
- 색·글꼴·간격은 `docs/design-system.md`와 `.impeccable.md`의 `sp-*` 토큰을 사용한다.

## 6. 데이터와 구현 경계 제안

### 유지할 것

`RecordEvidence`의 본문·출처·AI 제외, `InquiryThread`의 주제, `NarrativeScene`의 작성 구성, 원본 비교, AI 실행 큐, 명시적 반영을 재사용한다. 근거 본문을 그래프용 데이터에 복제하지 않는다.

### 새로 구분할 것

| 개념             | 저장할 정보                                                        | 동작 계약                                                                 |
| ---------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------- |
| 관계             | ID, 양 끝의 근거/장면/주제 참조, 관계 설명·방향, 작성자 출처, 판본 | 같은 학생·수업반·학기 경계 확인. 다른 영역 자료는 생성 범위에서 별도 여과 |
| 화면 배치        | 참조 ID별 위치·접힘, 뷰포트                                        | AI 요청서에서 제외. 초기에는 기기별 UI 설정으로 보관해 동기화 충돌을 줄임 |
| 작성 재료 스냅샷 | 선택한 근거·장면·관계 ID와 판본, 순서, 제외 이유                   | 생성 직전 화면과 요청서가 하나의 해석 결과를 공유                         |
| 제안             | 기준 판본, 추가/수정/삭제 목록, 상태                               | 적용 전 본자료 쓰기 0회. 기준 변경 시 재검토                              |

첫 구현에서는 근거↔근거 관계와 기존 주제→주제 연결의 정확한 표시부터 제공하고, 장면 연결 편집을 다음 단계에 추가한다. 최소 범위에서도 **실제 근거 카드를 연결**할 수 있어야 한다.

주제 소유의 정본은 `RecordEvidence.threadId`로 유지한다. 지도에서 보이는 그룹 위치나 관계선이 이 값을 암묵적으로 바꾸지 않는다. 기존 장면 소속에서 나오는 포함 관계와 새로 적는 의미 관계도 중복 저장하지 않는다.

참조 관계의 순환은 허용할 수 있으나 순서 관계의 순환은 금지한다. 자기 연결·동일 관계 중복·존재하지 않는 대상은 거부한다. 방향 없는 비교와 방향 있는 진행 관계를 구별한다. 이 상세 타입은 P0에서 확정한다.

구현 시 화면 컴포넌트가 아니라 순수 규칙에서 범위·유효 관계·보낼 근거를 계산한다. 사용자 동작은 usecases를 통하고 저장소는 기존 DI·Repository 경로를 이용한다. 그래프 라이브러리 타입은 adapters 밖으로 내보내지 않는다.

관계 저장 파일 신설은 도메인 관계와 화면 좌표 분리를 확정한 뒤 진행한다. 기존 파일 잠금 순서, `SYNC_FILE_KEYS`, 보관함·학년도 전환·백업·동기화·브릿지 계약까지 한 묶음으로 설계한다. 원본 삭제는 관계를 미해결로 표시하거나 안전하게 정리하되 다른 근거를 연쇄 삭제하지 않는다.

### 기술 후보

[React Flow](https://reactflow.dev/learn/layouting/sub-flows)를 캔버스 후보로 우선 검증한다. 그룹·연결·선택·확대 기능을 기존 React 화면과 조합할 수 있다. 설치나 도입 확정은 이번에 하지 않았다.

자동 배치는 별도 문제다. [공식 비교](https://reactflow.dev/learn/layouting/layouting)는 Dagre의 그룹 안팎 연결 제약 등을 명시한다. 쌤핀은 분기·합류·접힌 묶음이 있으므로 ELK 후보를 함께 실험하되 실제 카드 크기에서 비교한 뒤 결정한다. 전체 캔버스를 매 입력마다 재배치하지 않고 보기 메뉴의 `[카드 위치 정돈]` 때만 실행한다. AI 정리 제안과 이름을 구별한다.

[접근성 문서](https://reactflow.dev/learn/advanced-use/accessibility)의 기본 지원만으로 검증을 끝내지 않는다. 한국어 접근 이름, Tab 이동, 키보드 연결, 목록 대체, 미저장 입력 보호는 쌤핀에서 확인한다.

| 단계                 | 할 일                                                                                         | 다음 단계로 넘어갈 증거                                                    |
| -------------------- | --------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| P0. 계약 확정        | 기존 결정 변경 초안, 관계/배치/작성 순서 분리, 신원·범위·저장 실패 계약                       | 아래 AC와 데이터 이행표가 맞물리고 기존 기능 보존 범위가 명시됨            |
| P1. 조작 프로토타입  | 합성 자료로 근거 노드·분기·합류·상세·선택·작성 구성 이동 구현. 기존 자료 저장은 연결하지 않음 | 1280/1440/1920에서 같은 과업을 수행한 영상/스크린샷·시간·실수 기록         |

| P3. 작성 입력 연결   | 선택 범위와 실제 요청서 일치, 분기 순서 편집, 제외 설명                                       | 4개 이상 연결·합류·영역 혼합·제외 근거가 있는 합성 사례에서 ID와 순서 비교 |
| P4. AI 부분 제안     | 선택 맥락, 변경 목록, 일부 적용, 판본 충돌 방지                                               | 적용 전 쓰기 0회, 늦은 응답·중복 응답·취소·부분 실패 재현                  |
| P5. 초안 왕복과 검증 | 재료 역추적, 원본 변경 알림, 담임·수업반 양쪽 QA, 사용자 가이드                               | 기존 글 보존, 실제 Electron·AI 경로 확인, 전체 게이트 및 가이드 점검       |

P1에서 비교할 과업: '근거 12개 중 관련 4개를 찾기', '관찰 두 개와 제출물 하나를 연결하기', '잘못된 연결 되돌리기', '해당 재료만 초안에 보내기'. 기존 화면과 지도에서 같은 합성 자료로 비교한다. 잠정 목표는 연결·선택 과업의 클릭/시간 개선, 근거 누락·오선택 0건이다. 시간 단축률은 측정 후 결정하며 지금 추정 효과를 사실로 발표하지 않는다.

## 8. 수용 기준과 실패 시나리오

1. **관계 조작**: 근거 두 개를 직접 연결·설명·해제할 수 있다. 주제 칩 간 이동만으로 대체하지 않는다.
2. **분기·합류**: A→B, A→C, B→D, C→D를 실제 연결점에 맞춰 표시한다. 줄 순서로 B→C처럼 오해하게 그리지 않는다.
3. **선택 일치**: 생성 미리보기의 ID 집합·순서와 실제 요청서가 같다. 4개 이상이어도 조용히 자르지 않는다.
4. **경계**: 같은 이름·같은 번호의 다른 학생/학급, 학년도 전환 후 자료가 섞이지 않는다.
5. **소유 보존**: 연결 생성·위치 이동·묶음 접기로 근거의 주제/영역/본문이 바뀌지 않는다.
6. **삭제 보존**: 연결·화면 배치 삭제로 원본/다른 근거를 지우지 않는다. 근거 삭제 시 영향을 미리 알린다.
7. **저장 실패**: 실패 시 성공 알림 없음, 교사 입력 보존, 재시도 시 중복 관계 없음. Undo도 실패하면 실패로 표시한다.
8. **AI 적용**: 점선 제안은 쓰기 0회, 일부 적용은 고른 항목만 바꾸고 오래된 판본 응답은 그대로 덮어쓰지 않는다.
9. **출처**: AI 관계 설명을 관찰 원문으로 저장하지 않는다. '사용 재료'와 문장별 검증을 구별한다.
10. **왕복**: 지도→작성 구성→초안 비교→지도에서 선택·학생·영역·미저장 글을 보존한다.
11. **이행**: 기존 주제/장면/이음말/근거 ID와 기존 요청서 기준선을 유지한다. 옛 주제 연결은 출처를 남겨 이행하며 이중 정본을 만들지 않는다. 하위 버전 복귀 시 신규 관계 보존 정책을 명시한다.
12. **범위 예산**: AI 제외·원본 삭제·영역 불일치·길이 초과를 사유별로 노출한다. 현재 보낸 재료와 이전 결과 재료를 혼동하지 않는다.
13. **가독성·접근성**: 1280/1440/1920, 밝음/어두움, 사용자 큰 글꼴, 키보드만으로 핵심 과업 수행. 상세창에서 원문이 잘리지 않는다.
14. **부하**: 학생 1명에 근거 200개/주제 10개/관계 300개인 합성 자료로 선택·확대·정리의 지연을 측정한다. 목표 예산은 P1 기준 측정 후 확정한다.

필수 구현 검증: `npx tsc --noEmit`, `npm run lint`, `npm run test`, `npm run regression-check`. 사용자 행동 변경 시 `landing/src/content/docs.ts`와 필요한 스크린샷을 갱신하고 `cd landing`에서 `npm run docs:check`, `npm run build` 실행. 브라우저와 Electron, 실제 내 AI 호출 증거를 구분한다.

- 현재 코드·관련 ADR·기존 계획서와 공식 레퍼런스를 대조했다.
- `npx vitest run src/domain/rules/__tests__/narrativeScenes.test.ts src/adapters/components/RecordDraft/__tests__/narrativeFlowView.test.tsx --maxWorkers=2`: **2개 파일, 47개 테스트 통과**.

## 10. 설계상 남은 선택

현재 권고 기본값은 자동 배치 + 자유 이동, 근거 중심 노드, 선택한 주제부터 펼치기, 관계와 작성 순서 분리이다. P1에서 **정리 없이 초안 만들기**를 기본 과업으로 검증하고, 관계를 먼저 정리하거나 글 순서를 직접 정하는 선택 경로도 비교한다. AI 문장별 정밀 출처 연결은 추가 응답 형식·편집 후 위치 추적이 필요한 후속 범위로 둔다.

## 11. 교사 사용 난이도·기존 화면 연동 재검토 (2026-09-11)

### 11.1 앞선 안에서 줄인 부담

| 복잡해질 지점                                 | 수정한 원칙                                                                   |
| --------------------------------------------- | ----------------------------------------------------------------------------- |
| 지도→선택→담기→작성 구성→초안이라는 별도 단계 | 기존 `근거 정리 ↔ 초안` 두 화면 안에서 직접 이동. 담기 단계 제거              |
| 연결을 만들 때마다 유형·설명 지정             | 연결 먼저, 설명은 필요할 때. 연결이 없어도 생성 가능                          |
| AI 묶기·연결·배치를 상시 버튼으로 각각 제공   | `AI로 정리 제안` 한 입구, 상세 요청은 선택 입력                               |
| 근거 지도라는 새 기능을 사이드바에 추가       | 기존 `근거 정리`의 본문을 교체. 지도/목록은 보기 메뉴에 두고 마지막 선택 기억 |
| 자료를 정리하고 나서야 AI 초안 작성           | 정리하지 않은 근거도 명시된 범위에서 초안 작성 가능                           |
| AI 정리와 화면 정돈 모두 '정리하기'로 부름    | `AI로 정리 제안`과 `카드 위치 정돈`으로 결과를 구별                           |

### 11.2 버튼 노출 기준

상단 작업 버튼은 **근거 추가 / AI로 정리 제안 / 이 근거로 초안 쓰기** 최대 3개, 강조 버튼은 마지막 하나만 둔다. 이는 시제품 검증용 상한이며 학생 선택·탭·지도 확대 조작과 구분해 센다. 카드마다 같은 세 버튼을 반복하지 않는다.

| 상태               | 추가로 보이는 조작                                     | 기본 동작                                                            |
| ------------------ | ------------------------------------------------------ | -------------------------------------------------------------------- |
| 선택 없음          | 별도 선택 도구막대 없음                                | 현재 학생·영역의 사용할 근거 수를 표시. AI 실행 준비에서 범위를 확인 |
| 카드 1개 선택      | 원본 보기·메모 편집, 나머지는 상세 메뉴                | 전문을 읽는다. 초안 대상이 `고른 근거 1건`임을 표시                  |
| 카드 2개 이상 선택 | 연결하기·주제로 묶기                                   | 선택한 범위에만 작업. `선택 해제`로 전체 범위 복귀                   |
| 연결 선택          | 설명 수정·연결 끊기                                    | 원본이나 주제 소유를 바꾸지 않는다                                   |
| AI 제안 확인       | 선택한 제안 적용·취소                                  | 고급 선택/일부 적용을 제공하지만 항목마다 버튼을 늘리지 않음         |
| 초안 준비          | AI로 초안 만들기                                       | 글 순서·세부 요청은 접혀 있고 필요한 경우에만 조정                   |
| 생성 결과          | 이 글로 바꾸기·다시 만들기, 기존 비교/붙이기 경로 유지 | 기존 글에 대한 변경은 명시적으로 적용                                |

현재 맥락을 상단에 표시하고 실행 준비에서 반복 설명을 요구하지 않는다. 근거 0건이면 생성 대신 `근거 추가`가 강조된다. 기존 글 보호, 원본 비교, 삭제 등 결과가 큰 동작은 버튼 수를 줄이려고 자동화하지 않는다. 중요 상태·오류는 항상 보이고, 선택 기능은 클릭/키보드로 찾을 수 있어야 한다.

지도 확대/축소·화면 맞춤·되돌리기는 하단의 고정 위치에 둔다. 아이콘에는 한국어 접근 이름과 툴팁을 붙인다. 연결·메모·AI 제외는 hover 전용으로 숨기지 않는다. 기본 지도 조작을 몰라도 `목록` 보기와 클릭 메뉴로 같은 핵심 과업을 수행할 수 있게 한다.

### 11.3 기존 페이지 연결: 확인한 것과 추가할 것

| 출발 위치                           | 이번 코드 확인                                                                                             | 설계 계약                                                                                      |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 수업 관리 → 수업 기록 → 생기부 초안 | `ClassRecordTab.tsx`에 기존 탭과 화면 이동 요청 처리 있음                                                  | 메뉴 유지. 근거 정리 도착 시 학생·근거를 바로 선택                                             |
| 담임 업무 → 기록/초안               | `HomeroomPage.tsx`, `InputMode.tsx`에 저장 보호와 `근거 정리에서 보기` 경로 있음                           | 저장 후 강제 이동하지 않고 기존 이동 동작을 유지                                               |
| 근거 정리 → 초안                    | `RecordDraftView.tsx`가 학생 선택을 공유하고 `onWriteDraft`로 초안·AI 패널을 엶                            | 이 경로를 확장해 선택 ID·범위·글 순서 전달. 별도 생성 화면을 만들지 않음                       |
| 담임/수업반 과제 수합 상세          | 두 호스트가 `AssignmentDetail`을 사용. 확인한 상세 props는 `onBack`; 직접 생기부 이동 경로는 확인하지 못함 | **추가 구현 대상**. 제출물 선택 시 `생기부 근거로 추가`, 기존 근거면 `근거 정리에서 보기` 제공 |
| 기존 자료에서 근거 가져오기         | `collectEvidenceCandidates.ts`에 담임/교과별 출처와 제출물 후보 경로 있음                                  | 후보 변환·중복 판정을 재사용. 화면 이동과 자료 추가를 혼동하지 않음                            |

수합에서 추가할 때 선택한 학생의 제출물만 미리 보여주고 기존 영역을 이어받는다. 목적 영역을 추론할 수 없을 때만 고르게 한다. 원문 열기·다운로드·수합 확인 같은 기존 목적은 바꾸지 않는다. 여러 학생을 한 번에 추가했다면 결과는 수합 화면에서 요약하고 한 학생 지도로 임의 이동하지 않는다.

추가 성공 후 `근거 정리에서 보기`를 제공한다. 이미 추가된 원본은 복제하지 않고 기존 근거로 이동한다. 재제출로 내용이 바뀌었다면 비교 후 반영한다. 구체 중복 키는 학생·학급·출처 종류·원본 식별자를 함께 감사한 뒤 확정한다.

기존 `RecordFlowIntent`는 학생·수업반·근거·주제 등의 이동 요청을 지원하지만 영역·과목·학기·출발 화면 복귀 정보는 현재 인터페이스에서 확인되지 않는다. 호스트 상태로 보존되는 값까지 추적한 뒤 필요한 정보를 확장한다. 기본 첫 학생이나 첫 과목으로 대체하지 않는다. 출발 화면으로 돌아오면 수합 과제·학생·필터·스크롤을 복원한다. 일반 탭 클릭을 포함한 모든 이동에 미저장 글 보호가 일관되게 적용되는지도 확인한다.

### 11.4 추가 수용 기준: 설명 없이 할 수 있는가

- **AC-15 기본 경로**: 합성 근거가 준비된 상태에서 연결/주제/장면/글 순서를 한 번도 편집하지 않고 초안 준비·생성을 마칠 수 있다.
- **AC-16 버튼 수**: 1280/1440 화면의 상단 작업 버튼 ≤3, 강조 버튼 ≤1. 상세창을 열어도 같은 작업 버튼이 중복되지 않는다. 문서가 아닌 실제 화면에서 센다.
- **AC-17 명칭 이해**: 처음 쓰는 교사 3~5명에게 버튼을 누르기 전 예상 결과를 말하게 한다. 정리 제안을 초안 생성이나 즉시 변경으로, 위치 정돈을 내용 변경으로 오해하면 문구를 수정한다. 소규모 검증 결과를 전체 교사에게 일반화하지 않는다.
- **AC-18 일관성**: 같은 행동은 담임·수업반·수합에서 같은 이름. `근거`, `재료`, `자료`, `장면`, `구성`을 동일 대상을 뜻하는 동의어로 혼용하지 않는다. 원본 파일은 `제출물/원본`, 생기부 작성용은 `근거`로 구별한다.
- **AC-19 연동 왕복**: 수합의 한 제출물→근거 추가→정확한 학생 카드→초안→수합 복귀. 학생·과목 재선택 0회, 중복 근거 0건, 출발 필터 손실 0건. 맥락이 원래 없는 경우의 최소 질문은 예외로 기록한다.
- **AC-20 안전한 축약**: 버튼을 줄여도 원본 비교·AI 제외 이유·저장 실패·명시적 초안 반영이 사라지지 않는다. 지도 밖/필터 밖/삭제된 대상 이동을 각각 시험한다.
- **AC-21 기존 기능 보존**: 다중 학생/날짜 관찰 입력, 수합 조회·다운로드, 초안 다중 학생 생성·분량 조절·비교·복사·내보내기를 기존 경로에서 찾을 수 있다. 한 학생 지도 때문에 일괄 작업을 잃지 않는다.

이 항목은 P0 계약·P1 시제품·P5 실제 화면 검증에 포함한다. 교사 참여 검증을 아직 하지 못했다면 '사용하기 쉽다'를 완료 조건으로 보고하지 않고 미검증으로 남긴다.
