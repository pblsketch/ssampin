# 계획 — 유리 표면(투명도 · 흐림 · 배경) 기반 공사

작성 2026-08-14 · 상태 **계획** · 선행 작업 [[neutral-theme.handoff]]

## 한 줄 요약

"글래스모피즘 **테마**를 추가"하는 것이 아니라, **투명도 · 흐림 · 뒤에 비치는 배경을
제대로 다루는 기반**을 놓는다. 유리 느낌은 그 기반 위에서 설정으로 켜는 결과물이다.

## 왜 테마가 아닌가

준일님이 인스타그램 화면(글래스모피즘 대시보드)을 보고 테마 추가를 검토 요청.
확인 결과 **테마 그릇이 유리를 담지 못한다.**

쌤핀 테마가 표현할 수 있는 값은 불투명한 색 8개(`ThemeColors`) + 모양 힌트 5개
(`ThemeStyleHint`)뿐이다. 유리의 3요소인 반투명 · 흐림 · 배경이 하나도 없다.
프리셋 한 줄 추가가 아니라 모델 확장 · 적용 로직 · 설정 화면이 모두 필요하다.

동시에, 사용자가 이미 겪던 두 가지 문제가 같은 뿌리로 드러났다.

- 설정의 `배경 투명도` · `카드 투명도` 를 조절해도 **대시보드에는 아무 변화가 없다**
- 흐림(블러)을 조절할 방법이 **아예 없다**

그래서 세 가지를 한 작업으로 묶는다.

## 실측으로 확인한 사실 (추측 아님 — 재확인 불필요)

### ① sp-\* 토큰의 투명도 수식은 무효다. 그러나 **전역 수리하면 안 된다**

브라우저 실측:

| 클래스                | 실제 렌더                      |
| --------------------- | ------------------------------ |
| `bg-sp-accent`        | `rgb(28,28,30)` ✅             |
| `bg-sp-accent/10`     | `rgba(0,0,0,0)` — 완전 투명 ❌ |
| `border-sp-accent/40` | 회색 기본값 (강조색 아님) ❌   |
| `text-sp-muted/50`    | 무효 — 본문색으로 렌더 ❌      |

원인: `tailwind.config` 에 `sp` 색이 `'var(--sp-card)'` 형태로만 정의돼 있고
`<alpha-value>` 자리가 없다. 사용처는 **2,950곳 / 455파일**.

**전역 수리 금지.** 고치면 `text-sp-muted/NN` 327곳이 아래처럼 떨어진다
(뉴트럴 라이트, muted `#6e6e73`, 카드 `#ffffff` 기준):

|               | 지금                        | 수리 후       |
| ------------- | --------------------------- | ------------- |
| `/70` (67곳)  | 본문색으로 진하게 (17.89:1) | **2.81:1** ⛔ |
| `/60` (95곳)  | ″                           | **2.37:1** ⛔ |
| `/50` (113곳) | ″                           | **2.00:1** ⛔ |
| `/40` (52곳)  | ″                           | **1.72:1** ⛔ |

배관이 고장 나 있던 **덕분에** 지금 읽히고 있다. 전역 수리는 "안 보이는 글자"를
327개 한 번에 만드는 일이다. 이 작업에서는 **기존 토큰을 건드리지 않고 유리 전용
경로를 따로 낸다.** 2,950곳 정리는 별도 PDCA(단계적 이관 + 대비 확인)로 분리한다.

### ② 정답 기법은 이미 코드에 있다

`Widget.tsx:411-412` (위젯 모드)가 이미 이렇게 한다.

```ts
backgroundColor: `rgba(var(--sp-widget-rgb), ${settings.widget.opacity})`,
'--sp-card': `color-mix(in srgb, var(--sp-card-base) ${cardOpacity * 100}%, transparent)`,
```

`color-mix` 는 위 함정을 피해 간다. **새로 발명하는 게 아니라 검증된 코드를 본체로
옮기는 일이다.**

### ③ 투명도 설정은 고장이 아니라 배선이 안 된 것

`settings.widget.opacity` · `settings.widget.cardOpacity` 를 읽는 곳은
`Widget.tsx` **한 곳뿐**이다. 대시보드는 이 값을 아예 읽지 않는다.
그런데 슬라이더는 `설정 → 화면` 탭에 있다 — **설정이 놓인 자리와 효과가 나는 자리가
어긋나 있다.**

### ④ 밝은 테마에서는 유리가 원리적으로 성립하지 않는다

뉴트럴 라이트의 카드는 순백(`#ffffff`)이다. 불투명도를 38%까지 낮춰도 뒤가 밝으면
**흰색 위에 흰색**이라 차이가 안 보인다. 더 낮추면 글자가 죽는다.
실측 시안에서 사이드바는 비쳤지만 카드는 끝내 불투명해 보였다.

레퍼런스 이미지가 유리로 읽히는 이유는 카드 **안에 어두운 사진**이 들어 있기 때문이다.
쌤핀 카드 안에 들어가는 것은 숫자와 표다.

→ **유리는 어두운 계열에서만 노출한다.**

### ⑤ 위젯 카드는 `bg-sp-card` 가 두 겹이다

대시보드 실측: `bg-sp-card` 요소 **85개** 중 바깥 틀은 **26개**, 나머지 **59개**가
위젯 자신의 뿌리다. 주간시간표는 바깥 틀(549×456) 안에 거의 같은 크기의 카드(547×454)가
하나 더 있다.

바깥에만 유리를 씌우면 **안쪽 불투명 카드가 그 위를 덮는다.** 안쪽에도 유리를 칠하면
42% × 42% 로 겹쳐 다시 불투명해진다.

→ **유리는 바깥 한 겹만. 안쪽은 배경을 갖지 않는다.** 메타테스트로 고정한다.

### ⑥ 카드 안까지 맞추면 가독성이 **지금보다 좋아진다**

배경 사진의 실제 픽셀을 뽑아 겹쳐 계산한 결과(뉴트럴 다크, 덮개 없음):

|                           | 3.0 미만 | AA 4.5 미만 |
| ------------------------- | -------- | ----------- |
| 카드 껍데기만 유리        | 4건      | 9건         |
| **안쪽 면·타일까지 맞춤** | **0건**  | **2건**     |
| 시간표 화면(빽빽한 표)    | **0건**  | 1건         |

껍데기만 했을 때의 4건은 **유리를 켜지 않아도 원래 나쁘던 도구 타일**
(자리뽑기 2.67 · 랜덤뽑기 2.67 · 타이머 3.85 · 활동기호 4.09)이다.
유리에 맞춰 손보니 그 4건이 사라졌다.

### ⑦ 수치는 통과해도 빽빽한 표는 시각적으로 산만하다

시간표 화면은 대비 3.0 미만이 0건인데도, 표 뒤로 배경색이 칸마다 다르게 지나가
가로세로로 훑기 어려웠다. **대비 계산으로는 잡히지 않는 문제.**

→ **데이터가 빽빽한 영역은 유리에서 제외**하고, 그 위에 사용자 조절을 얹는다.

### ⑧ 윈도우 11 내장 재질(Mica/Acrylic)이 쓸 수 있고, 투명 창과도 함께 된다

Electron 43.3.0 · Windows 11 빌드 26200 에서 별도 최소 앱으로 실측.

- `backgroundMaterial: 'mica' | 'acrylic'` **동작 확인**
- **`transparent: true` 와 함께 써도 재질이 적용된다** — 창 안팎의 디테일 양을 재보니
  창 밖 15~22 vs **창 안 0.2~0.6** 으로, 바탕화면 무늬가 실제로 뭉개졌다.
  → **위젯 모드·옆핀 창에도 쓸 수 있다** (초기 우려는 오판이었음)
- `mica` 는 매우 옅다. **`acrylic` 이 유리답다.**
- ⚠️ **재질의 밝기를 앱이 통제할 수 없다.** OS 라이트 모드 + 밝은 바탕화면에서
  Mica 배경은 `#f3f3f3`, Acrylic 은 `#d5d4d3` 로 나왔다. 흰 글씨 대비 1.11 · 1.48 —
  **안 보인다.** 실제로 테스트 창의 제목이 사라졌다.
  → `nativeTheme.shouldUseDarkColors` 로 OS 모드를 읽어 글자·카드 진하기를 맞춰야 한다.

### ⑨ 성능은 이 PC 기준 차이 없음

흐림 26겹 + 스크롤에서 유리 켬/끔 모두 평균 16.67ms · 60fps · 최악 프레임 16.8ms.
**단, 개발 PC 한 대 기준이다.** 학교 저사양 PC·그래픽 가속 미지원 환경 미확인.

## 준일님 결정 사항

| 결정        | 내용                                                                 |
| ----------- | -------------------------------------------------------------------- |
| 접근        | 테마 추가가 아니라 **기능(기반) 먼저**                               |
| 배경        | **윈도우 11 내장 재질 우선**, 안 되면 앱 생성 배경, 원하면 내 사진   |
| 적용 범위   | **데이터 영역 자동 보호 + 3단계 사용자 조절** (자동 우선, 조절 병행) |
| 설정 강도   | **3단계** (없음 / 약하게 / 강하게)                                   |
| 투명도 설정 | **위젯 모드와 대시보드를 하나로 합친다**                             |

### 합치기 결정에 대한 구현 방침

위젯(바탕화면 위)과 대시보드(창 안)는 적정 투명도가 다르다는 우려가 있었으나,
**설정을 나누지 않고 해결한다.** 사용자는 값 하나를 고르고, 앱이 맥락별 곡선으로
환산한다. 겉으로 보이는 설정은 하나다.

```
사용자 값 1개 → 위젯 창 배경 알파 / 대시보드 카드 알파 / 흐림 세기
```

기존 사용자가 설정해 둔 `widget.opacity` · `widget.cardOpacity` 값은 **승계**한다.
기본값으로 되돌리지 않는다.

## 설계

### 새 토큰 (기존 토큰은 건드리지 않는다)

| 토큰                | 유리 꺼짐           | 유리 켜짐                                            |
| ------------------- | ------------------- | ---------------------------------------------------- |
| `--sp-glass-card`   | `var(--sp-card)`    | `color-mix(in srgb, var(--sp-card) N%, transparent)` |
| `--sp-glass-blur`   | `0px`               | `16~28px`                                            |
| `--sp-glass-border` | `var(--sp-border)`  | 밝은 헤어라인                                        |
| `--sp-inset-1`      | `var(--sp-bg)`      | `rgba(255,255,255,.06)`                              |
| `--sp-inset-2`      | `var(--sp-surface)` | `rgba(255,255,255,.09)`                              |

**핵심은 `--sp-inset-*` 이다.** 지금 카드 안쪽 면은 `bg-sp-bg`(앱 배경색)를 참조하는데,
유리를 켜면 앱 배경이 사진으로 바뀌면서 **색의 사다리에서 맨 아래 칸이 빠진다.**
안쪽 면이 앱 배경이 아니라 **카드 자신을 기준으로 한 상대 면**을 쓰게 만든다.

### 규칙

1. **유리는 위젯 바깥 틀 한 겹만.** 안쪽 `bg-sp-card` 는 배경 없음.
2. **데이터 밀집 영역(표·그리드)은 불투명 유지.** 자동 적용.
3. **유리는 어두운 계열 테마에서만 노출.** 밝은 테마에서는 설정 자체를 숨긴다.
4. OS 재질 사용 시 `nativeTheme` 로 밝기를 읽어 글자·카드 진하기를 맞춘다.

### 배경 3단 폴백

1. **윈도우 11** → `backgroundMaterial: 'acrylic'`
2. **윈도우 10 · macOS** → 앱이 생성한 추상 배경
   (매끈한 그라데이션은 흐려도 티가 안 난다 — 덩어리와 경계를 넣을 것)
3. **원하는 사용자** → 내 사진 (`file://` 경로 방식, 이미 구현됨)
   ⚠️ 경로만 저장되므로 **다른 PC에서는 보이지 않는다.** 기본값으로 삼지 말 것.

## 단계

1. **토큰·유틸 신설 + 안쪽 면 교체**
   유리가 **꺼진 상태에서 지금과 100% 동일**해야 한다. 이게 안전장치다.
2. **투명도 배선 + 설정 통합**
   대시보드가 투명도 값을 읽게 하고, 위젯 모드 설정과 하나로 합친다. 기존 값 승계.
3. **흐림 설정 신설**
4. **배경 3단 폴백** (OS 재질 → 생성 배경 → 내 사진)
5. **유리 적용** — 바깥 한 겹 + 데이터 영역 보호
6. **3단계 프리셋 UI** (어두운 테마에서만 노출)
7. **검증**

## 완료 조건

- 검증 게이트 4종 통과 (`tsc` · `lint` · `test` · `regression-check`)
- **유리를 끈 상태에서 기존 화면과 시각적으로 동일** (회귀 없음)
- 대비 스캔: 라이트/다크 × 대시보드·시간표·일정·학급·설정에서 **3.0 미만 0건**
- 메타테스트: 유리 두 겹 금지 · 안쪽 면이 앱 배경색을 참조하지 않음
- **저사양 환경 실측** (그래픽 가속 미지원 포함)
- 실기기에서 위젯 모드·옆핀 확인

## 하지 말 것

- ❌ `tailwind.config` 의 sp 토큰에 `<alpha-value>` 를 넣는 전역 수리 (위 ① 참조)
- ❌ 밝은 테마에 유리 노출 (위 ④)
- ❌ 안쪽 카드에도 유리 칠하기 (위 ⑤)
- ❌ 내 사진을 기본 배경으로 삼기 (다른 PC에서 안 보임)
- ❌ `mica` 채택 (너무 옅다 — `acrylic` 을 쓸 것)
