## 2. 사전 확인 실험 결과 (2026-09-01 실측)

### 2-1. 한글(.hwpx)에 사진 넣기 — **된다**

`@ubermensch1218/hwpxcore@0.1.3` (이미 쓰는 의존성) 의 `package.addBinaryItem` +
`HwpxOxmlParagraph.addPicture` 로 표 칸 안에 사진을 넣고, **설치된 한글 2024로 직접 열어
PDF 로 변환해 검증**했다.

```
COM 생성 OK → 보안모듈 등록 OK → 열기 결과: True → PDF 저장 결과: True
PDF 안 이미지 4장 (각 240x320) 실제 렌더 확인
```

- JPEG · PNG 둘 다 정상 렌더
- 사진 없는 학생 = 이름만, 빈자리 = 빈 칸 (구분됨)
- claw-hwp 검사기: `tableCount 1 / cellCount 6 / imageCount 4`

### 2-2. claw-hwp / rhwp 는 쓰지 않는다

claw-hwp 는 Claude Code 플러그인(개발 도구)이라 제품에 들어갈 수 없다. 엔진(`@rhwp/core`,
MIT)만 떼어 오는 안도 검토했으나 **기각**한다.

- claw-hwp 자체 문서가 rhwp 의 HWPX 이미지 출력이 깨진다고 명시
  (`references/rhwp-api.md:331` — "이미지는 그냥 내보내기로는 살아남지 못한다")
- 정상 출력에 4,510줄짜리 후처리(`create.js`)가 필요하고, 그 파일에는 라이선스 표기가 없다
- WASM 4.5MB + JS 252KB 증가, 기존 HWPX 라이브러리와 중복

**claw-hwp 는 점검표·검사기로만 쓴다.** 아래 세 함정은 라이브러리가 달라도 재발하므로
구현 중 점검 대상으로 남긴다.

| claw-hwp 경고                              | hwpxcore 실측        | 조치                                               |
| ------------------------------------------ | -------------------- | -------------------------------------------------- |
| 그림 그릴 문단이 빈 채로 남음              | `<hp:pic>` 정상 생성 | 없음                                               |
| 목록에 `isEmbeded="1"` 누락                | 자동으로 붙음        | 없음                                               |
| 배치 캐시(`linesegarray`)가 그림 높이 무시 | 해당                 | **문단 생성 시 제거** (기존 코드에 이미 있는 방식) |

### 2-3. Excel 사진판은 만들지 않는다 (실측 후 오너 확정)

만들어 봤고 **파일 자체는 정확했다** — LibreOffice 로 렌더하면 사진이 칸의 78% 를 차지하고
3:4 비율도 유지된다. 그런데 **엑셀에서 열면 깨진다.**

- 화면 배율 175% 인 PC 에서 엑셀이 행 높이를 요청값의 **4/7 로 줄여 잡는다** (실측:
  요청 20→11.5, 30→17.2, 84→48 — 모두 96/168 = 0.5714 배).
- 그러면 사진이 칸을 꽉 채워 **아래 이름을 덮는다.** 사진을 칸에 묶는 방식(tl~br 두 점 고정)
  으로 바꾸니 칸을 넘지는 않게 됐지만, 이름 자리는 여전히 모자랐다.
- 엑셀이 만든 파일은 같은 값을 그대로 읽으므로, 파일이 아니라 **엑셀 + 화면 배율의 상호작용**이다.
  배율 125% 는 견디지만 150% 이상에서 무너진다 — 교사 노트북에 흔한 조건이라 내보낼 수 없다.

근본 해결은 **사진과 이름을 서로 다른 칸에 두는 것**(좌석 한 칸을 두 줄로)인데, 지금 엑셀
출력의 테두리·짝꿍 간격·3인 그룹 보정 로직을 전부 다시 맞춰야 해서 이번 범위를 넘는다.
→ **Excel 은 기존처럼 이름만 내보낸다.** 사진이 필요하면 PDF·한글을 쓴다.
**오너 확정(2026-09-01): 엑셀은 하지 않는다.** 다시 제안하지 말 것.

### 2-4. 알려진 주의점

- **`imgDim`(그림 원본 크기)은 건드리지 않는다.** 규격만 보면 픽셀 값이어야 할 것 같아
  실제 픽셀(240×320)로 덮어썼더니 **한컴이 사진을 점만 하게 그렸다**(실측). 이 라이브러리는
  표시 크기와 같은 한글 단위로 적고 한컴도 그 전제로 읽는다. 규격 문서만 보고 고치지 말 것.
- **좌석 칸 높이를 키우면 교탁 줄이 다음 쪽으로 밀린다.** 처음 44000 HU 로 잡았다가 교탁이
  잘렸다. 사진 모드는 위아래 여백·머리말을 줄여 자리를 벌고, 좌석 영역을 38000 HU 로 둔다.
- 사진이 들어가려면 **칸이 높아져야 한다.** PDF 는 칸 높이 상한 32pt(`SeatingPdf.ts:112`),
  한글은 고정 6649 HU(`HwpxExporter.ts:520`) 가 걸려 있다.

## 4. 설계

### 4-1. 레이어 배치 (Clean Architecture)

```
domain/entities/StudentPhoto.ts          (변경 없음)
  ↑
usecases/studentPhoto/LoadSeatingPhotos.ts   ← 신규: 내보내기 시점에만 사진 바이트를 읽는다
  ↑
adapters/components/Seating/Seating.tsx      ← 내보내기 버튼이 호출, 결과를 exporter 에 넘김
  ↓
infrastructure/export/{pdf/SeatingPdf, ExcelExporter, HwpxExporter}.ts
                                             ← 저장소를 모른다. 넘겨받은 사진만 그린다
```

**exporter 가 사진 저장소를 직접 import 하지 않는 것이 핵심이다.**
빌드 게이트(`scripts/check-bundle-isolation.mjs:44`)가 학생용 화면 파일에 `student-photos`
문자열이 섞이면 빌드를 실패시킨다. 지금 학생 정보를 `getStudent` 로 넘겨받는 방식과 똑같이,
사진도 **호출하는 쪽이 넘겨준다.**

### 4-2. 신규 usecase

```ts
// src/usecases/studentPhoto/LoadSeatingPhotos.ts
/** 그림 하나를 그리는 데 필요한 최소 정보 — domain 에 둔다(infrastructure 가 import 해야 함) */
// src/domain/entities/StudentPhoto.ts
export interface StudentPhotoImage {
  readonly bytes: Uint8Array;
  readonly mimeType: string;
  readonly width: number;
  readonly height: number;
}

/** 담임/수업반 한 명단의 사진을 좌석표 식별자 기준 Map 으로 읽는다 (내보내기 시점에만 호출) */
export async function loadSeatingPhotos(
  repository: IStudentPhotoRepository,
  scope: { ownerKind: StudentPhotoOwnerKind; ownerKey: string },
): Promise<ReadonlyMap<string, StudentPhotoImage>>;

/** 메뉴에 사진판 줄을 보일지 — 목록(메타)만 보고 판단한다 */
export async function hasSeatingPhotos(...): Promise<boolean>;
```

- 담임: `ownerKind='homeroom'`, `ownerKey='homeroom'` → 키는 `Student.id`
- 수업반 확장 시: 키에서 `{반id}--` 접두사를 떼어 `학년-반-번호` 로 맞춘다
  (`useStudentPhotoUrls` 와 동일 규칙 — **두 곳에 흩어지지 않게 이 함수 하나로 모은다**)

### 4-3. 포맷별 레이아웃

**PDF** (`SeatingPdf.ts`)

- 칸 높이 상한 32pt → 사진 모드에서는 `min(130, 445/rows)`
- 칸 안: 사진(3:4, 위) + 이름(아래 14pt 줄)
- 사진 높이 = `cellH - 이름줄 - 여백`, 너비 = 높이×3/4, `seatW - 8` 로도 제한
- `image/jpeg` → `embedJpg`, `image/png` → `embedPng`, 그 외 → **이름만** (조용히 건너뜀)

| 배치           | 칸 크기   | 사진 높이 |
| -------------- | --------- | --------- |
| 4줄×6열 (24명) | 105×111pt | 약 80pt   |
| 5줄×6열 (30명) | 105×89pt  | 약 62pt   |
| 6줄×6열 (36명) | 105×74pt  | 약 50pt   |

**한글** (`HwpxExporter.ts`)

- 좌석 칸 높이 고정 6649 → `min(9500, 38000/줄수)` HU (5줄이면 7600)
- 사진 모드는 위아래 여백·머리말을 줄인다(2834→1417) — 그래야 교탁 줄이 안 밀린다
- 칸 안: 사진 문단(신규) + 이름 문단. **학번 줄은 빼고 두 줄로** 만든다 (높이가 모자란다)
- 사진 높이 = `칸 높이 − 2100`, 너비 = 높이×3/4, 칸 안쪽 너비로도 제한
- 새 문단에는 `linesegarray` 를 넣지 않는다 · `imgDim` 은 건드리지 않는다 (2-4)

### 4-4. 화면 — 담임(`Seating.tsx`) · 수업반(`ClassSeatingTab.tsx`)

- 내보내기 형식에 사진판 2종(PDF·한글) 추가
- 사진은 **내보내기를 누른 그 순간에만** 읽는다 (화면에 상시 올리지 않는다)
- 사진판 2줄은 `FEATURE_FLAGS.studentPhotos` 가 켜져 있고 **사진이 1장 이상일 때만** 보인다
- 사진판 앞에 구분선 + "얼굴 사진 넣기" 소제목

**수업반에서 추가로 한 것**

- **PDF 내보내기 자체를 신설했다.** 그동안 수업반은 Excel·한글 2종뿐이었다.
- 사진 범위는 `{ ownerKind: 'teaching-class', ownerKey: classId }` — **그 수업반 사진만** 나온다.
- ⚠️ **열쇠가 맞아떨어지는 이유**: `ClassSeatingTab` 이 좌석표용 `Student` 를 만들 때
  `id` 에 `studentKey`(`학년-반-번호`)를 넣는다. `loadSeatingPhotos` 도 수업반이면 저장소 키에서
  `{반id}--` 접두사를 떼어 같은 값을 돌려준다. 그래서 내보내기 코드는 **한 줄도 안 고쳤다.**
  이 대응이 깨지면 사진이 조용히 한 장도 안 붙으므로 단위 테스트로 못 박아 두었다.

### 단위 테스트

`src/infrastructure/export/__tests__/photoSeating.test.ts` (6건)

⚠️ **알파(투명도) 있는 PNG 로 세면 개수가 어긋난다** — pdf-lib 이 투명도용 그림을 하나 더
만든다. 시험용 이미지는 알파 없는 것을 쓴다.

`src/usecases/studentPhoto/__tests__/LoadSeatingPhotos.test.ts` (6건)

- 담임 열쇠는 `Student.id` 그대로 / 수업반은 `{반id}--` 접두사를 떼어 `학년-반-번호` 로
- 다른 명단(다른 수업반·담임) 사진이 섞이지 않는다
- 사진 본체를 못 읽거나 빈 파일이면 그 학생만 빠진다
