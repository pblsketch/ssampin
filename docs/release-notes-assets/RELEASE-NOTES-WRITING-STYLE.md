# 🔒 쌤핀 인앱 업데이트 안내 (release-notes.json) 작성 스타일 가이드 (v2.0.4 도입)

> **이 스타일은 v2.0.4부터 모든 신규 release-notes.json description 작성에 적용된다.**
> 본 가이드는 인앱 `UpdateNotification` 모달과 `Settings > 앱 정보`의 릴리즈 노트 섹션에 노출되는 텍스트의 친화도를 Threads 게시글 수준으로 유지하기 위한 contract다.
>
> 카드뉴스 스타일: `CARD-NEWS-STYLE.md`
> Threads 타래 스타일: `THREADS-POST-STYLE.md`
> 본 가이드는 위 두 가이드와 4채널(인앱 / Threads / 카드뉴스 / 노션) 동기화의 master 역할.

---

## 1. 4슬롯 description 구조 (필수)

모든 `changes[].description`은 **4슬롯 구조**로 작성한다. 슬롯은 위에서 아래로 흐르며, 빈 줄 1개로 구분한다.

```
{슬롯 1: 리드}

· {슬롯 2: 불릿 1}
· {슬롯 2: 불릿 2}
· {슬롯 2: 불릿 3}

{슬롯 3: How — [설정 > 경로]로 켜세요}

{슬롯 4: 공감 마무리}
```

### 슬롯별 정의

| 슬롯 | 역할 | 길이 | 필수도 |
|------|------|------|--------|
| 1. 리드 | **무엇이 달라지는가** — 사용자 시점, 본질부터. (How는 슬롯 3) | 60~120자 (1~2 문장) | **필수** |
| 2. 불릿 | 핵심 동작·옵션 나열 (`· ` 시작) | 각 50자 내, 3~5개 | new·major improve 필수 / 단순 fix·improve 생략 가능 |
| 3. How | 어디서 켜는가 — 대괄호 UI 경로 + 환경 한정 | 30~80자 | 사용자 액션 가능 시 필수 / 자동 동작은 생략 |
| 4. 마무리 | 교실·업무에서 **언제 도움이 되는가** (공감형 한 줄) | 30~60자 | new·major improve 필수 / 단순 fix는 생략 가능 |

### 진입 순서 원칙

**Why → What → How → 공감** 순서로 흐른다. 절대 How(설정 경로)부터 시작하지 않는다.

```
❌ "Windows 설정 → 위젯 → [바탕화면 아이콘 아래 모드]를 켜면..."  (How로 시작)
✅ "위젯이 일반 창이 아니라 진짜 바탕화면 작업판처럼 깔립니다."  (Why로 시작)
```

## 2. 톤·어투

- **기본**: `~어요`, `~합니다`, `~세요` 혼용. **옆자리 선배 교사** 톤.
- **금지**:
  - `~됐다`, `~된다` 등 보고서체
  - 1인칭 복수("우리·저희") — 객체화·기능 시점 회피
  - 과장 영업어("강력한", "혁신적인", "최첨단", "압도적")
- **권장 동사 (신규)**: "추가했어요", "정비했어요", "정밀화했어요", "한 번에 정리할 수 있어요"
- **권장 동사 (수정)**: "차단했어요", "봉쇄했어요", "근본 해결", "영구 해소" — 같은 사고가 다시 안 생긴다는 신호
- **권장 동사 (개선)**: "다듬었어요", "보강했어요", "끌어올렸어요"

### 시점 통일

기능 주체가 아니라 **사용자 시점**으로 쓴다.

```
❌ "크기 조절이 가능합니다"  (기능 주체)
✅ "원하는 크기로 자유롭게 맞출 수 있어요"  (사용자 시점)

❌ "동기화 제안 기능을 추가했어요"  (기능 주체)
✅ "한 번에 골라 보낼 수 있도록 정비했어요"  (사용자 시점)
```

## 3. 길이 가이드

| 구분 | 권장 길이 | 슬롯 사용 |
|------|----------|----------|
| `highlights[]` 각 항목 | **40~60자** | 단일 줄, 이모지 1개 + em-dash + 한 줄 요약 |
| `description` — 단순 `fix`·`improve` | **80~150자** | 슬롯 1 + 3 (불릿·마무리 생략) |
| `description` — `new` / 메이저 `improve` | **250~400자** | 4슬롯 모두 |
| `description` 절대 상한 | **500자** | Threads 제한과 통일, 모달 스크롤 부담 한계 |

**현실적 잣대**: 한 description의 텍스트 본문이 모달에서 5초 안에 훑어지는가? 안 훑어지면 너무 길다.

## 4. 이모지

| 자리 | 규칙 | 예시 |
|------|------|------|
| `highlights[]` 첫머리 | **이모지 1개** (현재 정책 유지) | `🖥️ 바탕화면 아이콘 아래 모드 신설 — ...` |
| `description` 본문 | **이모지 0개** (Threads와 동일) | — |
| `description`의 type=fix 강조 | `⚠️` **1개만 예외** (보안 핫픽스 등 강한 주의 환기 필요 시) | `⚠️ 데이터 손실 가능 사고를 차단했어요...` |
| 슬롯 4 (마무리) | 이모지 금지 | — |

이모지 연속 사용·장식적 이모지(✨🎉🚀) 절대 금지.

## 5. 기호·구두점

| 자리 | 기호 | 비고 |
|------|------|------|
| 강조·분리 | em-dash `—` (U+2014) | hyphen `-`·en-dash `–` 금지 |
| 불릿 (1단계) | `· ` (가운뎃점 + 공백) | `-`·`*`·`•` 금지 |
| 불릿 (2단계, 종속) | `  ◦ ` (들여쓰기 2칸 + 공백 점) | 거의 안 쓰는 게 좋음 |
| UI 경로 | 대괄호 `[설정 > 위젯 > 외곽선]` | 화살표 `→` 보조 사용 가능 |
| 강조 키워드 | `**bold**` (마크다운 호환) | UI 렌더가 정규식으로 처리 |
| 환경 한정 | 괄호 `(Windows 11 24H2 검증, macOS 비활성)` | 슬롯 3 끝에 부가 |

## 6. type별 작성 가이드

### 6.1 `type: "new"` (신규 기능)

4슬롯 모두 사용. 가장 풍성한 작성.

```
{본질 한 두 문장 — 사용자 시점}

· {핵심 동작 1}
· {핵심 동작 2}
· {핵심 동작 3}

[설정 > {경로}]에서 사용하세요. ({환경 한정})

{언제 도움이 되는지 한 줄 — 공감형}
```

### 6.2 `type: "improve"` (개선)

기존 기능의 변화. 4슬롯 모두 사용 또는 슬롯 1 + 3 + 4.

```
{무엇을 어떻게 다듬었는지 한 두 문장}

· {개선된 점 1}
· {개선된 점 2}

({환경 한정 또는 적용 대상})

{체감되는 차이 한 줄}
```

### 6.3 `type: "fix"` (버그 수정)

슬롯 1 + 3 (선택). 마무리는 생략 가능.

```
{어떤 사고를 차단·해소했는지 — 사용자 시점, 안심 신호}

· {원인 또는 해결 메커니즘 (선택)}
· {재발 방지 조치 (선택)}

({이전 버전에서 영향 받았던 사용자에 대한 안내, 선택})
```

### 6.4 `type: "change"` (변경)

기존 동작 방식이 바뀐 것. 슬롯 1 + 3 + 4. 사용자가 적응해야 할 변경이라면 마무리에 안내 강조.

```
{무엇이 어떻게 바뀌었는지}

· {새 동작}
· {이전 동작과의 차이}

[설정 > {경로}]에서 조정 가능합니다.

{왜 이렇게 바꿨는지·언제 도움이 되는지 한 줄}
```

## 7. before / after 샘플 (3개)

본 가이드의 살아있는 검증 사례. v2.0.3 actual changes를 4슬롯으로 다시 쓴 것 (소급 적용은 안 하지만 학습용으로 보존).

### 7.1 `new` — 바탕화면 아이콘 아래 모드

**Before** (v2.0.3 실제, 320자, 한 문단)
> Windows 설정 → 위젯 → [바탕화면 아이콘 아래 모드]를 켜면 쌤핀 위젯이 바탕화면 위에 깔린 진짜 작업판이 됩니다. 윈도우키+D로 모든 창을 내려도 위젯은 계속 보이고, 바탕화면 아이콘 위에서는 클릭이 그대로 통과해 평소처럼 폴더를 열 수 있어요. 위젯 빈 공간에서는 클릭·휠·드래그가 모두 위젯으로 라우팅되며, 가장자리 8방향에서 자유롭게 크기 조절이 가능합니다. 마우스를 위젯 위에 올린 동안에는 Ctrl+1~4 단축키로 레이아웃을 즉석 전환할 수 있어요. (Windows 11 24H2 검증 완료)

**After** (4슬롯, 약 340자)
> 위젯이 일반 창이 아니라 **진짜 바탕화면 작업판**처럼 깔립니다. Win+D로 모든 창을 내려도 위젯은 그대로 보이고, 바탕화면 아이콘 위 클릭은 통과해 폴더가 평소처럼 열려요.
>
> · 위젯 빈 공간에서는 클릭·휠·드래그 모두 위젯으로 라우팅
> · 가장자리 8방향 자유 리사이즈, 헤더 잡고 드래그로 위치 이동
> · 위젯 위에 마우스 올린 동안 Ctrl+1~4로 레이아웃 즉석 전환
>
> [설정 > 위젯 > 바탕화면 아이콘 아래 모드] 토글로 켜세요. (Windows 11 24H2 검증, macOS·리눅스 비활성)
>
> 시간표·할일을 늘 곁에 두고 수업하시는 분들께 가장 어울려요.

### 7.2 `new` — NEIS → Google Calendar 자동 동기화

**Before** (v2.0.3 실제, 270자)
> NEIS에서 가져온 학사일정을 구글 캘린더에 그대로 비춰보고 싶다는 요청이 많아 자동 동기화 제안 기능을 추가했어요. 일정 페이지 상단·설정·캘린더 동기화 카드 등 4곳에서 제안 배너가 뜨고, [동기화 시작]을 누르면 학사일정 그룹 단위 토글 또는 개별 항목 체크로 골라 보낼 수 있습니다. 한 번 dismiss하면 영구 [다시 보지 않기]도 가능하고, 매핑을 해제하면 구글 캘린더의 잔존 일정도 자동으로 정리해줍니다.

**After**
> NEIS 학사일정을 **구글 캘린더에도 그대로 비춰** 보고 싶다는 요청이 많아 자동 동기화 제안을 정비했어요.
>
> · 일정·설정·캘린더 동기화 카드 등 4곳에 제안 배너
> · 그룹 단위 토글(시험·휴업·행사) 또는 개별 항목 체크로 선별 전송
> · [다시 보지 않기]로 영구 dismiss 가능
> · 매핑 해제 시 구글 캘린더의 잔존 일정도 자동 정리
>
> 구글 캘린더와 NEIS를 따로 관리하시던 분들께 한 번에 정리할 길이 열렸어요.

### 7.3 `new` — 데이터 백업·복원·데이터 위치 센터

**Before** (v2.0.3 실제, 200자)
> 설정에 [데이터 관리] 메뉴가 신설됐어요. 시간표·자리·일정·학생기록·메모·할일·즐겨찾기 등 모든 사용자 데이터를 한 번에 ZIP으로 백업하고, 다른 PC에서 그대로 복원할 수 있습니다. 데이터가 실제로 어느 폴더에 저장되어 있는지도 한 번에 확인 가능해서, 학교 PC를 옮기거나 노트북 교체 시 사용자가 직접 확인할 수 있어요.

**After**
> 학교 PC를 옮기거나 노트북을 바꿀 때 **1분이면 데이터 이전이 끝나도록** 백업 센터를 신설했어요.
>
> · [전체 백업] — 시간표·자리·일정·학생기록·메모·할일·즐겨찾기·노트·설정을 ZIP 한 파일로
> · [복원] — 다른 PC에서 ZIP 선택 한 번에 그대로 복구
> · [데이터 폴더 열기] — OS 탐색기로 실제 저장 경로 즉시
>
> [설정 > 데이터 관리]에서 사용하세요.
>
> Drive 동기화는 평소 자동 sync용, 백업 센터는 학기말·중요 변경 전 스냅샷 — 두 가지를 보완적으로 쓰면 안전합니다.

## 8. 4채널 동기화 매핑

같은 release-notes.json 데이터가 4채널로 흐른다. 본 가이드의 4슬롯 구조가 master, 나머지는 자동 파생.

| 채널 | 매핑 |
|------|------|
| **인앱 모달** (`UpdateNotification.tsx`) | description 4슬롯 그대로 렌더 (`· `→`<li>`, `**bold**`→`<strong>`, 빈 줄→spacing) |
| **인앱 설정** (`AppInfoSection.tsx`) | description 4슬롯 그대로 렌더, 현재 버전 기본 펼침 |
| **Threads 타래** (`threads-post.md`) | 1 description = 1 thread. 슬롯 1→리드, 슬롯 2→불릿, 슬롯 3→How, 슬롯 4→마무리. 자동 변환기 (Layer 3 D-09) |
| **카드뉴스** (`cards/*.png`) | highlights[] → 카드 1 (인트로) + 카드 N (각 콘텐츠) + 카드 8 (아웃트로). 자동 변환기 (Layer 3 D-10) |
| **노션 가이드** (선택) | description 4슬롯 → 노션 callout/bullet 블록. 자동 변환기 (Layer 3 D-12, P3) |

## 9. 발행 전 체크리스트

릴리즈 직전 release-notes.json 신규 항목에 대해 다음을 확인:

- [ ] 모든 `description`이 4슬롯 구조 (`new`·메이저 `improve`) 또는 슬롯 1+3 (`fix`·단순 `improve`)
- [ ] 슬롯 1이 How(설정 경로)로 시작하지 않음 (Why로 시작)
- [ ] 사용자 시점 어휘 — 기능 주체 동사("가능합니다") 없음
- [ ] 슬롯 4 (마무리)가 공감형 — "~하시는 분께 좋아요", "~할 때 한 번에 정리하기 좋습니다"
- [ ] 이모지: highlights 첫머리 1개만 (description 본문 0개)
- [ ] 기호: em-dash `—` 사용, hyphen·en-dash 없음
- [ ] 불릿: `· ` (가운뎃점) 사용, `-`·`*`·`•` 없음
- [ ] UI 경로: 대괄호 `[설정 > 경로]` 형식
- [ ] 환경 한정: 슬롯 3 끝에 괄호로 명시 (예: `(Windows 11 24H2 검증, macOS 비활성)`)
- [ ] 길이: highlights 40~60자, description 절대 상한 500자
- [ ] Layer 3 변환기 dry-run 실행 → Threads·카드 프롬프트 자동 생성 결과 검수
- [ ] (선택) `notionUrl` 필드 추가된 항목은 모달에서 [📖 자세히 보기 ↗] 노출 확인

## 10. 진화 정책

본 가이드는 **v2.0.4부터 락**된다. 임의 변경 금지. 다음 경우에만 갱신:

1. 사용자(교사) 검증으로 슬롯 구조 또는 톤이 부적합하다는 정량 증거 발견
2. UI 렌더가 새 마크다운 문법(예: 인라인 링크 `[text](url)`)을 정식 지원하게 됨
3. 새 channel 추가 (예: 카카오 채널 자동 발행)
4. 다국어(영어·일본어 등) 지원 시작

갱신 시 본 파일 상단에 변경 이력 추가:

```
## 변경 이력
- v2.0.4 (2026-05-XX): 초안 락
- v2.x.x: ...
```
