## 1. 무엇이 바뀌었나 — 정책 전환의 전모

|                   | 이전 설계 (계획서 §5.7 원안)  | **현재 (2026-08-21 오너 결정)**                        |
| ----------------- | ----------------------------- | ------------------------------------------------------ |
| 민감 표현 감지 시 | **전송 차단.** 강행 옵션 없음 | **경고만.** 선생님이 판단해 그대로 보낼 수 있다        |
| 차단 키워드       | 24개 (§5.7.3-a)               | **차단 목록 없음.** 24개는 전부 **경고 대상**으로 이동 |
| "그래도 보내기"   | UI·코드 어디에도 없음         | **있다.** 그것이 기본 동작이다                         |
| 강제 수단         | 코드                          | **정보 제공**                                          |

### 1.1 ★이 전환이 뒤집는 것 — 숨기지 않고 적는다

- **ADR-061 결정 7-4** _"3등급 차단은 선택이 아니라 필수가 된다"_ → **철회됨.**
- **계획서 §15 성공 기준 8** _"3등급 표현을 입력하면 전송이 차단되고, 강행 경로가 UI에도 코드에도 없다"_ → **다시 써야 한다**(§6).
- **옵트인 안내·개인정보처리방침에 "민감정보를 자동으로 막습니다"라고 쓸 수 없다.**
  → **"무엇이 나가는지 보여 드립니다"** 로 바꾼다. **확인되지 않은 유리한 문구를 쓰지 않는다**는 기존 원칙 그대로다.

### 1.2 그럼에도 이 선택이 성립하는 근거 4가지

1. **차단 논거였던 "경고는 무시된다"가 이 UI에는 적용되지 않는다.**
   일반적인 경고는 **한 번 뜨고 사라지는 팝업**이다. 여기 경고는 **입력창 위에 상시로 떠 있는
   「나갈 문장」 줄**(설계 §1.2)의 상태 변화다. 타이핑하는 내내 눈앞에 있다.
2. **이 층은 4겹 중 2층일 뿐이다.** 나머지 셋은 그대로다 —
   **이름 자동 삭제**(§5.2) · **도구 등급제**(§4, 민감 데이터를 애초에 못 가져옴) · **전송 직전 PII 관문**(§4.4 그물 ③).
3. **1층(제안 칩)이 실질 방어로 남는다.** 자유 타이핑 자체를 줄이는 구조는 그대로다.
4. **오탐이 기능을 죽인다.** "진단평가 일정 알려줘"가 막히면 선생님은 이 기능을 안 쓴다.
   **안 쓰이는 안전장치는 안전하지 않다.**

### 1.3 ★그래도 남는 위험 — 정직하게

**민감한 내용이 실제로 나갈 수 있다.** 선생님이 경고를 보고도 보내면 나간다. 그리고 무료 티어라
**학습에 쓰일 수 있고 회수할 수 없다.**

→ **이 사실을 사용자 가이드와 옵트인 안내에 적는다.** 완벽을 약속하지 않는다.
→ **관측한다**(§5): 경고 노출 대비 그대로 보낸 비율. **내용은 저장하지 않는다.**
→ 그 비율이 높으면 **경고 문구·형태를 고친다.** 차단으로 되돌리는 것은 오너 재결정 사항이다.

## 2. 3단계 상태 — 「나갈 문장」 줄 하나로 전부 표현한다

새 화면을 만들지 않는다. **이미 설계된 발신 미리보기 줄**(설계 §1.2)이 색과 문구만 바꾼다.

### 2.1 평상시 (정상)

```
┌──────────────────────────────────────────────────────────────┐
│ ↗ 나갈 문장   담당 학생 1명의 이번 달 상태를 요약해 줘        │
│                                            이름 1개 지움  ⓘ  │
└──────────────────────────────────────────────────────────────┘
```

| 요소             | 토큰                                           |
| ---------------- | ---------------------------------------------- |
| 배경             | `bg-sp-bg`                                     |
| 왼쪽 레일        | `border-l-2 border-l-sp-border`                |
| 라벨 "나갈 문장" | `text-sp-muted` · `text-xs` · `font-sp-medium` |
| 본문             | `text-sp-text` · `text-xs`                     |
| "이름 N개 지움"  | `text-sp-success` · `text-xs`                  |
| 모서리           | `rounded-lg`                                   |

### 2.2 주의 (민감 표현 감지) — **막지 않는다**

```
┌──────────────────────────────────────────────────────────────┐
│ ⚠ 나갈 문장   집이 좀 어려운 학생이 있는데 어떻게 도와줄까요  │
│               ~~~~~~~~~~~~~                                   │
│               ↑ 가정 형편 이야기예요                          │
│                                                              │
│   AI에 보내면 학습에 쓰일 수 있고 되돌릴 수 없어요.           │
│   [ 이 부분 지우기 ]   [ 그대로 보내기 ]                      │
└──────────────────────────────────────────────────────────────┘
```

| 요소               | 토큰                                                    | 비고                                                     |
| ------------------ | ------------------------------------------------------- | -------------------------------------------------------- |
| 왼쪽 레일          | `border-l-2 border-l-sp-warning`                        | **색 단독 아님** — ⚠ 아이콘 + 라벨 병용                  |
| 감지 구간          | `underline decoration-wavy decoration-sp-warning`       | 밑줄로 **어디가** 걸렸는지 표시                          |
| 안내문             | `text-sp-text` · `text-xs`                              | ⚠️ `text-sp-warning` 을 본문에 쓰지 않는다(AA 미달 이력) |
| `[이 부분 지우기]` | `bg-sp-card` · `border border-sp-border` · `rounded-lg` | 감지 구간만 지우고 나머지는 살린다                       |
| `[그대로 보내기]`  | `bg-sp-accent` · `text-sp-accent-fg` · `rounded-lg`     | **기본 동작.** `Enter` 로도 그대로 전송된다              |

**★핵심 규칙 4가지**

1. **입력을 막지 않는다.** 타이핑도, `Enter` 도 그대로 동작한다. 경고는 **정보이지 관문이 아니다.**
2. **`[그대로 보내기]` 가 주 버튼이다.** 회색으로 숨기지 않는다 — 숨기면 그게 사실상 차단이다.
3. **어디가 걸렸는지 반드시 표시한다.** 모르면 고칠 수 없다.
4. **입력창 내용은 어떤 경우에도 사라지지 않는다.**

### 2.3 심각 (되돌릴 수 없는 종류) — **역시 막지 않는다. 한 번 더 물을 뿐**

`자해` · `자살` 두 갈래에서만 **확인 한 단계**를 둔다. 차단이 아니라 **확인**이다.

```
┌──────────────────────────────────────────────────────────────┐
│ ⚠ 이 내용은 되돌릴 수 없어요                                  │
│                                                              │
│   보낸 내용은 AI 학습에 쓰일 수 있고, 한 번 나가면            │
│   지울 수 없어요. 그래도 보내시겠어요?                        │
│                                                              │
│   [ 다시 쓸게요 ]        [ 알고 있어요, 보낼게요 ]            │
│                                                              │
│   ─────────────────────────────────────────────              │
│   위기 상황이라면 자살예방상담 109 (24시간)                   │
└──────────────────────────────────────────────────────────────┘
```

- **`자살예방교육` · `자해예방` 처럼 "예방" 이 붙으면 이 단계를 건너뛴다** — 유일한 예외 규칙이다.
- 위기 안내는 **차단 문구가 아니라 도움 정보**다. 작게, 구분선 아래에.
- 이 단계도 **끝에는 반드시 보낼 수 있다.**

## 3. 감지 대상 — 전부 "경고", 심각도만 둘로

> **세는 단위 주의**: 아래 표에는 **개별 단어 32개**(주의 30 · 심각 2)가 그대로 나열돼 있고,
> 구현(`screenAssistInput.ts`)도 **정확히 같은 32개**다(단어 단위로 대조 확인).
> 계획서 §5.7.3-a 의 "24개" 표는 `약물 / 복용` 처럼 **개념을 묶어** 센 것이라 숫자가 다르다.
> **정본은 이 문서와 코드의 32개**이고, 테스트가 그 수를 고정한다.

**코드 위치**: `src/domain/rules/screenAssistInput.ts` 한 파일. 목록을 코드 여기저기 흩지 않는다.

### 3.1 주의 (30개) — §2.2 노란 줄

| 갈래           | 표현                                                                          |
| -------------- | ----------------------------------------------------------------------------- |
| 가정 형태·경제 | 실직 · 해고 · 이혼 · 재혼 · 별거 · 한부모 · 조손 · 위탁가정 · 수급 · 기초생활 |

### 3.2 심각 (2개) — §2.3 확인 한 단계

> 자해 · 자살

### 3.3 ★오탐이 나도 기능이 안 죽는다 — 이 설계의 가장 큰 이점

이전 설계에서는 **"진단"을 넣으면 "진단평가 일정 알려줘"가 막혀서** 허용목록을 정교하게 만들어야 했다.
**경고만 하는 지금은 그럴 필요가 없다.**

> "진단평가 일정 알려줘" → 노란 줄이 잠깐 뜬다 → `Enter` → **그대로 나간다**

**오탐의 대가가 "차단"에서 "잠깐 거슬림"으로 내려갔다.** 그래서:

- **허용목록(예외 처리)을 만들지 않는다.** 유일한 예외는 §2.3의 "예방" 하나뿐이다.
- **목록을 넉넉하게 잡아도 된다.** 넓게 잡는 비용이 낮아졌다.
- **오너가 목록을 나중에 고치기 쉽다.** 상수 배열 하나다.

### 3.4 이름·연락처는 이 층 소관이 아니다

**이름은 경고 대상이 아니라 자동 삭제 대상이다**(§5.2, 별도 장치).
연락처·주민번호 형태는 **전송 직전 PII 관문**(§4.4 그물 ③)이 처리한다. **이 두 가지는 그대로 차단이다.**

> 즉 **"차단이 전부 사라진 것"이 아니다.** 기계가 확실히 판정할 수 있는 것(이름·연락처)은 계속 막고,
> **사람의 맥락 판단이 필요한 것**만 경고로 내렸다.

## 4. 접근성

- 경고 줄은 `role="status"` `aria-live="polite"` — 타이핑 중 끼어들지 않는다.
- §2.3 확인 단계는 `role="alertdialog"`, 첫 포커스는 **`[다시 쓸게요]`**.
- 감지 구간 밑줄은 `<mark>` 로 감싸고 `aria-label="주의: 가정 형편 표현"` 을 붙인다 —
  **밑줄은 시각 정보라 스크린 리더에 안 들린다.**
- `Enter` 전송이 경고 상태에서도 동작한다. **키보드만 쓰는 사람에게 차단이 생기면 안 된다.**
- 경고 색은 절대 단독으로 쓰지 않는다 — ⚠ 아이콘 + `font-sp-semibold` 라벨 병용.

## 5. 관측 (내용은 저장하지 않는다)

| 지표                                 | 왜 보나                                               |
| ------------------------------------ | ----------------------------------------------------- |
| 경고 노출 횟수                       | 목록이 너무 넓은가                                    |
| **경고 후 그대로 보낸 비율**         | **경고가 실제로 읽히는가** — 이 설계의 핵심 검증 지표 |
| `[이 부분 지우기]` 사용률            | 대안 제시가 쓸모 있는가                               |
| §2.3 확인 단계 도달·통과 횟수        | 심각 갈래가 적정한가                                  |
| 제안 칩 사용률 대비 자유 타이핑 비율 | 1층 방어가 작동하는가                                 |

**★어떤 지표에도 입력 내용을 담지 않는다.** 어떤 갈래가 걸렸는지(카테고리명)와 횟수만 센다.
