# 여러 학생의 AI 근거 지도 제안 설계

- 날짜: 2026-09-13
- 상태: G008 root 직접 수정 및 자동 검증 완료, 미배포. G006·G007 독립 리뷰의 재현 결함을 수정하고 최종 집중 94검사·전체 10,793검사·필수 게이트·빌드를 확인했다. 고정 뼈대 실제 화면 완주·AI 주제별 뼈대 선택·담임 화면은 미검증. [직접 마무리 증거](../../../.omo/evidence/record-map-direct-completion.md).
- 범위: 학급 운영 / 수업 관리 → 생기부 초안 → 근거 정리 → 지도.
- 디자인 기준: 루트 `DESIGN.md`의 Information architecture, Design principles, Components, Accessibility, Interaction states. 기존 학생·영역 맥락과 sp-\* 토큰을 유지한다.

## 1. 설계 당시 코드에서 확인한 사실

| 현재 기능                                                          | 직접 확인한 근거                                                            | 이번 요구와의 차이                                                |
| ------------------------------------------------------------------ | --------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| AI로 정리 제안 메뉴에서 미분류 근거 묶기와 주제별 장면 배치를 선택 | `RecordEvidenceBoard.tsx:2025`의 organizeMenu                               | 학생 전체 지도를 구성하는 단일 작업은 아님                        |
| 한 학생의 한 주제에 대한 장면 제안                                 | 같은 파일 `runNarrativeSuggest`(2171), `buildNarrativeSuggestPack`          | 학생 배열, 뼈대 선택 정책 입력 없음                               |
| 제안은 화면 메모리 상태, 적용 전 현재 지도 미변경                  | 같은 파일 `narrativeSuggest`, `applyNarrativeSuggest`(2250)                 | 화면 이동과 장시간 다학생 작업을 위한 제안 보관소 필요            |
| 적용 전에 근거·장면 변경 감지, 적용은 편집 이력으로 감쌈           | `narrativeFingerprint`, `history.run('AI 장면 적용', …)`                    | 학생별 전체 지도 제안에도 확대 필요                               |
| 내장/개인 뼈대, 현재 영역에 맞는 목록, 장면 역할·이름·차례 저장    | `ScaffoldPicker.tsx`, `narrativeFrames.ts`의 RecordScaffold, ADR-116        | AI의 후보 선택·선택 이유·고정 뼈대 검증 없음                      |
| AI 요청에는 현재 장면이 문맥으로 포함됨                            | `narrativeSuggestPack.ts`의 currentScenes                                   | 지정 뼈대의 역할·이름·차례를 강제하는 계약은 아님                 |
| 본문 초안에는 학생 대기열과 중단 기능이 있음                       | `RecordDraftAiPanel.tsx:648` runQueue, `useRecordAiRunStore`, `ownAiRun.ts` | 결과 한 명을 미리보기로 보내고 return. 지도 배치 작업과 별도 기능 |

코드와 현재 저장된 지도 스크린샷(`landing/public/docs/screenshots/record-evidence-map.png`)을 확인했다. 스크린샷은 이번 세션에서 실행한 화면 증거가 아니다. 기존 본문 대기열을 그대로 지도에 연결하면 적용 시점·결과 형식·저장 위치가 다르므로 부적절하다. 취소·오류 처리 원칙은 재사용한다.

## 2. 사용자 요청을 두 축으로 풀기

네 개의 배타적인 실행 모드로 만들지 않는다. 특정 학생 선택과 N명 단위 처리는 함께 사용할 수 있어야 한다.

| 설정      | 선택                                         | 의미                                           |
| --------- | -------------------------------------------- | ---------------------------------------------- |
| 대상 학생 | 현재 학생 / 직접 선택 / 현재 반 전체         | 누가 대상인가                                  |
| 확인 간격 | 1명씩 / N명씩 / 전체 계속 만들기             | 몇 명의 제안을 만든 뒤 다음 생성 전에 멈추는가 |
| 뼈대      | 기존 구성 유지 / 직접 고르기 / AI에게 맡기기 | 주제 안의 장면 구조를 무엇으로 정하는가        |

예: 현재 반 전체 + 1명씩, 선택한 12명 + 3명씩, 현재 반 전체 + 전체 계속 만들기 모두 가능하다.

**설계 가정:** ‘N명씩’은 생성·검토 묶음 크기이며, AI 동시 실행 개수가 아니다. UI에 ‘5명의 제안을 만든 뒤 멈춥니다’라고 명시한다. 전체 계속 만들기는 중간 승인 없이 모든 대상의 제안을 생성하지만 지도 자동 적용을 뜻하지 않는다. 실제 동시 처리 속도 요구는 별도 미확정 사항이다.

## 3. 진입과 설정 화면

기존 상단 `AI로 정리 제안 ▾`에 `여러 학생의 지도 제안…`을 추가한다. 현재 학생의 간단한 주제 묶기·장면 제안은 그대로 접근할 수 있다. 상단에 새 강조 버튼을 늘리지 않는다.

설정은 같은 작업 공간의 넓은 패널에서 진행한다. 학생 선택·뼈대 선택을 중첩 모달로 열지 않는다. 유리 모드의 고정 위치 문제를 피하도록 기존 floating/portal 경계를 따른다.

```text
AI로 지도 제안                                      닫기
수업 관리 · 2학년 3반 · 국어 · 과목별 세특

대상 학생     [현재 학생] [직접 선택] [현재 반 전체]
              12명 선택 · 제안 가능 10명 · 근거 없음 2명

뼈대          (●) 기존 구성 유지
              ( ) 직접 고르기   ( ) AI에게 맡기기

확인 간격     [1명씩] [5명씩 ▾] [전체 계속 만들기]
              5명의 제안을 만든 뒤 멈춥니다.

추가 설정 ▸   기존 주제 유지 / 추가 요청

지도는 검토 후 적용할 때 바뀝니다.
                                      [10명 제안 만들기]
```

- 첫 진입 기본값은 현재 학생·1명씩·기존 구성 유지. 전체 대상 자동 선택은 하지 않는다.
- 다학생 진입에서는 직접 선택을 열고 현재 학생만 선택해 둘 수 있다. 숫자와 실제 목록을 함께 보여 준다.
- 직접 선택에서 이름/실제 출석번호 검색, 전체 선택, 선택 해제, ‘제안 가능한 학생만’ 필터 제공. 검색 결과 전체 선택과 반 전체 선택을 구분한다. 검색을 바꿔도 선택 유지.
- 목록에는 출석번호·이름·사용 가능한 근거 수·기존 주제 수를 표시한다. 근거 0명도 행과 제외 이유를 유지한다.
- N은 양의 정수. 빈값·0·음수·소수에는 인라인 오류. 대상 수보다 크면 ‘선택한 전원 N명’으로 실제 적용값을 표시한다. 마지막 묶음은 남은 인원만 처리한다.
- 현재 반·영역·과목은 고정 맥락으로 표시한다. 영역 ‘전체’로 진입하면 먼저 한 영역을 선택하게 한다. 학급 전체와 학교 전체를 혼동하지 않는다.
- 나가기 전 시작하지 않은 선택은 세션 내 보존한다. 실제 시작 시 학생 목록과 설정의 복사본을 확정한다.

## 4. 뼈대 정책

### 기존 구성 유지 — 기본

이미 구성한 주제의 장면 ID·이름·역할·차례·교사 메모를 유지하고, 미배치 근거의 자리와 필요한 연결만 제안한다. 기존 배치를 이동시키지 않는다. 장면이 없는 새 주제에는 해당 영역의 기본 뼈대를 사용하고 설정 요약에 알린다.

### 직접 고르기

현재 영역에 맞는 내장/개인 뼈대 목록과 장면 차례 미리보기를 기존 고르개 표현으로 제공한다. 선택은 작업 설정이며 실제 `applyScaffold`를 호출하지 않는다. 후보를 고르는 UI와 즉시 지도에 까는 UI의 동작을 분리한다.

- 선택한 뼈대의 역할·이름·차례를 각 대상 주제에 동일하게 사용한다. 주제 내용과 근거 배치는 학생마다 다르다.
- AI가 장면을 추가·삭제·재정렬할 수 없다. 맞지 않는 근거는 ‘자리 미정’으로 남긴다.
- 기존 교사 메모·연결별 해석을 옮길 자리가 불명확하면 ‘확인 필요’로 남긴다. 조용히 삭제하거나 AI 이유로 덮지 않는다.
- 여러 주제가 있으면 선택한 뼈대를 각 주제에 사용한다는 안내를 표시한다. 주제별 예외는 결과 검토에서 조정한다.

### AI에게 맡기기

영역에 맞는 내장/개인 뼈대를 후보로 보내고 **학생의 주제별로** 하나를 선택하게 한다. 학생마다 모든 주제에 같은 뼈대를 강요하지 않는다.

- AI는 제공된 후보 ID만 반환한다. 저장된 개인 뼈대를 수정하거나 새 개인 뼈대를 만들지 않는다.
- 선택 이유는 근거 번호를 짚은 짧은 설명으로 받는다. 자신감 점수처럼 근거 없는 정밀 숫자는 표시하지 않는다.
- 적합한 후보가 없으면 ‘뼈대 직접 선택 필요’로 남긴다. 임의 후보로 몰래 대체하지 않는다.
- 검토 시 `자료 비교형 · 뼈대 바꾸기`에서 다른 후보를 고르면 해당 주제만 다시 제안한다. 앞 제안은 새 결과 확인 전 보존한다.
- 생성 중 개인 뼈대가 변경되어도 시작 시 후보 내용의 복사본을 사용한다. 결과에 사용한 이름·내용·판별용 값이 남는다.

## 5. 주제와 장면을 잇는 전체 지도 제안

기본은 **기존 주제를 유지하고 미분류 근거를 정리**한다. 이미 완료한 주제는 제외한다. 기존 지도를 다시 만들고 싶은 경우에만 추가 설정의 ‘주제부터 다시 제안’을 선택한다. 변경되는 주제·배치는 검토 화면에 분명히 표시한다.

생성 파이프라인은 다음 순서로 실행한다.

1. 학생·반·영역·과목 맥락의 원본과 현재 지도를 복사한다. AI 제외/빈 내용/금지 항목/분량 제한과 이름 가리기를 기존 규칙대로 적용한다.
2. 미분류 근거를 기존/새 주제에 분류하는 **임시 제안**을 만든다. 아직 실제 주제나 근거 소속을 저장하지 않는다.
3. 임시 주제별 뼈대 결정 → 장면 배치 → 장면 사이 이음말을 제안한다.
4. 주제 간 연결은 실제 근거로 설명 가능한 경우에만 제안한다. 제목 유사성·날짜 순서만으로 성장이나 인과를 만들지 않는다. 순환·타학생 연결은 거부한다.
5. 학생별 전체 제안의 참조·뼈대·소속을 검증하고 검토함에 저장한다. 일부 단계 실패는 미완성으로 표시하며 학생 전체 적용을 막고 실패 단계만 재시도한다.

제안 단계에서 원본을 바꾼 다음 되돌리는 방식은 금지한다. 새로운 주제에는 임시 ID를 사용하고 적용 시 실제 ID를 할당한다. `RecordEvidence.threadId`가 주제 소유의 기준이며 장면 다중 참조는 같은 주제 안에서만 허용한다. 원본 하나를 여러 독립 근거처럼 부풀리지 않는다.

AI에서 빠진 근거·교사 제외·화면 범위 밖 근거는 제안에 없다는 이유로 삭제하거나 이동하지 않는다. 분량 제한으로 일부만 보냈다면 누락 건수를 보여 주고 확인 필요로 처리한다. 근거가 적어도 연결할 수 있는 만큼 제안하며 장면을 전부 채우는 것을 성공 조건으로 삼지 않는다.

## 6. 진행과 검토

```text
지도 제안   12명 중 5명 확인 가능 · 실패 1명 · 남음 6명
[계속 만들기]  [중단]

학생 목록             선택한 학생의 지도 제안
01 김○○  검토 대기     주제 2개 · 장면 7개 · 자리 미정 1건
02 이○○  확인 필요     [제안 보기] [현재 지도 보기]
03 박○○  다시 시도     ‘자료 비교’ — 자료 비교형 / 선택 이유
                      기존과 달라지는 점 · 원본 근거 확인

                      [이번 제안 보류] [이 학생 지도에 적용]
```

- 기존 한 학생 지도를 재사용한다. 여러 학생의 축소 지도를 한 화면에 모두 펼치지 않는다.
- 학생 목록은 반 전체 명단이 아니라 이번 작업의 대상·상태 목록이다. 검토 중인 학생을 생성기가 자동으로 바꾸지 않는다.
- 전체 생성 중에도 먼저 끝난 학생을 읽고 적용할 수 있다. 설정은 현재 작업 중 바뀌지 않는다.
- 1명/N명 묶음이 끝나면 다음 생성만 멈춘다. 적용을 강요하지 않고 ‘다음 N명 제안 만들기’로 보류한 채 진행 가능하다.
- ‘현재/제안’ 전환과 변경 요약을 제공하고 선택한 근거의 전문·출처를 읽을 수 있게 한다. AI 설명과 교사 메모를 구분한다.
- 주제별 수정/재제안 후 학생 단위로 적용한다. 초기 버전의 저장 단위는 학생 전체로 통일한다.
- 여러 명 적용은 검토를 마친 학생을 체크한 경우에만 `검토한 4명 적용`으로 제공한다. ‘전체 생성’과 ‘일괄 적용’은 같은 버튼이 아니다. 충돌/미완성/확인 필요 항목은 일괄 적용 불가.
- ‘검토 완료’는 명시적 체크이며 단순히 행을 클릭했다는 이유로 자동 체크하지 않는다. 제안을 수정·재생성하면 체크를 해제한다.
- 적용 성공은 디스크 저장 확인 뒤 표시한다. 일부 학생 저장 실패는 성공/실패를 별도로 집계하고 성공 학생을 재적용하지 않는다.
- 적용된 지도에서 기존 `이 근거로 초안 쓰기` 흐름으로 이어진다. 이번 기능에 본문 자동 생성까지 묶지 않는다.

## 7. 상태·취소·복원 계약

실행 상태와 검토 상태를 분리한다. 생성 성공과 교사 적용은 다른 사건이다.

- 실행: 대기 → 생성 중 → 생성됨 / 실패 / 건너뜀 / 중단됨.
- 검토: 미검토 → 검토 완료 / 보류 / 원본 변경됨 → 적용 중 → 적용됨 / 저장 실패.
- 보낼 근거가 없으면 호출하지 않고 건너뛴 이유를 표시한다. 특정 학생 실패는 다른 학생 생성까지 막지 않는다.
- 제공자 인증/사용량 제한은 대기열을 멈추고 이유와 재개를 제공한다. 자동 무한 재시도 금지.
- 중단은 실행 중 요청 취소와 미시작 요청 중지를 함께 수행한다. 취소 후 늦게 도착한 응답은 run ID/attempt ID로 무시한다. 완성된 제안은 보존한다.
- 화면 닫기는 생성 중단이 아니다. 기존 생기부 화면에 `지도 제안 진행 중/검토 대기`로 재진입한다. 앱 종료 시 실행 중 작업은 중단됨으로 저장하고 재시작 후 사용자가 이어 간다. 자동 재호출하지 않는다.
- 적용 전 fingerprint는 근거 본문/제외 여부/소속, 주제 상태/연결, 장면/메모/초안 포함 설정, 학생·영역 맥락을 포함한다. 지도 좌표만 바뀐 경우는 의미 충돌로 보지 않고 최신 위치를 유지한다.
- 원본이 달라지면 해당 학생만 적용 불가, 현재 기준으로 재제안 가능. 다른 학생 결과는 보존한다.
- 적용 후 학생별 되돌리기를 제공한다. 후속 편집이 생겼으면 옛 전체 자료를 덮지 않는다. 기존 실행 취소는 학생 전환 시 초기화되므로 다학생 작업은 저장된 적용 기록과 별도 복원 검사가 필요하다.

## 8. 구현 구조와 저장 일관성

아래 경로로 구현했다. 기존 기능에서 AI 실행/저장을 UI 반복문으로 호출하지 않고 학생별 실행·검토·적용 책임을 분리한다.

| 계층                                    | 제안 책임                                                                                 |
| --------------------------------------- | ----------------------------------------------------------------------------------------- |
| domain/entities/RecordMapProposal.ts    | 작업·학생별 제안·뼈대 정책·검토 상태·작업 맥락                                            |
| domain/rules/recordMapProposal.ts       | 참조/소속/뼈대 검증, 변경 비교, 상태 전이                                                 |
| domain/services/recordMapSuggestPack.ts | 기존 익명화/제외 규칙으로 주제·뼈대·장면 요청 구성                                        |
| domain/ports 및 repositories            | AI 실행/취소, 제안 보관, 지도 적용 포트                                                   |
| usecases/recordMap                      | 학생별 생성, 묶음 진행, 검토 표시, 적용·재개·되돌리기                                     |
| infrastructure / DI                     | 기존 own AI 연결, IStoragePort 기반 작업·제안 저장 구현                                   |
| adapters/stores/useRecordMapRunStore.ts | 현재 진행 구독, 화면 재진입, 선택 상태                                                    |
| adapters/components/RecordDraft         | RecordMapBatchPanel / StudentSelection / ProposalReview. 기존 지도와 뼈대 미리보기 재사용 |

작업에는 schemaVersion, runId, context(운영/수업, 반 ID, studentRef, 영역, 과목 및 실제 존재하는 학기 식별자), 대상 목록, 확인 간격, 뼈대/후보 복사본, provider, 단계·시도 ID를 저장한다. 학생 이름/화면 인덱스를 식별 키로 쓰지 않는다. 동일 학생의 다른 반·과목을 충돌 없이 구분한다.

학생별 제안에는 원본 fingerprint, 임시 주제, 장면 차례, 근거 ID 참조, 제안 메모, 주제 연결, 뼈대 선택 이유, 제외/미배치 사유, 검토/적용 판본을 저장한다. 완성 제안은 로컬에 저장하되 실제 지도와 별도 파일로 관리한다. 원본 프롬프트·별칭 매핑은 장기 저장하지 않고 재개 시 현재 데이터로 다시 만든다. 보관 실패 시 ‘저장되지 않음’을 표시하고 현재 결과를 유지한다.

초기 실행 동시성은 앱 전체 1개를 제안한다. 기존 본문 생성·채팅과 AI 실행 슬롯을 조정하고, 같은 학생의 같은 맥락에 지도 작업을 중복 시작하지 않는다. N명은 처리 묶음이며 한 프롬프트에 N명을 합치지 않는다. 속도 증대는 제공자 제한과 실측 후 별도 결정한다.

지도 적용은 근거 파일과 주제 파일을 함께 바꾸므로 기존 단일 주제 적용 함수를 반복 호출하는 것만으로 원자성이 보장되지 않는다. 다음을 구현 게이트로 둔다.

1. 저장 직전 최신 로드·충돌 검사와 학생 단위 변경 계획 작성.
2. 전체 파일 저장은 하나의 쓰기 조정자를 통해 직렬화하고 타학생 변경을 최신 자료에 병합.
3. 학생별 적용 전후 기록과 진행 단계를 저장하는 복구 기록 작성.
4. 근거 소속·주제/장면 저장 중 실패하면 해당 변경만 복구. 복구 실패는 복구 필요로 표시하고 추가 적용을 잠근다.
5. 재시작 시 미완료 기록을 검사하고 중복 적용 없이 복원/완료 판정. 테스트로 두 번째 파일 저장 실패를 재현한다.

이 쓰기 경로와 기존 편집 경로의 충돌 제어를 함께 설계해야 한다. 앱이 여러 창에서 같은 파일을 쓴다면 소유 실행기를 하나로 두거나 명시적 IPC 동기화가 필요하다. Zustand만으로 창 간 공유된다고 가정하지 않는다.

## 9. 접근성·레이아웃

- sp-\* 색, 기존 폰트, 4px 간격, rounded-xl, Material Symbols를 그대로 사용한다. 상태는 색과 텍스트로 전달한다.

## 11. 구현 상태와 검증

- 대상 학생, 확인 간격, 뼈대 정책을 서로 독립된 설정으로 구현했다. 상단 `AI로 정리 제안 ▾`에서 여러 학생 패널로 들어가 현재 학생·직접 선택·반 전체와 1명씩·N명씩·전체 계속 만들기, 기존 구성·직접 선택·AI 주제별 선택을 조합할 수 있다.
- 제안 생성과 지도 적용을 분리했다. 생성된 학생별 제안은 검토함에 저장하고, 명시적으로 검토 완료한 학생만 한 명 또는 여러 명에게 적용한다. 원본 fingerprint가 달라지면 그 학생만 막고, 학생 단위 적용 기록으로 되돌린다. 부분 저장 실패는 복구 기록으로 재시작 시 정리한다.
- 2026-09-13 합성 수업반 3-8의 10명 자료와 격리 경로 `E:/github/ssampin/.qa-data-record-map`에서 Electron CDP 9334로 수업 관리 → 생기부 초안 → 근거 정리 → 여러 학생 패널 진입을 확인했다. Codex CLI 0.153.4와 ChatGPT 로그인을 사용한 세 번째 실제 1명 요청에서 기존 구성 유지 정책의 4개 주제와 자리 미정 2건 제안이 생성됐다.
- 제안 전 `record-evidence` 해시 `7D4BE9F9D0C18F540A765DAFC11985F86AB88760685E6461FCAA3EFFA3200A84`, `inquiry-threads` 해시 `76951EBD8462309577BA3F63EF3DEB21392D0378125B117671901DCFE37AE7F1`는 제안 후에도 같았다. 검토 완료 후 적용에서 두 지도 파일이 바뀌고 적용 기록이 `committed`가 됐으며, 되돌린 뒤 `rolled-back`과 `unreviewed`를 확인했다.
- 반 전체 10명·N=3 작업을 실제로 시작해 3초 뒤 중단했다. 실행 중인 AI 요청은 `started`에서 `cancelled`로 끝났고 10개 항목이 모두 `cancelled`로 저장됐다. 패널 재진입에서 `10명 남음`과 [이어 하기]가 복원됐으며, 이어 하기를 실제 시작한 뒤 다시 중단되는 것까지 확인했다. 앱 재시작은 같은 반·영역의 최신 작업을 자동 AI 호출 없이 복원한다.
- 1279×801 라이트·다크와 1439×901 다크 화면에서 패널 표시와 스크롤을 확인했다. 근거 화면은 `output/playwright/record-map-batch/`의 PNG 다섯 장이며, 상세 판정은 `.omo/evidence/record-map-batch-g005/G005-manual-qa.md`에 기록했다.
- 실제 첫 두 기존 구성 응답에서 선택 항목의 null 허용과 빈 장면 계약 결함을 발견해 수정했다. 고정 뼈대 실제 응답은 장면 ID 생략과 표시 이름 사용 때문에 처음 실패했고, 캡처한 응답을 회귀 검사에 추가해 파서 검사는 통과했다. 그 뒤 고정 뼈대 정책의 실제 UI 흐름은 다시 완주하지 못했다. AI가 후보 중 주제별 뼈대를 고르는 정책도 실제 AI로 검증하지 않았다.
- 브라우저 모드는 `electronAPI`가 없어 AI 실행을 검증할 수 없었다. 진입, 10명 표시, 직접 근거 저장만 확인했다. 담임 화면은 공통 보드 속성과 컴포넌트 검사만 통과했으며 실제 화면은 미검증이다. Playwright CLI의 Windows `SyntaxError` 때문에 raw CDP 보조 스크립트로 화면을 캡처했으며 이는 제품 결함으로 판정하지 않았다.
- 첫 최종 리뷰 G006은 독립 아키텍처 리뷰가 P1 5건과 재현된 중단 경쟁 조건으로 `BLOCK`, 독립 코드 리뷰가 높음 5건·보통 5건·낮음 2건으로 `REQUEST CHANGES`를 내어 통과하지 못했다. 불확실한 CAS 뒤 부분 적용, 파일이 없을 때의 CAS 비교값, 뼈대 변경 중 교사 메모 손실, 복구 중 새 적용·클라우드 동기화 진입, 중단 상태를 늦은 완료가 덮는 경쟁 조건, 실행 당시 제공자 맥락, 근거 수준의 현재/제안 비교와 정직한 실패 표시가 주요 보완 범위였다.
- G007에서 불확실한 쓰기 뒤 두 파일을 다시 읽어 `committed`·`rolled-back`·`recovery-required`를 판정하고, 첫 파일이 없을 때 원본 `null`을 CAS 비교값으로 보존했다. 끝나지 않은 복구는 새 적용과 Drive 접근 전 동기화를 막고 앱 시작 시 현재 저장소로 복구한다. 뼈대가 바뀌어도 교사 메모·출처·이음말·연결별 해석을 옮길 수 있을 때만 보존하며, 모호하면 적용 기록을 쓰기 전에 거부한다. 중단된 실행은 늦은 묶음 완료가 덮지 않고, 재개는 작업에 저장된 제공자를 사용한다.
- 앱 전체의 구독 AI 실행을 동시에 하나만 허용한다. 초안+초안, 초안+패널, 패널+초안, 패널+패널의 두 번째 실행은 `busy`로 거절하며 두 번째 프로세스를 만들지 않는다. 정상 종료·취소 뒤 다음 실행은 허용하고 화면에는 한국어 안내를 전달한다.
- 검토 화면은 [AI 제안]/[현재 지도] 전환, 주제·뼈대와 선택 이유·장면 차례/역할·장면/주제 이음말, 근거 차례와 펼쳐 보는 원문·날짜·출처·교사 메모, 자리 미정 원문/이유, 포함·제외·길이 초과·생략 메모 집계를 제공한다. 누락 근거·원본 변경·미완성 제안은 검토와 적용을 막고 그 학생만 다시 제안한다. `scaffoldId: null`은 기존 구성 유지 정책에서는 허용하지만 AI 선택 정책에서는 [뼈대 선택 필요]와 직접 선택 후 재제안으로 처리한다.
