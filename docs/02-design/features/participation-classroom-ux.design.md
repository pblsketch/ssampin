# 퀴즈·설문·토론 — 만들기·진행·참여 경험 개선 설계 (2026-09-21)

대상 도구는 쌤도구의 **퀴즈·설문·토론**(옛 참여교실)이다.
[ADR-125](../../03-decisions/ADR-125.md)~[ADR-130](../../03-decisions/ADR-130.md)으로 문항 유형과 시각 언어를
정리한 뒤, **문항을 만드는 교사 · 수업을 진행하는 교사 · 참여하는 학생** 세 경험을 다듬는 작업이다.

이 문서는 ① 코드와 실화면으로 확인한 현황, ② 레퍼런스 근거, ③ 목표 화면과 상태 전이,
④ 공개 범위(무엇이 누구에게 나가는가)를 담는다. 검증 결과는
[보고서](../../04-report/features/participation-classroom-ux.md)에 있다.

## 1. 확인한 현황 (가설이 아니라 실행 근거)

확인 방법은 두 가지다.

- **코드**: 아래 파일 경로·줄 기준.

## 3. 목표 상태 모델 — 진행 3축

### 3.1 무엇이 바뀌나

기존은 문항마다 `open → revealed` 한 방향이었다. 이제 **응답 잠금**과 **공개 두 종류**를 분리한다.

| 축                  | 값                                       | 저장 위치          |
| ------------------- | ---------------------------------------- | ------------------ | ------------------------------- |
| 응답 받는 중 / 마감 | `phase: 'open'                           | 'revealed'`        | 기존 `LiveSession.phase` 그대로 |
| 결과 공개           | `resultsPublished: boolean` (기본 false) | `LiveSession` 신설 |
| 정답·해설 공개      | `answerPublished: boolean` (기본 false)  | `LiveSession` 신설 |

`phase === 'revealed'` 는 이제 **"응답을 마감했다"** 를 뜻한다(공개 여부와 무관).
기존 이름을 유지하는 이유는 `shareSnapshot`·`ClassroomShareView`·마이그레이션 등 12개 파일이
이 값을 쓰고 있어 이름을 바꾸면 옛 자료 호환과 검사 범위가 함께 흔들리기 때문이다.
대신 **화면에 보이는 말**은 `응답 마감됨`으로 통일하고, 파생 상태를 도메인 한 곳에서 계산한다.

### 3.2 파생 상태 (`domain/rules/participationStage.ts` 신설)

```
lobby      학생 입장 대기
collecting 응답 받는 중                 (phase=open)
closed     응답 마감 · 아직 공개 안 함   (phase=revealed, 결과✗)
results    결과 공개                    (phase=revealed, 결과✓, 정답✗)
answer     정답·해설까지 공개            (phase=revealed, 결과✓/✗, 정답✓)
finished   활동 종료                    (phase=podium|end)
```

정답이 없는 문항은 `answer` 로 가지 않는다. `questionHasAnswer()` 가 판단한다.

### 3.3 교사 조작과 전이

| 단추                    | 조건                            | 하는 일                                                       |
| ----------------------- | ------------------------------- | ------------------------------------------------------------- |
| 활동 시작               | lobby                           | 서버 `activate`, phase=open                                   |
| **응답 마감**           | collecting                      | 서버 `close` → 서버 phase `closed`. 공개 플래그 둘 다 false   |
| **결과 공개**           | closed                          | 서버 `publish`(정답 제외) → 서버 phase `revealed`. 결과✓      |
| **정답·해설 공개**      | closed/results & 정답 있는 문항 | 서버 `publish`(정답 포함). 정답✓                              |
| **토론 후 다시 답하기** | closed/results/answer           | 서버 `reopen`, 차수 +1, 앞선 응답은 `responseHistory` 로 보존 |
| **다음 문항**           | closed/results/answer           | 서버 `advance`. 공개 플래그 초기화                            |
| 활동 종료               | 언제나                          | 서버 `end`                                                    |

**직선 강제 금지** — `closed` 에서 곧바로 [다음 문항]으로 갈 수 있고,
[정답·해설 공개] 전에 [토론 후 다시 답하기]를 할 수 있다.

### 3.4 서버 단계 (`electron/ipc/liveMultiSurvey.ts`)

서버에 `closed` 단계를 새로 둔다. `lobby | open | closed | revealed | ended`.

- `close`: `open` → `closed` (이미 `closed`·`revealed` 면 그대로 둔다 — 두 번 눌러도 안전)
- `publish`: `closed | revealed | ended` 에서만. `revealed` 로 올리고 개인 결과를 갈아 끼운다.
- `advance` · `reopen`: `closed` 와 `revealed` 양쪽에서 받는다.

`closed` 에서 학생에게 내려보내는 것은 **문항 + 내가 낸 답**뿐이다.
집계(`aggregated`)·공감 목록(`voteCandidates`)·개인 결과(`personal`)는 보내지 않는다.

## 4. 공개 범위 — 무엇이 누구에게 가는가

화면에서 감추는 것과 **보내지 않는 것**을 구분한다.

| 자료           | 학생 기기          | 교실 화면(별도 창)                            | 교사 화면 |
| -------------- | ------------------ | --------------------------------------------- | --------- |
| 문항 본문·보기 | 보냄               | 보냄                                          | 보냄      |
| **정답·해설**  | 정답 공개 뒤에만   | **정답 공개 뒤에만**                          | 언제나    |
| 응답 분포      | 결과 공개 뒤에만   | **결과 공개 뒤에만**(의견 문항은 받는 중에도) | 언제나    |
| 개별 응답 원문 | 내 것만            | 공개된 의견 문항만                            | 전부      |
| **학생 별명**  | 내 것만            | **대기실에만**(진행 중에는 안 감)             | 전부      |
| 미응답자 명단  | 안 감              | **안 감**                                     | 교사 전용 |
| 순위           | 내 순위(경쟁 모드) | 교사가 공개할 때만                            | 언제나    |

### 4.1 스냅샷에서 정답을 지운다

`buildShareSnapshot()` 이 `currentQuestion` 을 통째로 실어 보내던 것을 바꾼다.
정답 공개 전에는 `correctAnswer` · `correctChoiceIds` · `acceptedAnswers` · `solution` ·
`explanation` 을 **뺀 문항**을 만들어 보낸다. 화면이 그리지 않더라도 자료가 창에 있으면
개발자 도구·화면 녹화·확장 프로그램 어디로든 샐 수 있다.

`responsesForCurrent` 도 마찬가지다 — 정답 있는 문항은 결과 공개 전까지 빈 배열로 보낸다.

## 5. 화면 설계

### 5.1 활동 목록 (`ParticipationClassroom.tsx`)

```
┌ 퀴즈·설문·토론                                   [쌤도구로] ┐
│ 작은 제목줄 (text-xl) + 한 줄 설명                          │
├──────────────────────────────────────────────────────────────┤
│ [+ 새 활동 만들기]  ← 한 줄 짜리 주요 단추                  │
│                                                              │
│ 이어서 하기            ← 가장 최근에 고친 활동 1개(있을 때) │
│ 내 활동 (n)            ← 최근에 고친 순                      │
│ 지난 활동 결과                                               │
└──────────────────────────────────────────────────────────────┘
```

- 큰 소개 영역은 **활동이 하나도 없을 때만** 보여 준다(첫 사용 안내).
- 활동이 있으면 목록이 첫 화면에 바로 온다.
- 각 줄에 문항 수 · 마지막 수정 시각 · [열기] · [⋯ 더보기(복제/삭제)].
  삭제는 더보기 안으로 넣어 실수로 누르기 어렵게 한다.

### 5.2 편집 화면 (`ParticipationEditor.tsx`)

```
┌ 상단 ────────────────────────────────────────────────────────┐
│ [목록으로] 활동 제목            ● 저장 상태   [활동 설정] [미리보기] [학생 초대하기] │
├─ 왼쪽 240 ─┬─ 가운데(최소 480) ─────────┬─ 오른쪽 미리보기(360) ┐
│ 문항 목록  │ 질문                        │ 실제 학생 화면        │
│ 1 ■ 객관식 │ 보기 (추가/삭제/위·아래)    │ (좁으면 접는다)      │
│ 2 ■ 토론   │ 정답·해설 / 이유 받기       │                       │
│ + 문항 추가│                             │                       │
└────────────┴─────────────────────────────┴───────────────────────┘
```

- **활동 전체 설정은 상단 [활동 설정]** 안으로 옮긴다. 지금 적용된 설정은
  상단에 요약 배지(`경쟁 모드` · `빠른 정답 보너스`)로 남긴다.
- 미리보기는 `1280px 이상`에서만 3열로 편다. 그 아래에서는 상단 [미리보기]가 덮어쓰기(전환)로 뜬다.
  가운데 열은 `min-w-[480px]` 을 보장한다.
- 저장 상태는 네 가지: `저장됨` / `저장하지 않은 변경` / `저장 중…` / `저장하지 못함`.
  **저장을 요청한 시점의 내용**과 견주므로, 저장 중에 고친 내용은 `저장하지 않은 변경`으로 남는다.
- 실행할 수 없으면 상단에 `3번 문항의 두 번째 보기를 입력해 주세요.` 처럼 **자리**를 적고,
  누르면 그 문항으로 이동하고 그 입력칸에 초점을 준다.

#### 보기 조작과 정답 연결

보기는 `{id, text}` 로 관리하고 정답은 `correctChoiceIds`(id 목록)로 가리킨다.
**삭제·이동은 id 를 건드리지 않으므로** 정답 연결이 따라간다. 다만 지금은 두 조작이 없다.

- [위로]·[아래로] 단추 — 키보드만으로도 같은 일을 할 수 있어야 한다.
- [보기 지우기] — 지운 보기가 정답이면 `correctChoiceIds` 에서도 뺀다.
- 보기는 최소 2개를 남긴다.
- 유형 바꾸기([정답 사용] 켜고 끄기)로 정답이 사라지면 **먼저 알린다.**

### 5.3 교사 진행 화면 (`ParticipationConsole.tsx`)

```
┌ 상단 고정 ───────────────────────────────────────────────────┐
│ 활동 제목 · 2/5문항 · 2차 응답     [교실 화면] [활동 종료]  │
├──────────────────────────────────────────────────────────────┤
│ 질문                                            (스크롤 영역) │
│ 입장 25명 · 이번 문항 응답 20명 · 미응답 5명 [명단 보기]     │
│ 결과 / 학생별 응답                                            │
├ 아래 고정 ───────────────────────────────────────────────────┤
│ ● 응답 받는 중        [응답 마감]  (보조) [다음 문항]        │
└──────────────────────────────────────────────────────────────┘
```

- 진행 단추는 **아래 고정 띠**에 둔다. 질문이 길거나 응답이 많아도 밀리지 않는다.
- 현재 상태를 왼쪽에 점+글로 적고, **지금 할 주요 행동 하나만 채움 단추**로 둔다.
  나머지(다음 문항·다시 받기)는 낮은 강조.
- 미응답자 명단은 **교사 전용** 표시와 함께 접힌 채로 둔다.

### 5.4 교실 화면 (`ParticipationShare.tsx`)

- `응답 마감` 상태에서는 `응답을 마감했어요 · 결과를 함께 살펴볼까요?` 만 크게.
  분포·정답은 그리지 않는다(자료도 보내지 않는다 — §4.1).
- 결과 공개 뒤에 분포, 정답 공개 뒤에 정답·해설.
- 교사 전용 명단·미응답자는 어떤 상태에서도 그리지 않는다.
- 창을 운영체제 닫기로 닫으면 `multi-survey-share:closed` 이벤트로 교사 화면에 알린다.

### 5.5 학생 화면 (`participationStudentPage.ts`)

**입장**

```
퀴즈·설문·토론
[활동 이름]
선생님이 연 활동이에요.
별명  [           ]
· 별명은 선생님 화면에 보여요. 다른 친구에게는 보이지 않아요.
[참여하기]
```

- **다른 학생이 입장해도 이 화면이 사라지지 않는다**(P1).
- 실제 설정을 그대로 말한다. 익명이 아니므로 `익명`이라고 쓰지 않는다.

**문항**

- 제목 아래에 응답 방식을 적는다: `하나 선택` / `여러 개 선택` / `이유도 작성` / `순서대로 배열`.
- 척도·숫자·가치수직선은 **고르기 전에는 미선택**이다. 손대지 않고 제출하면
  `얼마나 그런지 골라 주세요.` 로 막는다. 명시적으로 고른 최솟값·0점은 그대로 받는다.
- 작성 중인 내용은 `sessionStorage` 에 **문항·차수별로** 저장한다.
  새로고침·연결 끊김 뒤 돌아오면 되살리고 `쓰던 내용을 되살렸어요.` 로 알린다.
  확정된 제출이 있으면 초안을 쓰지 않는다(충돌 금지).

**제출 뒤**

```
✓ 냈어요            ← 작은 표시
내 답: 책 읽기
내가 쓴 이유: …
다음: 선생님이 결과를 공개할 때까지 기다려 주세요.
```

**마감 뒤 (공개 전)**

```
응답을 마감했어요
내 답: 책 읽기
결과는 선생님이 공개하면 보여요.
```

**활동 종료**

- 내가 낸 답과 근거를 문항별로 되짚는다(`review`).

### 5.6 토론 전후 비교

`responseHistory`(차수별 보존)가 이미 있다. 이것으로 비교 화면을 만든다.

- 교사: 차수별 분포를 위아래로 나란히 두고, 그 아래에 **근거를 두 단**(Kialo 배치)으로 읽게 한다.
  `1차 18명 응답 · 2차 21명 응답` 처럼 차수별 참여 인원을 따로 적는다.
- 학생: 활동 종료 화면에서 `처음 생각` / `토론 뒤 생각`을 나란히 본다.
- 개인별 변화는 **같은 `studentId` 로 이어지는 경우에만** 표시한다. 추정으로 잇지 않는다.
- 입장이 바뀐 것을 향상·점수로 해석하지 않는다. 설문·의견 문항에는 정오 표시를 붙이지 않는다.

## 6. 시각 기준

| 항목      | 규칙                                                                                                    |
| --------- | ------------------------------------------------------------------------------------------------------- |
| 위계      | 질문 > 응답·결과 > 주요 행동 > 설정 > 소개. 소개 문구는 첫 사용 안내로만                                |
| 구획      | 카드 안 카드를 줄인다. 같은 층이면 여백·구분선으로 나눈다                                               |
| 단추      | 주요 행동만 `bg-sp-accent text-sp-accent-fg`. 나머지는 테두리. 삭제는 더보기 안으로                     |
| 토큰      | 채운 배경은 `sp-accent` 만(짝이 되는 `sp-accent-fg` 가 있는 유일한 토큰). 나머지 의미색은 테두리·글자색 |
| 투명도    | `bg-sp-*/NN` 는 이 저장소에서 클래스가 생성되지 않는다 — 쓰지 않는다                                    |
| 모서리    | `rounded-xl` 기준, `rounded-sp-*` 금지, 직각 금지                                                       |
| 문항 목록 | 긴 질문은 두 줄까지. 번호·유형 띠·선택·오류를 색 외에 글·아이콘으로도 구분                              |
| 상태      | 색만으로 뜻을 전하지 않는다. `●`+글 또는 아이콘+글                                                      |
| 터치      | 목표 44×44. 붙어 있는 조작은 24×24 + 간격(WCAG 2.2 AA 2.5.8 예외)                                       |

## 7. 바꾸지 않는 것

- 문항 유형 구성과 이름(ADR-128·129·130). 유형을 더하거나 빼지 않는다.
- 학생 별명 자유 입력. 학급 명렬 연동은 개인정보 판단이 필요해 이 작업 범위 밖이다.
- 자기 속도(과제형) 진행. 접속 서버 구조 결정이 먼저다.
- 결과 내보내기(CSV)·문항 보관함. [격차 분석](../../03-analysis/participation-classroom-gap-20260921.analysis.md) 4·6번 그대로 남긴다.
- 부적절 응답 가리기(`hideWord` 확장)는 이 작업에서 **교실 화면 공개 제어**로 일부만 닿는다.
  응답 단위 가리기는 그 분석 문서의 1번 항목으로 남는다.

## 8. 학생 입장 주소 (2026-09-22 추가 · [ADR-132](../../03-decisions/ADR-132.md))

주소의 종류를 **한 곳**(`domain/rules/participationEntry.ts`)에서 정하고, 화면은 그 규칙만 읽는다.

| 종류        | 언제                        | 화면이 하는 일                                                           |
| ----------- | --------------------------- | ------------------------------------------------------------------------ |
| `preparing` | 터널을 켜는 중              | 주소·QR **감춤** · `활동 시작` 막음 · [기다리지 않고 …] 단추             |
| `internet`  | 터널(+짧은 주소) 성공       | 짧은 주소 + 코드. 경고 없음                                              |
| `local`     | 터널 실패 · 선생님이 내려감 | 같은 Wi-Fi 주소 + 경고. 코드 칸 없음(짧은 코드는 인터넷 주소에만 붙는다) |

규칙이 주는 것: `canInviteStudents()`(안내해도 되는가) · `entryAccessLabel()`(제목) ·
`entryAccessWarning()`(선생님용 경고) · `entryAccessClassroomNote()`(**뒷자리에서 읽히는 짧은 한 줄**) ·
`ENTRY_PREPARING_HINT`.

교실 화면은 스냅샷만 받으므로 `ShareSnapshot.entryKind` 로 같은 값을 전달한다.
선생님용 경고문을 교실 화면에 그대로 띄우지 않는다 — 길이가 다른 화면이다.

한 번 `local` 로 내려가면 되돌리지 않는다(`localChosenRef`). 이미 불러 준 주소를 갈아치우면
학생이 헷갈린다. 터널 성공 뒤 **짧은 주소 발급만** 실패하면 터널 주소를 그대로 쓴다.
