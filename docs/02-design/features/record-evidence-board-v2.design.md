## 4. 항목별 설계

### 4-1. 기존 기록은 미분류에 저절로 (지적 1, R1)

**거울 카드(mirror)** = 아직 근거로 저장되지 않은, 이 학생의 원본 기록 한 건. 후보 계산은 지금 서랍의 `candidatesFor` 를 그대로 옮긴다.

- 위치 이동: `candidatesFor` → `src/usecases/studentRecords/collectEvidenceCandidates.ts`(순수 함수, 스토어 데이터를 인자로 받음) + `src/adapters/hooks/useEvidenceCandidates.ts`(스토어 구독 + 로드). **한 곳에서 계산**해 보드·초안 행·오른쪽 패널이 같은 수를 본다.
- 표시: 미분류 열에 저장 카드와 섞어 **날짜순**으로. 출처 칩 자리에 "관찰기록"처럼 원본 종류를 그대로 쓰고, 카드 배경만 `bg-sp-surface`(저장 카드는 `bg-sp-card`)로 한 단계 가라앉힌다. 별도 배지·설명 문구는 달지 않는다 — 칩과 배경 톤만으로 구분한다(장식 금지).
- 이미 저장된 것과의 중복: `sourceId` 가 이 학생 근거에 있으면 거울을 만들지 않는다(지금 '추가됨' 판정과 같은 규칙).
- 첫 손댐 = 저장: 끌어 주제에 놓기 · 하단 바로 보내기 · AI 제외 켜기 · 수정 → 그 순간 `add({...candidate, threadId?, excludedFromAi?})` 한 번. `RecordEvidenceAddInput.threadId` 가 이미 있어 **주제로 바로 저장이 한 번의 쓰기**다. 여러 장이면 `addMany`.
- 영역(`areas`): 이 컨텍스트 영역이 1개면 그 영역, 여러 개면 보드의 영역 필터 값, 필터가 "전체"면 `[]`(엑셀 업로드와 같은 "유형 미지정" 상태 — 이미 허용된 경로).
- 영역 필터와 거울: 거울은 아직 영역이 없으므로 **어느 필터에서도 미분류에 보인다**(미분류는 받은편지함이다). 저장 카드는 지금처럼 필터를 따른다.
- 기재 금지 어휘: 거울도 `hasProhibitedTerms(content)` 를 계산해 "AI 제외" 상태로 보여 준다(저장하면 스토어가 같은 판정을 하므로 일관).
- 거울에는 [삭제]가 없다. 지울 것은 원본이며, 그 자리는 관찰 탭이다. 쓰기 싫은 기록은 [AI 제외]로 충분하다. 실사용에서 "숨기기"가 필요해지면 그때 `RecordEvidenceData.dismissedSourceIds?` 를 추가한다(지금은 만들지 않는다).
- 초안 행의 [미분류 N건]·오른쪽 패널 「근거」탭의 미분류 수는 **저장 미분류 + 거울**을 합친 수로 바꾼다. 아니면 행은 2건, 보드는 7건으로 어긋난다.
- AI 분류 제안 입력에도 거울을 넣는다(미분류 전체가 입력이다). 제안 적용 시 거울은 `add(threadId)`, 저장 카드는 `moveToThread`.
- 가져오기 메뉴 정리: [가져오기 ▾] → **[엑셀 ▾]**(양식 받기 / 업로드) 둘만. 출처 서랍 5종·[학급 전체 가져오기]·`IMPORT_SOURCES_BY_CONTEXT` 삭제. `RecordEvidenceImportDrawer` 는 엑셀 전용으로 축소(이름은 유지).
- 성능: 후보 계산은 `useMemo` 로 학생·원본 스토어가 바뀔 때만. 관찰·루브릭·성적·첨부 스토어 로드는 보드가 열릴 때 1회(지금 서랍이 하던 것을 보드로 옮김).

### 4-2. 긴 주제 이름 (지적 2)

- 열 머리 `h4`: `truncate` → `line-clamp-2 break-keep leading-snug` + `title` 유지. 건수 배지는 첫 줄 오른쪽에 고정(`items-start`).
- 새 주제 고스트 열 머리도 같게.
- 하단 바 주제 단추: `max-w-[14rem] truncate` + `title`. 단추가 5개를 넘으면 [주제 더 보기 ▾] 로 접는다(지금은 무한히 늘어난다).
- 열 머리 제목을 **두 번 클릭하면 바로 고칠 수 있게** 한다(서랍 `InquiryThreadPanel` 의 `titleDraft` 패턴을 재사용). 이름을 짧게 고치는 길이 서랍 안에만 있는 것이 지금의 불편 중 하나다.

### 4-3-a. 모델 이름은 이름만 (오너 결정 2026-09-06)

"가장 강력함 · 꼼꼼함 · 두루 좋음" 같은 부연 설명을 **전부 뺀다.** 남기는 것은 모델명뿐이다. `기본 (권장)` 은 모델명이 아니라 "고르지 않음"이라 그대로 둔다.

```
claude: 기본 (권장) · Fable 5.1 · Opus 5 · Sonnet 5 · Haiku 4.5
codex : 기본 (권장) · GPT-6 Astra · GPT-5.6 Sol · GPT-5.6 Terra · GPT-5.6 Luna · GPT-5.4 Mini
```

★**목록은 두 군데다.** 화면에 실제로 뜨는 것은 **서버 목록**이고, 앱 안 목록은 서버를 못 받았을 때의 대비용이다.

| 자리                                                    | 역할                   | 필요한 일                 |
| ------------------------------------------------------- | ---------------------- | ------------------------- |
| `src/domain/rules/ownAiCliRules.ts` (101~113)           | 서버 실패 시 대비용    | 코드 수정                 |
| `supabase/functions/ssampin-ai-models/index.ts` (42~57) | **평소에 보이는 목록** | 코드 수정 **+ 함수 배포** |

★배포하지 않으면 코드만 고친 채 화면은 그대로다(엣지 함수는 만들어도 배포를 따로 해야 산다 — 실사고 이력). 배포 뒤 앱에서 설정 > AI 연결의 모델 목록을 **실제로 열어** 설명이 사라졌는지 확인한다. 배포는 오너 승인 후 실행한다(운영 반영).

### 4-4. 끌어다 놓기 (지적 4, R3)

- 라이브러리: `@dnd-kit/core` 만(이미 의존성, 할 일 칸반 선례). `PointerSensor` `activationConstraint: { distance: 6 }` 로 **클릭(선택)과 끌기(이동)를 구분**한다.
- 끌리는 것: 카드 1장. 끄는 카드가 **선택된 상태**면 선택 전체가 함께 간다(끌기 미리보기에 "N건" 배지). 선택 안 된 카드를 끌면 그 한 장만.
- 놓는 곳: 열린 주제 열 · 미분류 열 · [+ 새 주제] 칸(놓으면 이름 입력이 열리고, 확정 시 `moveToNewThread`). 닫힌 주제 열은 받지 않는다(흐려짐).
- 저장: 지금의 관문 `moveToThread / moveToNewThread / unclassify` 그대로. 거울은 `add(threadId)`. **새 저장 경로를 만들지 않는다.**
- 되먹임: 대상 열 `ring-sp-accent`, 끌기 미리보기(`DragOverlay`)는 본문 2줄 압축 카드. 놓은 뒤 토스트 "2건을 '할인 문구와 선택'으로 보냈습니다".
- 키보드: 끌기용 키보드 센서는 붙이지 않는다. 키보드 경로는 하단 바(Enter/Space 로 선택 → Tab 으로 단추)이며 이것이 정석 경로다.
- 분리: 카드를 `EvidenceCard.tsx`, 열을 `EvidenceColumn.tsx` 로 뺀다(보드 1,268줄 → 끌기까지 넣으면 유지 불가).

### 4-5. AI 제외를 카드에서 바로 (지적 5)

- 카드 동작 줄: `[영역 칩들] … [AI 제외 토글] [수정] [삭제]`. [ … ] 단추와 펼침 줄은 없앤다.
- 토글 모양: 꺼짐 = 회색 윤곽 `block` 아이콘 + "AI 제외", 켜짐 = 호박색 채움 + "AI 제외". 메타 줄의 호박색 "AI 제외" 배지는 **없앤다**(같은 정보가 두 번).
- 자동 판정 이유: 켜진 토글의 `title` 과, 켜진 카드 아래 한 줄 "학원 언급이 있어 자동으로 제외했습니다"(`summarizeProhibited`). 교사가 직접 켠 것은 이유 줄 없음.
- 여러 장: 하단 바에 [AI 제외] [AI 제외 해제] 추가. 스토어 `setExcludedFromAiMany(ids, excluded)` **신설**(한 번의 저장). 거울이 섞여 있으면 거울은 `add(excludedFromAi)`.
- 영역이 1개인 컨텍스트에서는 영역 칩을 카드에 그리지 않는다(뺄 수도 없는 칩 — §6-b).

### 4-6. AI 분류 제안이 "없음"으로 끝나는 문제 (지적 6, R2)

원인은 두 겹이다. (a) 지시가 엄격해 서로 다른 활동 3~5건이면 규칙대로 `없음`이 정답이 된다. (b) 화면이 이유를 모르니 교사는 다음에 뭘 해야 할지 알 수 없다.

- 꾸러미(`threadSuggestPack.ts`) 지시 변경:
  - "기록이 하나뿐이어도 뚜렷한 활동이면 그 활동 이름으로 주제를 제안하세요. 서로 관련 없는 기록을 한 주제에 억지로 넣지는 마세요."(R2)
  - "파일 제출 기록(본문 없음)은 같은 과제·활동의 다른 기록과 한 주제에 넣으세요."
  - 기록 줄에 **출처와 태그**를 싣는다: `3. (6/18, 관찰기록, 태그: 개념 설명) 본문…` — 묶을 단서가 본문뿐이던 것을 보강. 실명·학번 가림 규칙은 그대로.
  - `없음` 일 때 형식을 `없음 | 이유 한 문장` 으로.
- 파서(`threadSuggestionParser.ts`): `none` 실패에 `reason?: string` 을 붙인다. 이유 문장도 `restoreModelText` 로 별칭을 되돌린다.
- 화면: `notice` 줄이 막다른 길이 되지 않게 한다.
  - `none`: "AI 판단: {이유}. 카드를 끌어 주제로 옮기거나 [+ 새 주제로]를 눌러 직접 묶을 수 있습니다." + [다시 제안 받기].
  - `no-format` / `no-valid-numbers`: 지금 문구 + [답 원문 보기](접힘, 별칭 상태 그대로 — 실명 없음). 진단이 가능해진다.
  - 실행 중 문구는 유지.
- 진단 로그: 답 원문을 `console.debug('[threadSuggest] answer', …)` 로 남긴다(별칭 상태, 실명 0건). 실기기에서 원인을 볼 유일한 길이다.
- 테스트: 기존 `threadSuggestPack.test.ts` 에 (1) 출처·태그가 실리되 실명 0건, (2) 1건 주제 허용 문구 포함. 파서 테스트에 `없음 | 이유` → `failure: 'none', reason`.

### 5-j. ★영역이 1개일 때 "보이지 않는 필터"가 근거를 통째로 숨겼다 (2026-09-06 실사고, 수정 완료)

§5-b 로 "영역이 1개면 필터 줄을 그리지 않는다"를 넣었는데, **`areaFilter` 값은 그대로 걸린 채**였다(`initialArea` 로 들어온 값).
초등 교과처럼 영역이 `subjectDev` 하나뿐인 화면에서, `areas: ['subject']` 로 분류된 옛 근거 8건이 **화면에서 사라지고 교사가 끌 방법도 없었다.**
실제로 한 학생의 미분류가 10건인데 3건만 보였고, 근거 7건이 묶인 주제 열은 **0건**으로 보였다.

- 고침: 영역이 하나뿐이면 **필터를 아예 걸지 않는다**(`areaFilter = null`). 새로 넣을 때 쓸 영역은 `singleArea` 가 따로 들고 있다.
- 회귀 고정: `RecordEvidenceBoard.test.tsx` — "영역이 1개면 다른 영역으로 분류된 근거도 숨기지 않는다"(고치기 전 코드에서 실패함을 확인).
- 교훈: **끌 수 없는 필터는 필터가 아니라 데이터 소실처럼 보인다.** 컨트롤을 숨길 때는 그 컨트롤이 걸어 두는 값도 같이 풀어야 한다.
  게이트 4종이 전부 초록인 채로 존재했던 결함이다(필터 값이 걸린 경로를 테스트가 렌더하지 않았다).

## 8. 실기기 확인 시나리오

1. 관찰 기록이 3건 있는 학생의 보드를 열면 **가져오기를 누르지 않아도** 미분류에 3장이 가라앉은 배경으로 보이고, 앱을 재시작해도 `record-evidence.json` 에 그 3건이 없어야 정상(저장 0회).
2. 그중 1장을 주제 열로 끌어다 놓으면 열 테두리가 강조색으로 바뀌었다가 카드가 그 열로 가고, 파일에 그 1건만 `threadId` 가 있는 근거로 생겨야 정상.
3. 카드 2장을 클릭해 고른 뒤 하나를 끌면 두 장이 함께 가야 정상. 6px 이내로 눌렀다 떼면 선택만 바뀌어야 정상.
4. 카드의 [AI 제외]를 누르면 호박색으로 바뀌고 하단 바에서 [AI 제외 해제]로 여러 장을 한 번에 되돌릴 수 있어야 정상.
5. 주제 이름을 30자로 지으면 열 머리에 두 줄로 다 보이고, 두 번 클릭해 바로 고칠 수 있어야 정상.
6. 흐름라온에서 [AI 분류 제안] → 이유 문장이 보이거나(없음), 1건짜리 주제 씨앗이 점선으로 떠야 정상. [답 원문 보기]에 실명이 없어야 함.
7. 영역이 1개인 수업반에서는 영역 필터 줄과 카드 영역 칩이 보이지 않아야 정상.
8. 카드 [삭제] 뒤 토스트 [되돌리기]로 5초 안에 복구.

## 9. 하지 않는 것

- 거울 "숨기기"(dismissed 목록) — 실사용에서 필요가 확인되면.
- 키보드 끌기 센서 — 하단 바가 키보드 경로.
- 열 폭을 화면에 맞춰 늘리기.
- 서랍 split — 별도 판단.
- 열 순서 바꾸기(정렬 끌기) — 요청 없음.
