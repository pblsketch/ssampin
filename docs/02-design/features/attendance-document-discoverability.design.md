## 0. 한 줄 요약 (비개발자용)

질병으로 결석·지각한 기록에도 **증빙서류 칸이 기본으로 생깁니다.**
지금은 체험학습(출석인정)에만 생겨서, 진단서를 걷는 학교 선생님 눈에는 이 기능이 아예 없는 것처럼 보였습니다.
무단(미인정)은 서류를 안 걷으므로 아예 대상에서 빼고, 학교 방침이 다르면 설정에서 바꿀 수 있게 합니다.

## 1. 목표 & 범위

**목표** — 증빙서류 기능이 "있는데 안 보이는" 상태를 없앤다.

**범위 안 (7건)**

1. `requiresDocument`에 '미인정' 공통 제외 추가
2. 기본 정책 `{인정}` → `{인정, 질병}`
3. 설정 화면 — '미인정' 행 제거, 설명 재작성
4. 배지 — 상태별 알약/아이콘 차등 (나이스·서류 공통)
5. 정책 밖 출결 수정 화면에 안내 1줄 + 설정 딥링크
6. 업데이트 1회 안내 배너
7. 화면 표기 "증빙서류" 통일 + 사용자 가이드 재작성

**범위 밖 (명시적 제외)**

| 제외                           | 근거                                                                   |
| ------------------------------ | ---------------------------------------------------------------------- |
| 모바일 지원                    | 분석서 §10-3 — 별도 작업 단위                                          |
| 엔티티 스키마 변경             | §11-2 — 2상태라 신규 필드 불요. **동기화·병합 계약을 건드리지 않는다** |
| 출결 입력 화면 체크박스        | §11-4 — 새 기록은 자동으로 '미제출'이라 입력 시점에 할 일이 없다       |
| 기록 단위 '대상 아님' override | §11-1 — 오너가 폐기                                                    |

## 2. 설계 원칙 — **게이트 함수 하나만 고친다**

집계 표면 6곳이 전부 `requiresDocument()` **하나를 통해** 계산한다. 실측:

| 표면          | 호출 지점                        |
| ------------- | -------------------------------- |
| 목록 배지     | `DefaultRecordListView.tsx:158`  |
| 타임라인 배지 | `StudentTimelineView.tsx:186`    |
| 검토 큐       | `useReviewQueue.ts:85`           |
| 미제출 배너   | `AttendanceStatusBanners.tsx:54` |
| 통계 완료율   | `ProgressMode.tsx:906-910`       |
| 조회 필터     | `useRecordFilters.ts:144`        |

→ **규칙(도메인 순수 함수)만 고치면 6곳이 자동으로 따라온다.** 어댑터 코드 변경 0.
이건 M4가 이미 만들어 둔 구조다 — 그 설계를 그대로 활용한다.

## 3. 도메인 레이어

### 3-1. '미인정' 공통 제외 — `attendanceDocumentPolicy.ts`

`isRequired()`에서 정책을 조회하기 **전에** 축을 검사한다.

```
function isRequired(policy, axis, status) {
  // 미인정(무단)은 증빙서류를 걷지 않는다 — 학교 공통(오너 확정 2026-08-27).
  // 정책보다 우선하므로 저장된 설정에 남아 있어도 무시된다(마이그레이션 불요).
  if (axis === '미인정') return false;
  return policy.requiredBy[axis]?.includes(status) ?? false;
}
```

`axisOf()`는 이미 `'미인정'`을 `'인정'`보다 먼저 판정한다(`:47-53`) — `'미인정'.includes('인정')`
때문에 순서가 중요한데 **현재 코드가 이미 올바르다.** 건드리지 않는다.

### 3-2. 기본 정책 확대

```
export const DEFAULT_ATTENDANCE_DOCUMENT_POLICY = {
  requiredBy: { 인정: ALL_DOC_STATUSES, 질병: ALL_DOC_STATUSES },
};
```

'기타'는 **기본 꺼짐** — 정의가 학교마다 달라 보수적으로 둔다. 설정에서 켤 수 있다.

### 3-3. 하위호환

- `attendanceDocumentPolicy === undefined`(설정 미변경 사용자) → 새 기본값 적용 → **의도된 변화**(§5)
- 사용자가 직접 설정한 정책 → 그대로 존중. 단 '미인정'은 3-1이 무시
- 저장된 설정 데이터는 **건드리지 않는다** — settings whole-file LWW 동기화 회피

## 4. 어댑터 레이어

### 4-1. 배지 — `RecordCompletionBadge.tsx`

같은 행의 후속조치 표시(`DefaultRecordListView.tsx:134-149`)가 이미 쓰는 언어를 따른다:
**끝난 일은 맨 아이콘, 남은 일은 알약.**

| kind     | 완료                             | 미완료               |
| -------- | -------------------------------- | -------------------- |
| neis     | 초록 `check_circle` **아이콘만** | 빨강 알약 + "미반영" |
| document | 초록 `description` **아이콘만**  | 주황 알약 + "미제출" |

- 완료 상태도 **클릭 토글 유지** — 오조작 되돌리기 경로를 없애지 않는다
- `title` / `aria-label`은 지금 문구 그대로 유지(라벨이 사라져도 접근성·툴팁은 보존)
- 최소 터치 영역 확보 — 아이콘만이어도 클릭 대상은 충분히 크게

> 시각 최종 확정(정확한 색·아이콘·여백)은 **프론트엔드 디자인 협업 대상**이다.
> 위는 구조 권고이며, 착수 전 확인이 필요하다.

### 4-2. 정책 밖 안내 — `InlineRecordEditor.tsx:319`

출결이면서 `requiresDocument()`가 false일 때, 체크박스 자리에 안내 1줄을 대신 넣는다.

```
지금 방침에선 이 출결의 증빙서류를 걷지 않아요 · [방침 바꾸기]
```

`[방침 바꾸기]` → 기존 딥링크 메커니즘 재사용:
`window.dispatchEvent(new CustomEvent('ssampin:navigate', { detail: 'settings#record-reminder' }))`
(`App.tsx:1039` → `parseNavigationTarget` — `navigationTarget.ts:32`가 `settings#<tab>`을 지원)

**미인정은 예외** — 공통 규칙이라 방침을 바꿔도 안 걷는다. 안내 대신 조용히 아무것도 안 그린다.

### 4-3. 설정 — `RecordReminderSection.tsx`

- **이름 유지**: "증빙서류 요구 설정" (분석서 §11-3 — 정책이 진짜 게이트이므로 이 이름이 정확)
- `AttendanceDocumentPolicyEditor`의 축 렌더에서 **'미인정' 행 제외**
- 설명 문구 재작성:
  > 체크한 출결만 증빙서류 대상으로 관리해요. 기본은 출석인정(체험학습 등)과 질병이고,
  > 무단(미인정)은 서류를 걷지 않아 목록에 없어요. 바꾸면 조회·통계·검토가 바로 다시 계산돼요.

### 4-4. 업데이트 안내 배너 (신규)

`SampleRosterWarningBanner.tsx` 패턴을 그대로 따른다 — 색조 면 + 아이콘 칩 + CTA + 닫기,
닫으면 settings에 `dismissedAt` 저장.

- 표시 조건: `attendanceDocumentPolicy === undefined` **그리고** 아직 안 닫음
  (직접 설정한 사용자는 영향이 없으므로 안 띄운다)
- 위치: 기록 탭 상단
- 문구:
  > 이번 업데이트부터 **질병 출결도 증빙서류 대상**이에요. 학교 방침이 다르면 설정에서 끄실 수 있어요.
  > `[설정 열기]` `[✕]`

### 4-5. 문구 통일

화면 표기를 **"증빙서류"**로 맞춘다 (분석서 §3 — 지금 4가지로 갈려 있다).

| 위치                          | 현재                         | 변경                                               |
| ----------------------------- | ---------------------------- | -------------------------------------------------- |
| `InlineRecordEditor.tsx:329`  | 출결 서류 제출 확인          | **증빙서류 제출 확인**                             |
| `RecordCompletionBadge` title | 서류 제출 완료 / 서류 미제출 | **증빙서류 제출 완료 / 증빙서류 미제출**           |
| 배너·필터·통계 열 라벨        | 서류                         | **증빙서류** (폭 제약 시 "서류" 유지 + title 보강) |

## 5. 리스크 & 완화

| 리스크                           | 영향                                                                             | 완화                                                                                                         |
| -------------------------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| **기존 사용자 미제출 건수 급증** | 설정 미변경 사용자는 과거 질병 출결이 전부 '미제출'로 재계산 → 배너·검토 큐 폭증 | **의도된 결과**(§11-5). 날짜 컷오프는 불가능(정책은 조회 시 계산). → 4-4 안내 배너 + 릴리즈 노트 명시로 예고 |
| 배지 밀도 상승                   | 목록 행마다 서류 배지가 상시 노출                                                | 4-1 차등으로 **완료 상태는 오늘보다 조용해진다**(분석서 §10-4 비교표)                                        |
| 미인정 예외가 과한 일반화        | 무단결석 확인서를 걷는 학교가 있으면 막힌다                                      | 오너 확정 사항. 문제 제기 시 설정 행을 되살리면 되고 **데이터 변경이 없어 되돌리기 쉽다**                    |
| 정책 밖 '기타' 침묵              | 기타 사유는 여전히 안 보임                                                       | 4-2 안내 문구가 그 자리에서 알려준다                                                                         |

**되돌리기** — 이 작업은 **데이터를 하나도 안 바꾼다.** 전부 계산 규칙과 화면이다.
문제가 생기면 기본값을 되돌리는 것만으로 원상복구된다.

**추가 테스트 (신규 작성)**

- `requiresDocument` — '미인정'은 정책에 켜져 있어도 false (공통 제외 우선)
- `requiresDocument` — 새 기본값에서 질병 결석/지각/조퇴/결과 전부 true
- `requiresDocument` — 기본값에서 '기타'는 false
- 다중 교시 OR 집약이 미인정 제외와 함께 동작 (예: 1교시 미인정 + 3교시 질병 → **true**)

> 마지막 두 개가 중요하다 — OR 집약(`:88`)과 레거시 폴백(`:92-94`)은 **서로 다른 경로**라
> 한쪽만 고치면 조용히 어긋난다.
