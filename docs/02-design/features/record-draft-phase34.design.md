# Phase 3 — 학생 자기평가서

## 3-1. 왜 필요한가

오너 요구는 근거 3종(교사 관찰 / 학생 과제물과 교사 평가 / **학생 자기평가서**)의 결합이고,
셋 중 이것만 없다. 교사가 못 보는 것 — 학생이 무엇을 궁금해했고 어디서 막혔는지 — 은
학생만 안다. 실측이 "병목은 모델이 아니라 근거의 구조와 위생"이라고 했으므로, 근거의
**폭**을 넓히는 일이다.

## 3-2. 문항 — 교사가 쓰고, 추천은 슬롯을 달고 온다

**교사 자율이 먼저다.** 빈 칸에서 시작하고, 필요할 때 추천을 꺼낸다.

여기 설계 문제가 하나 있었다. 교사가 자유롭게 쓰면 **학생 답변이 슬롯과 안 맞는다** —
"같은 언어로 정렬한다"는 Phase 3 의 핵심이 깨진다.

→ **추천 문항에 슬롯을 미리 달아 둔다.** 교사가 추천을 고르면 그 문항의 답변이 자동으로
해당 슬롯으로 들어간다. 직접 쓴 문항은 슬롯을 지정할 수 있고, 안 해도 된다.

```
[질문]     이 활동을 하면서 가장 궁금했던 건 무엇이었나요?
[시행착오] 처음 생각대로 안 됐던 지점이 있나요? 어떻게 바꿨나요?
[시도]     여러 방법 중에 무엇을 골랐고, 왜 그걸 골랐나요?
[융합]     다른 과목에서 배운 것과 이어진 데가 있나요?
```

**교사는 자유롭고 AI 는 갈래를 안다.** 이게 이 설계의 핵심 장치다.

## 3-3. 걷는 방식 — 과제에 얹거나, 단독으로

두 갈래 모두 **기존 학생 웹앱**(`student.html` → `src/student/`)을 쓴다. 링크·본인 확인·
제출 폼이 이미 있고, 과제의 `identifyByName`·`studentNumber`·`studentName` 으로 **누가 냈는지
특정된다**(신원 문제는 이미 풀려 있다).

- **과제에 얹기** — 과제를 낼 때 "자기평가도 함께 받기"를 켠다. 학생은 제출 화면에서 같이 쓴다.
  제출물과 성찰이 한 세트로 묶인다.
- **단독 열기** — 과제 없이 수업만 하고도 성찰을 받는다. 같은 링크 방식.

## 3-4. 학기말 종합 — 앞선 답변 보여주기는 교사가 정한다

켜면 학기 동안 쓴 자기평가가 위에 뜨고 그걸 보며 종합한다. 끄면 백지에서 쓴다.

- **켤 때 좋은 점**: 막연한 소감 대신 구체적 회고가 나온다.
- **끌 때 좋은 점**: 기억에 남은 것만 쓰니 진짜 의미 있었던 게 걸러진다. 앞 답변을 베끼지 않는다.

학급 상황이 다르므로 **교사 판단에 맡긴다**(설정 하나 늘어나는 비용은 감수).

## 3-5. ★제출분은 교사가 골라야 창고로 들어간다

**자동으로 안 들어간다.** 제출분은 **대기 목록**에 쌓이고, 교사가 "이건 근거로 쓰자"를 골라야
`RecordEvidence` 로 간다(`sourceType: 'selfAssessment'`).

왜: 학생 글이 곧바로 AI 재료가 되면 **학생 표현이 세특에 그대로 흘러든다.** 세특은 교사가
관찰한 것을 교사의 언어로 쓰는 기록이지 학생 말의 전재가 아니다. 지저분한 응답·장난·빈 답도
걸러야 한다.

창고로 들어갈 때 **Phase 1 의 기재 금지 항목 검사를 똑같이 통과**한다(학생이 수상·학원을
적을 수 있다).

## 3-6. 미결 — 착수 전 확인할 것

⚠️ **미성년자에게서 데이터를 새로 걷는다.** 개인정보 처리방침에 수집 항목·목적·보관 기간이
반영돼야 하고, **에듀집(학운위) 필수기준**과 겹치는지 확인이 필요하다. 이건 설계가 아니라
규제 확인이라 오너 판단이 필요하다.

# Phase 4 — 쌤핀 AI 로 생기부 초안 쓰기

## 4-1. 진입점 — 초안 화면의 버튼

지금 있는 생기부 초안 표에서 학생 줄의 **[AI 초안]** 버튼을 누른다. 맥락(누구·어느 영역)이
버튼 위치로 이미 정해져 있어 말로 짚을 필요가 없다. 결과는 그 칸으로 돌아온다.

AI 대화창은 쓰지 않는다 — "3번 학생 세특 써줘"는 누구·어느 영역인지 말로 짚어야 해 어긋난다.

## 4-2. 단위 — 한 명씩, 또는 골라서 최대 5명

- 기본은 한 명. 학생 줄 버튼.
- 여러 명을 고르면 **최대 5명**까지 한 번에.

★5의 근거는 둘이다. **비용**(일괄이 지출을 튀게 한다)과 **품질**(연달아 쓰면 문장이 닮아간다).
6명째부터는 막고 이유를 한국어로 알린다.

**생기부 전용 일일 상한**을 기존 `ASSIST_DAILY_GLOBAL_LIMIT` 과 **별도**로 둔다 — 생기부가
다른 기능(할 일·일정 조회)의 할당량을 잡아먹으면 안 된다.

## 4-3. 커스텀 프롬프트 — 초안 화면에 접어서

설정 깊은 곳이 아니라 **쓰는 자리**에 둔다. 접힌 칸을 펴서 문체·관점 지시를 적는다.
지금 무엇이 걸려 있는지 그 자리에서 보인다.

★**위험 지시는 저장 시점에 차단**한다(ADR-072 결정 4). 실측에서 사고를 낸 두 종류만 막는다 —
**분량 강제**("반드시 채워라"), **근거 무시**("근거 없어도 써라"). 그 두 줄이 안전 규칙을 이겨
한도의 4배를 창작했다. 여기에 **학생 실명 유입 차단**을 더한다(자유 입력창이라 무심코 적는다).

## 4-4. 결과 — 미리보기 후 [실행]

쌤핀 AI 의 쓰기가 이미 이 방식이다(v2.4.4). 생기부도 따른다 — 바로 칸에 꽂히지 않는다.
저장되면 **Phase 1 의 기재 금지 경고**와 **바이트 한도 검사**를 그대로 통과한다.
모든 초안은 `requiresTeacherReview: true` — 자동 확정 경로는 없다.

## 4-5. 근거가 얇으면 — 돌리되 짧게

막지 않는다. 근거가 두 줄이면 두 줄짜리 초안이 나온다.

실측 근거가 있다: **"본문의 모든 서술이 근거의 어느 줄에서 나왔는지 짚을 수 있는가"를
사용자 입력 맨 끝에 붙이면** 얇은 근거 창작이 0/2 → 2/2 로 고쳐졌다(§3-1). 그 지시를
**사용자 턴 끝**에 넣는다 — 시스템 프롬프트에만 적으면 묻힌다.

교사에게는 근거 건수를 함께 보여 준다(초안 화면에 이미 "근거 N건" 배지가 있다).

## 4-6. ★착수 전 반드시 — 경계 해제

이 Phase 는 `ALLOWED_GRADES = [1]` 을 여는 일이다. ADR-061 결정 7이 "영구 경계"로 못 박은 것을
뒤집는다(ADR-072 결정 2에서 이미 방향은 정해졌다).

1. **계약 테스트 2곳**(`assistToolRegistry.contract.test.ts`·`assistServerRequest.test.ts`)이
   빨간불이 된다. **끄지 말고** 무엇이 새로 열리는지 드러낸 뒤 갱신한다.
2. **ADR-061 결정 7을 대체하는 ADR** 을 남긴다.
3. **개인정보 처리방침** — 학생 서술이 업스테이지로 나간다. **재위탁 대상**에 미국 사업자가
   있는지 방침 표를 직접 열어 확인한다(법인 소재지로 판단하지 않는다).
4. **무료 티어는 학습에 활용되고 옵트아웃이 없다.** 이 사실을 쉬운 한국어로 고지한다.
5. **실측 하네스 재실행** — C·E 사례가 통과로 바뀌는지 본다. 이것을 릴리즈 게이트로 삼는다.

## 4-7. 잠금 — 3단

실험실 기능에서 켬 → 생기부 AI 를 따로 켬 → 고지 확인. 기존 `allowRecordWrite` 패턴을 재사용한다
(`Settings/aiBridge/AiBridgeCard.tsx`).

## 4-8. ★AI 브릿지와의 가르마

두 경로가 **같은 초안 칸**(`record-drafts.json`)에 쓰고 **같은 근거**를 읽는다. 겹치는 채로 두면
서로의 초안을 말없이 덮는다. 셋으로 가른다.

### ① 확정된 것은 누구도 못 건드린다 — **2026-08-25 선반영 완료**

브릿지 core 에는 확정 잠금이 있었지만(`write.ts` "confirmed 잠금"), **앱이 켜져 있으면** 브릿지
쓰기가 loopback 으로 앱 스토어를 타서 **우회됐다** — 앱이 꺼져 있으면 막히고 켜져 있으면
뚫리는 상태였다. 잠금을 `useRecordDraftsStore.upsert`(단일 효과경계)로 올려 경로와 무관하게 막았다.

- 교사 본인은 확정 초안도 고칠 수 있다(자기 기록이다). AI(`origin: bridge|assist`)만 거부.
- 회귀 테스트 5건으로 고정(거부 시 원본 보존·확정 전에는 허용 포함).

### ② 누가 썼는지 초안에 남긴다 — Phase 4 작업

지금 초안에는 출처가 없다. `RecordDraft.source?: bridge|assist|teacher` 를 남기면 덮어쓸 때
"브릿지가 쓴 초안을 쌤핀 AI 로 다시 쓸까요?"를 물을 수 있다. **지금은 말없이 사라진다.**

오늘 넣은 `origin` 은 **잠금 판단용 인자**일 뿐 저장되지 않는다. 엔티티·동기화·브릿지 미러까지
건드리는 일이라 Phase 4 로 묶는다.

### ③ 역할을 나눈다 — 중복이 아니라 **가벼운 길과 깊은 길**

실측이 근거다. `solar-pro3` 는 기재 금지 항목을 못 거르고(C 2/2 실패) 교사 지시에 진다(E 2/2 실패).
Claude·GPT 는 그보다 낫다. 같은 기능의 중복으로 두지 말고 쓰임을 가른다.

|         | 쌤핀 AI (Phase 4)             | AI 브릿지 (기존)                    |
| ------- | ----------------------------- | ----------------------------------- |
| 자리    | **기본값** — 진입장벽 0       | **깊은 길** — 설치·설정 필요        |
| 쓰임    | 근거가 갖춰진 학생을 빠르게   | 품질이 필요한 학생, 대화하며 다듬기 |
| 한 번에 | **최대 5명**                  | 제한 없음                           |
| 비용    | **오너 부담**(일일 상한 별도) | 교사 구독(오너 부담 0)              |
| 모델    | solar-pro3                    | Claude·GPT 등                       |

★두 경로 모두 **같은 안전장치**를 통과한다 — 확정 잠금 · 바이트 한도 · 기재 금지 경고 ·
`requiresTeacherReview` · 근거의 `excludedFromAi`. 안전은 갈라지지 않는다.

## 5. 수용 기준

**Phase 3**

- AC3-1 교사가 문항을 직접 쓰고, 추천을 꺼내 쓸 수 있다. 추천 문항은 슬롯을 달고 온다.
- AC3-2 과제에 얹어서도, 단독으로도 열 수 있다.
- AC3-3 학생이 링크로 들어와 본인 확인 후 제출하면 누가 냈는지 특정된다.
- AC3-4 학기말 종합에서 앞선 답변 노출을 교사가 켜고 끌 수 있다.
- AC3-5 ★제출분은 대기 목록에 쌓이고, **교사가 고른 것만** 창고로 간다.
- AC3-6 창고로 갈 때 기재 금지 항목 검사를 통과하고, 슬롯이 유지된다.

**Phase 4**

- AC4-1 초안 화면 버튼으로 시작하고 결과가 그 칸으로 돌아온다.
- AC4-2 한 명씩·여러 명 모두 되고, **6명째는 막고 이유를 알린다.**
- AC4-3 커스텀 프롬프트를 초안 화면에서 쓰고, **분량 강제·근거 무시·학생 실명**은 저장이 거부된다.
- AC4-4 미리보기 후 [실행]으로만 칸에 들어간다. 모든 초안이 `requiresTeacherReview: true`.
- AC4-5 근거가 얇으면 짧게 나온다(창작하지 않는다). 근거 인용 지시가 사용자 턴 끝에 있다.
- AC4-6 생기부 전용 일일 상한이 기존 상한과 별도로 동작한다.
- AC4-7 3단 잠금이 모두 켜져야 동작한다.
- AC4-8 실측 하네스 재실행에서 C·E 가 통과로 바뀐다.
- AC4-9 ★확정된 초안은 두 AI 경로 모두에서 거부되고 교사는 고칠 수 있다(①, 선반영 완료).
- AC4-10 초안에 출처가 남아, 다른 AI 가 쓴 초안을 덮을 때 교사에게 묻는다(②).
