## 0. 한 문장 요약 (비개발자용)

> 오른쪽에 **사이드바와 짝을 이루는 두 번째 세로 칸**을 연다. 왼쪽 사이드바가 "어디로 갈까"라면 오른쪽 패널은 "지금 뭐가 어떻지"다. 화면을 덮지 않고 **밀어내며**, 답의 절반인 **숫자 카드가 AI 문장보다 먼저** 나타나고, 입력창 위에는 **"실제로 나갈 문장"이 항상 한 줄로 떠 있다.**

## 1. 미적 방향 (Aesthetic Direction)

### 1.1 방향: **조용한 계기판 (Quiet Instrument Panel)**

쌤핀은 교사용 **업무 대시보드**다. 편집형(잡지풍) 기본값 — 따뜻한 크림색 배경, 세리프 디스플레이 폰트, 이탤릭 강조, 테라코타 액센트 — 은 **이 화면에 부적합하다.** 이 패널은 읽고 감상하는 지면이 아니라, 수업 사이 20초 동안 숫자를 확인하고 화면으로 넘어가는 **계기판**이기 때문이다. 따라서 편집형 기본값을 **명시적으로 기각**하고, 아래를 채택한다.

| 축     | 채택값                                                                                                   | 근거                                                                                    |
| ------ | -------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 배경   | `--sp-bg` / `--sp-surface` / `--sp-card` 3단 무채 중성면 — **크림 아님, 종이 아님**                      | 프로젝트 실존 토큰. 새 팔레트를 만들지 않는다                                           |
| 액센트 | `--sp-accent` **단일 액센트** + `--sp-highlight` (사전 확인이 필요한 것에만)                             | 액센트를 **두 개까지만** 쓴다. 셋째부터는 계기판이 크리스마스트리가 된다                |
| 타이포 | `--sp-font-family` (`Pretendard Variable`) **단일 패밀리**, 굵기 축(400/510/590/680)으로만 위계를 만든다 | 새 폰트를 들이지 않는다. 대시보드에서 서체 대비는 소음이다 — **위계는 굵기와 여백으로** |
| 형태   | 카드 `rounded-xl` · 버튼/입력 `rounded-lg` · 칩/배지 `rounded-full`. **직각 0**                          | 프로젝트 라운드 정책                                                                    |
| 밀도   | 4px 그리드. 한 턴 = 16px 간격, 턴 내부 = 8px                                                             | 좁은 폭(320~384px)에서 12px 이상 여백은 사치다                                          |
| 모션   | 120~200ms. **이동 거리 최대 4px.** 스케일 변화 없음                                                      | 업무 중 곁눈으로 보는 패널이 튀면 방해가 된다                                           |

### 1.2 기억에 남을 한 가지 — **발신 미리보기 줄 (The Outbound Line)**

입력창 **위에** 고정된 한 줄이 있다. 선생님이 타이핑하는 동안 이 줄은 **실시간으로 다시 쓰인다.**

```
↗ 나갈 문장:  담당 학생 1명의 이번 달 상태를 요약해 줘        이름 1개 지움
```

이것이 이 패널의 시그니처다. 챗봇 UI에서 "무엇이 나가는가"를 상시로 보여 주는 제품은 흔하지 않고, 쌤핀이 개인정보를 다루는 방식 그 자체가 **장식이 아니라 인터페이스 요소**가 된다. 3등급이 감지되면 **바로 이 줄이 차단 상태로 변한다**(§9) — 그래서 "아무 일도 안 일어난 것처럼 보이는" 문제(§5.7.4)가 시각적으로 해소된다.

### 1.3 기존 고객지원 챗봇과 첫눈에 다르게 보이는 방법

| 축     | 기존 챗봇 (`HelpChat`)       | 쌤핀 AI 패널                                       |
| ------ | ---------------------------- | -------------------------------------------------- |
| 위치   | 우하단 떠 있는 사각 오버레이 | **오른쪽 끝에 붙어 화면 높이를 꽉 채우는 세로 칸** |
| 그림자 | `--sp-shadow-lg` (떠 있음)   | **그림자 없음** + `border-l` 1px (붙어 있음)       |
| 배경   | `--sp-card`                  | `--sp-surface` — 왼쪽 사이드바와 같은 면           |
| 말풍선 | 좌우 정렬된 버블             | **버블 없음.** 카드(앱) vs 평문(AI)의 대비로 구분  |
| 모서리 | 네 모서리 둥금               | **왼쪽 위·아래만 둥글고 오른쪽은 창에 붙음**       |

> **의도**: "떠 있는 것 = 손님", "붙어 있는 것 = 살림살이". 쌤핀 AI는 살림살이 쪽이다.

## 2. 토큰 사용 규칙 + 구현자 주의 5가지

### 2.1 쓸 수 있는 토큰 (`src/index.css:17-98`)

색 `--sp-bg` `--sp-surface` `--sp-card` `--sp-border` `--sp-accent` `--sp-accent-fg` `--sp-highlight` `--sp-info` `--sp-success` `--sp-warning` `--sp-error` `--sp-text` `--sp-muted` `--sp-today-bg` · 반경 `--sp-radius-xs/sm/md/lg/xl/pill` · 그림자 `--sp-shadow-none/sm/md/lg/accent` · 굵기 `--sp-weight-normal/medium/semibold/bold` · 모션 `--sp-duration-quick/base/slow` `--sp-ease-out` `--sp-ease-out-cubic` `--sp-ease-in-out`

### 2.2 주의 5가지 (전부 실제 사고 이력이 있다)

| #   | 주의                                                                                                                                                                                                    |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ①   | **`dark:` 변형은 데스크톱에서 죽어 있다.** 테마는 `.theme-light` / `.theme-dark` 클래스로 전환된다. 이 문서의 모든 색은 **토큰 이름으로만** 지정하고, 다크 대응은 토큰 정의가 알아서 한다               |
| ②   | **`sp-*` 토큰에 Tailwind 투명도 수식(`bg-sp-card/50`)은 무효다** — 조용히 투명하게 렌더된다. 반투명이 필요하면 `opacity-*` 유틸이나 별도 레이어를 쓴다. 이 문서는 **투명도 수식을 한 번도 쓰지 않는다** |
| ③   | **옅은 틴트 위 `text-sp-error`(3.66) / `text-sp-warning`(4.44)은 AA 미달 이력이 있다.** → 이 문서의 모든 경고·오류는 **색 + 아이콘 + 굵기 + 한국어 라벨** 4중으로 표기한다. **색 단독 표기 0건**        |
| ④   | **하드코딩 HEX 0건.** 이 문서는 색을 **토큰 이름으로만** 지정하며 HEX 표기를 한 번도 쓰지 않는다(`grep '#[0-9a-fA-F]{3,6}'` → 0건). 토큰의 현재 값이 궁금하면 `src/index.css:17-98` 을 볼 것            |
| ⑤   | **`rounded-sp-*` 금지 · 직각 금지.** Tailwind 기본 키(`rounded-lg` `rounded-xl` `rounded-full`)만                                                                                                       |

### 2.3 경고·오류 표기 규칙 (③의 구체화)

```
✗ 하지 않는다:   빨간 배경 + text-sp-error 글자
✓ 한다:          bg-sp-card + border-l-2 border-l-sp-error
                 + ⛔ 아이콘 + font-sp-semibold 라벨("보내지 않았어요")
                 + 본문은 text-sp-text (일반 본문색)
```

**원리: 색은 "어디를 볼지"만 알려 주고, "무슨 일인지"는 반드시 글자가 말한다.** 색맹·저대비 환경·다크 테마 어디서도 정보가 사라지지 않는다.

### 3.1 DOM 위치 (기존 사이드바 선례를 그대로 따른다)

`src/App.tsx:1241` 의 `<div className="flex flex-1 min-h-0">` 안에서 `<Sidebar/>`(1243)와 본문(1255)이 **flex row 형제**다. 본문의 **오른쪽 형제**로 패널을 추가하면 동일한 밀어내기 동작을 얻는다.

```
[ Sidebar ]  [ 본문(main, flex-1, overflow-y-auto, p-8) ]  [ ★ 쌤핀 AI 패널 ]
   왼쪽 레일              가운데 (밀린다)                        오른쪽 레일 (신규)

> **좌우 레일 대칭**이 이 배치의 시각적 논리다. 왼쪽은 `bg-sp-surface`, 오른쪽도 `bg-sp-surface`. 가운데 흰 본문이 두 회색 레일 사이에 놓인다.

### 3.4 열림·닫힘 모션

**문제**: 패널 폭을 애니메이션하면 안쪽 텍스트가 매 프레임 재배치되어 글자가 출렁인다.

**해법**: 바깥 래퍼의 폭만 움직이고, 안쪽 내용은 **목표 폭으로 고정**한 채 래퍼가 잘라 낸다.

```
<래퍼>  width: 0 → 384px   transition: width var(--sp-duration-slow) var(--sp-ease-out-cubic)
        overflow-hidden
  <내용> width: 384px 고정 (움직이지 않는다)
```

| 동작 | 속성               | 지속                                                           | 이징                  |
| ---- | ------------------ | -------------------------------------------------------------- | --------------------- |
| 열림 | 래퍼 `width`       | `--sp-duration-slow` (200ms)                                   | `--sp-ease-out-cubic` |
| 열림 | 내용 `opacity` 0→1 | `--sp-duration-base`, **80ms 지연** (폭이 절반 열린 뒤 나타남) | `--sp-ease-out`       |
| 닫힘 | 래퍼 `width`       | `--sp-duration-base` (160ms) — **닫힘은 열림보다 빠르게**      | `--sp-ease-out`       |
| 닫힘 | 내용 `opacity` 1→0 | `--sp-duration-quick` (120ms), 지연 없음                       | `--sp-ease-out`       |

> **원리: 들어올 때는 예의 바르게, 나갈 때는 즉시.** 닫기를 눌렀는데 200ms 기다리는 건 답답하다.

`prefers-reduced-motion: reduce` — 폭 전환 제거, `opacity` 만 `--sp-duration-quick`.

## 4. 진입점 2종

### 4.1 사이드바 하단 항목 (`Sidebar.tsx:386` 블록)

`NAV_ITEMS`(85-98)에 넣지 **않는다.** 설정 버튼과 같은 `border-t border-sp-border` 하단 블록에 형제로 둔다. **이유: 페이지 이동이 아니라 토글이기 때문이다.** 위쪽 목록과 섞이면 "누르면 화면이 바뀐다"고 오해한다.

```
┌─ 사이드바 하단 블록 · border-t border-sp-border · pt-2 ───┐
│                                                           │
│   ✦  쌤핀 AI                              ●           │  ← 꺼짐: 점 없음
│   ↑ 18px         ↑ text-sm weight-medium      ↑ 6px 액센트 점(열림 표시)
│                                                           │
│   ⚙  설정                                                 │
└───────────────────────────────────────────────────────────┘
```

| 상태           | 배경                 | 글자            | 아이콘           | 추가 표시                 |
| -------------- | -------------------- | --------------- | ---------------- | ------------------------- |
| 기본           | 투명                 | `text-sp-muted` | `text-sp-muted`  | —                         |
| 호버           | `bg-sp-card`         | `text-sp-text`  | `text-sp-text`   | — (`--sp-duration-quick`) |
| **열림(활성)** | `bg-sp-card`         | `text-sp-text`  | `text-sp-accent` | 오른쪽 끝 6px 액센트 원   |
| 옵트인 꺼짐    | **항목 자체가 없다** | —               | —                | 계획서 §5.8               |

- 높이 36px(`h-9`), 좌우 12px(`px-3`), 반경 `rounded-lg`, 아이콘↔글자 간격 8px(`gap-2`)
- `aria-pressed` 로 토글 상태를 노출한다 (`aria-expanded` 아님 — 펼침이 아니라 켬/끔이다)
- **활성 표시를 배경색만으로 하지 않는다.** 액센트 점을 함께 둔다(§2.3 원리)

### 4.2 명령 팔레트의 "AI에게 묻기" 항목

매칭 0건 + 질문형 입력일 때만, **결과 목록 맨 위**에 나타난다.

```
┌────────────────────────────────────────────────────────────┐
│  🔎  오늘 결석                                              │
├────────────────────────────────────────────────────────────┤
│                                                            │
│  ┃ ✦  "오늘 결석" 쌤핀 AI에게 묻기               ↵     │  ← 좌측 2px 액센트 레일
│  ┃    오른쪽 패널이 열려요                                  │
│                                                            │
│  ─────────────────────────────────────────────────────     │
│  일치하는 명령을 찾을 수 없습니다                            │  ← 기존 문구, 그대로 남긴다
└────────────────────────────────────────────────────────────┘
```

| 요소             | 스펙                                                                                                         |
| ---------------- | ------------------------------------------------------------------------------------------------------------ |
| 좌측 레일        | `border-l-2 border-l-sp-accent` — **팔레트의 다른 항목에는 없는 유일한 장식.** "이건 명령이 아니라 질문이다" |
| 높이             | 52px (`h-13` 없음 → `py-3` 로 자연 높이). 기존 항목(40px)보다 크다 — 두 줄이기 때문                          |
| 1행              | `text-sm` `weight-medium` `text-sp-text`. 입력한 문구는 큰따옴표로 감싼다                                    |
| 2행              | `text-xs text-sp-muted` — "오른쪽 패널이 열려요" (결과를 예고한다)                                           |
| 선택(하이라이트) | 기존 팔레트 항목과 **동일한** 배경 처리. 레일만 다르다                                                       |
| 엔터 힌트        | 우측 `↵` `text-xs text-sp-muted`                                                                             |
| 기존 문구        | "일치하는 명령을 찾을 수 없습니다"를 **지우지 않는다.** 구분선 아래로 내리고 `text-sp-muted` 유지            |

> **근육 기억 보호**: 매칭이 1건이라도 있으면 이 항목은 나타나지 않는다. 팔레트를 쓰던 선생님의 손이 달라지지 않는다.

## 5. 메시지 요소 4종

### 5.0 이 4종을 가르는 단 하나의 원리

> **앱이 만든 것은 "물체"로, AI가 만든 것은 "공기"로 그린다.**
> 물체 = 테두리·배경·그림자가 있는 카드. 공기 = 배경도 테두리도 없는 평문.
> 그래서 모델이 환각해도 **환각은 공기 쪽에만 있고 숫자는 물체 쪽에 찍혀 있다**(계획서 P2 원칙의 시각화).

### 5.1 ① 숫자 카드 (도구 결과 = 앱 데이터)

```
┌──────────────────────────────────────────────────────┐  rounded-xl
┃ ┌ 헤더 줄 ────────────────────────────────────────┐  ┃  border border-sp-border
┃ │ 지훈 · 3-2 · 8월              [ 앱 데이터 ]     │  ┃  border-l-2 border-l-sp-accent
┃ └─────────────────────────────────────────────────┘  ┃  bg-sp-card
┃                     ↑ gap-3 (12px)                    ┃  shadow-sp-sm
┃ ┌ 숫자 그리드 3열 (384px) / 2열 (320px) ──────────┐  ┃  p-3
┃ │   2          1          3                       │  ┃
┃ │  결석       지각      관찰 기록                  │  ┃
┃ └─────────────────────────────────────────────────┘  ┃
┃                     ↑ gap-2 (8px)                     ┃
┃ ┌ 보조 줄 ────────────────────────────────────────┐  ┃
┃ │ 기록 분류 · 수업태도 2 · 교우관계 1              │  ┃
┃ └─────────────────────────────────────────────────┘  ┃
└──────────────────────────────────────────────────────┘
```

| 부분      | 배경         | 테두리                                                      | 글자                                                  | 반경         | 그림자         |
| --------- | ------------ | ----------------------------------------------------------- | ----------------------------------------------------- | ------------ | -------------- |
| 카드      | `bg-sp-card` | `border border-sp-border` + `border-l-2 border-l-sp-accent` | —                                                     | `rounded-xl` | `shadow-sp-sm` |
| 헤더 제목 | —            | —                                                           | `text-sm` `weight-semibold` `text-sp-text`            | —            | —              |
| 숫자      | —            | —                                                           | **24px** `weight-bold` `text-sp-text`, `tabular-nums` | —            | —              |
| 숫자 라벨 | —            | —                                                           | `text-xs` `weight-normal` `text-sp-muted`             | —            | —              |
| 보조 줄   | —            | 위쪽 `border-t border-sp-border`, `pt-2`                    | `text-xs` `text-sp-muted`                             | —            | —              |

- **왼쪽 2px 액센트 레일이 "이건 앱이 그린 것"의 유일하고 일관된 표식**이다. AI 문장에는 절대 붙이지 않는다.
- 숫자는 반드시 `tabular-nums`. 스트리밍 중 숫자가 좌우로 흔들리면 계기판이 아니다.
- 숫자가 0이면 회색(`text-sp-muted`)으로 낮춘다. **0을 굵게 쓰면 눈이 잘못된 곳에 간다.**
- 값이 4개 이상이면 2행으로 흐른다. **가로 스크롤 금지.**

### 5.2 ② AI 해설 (평문)

```
[AI 요약]  8월에는 결석이 2회 있었고 관찰 기록은 수업태도 쪽이
           많네요. 기록 내용까지는 여기서 볼 수 없어요.
```

| 속성          | 값                                                             |
| ------------- | -------------------------------------------------------------- |
| 배경          | **없음** (패널 배경 `--sp-surface` 그대로)                     |
| 테두리        | **없음**                                                       |
| 글자          | `text-sm` (14px) / 행간 1.7 / `weight-normal` / `text-sp-text` |
| 좌측 들여쓰기 | 배지 다음부터 이어 쓴다. 두 번째 줄부터 들여쓰지 **않는다**    |
| 최대 폭       | 패널 폭 - 32px (스레드 패딩)                                   |
| 배지          | 첫 줄 앞에 인라인 (§5.4)                                       |

> **의도적 대비**: 카드는 회색 면 위 밝은 물체, AI 문장은 면 그 자체. 스크롤하며 훑으면 **카드만 눈에 걸린다** — 그게 맞다. 선생님이 급할 때 필요한 건 숫자다.

### 5.3 ③ 도구 호출 칩 줄

```
🔍 읽음: 출결 요약 (3-2, 8월)   🔍 읽음: 기록 통계 (3건)   ⚠ 실패: 진도 요약   ⌄
└──────── 기본 칩 ──────────┘                              └─ 실패 칩 ─┘   └ 펼침
```

| 종류                        | 배경       | 테두리                       | 글자·아이콘                                                                | 언제                         |
| --------------------------- | ---------- | ---------------------------- | -------------------------------------------------------------------------- | ---------------------------- |
| **기본** (1등급, 사후 표시) | `bg-sp-bg` | `border border-sp-border`    | `text-xs` `text-sp-muted`, 🔍 아이콘 12px                                  | 읽기 도구가 이미 실행됨      |
| **사전 확인 필요**          | `bg-sp-bg` | `border border-sp-highlight` | `text-xs` `text-sp-text` `weight-medium`, ⚑ 아이콘                         | `polish_sentence` · `open_*` |
| **실패**                    | `bg-sp-bg` | `border border-sp-error`     | `text-xs` `text-sp-text` `weight-medium`, ⚠ 아이콘 + **"실패:" 라벨 필수** | 도구 실행 실패               |

- 공통: 높이 24px(`h-6`), 좌우 8px(`px-2`), 반경 `rounded-full`, 칩 간격 4px(`gap-1`)
- **실패 칩의 글자색은 `text-sp-error` 가 아니라 `text-sp-text`** 다 — AA 미달 이력(§2.2 ③) 때문. 빨강은 **테두리에만** 쓰고 의미는 "실패:" 라는 글자가 전달한다.
- 칩을 누르면 아래로 펼쳐진다: `bg-sp-bg` `rounded-lg` `border border-sp-border` `p-3` `text-xs` 안에 **실제로 모델에게 나간 값 원본**. 요약하지 않는다.
- 폭이 모자라면 **줄바꿈**한다(가로 스크롤 금지). 320px에서는 칩 2개 + `+2` 요약 칩.
- 펼침/접힘: `--sp-duration-base` + `--sp-ease-out`, `max-height` + `opacity`.

### 5.4 ④ 출처 배지 3종

```
[ 앱 데이터 ]        [ AI 요약 ]        [ AI 다듬음 ]
 액센트 테두리        테두리 없음         하이라이트 테두리
```

| 배지        | 배경       | 테두리                       | 글자                                      | 위치                     | 뜻                             |
| ----------- | ---------- | ---------------------------- | ----------------------------------------- | ------------------------ | ------------------------------ |
| `앱 데이터` | `bg-sp-bg` | `border border-sp-accent`    | `text-xs` `weight-medium` `text-sp-text`  | 숫자 카드 헤더 **우측**  | 앱이 직접 그림. 모델 문장 아님 |
| `AI 요약`   | **투명**   | **없음**                     | `text-xs` `weight-medium` `text-sp-muted` | 해설 첫 줄 **앞 인라인** | 모델이 생성한 문장             |
| `AI 다듬음` | `bg-sp-bg` | `border border-sp-highlight` | `text-xs` `weight-medium` `text-sp-text`  | 결과 **상단 단독 줄**    | 선생님 문장을 모델이 윤문      |

- 공통: 높이 20px(`h-5`), 좌우 8px(`px-2`), `rounded-full`, 대괄호는 **글자로 넣지 않는다**(모양이 배지다)
- **세 배지 모두 한국어 라벨을 항상 표시한다.** 아이콘만 남기는 축약을 하지 않는다 — 320px에서도 라벨 유지.
- `AI 요약` 배지에만 테두리가 없는 이유: **가장 자주 나오기 때문**이다. 매번 테두리가 있으면 스레드가 울타리밭이 된다.

## 6. 스트리밍 연출

### 6.1 순서 — 답의 절반이 먼저 온다

```
t=0ms      선생님이 Enter
           ↓
t≈0ms      ┌ 사용자 질문이 스레드에 즉시 붙는다 (낙관적 렌더)
           │ 입력창 비움 → 발신 미리보기 줄도 초기화
           ↓
t≈0-40ms   ⋯ 도구 판단 중 ⋯          ← 칩 자리에 스켈레톤 칩 2개 (펄스 없음, 정적 회색)
           ↓
t≈?        🔍 읽음: 출결 요약  ← 칩이 하나씩 확정된다 (각각 fade+2px, stagger 40ms)
           ↓
t≈?        ┌──────────────┐
           │  2   1   3   │  ← ★ 숫자 카드 등장. 여기서 이미 답의 절반
           └──────────────┘     fade + translateY(4px→0), --sp-duration-base, ease-out-cubic
           ↓
t≈+120ms   [AI 요약] ●●●        ← 타이핑 인디케이터
           ↓
t≈?        [AI 요약] 8월에는 결석이 2회 있었고 관찰 기록은▌
                                                        ↑ 커서
           ↓
완료        [ 기록 3건 열어보기 ]  [ 출결 화면 열기 ]   ← 액션 버튼이 마지막에 fade-in
```

> **이 순서 자체가 설계다.** 모델이 3초 늦어도 선생님은 1초 안에 숫자를 보고 있다. 그래서 §7의 실패 처리가 "빈 화면"이 아니라 "문장만 없는 상태"가 된다.

### 6.2 각 연출의 스펙

| 연출                  | 스펙                                                                                                                                    |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| **스켈레톤 칩**       | `bg-sp-card` `rounded-full` `h-6` `w-24`, **애니메이션 없음**(정적). 도구 판단은 보통 1초 미만이라 반짝이면 오히려 산만하다             |
| **칩 확정**           | `opacity` 0→1 + `translateY(2px→0)`, `--sp-duration-quick`, `--sp-ease-out`, 칩마다 **40ms stagger**                                    |
| **숫자 카드 등장**    | `opacity` 0→1 + `translateY(4px→0)`, `--sp-duration-base`, `--sp-ease-out-cubic`. **스케일 변화 없음**                                  |
| **타이핑 인디케이터** | 6px 원 3개, `gap-1`, `bg-sp-muted`. 각 원이 `opacity` 0.35→1→0.35, 주기 1200ms, 서로 **160ms 지연**. 이동 거리 0 (위아래로 뛰지 않는다) |
| **텍스트 스트림**     | 글자 단위 fade 금지(재배치 비용). **문자열을 그대로 이어 붙이고**, 끝에 커서만 둔다                                                     |
| **커서**              | 2px × 1em 블록, `bg-sp-accent`, `animation: 1s step-end infinite` 로 깜빡. 스트림 종료 시 즉시 제거                                     |
| **액션 버튼 등장**    | 스트림 완료 후 `opacity` 0→1, `--sp-duration-base`, 지연 80ms                                                                           |
| **자동 스크롤**       | 사용자가 위로 스크롤한 상태면 **따라가지 않는다.** 대신 하단에 `새 답변 ↓` 알약 버튼(`rounded-full` `bg-sp-card` `shadow-sp-md`)        |
| **감속 모드**         | `prefers-reduced-motion: reduce` → 커서 깜빡임 정지(고정 표시), 인디케이터는 정적 `…`, 모든 `translateY` 제거하고 `opacity` 만          |

### 6.3 비스트리밍 강등 (공급자에 SSE가 없을 때)

숫자 카드까지는 **동일하게** 진행하고, 해설 자리에만 다음을 둔다.

```
[AI 요약]  ●●●  문장을 만들고 있어요…      ← text-xs text-sp-muted
```

시각적 차이는 이것뿐이다. **강등 사실을 크게 알리지 않는다** — 숫자는 이미 나와 있어 체감 손실이 작다.

## 7. 실패·강등 (문구는 계획서 §5.6, 여기서는 시각 처리만)

### 7.1 공통 원칙 3가지

1. **입력창 내용은 어떤 실패에서도 복원된다.** 시각적으로도 "지워졌다가 돌아온" 티가 나지 않게, 전송 실패 시 입력창 텍스트를 **애니메이션 없이 즉시** 되돌린다.
2. **실패한 턴도 스레드에서 자리를 지킨다.** 사라지면 무슨 일이 있었는지 모른다.
3. **숫자 카드는 살아 있다.** 오류 카드는 카드를 **대체하지 않고 아래에 덧붙는다.**

### 7.2 오류 카드 (모든 실패 상황의 공통 형태)

```
   ┌──────────────┐
   │  2   1   3   │   ← ★ 그대로 남는다. 흐려지지도 않는다
   └──────────────┘
          ↑ gap-3
┏━┬──────────────────────────────────────────────┐  rounded-xl
┃ │  ⚠  요약 문장은 지금 만들 수 없어요           │  bg-sp-card
┃ │     숫자는 위에 그대로 있어요.                │  border border-sp-border
┃ │                                              │  border-l-2 border-l-sp-warning
┃ │            [ 다시 시도 ]                     │  p-3
┗━┴──────────────────────────────────────────────┘
 ↑ 2px 경고 레일
```

| 부분      | 스펙                                                                                     |
| --------- | ---------------------------------------------------------------------------------------- |
| 레일      | `border-l-2 border-l-sp-warning` (일시적 실패) / `border-l-sp-error` (차단·한도)         |
| 아이콘    | 16px, 색은 레일과 같은 토큰. **아이콘 단독으로 의미를 전달하지 않는다**                  |
| 1행       | `text-sm` `weight-semibold` **`text-sp-text`** — 경고색 글자 금지(§2.2 ③)                |
| 2행       | `text-xs` `text-sp-muted`                                                                |
| 버튼      | `h-8` `px-3` `rounded-lg` `bg-sp-bg` `border border-sp-border` `text-xs` `weight-medium` |
| 등장 모션 | `opacity` + `translateY(4px→0)`, `--sp-duration-base`. **흔들기·펄스 금지**              |

### 7.3 상황별 시각 차이

| 상황               | 레일 색        | 아이콘 | 숫자 카드   | 버튼          | 추가 표시                                                           |
| ------------------ | -------------- | ------ | ----------- | ------------- | ------------------------------------------------------------------- |
| 429 한도 초과      | `--sp-error`   | ⛔     | **유지**    | 없음          | 헤더의 "남은 질문" → **"내일 열려요"**                              |
| 모델 장애·타임아웃 | `--sp-warning` | ⚠      | **유지**    | `[다시 시도]` | —                                                                   |
| 네트워크 끊김      | `--sp-warning` | ⚠      | **유지**    | `[다시 시도]` | 헤더 우측 `연결 끊김` 칩 (`border-sp-warning`)                      |
| 도구 실행 실패     | — (카드 없음)  | ⚠      | 나머지 유지 | 없음          | **해당 칩만** 실패 칩으로 (§5.3)                                    |
| A→B 강등           | — (카드 없음)  | —      | 유지        | 없음          | 해설 아래 `text-xs text-sp-muted` 한 줄: "간단한 방식으로 답했어요" |

> **A→B 강등은 카드로 만들지 않는다.** 카드로 만들면 실패처럼 보인다. 실패가 아니라 품질 편차의 고지다.

## 8. 거절을 기능으로 — 2등급 응답 카드

계획서 §5.2의 3단 응답(숫자 카드 → AI 해설 → 화면 이동 버튼)을 시각적으로 완성한다. **핵심: "못 한다"가 아니라 "여기서는 이만큼, 나머지는 저 화면에서"로 읽히게 하는 것.**

```
   🔍 읽음: 출결 요약 (3-2, 8월)   🔍 읽음: 기록 통계 (3건)   ⌄
   ↑ gap-2
 ┏━┬─────────────────────────────────────────────────┐
 ┃ │ 지훈 · 3-2 · 8월                 [ 앱 데이터 ]  │
 ┃ │                                                 │
 ┃ │   2          1          3                       │
 ┃ │  결석       지각      관찰 기록                  │
 ┃ │ ─────────────────────────────────────────────   │
 ┃ │ 기록 분류 · 수업태도 2 · 교우관계 1              │
 ┗━┴─────────────────────────────────────────────────┘
   ↑ gap-3
   [AI 요약] 8월에는 결석이 2회 있었고 관찰 기록은 수업태도
   쪽이 많네요. 기록 내용까지는 여기서 볼 수 없어요.
   ↑ gap-3
   ┌───────────────────────┐ ┌────────────────────┐
   │  기록 3건 열어보기 →  │ │  출결 화면 열기 →  │   ← h-8, gap-2, 줄바꿈 허용
   └───────────────────────┘ └────────────────────┘
   ↑ gap-2
   ⌄ 더 깊이 분석하려면 (AI 브릿지)        ← 접힌 채. text-xs text-sp-muted
```

### 8.1 "화면 열기" 버튼 스펙 — **이 패널에서 가장 중요한 버튼**

계획서 §5.1.4의 5번(답과 결과를 동시에 본다)이 이 버튼에 걸려 있다.

| 속성        | 값                                                                                                                      |
| ----------- | ----------------------------------------------------------------------------------------------------------------------- |
| 높이·패딩   | 32px (`h-8`), 좌우 12px (`px-3`)                                                                                        |
| 반경        | `rounded-lg`                                                                                                            |
| 배경·테두리 | `bg-sp-bg` + `border border-sp-accent`                                                                                  |
| 글자        | `text-xs` `weight-medium` `text-sp-text`                                                                                |
| 아이콘      | 오른쪽 화살표 12px, `text-sp-accent`, 글자와 `gap-1`                                                                    |
| 호버        | `bg-sp-card` (`--sp-duration-quick`). **위로 뜨지 않는다** — `translateY` 없음                                          |
| 누른 뒤     | **패널은 그대로 있고 왼쪽 본문만 바뀐다.** 버튼은 `text-sp-muted` + `border-sp-border` 로 가라앉아 "이미 열었음"을 표시 |
| 최대 개수   | 한 턴에 **2개까지.** 3개 이상이면 앱이 판단을 미룬 것이다                                                               |

> **왜 채움(filled) 버튼이 아닌가**: 액센트로 꽉 채운 버튼은 "제출"처럼 읽힌다. 이건 이동이다. **테두리만 액센트**가 "여기 말고 저기"라는 뜻에 맞는다.

### 8.2 "더 깊이 분석하려면 (AI 브릿지)" 접힘 줄

- **항상 접혀 있다.** 기본 노출 금지 — 매번 보이면 "이 챗봇은 반쪽"이라는 인상이 굳는다(계획서 §5.2 원리 3).
- `text-xs` `text-sp-muted`, 높이 20px, 좌측 `⌄` 12px 아이콘
- 펼치면 `bg-sp-bg` `rounded-lg` `border border-sp-border` `p-3` 안에 안내문 + 브릿지 설정 링크
- **강조하지 않는다**: 액센트·하이라이트 색을 쓰지 않는다

## 9. 3등급 차단 화면

계획서 §5.7.3의 문구를 그대로 쓴다. 시각 목표는 **"겁주지 않으면서 이유가 분명하게"** 이다. 그러려면 세 가지를 지켜야 한다.

> ① **빨간 배경을 쓰지 않는다** — 벌주는 화면처럼 보인다.
> ② **어디가 걸렸는지 보여 준다** — 모르면 고칠 수 없다.
> ③ **입력은 절대 사라지지 않는다** — 차단이지 삭제가 아니다.

### 9.1 두 자리에서 동시에 일어난다

차단은 **스레드가 아니라 입력부에서** 일어난다. 아직 보내지 않았기 때문이다.

```
┌─── 입력부 (차단 상태) ──────────────────────────────────────────┐
│                                                                 │
│ ┏━┬──────────────────────────────────────────────────────────┐  │
│ ┃ │ ⛔  이 내용은 AI에 보내지 않아요                          │  │  ← 안내 카드
│ ┃ │                                                          │  │    bg-sp-card
│ ┃ │ 가정 형편·건강·상담 내용은 무료 AI에 보내면 학습에        │  │    border-l-2
│ ┃ │ 쓰일 수 있어서 막았어요. 선생님 잘못이 아니에요.          │  │    border-l-sp-error
│ ┃ │                                                          │  │    rounded-xl p-3
│ ┃ │ ┌──────────────────┐ ┌──────────────────┐                │  │
│ ┃ │ │ 상담 기록에 남기기│ │ 이 부분만 지우기 │                │  │
│ ┃ │ └──────────────────┘ └──────────────────┘                │  │
│ ┗━┴──────────────────────────────────────────────────────────┘  │
│                            ↑ gap-2                              │
│ ↗ 나갈 문장:  ─── 보내지 않습니다 ───          ← 미리보기 줄이 바뀐다
│ ────────────────────────────────────────────────────────────    │
│ ┌─ textarea (내용 그대로!) ────────────────────────────────┐    │
│ │ 지훈이가 어제 ▁▁▁▁▁▁ 얘기를 꺼냈는데 어떻게 대응하면    │    │
│ │              ↑ 걸린 구절 강조 (밑줄 + 배경)              │    │
│ │ 좋을까?                                          ⌁ 보내기│    │  ← 비활성
│ └──────────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────────┘
```

### 9.2 토큰 매핑

| 요소                   | 배경         | 테두리                                                     | 글자                                                                       | 반경         |
| ---------------------- | ------------ | ---------------------------------------------------------- | -------------------------------------------------------------------------- | ------------ |
| 안내 카드              | `bg-sp-card` | `border border-sp-border` + `border-l-2 border-l-sp-error` | 제목 `text-sm weight-semibold text-sp-text` / 본문 `text-xs text-sp-muted` | `rounded-xl` |
| ⛔ 아이콘              | —            | —                                                          | 16px `text-sp-error`                                                       | —            |
| `[상담 기록에 남기기]` | `bg-sp-bg`   | `border border-sp-accent`                                  | `text-xs weight-medium text-sp-text`                                       | `rounded-lg` |
| `[이 부분만 지우기]`   | `bg-sp-bg`   | `border border-sp-border`                                  | `text-xs weight-medium text-sp-text`                                       | `rounded-lg` |
| **걸린 구절 강조**     | `bg-sp-card` | 아래쪽 `border-b-2 border-b-sp-error` (물결 대신 직선)     | `text-sp-text` `weight-semibold` **(색 안 바꿈)**                          | —            |
| 발신 미리보기 줄       | —            | —                                                          | `text-xs weight-medium text-sp-text` + ⛔ 12px                             | —            |
| 보내기 버튼(비활성)    | `bg-sp-card` | `border border-sp-border`                                  | `text-sp-muted`, `cursor-not-allowed`                                      | `rounded-lg` |

- **걸린 구절의 글자색을 바꾸지 않는다.** 배경+밑줄+굵기로만 표시한다 — 옅은 틴트 위 빨간 글자 AA 미달을 원천 회피(§2.2 ③).
- **강행 버튼은 이 화면 어디에도 없다.** "그래도 보내기"를 둘 자리를 스펙에 만들지 않는다(계획서 §5.7.3-a 규칙 3).
- 등장 모션: `opacity` + `translateY(4px→0)`, `--sp-duration-base`, `--sp-ease-out-cubic`. **흔들기(shake) 금지** — 벌주는 느낌이 난다.
- 자해·자살 키워드(§5.7.3-a #17·#18)일 때는 안내 카드 **아래에** 위기 안내 줄을 별도 카드로 덧붙인다: `border-l-2 border-l-sp-info` + 전화번호 링크. **차단 카드와 섞지 않는다** — 성격이 다르다.

### 9.3 스크린 리더 처리

- 안내 카드는 `role="alert"` (즉시 알림). 차단은 사용자가 놓치면 안 되는 상태 변화다.
- textarea 에 `aria-invalid="true"` + `aria-describedby` 로 안내 카드를 연결
- 걸린 구절은 시각 강조만으로는 전달되지 않으므로, 안내 카드 본문에 **해당 구절을 텍스트로 한 번 더 말한다**: "걸린 부분: '○○'"

### 10.3 이 화면에서 절대 하지 않는 것

- **"나가는 것" 칸을 작게 만들지 않는다.** 두 칸은 **같은 폭**이다. 불리한 정보를 시각적으로 축소하면 고지가 아니라 마케팅이 된다.
- **학습 고지 블록을 접지 않는다.** 계획서의 "가장 중요한 문장"이므로 처음부터 펼쳐져 있다.
- **`[켤게요]` 버튼을 미리 강조해 시선을 끌지 않는다.** 스크롤을 끝까지 내려야 버튼에 닿게 배치한다(다이얼로그 본문 스크롤, 버튼 줄은 하단 고정 `border-t`).
- ⟡실렌더 확정: 세로가 길어 1024px 높이 화면에서 잘릴 수 있다 → 본문 `overflow-y-auto` + 하단 버튼 줄 고정으로 처리하고, 실제 높이는 Phase 3에서 확인.
- ⚠️ **유리(반투명 카드) 규칙과의 충돌 확인 필요**: 이 다이얼로그는 `role="dialog"` 를 갖고, 프로젝트에는 `[role=dialog]` + `.bg-sp-card` 면에 걸리는 가독성 규칙이 있다. 첫 실행 팝업에서 실제 사고가 있었던 자리이므로 **실렌더로 반투명 여부를 확인**한다.

### 10.4 좁은 화면 (< 560px 또는 오버레이 모드)

두 칸이 **위아래로 쌓인다.** 순서는 **"나가는 것"이 먼저** — 불리한 정보가 위다.

│ │                                                    ⌁ 보내기 ││ ← 비활성
│ └─────────────────────────────────────────────────────────────┘│
│ 오늘 질문 한도를 다 썼어요. 자정에 다시 열려요.  ← 하단 안내 줄 교체 │
```

| 규칙                                                                                           |
| ---------------------------------------------------------------------------------------------- |
| **숫자 카드를 흐리게(`opacity`) 하지 않는다.** 도구는 로컬 실행이므로 한도와 무관하게 정상이다 |
| **textarea 는 잠그지 않는다.** 보내기 버튼만 비활성. 적어 두는 것까지 막을 이유가 없다         |
| **패널을 닫으라고 하지 않는다.** 지난 대화와 숫자 카드는 계속 읽고 스크롤할 수 있다            |
| 하단 안내 줄(`숫자·요약은 여기서…`)이 한도 안내로 **교체**된다. 두 줄로 쌓지 않는다            |

## 12. 빈 상태 (처음 열었을 때)

### 12.1 제안 칩은 장식이 아니라 **방어 장치**다

계획서 §5.7.5는 "우회·완곡 표현은 키워드로 막을 수 없고, **1층(제안 칩)이 유일한 실질 방어**"라고 적었다. 그러므로 이 화면의 칩은 예쁜 시작점이 아니라 **"이 도구는 이런 모양의 질문에 답한다"를 가르치는 장치**다. 칩 문구는 전부 **집계형**이며, 사람·사연을 묻는 형태를 한 개도 포함하지 않는다.

```
┌──────────────────────────────────────────────────┐
│                                                  │
│                                                  │  ← 위 여백 넉넉히 (py-8)
│                     ✦                            │  ← 28px 아이콘, text-sp-muted
│                                                  │
│           무엇이 궁금하세요?                      │  ← text-sm weight-semibold
│      지금 보고 있는 화면을 알고 있어요.           │  ← text-xs text-sp-muted
│                    ↑ 3-2반 출결이면 "3-2반 출결 화면" 처럼 구체적으로
│                                                  │
│   ┌────────────────────────────────────────┐    │
│   │  오늘 우리 반 결석 몇 명?               │    │  ← 제안 칩 (세로 스택)
│   └────────────────────────────────────────┘    │
│   ┌────────────────────────────────────────┐    │
│   │  이번 주 마감 남은 일 알려 줘           │    │
│   └────────────────────────────────────────┘    │
│   ┌────────────────────────────────────────┐    │
│   │  3-2반 이번 달 지각 추이                │    │
│   └────────────────────────────────────────┘    │
│                                                  │
│   ─────────────────────────────────────────      │
│   가정 형편·건강·상담 내용은 물어볼 수 없어요.    │  ← text-xs text-sp-muted
│   (자동으로 막혀요)                              │     처음부터 알려 준다
│                                                  │
└──────────────────────────────────────────────────┘
```

### 12.2 제안 칩 스펙

| 속성        | 값                                                                                                                                                                                                                            |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 형태        | **세로 스택 full-width.** 가로 배치는 320px에서 문장이 잘린다                                                                                                                                                                 |
| 높이        | 36px (`h-9`), 좌우 12px (`px-3`)                                                                                                                                                                                              |
| 반경        | `rounded-full` (칩이므로)                                                                                                                                                                                                     |
| 배경·테두리 | `bg-sp-bg` + `border border-sp-border`                                                                                                                                                                                        |
| 글자        | `text-xs` `weight-normal` `text-sp-text`, 왼쪽 정렬                                                                                                                                                                           |
| 간격        | 8px (`gap-2`)                                                                                                                                                                                                                 |
| 호버        | `border-sp-accent` + `bg-sp-card`, `--sp-duration-quick`                                                                                                                                                                      |
| 등장        | `opacity` + `translateY(4px→0)`, **stagger 60ms** — 패널 열림 모션이 끝난 뒤 시작                                                                                                                                             |
| 개수        | **3개.** 4개 이상은 고르는 부담이 된다                                                                                                                                                                                        |
| 내용        | 화면 맥락에 따라 달라진다(출결 화면이면 출결 질문). 맥락이 없으면 **기본 4종**(계획서 §5.7.2 기준). 좁은 폭에서는 2줄로 접는다                                                                                                |
| 클릭 동작   | **즉시 전송한다.** 입력창을 거치지 않는다 — 계획서 §5.7.2·Phase 3 인수 조건("자유 입력 없이 질문이 나간다")·e2e 시나리오가 요구하는 동작이다. **채워 넣기만 하면 선생님이 그 문장을 고쳐 쓸 자리가 생겨 1층 방어가 무너진다** |

### 12.3 대화가 있다가 지운 뒤의 빈 상태

동일한 화면이되 부제만 바뀐다: `이전 대화를 지웠어요.` **"대화 없음" 같은 시스템 말투를 쓰지 않는다.**

## 13. 저해상도 접힘 (1280px · 1024px)

### 13.1 창 너비별

| 창 너비      | 패널           | 본문            | 시각적 변화                                                                        |
| ------------ | -------------- | --------------- | ---------------------------------------------------------------------------------- |
| ≥ 1440px     | 384px 도킹     | 밀림            | 기준 상태                                                                          |
| 1280~1440px  | 384px 도킹     | 밀림            | 동일. 본문이 좁아지지만 `main`의 `p-8`은 유지                                      |
| 1024~1280px  | **320px 도킹** | 밀림            | 패널 내부가 접힌다(§13.2)                                                          |
| **< 1024px** | **오버레이**   | **밀리지 않음** | 패널이 본문 위를 덮고, 뒤에 어두운 막(scrim). **전환 사실을 문구로 알리지 않는다** |

### 13.2 패널 내부 접힘 (384px → 320px)

**컨테이너 폭 기준으로 접는다.** 창 너비가 아니라 **패널 자신의 폭**이 기준이어야 오버레이 모드에서도 같은 규칙이 적용된다.

| 요소             | 384px                        | 320px                                          | 접는 이유                           |
| ---------------- | ---------------------------- | ---------------------------------------------- | ----------------------------------- |
| 숫자 카드 그리드 | 3열                          | **2열** (3번째 값은 다음 행)                   | 열당 96px 미만이면 숫자가 붙는다    |
| 숫자 크기        | 24px                         | **20px**                                       | —                                   |
| 도구 칩          | 최대 3개 표시                | **최대 2개 + `+N` 칩**                         | 줄바꿈이 3줄이 되면 스레드를 먹는다 |
| 칩 안 괄호 부연  | `읽음: 출결 요약 (3-2, 8월)` | **`읽음: 출결 요약`** (부연 제거, 펼치면 보임) | —                                   |
| 화면 열기 버튼   | 가로 2개                     | **세로 2개** (full-width)                      | 12자 넘는 라벨이 잘린다             |
| 헤더 "남은 질문" | `오늘 남은 질문 32회`        | **`남은 32회`**                                | —                                   |
| 출처 배지        | 라벨 유지                    | **라벨 유지 (절대 축약 안 함)**                | 책임 소재 표기는 줄이지 않는다      |
| 하단 안내 줄     | 한 줄                        | **두 줄 허용** (`h-5` → `min-h-5`)             | 자르는 것보다 낫다                  |
| 발신 미리보기 줄 | 한 줄 말줄임                 | 한 줄 말줄임 (동일)                            | 클릭하면 전체 펼침                  |

### 13.3 오버레이 모드 (< 1024px)

```
┌──────────── 창 ────────────────────────────────────┐
│ [Sidebar] [ 본문 (그대로, 밀리지 않음) ]           │
│                          ▓▓▓▓┌─────────────────┐   │
│                          ▓▓▓▓│ 패널            │   │
│                          ▓▓▓▓│ min(384, 100vw  │   │
│                          ▓▓▓▓│      - 32px)    │   │
│                          ▓▓▓▓│ shadow-sp-lg    │   │
│                          ▓▓▓▓└─────────────────┘   │
│                          ↑ scrim                   │
└────────────────────────────────────────────────────┘
```

| 항목        | 도킹 (≥1024)                         | 오버레이 (<1024)                                                                 |
| ----------- | ------------------------------------ | -------------------------------------------------------------------------------- |
| 그림자      | `shadow-none`                        | **`shadow-sp-lg`** (떠 있음을 표시)                                              |
| 좌측 경계   | `border-l border-sp-border`          | 유지 (그림자와 함께)                                                             |
| 배경막      | 없음                                 | **있음.** 검정 20% ⟡ 기존 모달 scrim과 동일 값을 재사용할 것 (새 토큰 신설 금지) |
| ARIA        | `role="complementary"`               | **`role="dialog"` `aria-modal="true"`**                                          |
| 포커스 트랩 | **없음** (본문을 계속 조작해야 한다) | **있음**                                                                         |
| 열림 모션   | 폭 전환                              | `translateX(16px→0)` + `opacity`, `--sp-duration-slow`                           |
| 배경 클릭   | 해당 없음                            | **닫는다**                                                                       |

> **경계에서의 재배치**: 창을 줄여 1024px을 지나면 패널이 도킹→오버레이로 바뀐다. **이때 애니메이션을 넣지 않는다** — 창 크기 조절 중 패널이 춤추면 고장처럼 보인다. 상태만 즉시 교체한다.

## 15. 접근성

### 15.1 역할·이름

| 상황          | role                           | 이름                          |
| ------------- | ------------------------------ | ----------------------------- |
| 도킹          | `complementary`                | `aria-label="쌤핀 AI"`        |
| 오버레이      | `dialog` + `aria-modal="true"` | `aria-labelledby` → 헤더 제목 |
| 스레드        | `log`                          | `aria-label="대화 내용"`      |
| 사이드바 항목 | `button` + `aria-pressed`      | "쌤핀 AI"                     |

> **도킹 모드에서 `role="dialog"` 를 쓰지 않는다.** 모달이 아닌데 dialog로 선언하면 스크린 리더가 본문 접근을 방해한다.

### 15.2 포커스 순서

패널이 열리면 포커스는 **입력창(textarea)** 으로 간다. 헤더가 아니다 — 열었다는 건 묻겠다는 뜻이다.

```
Tab 순서:
  textarea
  → 보내기 버튼
  → (스레드 안 상호작용 요소들: 도구 칩 → 화면 열기 버튼 → 다시 시도 → 브릿지 접힘)
  → 헤더: ⋯ 더보기 → ✕ 닫기
  → (도킹 모드) 본문으로 나간다 / (오버레이 모드) textarea 로 순환
```

- **스레드는 도킹 모드에서 포커스 트랩을 걸지 않는다.** 왼쪽 본문을 계속 조작하는 것이 이 설계의 핵심 가치다(§8.1).
- 스레드 컨테이너는 `tabindex="0"` 을 주어 **키보드만으로 스크롤**할 수 있게 한다.
- 닫은 뒤 포커스는 **열기 전에 있던 요소**로 돌아간다. 팔레트로 열었으면 팔레트를 띄우기 전 요소로.

### 15.3 키보드

| 키                  | 동작                                                                        |
| ------------------- | --------------------------------------------------------------------------- |
| `Esc`               | 패널을 닫는다. **입력창에 내용이 있으면 내용은 보존**한다(다시 열면 그대로) |
| `Esc` (칩 펼침 중)  | 펼침만 닫는다. 한 번 더 눌러야 패널이 닫힌다                                |
| `Enter`             | 전송 (차단 상태면 아무 일도 하지 않고 `role="alert"` 카드로 포커스 이동)    |
| `Shift+Enter`       | 줄바꿈                                                                      |
| `Ctrl+K`            | 팔레트 (패널이 열려 있어도 동작. 기존 동작 그대로)                          |
| `Tab` / `Shift+Tab` | §15.2 순서                                                                  |

**새 전역 단축키는 만들지 않는다.** 과거 "새 단축키 하나 붙이려다 기존 단축키 전체의 문제 6건"이 나온 이력을 따른다.

### 15.4 `aria-live` — 스트리밍은 읽어 주면 안 된다

| 영역                    | 설정                                                                                   | 이유                                                  |
| ----------------------- | -------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| **숫자 카드**           | `aria-live="polite"` (한 번에 통째로 등장)                                             | 답의 핵심. 등장 즉시 알린다                           |
| **AI 해설 (스트림 중)** | `aria-live="off"` + `aria-busy="true"`                                                 | **글자마다 읽으면 사용 불가.** 스트림 중에는 침묵한다 |
| **AI 해설 (완료)**      | `aria-busy="false"` 로 바꾸고, 별도 `aria-live="polite"` 영역에 **완성 문장 1회** 안내 | 한 번만 읽어 준다                                     |
| **도구 칩 줄**          | `aria-live="off"`                                                                      | 부가 정보. 소음이 된다                                |
| **도구 실패 칩**        | `aria-live="polite"`                                                                   | 실패는 알아야 한다                                    |
| **오류 카드**           | `role="status"` (일시 실패) / `role="alert"` (차단·한도)                               | 심각도에 맞춘다                                       |
| **3등급 차단 카드**     | `role="alert"`                                                                         | 놓치면 안 되는 상태 변화                              |
| **발신 미리보기 줄**    | `aria-live="off"` + 전송 직전 값 변화만 `polite`                                       | 타이핑마다 읽으면 사용 불가                           |

### 15.5 대비

- 본문 글자는 `--sp-text` on `--sp-surface` / `--sp-card` 조합만 쓴다 (AA 이상)
- `--sp-muted` 는 **12px 보조 텍스트에만.** 14px 이상 본문에 쓰지 않는다
- **`text-sp-error` / `text-sp-warning` 을 옅은 배경 위 글자색으로 쓰지 않는다**(3.66 / 4.44 — AA 미달 실측 이력). 이 문서 전체에서 두 토큰은 **테두리(`border-l-*`)와 아이콘에만** 등장한다
- 포커스 링은 기존 `.focus-ring` 유틸(`ring-2 ring-sp-accent ring-offset-2 ring-offset-sp-bg`)을 **그대로 재사용**한다. 패널 배경이 `--sp-surface` 이므로 ⟡실렌더 확정: `ring-offset` 색이 어긋나 보이면 패널 내부용으로 `ring-offset-sp-surface` 변형을 검토
- 다크 테마는 `.theme-dark` 의 토큰 재정의로 자동 대응. **이 문서에는 `dark:` 가 0건이다**

## 16. 새 토큰이 필요한가 — 결론: **색 토큰은 신설하지 않는다**

| 후보                                           | 판정                                                                                                         |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 오류/경고 **틴트 배경** (`--sp-error-tint` 등) | **불필요.** 옅은 틴트는 AA 미달 사고의 원인이었다. 테두리+아이콘+라벨로 해결했다(§2.3)                       |
| 패널 폭 상수                                   | **불필요.** Tailwind `w-96` / `w-80` 로 충분                                                                 |
| 오버레이 scrim 색                              | **신설 금지.** 기존 모달이 쓰는 scrim 값을 재사용한다 ⟡실렌더 확정 — 재사용 가능한 클래스가 없으면 그때 검토 |
| `ring-offset-sp-surface`                       | ⟡**검토 대상.** 패널 내부 포커스 링 오프셋이 어긋나 보이면 Tailwind 설정에 오프셋 색만 추가(§15.5)           |
| 새 폰트·새 굵기                                | **불필요.** `--sp-font-family` 단일 + 기존 굵기 4단계로 전 화면을 그렸다                                     |
