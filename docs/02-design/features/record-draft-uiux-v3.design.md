- 상태: 오너 인터뷰 완료(2026-09-06), 설계 확정, 구현 전
- 작성일: 2026-09-06
- 선행: [근거 자료 서브페이지](record-evidence-subpage.design.md) · [관찰 슬롯](observation-slots.design.md) ·

## 0. 한 줄

**근거 정리 → AI 초안 → 검토**가 기본 경로라는 전제로, (1) 근거 정리를 학생별 **보드 한 장**으로
줄이고, (2) AI 초안을 **오른쪽 넓은 패널**에서 읽고 비교하게 하고, (3) 초안 문단마다 **서사 역할
형광펜**을 켜고 끌 수 있게 한다.

## 2. 오너 결정 (2026-09-06 인터뷰)

| 항목                  | 결정                                                                                         |
| --------------------- | -------------------------------------------------------------------------------------------- |
| 기본 경로             | 근거 정리 → AI 초안 → 검토. AI 활용이 기본                                                   |
| 근거 정리 화면        | **보드형**으로 목록 화면을 **대체**한다(전환 유지 안 함)                                     |
| 묶기 방법             | 체크 후 묶기가 정석, 제안은 보조, **끌어놓기 제거**                                          |
| AI 분류 제안          | **허용** — 단 "이렇게 묶으면 어떨까요"까지. 저장은 [적용]을 눌러야 한다                      |
| 카드 상시 표시        | 본문·날짜·주제·**출처·유형 토글·수정·삭제**                                                  |
| 엑셀·끌어오기         | 「가져오기」 하나로 접는다(사용 빈도 낮음)                                                   |
| 담임(학급 운영)       | 주제 묶기·형광펜 **모두 적용**(행특뿐 아니라 자율·진로도)                                    |
| 외부 AI용 select·복사 | 제거, AI 패널 안 주제 선택으로 합침                                                          |
| AI 미리보기           | 오른쪽 넓은 패널, 본문 14px 이상                                                             |
| AI 초안 보존          | **만든 것마다 전부** 남긴다(버전 목록), 내 글과 좌우 비교                                    |
| 내 글 이전 버전       | 저장하지 **않는다**. 대신 [바꾸기] 직후 **되돌리기**                                         |
| 글자 크기             | 작은 글자를 정상 비율로 고쳐 설정 > 화면 글꼴 크기를 따르게 **먼저**, 그 위에 화면 전용 조절 |
| 형광펜 기준           | 영역 무관 **공통 골격 4종**: 동기·질문 → 과정 → 결과 → 교사 평가                             |
| 형광펜 표식 주체      | AI가 문단 앞에 표식을 붙여 보내고 앱이 색으로 바꿈                                           |
| 형광펜 범위           | 미리보기 **와** 저장 후 편집 칸 모두. 화면 전체 스위치 1개. 범례는 켰을 때만                 |
| 편집 후 표식          | 고친 문단은 색이 흐려짐 **+** [다시 표시]로 AI 재요청                                        |

## 3. ★ADR-083 수정 포인트 (구현 시작 시 DECISIONS.md 에 ADR 로 적는다)

1. **"담임 행특에는 적용하지 않는다" → 폐기.** 오너: 학급 운영에서 남긴 기록에도 행특·자율·진로에
   들어갈 줄기가 있다. 주제 묶기·형광펜은 담임/교과 구분 없이 적용한다.
2. **"AI는 흐름을 만들지 않는다. 제안은 전부 문자열 검사" → 완화.** AI 는 분류 **제안**을 할 수 있다.
   지키는 선:
   - 제안은 화면에 점선(고스트)으로만 뜨고, [적용] 전에는 **아무것도 저장되지 않는다**.
   - 근거 본문이 밖으로 나가므로 **생기부 초안과 같은 규칙**: 구독 AI(Claude Code·Codex)만, 쌤핀
     AI(Solar) 폴백 없음, 실명·학번 가림(`redactOutbound` 세션), `excludedFromAi`·기재 금지 근거 제외.
   - 기존 문자열 검사 제안(`threadSuggest.ts`)은 AI 없이도 도는 **보조**로 남긴다.
3. 유지: 주제는 선택이다 · 점수판 없음 · 고아 threadId 관용 · 주제 이름 1순위는 수행평가 이름.

├──────────────────────────────────────────────┬──────────────────────────────────┐
│ 학생 행 목록 (기존, 정리)                     │ 오른쪽 패널 (선택 학생)            │

「근거 정리」 토글은 같은 자리에서 **보드**를 연다(§6). 학생·영역은 그대로 이어진다.

### 4-1. 선택 학생 상태를 올린다 (P1)

`RecordDraftView` 가 `selectedStudentRef` 를 가진다. 행 클릭·편집 칸 포커스·[AI ▸] 클릭이 이 값을
바꾼다. 오른쪽 패널과 보드는 이 값을 **props 로 받는다**(각자 `students[0]` 로 시작하지 않는다).
영역(`activeArea`)도 같은 방식으로 내려간다.

### 4-2. 학생 행 정리 (P5·P6·P7)

- 왼쪽 칸: 번호·이름 / 상태 배지 / **근거 N건**(근거 창고 건수만) / 미분류 N건(**버튼** — 보드를 그 학생·미분류
  열로 연다) / 검토 필요. `basisObservationIds` 의 "🔗 근거 N건 ▸" 은 패널 「근거」 탭 안으로 옮긴다.
- 제거: "이 주제로… ▾" select, "요청문 복사" 버튼, 행 안의 `RecordDraftAiButton` 인라인 미리보기.
- 행에는 **[AI ▸]** 버튼 하나만 남고, 누르면 오른쪽 패널 AI 탭이 그 학생으로 열린다.
- 글자 크기: 행 안 `text-[0.55rem]`·`text-[0.6rem]` 을 **전부 없앤다**. 최소 `text-xs`(0.75rem).
  배지류 `text-xs`, 본문·편집 칸 `text-sm` 이상.

### 4-3. 글자 크기 조절 (B3·F1)

1단계(비율 복원): 위 4-2 로 `RecordDraft/` 아래 모든 파일에서 0.55·0.6·0.65rem 을 없앤다. 그러면 설정 > 화면

> 글꼴 크기(작게~매우 크게)가 그대로 먹는다.
> 2단계(화면 전용): 상단 바 「Aa」 3단(보통/크게/매우 크게). 메모의 `MEMO_FONT_SIZE_CLASS` 와 같은 방식으로
> `RecordDraftFontSize = 'base' | 'lg' | 'xl'` 를 두고 **편집 칸·미리보기·근거 카드 본문**에만 적용한다
> (배지·탭은 안 키움 — 행 높이 폭증 방지). 저장: `useSettingsStore` 에 `recordDraftFontSize?` 선택 필드.

## 5. 오른쪽 패널 — AI 초안

### 5-1. 흐름

1. 주제 고르기(칩: 전체 근거 / 주제 A / 주제 B …). 담임도 동일.
2. [이 학생만] / [남은 학생 모두 N명] (+ 둘 다 연결됐을 때 공급자 칩 — ADR-084 D-A 그대로).
3. 진행 문구 → 미리보기.
4. 미리보기: **버전 탭**(v1 · v2 · v3 …, 최신이 기본) / 본문(`text-sm` 이상, 형광펜) / 제외됨 N건 사유 /
   [반영|바꾸기] [뒤에 붙이기] [버리기] / [내 글과 비교].
5. [내 글과 비교]: 패널이 좌(내 글)·우(고른 버전)로 갈린다. 문단 단위로 나란히.

### 5-2. AI 초안 보존 (E1)

새 엔티티 `RecordAiDraft` — 파일 `record-ai-drafts.json`, 저장소·동기화·보관함(archiveScope) 등록.

```ts
interface RecordAiDraft {
  readonly id: string;
  readonly draftKey: { area: RecordArea; studentRef: string; subject?: string; classId?: string };
  readonly threadId?: string; // 어느 주제로 썼나(없으면 전체 근거)
  readonly provider: 'claude' | 'codex';
  readonly model?: string;
  readonly paragraphs: readonly { role: NarrativeRole | null; text: string }[]; // 실명 복원 완료 상태
  readonly excluded: string; // "제외됨 N건 (…)" 요약
  readonly appliedAt?: number; // [반영]한 시각(없으면 안 반영)
  readonly createdAt: number;
}
```

- **[버리기]는 삭제다.** 그 버전은 `RecordAiDraft` 에서 지운다(오너 결정 2026-09-06). "만든 것마다 남긴다"는
  [반영]·[뒤에 붙이기]·**그냥 두고 다른 버전을 만든 경우**에 해당한다.
- 별칭 매핑은 저장하지 않는다(기존 원칙). 저장 시점에 이미 실명으로 되돌린 글이다.
- 개수 상한: 학생·영역당 20개. 넘으면 가장 오래된 **미반영** 버전부터 지운다.
- 개인정보 수위는 `RecordDraft` 와 같다(같은 폴더·같은 백업·같은 보관함).

### 5-3. 되돌리기 (E2)

[바꾸기]로 편집 칸을 덮으면 패널 하단에 **[되돌리기]** 가 30초간 뜬다. 이전 글은 메모리에만 있고,
누르면 upsert 로 복원한다. 화면을 떠나면 사라진다. 디스크에 이전 글을 남기지 않는다.

## 6. 근거 정리 보드 (D2·D3)

`RecordEvidenceView`(목록)를 **`RecordEvidenceBoard` 로 대체**한다. 파일 삭제, dnd-kit 드래그 코드
(`DraggableEvidence`, 칩 drop 대상) 삭제. `InquiryThreadChips` 는 열 머리로 흡수.

```
┌ [← 초안으로]  {학생 선택 ▾}  영역 필터: [전체|자율|진로|행특]   [가져오기 ▾] [+ 근거 직접 입력] [✨ AI 분류 제안]
├──────────────┬──────────────┬──────────────┬──────────────┬─────────┐
│ 미분류 (7)    │ 주제 A (5)    │ 주제 B (3)    │ 주제 C (2)    │ + 새 주제 │
│ ┌ 카드 ┐      │ ┌ 카드 ┐      │ ┌ 카드 ┐      │              │         │
│ │ 본문      │  │ │ 본문      │  │ ┆ 고스트 ┆   ← AI 제안(점선)          │
│ │ 9/2·관찰   │  │ │ 9/4·수행  │  │ ┆ [적용][무시]┆                      │
│ │ 유형칩 수정 삭제│ …          │  │              │              │         │
│ └──────┘      │              │              │              │         │
└──────────────┴──────────────┴──────────────┴──────────────┴─────────┘
  선택 N건 →  [주제 A] [주제 B] [주제 C] [+ 새 주제로] [미분류로]   [선택 해제]
```

### 6-1. 규칙

- 열 = 이 학생의 주제(open 먼저, closed 뒤에 접힘). 첫 열은 항상 미분류.
- **카드 클릭 = 선택 토글**(체크박스 대신). 선택이 1건 이상이면 하단 바가 뜬다 → 열 이름 버튼으로 보낸다.
  이것이 "체크 후 묶기"의 정석 경로다. 끌어놓기는 없다.
- 카드 상시 표시: 본문 / 날짜 · 출처 / **유형 토글**(이 컨텍스트의 영역 칩) / 수정 · 삭제.
  접는 것: AI 전송/제외 토글(카드 「…」 안), 점검 사유.
- 주제 열 머리: 이름 · 건수 · [열기](기존 `InquiryThreadPanel` 시간순 줄기·키워드·다음 메모를 **옆 서랍**으로) ·
  닫기/삭제.
- "이것도 이 주제?"(문자열 검사) 는 미분류 카드 하단에 **작은 칩 1~2개**로만 남긴다.
- 영역 필터는 카드를 숨길 뿐 열은 그대로다(주제는 영역을 모른다 — 기존 데이터 모델 유지).
- 학생 바꾸기: 상단 학생 선택(▾) 또는 ←/→. 학생이 바뀌면 선택·제안 전부 비운다(기존 방어선 유지).

### 6-2. 가져오기 ▾ (A4)

드롭다운 한 개: 관찰 기록 / 누가기록 / 수행평가 / 성적 서술 / 첨부 / 과제 제출 / ─ / 엑셀 양식 받기 / 엑셀 업로드.
고르면 **오른쪽 서랍**에 후보 목록(기존 `candidatesFor` 로직 그대로)이 열린다. 서랍 안에 [학급 전체 가져오기].

### 6-3. AI 분류 제안 (D1)

- 버튼은 구독 AI가 연결돼 있을 때만 보인다. 없으면 초안과 같은 안내.
- 입력: 이 학생의 **미분류** 근거(가림·제외 규칙 적용) + 기존 주제 이름·키워드. 새 프롬프트 조립 함수
  `buildThreadSuggestPack`(domain, 순수) — `recordDraftPack` 과 같은 가림 세션 사용.
- 출력 형식(모델에 요구): 줄마다 `주제명 | 근거번호,근거번호`. 주제명이 기존과 같으면 그 열, 아니면 「+ 새 주제」 열에
  고스트 열로.
- 화면: 제안된 카드가 해당 열에 **점선 고스트**로 뜬다. 열 머리에 [이 열 적용] / 상단 [전체 적용] / [무시].
  적용 전엔 `setThread` 를 부르지 않는다.
- 파싱 실패·형식 불일치 → "제안을 읽지 못했습니다" 한 줄, 저장 없음.

## 7. 형광펜

### 7-1. 어휘 (G1-c)

```ts
type NarrativeRole = 'motive' | 'process' | 'result' | 'evaluation';
const NARRATIVE_ROLE_LABELS = {
  motive: '동기·질문',
  process: '과정',
  result: '결과',
  evaluation: '교사 평가',
};
```

색: 4종 고정, 배경 `/15` 톤(기존 칩 방식) — 동기 sky · 과정 violet · 결과 emerald · 평가 amber. HEX 직접 쓰지 않는다.
영역 무관 공통(교과·담임 전부).

### 7-2. AI 표식 (C2)

`recordDraftPack` 의 마지막 지시에 한 문단을 덧붙인다:

> 문단마다 줄 첫머리에 그 문단의 역할을 `[동기]` `[과정]` `[결과]` `[평가]` 중 하나로 표시하세요. 표식은 문단 첫머리에만,
> 한 문단에 하나만 씁니다.

파서 `parseNarrativeParagraphs(text)` (domain, 순수): 문단 분리 → 첫머리 표식 추출·제거 → `{ role, text }[]`.
표식이 없는 문단은 `role: null`. 표식이 하나도 없으면 전부 null (형광펜 없이 그대로 보여 주고 "표식 없음" 한 줄).
**저장되는 `RecordDraft.content` 는 표식이 제거된 순수 텍스트**다 — NEIS 복사 원칙 그대로.

### 7-3. 저장 후 편집 칸에서의 형광펜 (C3·G2)

`RecordDraft` 에 선택 필드 추가:

```ts
readonly roleMarks?: readonly { role: NarrativeRole; text: string }[]; // [반영] 시점의 문단별 역할
```

- 렌더: 편집 칸 뒤에 같은 글꼴·여백의 **거울 레이어**(`RoleHighlightLayer`)를 깔고, textarea 배경을 투명으로. 문단별
  배경색만 그린다(글자는 textarea 가 그린다). 스크롤·크기 동기화. 새 의존성 없음.
- 대응: 현재 문단 텍스트와 `roleMarks[i].text` 가 **같으면** 진하게, 다르면 같은 색을 `/5` 로 **흐리게**(a).
  문단 수가 달라지면 순서대로 맞추고 남는 문단은 색 없음.
- [다시 표시](b): 현재 편집 칸 글을 **표식만 붙여 달라**는 짧은 프롬프트로 구독 AI에 보낸다(가림 적용, 근거 미포함).
  결과로 `roleMarks` 만 갱신, `content` 는 건드리지 않는다. 답의 본문이 원문과 다르면 버리고 안내.
- 화면 전체 스위치 1개(상단 바), `useSettingsStore.recordHighlightOn?` 에 기억. 켰을 때만 범례가 정보 바에 뜬다.

## 11. 하지 않는 것

- 마인드맵 시각화(보드로 충분, 규모 3~4배).
- 내 글 이전 버전 디스크 저장(되돌리기 30초로 대체).
- 형광펜 문단 색을 선생님이 직접 바꾸는 편집기(표식은 AI·[다시 표시]로만).
- 쌤핀 AI(Solar)로 분류 제안·초안 폴백.
- 영역별 형광펜 어휘 분기(공통 4종으로 통일).

## 12. 열린 위험

- 모델이 표식 형식을 안 지키면 형광펜이 비게 된다 → 파서는 관대하게(`[동기]` `【동기】` `(동기)` 허용), 실측 후 프롬프트 조정.
- 거울 레이어와 textarea 줄바꿈이 어긋나면 색이 밀린다 → 같은 폰트·`white-space: pre-wrap`·`word-break` 를 강제하고
  resize 시 동기화. 글꼴 변경(설정 > 화면) 시에도 재측정.
- `RecordAiDraft` 가 학생·영역당 최대 20개 × 문단 → 파일이 커진다. 상한으로 막고 실사용 후 조정.
