# 장면 연결점으로 순서 바꾸기

- 작성: 2026-09-13
- 상태: 사용자 승인 후 로컬 구현 및 브라우저 검증. 다중 근거 연결을 포함한 범위는 §6, 검증 결과는 월별 기록을 따른다.
- 대상: 학급 운영·수업 관리 → 생기부 초안 → 근거 지도
- 기존 구현: 장면 배열 순서로 화살표가 자동 생성되며 상세의 앞/뒤 버튼으로 순서를 바꾼다. 근거 소속 가지와 장면 순서 화살표는 별개다.

## 1. 화면

장면 카드의 현재 세로 화살표와 맞추어 위쪽 왼편에 ‘시작’, 아래쪽 왼편에 ‘다음’ 연결점을 둔다. 작은 원은 평소 옅게 보이며 장면 선택·마우스 접근·키보드 초점 때 강조한다. 원의 보이는 크기는 8px, 실제 누를 수 있는 영역은 최소 32px로 한다. 카드 본문 클릭은 기존 상세 열기이고 연결점에서만 선 끌기를 시작한다.

메모는 장면 옆에 붙는다. 연결점과 선의 통로를 메모 공간 밖에 확보하여 메모를 관통하지 않는다. 근거 소속 가지는 카드 오른쪽에서 나가므로 순서 연결점과 혼동하지 않도록 한다. 선 굵기는 다른 연결선과 같은 1.25px를 유지한다.

## 2. 핵심 동작

1. A의 ‘다음’ 원을 누르면 얇은 임시 선이 포인터를 따라간다.
2. 같은 주제의 다른 장면 시작점만 연결 가능한 대상으로 강조한다. 대상 주변 32px 안에서 선 끝이 붙는다.
3. B 시작점에 접근하면 ‘A 다음에 B 놓기’와 변경될 전체 순서를 미리 보여 준다. 기존 연결 중 바뀌는 선은 옅어지고 새 선은 점선으로 나타난다. 이 단계에서는 저장하지 않는다.
4. 놓으면 B를 A 바로 뒤로 이동한다. 나머지 장면의 상대 순서와 모든 근거 소속·메모를 유지한다. 연결선과 카드가 같은 순서로 재배치된다.
5. 저장 성공 후 ‘B를 A 다음으로 옮겼습니다 · 되돌리기’를 표시한다. 실패하면 원래 순서와 입력을 보존하고 이유를 알린다.

예: A → B → C → D에서 A의 다음점을 D의 시작점에 놓으면 A → D → B → C가 된다. D만 이동하며 기존 B·C를 지우거나 다른 주제로 옮기지 않는다. 이미 바로 다음인 장면에 놓는 동작은 저장 없이 종료한다.

기존 화살표의 끝을 잡아 다른 시작점에 놓는 것도 동일한 ‘다음 장면 바꾸기’ 동작이다. 빈 공간에 놓거나 Esc를 누르면 취소한다. 화살표를 빈 곳에 놓았다고 장면이나 근거를 삭제하지 않는다.

## 3. 순서와 관계 의미 보호

현재 생기부 초안은 하나의 장면 순서를 사용한다. 이 UX도 한 장면의 앞/뒤 연결을 각각 하나로 유지한다. 자기 자신·다른 주제·마친 주제·가상 장면·자리 미정에는 연결하지 않는다. 순환·분기 그래프를 조용히 생성하지 않는다. 주제 간 연결은 기존 주제 연결 편집에 맡긴다.

순서 변경으로 앞 장면이 달라진 모든 장면을 계산한다. 예에서는 D와 B의 앞 장면만 바뀌므로 두 연결을 확인 대상으로 표시한다. C의 앞 장면은 B로 같아 그대로 유지한다. 기존 이음말은 자동 삭제하거나 새 관계 설명으로 단정하지 않는다.

- 관계가 바뀐 기존 이음말은 ‘이음말 확인’ 상태로 보존한다. 새 연결을 설명하는 문장인지 교사가 확인·수정·비우기 할 수 있다.
- 확인 전에는 이전 관계의 이음말을 AI 초안 요청서에 확정된 연결 설명으로 보내지 않는다. 장면 본문·근거·일반 메모는 계속 보낸다. 검토가 필요한 연결 수를 짧게 알린다.
- 되돌리기는 순서뿐 아니라 원래 이음말과 검토 상태도 한 번에 복원한다.

현재 leadIn은 대상 장면의 문자열뿐이므로 관계 재검토 상태와 원래 앞 장면을 보존할 모델 확장이 필요하다. 화면의 선만 바꾸는 구현으로 끝내지 않는다. 기존 앞/뒤 버튼도 같은 순서 변경 경로와 이음말 검토 규칙을 적용해야 한다.

## 4. 조작 접근성

- 시작점/다음점 접근 이름: ‘{장면 이름} 시작 연결점’, ‘{장면 이름} 다음 장면 연결’.
- 다음점 클릭 후 대상 시작점 클릭도 드래그와 같은 동작을 제공한다.
- 키보드: 다음점에서 Enter/Space → 대상 시작점에 Tab 이동 → Enter로 연결, Esc로 취소한다. 변경된 순서를 읽어 준다.
- 작은 화면에서는 가장자리 접근 시 지도만 자동 스크롤한다. 기존 카드 드래그·빈 화면 이동과 충돌하지 않는다.
- 저장 중 중복 연결을 막고, 현재 편집 중인 미저장 메모는 기존 보존 규칙을 따른다.

## 5. 구현 범위와 완료 조건

순서 변경을 하나의 저장 동작으로 추가하고, 포인터 미리보기·직접 연결점·키보드 경로·관계 검토·되돌리기를 함께 구현한다. 장면 카드 자유 좌표 이동이나 주제 노드 드래그는 별도 기능이며 이 기능 구현으로 지원한다고 설명하지 않는다.

검증: A→D, 뒤에서 앞으로 이동, 바로 다음 선택, 자기 자신, 다른 주제, 닫힌 주제, 취소, 화면 경계 스크롤, 저장 실패, 변경 중 학생 전환, 키보드 경로, 이음말이 있던 세 연결의 검토/초안 제외/되돌리기. 저장 장면 순서·그려진 선·초안 순서가 같아야 한다. 기존 메모·근거 ID 집합은 바뀌지 않아야 한다.

## 6. 근거와 장면의 다중 연결

하나의 자료에 과정과 결과가 함께 있으면 같은 주제의 두 장면에서 참조할 수 있다. 원본과 근거 카드는 한 건을 유지하고 연결선만 여러 개 표시한다. 근거 수와 AI 원문 목록도 고유 ID로 센다. 주제 소속은 계속 `RecordEvidence.threadId`를 따른다.

- 근거 연결점에서 다른 장면으로 끌면 기존 연결을 유지하면서 새 참조를 추가한다.
- 기존 연결의 끝점을 다른 장면으로 끌면 해당 참조만 옮긴다. 다른 장면의 참조는 유지한다.
- 연결 해제는 해당 참조만 없앤다. 마지막 참조를 해제해도 원본은 주제의 자리 미정에 남는다.
- 연결마다 선택적으로 ‘이 장면에서 쓸 부분’을 적는다. 원본의 공통 메모와 구분하고, 연결을 옮길 때 함께 보존한다. 이미 연결된 대상에 놓으면 기존 메모를 덮어쓰지 않는다.
- 카드 본문 드래그와 연결점 드래그는 서로 다른 의도를 표현한다. 연결을 수정하면서 원본을 복제하거나 주제 소속을 몰래 바꾸지 않는다.
- AI에는 원본을 한 번 보내고 장면별 참조와 해당 부분 메모를 함께 보낸다. 하나의 자료를 여러 번 관찰한 것처럼 세거나 같은 문장을 반복하지 않도록 지시한다. 연결 메모에도 익명화·제외 근거·금지 정보 처리를 적용한다.

추가 검증: 한 자료를 과정·결과에 연결, 카드 1개와 연결선 2개, 연결별 메모 저장과 재로딩, 한 연결만 이동·해제, 마지막 연결 해제, 같은 대상 중복 연결, 닫힌 주제·다른 학생 연결 차단, 실패 시 입력 보존, 되돌리기. AI 요청서의 고유 원문 수와 장면별 참조를 확인한다.
