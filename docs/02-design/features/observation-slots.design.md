# 관찰 슬롯 (observation-slots) — 설계서 v1.0

- 상태: 설계 확정, 구현 전
- 작성일: 2026-08-25
- 상위 계획: [record-draft-system-v2](../../01-plan/features/record-draft-system-v2.plan.md) §4 Phase 2
- 관련 결정: [ADR-072](../../../DECISIONS.md) 결정 6

## 1. 무엇을 만드나

생기부 초안의 재료가 되는 기록에 **"어떤 장면인가"** 를 한 번의 탭으로 붙인다.

오너 프롬프트는 관찰 자료를 갈래별로 요구하는데, 지금 기록은 자유서술 한 칸이라 갈래가
뭉개져 있다. 실측에서 **"근거만 두꺼우면 AI 품질은 쓸 만하다"** 가 확인됐으므로
(`docs/03-analysis/record-draft-solar-quality.analysis.md` §5), 병목은 모델이 아니라
**근거의 구조**다. 그 구조를 입력 단계에서 만든다.

## 2. 불가침 제약

**오너 의도는 "평소에 꾸준히 누적"이다.** 학기말 정리 도구가 아니다.

- **기록 하나 = 순간 하나 = 슬롯 하나.** 늘어나는 동작은 **칩 한 번 탭**까지다.
- 슬롯은 **선택이다.** 안 고르고도 저장된다. 필수로 만들면 입력이 막히고, 그게 기록이
  안 쌓이는 길이다.
- 지금도 알림으로 겨우 채우는 상황이다. **부담이 늘면 기능 전체가 죽는다.**

## 3. ★저장 방식 — 태그가 아니라 새 칸으로 간다 (초기 판단 정정)

계획서 초안은 "**태그 어휘 확장**으로 구현한다 — 새 필드·저장 구조 변경 없음"이라고 적었다.
**교과 관찰만 놓고 보면 맞지만, 담임 누가기록까지 포함하기로 하면서 성립하지 않는다.**

- `StudentRecord.tags` 는 **이미 "세부 분류"로 쓰이고 있다.** 비출결 기록에서 서브카테고리
  직접편집을 대체하는 축이다(`InlineRecordEditor.tsx:40-41`, 화면 라벨도 "세부 항목 / 태그").
  여기에 슬롯을 섞으면 **한 배열에 두 의미가 뒤섞인다** — 이 저장소가 P3 로 경계해 온 바로
  그 안티패턴이다(`UnifiedRecordDraft.ts`: "category 값을 tags 배열에 절대 혼입 금지").
- 태그로 가면 기존 **태그 필터·통계 표·내보내기**에 슬롯이 섞여 나온다. 통계는 태그마다
  표 열을 하나씩 그리므로(`ClassRecordStatsView.tsx:340`) 열이 14개가 되어 가로로 넘친다.

**→ 두 엔티티에 선택 필드 `slots?: readonly string[]` 을 새로 둔다.**

기존 선례를 그대로 따른다 — `ObservationRecord.category?`·`term?` 처럼 **additive optional**
이라 구 데이터는 부재로 남고 추측해 채우지 않는다.

### 영향 범위

| 대상                                  | 할 일                                                                            |
| ------------------------------------- | -------------------------------------------------------------------------------- |
| `ObservationRecord` · `StudentRecord` | `slots?` 추가(선택)                                                              |
| 동기화                                | 봉투/병합 규칙에 새 칸 반영. **부재를 빈 배열로 덮어쓰지 말 것**(구 데이터 보존) |
| 브릿지 미러                           | `get_observations` 응답에 슬롯 노출(태그와 같이 탈식별 통과)                     |
| 근거 창고                             | `RecordEvidence.slots?` + `evidenceImport` 변환에 실어 보냄                      |
| 모바일                                | 입력 시트·카드에 동일 축                                                         |

**태그 축은 손대지 않는다.** 기존 4종(`교과역량` 등)과 담임의 세부 분류는 그대로다.

## 4. 슬롯 어휘 — 두 벌

작성 주체가 다르면 필요한 장면도 다르다. 오너 프롬프트의 입력 양식이 세특용과 행특용으로
갈려 있는 것이 근거다.

### 교과(수업반) — 세특용

| 슬롯     | 무엇을 담나                  |
| -------- | ---------------------------- |
| 질문     | 학생이 던진 의문·꼬리 질문   |
| 시도     | 해 본 것, 고른 것            |
| 시행착오 | 안 된 것, 고쳐 간 과정       |
| 산출물   | 보고서·발표·제작물           |
| 주고받음 | 교사와의 상호작용            |
| 연결     | 다른 교과·영역과 이어진 지점 |

### 담임 — 행특용

| 슬롯      | 무엇을 담나                                                           |
| --------- | --------------------------------------------------------------------- |
| 학습 태도 | 태도가 드러난 장면                                                    |
| 인성·관계 | 구체적 사건                                                           |
| 학급 역할 | 제안 → 실제로 한 일                                                   |
| 변화      | **시기 대비가 있을 때만.** 근거 없는 변화 서술을 막는 장치이기도 하다 |
| 아쉬운 점 | 있으면                                                                |
| 진로      | 관심이 드러난 모습                                                    |

★`변화` 슬롯은 값이 두 가지다 — 재료 분류이면서, **"변화 서사를 써도 되는가"의 근거 표식**이
된다. 실측 D 사례(시기 대비 없는 변화 서사)를 데이터 쪽에서 받쳐 준다.

## 5. 화면 — (나)안: 본문 아래

오너 선택. 슬롯은 **무엇을 썼는지**에 대한 것이라, 본문을 쓴 **다음**에 고르는 자리에 둔다.

```
분류   [수업 관찰] [상담·관계] [생활·학습] [기타]  [+ 분류]
       [교과역량] [학습태도] [진로흥미] [특이사항]  [+ 태그]
┌─ 본문 ─────────────────────────────────┐
└────────────────────────────────────────┘
어떤 장면인가요?  [질문] [시도] [시행착오] [산출물] [주고받음] [연결]
```

- **클릭 1번.** 접지 않는다 — 한 번 더 눌러야 하면 대부분 안 누른다.
- textarea 가 구분선 역할을 해 **축이 저절로 갈린다.** 라벨을 세 개나 붙일 필요가 없다.
- 순서가 교사의 실제 사고 흐름과 맞는다(쓰고 나서야 무슨 장면인지 안다).

### 스타일

기존 칩과 같은 형태를 쓴다(새 시각 언어를 만들지 않는다).

```
공통   px-2 py-0.5 rounded-full text-caption font-medium transition-colors
선택   bg-sp-accent text-white
비선택 bg-sp-surface text-sp-muted hover:text-sp-text
안내   text-caption text-sp-muted mr-0.5   ("어떤 장면인가요?")
행     flex flex-wrap items-center gap-1
```

- 하드코딩 HEX 금지, `sp-*` 토큰만.
- **`sp-*` 에 Tailwind 투명도 수식(`/20`)은 무효다** — 조용히 투명해진다. 알파가 필요하면
  다른 방법을 쓴다.
- 라운드는 Tailwind 기본 키만. 직각 금지.
- 모든 문구 한국어. 다크·라이트 양쪽에서 대비 확인.

★이 배치는 **실화면 렌더 확인이 필요하다**(단독 확정 금지 — 오너 검토 후 조정).

## 6. 알림 연동 — 문구만 바꾼다

알림 규칙은 순수 함수로 잘 분리돼 있다(저장처를 모른 채 provider 주입으로 돈다).

**★누구를 부를지는 바꾸지 않는다.** 선정은 지금처럼 "공백 오래된 순"이다. 슬롯이 비었다고
어제 기록한 학생을 다시 부르면 성가시고, 그게 알림을 끄게 만든다.

**바꾸는 것은 문구뿐이다.** 뽑힌 학생에게 눈에 띄는 빈 슬롯이 있으면 그걸 가리킨다.

```
지금   요즘 {name} 학생은 학교에서 어떤 모습이었나요?
슬롯   {name} 학생, 요즘 '시행착오' 장면이 안 보이네요. 있었나요?
```

- `REMINDER_PROMPTS` 후보 배열에 슬롯형 문구를 더하고, 슬롯 현황을 아는 경우에만 고른다.
- 슬롯 현황은 **provider 주입**으로 받는다(순수성 유지, 저장처 은닉 — 기존 방식 그대로).
- 프리셋(가볍게·보통·꼼꼼히)·설정 화면·발화 상한·방해금지는 **손대지 않는다.**

## 7. 통계 — 별도 구역 신설

기존 "태그별 표"는 **그대로 둔다**(열 넘침 방지). 슬롯은 **별도 구역**에 둔다.

- 학생별로 어느 슬롯이 비었는지 한눈에 보이는 것이 목적이다("질문 5 · 시행착오 0").
- 표 열을 6개 더 붙이는 대신, **채워진 슬롯 수 / 전체** 요약과 빈 슬롯 강조가 낫다.
  구체 형태는 실화면에서 정한다.
- 검색 필터는 **이번 범위에서 제외**한다(오너 선택: "보통"). 필요해지면 후속.

## 8. 수용 기준

- **AC-1** 데스크톱·모바일 관찰 입력에서 슬롯을 **탭 한 번**으로 붙인다.
- **AC-2** 담임 누가기록에도 붙는다. **세부 분류(tags)와 섞이지 않는다.**
- **AC-3** 슬롯을 안 고른 기록도 정상 저장된다(강제 없음).
- **AC-4** 근거 창고로 끌어와도 슬롯이 유지된다.
- **AC-5** 기기 간 동기화에서 구 데이터의 슬롯 부재가 빈 배열로 덮이지 않는다.
- **AC-6** 알림이 빈 슬롯을 문구로 가리킨다. **선정 로직은 변하지 않는다.**
- **AC-7** 통계에 슬롯 현황 구역이 생기고, **기존 태그 표의 열 수는 그대로다.**
- **AC-8** 브릿지 `get_observations` 가 슬롯을 탈식별해 노출한다.
- **AC-9** 기존 태그·기록·필터·내보내기가 깨지지 않는다.
- **AC-10** 게이트 4종 통과 + 브릿지 테스트 통과 + 번들 재생성.

## 9. 위험

| 위험                             | 대응                                                  |
| -------------------------------- | ----------------------------------------------------- |
| 입력 부담 증가로 기록이 줄어든다 | 칩 한 번 탭 고수. 접지 않음. 슬롯 선택 강제 안 함     |
| 새 칸이 동기화에서 유실된다      | 부재≠빈 배열. 병합 규칙에 명시하고 회귀 테스트로 고정 |
| 담임 태그와 의미가 섞인다        | 별도 칸으로 분리(§3). 화면에서도 다른 자리            |
| 통계 표가 넘친다                 | 태그 표 불변 + 슬롯은 별도 구역(§7)                   |
| 어휘가 실사용과 안 맞는다        | 오너가 교사다. 실화면 확인 후 조정                    |
