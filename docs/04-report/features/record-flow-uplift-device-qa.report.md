## 0. 먼저 읽을 것 — 왜 게이트로는 못 잡나

게이트 4종(타입·lint·테스트·회귀)은 전부 초록이다. 그런데 이 저장소에는 **게이트가 전부 초록인
채로 존재한 결함**이 여러 번 있었다(출석번호 밀림, 유리 모드 모달 갇힘, 드라이브 목록 100개 잘림).
아래 항목들은 그런 종류다 — 화면을 실제로 그려 보거나, 실제 장치를 만져야만 드러난다.

**⚠️ 데스크톱 변경이 포함되어 있다.** `electron/main.ts`·`electron/ipc/` 를 고쳤으므로
`npm run electron:dev` 를 **완전히 껐다 켜야** 반영된다(watch 되지 않는다).

## 3. 이번에 T6 가 새로 만진 것 (T1~T5 계획에 없던 수정 — 특히 봐 주세요)

- **`.txt`·`.md` 본문 추출.** T5 는 "kordoc 확장자 목록에 `txt`·`md` 를 넣어 달라"고 요청했는데,
  **실측해 보니 kordoc 은 평문을 못 읽는다**(`UNSUPPORTED_FORMAT`). 목록에만 넣었으면 파일을
  내려받아 파서에 넘기고 **실패로 굳어 지금보다 나빠졌을 것**이다. 그래서 메인 프로세스에
  평문 해독 갈래를 따로 넣었다(UTF-8 → 실패 시 CP949).
  → **확인**: 한글 윈도우에서 만든 `.txt`(CP949)와 UTF-8 `.txt` 둘 다 글자가 안 깨지는지.
  → 이 갈래는 **과제 제출과 관찰 첨부 두 경로가 함께** 쓴다.
- **`.md` 를 문서 첨부로 받도록 열었다.** 파서는 읽는데 문 앞에서 막히는 비대칭을 없앴다.
- **담임 누가기록(`InputMode.tsx`)에 [말로 쓰기] 추가.** T1 의 범위 표에는
  수업 관찰(`ObservationForm`)·알림·옆핀 세 곳만 있었고 **담임 누가기록이 빠져 있었다.**
  오너가 실제 화면에서 "버튼이 안 보인다"고 신고해 확인한 결과 정말 없었다 — 계획의 누락이다.
  담임이 관찰을 가장 많이 적는 화면이라 여기가 빠지면 기능의 값이 크게 준다.
  → **확인**: 이 화면 메모 칸 아래 [말로 쓰기]가 보이고 눌렀을 때 커서가 메모 칸으로 가는지.
- **설정 → 학생 관찰 기록 탭 맨 아래에 음성 고지**를 꽂았다. 실험실이 아니라 여기 둔 이유는
  말로 남기기가 실험실 스위치에 매여 있지 않기 때문이다(데스크톱이면 늘 보인다).
  → **확인**: 그 탭을 열었을 때 고지가 어색하지 않게 붙어 있는지.

## 4. 실험실 토글 제안 (항목별)

원칙: **되돌릴 수 없는 것·남에게 보이는 것·바깥으로 나가는 것**은 실험실 뒤에 둔다.
반대로 **기존 화면을 조용히 좋아지게 하는 것**은 토글을 만들지 않는다 — 스위치가 늘수록
"켜야 보이는데 켤 줄 몰라 못 쓰는" 기능이 된다.

| 기능                                | 제안                            | 이유                                                                                                                                                          |
| ----------------------------------- | ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **말로 남기기 (버튼)**              | 🟢 **토글 없이 기본 켬**        | 데스크톱 앱이 아니면 버튼이 **스스로 사라진다**. 누르기 전에는 아무 일도 없고, 고지는 설정에 이미 있다. 스위치를 두면 "마이크가 왜 안 보이죠" 문의만 는다.    |
| **말 → 학생별로 나누기**            | 🔵 **쌤핀 AI 실험실 종속**      | 이미 그렇게 되어 있다(꺼져 있으면 진입 자체가 없음). 별도 스위치를 **더 만들지 말 것**.                                                                       |
| **주제로 묶기 (근거 창고 주제 열)** | 🟡 **기본 켬 — 단, A3 확인 후** | 선택 기능이고(안 묶으면 지금과 동일), 데이터를 밖으로 보내지 않는다. **다만 디자인 승인을 못 받았으므로 유리 모드 실렌더(A3)를 보신 뒤에 결정하시길 권한다.** |
| **탐구 흐름 화면**                  | 🟡 위와 같음                    | 주제 열과 한 몸이다. 따로 가를 이유가 없다.                                                                                                                   |
| **성취기준 고르기**                 | 🟢 **토글 없이 기본 켬**        | 순수 추가다. 안 고르면 예전 그대로 저장된다. 자료는 필요할 때만 읽어 들여 첫 화면 무게에 영향이 없다.                                                         |
| **점검 경고 6종**                   | 🟢 **토글 없이 기본 켬**        | 막지 않고 알리기만 한다. 다만 **B4(오탐률)를 보시고**, 시끄러우면 토글이 아니라 **기준값(30일)을 손보는 쪽**이 맞다.                                          |
| **과제 파일 본문 유입**             | 🟠 **기본 켬 + 되돌릴 길**      | 학생이 쓴 글이 근거 창고로 들어오는, 이번 묶음에서 **가장 무거운 변화**다. §5 의 한계를 먼저 읽어 주시길.                                                     |

## 5. 오너가 알고 결정하셔야 할 한계 (숨기지 않고 적는다)

1. **명단 밖 이름은 가려지지 않는다.** 근거 → AI 경로는 가명 처리를 태우지만, 가려지는 것은
   **명단에 있는 학생의 실명·학번**과 형태로 알아보는 것(전화번호·주민번호·생일·이메일)뿐이다.
   학생 글에는 **다른 반 친구·가족·학원 이름**이 흔하다. 이 한계는 관찰 첨부 경로에 이미 있던
   것과 같고, 과제 본문 유입이 그 경로를 **넓힌다.**
2. **점검 6종 중 2종은 브릿지(앱이 꺼진 상태의 AI 저장)에서 영구히 생략된다** — 성취기준 원문과
   같은 반 다른 초안이 브릿지에 없기 때문이다. 생략됐다는 사실은 응답에 실려 나간다.
   ★재료를 도구 인자로 받는 방식은 **일부러 택하지 않았다** — 원문을 인자로 넣으면 그 문장이
   모델에 그대로 들어가 막으려던 복사를 오히려 유발한다.
3. **성취기준 코드는 AI 로 가지 않는다**(의도한 상태). 브릿지에 번들이 없어 코드가 뜻 없는
   문자열이고, 모델이 `[9수02-15]` 를 본문에 옮겨 적을 위험만 남는다.
4. **미러 지문 대조는 보증이 아니라 알람이다.** 저장소가 갈라져 있어 **CI 에서는 본체↔브릿지
   실제 파일 대조가 돌지 않는다**(브릿지 파일이 체크아웃에 없다).
5. **하네스는 아직 실행되지 않았다**(API 호출 비용 — 오너 승인 대기). 채점 경로만 가짜 응답으로
   확인했다. B4 의 오탐 기준을 제대로 잡으려면 이게 필요하다.
6. **`submission-texts`(학생 글 본문 캐시)는 기기 사이로 동기화하지 않는다**(T5 결정).
   학년도 전환 때는 과제와 함께 보관함으로 내려가도록 이번에 붙였다.
