## 1. 무엇을 만들었나

쌤도구를 **쌤핀 창 밖 별도 창**으로 띄울 수 있게 했다. 타이머를 켜 둔 채 시간표나 생기부를 보는,
바로 그 쓰임이 목적이다. 창을 옮겨도 **진행 중인 시간·입력·제외 목록·결과가 그대로 따라간다.**

지원 도구는 **9종**: 타이머(일반·스톱워치·발표), 랜덤 뽑기, 신호등, 점수판, 룰렛, 주사위, 동전,
QR코드, 활동 기호.

## 2. 사용자에게 달라지는 것

| 자리 | 무엇이 생겼나 |
| --- | --- |
| 쌤도구 목록의 카드 | 오른쪽 위 **새 창 아이콘** — 빈 상태로 별도 창 열기. 카드 본체 클릭은 지금처럼 본문 열기 |
| 도구 화면 머리줄 | **[팝업으로 옮기기]** — 지금 상태 그대로 별도 창으로 |
| 별도 창 머리줄 | **[항상 위]**(기본 꺼짐) · **[본문으로 가져오기]** · **[닫기]** |
| 팝업 사용 중인 도구의 본문 | 도구 대신 **"별도 창에서 사용 중"** 안내와 **[창 보기]** |

기존 본문 열기와 병렬 보기(한 창에 도구 둘)는 그대로 남아 있다.

## 3. 어떻게 만들었나 (짧게)

- **상태를 창 밖으로 옮기는 계약**을 만들었다. 도구는 "지금 돌고 있는 것을 **먼저 멈추고** 상태를
  담는" 함수와 "담은 것을 다시 적용하는" 함수 한 쌍을 등록한다. 멈추는 책임을 계약 안에 넣었기
  때문에, 두 창이 동시에 같은 타이머를 세는 구간이 아예 없다 → **알람이 두 번 울리지 않는다.**
- 창을 만들고 화면이 준비되기까지 실제로 2~3초가 걸린다. 그래서 상태를 담을 때 **찍은 시각**을
  함께 넘기고, 받는 쪽이 그동안 흐른 시간을 더해 복원한다. 옮기는 사이에 시간이 다 됐으면
  받는 쪽에서 딱 한 번 알람이 울린다.
- **새 창이 "준비 끝"이라고 알리기 전에는 원래 창이 실행을 놓지 않는다.** 창이 안 뜨거나 실패하면
  원래 창에서 흐른 시간까지 반영해 되살아나고 안내가 뜬다.
- 도구 하나당 창 하나만 만든다. 다시 열면 기존 창을 앞으로 가져온다.
- 허용한 9종 밖 도구 id·외부 주소·모르는 창의 요청은 전부 거절한다.

**실제 Electron 창 — 수행함** (다른 세션의 dev 인스턴스는 건드리지 않고 별도 인스턴스로)

- 5분 타이머 → 팝업 이동 → 본문을 시간표로 이동 → 본문 복귀: **04:56 → 04:54 → 04:49 → 04:41**
  로 시간이 끊기지 않고 이어졌다.
- 종료 8초 전에 옮겼을 때 **알람은 팝업에서 1회, 본문 0회.** 6초 더 기다려도 늘지 않았다.
- 9종 전부 실제 창으로 열렸고 전부 닫은 뒤 목록이 비었다(잔재 없음).
- 재열기 = 기존 창 포커스(창 수 1 → 1). 자리 뽑기·외부 주소·칠판 요청은 전부 거절.
- 고친 뒤 **본문 페이지를 그대로 둔 채** 복귀시켜도 04:50 → 04:47 로 이어졌다(05:00 초기화 없음).
- 갈무리 7장은 [검증 기록](../../03-analysis/tool-popup.qa.md) §2-4 참조.

## 6. 검토에서 잡혀 고친 것

architect 검증에서 **막는 결함 2건**이 나왔고 둘 다 고친 뒤 실기기로 다시 확인했다.

1. **복귀할 때 상태가 버려졌다** — 본문이 이미 그 도구 화면이면 화면이 다시 만들어지지 않아
   넘어온 상태가 사라지고(타이머 05:00 초기화), 남은 봉투가 나중에 **유령 알람**까지 울렸다.
   첫 검증 시나리오가 하필 안전한 경로(본문을 시간표로 옮겼다 복귀)를 밟아 통과했던 것이다.
   → 도착하는 대로 집어 화면을 다시 만들도록 고쳤다. 실기기 재확인 + REGRESSION #75 로 고정.
2. **쌤도구 카드가 격자 칸을 채우지 못했다** — 보조 버튼을 형제로 두려고 카드를 감쌌더니
   카드가 격자 항목이 아니게 되어 높이·너비가 들쭉날쭉해졌다. → 실측으로 확인(모두 154×174).

이어서 읽는 곳이 없는 코드(스토어 `pendingToolId`, 창 관리자 `ready`·`isAlwaysOnTop`,
창 계약 `send`, 통로 `kind`, domain `ToolPopupHandoff`)를 지우고 게이트를 다시 돌렸다.

**계획에서 의도적으로 뺀 것 하나** — 처음 계획에는 `domain/entities/ToolPopup.ts` 에
`ToolPopupHandoff`(이관 봉투) 타입을 두기로 되어 있었다. 막상 만들고 보니 **아무도 읽지 않는
타입**이었다(참조 0건, 검토자도 저장소 전체 grep 으로 확인). 실제 봉투 계약은 화면 쪽의
`ToolPopupSnapshotEnvelope` 와 창 관리자의 `StoredHandoff`·`ClaimedHandoff` 에 살아 있다.
나중에 이 타입을 찾다가 헤매지 않도록 여기 적어 둔다.

## 8. 곁가지로 함께 고친 것 — 타이머 "시간 종료!" 덮개

처음엔 범위 밖으로 남겼다가, 오너 요청으로 이어서 마무리했다.

**무엇이 잘못돼 있었나** — 종료 덮개가 `bg-sp-bg/90` 을 썼는데, `sp-*` 토큰에 투명도 수식을 붙이면
Tailwind 가 **규칙을 아예 만들지 않는다.** 그래서 덮개가 완전히 투명했고(실측 `rgba(0,0,0,0)`),
뒤의 큰 숫자가 "시간 종료!" 글씨와 겹쳐 보였다. 밝은 테마에서 특히 심했다.

**무엇을 바꿨나** (디자인 에이전트와 방향을 정한 뒤, 세 줄):

1. 덮개 배경 → 인라인 `var(--sp-bg)`. 가릴 대상이 같은 자리·같은 크기의 숫자라 **반투명이 곧 겹침**이어서,
   원래 의도했던 90% 대신 아예 불투명하게 덮었다.
2. 빨간 점멸 `bg-red-600/30` 은 그대로. 진짜 색이라 이미 정상이고, 테마마다 달라지면 안 되는 경보색이다.
3. 글씨색 `text-red-400` → `text-sp-error`. red-400 은 **밝은 테마에서 큰 글씨 기준(3:1)에도 미달**했다
   (2.13~2.77). `sp-error` 는 테마별로 값이 갈려(라이트 `#dc2626` · 다크 `#f87171`) 12개 테마 전부 3.72 이상이다.

**확인** — 실제 Electron 창에서 두 테마 모두 실측했다. 밝은 테마 `rgb(255,255,255)` + 글씨 `#dc2626`,
어두운 테마(설정에서 실제로 바꿈) `rgb(25,25,25)` + 글씨 `#f87171`. 갈무리 3장(08·09·10).

**재발 방지** — REGRESSION **#82** 신설. 이 함정은 코드 리뷰로 안 잡히고 게이트도 초록이라,
누가 클래스로 되돌리면 그대로 재발한다. **변이 시험으로 진짜 잡는지 확인했다**(옛 코드로 되돌리면 실패).

**범위** — 같은 함정이 저장소 전체에 수천 곳 있지만(쌤도구 폴더만 547곳) 자리마다 디자인 판단이
필요한 별도 작업이라 손대지 않았다. 이번엔 **가림이 목적인 덮개 한 곳**만 고쳤다. 팝업 9종의 다른
전면 덮개는 `bg-black/60`·`bg-white` 처럼 진짜 색이라 문제없음을 확인했다.
