## 알려진 제한과 미검증

- **[적용]·[덮어쓰기]로 실제 저장**은 오너 자료라 누르지 않았다(저장 경로 자체는 이번에 바뀌지 않음).
- **자동 동기화·[컴시간 변동 확인]** 화면 경로: 이 PC 에는 컴시간 자동 연동이 설정돼 있지 않아 화면으로 확인하지 못했다.
  같은 `getSchoolData` 를 쓰며, 실서버로 일일자료(이번 주 보강·교체)까지 받는 것은 확인했다.
- macOS 실기기는 확인할 수 없다(빌드·자산 검증만).
- **자동 업데이트 감지·설치**(v2.5.7 이하 → v2.5.8)는 이 PC 가 이미 2.5.8 이라 확인하지 못했다. 피드 `latest.yml`·`latest-mac.yml` 은 `version: 2.5.8`.
- 이 PC 의 Supabase CLI 는 npx 최신(3.0.0)이 저장소 `config.toml` 의 `[inbucket]` 을 거부한다. 다음 릴리즈의 KB ingest 도 `supabase@2.x` 를 지정하거나, 설정을 `[local_smtp]` 로 옮기는 별도 작업이 필요하다.
- 컴시간이 열쇠·공식을 또 바꾸면 다시 「컴시간 서비스 구조가 바뀐 것 같아요」가 뜬다(의도적 차단 대응이라 재발 가능).
