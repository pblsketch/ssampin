## 1. 확인 방법

두 가지를 나눠 썼다.

| 방식          | 무엇을 어떻게                                                                                                        |
| ------------- | -------------------------------------------------------------------------------------------------------------------- |
| **브라우저**  | 설치된 크롬을 headless 로 띄우고 CDP 로 몰았다. **교사 1 + 학생 2 + 교실 화면 1** 을 동시에 열고 같은 세션에 붙였다. |
| **실제 서버** | 학생 접속 서버(`electron/ipc/liveMultiSurvey.ts`)를 esbuild 로 그대로 묶어 실행했다. HTTP·WebSocket 왕복이 진짜다.   |

도구와 기록은 `output/participation-ux/`(git 제외)에 있다 —
`drive.mjs`(CDP 조종), `host.cjs`(서버 브리지), `before.mjs`·`after.mjs`·`after2.mjs`·`contrast.mjs`.

**Electron 창 자체는 열지 않았다.** 교실 화면은 별도 `BrowserWindow` 대신 같은 스냅샷을
`BroadcastChannel` 로 옮겨 **실제 `buildShareSnapshot()` 출력을** 그렸다.
이 확인은 실기기 Electron 확인을 대신하지 않는다(§6).

## 3. 무엇이 어떻게 좋아졌나

### A. 교사가 만들 때

| 바뀐 것                           | 확인 결과                                                                                |
| --------------------------------- | ---------------------------------------------------------------------------------------- |
| 저장 상태가 실제와 맞는다         | 저장 전 `저장하지 않은 변경` → 저장 후 `저장됨` → 다시 고치면 `저장하지 않은 변경`       |
| 저장 중 추가 수정을 삼키지 않는다 | `useDraftSaveState` 가 **저장 요청 시점의 내용**과 견준다. 실패하면 `저장하지 못함` 고정 |
| 고칠 자리를 말해 준다             | `아직 학생을 초대할 수 없어요. / 1번 문항의 정답을 골라 주세요.` — 누르면 그 자리로 이동 |
| 보기를 지우고 옮길 수 있다        | ↑·↓·✕ 추가. 옮긴 뒤 정답 연결이 따라감(`correctStillLinked: [false,true,false]`)         |
| 정답 연결이 뒤바뀌지 않는다       | 정답이던 보기를 지우면 `correctChoiceIds` 에서도 빠진다 (단위 테스트 2건)                |
| 활동 설정이 분리됐다              | `main h2` = `[]`. 위쪽 [활동 설정] + 상시 요약 배지                                      |
| 목록이 먼저 보인다                | 소개 영역은 **활동이 없을 때만**. 있으면 [이어서 하기] + [내 활동]                       |
| 삭제가 멀어졌다                   | 목록의 [⋯] 안으로                                                                        |
| 유형 변경 손실을 먼저 알린다      | [정답 사용]을 끄면 `골라 둔 정답 N개가 사라져요` 확인                                    |
| 1366 3열이 유지된다               | 240 / 725 / 401, 가로 스크롤 없음. 1280 미만에서는 미리보기를 접고 이유를 적는다         |

### B. 교사가 진행할 때

**진행을 세 축으로 나눴다**(ADR-131). 실제 단추 흐름:

```
응답 받는 중   → [응답 마감]
응답 마감됨    → [결과 공개] [정답·해설 공개] [다음 문항] (+ 정답 없으면 [토론 후 다시 답하기])
결과 공개 중   → [정답·해설 공개] [다음 문항]
```

| 확인 항목         | 결과                                                                             |
| ----------------- | -------------------------------------------------------------------------------- |
| 마감 ≠ 공개       | 마감 뒤 학생 화면 `응답을 마감했어요. 더 낼 수 없어요.` + 내 답. 분포 없음       |
| 마감 뒤 스냅샷    | `stage: closed`, 정답 값 없음, 응답 원문 0건                                     |
| 결과 공개         | 응답 1건 전달, 정답은 여전히 없음. 학생은 `우리 반의 응답` 분포만 본다           |
| 정답 공개         | 그때 `answer: '책 읽기'` 와 해설이 간다                                          |
| 진행 단추 위치    | 아래 고정 띠. `bottom 768 = viewportH 768`                                       |
| 수치의 뜻         | `입장 2명 · 이번 문항 응답 1명 · 미응답 1명` + "학급 전체 인원과 다를 수 있어요" |
| 미응답자 명단     | 교사 전용 표시와 함께 접힌 채로 제공                                             |
| 교실 창 외부 닫기 | [교실 화면 닫기] → [교실 화면 띄우기]로 되돌아옴. 다시 열면 세션 유지            |
| 늦은 제출         | 마감 뒤 학생 화면에 제출 단추가 없고 서버도 `open` 에서만 받는다                 |
| 중복 제출         | 같은 학생이 두 번 눌러도 `responses` 2건(학생 2명), 집계 2명                     |

### C. 학생이 참여할 때

| 확인 항목           | 결과                                                                          |
| ------------------- | ----------------------------------------------------------------------------- |
| **입장 화면 유지**  | 다른 학생이 입장해도 별명 칸이 그대로(`hasNickname: true`) — P1 해결          |
| 입장 안내           | `별명은 선생님 화면에 보여요. 교실 화면과 다른 친구 화면에는 나오지 않아요.`  |
| 응답 방식 표시      | `하나 선택` / `여러 개 선택` / `막대를 움직여 자리 고르기 · 이유도 작성`      |
| 척도 미선택 방지    | `아직 고르지 않았어요` → 그냥 제출하면 `막대를 움직여 내 자리를 골라 주세요.` |
| 명시적 최솟값       | 막대를 1로 옮겨 제출하면 그대로 접수                                          |
| 초안 복원           | 고르다 새로고침 → 선택 유지 + `쓰던 내용을 되살렸어요. 이어서 작성하세요.`    |
| 제출 후             | 작은 ✓ + `냈어요` + **내 답 · 내가 쓴 이유 · 다음 안내**                      |
| 연결 끊김           | `연결이 끊겼어요. 다시 잇는 중이에요 — 쓰던 내용은 그대로 있어요.`            |
| 활동 종료           | 문항별로 내 답·내 근거·처음 생각을 되짚는다                                   |
| 360·390px 가로 넘침 | 둘 다 없음                                                                    |

### D. 토론 전후 비교

`responseHistory`(이미 있던 차수 보존)로 새 화면을 만들었다.

```
처음 생각        2명 응답   1(1명) 9(1명)
2차 · 토론 뒤    2명 응답   7(1명) 9(1명)
사람별로 견주기 · 교사 화면에만 나와요 (2명)
  가나 [생각이 달라졌어요]  처음 1 "숙제가 너무 많아요" → 뒤 7 "친구 이야기를 듣고 생각이 달라졌어요"
  다라                      처음 9 "숙제로 복습이 돼요"   → 뒤 9 "그대로 생각해요"
```

- 차수마다 **참여 인원을 따로** 적는다.
- 두 차수에 **모두 응답한 학생만** 잇는다. 이어지지 않는 응답은 추정하지 않는다.
- `입장이 바뀐 것이 더 나은 답이라는 뜻은 아니에요` 를 화면에 적었다. 정오 표시는 붙이지 않는다.

## 6. 확인하지 못한 것

- **Electron 실기기.** 교실 화면은 실제 별도 `BrowserWindow` 대신 같은 스냅샷을 그려 확인했다.
  창을 두 번째 모니터로 옮겨 전체 화면으로 쓰는 것, 운영체제 닫기 단추의 실제 동작,
  설치본에서의 조작은 미검증이다.
- **학교망·휴대폰 여러 대 동시 참여.** 터널·짧은 주소 발급 경로는 이번에 타지 않았다.
- **다크 테마 육안 확인.** 색상값은 재어 봤지만(`bodyBg rgb(15,23,42)`, 채움 단추 대비 3.68)
  13개 테마를 눈으로 돌려 보지는 않았다.
- **키보드만으로 전체 조작.** 초점 링과 조작 가능 여부는 확인했지만 탭 순서를 끝까지 따라가지는 않았다.

## 7. 재어 본 접근성 수치 — 오너·디자인 판단이 필요한 것

`contrast.mjs` 로 실제 렌더된 화면에서 WCAG 상대 휘도 공식으로 쟀다.

**터치 영역**: 교사 화면 진행 단추 44×44 이상, 학생 [응답 보내기] 270×50.
서로 붙어 있는 보기 조작(↑·↓·✕)은 36×36 + 간격 — WCAG 2.2 AA(2.5.8)의 **24×24 + 간격 예외**를 지키고,
같은 일을 하는 다른 길(끌어놓기)도 있다. 제품 목표 44px(= 2.5.5 AAA)에는 못 미친다.

**글자 대비** — 남은 미달은 모두 **프로젝트 공통 토큰** 문제다. 이 화면만의 선택이 아니다.

| 토큰 조합                             | 실측                      | 기준    |
| ------------------------------------- | ------------------------- | ------- |
| `text-sp-muted`(#787774) on `sp-card` | 4.10 : 1                  | 4.5 : 1 |
| `text-sp-muted` on `sp-bg`            | 4.48 : 1                  | 4.5 : 1 |
| `text-sp-accent`(#2383e2) 글자        | 3.88 : 1                  | 4.5 : 1 |
| `bg-sp-accent` + `sp-accent-fg`(흰)   | 3.88(밝게) / 3.68(어둡게) | 4.5 : 1 |

이 화면 안에서 고칠 수 있는 것(구획 제목·문항 번호·삭제 단추의 보조색)은 본문 색으로 바꿨다.
**나머지는 테마 토큰을 바꿔야 하고 모든 화면에 영향을 준다** — 단독으로 바꾸지 않았다.
디자인 전문 에이전트와 함께 볼 일이고, 오너 판단이 먼저다.

## 8. 남은 거친 곳

- 가치수직선의 **학생용 집계**는 숫자만 나열한다(`우리의 생각 | 1 | 9`).
  교사·교실 화면은 제대로 그린다. 학생 화면의 표현을 다듬는 것은 별도 작업이다.
- 문항 제한 시간·부적절 응답 가리기·결과 내보내기·문항 보관함은
  [격차 분석](../../03-analysis/participation-classroom-gap-20260921.analysis.md)에 그대로 남아 있다.
