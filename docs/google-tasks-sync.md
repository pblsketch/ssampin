# Google Tasks 동기화

쌤핀 할 일과 Google Tasks 를 양방향으로 맞춘다. 이 문서는 현재 구현의 구조, 필드 매핑, 충돌·삭제 정책,
로그인 정보 저장 규칙, 알려진 한계, 수동 테스트 체크리스트를 적는다.

- 정본 코드: `src/adapters/stores/useTasksSyncStore.ts`(`syncNow`) · 순수 규칙 `src/domain/rules/tasksSyncRules.ts`
- 결정: [ADR-141](03-decisions/ADR-141.md)(충돌·로그인 정보 저장) · [ADR-136](03-decisions/ADR-136.md)(구글에서 받은 자료)
  · 이전 정밀화: [google-tasks-sync-fix 보고서](04-report/features/google-tasks-sync-fix.report.md)
- `src/usecases/tasks/SyncTodos.ts` 는 **현재 쓰이지 않는다**(충돌 수가 항상 0 인 옛 구현). 수정하지 말고 `useTasksSyncStore.ts` 를 본다.

## 2. 인증

- 시스템 브라우저 + `127.0.0.1` 임시 서버(loopback) + PKCE(S256). 학교 보안 프로그램이 막으면 수동 PKCE 로 넘어간다.
- 요청 스코프는 승인된 4개뿐이다: `calendar`, `drive.file`, `userinfo.email`(기본 3개) + `tasks`(Tasks 를 켤 때 추가 동의,
  `include_granted_scopes`). **스코프를 늘리면 구글 재검증이 필요하다.**
- 토큰: 액세스 토큰은 만료 전 자동 갱신(리프레시 토큰 유지). 갱신이 `invalid_grant` 로 거절되면 다시 로그인해야 한다.
  Tasks API 가 401 을 주면 한 번 갱신해 다시 보낸다.
- 클라이언트 ID/Secret 은 빌드 때 `VITE_GOOGLE_CLIENT_ID`·`VITE_GOOGLE_CLIENT_SECRET` 로 주입한다(코드에 없다).

### 로그인 정보 저장 규칙 (ADR-141)

`electron/ipc/secureStorage.ts` — **모든 키**에 적용된다(구글 토큰 `calendar-tokens`, 마크다운 변환 복원표 등).

| 상황              | 동작                                                                                                                           |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 쓰기, 암호화 가능 | 암호화해서 `data/.<key>` 에 쓴다.                                                                                              |
| 쓰기, 암호화 불가 | **디스크에 쓰지 않는다.** 메인 프로세스 메모리에만 두고, 같은 키의 옛 평문 파일은 지운다. 앱을 다시 켜면 다시 로그인한다.      |
| 읽기, 암호화 가능 | 복호화한다. 실패했는데 내용이 JSON 텍스트면 옛 평문이므로 암호화해 다시 쓰고 값을 돌려준다. 그 밖의 실패는 파일을 두고 `null`. |
| 읽기, 암호화 불가 | 메모리 값, 없으면 옛 평문 JSON 파일을 읽기만 한다.                                                                             |

## 3. 동기화 흐름 (`syncNow`)

동시에 하나만 돈다(뮤텍스). 일일 한도 쿨다운 중에는 호출하지 않는다.

0. **준비**: 토큰, 로컬 할 일 스냅샷. 올리거나 지울 보류 변경(`pendingRemoteOp` 가 `update`/`delete` 이고 `googleTaskId` 가 있음)이
   있을 때만 구글 목록을 한 번 읽어 **충돌 판정용 스냅샷**을 둔다(실패하면 판정만 건너뜀).
1. **삭제 올리기**: 고아 삭제 큐 + `pendingRemoteOp: 'delete'`.
2. **생성 올리기**: `pendingRemoteOp: 'create'`.
3. **수정 올리기**: `pendingRemoteOp: 'update'`. 구글에서 이미 지워진 항목은 수정을 보내지 않고 새로 만든다. 수정 응답에 `deleted: true` 가 오거나 404 여도 새로 만든다.
4. **가져오기**: 구글 전체를 다시 읽어 반영한다(보류 변경이 있는 항목은 건드리지 않는다).
5. **조정(RECONCILE)**: 동기화 중 선생님이 한 추가·수정·삭제를 보존한다.

올리기가 가져오기보다 먼저 돌므로 **쌤핀에서 고친 항목은 구글을 덮는다.** 이것이 "쌤핀이 이긴다"의 실제 구현이다.

트리거: 앱 시작(2초 뒤), 할 일 저장 후 2.5초, 주기(최소 5분), 창 포커스(10초 쿨다운), 설정의 "지금 연동 실행".

## 4. 필드 매핑

| 쌤핀 `Todo`                                                                                                   | Google Task                          | 방향            | 비고                                                                                  |
| ------------------------------------------------------------------------------------------------------------- | ------------------------------------ | --------------- | ------------------------------------------------------------------------------------- |
| `text`                                                                                                        | `title`                              | 양방향          |                                                                                       |
| `notes`                                                                                                       | `notes`                              | 양방향          | 지운 메모는 올릴 때 `null`, 구글이 비운 메모(필드 없음)는 쌤핀에서도 지운다           |
| `dueDate` (`YYYY-MM-DD`)                                                                                      | `due`                                | 양방향          | 구글은 날짜만 의미가 있다. 올릴 때 `T00:00:00.000Z` 를 붙이고, 받을 때 앞 10자만 쓴다 |
| `completed`                                                                                                   | `status` (`completed`/`needsAction`) | 양방향          | 구글에서 완료하면 `completedAt` 을 찍는다                                             |
| `updatedAt`                                                                                                   | —                                    | 올리지 않음     | 쌤핀 안의 수정 시각                                                                   |
| `lastSyncedAt`                                                                                                | `updated`                            | 읽기            | 충돌 판정 때 구글 `updated` 와 비교한다                                               |
| `googleTaskId`·`googleTaskListId`                                                                             | `id`·목록                            | 연결            | 중복 생성 방지의 열쇠                                                                 |
| `origin`                                                                                                      | —                                    | 올리지 않음     | `google` 이면 쌤핀 AI 로 보내지 않는다(ADR-136)                                       |
| `startDate`·`time`·`priority`·`category`·`recurrence`·`subTasks`·`status`(프로 모드)·`checkAt`·`relatedStaff` | —                                    | **올리지 않음** | 구글에 대응하는 칸이 없다                                                             |
| —                                                                                                             | `parent`(하위 할 일)                 | **건너뜀**      | 쌤핀 하위 할 일로 옮기지 않는다                                                       |

동기화 범위: 보관(archive)되지 않은 쌤핀 할 일 **전체** ↔ 선택한 구글 목록 **1개**.

## 5. 충돌 정책

**승자는 늘 쌤핀이다.** 시각 비교로 승자를 정하지 않는다(쌤핀 PC·구글 서버·휴대폰의 시계가 서로 다르다). 이 정책은
알리고 기록할 뿐 승자를 바꾸지 않는다.

| 종류             | 판정                                                                                                                            | 처리                                                   |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| `edit-edit`      | 쌤핀 `pendingRemoteOp: 'update'` + 구글 `updated` 가 `lastSyncedAt` 보다 **5분을 넘어** 뒤 + 내용(제목·메모·마감일·완료)이 다름 | 쌤핀 내용으로 구글을 갱신하고, 덮이는 구글 내용을 기록 |
| `remote-deleted` | 쌤핀 `update` + 구글 스냅샷에 없거나 `deleted: true`                                                                            | 수정을 보내지 않고 새 할 일로 만든다. 구글 삭제를 기록 |
| `local-deleted`  | 쌤핀 `delete`(**보관**) + 구글에서 5분을 넘어 뒤에 고쳐 내용이 다름                                                             | 구글에서도 지운다. 사라지는 구글 내용을 기록           |

- **내용이 같으면 충돌이 아니다.** 올린 내용이 되돌아오는 메아리와 시계 어긋남을 걸러 낸다.
- 판정하지 않는 것: 구글과 연결되지 않은 항목, 옛(다른) 목록에 연결된 항목, `pendingRemoteOp` 가 없거나 `create` 인 항목
  (쌤핀 전용 칸만 바뀐 수정 포함), 구글 하위 할 일, 로컬 기록이 이미 없는 고아 삭제.
- **알림**: 회차에 새로 기록된 충돌이 있으면 앱 안 토스트를 한 번(개수만, 제목 없음). 성공·실패·한도 중단 모두에서 같다.
- **기록**: 설정 > Google Tasks 카드의 "최근 충돌 기록"(최대 20개, "기록 지우기"). 선택·되돌리기 화면은 없다.
- **저장**: 기기 전용 키 `tasks-sync-conflicts`. 드라이브 동기화 대상이 **아니다**(메타 테스트가 강제). 동기화를 끄면 지운다.
  구글에서 받은 자료이므로 쌤핀 AI·AI 브릿지·돌아보기 숫자에 쓰지 않는다. (백업은 `data/` 의 `.json` 을 모두 담으므로 함께 담긴다.)
- 같은 충돌은 `구글 ID + 종류 + 구글 updated` 로 한 번만 기록한다(올리기가 실패해 다음 회차에 다시 걸려도).

### 한계

- 마지막 동기화 직후 **5분 안에** 구글에서 고친 변경은 판정하지 못한다(쌤핀 내용이 덮이되 기록이 없다).
- PC 시계가 구글과 5분 넘게 어긋난 PC 에서는 불필요한 알림이 날 수 있다(내용이 다를 때만). 결과(쌤핀이 이김)는 같다.
- 컴퓨터를 두 대 이상 같은 구글 목록에 연결하면 각자 판정하고 기록한다. **한 대에서만 켜 두기를 권한다.**
- 구글에서 반복 할 일을 완료해도 쌤핀은 다음 회차를 만들지 않는다(쌤핀에서 완료할 때만 만든다).

## 6. 삭제 정책

| 일                                | 반영                                                                                |
| --------------------------------- | ----------------------------------------------------------------------------------- |
| 쌤핀에서 영구 삭제                | 구글에서도 삭제(고아 삭제 큐로 보장). 로컬 기록이 이미 없어 충돌 기록은 남지 않는다 |
| 쌤핀에서 완료 항목 보관           | 구글에서 삭제하고 쌤핀에는 보관본이 남는다(연결 해제, 다시 올리지 않음)             |
| 구글에서 삭제(`deleted: true`)    | 쌤핀에서도 삭제. 보관된 항목은 기록을 두고 연결만 끊는다                            |
| 구글 앱에서 "완료 항목 지우기"    | `hidden` 표시일 뿐 삭제로 보지 않는다(완료로 반영)                                  |
| 구글에서 지웠는데 쌤핀에서 고침   | 쌤핀 변경을 살려 구글에 다시 만들고 기록                                            |
| 쌤핀에서 보관했는데 구글에서 고침 | 보관(삭제)이 이기고 구글 내용을 기록. 영구 삭제는 기록하지 못한다                   |

## 7. 마감일·메모 지우기

- 올리기: 수정(PATCH)에서 마감일·메모가 없으면 `due: null`·`notes: null` 로 보낸다. 생성(POST)은 빈 칸을 보내지 않는다.
- 가져오기: 구글이 더 새롭고 쌤핀에 보류 변경이 없을 때, 구글 `notes` 가 없으면 쌤핀 메모도 지운다.
- **확인됨(2026-10-14, 구글 API 탐색기·임시 목록)**: `{"due":null,"notes":null}` 수정 뒤 다시 읽으면 두 필드가 응답에서 사라진다. 앱 화면에서의 확인은 체크리스트 9번.

## 8. 수동 테스트 체크리스트

자동 테스트가 못 보는 것(실제 구글 계정)을 사람이 확인한다. 쌤핀 Windows 설치본, 테스트용 구글 계정.
5분 허용 오차 때문에 충돌 재현은 **마지막 동기화 후 5분 이상 지난 뒤** 구글에서 고친다.

## 9. 구글 API 실제 동작 (직접 확인, 2026-10-14)

구글 API 탐색기에서 임시 목록을 만들어 확인하고 목록째 지웠다. 이 표의 동작에 이 문서와 코드가 기대고 있다.

| 확인한 것                                     | 결과                                                                                                                     |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 수정(PATCH)에 `due: null`, `notes: null`      | 200. 응답과 다시 읽은 결과 모두 두 필드가 **없다**(지워짐)                                                               |
| 삭제(DELETE)                                  | 204. 이후 `showDeleted=true` 목록에 `deleted: true` 로 남고 **제목·메모가 그대로**이며 `updated` 는 삭제 시각으로 바뀐다 |
| 삭제된 항목에 수정(PATCH)                     | **200 으로 받아들여진다**(오류 아님). `deleted: true` 는 그대로, 되살아나지 않는다                                       |
| 삭제된 항목이 기본 목록(`showDeleted` 없음)에 | 나오지 않는다                                                                                                            |
| 완료(`status: completed`)                     | 응답에 `completed` 시각이 붙는다. 다시 `needsAction` 으로 하면 `completed` 필드가 **사라진다**                           |
| `status` 없이 제목만 수정                     | `updated` 가 바뀐다(우리가 올린 내용도 `updated` 를 갱신한다 — 충돌 판정이 내용 비교와 5분 허용 오차를 함께 쓰는 이유)   |

삭제된 항목에 수정이 "성공"한다는 점이 중요하다. 그래서 올리기 전 구글 상태를 읽어 미리 가르고, 읽지 못한 회차에는
수정 응답의 `deleted: true` 로 가른다. 어느 쪽이든 쌤핀에서 고친 내용을 살려 새로 만든다.
