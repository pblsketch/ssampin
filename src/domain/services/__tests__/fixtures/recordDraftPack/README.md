# 요청서 기준선 픽스처 (recordDraftPack)

- `pre/` — P0(정렬·주제 정보) **직전** 출력. **대조하지 않는다.** 정렬이 무엇을 바꿨는지 보여 주는 증거로만 남긴다.
- `base/` — P0 **적용 후** 같은 커밋에서 뜬 출력. `recordDraftPackBaseline.test.ts` 가 이것과 글자 하나까지 대조한다.

입력 정본은 `cases.ts`. 다시 뜨는 법도 그 파일 머리글에 있다.

## P0 이 바꾼 것 (2026-09-10 실측)

| 픽스처                                                             | pre → base                                                                                   |
| ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------- |
| `empty` · `prohibited` · `lessonContext-question` · `lifeRelation` | **줄 집합 동일**, 순서만 바뀜                                                                |
| `nodate`                                                           | 줄 집합 동일. 날짜 있는 셋이 앞(09-02 → 09-11 → 09-18), 무날짜 둘이 뒤(`createdAt` 오름차순) |
| `overflow`                                                         | **실린 근거가 바뀐다**: `세 번째·첫 번째·짧은 기록` → `첫 번째·두 번째·짧은 기록`            |

`overflow` 만 결과가 달라지는 이유: 분량 상한(`DRAFT_PACK_MAX_EVIDENCE_CHARS` 12,000자)은 **앞에서부터**
채우므로 순서가 바뀌면 잘리는 근거도 바뀐다. 잘린 근거는 예전에도 지금도 화면에 "제외됨 N건 · 한 번에
보낼 수 있는 분량을 넘음"으로 뜬다.

★**실제 사용자 중 몇 %가 이 영향을 받는지는 이 저장소에서 잴 수 없다** — 근거 12,000자를 넘기는 학생이
있어야 드러나고, 그 자료는 선생님 PC 에만 있다. 오너 결정(2026-09-10): 예산을 올리지 않고 **경고만** 둔다.
흐름 보기(P3)가 들어오면 장면에 놓인 근거가 먼저 실리고 "아직 안 놓음"부터 잘리므로, 서사에 쓴 근거는 남는다.
